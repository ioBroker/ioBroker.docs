# IoBroker 月度回顾 – 2026 年 7 月/8 月
2026 年盛夏可谓热闹非凡！自上次盘点以来，我们新增了多达 21 款适配器，数量之多前所未有。重点依然是能源和电动出行领域（例如 Hoymiles、Victron GX、Solakon ONE、特斯拉壁挂式充电器和 go-e 充电器），但摄像头、多媒体和系统工具等也占据了相当大的比例。

此外，还有一些真正罕见的适配器：F1 方程式赛车实时数据、从窗户追踪航班动态，以及带有学习型加热预测功能的桑拿房控制系统。

从底层来看，这可能是近年来规模最大的一次更新：8月初，**管理后台、JavaScript、设备和物联网组件在短短几天内就迁移到了**React 19 和 MUI 9**。因此，从版本 8 开始，**Node.js 22** 将成为管理界面的最低要求。请在更新前确认！

## 核心更新
### 管理员 7.9.x → 8.0.5
管理员已升级到**版本 8**。这是该时期最大的单次事件。

- ⚠️ **从 Admin 8.0.1 版本开始，Node.js 22 是强制要求的。** 任何仍在运行 Node 20 或更早版本的用户都必须提前更新。
- **React 19 + MUI 9** (v8.0.1) – 整个用户界面已更新至最新主要版本。更新后，请简要检查包含自定义组件的适配器配置页面。
- **安全修复** (v8.0.2) – **OAuth2 回调**的身份验证问题已得到纠正。
- **修订版初始设置助手** (v8.0.5) – 现代布局、反向导航和许多详细的修正。
- 小修复：当存在多个“web”实例时，快速访问中出现重复磁贴（v8.0.5），自定义设置中的保存按钮和验证（v8.0.2–8.0.4），别名对话框中的文件夹选择。

上次评测中提到的**AI助手**当然依然保留。

不想使用自有API密钥的用户也可以通过`iobroker.mcp`适配器，使用外部MCP客户端运行它。

### Js-controller 7.2.2 “Milla”
在此期间，js-controller 的相关消息一直保持沉默：当前版本仍为 2026 年 6 月 16 日发布的 7.2.2 版本，位于 `stable` 仓库中。GitHub 上仅提供了 `7.2.3-alpha.x` 系列的每日预发布版本；这些版本**不适用于生产环境**。

计划在 7.2.3 版本中修复的问题包括 @krobipd 提出的两个问题：在 npm ≥ 10.6.0 下，失败的适配器安装被错误地报告为成功；以及自动 ENOTEMPTY 恢复没有清理阻塞的 npm 临时目录。

### Vis-2 2.14.x → 2.15.4
vis-2 已经获得了几项显著的改进：

- ⚠️ **HTML ID 已更改** (v2.14.4) – 在多个视图中出现的组件现在使用 `v<view>_<widget>` 代替 `<view>_<widget>`。任何基于这些 ID 构建自定义 CSS 或脚本的用户都需要进行更新。
- **崩溃的小部件不再导致整个视图崩溃** (v2.15.0) – 而是显示一个占位符。
- **相对控件现在可以通过拖放操作重新排列**（v2.15.0），并新增半透明预览功能。旧的箭头按钮已被移除。
- **编辑器微调** (v2.15.0) – 小部件上新增名称标签、蓝色悬停高亮显示，以及用于多选的通用框架。此外，还包含用于自定义主题的 MUI CSS 变量 (`--mui-palette-*`)。
- **针对云用户的重要修复** (v2.15.4) – `vis-2-widgets-material`、`echarts`、`openweathermap`、`fullcalendar` 和 `vis-2-widgets-energy` 等组件集不再通过云端加载。名称类似 `iobroker.fritz.box` 的本地安装也被错误地视为云端安装。
- **模块联合** (v2.15.0) – MUI 现在按版本共享，而不是作为单例，因此小部件集可以拥有自己的 MUI 版本。

🔗 [vis-2 在 GitHub 上的发布](https://github.com/ioBroker/ioBroker.vis-2/releases)

## 重要适配器更新
### IoBroker.javascript 9.3.1 → 10.1.2
JavaScript 适配器已升级到 **版本 10**，并在升级过程中进行了大量清理。

- **TypeScript 6 和 React 19 / MUI 9** (v10.0.0)
- ⚠️ **脚本的“严格”模式已再次禁用** (v10.1.0) – TypeScript 6 默认启用该模式，这会导致许多现有脚本无法正常工作。希望启用该模式的用户可以在设置中的新**“TypeScript”**选项卡中找到编译器选项。
- **直接在脚本中访问数据** (v10.1.1) – 存储在管理后台的凭据以**`SECRETS`**的形式提供（例如，`SECRETS.CameraPassword.key`），已解密、只读，并实时更新。编辑器会在输入`SECRETS.`后自动补全，Blockly 也新增了一个“凭据”模块。
- **Blockly 11 → 13** (v10.1.0) – Blockly 现在来自 npm 包而非代码仓库；所有代码块定义均已转换为 TypeScript。**生成的代码保持不变**，来自其他适配器的自定义代码块将继续运行。
- ⚠️ **Blockly 用户应直接升级到 10.1.2**：在 Blockly 13 中，带有命名超时、间隔或计划的脚本无法再保存——保存按钮根本不会出现。
- **修复外部库的类型问题** (v10.1.0) – 此前，所有额外安装的库都被视为 `any` 类型，并且完全缺少 `ioBroker.*` 类型。这两个问题现已解决。
- **新建规则向导** (v10.1.0) – 从触发器、条件和操作逐步构建规则，并在最后显示最终结果。
- **数据安全** (v10.1.0) – 如果整个镜像目录丢失（例如，由于网络共享未挂载），脚本将不再从数据库中删除。

🔗 [适配器的 GitHub 页面](https://github.com/ioBroker/ioBroker.javascript)

### IoBroker.devices 3.0.2 → 4.1.1
设备适配器也已更新至主要版本。

- **React 19 和 MUI 9** (v4.0.0)，以及具有历史记录的小部件的最近 24 小时或一天的**最小值/最大值**。
- ⚠️ **重要数据修复** (v4.1.1) – 旧版本写入的状态缺少 `common.read`/`common.write`。加载设备列表时，这些状态现在**会自动修复一次**，以防止可写状态错误地保持为只读状态。4.0.x 版本的用户应进行更新。
- **新增小部件** (v4.0.2) – **按钮、按钮传感器、相机和吸尘器**小部件不再显示“不支持的小部件类型”。媒体播放器现在具有静音功能和独立的音量反馈，盲人小部件也新增了倾斜控制功能，包括一个停止按钮。
- **新增设备类型和改进的油箱小部件** (v4.1.0) – 手动添加的数据点现在可以显示在小部件 GUI 中，因此油箱除了显示填充水平外，还可以显示剩余升数。
- **外观** (v4.0.2) – “深蓝色”已重新设计为深海军蓝，类别图标现在带有彩色圆形徽章，并新增了紫外线指数、转速、运行时间和瓦/千瓦/瓦时等功能图标。信息设备不再默认隐藏，并且支持**用户自定义视图**。

🔗 [适配器的 GitHub 页面](https://github.com/ioBroker/ioBroker.devices)

### IoBroker.hoymiles
<img width="100" height="100" src="https://raw.githubusercontent.com/Eistee82/ioBroker.hoymiles/main/admin/hoymiles.png" />

**类别：**能源/太阳能 **开发商：**冰茶82

该适配器集成了带有集成式 WiFi/蓝牙 DTU 的 **Hoymiles HMS-xxxW-xT 和 HMS-xxx-xWB 系列微型逆变器**。可选择本地连接、云端连接或两者同时连接。

#### 函数作用域：
- **本地模式**，通过 TCP/Protobuf 协议在 10081 端口上进行通信——完全无需云服务
- **云模式** 通过 S-Miles API 实现，并具备自动逆变器检测功能
- **云中继**：代表本地连接将本地接收的数据转发到 Hoymiles 云，以便云上传不会被阻止。
- 实时数据（功率、电压、电流、频率、温度），每个光伏串的值以及日、月、年和总计的能量聚合。
- 命令：有功功率限制 2–100%，逆变器开/关/重启，DTU 重启，无功功率，功率因数
- 223 个报警和警告代码，支持 11 种语言，采用 AES-128 加密，适用于较新的 DTU 固件

#### 特色功能：
- 仅适用于**内置 WiFi 的 HMS 型号**，不适用于 HM/MI 系列、外置 DTU-Pro/DTU-WLite 或 HMT 三相单元
- WB 系列（“HiFlow Pro”）没有本地 TCP 端口，完全通过云端运行。

🔗 [适配器的 GitHub 页面](https://github.com/Eistee82/ioBroker.hoymiles)

### IoBroker.victron-gx
<img width="100" height="100" src="https://raw.githubusercontent.com/Sefina-DS/ioBroker.victron-gx/main/admin/victron-gx.png" />

**类别：**能源/太阳能与储能 **开发商：**Sefina-DS

该适配器将 ioBroker **直接本地连接到 Victron GX 设备**（Cerbo GX、Venus GX、Ekrano GX），而无需通过 Home Assistant 或 VRM 云。

＃＃＃＃ 特征：
- 通过本地 MQTT 协议读取数据，通过 Modbus TCP 协议写入数据和控制 ESS，并可自动检测设备 ID
- 自动检测所有连接的设备：电池/BMS、MultiPlus/Quattro、电网电表、光伏逆变器、交流负载、开关、壁挂式电源插座、温度传感器和储罐传感器
- **ESS 控制**：`GridSetpoint`（0 = 零馈入），实时设定点（保持 800 毫秒），`DisableCharge`/`DisableFeedIn`，`MinimumSoc` 和 DVCC 限制
- **通过 GX Bridge 集成 Shelly** – Shelly Pro3/Pro4 设备通过其共享的序列号组合成一个对象树；GX 内部继电器也可以切换。
- 完全支持来自 Node-RED 的虚拟设备（`dbus-victron-virtual`）。
- 管理员选项卡“设备”和“所有主题”带有 JSON 下载

#### 特色功能：
- 在 GX 设备上，必须启用 MQTT 和 Modbus TCP 服务器，并允许“写入访问”才能进行控制。
- 该适配器正在论坛上进行积极测试；用户主要寻找具有三相和不同 BMS 的系统。

🔗 [适配器的 GitHub 页面](https://github.com/Sefina-DS/ioBroker.victron-gx)

### IoBroker.solakon-one
<img width="100" height="100" src="https://raw.githubusercontent.com/berto-1974/ioBroker.solakon-one/main/admin/solakon.png" />

**类别：**能源/太阳能 **开发商：**berto-1974

该适配器通过 **Modbus TCP**（端口 502）在本地读取和控制 **Solakon-ONE 混合逆变器** 和电池储能系统，完全无需云服务。

＃＃＃＃ 特征：
- 每串光伏组件（`pv1` 至 `pv4`）的数据，包括电压、电流、功率以及总发电量
- 电池数据：荷电状态 (SoC)、健康状态 (SoH)、充放电功率、总量和温度
- 三相网络数据（电压、频率、有功/无功功率、功率因数），包括孤岛运行标志
- 可写入的操作模式：自耗模式、优先馈电模式、备用模式、**削峰模式**、强制充电/放电模式
- 最小/最大 SoC 和最大充电和放电电流（0-40 A）可调。
- 九种**遥控模式**，可设置有功/无功功率设定点和最长 3600 秒的超时时间

#### 特色功能：
- 设备上必须启用 Modbus TCP，轮询间隔为 1–300 秒
- 仓库中提供了德语文档，文件名为 `README.de.md`。

🔗 [适配器的 GitHub 页面](https://github.com/berto-1974/ioBroker.solakon-one)

### IoBroker.go-e-charger
<img width="100" height="100" src="https://raw.githubusercontent.com/hombach/ioBroker.go-e-charger/master/admin/go-eCharger.png" />

**类别：**能源/电动出行 **开发商：**hombach

该适配器通过本地 HTTP API 集成一个或多个 **go-e-Charger 壁挂式充电盒**，并且还包含完整的 PV 剩余电量充电功能。

＃＃＃＃ 特征：
- 同一实例中可同时显示多个墙盒，轮询周期为 3 秒。
- **ChargeNOW** – 电流可调的即时充电
- **ChargeManager** – 光伏剩余电量充电，可根据太阳能功率、家庭用电量和家用电池 SoC 持续调整充电电流。
- 计算公式公开：可用功率 = 太阳能 - 房屋用电量 + 壁挂式充电桩功率 - 电网储备 + 电池奖励；每次循环变化限制为 1 安培。
- 从第三代硬件切换**单相/三相**
- 每张RFID卡的能耗统计数据，包括卡名
- 每个墙盒的**只读模式**：适配器不会发送任何控制命令。

#### 特色功能：
- 在 go-e 应用中，“HTTP API v1”必须激活；对于相位切换，还必须激活“HTTP API v2”。
- ChargeManager 目前仅设计用于**一个**壁挂式充电桩。
- 切勿超过墙盒和家庭用电系统的最大额定电流。

🔗 [适配器的 GitHub 页面](https://github.com/hombach/ioBroker.go-e-charger)

### IoBroker.tesla-wallconnector3
<img width="100" height="100" src="https://raw.githubusercontent.com/nobl/ioBroker.tesla-wallconnector3/main/admin/tesla-wallconnector3.png" />

**类别：**能源/电动出行 **开发商：**nobl

该适配器通过用户自身网络上的本地 API 读取 **Tesla Wall Connector Gen 3** 的实时数据。

#### 函数作用域：
- `vitals`：充电状态、车辆连接状态、电流、电压、温度、警报和未就绪原因

- **北美地区安装采用分相模式**

#### 特色功能：
- **所有状态均为只读**。Wallbox API 不允许写入访问。
- 轮询间隔过短会导致墙盒内置的 Web 服务器过载。

### IoBroker.bosch-smart-home-camera
<img width="100" height="100" src="https://raw.githubusercontent.com/mosandlt/ioBroker.bosch-smart-home-camera/main/admin/bosch-camera.png" />

**类别：** 多媒体 / 摄像头与安防 **开发商：** mosandlt

迄今为止，本阶段最广泛的新增功能：它集成了**博世智能家居摄像头**（Eyes Outdoor Gen1/II、360 Indoor、Eyes Indoor II），包括用于外部录像机的本地 RTSP 中继。

＃＃＃＃ 特征：
- 通过浏览器中使用 Bosch SingleKey ID 通过 **OAuth2-PKCE** 登录，刷新令牌以加密形式存储。
- **通过推送通知在几分之一秒内推送动作、人物和音频事件**，并自动回退到轮询和自动快照。
- 每个摄像头一个**本地RTSP流**（`rtsp://127.0.0.1:<端口>/rtsp_tunnel`），包含看门狗功能 – 可针对`cameras`适配器或外部录像机进行配置
- 可控制隐私模式、前置聚光灯、RGB洗墙灯、图像旋转、紧急警报和云台旋转，并可预设名称
- 对运动区域、隐私遮罩、自动化规则和固件安装具有写入权限
- 两个自定义的 **vis-2 小部件**（单摄像头和多摄像头概览），支持画中画功能

#### 特色功能：
- **无官方 API** – 该连接是通过逆向工程实现的，博世可随时更改。

## 论坛讨论和精彩测试帖
论坛非常活跃。以下几个帖子值得一看：

- **[测试适配器“Aura”](https://forum.iobroker.net/topic/84910/test-adapter-aura)** – 该测试主题帖拥有约 96 个回复和超过 10,000 次浏览，是目前为止最活跃的测试主题帖。Aura 是一款经过全面重新设计的可视化仪表盘，现已加入官方最新软件仓库，可直接从适配器目录安装。它包含约 50 个小部件、一个拖放式网格、多种主题以及一个状态概览，可自动检测电池电量不足、窗户未关、忘记关灯和离线设备。
- **[测试适配器 vis2-materialdesign V0.3.3](https://forum.iobroker.net/topic/85168/test-adapter-vis2-materialdesign-v0.3.3)** – 对于那些仍然因为 Scrounger 的 Material Design 小部件而停留在 VIS 1 的用户：此适配器可将整个小部件集原生移植到 vis-2，包括管理区域的主题编辑器和暗黑模式。真正的迁移方案。
- **[最新版 Victron GX 测试适配器](https://forum.iobroker.net/topic/84991/test-adapter-victron-gx-im-latest)** – 上述 Victron 适配器正在积极开发中。我们尤其需要具备三相系统和各种 BMS 测试经验的测试人员。

- **[更新至 Zigbee 3.5.5 后，百叶窗反向运行](https://forum.iobroker.net/topic/85178/nach-update-auf-zigbee-3.5.5-l%C3%A4uft-die-jalousie-falsch-herum)** – 所有使用 Zigbee 遮阳系统的用户请注意：更新后，部分用户的百叶窗出现反向运行现象，受影响的型号包括 TS130F 和 LoraTap SC500ZB 等。开发者 Asgothian 正在该帖子中分析此问题，但他本人并未拥有任何卷帘门执行器，因此只能依赖社区提供的测量数据。
- **[目前最好不要更新 Grafana](https://forum.iobroker.net/topic/85028/grafana-aktuell-lieber-nicht-updaten)** – 简短但有用：更新到 grafana-enterprise 13.1.1 会因 dpkg 错误而中止，并留下一个部分配置的软件包。

也值得一看：**[喷气框架](https://forum.iobroker.net/topic/85129/test-adapter-jetframe-v1.3.3)** 的测试线程、**[看板作为独立适配器](https://forum.iobroker.net/topic/85030/test-kanban-board)** 和无云的 **[Anker Solix 和 Solarbank 4 的 Modbus 连接](https://forum.iobroker.net/topic/85013/anker-solix-smartmeter-gen-2-anker-solarbank-4-modbus)**。
