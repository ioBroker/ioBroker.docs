In October, the latest repository grew from 812 to 835 adapters, and the stable repository now contains 693. We'll introduce you to 39 of these adapters in this issue, along with eleven familiar ones that have made the jump to the stable repository. However, the real story of the month is something else entirely: Rarely have so many adapters been updated to the stable repository at once as in October.

Who `stable` Users of Node.js will currently see an unusually high number of updates in the admin panel, many of them with a new major version number. **131 adapters received a new stable version in October** , including socketio, mqtt, history, influxdb, shelly, and the js-controller. Almost all of them now require **Node.js 22** , many even **22.19** . What you should know before clicking "Update" is explained below under **"The Big Stable Wave** ".

The new additions offer something for everyone: an adapter that identifies washing machines and dryers based solely on their power consumption curves, one that sorts Alexa's shopping list according to the route taken in the supermarket, and one that measures radon in the basement. And with **esphome,** one of the most widely used adapters has finally reached version 1.0.0 after more than five years, thus making its way into the... `stable` found.

Furthermore, this edition delivers what we announced in September under **"What we are currently working on** ": The sections in vis-2 are there, as is the security in the admin.

## Core updates

### ⚠️ First: Node.js 22.19

In September, this space still said "plans it." Now it's happening, albeit in a different way than expected. The js-controller itself doesn't yet require the new minimum version, but the current versions of **admin, javascript, devices, iot, cloud, and socketio** do: They require **Node.js 22.19 or later** , and this also applies to their new features. `stable` Versions 8.1.0 and later, and JavaScript versions 10.4.0 and later, also require **js-controller 7.2.5** .

So the order is: first update Node.js, then the js-controller, then the adapters. `iob diag` shows you which version is currently running.

### js-controller 7.2.5

Two versions in October; since October 16th, **version 7.2.5** has also been available in the `stable` (formerly 7.2.2).

- **Version 7.2.4** supports **Node.js 26.** Additionally, sessions are now saved correctly again, fixing unexpected logouts in Admin and Web. `info.connection` An instance is reset when it goes offline.
- **7.2.5** writes at `sendTo` **which user** sent the message. This sounds insignificant, but it's the basis for permission checks in admin and JavaScript, see below.

### ioBroker.admin 8.0.21 → 8.3.6

**More security, as announced.** Since **Admin 8.1.0,** the AI assistant works with the rights of the user asking the question. Endpoint, permissions, and confirmations are no longer inherited from the request. The log search and the info dialog of the MCP server require the necessary permissions. `execute` This information came from two external security researchers, thank you! The same hardening is included in JavaScript 10.4.0 and vis-2 2.20.

**Single Sign-On.** Starting with version 8.0.22, the administrator has a dedicated tab for Single Sign-On with issuer, client ID, and scopes. ⚠️ With **version 8.3.5,** login via this method has become more secure: Tokens are no longer displayed in the address bar and therefore no longer in the browser history. Users who had Single Sign-On enabled with an administrator account prior to version 8.3.4 should check the **Users** page to ensure that each link belongs to the correct account.

**One AI setting for everyone.** A new AI **tab** has been added to the system settings, allowing you to select providers, API keys, and models. The AI Assistant in the Admin panel uses this tab, as does the AI Chat in the JavaScript adapter (from version 10.4.8 onwards). OpenRouter is also available from version 8.3.6, and users with a local model can simply enter an OpenAI-compatible server.

### ioBroker.vis-2 2.15.8 → 2.20.5 (only) `latest`)

The biggest new feature in this edition, and one we already announced in September. Important note: **vis-2 2.20 is currently only available in the `latest`.** In the `stable` It says 2.15.8.

**Sections.** A page in grid layout now consists of sections. Each has its own header with a title, subtitle, and icon, as well as a background, border, rounded corners, and optionally a glass effect. A section can be collapsed, even via a state, and the browser remembers the choice. It can be shown only to specific user groups, only above a certain width, or only while a state meets a condition. All properties can be bound to data points, and you can easily move sections with the mouse.

In October, **131 adapters** received a new `stable` received the -version, a large part of it in the week of October 12th to 19th. ### ⚠️ Read before updating

With these adapters, you need to do something or at least know something during the update:

- **ring 6.4.0 → 7.0.2:** The refresh token must be **re-entered** once; it is now stored encrypted. Devices previously running under `unknown_<id>` lay `doorbell_<id>` or `stickup_<id>` Newly created. The old objects remain and can be deleted manually.
- **SolarEdge 1.4.1 → 2.0.0:** SolarEdge deactivated the old interface on **November 1st** . Version 2.0.0 uses the new API v2, for which you need a **new API key** from the SolarEdge developer portal. The energy flow (`currentPowerFlow` Requires a Business Pro or Enterprise subscription or login via OAuth2 Site Access. More information in the [test thread.](https://forum.iobroker.net/topic/85581/test-adapter-solaredge-2.0)
- **cul 2.2.0 → 3.0.3:** Data points have been renamed: `battery` will `batteryLow` and `batteryState`, `window` and `isopen` to `open`, `valveposition` to `valvePosition` Please adjust scripts, visualizations, and aliases. The installation no longer requires build tools.
- **sonoff 3.3.0 → 5.1.1:** The **roles** of the objects have changed, `Switch1` until `Switch28` are now only readable. Anyone assigning aliases, voice assistants, or visualizations via roles should check. The adapter logs the data points created by version 3.3.0 with incorrectly shortened names at startup; these can be deleted.
- **shelly 10.6.1 → 12.0.0:** Requires **js-controller 7.2.2** and **Admin 8.0.11** . Timer, transition, and boost times are now displayed in milliseconds. This was previously the case on some Gen3 and Pro devices. `Relay0.Switch` A firmware bug caused inversion, which the adapter now corrects. Anyone who has compensated for this in scripts should check their work. The PLUG\_UI functions are disabled due to hardware issues.
- **Scenes 4.0.4 → 5.1.0:** The new **"Only on change"** option is enabled by default for triggers. If a trigger with the same value is written again, the scene will no longer start. Users who need the old behavior can disable the option for each trigger. A new feature is protection against infinite loops, which deactivates a scene that has been triggered too often.
- **Frigate 1.4.0 → 3.2.2:** All ON/OFF data points are now true Boolean values. Requires js-controller 7.1.0 and Admin 7.8.28
- **vis-2-widgets-energy 1.0.2 → 2.0.1:** The comparison widget no longer automatically converts from W to Wh or kW to kWh. Users who wish to scale the widget should use the "factor" field.
- **InfluxDB 4.0.2 → 5.1.8:** With version 5.1.6, some users experienced a log file filling up with the error message "invalid float value for field 'q'". This was caused by data from version 4 in the buffer. **Version 5.1.7** converts this data. `stable` Version 5.1.8 is now available. Anyone still on 5.1.6 should simply update.

Minor points to be aware of: **MQTT** no longer stores binary messages in data points; instead, there's the "Binary topics" option. **OpenWeatherMap** now provides daily rainfall and snowfall as a total instead of an average. **hm-rpc** displays the color temperature. `WHITE` from lamps connected to the CCU Lighting Gateway in Kelvin. **Telegram** has lost its polling interval setting and can now run via a proxy. **IoT 7.1.6** re-registers roller shutters with Alexa; existing Alexa routines involving roller shutters need to be edited once. And with the **mcp** adapter, tools now run with the logged-in user's privileges.

### What they all have in common

- **Node.js 22 is mandatory** ; 17 of the major adapters require 22.19 or newer. Furthermore, s7 only runs up to Node.js 24.
- **js-controller 6.0.11** is the new minimum; shelly and mihome-vacuum want 7.2.2.
- **Admin version 7.6.20** or newer is required almost everywhere. With the current version... `stable` (js-controller 7.2.5, Admin 8.3.5) is all of this fulfilled?

Anyone still using Node.js 20 or an early version of 22 should therefore update Node.js first and only then the adapters. And as always: make a backup beforehand, and in case of problems, any version can be reinstalled via the administrator account.

Besides the mandatory points, there's a lot that's worthwhile:

- **MQTT 8:** MQTT 5.0 in server and client mode, authentication with SCRAM-SHA-256, and configurable how received values are interpreted.
- **History 5 and InfluxDB 5:** a **data browser** in the instance configuration for viewing, editing, and deleting values, plus a **statistics** tab with storage usage and cleanup options. InfluxDB can optionally start InfluxDB and Grafana as containers and can write custom tags for each data point.
- **shelly 12:** Device management with control and setup of new devices, a Bluetooth map and many new devices, including the Gen4 series

- **xterm 4:** multiple terminal sessions that survive a reload or connection interruption
- **MCP 1.5:** Login via OAuth for MCP clients and ready-made instructions for ChatGPT and Claude
- **Frigate 3:** Manage Frigate as a container from the adapter, license plate and face names as data points
- **ping 3.1:** optional TCP check, for example for LXC containers, and a notification if the host is not allowed to send ICMP at all.
- **LGTV 3:** Support for webOS 26 and a remote control as a tab in the settings.
- **Modbus 9.2:** Modbus/UDP as master, import and export of register tables as CSV or JSON, and a proxy mode.
- **devices 4.2:** Connection to the ioBroker Device Manager and finally a widget for TVs with remote control

## Important adapter updates

### ioBroker.javascript 10.4.0 → 10.4.8

The `execute` The message used to execute a script with a full ioBroker interface now checks who is sending it. If the js-controller includes the user (from version 7.2.5 onwards), that user needs permission for host commands. The AI endpoint now only comes from the configuration, so a proxy in front of OpenAI must be entered there.

The AI chat in the editor now reliably delivers long answers, can be maximized, and recognizes an open Blockly script as context. Here are some important fixes: An uncaught error... `setStateAsync` was able to terminate the entire adapter, `onObject()` with `*` never responded, and `stopScript()` The script didn't actually stop. `stable` The version is now 10.4.4.

### ioBroker.assistant 1.0.2 → 1.3.0

The Smart Assistant, which we presented in detail in the article ["AI in ioBroker](https://www.iobroker.com/blog/2026_10_26) ," saw seven versions in October alone. It has been available since October 19th. `stable`.

**What actually happened during a request?** Clicking on a response in the Chat tab opens the **request details** : question and answer, duration, tokens used, data points read and written, and below that, the complete step-by-step process. You can see whether the local rule recognition understood the question, which tools the language model called, and where the time went. In the example below, the local recognition couldn't categorize the question, the language model read six data points in one round, and responded after 9.4 seconds. If you want to know why the assistant didn't understand something or understood it incorrectly, you can find the answer here.

**A conversation instead of individual commands.** The assistant remembers what was just discussed. In the example below, the temperature was requested via voice command through an ESPHome speaker, and the local rule detection incorrectly selected the wrong sensor – the water temperature. The correction, "I didn't want to know the water temperature, but the outside temperature in the cockpit," is sent to the voice model. #### ioBroker.sehybrid

<img width="100" height="100" src="https://raw.githubusercontent.com/heresiarch/ioBroker.sehybrid/main/admin/sehybrid.png" />

**Category:** Energy **Developer:** heresiarch

Reads PV, battery, and meter data from SolarEdge hybrid inverters (Home Hub) locally via Modbus TCP and makes the control block for the storage system writable. Ideal for anyone who wants to control their storage system themselves via script. Especially useful since SolarEdge has discontinued its old cloud interface.

### Laundry room, kitchen and shopping

#### ioBroker.laundrylens

<img width="100" height="100" src="https://raw.githubusercontent.com/backfisch88/ioBroker.laundrylens/main/admin/icon.png" />

**Category:** General **Developer:** backfisch88

Arguably the smartest new addition in this issue. LaundryLens uses the power curve of a smart plug to determine which program your washing machine or dryer is currently running, estimates the remaining time, and notifies you when the laundry is finished. No manufacturer cloud and no pre-configured profiles: the adapter learns your appliance's settings. With 81 installations, it's the most widely used new product in this issue. `latest`.

##### Features:

- It recognizes start, run, pause and end and assigns the program by comparing curves, with a hit rate that increases over several runs.
- Each program is learned on the individual device; three to five passes are recommended.
- Remaining time based on previous runtime and current performance, plus progress, phase and energy of the last run.
- A dedicated tab in the admin panel includes a cycle list and performance graph; records can be shortened and shared.
- Notifications via Telegram, Pushover, Signal, WhatsApp, Matrix, email and others, with placeholders for any data points.

##### Special features:

- Each device requires a measuring socket and its own instance.
- Still Alpha, tested with a Siemens washing machine and dryer; other brands may need fine-tuning.

## Farewells

Five adapters were removed from the repositories or moved in October. Existing installations will continue to run, but will no longer receive updates via the repository.

- **device-reminder** is from the `stable` has been removed and will later also be removed from the `latest` Disappear. With over 3,100 installations, this is the biggest case. The developer hasn't maintained it for a long time; the last version is almost three years old. Anyone who wants to be notified when their washing machine or dishwasher has finished will find two alternatives in this issue: **laundrylens** and **device-monitoring** . [Announcement in the forum](https://forum.iobroker.net/topic/85602/deprecated-adapter-device-reminder) .
- **Easee** has moved to the ioBroker community adapters. Easee changed its interface on September 1st; version 1.0.10 has not worked since then and has therefore been removed from the \[network/platform/etc.]. `stable` It has been taken over. ## Do you want to join us next time?

We now automatically find new adapters via the repositories; you don't need to do anything for that. However, there are two things we'll miss if you don't tell us:

**New features in existing adapters.** A new adapter stands out, a new feature in a familiar adapter doesn't. If you've built something you're proud of, add it to `docs/en/history/history.md` either post it or write it in the forum.

**Your own description.** What we write here is based on the README and the... `io-package.json` Anyone who contributes two sentences will have exactly the words they consider appropriate included in their post.
