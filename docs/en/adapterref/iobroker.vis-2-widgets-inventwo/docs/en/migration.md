# Migrating inventwo vis-1 widgets

If you imported a vis-1 project into VIS 2 that uses the old widgets of the adapter **vis-inventwo** (templates `i-vis-*`), the settings of this adapter can convert them into the VIS 2 widgets of this set.

The migration is an assistant, not a one-click solution: common cases are converted completely, others only partly, and a few widgets are not converted at all. After the migration you get a list of everything you should check by hand.

> The idea and parts of the mapping are based on the community tool [inventwo-vis1-to-vis2](https://github.com/crunchip77/inventwo-vis1-to-vis2) by crunchip77.

> **No guarantee:** The migration was built with care, but we cannot promise that it works flawlessly for every project — vis-1 projects come in too many different shapes for that. Always keep the original (new project or backup, see below) and check the result. If something is not converted as expected, please [open an issue](https://github.com/inventwo/ioBroker.vis-2-widgets-inventwo/issues) and describe the widget and its settings. Your feedback helps to improve the tool.

---

## How to use it

1. Import your vis-1 project into VIS 2 (if not done yet).
2. **Close the VIS 2 editor** of this project. An open editor may overwrite the result.
3. In ioBroker Admin open **Instances** and the settings of `vis-2-widgets-inventwo`.
4. Under **1. Project** select the **VIS 2 project**.
   - **Name of the new project** (optional): with a name, the project is copied with all its files to a new project and converted there — the original stays untouched. Without a name, the project itself is overwritten (a backup is saved first, see below).
   - **Original vis-1 project** (optional): select it if widgets are missing after the import (see [Widgets missing after the import](#widgets-missing-after-the-import)).
5. Click **Analyse**. Nothing is changed yet — you only see a preview:
   - how many widgets can be converted without rework,
   - how many can be converted but must be checked,
   - how many cannot be converted and stay unchanged.
6. Click **Convert project …** or **Create project …** and confirm.
7. Reload VIS 2 and work through the list **Converted widgets to be checked**.

The section **What can be converted?** at the top of the page lists all supported widgets.

With **Download report** you can save the result as a JSON file.

---

## Backup and undo

If you convert a project in place (no new name), the original `vis-views.json` is saved in the project folder as `vis-views-backup-inventwo-<date>-<time>.json`. The project is only overwritten after this backup was written and read back successfully.

If you wrote the result into a new project, there is nothing to undo: the original project is unchanged, and you can simply delete the new one.

To undo an in-place migration, open the tab **Files** in Admin, go to `vis-2.0/<project>/` and replace `vis-views.json` with the backup file.

---

## Widgets missing after the import

vis-1 stores a widget that is shown in several views once per view, with the view name appended to its ID (e.g. `w00220_02_EG`). VIS 2 removes every widget with an underscore in its ID when it loads a project, so after the import these widgets are gone — the tiles are missing in the editor and the widget list is shorter than before.

To get them back, select the original project under **Original vis-1 project (optional)**. It is only used as reference and is not changed. It must still exist in vis-1 (file storage `vis.0`). The assistant then adds each of these widgets once and enters the other views in its attribute **Show in views** — the way VIS 2 stores such widgets. The restored widgets are listed in the preview and are converted in the same run.

## What is converted

| vis-1 widget | VIS 2 widget | Result |
|---|---|---|
| Universal — Switch | Universal Widget, type *Switch* | complete |
| Universal — Background | Universal Widget, type *Read only* | complete |
| Universal — Navigation | Universal Widget, type *Nav* | complete |
| Universal — View in popup | Universal Widget, type *View in dialog* | complete |
| Universal — State | Universal Widget, type *Button* | check value and click behaviour; a reset time is taken over as *Reset value after (ms)* |
| Universal — Increase/decrease value | Universal Widget, type *Increase/decrease value* | check step value |
| Universal — HTTP | Universal Widget, type *Send HTTP request / Open URL* | check URL |
| Universal with analog clock | Universal Widget, content *Analog clock* | check clock face, time zone is not taken over |
| Multi | Universal Widget with several states | check conditions and look of the states |
| Switch, Switch small | Universal Widget, type *Switch* | complete |
| Background, Background small | Universal Widget, type *Read only* | complete |
| Button, Button small | Universal Widget, type *Button* | complete |
| Navigation, Navigation small | Universal Widget, type *Nav* | complete |
| Image, Image (new) | Universal Widget, content *Image* | check scaling, colors and shadow |
| Radio button list | Universal Widget with *separated buttons* | check size and spacing |
| Color picker | Universal Widget, content *Color picker* | check data points and shown elements |
| Checkbox | Checkbox Widget | only the first checkbox of the widget; look is not taken over |
| Switch basic | Switch Widget | only the first switch of the widget |
| Switch (rocker) | Switch Widget | check size and colors |
| Value list | Value List Widget | complete (some list styles do not exist) |
| Marquee | Marquee Widget | set the speed again |
| JSON table | Table Widget | columns, formats and colors are taken over; check the look |
| Slider (simple) | Slider Widget | check labels and value display |

Colors (including the hover colors for background, border and shadows; for the radio button list the hover background color), texts, images, corner radius, shadows, borders, alignment, spacing and opacity of the Universal and Multi widgets are taken over. The text size and the text shadow are moved to the CSS settings of the widget (`font-size`, `text-shadow`).

### Not converted

The color sliders (`i-vis-slider-color-hor`, `i-vis-slider-color-vert`) have no counterpart. They stay unchanged and are listed under **Widgets without conversion**.

Not available in VIS 2 and therefore dropped: the digital clock, the separate datapoint for closing a dialog, the matrix arrangement of radio buttons, thresholds per table cell, the rotation of sliders.

A dialog can still be closed by datapoint in VIS 2: it follows the **Object ID** of the widget and is open only while that datapoint holds **Value true** (see [Interaction types](/#/docs/adapterref/iobroker.vis-2-widgets-inventwo/docs/en/widgets/universal/interaction-types.md#view-in-dialog)). Only the additional close datapoint of vis-1 has no counterpart.
