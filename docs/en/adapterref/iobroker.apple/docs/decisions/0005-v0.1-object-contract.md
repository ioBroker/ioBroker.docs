# ADR 0005: Version 0.1 Object And Command Contract

- Status: accepted; device root amended by ADR 0010, enablement amended by ADR 0011, roles and Apple TV volume amended by ADR 0019
- Date: 2026-08-31

## Context

The accepted Apple TV PoC now permits the first adapter vertical slice. The
ioBroker object tree is a public API consumed by automations and visualizations,
so its IDs, types, roles, write behavior, and acknowledgement semantics must be
fixed before the protocol backend writes states.

Version 0.1 controls discovered Apple TV devices only. HomePod and generic
AirPlay receivers are classified and counted but do not yet receive individual
device objects or controls. Apple Music, streaming, groups, scenes, accounts,
outputs, and the generic JSON command endpoint remain outside this release.

## Decision

Use `devices.appletv.<deviceId>` for one physical Apple TV, where `deviceId` is
the lowercase normalized 12-character AirPlay device identifier. Display names
and network addresses never participate in the object ID.

The device object's `common.name` is a readable `AppleTV <display name>` label,
for example `AppleTV Living Room`. The technical object ID remains stable so a
rename, duplicate display name, or localization change does not break scripts.

The public `devices.*` tree contains active, persistently paired Apple TVs only.
Unpaired devices remain available as transient Admin pairing candidates but do
not create durable object trees. Passive devices retain their pairing and Admin
inventory entry but are disconnected and have no individual public tree. On
startup the adapter removes current Apple TV trees that have no corresponding
pairing that is enabled. Explicitly forgetting a pairing removes the complete
device root and later discovery alone does not recreate it. ADR 0011 defines
the durable enablement format and default-active upgrade behavior.

The instance-level contract is:

| State                   | Type    | Role                  | Read | Write |
| ----------------------- | ------- | --------------------- | ---- | ----- |
| `info.connection`       | boolean | `indicator.connected` | yes  | no    |
| `info.discoveryRunning` | boolean | `indicator.working`   | yes  | no    |
| `info.lastDiscovery`    | number  | `value.time`          | yes  | no    |
| `info.deviceCount`      | number  | `value`               | yes  | no    |
| `info.lastError`        | string  | `text`                | yes  | no    |

`info.deviceCount` is the total of the three exclusive discovery classes.
Class-specific totals are exposed as read-only numbers at
`devices.appletv.info.deviceCount`, `devices.homepod.info.deviceCount`, and
`devices.airplayReceiver.info.deviceCount`. HomePod and AirPlay Receiver have
no further runtime objects in this milestone.

| `lastCommand.status`       | string  | `text`                | yes  | no    |
| `lastCommand.error`        | string  | `text`                | yes  | no    |
| `lastCommand.completedAt`  | number  | `value.time`          | yes  | no    |

Durations and positions use seconds. Volume uses percent from 0 through 100.
Unknown or absent textual metadata is represented by an empty string; unknown
numeric metadata is zero. Public connection states are `discovered`,
`pairingRequired`, `connecting`, `online`, `degraded`, `recovering`, and
`unavailable`.

Only Apple TVs whose current backend reports the corresponding capability
receive writable controls. Directional and menu buttons live below `remote`,
media transport below `playback`, and wake/suspend below `power`.
`power.powerOn` and `power.powerOff` map to the SDK wake and suspend HID
operations. Volume uses the read-only `value` role until the active
backend reports volume control, then `volume.level` is reconciled as writable
`level.volume` and maps to the SDK absolute volume controller. ADR 0019 defines
this role split.

All backend projections and command results use `ack=true`. The adapter handles
only capability-created `remote.*`, `playback.*`, and `power.*` writes with
`ack=false` and boolean value `true`. It serializes
commands per target, checks the current connection and capability, executes the
typed backend command, records a stable result, then resets the button to
`false` with `ack=true`. A failed command is never represented as successful
state feedback.

Connection and command errors exposed in states are stable project codes, not
raw upstream messages. Version 0.1 uses `not_paired`, `not_discovered`,
`not_connected`, `unsupported`, `busy`, `timeout`, `protocol_error`, and
`unavailable`.

## Consequences

Automations and visualizations receive stable scalar states without Apple
protocol types. Unpaired network candidates no longer leave stale public device
objects; they enter the tree only after pairing completes. Device classes are
visible before their control backends exist, without creating speculative
device objects. Later volume, account, output, generic command, and scene APIs
require new capability evidence plus an ADR update and migration review.

## Validation

Contract tests must verify every object definition, type, role, read/write flag,
unit/range, idempotent reconciliation, readable device labels, `ack=false`
command handling, `ack=true` projection, independent remote/playback/power
capability gating, power-command dispatch, command serialization, discovery
class counts, and stable errors.
Integration tests must verify restart and unload behavior. Real-device
acceptance must verify both wake and suspend before power control is described
as hardware-validated.
