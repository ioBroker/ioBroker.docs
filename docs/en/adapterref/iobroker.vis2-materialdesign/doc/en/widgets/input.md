# Input

[User guide](/#/docs/adapterref/iobroker.vis2-materialdesign/doc/en/README.md) › [Widget catalog](/#/docs/adapterref/iobroker.vis2-materialdesign/doc/en/widgets/README.md) · [Deutsch](https://github.com/typhosj/ioBroker.vis2-materialdesign/blob/master/doc/de/widgets/input.md)

A native VIS 2 field for entering text or numbers. Template id:
`tplVis2-materialdesign-Input`.

<img src="../../media/vis2_input_runtime.png" alt="Material Design input field in VIS 2">

## Editor settings

The screenshot shows the **Common** and **layout input** groups expanded.
Settings not listed below are self-explanatory. The editor UI follows the
ioBroker system language, so the screenshots are German.

<img src="../../media/vis2_input_editor_overview.png" width="340" alt="Input general and layout options">

**Common**

- **Object ID** – the state the input is written to.
- **input type** – `text`, `number`, `date`, `time` or `mask`. `number` writes a
  number, everything else writes text; a number field cleared by the user writes
  nothing instead of putting a 0 into the state.
- **input mask** – for the `mask` input type only. Placeholders: `#` digit,
  `S` letter, `A` letter uppercased, `a` letter lowercased, `N` digit or letter,
  `X` any character. Every other character is a fixed separator, so `##:##`
  gives a time entry.
- **max length** – caps the entry and supplies the number behind the slash in the
  counter.
- **picker** – for `date` and `time` only. `browser (native)` uses the browser's own
  field and picker, whose language and 12/24-hour format the browser decides.
  `Material picker` shows the value in the format of the device language, keeps the
  field typable with a matching mask (`##.##.####` in German, `##/##/####` in US
  English) and opens a Material 3 calendar or clock dial from the icon at the end of
  the field. The state still receives `YYYY-MM-DD` or `HH:MM`.
- **time format** – for `time` with the Material picker: `locale` (12 or 24 hours
  as the device language has it), `24 hours` or `12 hours`.

`text`, `number` and `mask` write on leaving the field or on Enter, `date` and
`time` write right after picking a value. With the Material picker, typed text is
written on leaving the field or on Enter and the picker writes on OK; text that is
no valid date or time is not written.

**picker** (Material picker only)

- **background color, accent color, text color, text color on accent** – colors of
  the picker dialog. Empty, the Material 3 colors of the theme apply. The calendar or
  clock icon in the field takes the color of the **text delete icon**.

**layout input**

- **layout** – `regular`, `solo`, `solo-rounded`, `solo-shaped`, `filled`,
  `filled-rounded`, `filled-shaped`, `outlined`, `outlined-rounded` or
  `outlined-shaped`.
- **text alignment** – `left`, `center` or `right` for the entered text.
- **auto focus** – the field takes the focus when the view loads.
- Background, border and text colors each cover the normal, hovered and selected
  state.

**label of input**

- **text** – the floating label above the field.
- **offset x / offset y** – move it when it collides with an icon.

**appendixs of the input**

- **prepended text / appended text** – fixed text left or right inside the field,
  a unit for example. It is not written to the state.

**sub text of input**

- **text** – hint line below the field.
- **always show** – switched off, the hint only appears while the field has the
  focus.

**counter layout**

- **show counter** – shows the character count in the bottom right, as `12 / 30`
  once **max length** is set.

**icons**

The **text delete icon**, the **prefixed icon**, the **inner prefixed symbol**,
the **appended symbol** and the **outer appended symbol** each take an icon or an
image plus size and color.

<img src="../../media/vis2_input_editor_icons.png" width="340" alt="Input icon fields">

To pick from a list of values use the [Select](/#/docs/adapterref/iobroker.vis2-materialdesign/doc/en/widgets/select.md) widget instead.

## Read only, locking and PIN

**Read only** can be bound to a state: the checkbox next to it and vis-2's binding symbol switch the field to a binding. `{0_userdata.0.automatik}` blocks the widget while the state is on; `{a:0_userdata.0.automatik;!a}` inverts that and blocks it while the state is off. A bound string `true` or `1` counts as on. A read-only field shows no lock icon. Read only always wins over the lock: a read-only widget reacts to nothing and opens no PIN pad. Autofill ticks the box only for a non-writable object and never overwrites a binding.

**Locking** (group under **show advanced options**): **enable Locking**, **auto Locking after [s]** (1 s to 24 h, default 10), **PIN**, **icon** and **icon color**. While locked, the field is read-only and shows a lock icon at the end; a tap unlocks (or asks for the PIN) and puts the focus into the field. A focused field, an open menu or a drag in progress is never locked under your fingers; the widget locks once that ends.

<img src="../../media/vis2_input_locked.png" width="270" alt="Locked input field with the lock icon at its end">

**PIN** (all widgets with a lock): 1 to 12 digits, empty means no PIN. With a PIN, a tap on the locked widget opens a pad with the keys 1 to 9, Cancel, 0 and Delete; it checks as soon as the PIN is complete, shakes and clears on a wrong PIN. A hardware keyboard works too (digits, Backspace, Escape). The right PIN unlocks every widget with the same PIN in this browser until the lock time ends; a reload locks everything again. The PIN can be bound to a state to keep one central PIN. If the PIN is not 1 to 12 digits, or a bound PIN is empty, the widget stays locked and the pad says "PIN not set up". The editor already marks a typed invalid PIN in red; correct or clear it there. A numeric state loses leading zeros (0123 becomes 123); use a string state for such PINs. In the editor the pad never opens.

<img src="../../media/vis2_pin_pad.png" width="230" alt="PIN pad with two of four digits entered">

**Not a security feature:** the PIN stands in clear text in the project and in the state, and anyone who can write states bypasses every lock. It protects against accidental taps and children, not against attackers.
