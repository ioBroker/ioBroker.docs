# Глоссарий

При работе с ioBroker вам придётся столкнуться с рядом терминов, которые необходимо знать для понимания руководств и сообщений на форуме. Вот они, в алфавитном порядке.

- **адаптер**

  Модуль для устройства, сервиса или функции. Поскольку ioBroker полностью состоит из модулей, почти всё является адаптером: административный интерфейс, визуализация, выполнение скриптов. См.
  [Контроллер и адаптер](/docs/basics/adapter.md).

- **Администратор**

  Адаптер, предоставляющий веб-интерфейс, обычно работающий на порту 8081, обрабатывает всё: установку адаптеров, создание экземпляров, просмотр объектов и написание скриптов. См.
  [Административный интерфейс](/docs/admin/README.md).

- **Псевдоним**

  Виртуальная точка данных, указывающая на реальную. Это позволяет изменять имя, роль и единицу измерения внешней точки данных без модификации адаптера. См. [Псевдоним](/docs/basics/alias.md).

- **Резервная копия**

  Резервная копия установки. Резервная копия ioBroker содержит объекты, состояния и конфигурации. **нет** но зафиксированные измерения. См. [резервное копирование данных](/docs/config/backup.md).

- **Блокли**

  Графическое программирование: скрипты собираются из отдельных блоков, а не пишутся вручную. При сохранении получается JavaScript-код, который затем выполняется. Знания в области программирования не требуются.

- **ОИТ**

  _Центральный блок управлени&#x44F;_&#x426;ентр управления умным домом eQ-3 для Homematic. Текущая версия — CCU3. Он может использоваться для управления устройствами Homematic и Homematic IP, как беспроводными, так и проводными.

- **Точка данных**

  В разговорной речи это позиция, где находится значение. Точнее, она состоит из двух частей: **объект**, которая описывает значение и **Состояние**, который его содержит. См. [Условия](/docs/basics/states.md).

- **Устройство**

  Английский _устройств&#x43E;_&#x423;ровень в дереве объектов, обычно расположенный непосредственно под адаптером, который суммирует все каналы и состояния устройства.

- **Homematic**

  Система «умный дом» от eQ-3, широко используемая в Германии. Устройства подключаются через блок управления (CCU).

- **Хозяин**

  Компьютер, на котором работает ioBroker. В многохостовой конфигурации их несколько.

- **Пример**

  Непрерывный процесс работы адаптера. Большинство адаптеров позволяют использовать несколько адаптеров, так что, например, можно настроить два Hue Bridge отдельно. Номер экземпляра находится в начале дерева объектов: `hue.0` и `hue.1`Видеть
  [Контроллер и адаптер](/docs/basics/adapter.md).

- **JavaScript**

  Язык программирования, на котором написаны ioBroker и его адаптеры, а также на котором вы можете писать собственные скрипты.

- **js-контроллер**

  Основной процесс ioBroker. Он управляет двумя базами данных, запускает экземпляры, отслеживает их работу и перезапускает в случае ошибок. См.
  [js-контроллер](/docs/dev/controller.md).

- **jsonl**

  Формат файлов по умолчанию для двух внутренних баз данных. Это решает старую проблему. `file`—формат и значительно быстрее. См.
  [Редис](/docs/config/redis.md).

- **канал**

  Уровень, группирующий связанные состояния, обычно расположенный ниже устройства. Устройство может иметь несколько каналов.

- **категория**

  Английский _перечислени&#x435;_&#x421;писок предметов, которые относятся друг к другу: вся бытовая техника в комнате, все лампы в доме. См.
  [Категории](/docs/basics/enums.md).

- **Многохостовый**

  Например, для распределения нагрузки или использования интерфейса, подключенного только к определенному устройству, используется несколько компьютеров. Один хост управляет базами данных, а остальные подключаются к нему. См.
  [Многохостовый](/docs/config/multihost.md).

- **Node-RED**

  Графическое программирование путем объединения готовых модулей в последовательность. Альтернатива Blockly, имеющая собственный интерфейс.

- **объект**

  Описание точки данных: имя, тип данных, единица измерения, роль, доступность для чтения и записи. Сам объект редко меняется, но его состояние остается постоянным. См. [объекты](/docs/basics/objects.md).

- **Редис**

  База данных, хранящая свои данные в оперативной памяти. В ioBroker её можно дополнительно использовать для хранения состояний системы, что значительно сокращает количество операций записи на карту памяти или диск в более крупных системах. См.
  [Редис](/docs/config/redis.md).

- **Репозиторий**

  Список, из которого поставляются адаптеры. Их два: _стабильный_ для регулярной эксплуатации и _бета_ для тестирования. См.
  [Репозитории](/docs/basics/repositories.md).

- **роль**

  Что обозначает каждое значение: переключатели, температура, яркость. Пользовательские интерфейсы и голосовые помощники соответствующим образом настраиваются. См.
  [Роль точек данных](/docs/basics/roles.md).

- **Состояние**

  См. состояние.

- **вис / вис-2**

  Визуализация: пользовательские интерфейсы, состоящие из виджетов.
  **вис-2** Это преемник и правильный выбор для новых проектов. См.
  [Визуализации](/docs/viz/README.md).

- **Виджет**

  Элемент управления в визуализации. Он отображает или управляет состоянием, например, переключатель, изменяющий свой внешний вид.

- **Состояние**

  Английский _состояни&#x435;_&#x422;екущее значение точки данных, а также метка времени, время последнего изменения и индикатор подтверждения (`ack`). Видеть [Условия](/docs/basics/states.md).
