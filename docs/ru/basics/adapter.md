# Контроллер и адаптер

ioBroker состоит из двух типов программ: **js-контроллер** и
**Адаптеры**Контроллер обеспечивает целостность системы; адаптеры же выполняют её основные функции.

## js-контроллер

Контроллер JavaScript — это ядро каждой установки. На каждом хосте работает ровно один такой контроллер. Он написан на TypeScript и выполняет четыре задачи:

| Задача                 | Что за этим стоит?                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- |
| Управление экземпляром | Эта программа запускает и останавливает экземпляры, а также перезапускает их по мере необходимости.             |
| Сохранение данных      | Он управляет двумя базами данных: одной для объектов и другой для состояний.                                    |
| коммуникация           | Все экземпляры обмениваются данными через него, а не напрямую друг с другом.                                    |
| наблюдение             | Он сообщает о том, когда экземпляр больше не запущен, когда заканчивается память или когда доступно обновление. |

Контроллер JavaScript отсутствует во вкладке. **адаптер** Обновлено, но через вкладку. [Хозяева](/docs/admin/hosts.md)
или через командную строку. Подробная информация доступна по адресу:
[Обновить ioBroker](/docs/install/updateself.md).

## адаптер

Адаптер соединяет систему с ioBroker: устройство, сервис, протокол или даже просто источник данных в интернете. Внешне он говорит на языке подключенной системы; внутри он хранит данные в виде объектов и состояний. Таким образом, он выступает в качестве интерфейса между ioBroker и всем, что не является частью ioBroker.

Функциональность адаптера зависит от его предназначения. Типичные примеры:

- **Получить данные.** Измерения, состояния и сообщения от подключенной системы сохраняются в ioBroker в виде точек данных.
- **Руль.** Включайте и выключайте устройства, устанавливайте значения, отдавайте команды.
- **Записывать.** Сохраняйте значения для последующей оценки, например. `history`,
  `influxdb` или `sql`.
- **Визуализируйте.** Предоставьте поверхности, например. `vis-2` или `iqontrol`.
- **Автоматизируйте.** Запуск процессов в соответствии с условиями или расписанием, например.
  `javascript` или `scenes`.
- **Уведомить меня.** Отправляйте сообщения, например. `telegram` или `email`.
- **Присматривать за.** Создавайте резервные копии, обновляйте прошивку, осуществляйте мониторинг системы.

К числу известных примеров относятся адаптер Zigbee для радиосвязи, адаптер MQTT для всего, что использует этот протокол, а также адаптер JavaScript для пользовательских скриптов и Blockly.

### Преимущества

- **Гибкость.** Подключить можно практически любую систему, независимо от используемого протокола.
- **Расширяемость.** Новые адаптеры добавляются для новых устройств без каких-либо изменений в процессе установки.
- **Централизация.** Все взаимосвязанные системы управляются в одном месте и могут быть объединены между собой.

### Категории адаптеров

Каждый адаптер имеет категорию, которая определяет порядок отображения списка на вкладке.
**адаптер** фильтруемый: `alarm`, `climate-control`, `energy`, `hardware`,
`lighting`, `logic`, `multimedia`, `weather` и многое другое. Полный список с пояснениями доступен по адресу:
[публиковать адаптеры](/docs/dev/adapterpublish.md).

## Пример

Установленный адаптер пока не работает. **Пример** После создания будет работать только этот экземпляр. Он содержит конфигурацию, такую как адрес шлюза или учетные данные доступа.

Адаптер может существовать в нескольких экземплярах. Это всегда полезно, когда одна и та же система существует несколько раз или когда задачи должны оставаться раздельными. `hm-rpc.0` для радиоинтерфейса и `hm-rpc.1` для проводников, два `telegram`— Экземпляры для двух групп получателей.

Каждый экземпляр получает собственное пространство имен в дереве объектов, состоящее из имени адаптера и порядкового номера, например: `hm-rpc.0`Затем экземпляр размещает свои устройства, каналы и точки данных в рамках этой структуры.

Экземпляры создаются и настраиваются на вкладке
[Пример](/docs/admin/instances.md)Более подробную информацию о структуре данных можно найти по адресу:
[объекты](/docs/basics/objects.md) и
[Условия](/docs/basics/states.md).
