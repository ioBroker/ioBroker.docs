# объекты

В ioBroker существует два типа информации, и разница между ними объясняет почти все остальное:

- **объекты** описывать, _Что_ Что-то есть. Они редко меняются: название, единица измерения, указание на то, можно ли что-то прочитать или написать.
- **Условия** Сами значения составляют -23,5 °C. `true`«Гостиные». Они постоянно меняются. Они представлены на отдельной странице:
  [Условия](/docs/basics/states.md).

Таким образом, термометр — это не "21,3". Это предмет, который показывает: _Вот число, оно измеряется в градусах Цельсия, его можно прочитать, но нельзя записать, и оно называется «температура в гостиной»._ Значение 21,3 зависит от этого.

## Адрес: ID

Каждый объект имеет идентификатор (ID). Он имеет иерархическую структуру и разделяется точками — как путь к файлу, только вместо косых черт используются точки.

```
hm-rpc.1.ABC110022.2.VALUE
```

| Часть       | Значение                                       |
| ----------- | ---------------------------------------------- |
| `hm-rpc`    | адаптер                                        |
| `1`         | его экземпляр — второй, отсчет начинается с 0. |
| `ABC110022` | адрес устройства                               |
| `2`         | канал                                          |
| `VALUE`     | точка данных                                   |

Все, что создаёт адаптер, находится в его собственном пространстве имён.
`<adapter>.<instanz>.`Кроме того, существуют некоторые фиксированные пространства имен:

| пространство имен               | Содержание                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------ |
| `system.`                       | всё, что касается самого ioBroker                                                                |
| `system.adapter.`               | конфигурация адаптеров и их экземпляров                                                          |
| `system.host.`                  | компьютеры, на которых запущен ioBroker                                                          |
| `system.user.`, `system.group.` | Пользователи и группы                                                                            |
| `enum.`                         | Комнаты, ремесла и другие группы                                                                 |
| `alias.`                        | [Псевдоним](/docs/basics/alias.md) - пользовательские, стабильные имена для внешних точек данных |
| `0_userdata.0.`                 | Место для ваших личных вещей — см. ниже.                                                         |
| `scripts.js.`                   | скрипты адаптера JavaScript                                                                      |

Идентификаторы могут иметь длину до 240 байт. Следующие символы не допускаются:
``[ ] * , ; ' " ` < > \ ?``; от `^ $ ( ) /` Это не рекомендуется. Тем, кто создает собственные данные, лучше всего использовать буквы, цифры, подчеркивания и точки.

## Структура объекта

Каждый объект имеет четыре поля:

| Поле     | Что в нём содержится                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| `_id`    | адрес, указанный выше                                                                     |
| `type`   | Какой это тип объекта (см. ниже)?                                                         |
| `common` | Представление ioBroker: Имя, тип, единица измерения, роль, права на чтение и запись.      |
| `native` | Перспектива целевой системы: всё, что понимает только подключенное устройство или сервис. |

<img src="media/objekte_common_native.png" alt="Ein Geraet im Objekt-Editor: oben common, darunter native" width="780" />

На изображении показан дверной замок Homematic. `common` В нем указано то, что ioBroker должен знать об этом — название и символ. `native` Устройство обладает определенными характеристиками: адрес, прошивка, радиоадрес, тип устройства. ioBroker ничего из этого не считывает; адаптеру необходима вся эта информация.

Разделение `common` и `native` Именно поэтому виджет в визуализации может обрабатывать данные Homematic так же хорошо, как и данные Zigbee: все необходимое для ioBroker всегда находится в одном и том же месте.
`common`Что касается самого устройства, то оно остается в пределах нормы. `native` и никому не мешает.

## Типы объектов

В повседневной жизни вы будете сталкиваться в основном с первыми пятью:

| тип             | Что это такое                                            |
| --------------- | -------------------------------------------------------- |
| `state`         | Точка данных — место, где хранится значение.             |
| `channel`       | суммирует несколько взаимосвязанных точек данных.        |
| `device`        | объединяет каналы в одно устройство                      |
| `folder`        | папка, исключительно для организации информации.         |
| `enum`          | группировка: комната, торговля, собственная категория    |
| `adapter`       | шаблон установленного адаптера                           |
| `instance`      | его работающая копия                                     |
| `host`          | компьютер, на котором запущен ioBroker                   |
| `user`, `group` | Пользователи и группы                                    |
| `script`        | сценарий                                                 |
| `meta`          | Редко изменяющаяся дополнительная информация об адаптере |
| `config`        | настройки, например `system.config`                      |
| `chart`         | описание диаграммы                                       |

Устройства, каналы и точки данных не образуют обязательной иерархии — некоторые адаптеры создают устройства и каналы, другие — только точки данных в папках. Допускаются оба варианта.

## Где вы можете их увидеть

В административной панели в _объект&#x44B;_&#x414;ерево имеет именно такую структуру: каждый уровень между двумя точками — это строка. Значок инструмента в конце строки позволяет редактировать объект, а значок лупы — просматривать исходное содержимое, что зачастую гораздо полезнее для понимания, чем любое описание.

<img src="media/objekte_baum.png" alt="Der Objektbaum: Adapter, Instanz, Geraet, Kanal, Datenpunkte" width="900" />

Изображение следует читать сверху вниз следующим образом: `hm-rpc` это адаптер `0` по его просьбе, `LEQ0903185` устройство («замок»), включающее два канала, и в канале `1` Данные расположены в столбце. _тип_ Указывает тип объекта и столбец для каждой строки. _роль_ Здесь указано, что представляет собой точка данных, а текущее значение находится в крайнем правом углу.

Пространство имен `system.` только в **Экспертный режим** Видимый (переключатель в верхней части панели инструментов). Это сделано намеренно: там нет ничего, с чем вы обычно взаимодействуете.

Объекты, созданные адаптером, принадлежат этому адаптеру. Внесение изменений вручную приведет к их перезаписи при следующем запуске экземпляра. Если точка данных должна постоянно иметь собственное имя или сущность,
[Псевдоним](/docs/basics/alias.md) правильным способом.

## Собственные объекты: `0_userdata.0`

Для объектов, не являющихся результатом работы адаптера — маркера для скрипта, самоподдерживающейся заданной точки, буфера обмена между двумя автоматизациями — существует отдельное пространство имен: **`0_userdata.0`**.

Оно не принадлежит ни одному адаптеру и не перезаписывается ни одним из них. Именно поэтому это подходящее место. Точки данных, размещенные в пространстве имен адаптера, могут исчезнуть при следующем запуске экземпляра.

Они создаются в административной панели. _объекты_ с помощью знака плюс или из сценария — там вместе с **полный** ИДЕНТИФИКАТОР:

```js
createState('0_userdata.0.Heizung.Sollwert', 21, { type: 'number', unit: '°C', read: true, write: true });
```

## Где расположены объекты

Объекты и состояния находятся в **две отдельные базы данных** Они хранятся отдельно — поэтому иногда отображаются в интерфейсе по отдельности. Оба управляются js-контроллером и доступны в нескольких версиях:

| Подача документов | За что                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| `jsonl`           | файлы по умолчанию, начиная с js-controller 4 `objects.jsonl` и `states.jsonl` в каталоге данных |
| `file`            | старый формат файлов, который до сих пор встречается в более старых версиях программ.            |
| `redis`           | база данных в оперативной памяти для больших систем                                              |

В этом процессе будут использоваться обе базы данных. **разделенные** Таким образом, можно, и даже обычным способом, помещать в Redis только состояния, а объекты — в
`jsonl` Допускается следующее: состояния постоянно меняются, объекты — почти никогда.
`iobroker status` показывает, что используется в данный момент.

Для подавляющего большинства установок эта настройка является правильной. Рассматривать другие варианты стоит только в том случае, если js-контроллер постоянно потребляет много вычислительной мощности и система работает медленно.
[Редис](/docs/config/redis.md).

Эти две базы данных содержат только... **текущий** Текущее состояние. Значение точки данных за вчерашний день неизвестно. Если вам нужна историческая запись, например, для графика, активируйте запись, см. ниже.
[Запись данных](/docs/config/history.md).
