# Файл io-package.json

Помимо обычного `package.json` Каждый адаптер содержит второй файл: `io-package.json`В нём содержится всё, что **ioBroker** Эта информация необходима для адаптера и не имеет отношения к npm. Она определяет запись в списке адаптеров, объекты экземпляров, значки на плитке и поведение при запуске.

Создатель адаптеров полностью их настраивает. Любой, кто впоследствии будет изменять их вручную, должен знать, для чего нужны эти поля.

Файл содержит несколько блоков верхнего уровня:

| блокировать       | Содержание                                                                          |
| ----------------- | ----------------------------------------------------------------------------------- |
| `common`          | Основная часть: название, режим работы, интерфейс, зависимости.                     |
| `native`          | Конфигурация по умолчанию. Во время выполнения как `this.config.<feld>` читаемый.   |
| `encryptedNative` | поля из `native`которые хранятся в зашифрованном виде.                              |
| `protectedNative` | поля из `native`, который может прочитать только сам адаптер.                       |
| `objects`         | Объекты, создаваемые один раз для всей системы.                                     |
| `instanceObjects` | Объекты, которые находятся в **каждый** Будет создан новый экземпляр.               |
| `notifications`   | Настраиваемые категории уведомлений. См. [Уведомления](/docs/dev/notifications.md). |

## Сферы, имеющие значение

### идентификатор

`common.name` это название адаптера без префикса. `ioBroker.`Он написан строчными буквами. Это идентификатор везде: в дереве объектов, в пакете npm, в репозитории. Его нельзя изменить позже.

`common.titleLang` — это отображаемое имя, многоязычное. `common.desc` Краткое описание, также на нескольких языках.

`common.version` необходимо переключиться на версию, указанную в `package.json` Они подходят. Это подтверждает проверка адаптера.

### Режим работы

`common.mode` Определяет способ запуска экземпляра ioBroker:

| режим       | Вести себя                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `daemon`    | Программа работает непрерывно. Она перезапускается по завершении процесса. Это нормальное поведение.                            |
| `schedule`  | Он работает по расписанию; расписание хранится в объекте экземпляра и может быть изменено в панели администратора.              |
| `once`      | Эта процедура выполняется один раз после каждого изменения объекта экземпляра и после этого не перезапускается.                 |
| `subscribe` | Начинается, когда `.alive` Значение параметра устанавливается равным true и исчезает, когда оно становится равным false.        |
| `extension` | Он запускается не через ioBroker, а загружается из веб-экземпляра. Вот как это работает. `simple-api` и аналогичные расширения. |
| `none`      | Это вообще не запускает никакого процесса.                                                                                      |

В `schedule` Настройка по умолчанию относится к `common.schedule` в качестве выражения CRON.

`common.compact` Это позволяет экземпляру работать в том же процессе, что и другие. На небольших компьютерах это заметно экономит память, но требует от адаптера полной очистки после завершения работы.

### поверхность

`common.adminUI.config` описывает, как выглядит конфигурация:

- `json`Адаптер обеспечивает `admin/jsonConfig.json` с. **Маршрут на сегодня.**
- `materialize`старый `admin/index_m.html`.
- `html`: еще более старый `admin/index.html`.
- `none`Адаптер не имеет настроек.

`common.icon` это символ в папке `admin`, `common.extIcon` Его адрес на GitHub, чтобы список адаптеров мог отображать его и для неустановленных адаптеров.

### Что управляет символами на плитке?

Короткие символы под названием адаптера в панели администратора берутся из этого файла:

- `common.connectionType`: `local` или `cloud`Независимо от того, взаимодействует ли адаптер напрямую с устройством или через сервис, предоставляемый производителем.
- `common.dataSource`: `push`, `poll` или `assumption`Независимо от того, генерируются ли значения автоматически, запрашиваются или просто предполагаются.
- `common.plugins.sentry`Включает уведомления о сбоях. См.
  [Отчеты о дорожно-транспортных происшествиях](/docs/ecosystem/sentry.md).

Эти три элемента информации часто забываются. Они занимают всего три строки и избавляют пользователей от необходимости задавать вопрос на форуме.

### Зависимости

`common.dependencies` называет то, на чём основано **одинаковый** Например, должен присутствовать хост. `[{"js-controller": ">=5.0.19"}]`. `common.globalDependencies` называет что **где-то** должен запускаться в системе, как правило. `[{"admin": ">=6.0.0"}]`.

`common.osDependencies.linux` Отображает список пакетов операционной системы, устанавливаемых во время установки.

### Значения конфигурации

Всё под `native` Это параметр конфигурации по умолчанию. Во время выполнения он выглядит следующим образом: `this.config.<feld>` готовый.

Каждый пароль и каждые учетные данные для входа должны находиться в **оба** Слушать:
`encryptedNative` **и** `protectedNative`Первая настройка гарантирует шифрование значения в базе данных, вторая предотвращает его чтение любым другим адаптером. Настройка только одной из этих настроек создает уязвимость.

Пример из BackItUp:

```json
"encryptedNative": ["cifsPassword", "ftpPassword", "webdavPassword"],
"protectedNative": ["cifsPassword", "ftpPassword", "webdavPassword"]
```

### Объекты, возникающие спонтанно

`instanceObjects` Это список объектов, которые ioBroker создает с каждым новым экземпляром. Это чистый способ обработки всего, что и так должно всегда существовать, например, ветки. `info` со статусом подключения:

```json
"instanceObjects": [
  {
    "_id": "info",
    "type": "channel",
    "common": { "name": "Information" },
    "native": {}
  },
  {
    "_id": "info.connection",
    "type": "state",
    "common": {
      "role": "indicator.connected",
      "name": "Verbindung zum Gerät",
      "type": "boolean",
      "read": true,
      "write": false,
      "def": false
    },
    "native": {}
  }
]
```

?> `info.connection` Это не просто декоративный эффект: администратор впоследствии окрашивает экземпляр в зеленый или желтый цвет, и другие адаптеры могут реагировать соответствующим образом. Адаптер, устанавливающий соединение, должен находиться в этом состоянии.

### Новости

`common.messagebox: true` Создает диалоговое окно для каждого экземпляра. Без этой записи сообщение не будет получено. `sendTo` на. См.
[Сообщения между экземплярами](/docs/dev/messagebox.md).

## Переводы

Все многоязычные поля заполняются не вручную. Проект включает в себя...
`@iobroker/adapter-dev`и апелляция

```bash
npm run translate
```

переводит новые английские тексты из `io-package.json` и из файлов i18n на все поддерживаемые языки. Таким образом, будут созданы новые тексты. **Только на английском языке** Введите информацию; команда сделает все остальное.
