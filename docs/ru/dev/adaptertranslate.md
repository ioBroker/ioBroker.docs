# Адаптер перевода

ioBroker используется по всему миру. Для того чтобы адаптер был понятен везде, необходимо перевести три вещи:

- тексты интерфейса конфигурации,
- `title` и`desc` в`io-package.json` ,
- примечания к изменениям (`news` ) в`io-package.json` .

**Знание английского** и **немецкого языков** обязательно. Все остальное — на добровольной основе, но приветствуется.

## Поддерживаемые языки

`en` ,`de` ,`ru` ,`pt` ,`nl` ,`fr` ,`it` ,`es` ,`pl` ,`uk` ,`zh-cn` .

## Инструмент

Перевод выполнен с помощью`@iobroker/adapter-dev` Это относится к категории зависимостей развития:

```bash
npm install --save-dev @iobroker/adapter-dev
```

В`package.json` Оно получит запись в разделе`scripts` :

```json
"scripts": {
    "translate": "translate-adapter"
}
```

Адаптер от [Adapter Creator](/docs/dev/adapterdev.md) уже включает эту функцию.

!> Старый`gulp translate` Его больше нет в наличии. У кого ещё остался такой...`Gruntfile` или`gulpfile.js` Для переводов в пакете замените их на`adapter-dev` .

## Процесс

Новые тексты записываются **только** в файл на английском языке, то есть в`admin/i18n/en.json` или`admin/src/i18n/en.json` Впоследствии:

```bash
npm run translate
```

Это заполняет все недостающие переводы в других языковых файлах и в`io-package.json` только определенные языки:

```bash
npm run translate -- -l de fr it
```

Интерфейс в старом стиле HTML также имеет`words.js` Теперь его выращивают не вручную, а производят:

```bash
npm run translate all
```

Это переводит, а затем записывает.`words.js` из JSON-файлов. Всем, у кого ещё нет JSON-файлов, следует один раз вызвать \[команду/метод].`npm run translate to-json` удалить их из существующих`words.js` производить.

Команды поступают в трех формах: в письменном виде (`to-json` ), как знак (`j` ) и под старым названием Gulp (`adminWords2languages` Они делают одно и то же.

## Что переводится с помощью

Используется без каких-либо дополнительных настроек.`adapter-dev` Бесплатный сервис Google Translate имеет ограниченное количество применений. DeepL обеспечивает лучшие результаты. Для этого требуется всего одна переменная окружения:

```bash
export DEEPL_API_KEY="…"
npm run translate
```

Также`GOOGLE_APPLICATION_CREDENTIALS` Если установить такой порядок, то будет использоваться DeepL, затем Google Translate V3, а затем бесплатный Google Translate.

Машинный перевод — это только начало, а не решение проблемы. Немецкие и английские тексты всегда следует проверять вручную. Раздел о технических терминах в [руководстве по стилю](/docs/dev/adapterdocstyleguide.md) иллюстрирует, как часто машина допускает ошибки.

## Веблейт

Для перевода, осуществляемого сообществом, существует [weblate.iobroker.net](https://weblate.iobroker.net/) . Если вы зарегистрируете там свой адаптер, вы будете получать переводы от носителей языка, а не от машины. Weblate вызывает`to-words` даже как только что-то изменится.
