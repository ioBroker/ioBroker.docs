# Руководство по стилю для создания документации к адаптеру

- Документация создана с использованием языка Markdown.
- Хранение файлов документации к адаптеру регулируется следующим образом:
  - Каждый проект адаптера содержит папку. `/doc`.
  - Если документация доступна на немецком языке, она будет находиться в соответствующей подпапке. `de` Сохранено. В настоящее время поддерживаются следующие языки и, следовательно, названия папок: `en, de, ru, pt, nl, fr, it, es, pl`.
  - Соответствующая документация к адаптеру находится в файле. `README.md` который находится непосредственно в соответствующей языковой папке.
  - Медиафайлы будут храниться в подпапке. `media` файл, который также находится в папке языка.
  - За исключением файла README.md, имена файлов и папок пишутся строчными буквами. Допускаются следующие символы: `a-z`, `0-9`, нижнее подчеркивание `_` а также десятичную точку `.`
- В документах после 80 символов должен быть перенос строки.
- Желательно, чтобы форматирование текста соответствовало тому, что показано в файле. `.editorconfig` описано.
  - А[Plugin][] Автоматическое применение этих правил доступно для различных редакторов.
- Для текстов на немецком языке предпочтительно придерживаться новых правил немецкой орфографии.
- В справочных материалах следует избегать использования личных местоимений (например, «я», «ты», «мы»).
  - Используйте гендерно-нейтральные местоимения и существительные во множественном числе.
    - Хорошо: "они (несколько)", "их (имущество)", "лица", "люди", "разработчики"
    - Неправильно: "его", "её", "он", "она (женщина)", "мальчики", "девочки"
- При использовании скобок (всех форм скобок и кавычек) знаки препинания расставляются следующим образом:
  - Внутри скобок, если заключенный в скобки элемент содержит полное предложение (подлежащее, сказуемое, дополнение).
  - Вне скобок, если заключенный в скобки элемент содержит только предложение.
- Документы всегда начинаются с заголовка уровня H1.
- Ссылки не размещаются в одной строке (например, с помощью `[a link](http://example.com)`), но с использованием встроенных `[a link][]` и `[a link]: https://a.link/to/know` размещается в конце документа.
- При использовании тире применяется сокращенная форма со знаком минус, а не «—» или `Option+Shift+"-"` в OSX.
- Дополнительный контент:
  - В этой папке хранятся такие документы, как бинарные файлы, изображения, видео- или аудиозаписи. `media` подано.
  - Для обычных файлов медиафайлы встраиваются в текст с помощью... `[Medienbegriff](media/{dateiname})` и для изображений с использованием `![Medienbegriff](../../de/dev/media/{dateiname})`.
  - Изображения желательно сохранять в формате SVG. Если формат SVG недоступен, можно использовать файл PNG. Пожалуйста, следите за размером файла.
  - Короткие видеоролики можно встраивать в формате GIF.
  - Краткое описание содержания следует давать курсивом под каждым изображением.
- К разделам исходного кода относятся следующие сведения:
  - В зависимости от языка исходного кода необходимо выбрать соответствующую разметку. Например: `\` \`\`\` для JavaScript.
  - Исходный код может быть полным, но это необязательно. Блоки исходного кода содержат примеры, иллюстрирующие описываемый момент. Поэтому предоставление полностью функциональных программ не требуется. Если требуется полностью функциональная программа, она будет предоставлена в виде медиафайла в папке. `media/{code_beispieldatei}` с соответствующей ссылкой в документации.
- Если используются подчеркивания, одинарные кавычки, звездочки или обратные косые черты, необходимо вставить соответствующие экранирующие символы: `\_`, `\*`, `\\` и``\` `` вместо `_`, `*`, `\` и`` ` ``.
- Для того чтобы выделить какой-либо момент, следует соблюдать следующие правила:
  - Заголовок "Примечание:" следует выделять курсивом, т. е. следующим образом: `*Hinweis*:`.
  - После обозначения "Примечание:" следует использовать заглавную букву.
  - Для лучшей видимости примечание следует разместить в начале нового абзаба.
- Имеется \[документация] по адаптерам.[Vorlage][] Соответствующие разделы шаблона должны использоваться в указанном порядке и формате.
