# Разработайте собственный адаптер

Адаптер — это программа на Node.js, которая запускает, отслеживает и настраивает ioBroker. Он подключает устройство, сервис или функцию к дереву объектов: создает объекты, записывает в них значения и реагирует на значения, записанные другими объектами.

Всё остальное — это просто технические знания. Любой, кто знаком с Node.js, может написать адаптер. Дополнительные знания, которые вам понадобятся, вполне посильны и рассматриваются в этой главе.

## Чем отличается адаптер от других подобных устройств?

Адаптер — это npm-пакет с определённой структурой. Он состоит из четырёх файлов:

| файл                    | По какой причине                                                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json`          | Стандартный npm-манифест: зависимости, файл запуска, скрипты.                                                                                                                                                  |
| `io-package.json`       | Вся необходимая информация об адаптере для ioBroker: режим работы, интерфейс конфигурации, настройки по умолчанию, объекты, создаваемые для каждого экземпляра. См. [io-package.json](/docs/dev/iopackage.md). |
| `main.js`               | Программа запускается ioBroker, выполняет вход в систему, работает и очищает ресурсы при завершении работы.                                                                                                    |
| `admin/jsonConfig.json` | Интерфейс конфигурации в панели администратора, представленный в формате JSON вместо HTML. См. [Конфигурация JSON](/docs/dev/adapterjsonconfig.md).                                                            |

Сюда входят символ, переводы и файл readme.

## Резюме учреждения

Адаптер даже не выполняется, а используется как... **Пример** эксплуатируется. Может существовать несколько адаптеров одного типа, каждый со своей конфигурацией и своей ветвью в дереве объектов.

Обычная процедура в программе:

- **`ready`**&#x417;апуск экземпляра. Конфигурация считывается здесь (`this.config.<feld>`), соединение было установлено, и были созданы собственные объекты пользователя.
- **`stateChange`**&#x41A;то-то записал значение, на которое подписан данный экземпляр. Обычно это команда, передаваемая устройству.
- **`message`**&#x414;ругой экземпляр или скрипт отправляет запрос. См. [Сообщения между экземплярами](/docs/dev/messagebox.md).
- **`unload`**&#x42D;кземпляр завершится. Остановите таймер, закройте соединения, затем вызовите функцию обратного вызова. Пропуск этого шага приведет к тому, что процессы не смогут завершиться.

Способ запуска экземпляра определяется... `common.mode` фиксированный: постоянно действующий (`daemon`), согласно расписанию (`schedule`), один раз (`once`) и еще несколько особых случаев.

## Путь от идеи к внедрению

**1. Проверьте, существует ли оно уже.** Недоделанный адаптер, которому нужен помощник, стоит больше, чем двенадцатая попытка собрать то же самое устройство. [Список адаптеров](/adapters) и
[Запросы на адаптер](https://github.com/ioBroker/AdapterRequests/issues) Предоставьте информацию.

**2. Создайте структуру.** Он
[Создатель адаптеров](https://adapter-creator.iobroker.in/) Он запрашивает имя, тип и режим работы и предоставляет полный пакет, включая тесты и конфигурацию GitHub. То же самое можно сделать в командной строке с помощью

```bash
npx @iobroker/create-adapter@latest
```

Для работы требуется Node.js версии 18 или выше и npm версии 9 или выше. Путь к исполняемому файлу не должен содержать пробелов.

**3. Разработка и тестирование.** Вот что...
[dev-сервер](/docs/dev/devserver.md)Небольшая установка ioBroker в папку проекта, которая перезапускает адаптер при каждом изменении кода. Никакой загрузки в рабочую систему, никаких проблем с конфигурацией.

**4. Тестирование.** Данная структура включает тесты, которые запускают адаптер и проверяют, правильно ли он регистрируется и завершает работу. См.
[Тесты адаптера](/docs/dev/adaptertesting.md).

**5. Опубликовать.** Сначала загрузите его в npm, затем добавьте в репозиторий ioBroker. Требования для этого перечислены ниже.
[публиковать адаптеры](/docs/dev/adapterpublish.md)Предварительно стоит ознакомиться с ним. [Проверка адаптера](https://adapter-check.iobroker.in/).
