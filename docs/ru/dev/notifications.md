# Уведомления

Адаптер отслеживает информацию, которую должен знать пользователь: срок действия сертификата истекает, вход в службу был отклонен, жесткий диск целевого сервера заполнен. Эта информация не должна регистрироваться там, где ее никто не сможет увидеть, и не должна храниться в состоянии, на которое никто не подписан.

Для этого и существует система уведомлений js-контроллера. Она собирает такие сообщения, отображает их в панели администратора и делает доступными для адаптеров, которые их пересылают.

## Как пользователь их видит

На вкладке "Администратор" **Хозяева**На экране хоста отображается символ, указывающий количество открытых сообщений. Нажатие этой кнопки открывает диалоговое окно. _Уведомления, специфичные для хост&#x430;_&#x41E;дна вкладка на каждую категорию, содержащая сообщения, сгруппированные по экземплярам, каждое с отметкой времени. Одна кнопка. **Подтверждать** лидирует в своей категории.

Сама система уже распознает целый ряд категорий, все в пределах данной области.
_Системные уведомлени&#x44F;_&#x41D;едостаток памяти, недостаток места на диске, ошибки файловой системы, застревание экземпляров в цикле перезапуска, сбои автоматических обновлений и многое другое.

адаптер [менеджер уведомлений](/adapters/notification-manager) Оно пересылает эти сообщения, например, через Telegram или электронную почту. Таким образом, диалог, который вы должны просмотреть, преобразуется в сообщение, которое доходит до вас.

## Зарегистрируйте свои собственные категории

Адаптер, желающий генерировать собственные сообщения, описывает свои категории в `io-package.json` под `notifications`Структура двухступенчатая: одна
**Область** (_объем_) с несколькими **Категории**.

```json
"notifications": [
  {
    "scope": "meinAdapter",
    "name": {
      "en": "My adapter",
      "de": "Mein Adapter"
    },
    "description": {
      "en": "Notifications of my adapter",
      "de": "Meldungen meines Adapters"
    },
    "categories": [
      {
        "category": "loginFailed",
        "name": {
          "en": "Login rejected",
          "de": "Anmeldung abgelehnt"
        },
        "description": {
          "en": "The service rejected the stored credentials.",
          "de": "Der Dienst hat die hinterlegten Zugangsdaten abgelehnt."
        },
        "severity": "alert",
        "regex": [],
        "limit": 3
      }
    ]
  }
]
```

Поля категории:

| Поле          | Значение                                                                                                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `category`    | Идентификатор, используемый для последующей отправки сообщения.                                                                                                                   |
| `name`        | Название, многоязычное. Отображается в диалоговом окне в виде метки вкладки.                                                                                                      |
| `description` | Значение данной категории поясняется на нескольких языках. Это пояснение появляется над новостными сообщениями.                                                                   |
| `severity`    | `info`, `notify` или `alert`в порядке возрастания.                                                                                                                                |
| `regex`       | Шаблоны, по которым проверяются сообщения об ошибках. Если совпадение найдено, сообщение генерируется автоматически. Пустой массив, если сообщение исходит исключительно из кода. |
| `limit`       | Сколько сообщений этой категории можно хранить максимум?                                                                                                                          |

Что касается выбора уровня: `alert` Это предназначено для тех задач, которые необходимо решить, чтобы система могла продолжать функционировать. `notify` Вот что вам следует знать. `info` Для всего остального. Кто хочет. `alert` Это объяснение приведет лишь к тому, что пользователь в конечном итоге закроет диалоговое окно, не прочитав его.

## Отправить отчет

Во время выполнения программы достаточно одного вызова:

```js
await this.registerNotification('meinAdapter', 'loginFailed',
    'Die Anmeldung wurde abgelehnt. Bitte Zugangsdaten prüfen.');
```

Три основных элемента информации — это область, категория и текст для пользователя. Текст должен объяснять, что нужно делать, а не просто рассказывать о том, что пошло не так.

Это классифицировано `null` После отправки система проверяет сообщение на соответствие
`regex`-определяет структуру местности и сортирует их самостоятельно.

Четвертый параметр может предоставить дополнительную информацию (`contextData`), который может оценивать адаптеры пересылки.

## Что должно быть в уведомлении, а что нет.

Уведомление не является второй записью в журнале. Оно остается до тех пор, пока кто-либо его не подтвердит, и отображается для всех, кто настроил переадресатор. Все, что может произойти в течение каждой итерации, должно быть записано в журнал.

Полезными считаются сообщения, требующие от пользователя действий и которые он иначе бы не заметил: истекшие данные для входа в систему, устройство, которое перестало отвечать, конфигурация, которая устарела после обновления.

Временные прерывания бесполезны. Соединение, которое восстанавливается через десять секунд, должно быть зарегистрировано.
`info.connection`не в диалоговом окне уведомления.

## Демаркация

Адаптер может взаимодействовать тремя способами, и их часто путают:

| Прочь           | За что                                                                         |
| --------------- | ------------------------------------------------------------------------------ |
| **бревно**      | История ошибок. Предназначено для устранения неполадок, а не для пользователя. |
| **Условия**     | Текущая ситуация, приблизительно `info.connection`Постоянно перезаписывается.  |
| **Уведомления** | Отдельные события, требующие принятия мер и ожидающие подтверждения.           |

Сообщения о сбоях — это совсем другое: они отправляются разработчику, а не пользователю. См.
[Отчеты о дорожно-транспортных происшествиях](/docs/ecosystem/sentry.md).
