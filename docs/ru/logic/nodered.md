# Node-RED

Node-RED — это автономный инструмент управления рабочими процессами, не являющийся частью ioBroker, но хорошо интегрирующийся с ним. Программирование в Node-RED осуществляется с использованием...
_Поток&#x438;_&#x423;злы размещаются на поверхности и соединяются линиями, по которым передаются сообщения.

Доступ осуществляется через
[адаптер Node-RED](/adapters/node-red)Он берет с собой Node-RED, запускает его и устанавливает соединение с состояниями ioBroker. Начиная с версии адаптера 7, в него включена версия Node-RED 5; она обновляется вместе с адаптером, а не отдельно.

!> Node-RED работает как **собственный процесс** Помимо ioBroker, он имеет собственное потребление памяти и редактор. Для простых автоматизаций это представляет собой заметные накладные расходы, но это
[Блокли](/docs/logic/blockly.md)
более простой способ.

## Меблировать

1. адаптер _узел-красный_ Установите и создайте экземпляр.
2. При необходимости отрегулируйте параметры порта и защиты доступа в настройках экземпляра. Порт по умолчанию — ... **1880** на всех сетевых интерфейсах без регистрации.
3. Редактор открывается с помощью кнопки экземпляра в панели администратора или непосредственно под ней.
   `http://<adresse-des-servers>:1880`.

!> Доступность без регистрации и на всех интерфейсах означает: любой пользователь сети может изменять потоки и, таким образом, контролировать все, что контролирует ioBroker. Пользователям Node-RED следует настроить защиту доступа в параметрах экземпляра.

## Узлы ioBroker

В палитре редактора появляется отдельная группа. _ioBroker_ с шестью узлами:

| узел                     | За что                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------- |
| ioBroker в               | Триггер: выводит сообщение сразу после изменения состояния.                        |
| ioBroker out             | Записывает содержимое сообщения в состояние                                        |
| ioBroker получить        | Получает текущее значение состояния, не дожидаясь его изменения.                   |
| ioBroker получить объект | Извлекает объект по его идентификатору, то есть по его описанию, а не по значению. |
| список ioBroker          | Возвращает список штатов для заданного шаблона.                                    |
| ioBroker sendTo          | Отправляет команду экземпляру адаптера, например, Telegram.                        |

Таким образом, простой поток состоит из двух узлов: _ioBroker в_ для спускового крючка,
_ioBroker out_ Что касается реакции, то в промежутке между ними необходимо принять решение.

## Что важно в настройках экземпляра?

- **Ограничение на хранение.** По умолчанию установлено значение 128 МБ. Для потоков, содержащих большие объемы данных, требуется больше — в противном случае Node-RED завершит работу без видимых причин.
- **Дополнительные узлы.** Управление палитрой по умолчанию отключено. Пользователям, желающим установить дополнительные пакеты Node.js, необходимо включить его или добавить пакеты в настройках.
- **Создание посторонних объектов.** Также отключено по умолчанию. Пока эта функция отключена, поток может создавать только состояния ниже своего собственного экземпляра.
- **Хранение контекста.** Node-RED может сохранять значения после перезапуска. Начиная с версии адаптера 7, файловое хранилище называется... `file` вместо
  `default`Любой пользователь, явно выбравший место хранения в узле, должен выбрать его там еще раз.

## Почему стоит использовать Node-RED

Node-RED силен там, где важны данные. _пото&#x43A;_&#x41E;н может объединять несколько источников, запрашивать и отвечать на HTTP-интерфейсы, использовать MQTT, выполнять многошаговые преобразования и управлять очередями. Для классической домашней автоматизации — триггеров, условий и действий — он не превосходит адаптер JavaScript, но требует второго процесса и второго редактора.

Одновременное возникновение обоих явлений возможно и распространено. Состояния — это общий язык: то, что записывает поток, скрипт видит немедленно, и наоборот.
