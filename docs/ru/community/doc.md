# Напишите статью

Данная документация доступна в виде набора файлов Markdown в репозитории.
[ioBroker.docs](https://github.com/ioBroker/ioBroker.docs)Каждая страница здесь соответствует точно такому же файлу. Любой, кто обнаружит ошибку или захочет что-то добавить, должен отредактировать этот файл.

## Быстрый способ

Внизу каждой страницы, рядом с датой внесения изменений, указана ссылка. **Редактировать на GitHub**Это напрямую ведет к файлу, который сгенерировал эту страницу, а оттуда значок карандаша открывает редактор в браузере. При сохранении GitHub создает ветку и предлагает отправить запрос на слияние. Для внесения исправлений достаточно учетной записи GitHub.

Для более масштабных изменений целесообразен обычный подход: создать отдельную ветку репозитория, внести изменения локально и отправить запрос на слияние (pull request).

## Какой файл правильный?

Документация доступна на четырех языках по адресу: `docs/de`, `docs/en`, `docs/ru`
и `docs/zh-cn`Источником является только один из них. Это можно определить по заголовку файла:

```
---
title:       "Reiter Benutzer"
lastChanged: "07.09.2026"
---
```

Вот как выглядит исходный код. Сгенерированный перевод, с другой стороны, отображает поле.
`translatedFrom` И предупреждение по этому поводу:

```
---
translatedFrom: de
translatedWarning: If you want to edit this document ...
hash: ...
---
```

!> Файл с `translatedFrom` **нет** При следующем запуске редактирования файл будет перегенерирован, и внесенные изменения будут потеряны. Редактирование файла происходит на том языке, с которого он был переведен.

## Регулировать

Обязательные требования изложены в
[Руководство по стилю](/docs/community/styleguidedoc.md)Наиболее важные моменты:

- Названия файлов указаны мелким шрифтом, только `a-z`, `0-9`, `_` и `.`.
- Перенос строки на отметке 80 символов.
- Каждый документ начинается с заголовка первого уровня.
- В справочных текстах не используются личные местоимения, формулировки гендерно-нейтральны.
- Знак минуса следует использовать как тире, а не как длинное тире.
- Фотографии и другие вложения находятся в папке. `media` рядом с боком.

**Технические термины сохранены в оригинале.** Все, что содержится в коде, JSON-файле или дереве объектов, не будет переведено: `state`, `role`,
`button`, `level`, `string`, `callback`, `payload`Всем, кто ищет `level.` Поиск не находит "Stufen" (уровни). Для разработчиков английский термин всё равно более привычный.

Ситуация иная с терминами, которые пользователь читает на экране: они написаны так же, как в немецком административном интерфейсе, то есть... **объекты**, **Условия**,
**Категории**, **Протоколы**, **Пример**, **Хозяева**.

Информацию о других доступных наградах, таких как цветные индикаторные поля, можно найти в разделе
[Синтаксис Markdown](/docs/community/docmarkdown.md).

## Новые страницы

Одного нового файла недостаточно: страница также должна быть в `docs/content.md`
Его необходимо ввести, иначе он не появится в меню. Ввод также определяет название на четырех языках:

```
  * [en:Users;de:Benutzer;ru:Пользователи;zh-cn:用户](admin/users)
```

Если указано только слово без языкового кода, это относится ко всем языкам.

## Что имеет значение с точки зрения содержания?

- **Проверяйте, а не запоминайте.** Если на странице описывается поверхность, она должна располагаться рядом с открытой поверхностью. Подписи меняются.
- **Скажите им, что нужно сделать.** Список кнопок — это не набор инструкций. У читателя есть цель.
- **Недавние фотографии.** Скриншот старой версии скорее запутает, чем поможет. Лучше вообще не показывать изображение, чем видеть некорректное.
- **Не делайте никаких заявлений, которые не были проверены.** Записывание предположения как факта приносит больше вреда, чем пробел в информации.

Не обязательно писать целую страницу. Исправленная команда, добавленное предложение или актуальное изображение приветствуются.
