# Внесите свой вклад в дальнейшее развитие.

Все материалы, принадлежащие ioBroker, находятся в открытом доступе на платформе.
[GitHub](https://github.com/ioBroker)Это не мелочь для разработчиков, а причина, по которой каждый может внести свой вклад: нет закрытой версии, нет внутренней ветки и нет места, где нужно запрашивать разрешение, прежде чем что-то предложить.

## Как разделен проект

| Часть                    | Что внутри?                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------ |
| `ioBroker.js-controller` | Основные компоненты: базы данных, управление экземплярами, `iobroker`-команды.       |
| `ioBroker.admin`         | Интерфейс описан в главе «Администрирование» данного руководства.                    |
| `ioBroker.<name>`        | Для каждого адаптера требуется один репозиторий, обычно управляемый одним человеком. |
| `ioBroker/ioBroker`      | Скрипты установки Linux, включая средство для исправления ошибок при установке.      |
| `ioBroker.docs`          | Данная документация.                                                                 |

Адаптеры независимы. Любой, кто хочет улучшить адаптер, обращается к тому, кто его поддерживает, а не к центральному комитету. Для адаптеров, чей сопровождающий больше не активен, выполняются следующие шаги:
[iobroker-community-adapters](https://github.com/iobroker-community-adapters)
а.

## С чего начать?

**Знания программирования не требуются.** Практически повсеместно отсутствуют переводы. Каждый адаптер имеет файл, содержащий текст для его интерфейса конфигурации; добавление недостающего языка — это выполнимая и четко определенная задача. Документация также пользуется большим спросом, см. \[ссылка/ссылка].
[Напишите статью](/docs/community/doc.md).

**Обладая навыками программирования.** Самый простой способ начать — не с собственным новым адаптером, а с уже существующим: найдите понятный вам отчет об ошибке и отправьте предложение. Таким образом, вы узнаете о настройке, не принимая все решения самостоятельно.

**Отдельный адаптер.** Если устройство или услуга по-прежнему отсутствуют, инструкции по доступу к ним можно найти по адресу:
[Разработка адаптеров](/docs/dev/adapterdev.md)Правила включения в официальный репозиторий находятся по адресу:
[публиковать адаптеры](/docs/dev/adapterpublish.md).

Перед началом работы с новым адаптером:
[форум](https://forum.iobroker.net) Спросите, работает ли кто-нибудь над этим уже сейчас. Иногда случается, что два человека независимо друг от друга создают одно и то же.

## Как работает процесс подачи предложения

1. Создание ответвления от репозитория (_Вилка_).
2. Создайте ветку для изменений.
3. Вносите изменения как можно меньше и ограничьтесь одним пунктом.
4. Отправьте запрос на слияние (pull request) и объясните его в тексте. **Почему** Необходимы перемены, и важно не только то, какие именно они произведут.
5. Ответьте на дополнительные вопросы. Любое предложение, оставшееся без ответа после первого дополнительного вопроса, не будет принято.

Небольшие, но четко обоснованные изменения внедряются быстро. Крупные ремонтные работы следует обсуждать заранее; в противном случае большая часть работы будет потрачена впустую на то, что не планировалось.

## Что включает в себя проект

Помимо исходного кода, ioBroker нужны люди, которые отвечают на вопросы на форуме, тестируют бета-версии и четко описывают ошибки. Это менее заметно, чем работа над адаптером, но без этой работы остальное не будет функционировать.
