# Восстановить установку

После замены оборудования, неисправности карты памяти или неудачного обновления установка восстанавливается из резервной копии. Звучит сложнее, чем есть на самом деле: при правильном выполнении процесс занимает менее часа, и в итоге система возвращается в исходное состояние.

На этой странице описан полный процесс доступа к **недавно установлен**
Система. Для незначительных повреждений, таких как случайно удаленный объект, существуют более быстрые способы: [Восстановить конфигурацию](/docs/trouble/restore.md).

## Что входит в состав предохранителя, а что нет.

!> **Резервная копия ioBroker не содержит записанных данных измерений.** Он сохраняет объекты, состояния, конфигурации, скрипты и визуализации. Данные из `history`InfluxDB или SQL — это... **собственный** Типы резервного копирования в BackItUp необходимо включать отдельно. То же самое относится к базе данных Zigbee и Redis. Подробности см. ниже.
[резервное копирование данных](/docs/config/backup.md).

Тот, кто заметит это только в процессе реставрации, поймет это слишком поздно.

## Подготовка

**1. Настройте работающую систему.** Установите операционную систему, а затем ioBroker. [Инструкции для Linux](/docs/install/linux.md)Для процесса восстановления требуется исправная, пустая установка.

**2. Выясните, нужен ли вам Redis.** Если доступ к старой системе всё ещё существует,

```bash
iobroker status
```

Информация:

```
Objects type: redis
States  type: redis
```

Там написано рядом с одним из двух `redis`должно быть в новой системе. **ранее**
Сервер Redis запущен. Это указано для обоих серверов. `file` или `jsonl`В этом нет необходимости. Если есть сомнения, то есть если нет доступа к старой системе, лучше установить Redis.

**3. Установите Redis**при необходимости:

```bash
sudo apt update
sudo apt install redis-server
sudo usermod -a -G redis iobroker
sudo reboot
```

**4. Перенесите резервную копию в новую систему.** Для доступа к папке используйте программу SFTP, например FileZilla или WinSCP. `/opt/iobroker/backups`В процессе установки это уже создано.

BackItUp также может восстанавливать данные непосредственно с NAS, Dropbox или Google Drive. Однако восстановление из локального файла — это метод с наименьшим количеством потенциальных ошибок, поэтому именно он описан в этом руководстве.

## Вариант 1: с помощью BackItUp

Более удобный способ, не требующий использования ни одной консольной команды.

**1. Установите BackItUp.** В всаднике _адаптер_ после `backitup` Найдите и создайте экземпляр, используя знак плюса.

**2. Откройте вкладку «Восстановление».** и резервный источник на **Местный**
Задайте положение, затем сохраните.

![Вкладка «Восстановление» в BackItUp](../../de/tutorial/media/restore/1575301096581-restoretab.jpg)

!> Настройка **Запустите все адаптеры после восстановления.** Если предохранитель находится в..., он не выйдет из строя. **другие** Хост работает. Перед запуском обычно необходимо настроить IP-адреса. Это можно сделать на том же устройстве.

**3. Восстановите резервные копии.** Только что загруженный файл отображается в списке ниже. _iobroker_. Выбирать.

![Список найденных предохранителей](../../de/tutorial/media/restore/1575301146928-restoreliste.jpg)

**4. Подтвердите.** В сообщении указано, что ioBroker будет остановлен для восстановления, а затем перезапущен.

![Вопрос перед началом](../../de/tutorial/media/restore/1575301175231-restorestart.jpg)

**5. Смотрите.** В браузере открывается еще одна вкладка, где процесс выполняется так, как если бы он происходил в консоли.

![Процесс восстановления начался.](../../de/tutorial/media/restore/restoreWebUI.JPG)

История заканчивается историей успеха.

В зависимости от устройства и размера установки, это занимает от 10 до 15 минут, после чего ioBroker автоматически перезапускается.

**6. Оставшиеся предохранители.** Если в резервную копию были включены данные Redis, Zigbee, SQL или история транзакций, теперь они будут восстановлены по отдельности тем же методом. Они отобразятся в списке как отдельные записи:

## Способ 2: через консоль

Те, кто хочет увидеть, что происходит прямо сейчас, выбирают прямой путь.

```bash
iobroker stop
iobroker status
```

Только когда `iobroker status` подтверждает, что ничего больше не работает:

```bash
cd /opt/iobroker
iobroker restore <Name der Sicherung>
iobroker start
```

Списки без имен `iobroker restore` Имеющиеся предохранители можно выбрать по номеру.

Таким образом это возможно! **только резервная копия ioBroker** Восстановление. Резервные копии Redis, Zigbee, MySQL или истории создаются в BackItUp и восстанавливаются только там.

## После реставрации

В всаднике _бревно_ На видео показано, как ioBroker переустанавливает все адаптеры из старой установки один за другим с помощью npm. Это самая трудоемкая часть: в зависимости от размера установки, производительности устройства и скорости интернет-соединения, это может занять от двух до трех часов.

?> **В это время ничего не трогайте.** Не перезапускайте, не вмешивайтесь. В отчетах отображается информация о том, что уже выполнено: адаптеры без значка все еще находятся в очереди. Достаточно периодически обновлять страницу.

Если в исключительных случаях ioBroker не запускается автоматически после восстановления:

```bash
iobroker start
```

Как только у всех экземпляров появится свой значок, система снова будет полностью готова: со всеми настройками, скриптами, визуализациями и сопоставлениями.

## В какую сторону

Оба метода приводят к одному и тому же результату. Тем, кому неудобно пользоваться консолью, следует выбрать BackItUp, так как вероятность ошибок будет ниже. Тем, кто хочет точно видеть, что происходит в системе, следует выбрать второй метод.

И после этого, еще до внесения первого изменения: создайте новую резервную копию и убедитесь, что она находится в другом месте, а не на самом устройстве.
