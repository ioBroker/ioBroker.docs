# Восстановление установки

После замены оборудования, неисправности карты памяти или неудачного обновления установка восстанавливается из резервной копии. Звучит сложнее, чем есть на самом деле: при правильном выполнении процесс занимает менее часа, и в итоге система возвращается в исходное состояние.

На этой странице описан полный процесс настройки **новой** системы. Для решения незначительных проблем, таких как случайное удаление элемента, существуют более быстрые способы: [Восстановление конфигурации](/docs/trouble/restore.md) .

## Что входит в состав предохранителя, а что нет.

**Резервная копия ioBroker не включает записанные измерения.** Она создает резервные копии объектов, состояний, конфигураций, скриптов и визуализаций. Данные из`history` InfluxDB и SQL — это **отдельные** типы резервного копирования в BackItUp, и их необходимо включать отдельно. То же самое относится к базе данных Zigbee и Redis. Подробнее см. в разделе [«Резервное копирование данных»](/docs/config/backup.md) .

Тот, кто заметит это только в процессе реставрации, поймет это слишком поздно.

## Подготовка

**1. Настройте работающую систему.** Установите операционную систему, а затем ioBroker в соответствии с [инструкциями для Linux](/docs/install/linux.md) . Для восстановления системы требуется рабочая, пустая установка.

**2. Выясните, нужен ли Redis.** Если доступ к старой системе еще есть, предоставьте...

```bash
iobroker status
```

Информация:

```
Objects type: redis
States  type: redis
```

Там написано рядом с одним из двух`redis` На новой системе **предварительно** должен быть запущен сервер Redis. Это указано для обоих случаев.`file` или`jsonl` В этом нет необходимости. Если есть сомнения, то есть если нет доступа к старой системе, лучше установить Redis.

**3. При необходимости установите Redis** :

```bash
sudo apt update
sudo apt install redis-server
sudo usermod -a -G redis iobroker
sudo reboot
```

**4. Перенесите резервную копию на новую систему.** Используйте программу SFTP, например FileZilla или WinSCP, чтобы скопировать её в папку.`/opt/iobroker/backups` В процессе установки он уже создан.

BackItUp также может восстанавливать данные непосредственно с NAS, Dropbox или Google Drive. Однако восстановление из локального файла — это метод с наименьшим количеством потенциальных ошибок, поэтому именно он описан в этом руководстве.

## Вариант 1: с помощью BackItUp

Более удобный способ, не требующий использования ни одной консольной команды.

**1. Установите BackItUp.** На вкладке _«Адаптер»_ найдите...`backitup` Найдите и создайте экземпляр, используя знак плюса.

**2. Откройте вкладку «Восстановление»** и выберите в качестве источника резервного копирования **«Локальный»** , затем сохраните изменения.

![Вкладка «Восстановление» в BackItUp](../../de/tutorial/media/restore/1575301096581-restoretab.jpg)

Параметр **«Запускать все адаптеры после восстановления»** остается отключенным, если резервное копирование выполняется на **другом** хосте. Перед началом резервного копирования обычно необходимо скорректировать IP-адреса на этом хосте. Его можно включить на том же устройстве.

**3. Восстановите резервные копии.** Загруженный вами файл появится в списке под названием _iobroker_ . Выберите его.

![Список найденных предохранителей](../../de/tutorial/media/restore/1575301146928-restoreliste.jpg)

**4. Подтвердите.** В сообщении указано, что ioBroker будет остановлен для восстановления, а затем перезапущен.

![Вопрос перед началом](../../de/tutorial/media/restore/1575301175231-restorestart.jpg)

**5. Смотрите.** В браузере открывается новая вкладка, где процесс выполняется так, как если бы он происходил в консоли.

![Процесс восстановления начался.](../../de/tutorial/media/restore/restoreWebUI.JPG)

История заканчивается историей успеха.

![Реставрация завершена.](../../de/tutorial/media/restore/restoreWebUI_finish.JPG)

В зависимости от устройства и размера установки, это занимает от 10 до 15 минут, после чего ioBroker автоматически перезапускается.

**6. Оставшиеся резервные копии.** Если резервные копии Redis, Zigbee, SQL или данных истории также были созданы, теперь они будут восстановлены по отдельности тем же методом. Они отображаются в списке как отдельные записи:

![Все типы резервного копирования в списке](../../de/tutorial/media/restore/1575362131512-fullliste.jpg)

## Способ 2: через консоль

Те, кто хочет увидеть, что происходит прямо сейчас, выбирают прямой путь.

```bash
iobroker stop
iobroker status
```

Только когда`iobroker status` подтверждает, что ничего больше не работает:

```bash
cd /opt/iobroker
iobroker restore <Name der Sicherung>
iobroker start
```

Списки без имен`iobroker restore` Имеющиеся предохранители можно выбрать по номеру.

Таким способом можно восстановить **только резервные копии ioBroker** . Резервные копии Redis, Zigbee, MySQL или истории создаются в BackItUp и могут быть восстановлены только там.

## После реставрации

На вкладке _«Журнал»_ показано, как ioBroker переустанавливает все адаптеры из старой установки один за другим с помощью npm. Это самая трудоемкая часть: в зависимости от размера установки, производительности устройства и скорости интернет-соединения, это может занять от двух до трех часов.

**В это время ничего не трогайте.** Не перезапускайте, не вмешивайтесь. Вы можете отслеживать, что уже завершилось в экземплярах: адаптеры без символа все еще находятся в очереди. Достаточно периодически обновлять представление.

Если в исключительных случаях ioBroker не запускается автоматически после восстановления:

```bash
iobroker start
```

Как только у всех экземпляров появится свой значок, система снова будет полностью готова: со всеми настройками, скриптами, визуализациями и сопоставлениями.

## В какую сторону

Оба метода приводят к одному и тому же результату. Тем, кому неудобно пользоваться консолью, следует выбрать BackItUp, так как вероятность ошибок будет ниже. Тем, кто хочет точно видеть, что происходит в системе, следует выбрать второй метод.

И после этого, еще до внесения первого изменения: создайте новую резервную копию и убедитесь, что она находится в другом месте, а не на самом устройстве.
