# Запишите значения

Точка данных знает только свое **текущее** значение. ioBroker знает, насколько тепло было прошлой ночью или сколько электроэнергии было потреблено за прошлую неделю, только если кто-то это зафиксировал. Именно это и делают записывающие адаптеры.

## Какой адаптер?

| адаптер      | Где                            | Когда                                                                              |
| ------------ | ------------------------------ | ---------------------------------------------------------------------------------- |
| **история**  | В файлах на компьютере         | Небольшое количество данных, короткие промежутки времени. Хорошая отправная точка. |
| **инфлюксб** | В базу данных временных рядов  | Многочисленные данные, собранные за годы. Обычный подход для устоявшихся систем.   |
| **sql**      | В MySQL, PostgreSQL или SQLite | Если такая база данных уже существует.                                             |

Начните с`history` Переключение в дальнейшем возможно, и этого вполне достаточно для первоначальных графиков. Сравнение трех адаптеров, процесс миграции и то, что происходит с данными во время резервного копирования, можно найти в разделе [«Запись данных»](/docs/config/history.md) .

Запись означает перемещение данных на SD-карту, а запись расходует ресурсы SD-карты. Тем, кто хочет непрерывно записывать большие объемы данных, следует делать это не на SD-карте, а на SSD-накопителе или в базе данных на другом компьютере.

## Меблировать

1. адаптер`history` Установите и создайте экземпляр. Его конфигурация содержит настройки по умолчанию, которые впоследствии будут применяться ко всем новым точкам данных.
2. На вкладке [«Объекты»](/docs/admin/objects.md) найдите точку данных, которую необходимо записать.
3. В конце строки значок шестеренки открывает настройки для этой точки данных. Там включите экземпляр истории.

Запись начинается прямо сейчас. Ретроспективная запись отсутствует: запись начинается только с момента включения устройства.

## Важные настройки

| Отношение                                       | Что это делает                                                                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **В случае изменения или в пределах интервала** | Фраза "при изменении" почти всегда верна. Интервал генерирует данные даже в том случае, если ничего не происходит. |
| **Минимальное изменение**                       | Запись данных начинается только при достижении этого отклонения. Это позволяет исключить шум от датчика.           |
| **Время задержки**                              | Блокировка происходит вскоре после операции записи. Это помогает при значениях, которые колеблются каждую секунду. |
| **хранилище**                                   | Как долго будут сохраняться значения? Объем памяти неограниченно увеличивается.                                    |

Записывайте только то, что действительно будете просматривать. Запись каждой точки данных только потому, что она может когда-нибудь понадобиться, — самая распространенная причина замедления работы системы через год.

Полезные данные включают температуру, потребление, уровень заполнения и состояния переключения, которые можно использовать позже для определения момента возникновения той или иной ситуации. Неполезны счетчики, которые уже содержат историю и внутренние данные адаптеров.

## Проверьте, работает ли это.

Подождите немного, а затем один раз измените значение. После этого на вкладке «Объекты» в точке данных отобразится сообщение о том, что запись активна, и экземпляр истории будет регистрировать любые ошибки. Если ничего не регистрируется, стоит проверить [журнал](/docs/admin/log.md) .
