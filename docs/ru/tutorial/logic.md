# первая автоматизация

До этого момента ioBroker собирал данные. Теперь мы хотим, чтобы что-то происходило автоматически. Мы создадим самое простое и разумное правило: **Когда ситуация меняется, действуйте.**&#x412;сё остальное — это вариация того же самого.

## Что вам нужно

Он **JavaScript**-Адаптер. Он объединяет Blockly, правила, JavaScript и TypeScript, поэтому все четыре метода доступны одновременно.

1. В всаднике [адаптер](/docs/admin/adapter.md)
   после `javascript` Найдите и создайте экземпляр.
2. Затем слева появится новая вкладка. **Сценарии**.

Вам также понадобятся две точки данных: одна, которая изменяется, и одна, которую вы имеете право устанавливать. Если вы еще не подключили ни одного устройства, вы можете сделать это на соответствующей вкладке.
[объекты](/docs/admin/objects.md) под
`0_userdata.0` две отдельные точки данных, одна из которых имеет тип _Число_ и один из типов _Логическое значени&#x435;_&#x42D;то самый удобный способ тренировки, поскольку вы можете регулировать оба параметра вручную.

## Блочный текст или текст

|              | Блокли                                    | JavaScript                  |
| ------------ | ----------------------------------------- | --------------------------- |
| операция     | Сборка строительных блоков                | Кран                        |
| Подходит для | Начало работы и четкие правила            | Всё, что становится длиннее |
| Ошибка       | Практически невозможно допустить опечатки | Возможны опечатки.          |

Для первого правила мы будем использовать Blockly. Переключиться на другой сервис позже будет легко: Blockly генерирует JavaScript в фоновом режиме, и вы можете его просмотреть.

## Правило строится

1. В всаднике **Сценарии** Создайте новый скрипт Blockly и дайте ему имя, которое в дальнейшем будет указывать на его назначение.
2. Из группы **Курок** Возьмите базовый элемент для изменения состояния и поместите его на рабочее пространство. Он задает три вопроса: какое состояние выбрать, на что реагировать и какой тип изменения.
3. Выберите точку данных для наблюдения.
4. Из группы **Действия** базовый элемент для установки состояния
   **ниже** Вставьте триггер и введите вторую точку данных и желаемое значение.
5. Сохраните и запустите скрипт.

Чтобы проверить это, вручную измените первую точку данных на вкладке «Объекты» и посмотрите, изменится ли вторая точка данных.

Строительные блоки, которые **снаружи** События, запускаемые одним единственным событием, выполняются только один раз, а именно при запуске скрипта. Это один из самых распространенных источников путаницы для начинающих.

## Три классические ошибки новичков

**Путаница между командами и обратной связью.** Каждое условие, помимо своей ценности, обладает еще одной характеристикой: `ack = false` означает «кто-то этого хочет». `ack = true` Это означает «так оно и есть». Триггер, реагирующий на оба события, срабатывает дважды.

**Петля обратной связи.** Скрипт A изменяет точку данных 1, что запускает скрипт B, который изменяет точку данных 2, которая, в свою очередь, запускает скрипт A. Это видно в журнале по появлению одних и тех же строк в быстрой последовательности.

**Слишком много всего в одном сценарии.** Лучше иметь несколько небольших скриптов с описательными названиями, чем один, который может делать всё. В противном случае, через полгода вы даже не вспомните, почему загорается лампочка.

## Если это не так

Каждый скрипт имеет свой собственный вывод логов, который находится на вкладке
[Протоколы](/docs/admin/log.md) Это указывает на то, с чем именно возникли проблемы в экземпляре JavaScript. Запись в журнале — наиболее полезный инструмент для устранения неполадок: она показывает, действительно ли сработал триггер.
