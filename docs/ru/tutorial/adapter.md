# Управление адаптерами

В отношении адаптеров постоянно путают два термина, и это является источником большинства недоразумений:

- **Адаптер** — это программное обеспечение. Оно загружается на компьютер один раз.
- **Экземпляр** — это запущенный процесс данного адаптера со своей собственной конфигурацией. Может существовать несколько экземпляров одного и того же адаптера, например...`hue.0` для одного и`hue.1` для второго моста.

Действия выполняет только один экземпляр. Установленный адаптер без экземпляра просто простаивает.

Подробное описание вкладки _«Адаптер»_ , отображаемых символов и функций каждой панели инструментов приведено в разделе [«Адаптер»](/docs/admin/adapter.md) . На этой странице описаны основные процессы.

## Установите адаптер

**В панели администратора** нет специальной команды для этого, и это сделано намеренно: при создании экземпляра адаптер устанавливается автоматически, если это необходимо. Достаточно одного щелчка по знаку плюса рядом с плиткой.

**На консоли:**

```bash
iobroker install <adaptername>
```

## Создайте экземпляр

**В панели администратора** : на вкладке _«Адаптер»_ нажмите знак плюса на плитке адаптера. Это откроет конфигурацию для нового экземпляра.

**На консоли:**

```bash
iobroker add <adaptername>
```

Если файлы адаптера отсутствуют, ioBroker автоматически выполнит их предварительную установку.

## Обновлять

Если доступна более новая версия, плитка меняет цвет, и доступная версия отображается зеленым. Нажатие на значок обновления устанавливает ее. Затем в фоновом режиме происходят два шага: новые файлы устанавливаются и впоследствии загружаются в экземпляры.

```bash
iobroker upgrade <adaptername>
```

Обновление адаптеров полезно не только из-за появления новых функций: часто для работы адаптеров требуется определенная версия другого адаптера. В системе, где все обновлено, меньше неожиданностей.

## Вернуться к более старой версии

Если новая версия вызывает проблемы, можно установить более старую версию.

**В режиме администратора** : включите экспертный режим, затем **выберите «Установить определенную версию»** на обратной стороне плитки. Появится список версий, выпущенных разработчиком.

**На консоли:**

```bash
iobroker upgrade <adaptername>@<version>
```

## Загрузка файлов

Особый случай, не требующий внимания в обычном режиме работы: в процессе загрузки файлы адаптера повторно добавляются в базу данных. Это необходимо только в том случае, если кто-то вручную изменил файлы.

**В режиме администратора** : в режиме эксперта, затем на обратной стороне плитки **выберите «Загрузка файла»** .

**На консоли:**

```bash
iobroker upload <adaptername>
```

## Откуда берутся адаптеры

Список на вкладке _«Адаптер»_ изначально представляет собой просто каталог. Перечисленные там элементы ещё не установлены на компьютере. Они поступают из настроенного репозитория и обновляются при открытии окна администрирования; если соединение отсутствует, отображается последняя известная версия.

Существует три источника, и они различаются по степени зрелости:

| источник       | Что в нём содержится                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| **стабильный** | Протестированные версии. Правильный выбор для системы, которой необходимо работать.        |
| **бета**       | Более новые версии, ещё не прошедшие полное тестирование. Ранее назывались _"последняя"_ . |
| **GitHub**     | Статус разработки. Включая незавершенные промежуточные версии.                             |

Один и тот же номер версии может встречаться во всех трех версиях, если изменений было немного. Однако они также могут существенно отличаться. Именно поэтому часто возникает вопрос, почему версия, упомянутая на форуме, не предлагается в качестве обновления.

Используемый репозиторий указывается в [системных настройках](/docs/admin/settings.md) ; подробности можно найти в разделе [«Репозитории»](/docs/basics/repositories.md) .

## Единая версия из бета-версии или GitHub

Раньше для этого требовалось переключить весь репозиторий, а затем вернуть его обратно, о чём часто забывали. Теперь в этом нет необходимости: используя опцию **«Установить из локального источника»** на панели инструментов (значок Octocat), вы можете получить единую версию из npm или GitHub, а всё остальное — из _стабильного_ репозитория.

!> **Скачивайте с GitHub только после консультации с разработчиком.** Это незавершенная версия, а не релиз. Недоделанная версия может сделать установку непригодной. Всем, кто устанавливает тестовую версию, следует заранее сделать [резервную копию](/docs/config/backup.md) и знать, как к ней вернуться.

## Чего не следует делать

!> **Нет`npm install` вручную.** Способ

```bash
cd /opt/iobroker
npm install iobroker.<adaptername>
```

Раньше это часто включалось в руководства. В современных системах это приводит к проблемам с правами доступа или сбоям, поскольку npm запускается от имени неправильного пользователя.`iobroker` Команды выполняют ту же задачу и правильно устанавливают права доступа. Если это уже произошло, может помочь [средство исправления установки](/docs/trouble/install_fixer.md) .
