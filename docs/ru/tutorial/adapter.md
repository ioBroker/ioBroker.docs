# Управление адаптерами

В отношении адаптеров постоянно путают два термина, и это является источником большинства недоразумений:

- А **адаптер** Это программное обеспечение. Оно загружается на компьютер один раз.
- Один **Пример** Это непрерывный процесс настройки данного адаптера. Например, может существовать несколько версий одного и того же адаптера. `hue.0` для одного и `hue.1` для второго моста.

Действия выполняет только один экземпляр. Установленный адаптер без экземпляра просто простаивает.

Как и всадник _адаптер_ Ниже приведено подробное описание внешнего вида каждой плитки, используемых на ней символов и функций панели инструментов.
[адаптер](/docs/admin/adapter.md)На этой странице объясняется лежащий в основе этого процесс.

## Установите адаптер

**В административной панели** Для этого нет отдельной команды, и это сделано намеренно: при создании экземпляра адаптер устанавливается автоматически, если это необходимо. Достаточно одного щелчка по знаку плюса на плитке.

**На консоли:**

```bash
iobroker install <adaptername>
```

## Создайте экземпляр

**В административной панели**: в всаднике _адаптер_ Нажмите на знак плюса на плитке адаптера. После этого откроется окно настроек нового экземпляра.

**На консоли:**

```bash
iobroker add <adaptername>
```

Если файлы адаптера отсутствуют, ioBroker автоматически выполнит их предварительную установку.

## Обновлять

Если доступна более новая версия, плитка меняет цвет, и доступная версия отображается зеленым. Нажатие на значок обновления устанавливает ее. Затем в фоновом режиме происходят два шага: новые файлы устанавливаются и впоследствии загружаются в экземпляры.

```bash
iobroker upgrade <adaptername>
```

Обновление адаптеров полезно не только из-за появления новых функций: часто для работы адаптеров требуется определенная версия другого адаптера. В системе, где все обновлено, меньше неожиданностей.

## Вернуться к более старой версии

Если новая версия вызывает проблемы, можно установить более старую версию.

**В административной панели**Включите экспертный режим, затем на обратной стороне плитки.
**Установите определенную версию**Приводится список версий, выпущенных разработчиком для этой цели.

**На консоли:**

```bash
iobroker upgrade <adaptername>@<version>
```

## Загрузка файлов

Особый случай, не требующий внимания в обычном режиме работы: в процессе загрузки файлы адаптера повторно добавляются в базу данных. Это необходимо только в том случае, если кто-то вручную изменил файлы.

**В административной панели**: Экспертный режим, затем на обратной стороне плитки **Загрузка файла**.

**На консоли:**

```bash
iobroker upload <adaptername>
```

## Откуда берутся адаптеры

Список во вкладке _адаптер_ Изначально это просто каталог. Отображаемая там информация ещё не хранится на компьютере. Она поступает из настроенного хранилища и обновляется при открытии учетной записи администратора; если подключение отсутствует, сохраняется последняя известная версия.

Существует три источника, и они различаются по степени зрелости:

| источник       | Что в нём содержится                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| **стабильный** | Протестированные версии. Правильный выбор для системы, которой необходимо работать.        |
| **бета**       | Более новые версии, ещё не прошедшие полное тестирование. Ранее назывались... _последний_. |
| **GitHub**     | Статус разработки. Включая незавершенные промежуточные версии.                             |

Один и тот же номер версии может встречаться во всех трех версиях, если изменений было немного. Однако они также могут существенно отличаться. Именно поэтому часто возникает вопрос, почему версия, упомянутая на форуме, не предлагается в качестве обновления.

Используемый репозиторий указан в

[Репозитории](/docs/basics/repositories.md).

## Единая версия из бета-версии или GitHub

Раньше для этого требовалось переключить весь репозиторий, а затем вернуть его обратно, о чём часто забывали. Теперь это не нужно: Via
**Установите из собственного источника.** На панели инструментов (значок Octocat) вы можете получить отдельную версию из npm или GitHub, а все остальное — из других источников. _стабильный_ приходит.

!> **Использовать только с GitHub после консультации с разработчиком.** Это незавершенная работа, а не релиз. Недоработанная версия может сделать установку непригодной для использования. Всем, кто устанавливает тестовую версию, следует сначала... [Безопасность](/docs/config/backup.md) иметь и знать, как он вернется.

## Чего не следует делать

!> **Нет `npm install` вручную.** Путь

```bash
cd /opt/iobroker
npm install iobroker.<adaptername>
```

Раньше это часто включалось в руководства. В современных системах это приводит к проблемам с правами доступа или сбоям, поскольку npm запускается от имени неправильного пользователя. `iobroker`Команды делают то же самое и правильно устанавливают права доступа. Если это уже произошло, то
[Installation Fixer](/docs/trouble/install_fixer.md).
