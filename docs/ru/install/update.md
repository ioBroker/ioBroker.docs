# Выполните обновления

Установка ioBroker состоит из трех слоев, которые обновляются отдельно. Такой порядок оказался эффективным:

|   | Что                                          | Как часто                                          |
| - | -------------------------------------------- | -------------------------------------------------- |
| 1 | [адаптер](/docs/install/updateadapter.md)    | часто — что-то случается каждую неделю             |
| 2 | [js-контроллер](/docs/install/updateself.md) | редко — несколько раз в год                        |
| 3 | [Node.js](/docs/install/updatenode.md)       | Редко — когда срок службы версии подходит к концу. |

Кроме того, существует сама операционная система, которая поставляется в соответствии со своими собственными правилами.`sudo apt update && sudo apt full-upgrade` ).

## Перед каждым обновлением: делайте резервную копию.

Неудачное обновление без резервной копии может занять несколько дней. С резервной копией это займет полчаса.

```bash
iob stop
iob backup
iob start
```

Резервная копия сохраняется в виде ZIP-файла с указанием даты в соответствующей директории.`backups` в папке ioBroker. У всех, кто использует адаптер _Backitup_ , он и так уже запущен — в этом случае стоит проверить, действительно ли последняя резервная копия является недавней и находится ли она вне устройства.

В виртуализированной системе наиболее удобным способом обеспечения безопасности является создание снимка состояния перед обновлением; в случае сомнений предыдущее состояние можно восстановить за минуту.

## Хронологический порядок

**Сначала адаптеры, затем контроллер JavaScript.** Для нового контроллера JavaScript иногда требуются более новые адаптеры; обратный путь обеспечивает лучшую совместимость.

**Обновление Node.js следует проводить только в последнюю очередь и обдуманно.** Наиболее существенным изменением является изменение основной версии Node.js. Для этого существуют свои предварительные условия, и этому посвящена отдельная страница: [Обновление Node.js и npm](/docs/install/updatenode.md) .

**Не делайте всё за один вечер.** Если что-то пойдёт не так после трёх одновременных обновлений, причину будет сложно найти. Сделайте одно обновление, немного понаблюдайте, а затем переходите к следующему.

## Где отображаются обновления

В панели администратора, в разделе _«Адаптер»_ , для каждой записи отображается информация о наличии более новой версии в репозитории. Консоль отображает эту информацию.

```bash
iob update --updatable
```

Всё сразу, без каких-либо изменений.

## Стабильная и новейшая версия

Существует два репозитория. **В стабильном репозитории** содержатся версии, доказавшие свою работоспособность на широком спектре систем; **в последнем** — все версии сразу после их выпуска. Для системы, требующей надежной работы, стабильный репозиторий — это правильный выбор, а последний предназначен для тех, кто хочет находить и сообщать об ошибках. Более подробную информацию см. в [разделе «Репозитории»](/docs/basics/repositories.md) .

## Если после обновления что-то зависло

- [ioBroker больше не работает.](/docs/trouble/RunsNoMore.md)
- [Ошибка адаптера](/docs/trouble/adapter.md)
