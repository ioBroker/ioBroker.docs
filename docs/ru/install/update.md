# Выполнить обновления
Установка ioBroker состоит из трех слоев, которые обновляются отдельно. Такой порядок оказался эффективным:

| | Что | Как часто |
|---|---|---|
| 1 | [адаптер](/docs/install/updateadapter.md) | часто - каждую неделю выходит что-то новое |
| 3 | [Node.js](/docs/install/updatenode.md) | редко - когда срок службы версии подходит к концу |
| 3 | [Node.js](/docs/install/updatenode.md) | редко - когда срок поддержки версии подходит к концу |

Кроме того, имеется сама операционная система, которая поставляется в соответствии со своими собственными правилами (`sudo apt update && sudo apt full-upgrade`).

**В Docker** (образ с buanet) Node.js и операционная система включены в образ. Вместо `iobroker nodejs-update` или `apt` создается новый образ, и контейнер пересоздается (`docker pull` и пересоздание контейнера или `docker compose pull && docker compose up -d`). Данные остаются в томе под `/opt/iobroker` - в любом случае, сделайте резервную копию заранее. Адаптеры и JS-контроллеры обновляются как обычно в панели администратора или в консоли контейнера. См. [докер](/docs/install/docker.md) и [документация Buanet](https://docs.buanet.de/de/iobroker-docker-image/).

## Перед каждым обновлением: делайте резервную копию
Неудачное обновление без резервной копии может занять несколько дней. С резервной копией это займет полчаса.

```bash
iob stop
iob backup
iob start
```

Резервная копия сохраняется в виде ZIP-файла с кодом даты в каталоге `backups` внутри папки ioBroker. Пользователи адаптера *backitup* уже имеют его включенным по умолчанию - в этом случае стоит проверить, действительно ли последняя резервная копия является актуальной и находится ли она вне устройства.

В виртуализированной системе наиболее удобным способом обеспечения безопасности является создание снимка состояния перед обновлением; в случае сомнений предыдущее состояние можно восстановить за минуту.

## Хронологический порядок
**Сначала адаптеры, затем контроллер JavaScript.** Для нового контроллера JavaScript иногда требуются более новые адаптеры; обратный порядок более совместим.

**Использование Node.js только в крайнем случае и только намеренно.** Наиболее существенным вмешательством является изменение основной версии Node.js. Для этого существуют свои предварительные условия, и об этом есть отдельная страница: [Обновите Node.js и npm.](/docs/install/updatenode.md).

**Не делайте всё за один вечер.** Если что-то пойдёт не так после трёх одновременных обновлений, причину будет сложно найти. Сделайте один шаг, понаблюдайте за процессом, затем переходите к следующему.

## Когда адаптеру требуется более новая версия Node.js
Для некоторых версий адаптера требуется более новая версия Node.js или js-controller. Это указано в журнале изменений или файле README в разделе «Требования». В этом случае есть два варианта:

* **Намеренно отдавайте предпочтение Node.js** - сначала сделайте резервную копию, а затем действуйте, как описано ниже.

[Обновите Node.js и npm.](/docs/install/updatenode.md) описано.

**Пока что используйте текущую версию адаптера** или выберите другую версию.

Установите более старую, совместимую версию: в режиме администратора, в экспертном режиме через *Установить определенную версию* (см. [адаптер](/docs/tutorial/adapter.md)) или в консоли:

```bash
iobroker upgrade <adaptername>@<version>
```

Начиная с js-controller 6, неподходящую версию можно скрыть, чтобы она не предлагалась постоянно в качестве обновления, а затем не отображалась снова:

```bash
iobroker version <adaptername> --ignore <version>
iobroker version <adaptername> --recognize
```

## Где отображаются обновления
В панели администратора, в разделе *Адаптеры*, для каждой записи отображается информация о наличии более новой версии в репозитории. Консоль отображает эту информацию.

```bash
iob update --updatable
```

Всё сразу, без каких-либо изменений.

## Стабильная и новейшая версия
Существует два репозитория. **Stable** содержит версии, доказавшие свою эффективность; **Latest** содержит все версии сразу после их выпуска. Для системы, требующей надежной работы, Stable - это правильный выбор, а Latest предназначен для тех, кто хочет находить и сообщать об ошибках. Подробнее см. [Репозитории](/docs/basics/repositories.md).
