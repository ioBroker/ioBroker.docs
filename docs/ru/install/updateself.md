# Обновить js-контроллер

js-контроллер — это ядро ioBroker: он поддерживает базы данных, запускает адаптеры и отслеживает их работу. Он обновляется редко — всего несколько раз в год — и поскольку от него зависит всё, этот этап необходимо подготовить заранее.

## Ранее

1. **Безопасный.**`iob stop` ,`iob backup` ,`iob start` Кроме того, делается снимок виртуальной системы.
2. **Сначала обновите адаптер.** Для нового JS-контроллера иногда требуются более новые адаптеры. См. [раздел «Обновление адаптеров»](/docs/install/updateadapter.md) .
3. **Ознакомьтесь с изменениями.** Если произошёл скачок в основных версиях, будет указан список моментов, которые могут вызвать проблемы – например, требуемая версия Node.js, удалённая настройка.
4. **Планируйте заранее.** Не приезжайте непосредственно перед отъездом.

## Обновлять

Как только в репозитории появится новая версия, в панели администратора появится уведомление; обновление также можно инициировать там. В консоли:

```bash
iob update          # zeigt, welche Version das Repository führt
iob upgrade self    # aktualisiert den js-controller
```

Эта команда останавливает ioBroker во время процесса обновления и перезапускает его после этого.

?>`iob upgrade self` Она следует за настроенным репозиторием. Если этот репозиторий содержит **более старую** версию, она также будет понижена — это способ вернуться к предыдущей версии, если она вызывает проблемы, а также причина проверить репозиторий заранее.

## Впоследствии

- Всё снова работает? В _разделе "Экземпляры"_ не должно быть красных записей.
- Прочитайте журнал за первые несколько минут. Сообщения об устаревших запросах обычно относятся к одному адаптеру, которому необходимо обновиться.
- `iob diag` В нем кратко изложена текущая ситуация, и он служит основой для каждого вопроса на [форуме](https://forum.iobroker.net) .

## Если что-то пойдёт не так

Во-первых, [перестаёт работать ioBroker](/docs/trouble/RunsNoMore.md) — наиболее распространённые причины перечислены там в порядке убывания. Если это не поможет, самым быстрым решением будет восстановление из только что созданной резервной копии:

```bash
iob restore <datei>
```
