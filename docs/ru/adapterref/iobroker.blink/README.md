# IoBroker.blink
## Адаптер blink для ioBroker
Адаптер ioBroker для камер Blink.

## Поддерживаемые устройства
Этот адаптер предназначен для домашних камер видеонаблюдения Blink и соответствующих устройств, подключенных к учетной записи Blink.

Веб-сайт производителя: [Моргнуть](https://blinkforhome.com/) Обзор устройства: [Продукция Blink](https://blinkforhome.com/products) Поддержка / документация по устройству: [Поддержка Blink](https://support.blinkforhome.com/)

Данный адаптер не связан с компанией Blink или Amazon, не поддерживается ими и не получает от них одобрения.

## Функции
- Подключается к облаку Blink
- Опрашивает состояние камеры и модуля синхронизации.
- Поддерживает создание снимков вручную.
- Сохраняет актуальные снимки состояния
- Загружает последнюю доступную облачную видеозапись
- Позволяет включать или отключать обнаружение движения
- Поддерживает предупреждения о состоянии батареи и уведомления.
- Поддерживает интеллектуальное определение состояний для классифицированных событий движения (работает только в платных облачных сервисах).
- Поддерживает видео, хранящиеся в облаке, и видео, хранящиеся локально на SD-карте (SyncModule 2 и XR), через локальный сервер на порту 8085. - Требуется JavaScript, см. ниже!
- Для работы скрипта требуется установленный ffmpeg и много ресурсов, если у вас много камер, поэтому он лишь частично подходит для Raspberry Pi (минимум 4 ГБ — чем больше, тем лучше).
- Первоначальная версия для просмотра в реальном времени с JavaScript для каждой камеры - необходимый JavaScript устанавливается автоматически - за исключением старой модели XT2, поскольку она использует другой видеопоток
- Экспериментальная нативная сессия LiveView (не требуется вспомогательный JavaScript-код / ffmpeg) через `commands.start_live` / `commands.stop_live`, см. раздел "Реальная сессия LiveView" ниже.

## Адаптер Blink: Точки данных
Обзор всех точек данных, предоставляемых пользовательским адаптером ioBroker `blink.0`.
Статус: после рефакторинга для облачной истории + резервного копирования в локальное хранилище, а также экспериментальной нативной сессии LiveView, добавленной в версии v0.0.37/0.0.38.

## Условные обозначения
- `<CamID>` — числовой идентификатор камеры (например, `1754227`). Также используется в имени файла MP4.
- `<NetID>` — Идентификатор сети модуля синхронизации / домашней сети (например, `174553`).
- `<N>` — индекс слота в истории видео, **0 = самый новый** клип, **9 = самый старый**.

Все файлы MP4 и снимки хранятся в настроенном каталоге для снимков (по умолчанию: `/opt/iobroker/iobroker-data/blink/`).

### `video` – Текущее видео
Новейшее видео с камеры. Автоматически выбирается облачное хранилище; при необходимости используется локальное хранилище (USB-накопитель Sync Module 2).

| Точка данных | Тип | Описание |
|---|---|---|
| `video.file` | строка | Абсолютный путь к файлу MP4 (`<CamID>_latest.mp4`). |
| `video.id` | строка | Уникальный идентификатор клипа из API Blink. |
| `video.size` | число | Размер файла в байтах. |
| `video.ready` | логическое значение | Файл успешно загружен и воспроизводится. |
| `video.lastError` | строка | Последняя ошибка загрузки. `""` = ok, в противном случае сообщение типа `no video available`. |
| `video.lastError` | строка | Последняя ошибка загрузки. `""` = ok, в противном случае сообщение типа `видео недоступно`. |

### `video.history.0` … `video.history.9` – Галерея колец
Каждая камера имеет **10 слотов**, содержащих 10 самых последних видеороликов.

**Слот 0 = самый новый ролик**, слот 9 = самый старый. При каждом новом ролике слоты автоматически меняются (самый старый удаляется).

| Точка данных | Тип | Описание |
|---|---|---|
| `video.history.<N>.file` | строка | Абсолютный путь к файлу MP4 (`<CamID>_history_<N>.mp4`). Постоянное имя файла для каждого слота ⇒ стабильные URL-адреса в VIS. |
| `video.history.<N>.timestamp` | строка | Временная метка содержимого клипа (ISO). |
| `video.history.<N>.source` | строка | Источник клипа: `cloud` или `local_storage`. Пусто, если слот не используется. |
| `video.history.<N>.source` | string | Источник клипа: `cloud` или `local_storage`. Пусто, если слот не используется. |

### `commands` – Точки запуска
Установите значение `true` → при выполнении действия адаптер автоматически сбрасывается на `false`. (`commands.motion_detect` является единственным исключением — это постоянно включенный/выключенный переключатель, а не самосбрасывающийся триггер.)

| Точка данных | Тип | Действие |
|---|---|---|
| `commands.snapshot` | логическое значение | Запросить новый снимок (сохраненный в виде состояния Base64). |
| `commands.fetch_video` | логическое значение | Скачать последнее видео. Интеллектуальная логика: сначала облако, затем резервное локальное хранилище. |
| `commands.live_request` | логическое значение | Открыть потоковое видео MJPEG в реальном времени (вспомогательная функция веб-сетки, TTL ~60 с). |
| `commands.start_live` | логическое значение | Запустить экспериментальную сессию LiveView (вспомогательный JavaScript-код / ffmpeg не требуется). Результат отображается в `live.url` / `live.mode` / `live.session_id`. |
| `commands.stop_live` | логическое значение | Остановить сеанс LiveView, запущенный через `commands.start_live`. |
| `commands.motion_detect` | логическое значение | Переключатель обнаружения движения на камере (постоянное переключение, не сбрасывается автоматически). |
| `commands.clear_session` | логическое значение | Очистить сессию аутентификации (в случае проблем со входом в систему). |
| `commands.clear_session` | логическое значение | Очистить сессию аутентификации (в случае проблем со входом в систему). |

## Модуль синхронизации / сеть
Каждый модуль синхронизации получает свой собственный канал `blink.0.sync.<NetID>`. **Примечание:** В пути состояния используется `network_id`, а не фактический идентификатор устройства модуля синхронизации.

### `info` – Основные данные
| Точка данных | Тип | Описание |
|---|---|---|
| `info.name` | строка | Имя сети (например, "Home"). |
| `info.serial` | строка | Серийный номер модуля синхронизации. |

### `status` – Штат
| Точка данных | Тип | Описание |
|---|---|---|
| `status.armed` | логическое значение | Сетевая активация (включает обнаружение движения на всех камерах). |
| `status.last_update` | string | Временная метка последнего обновления (ISO). |

### `commands` – Триггер
| Точка данных | Тип | Действие |
|---|---|---|
| `commands.armed` | логическое значение | Включает/выключает всю сеть в режиме охраны (`true`) или снятия с охраны (`false`). Влияет на все камеры в этой сети. |

## Структура файлов в каталоге снимков
Путь по умолчанию: `/opt/iobroker/iobroker-data/blink/`

| Файл | Описание |
|---|---|
| `<CamID>_latest.mp4` | Самое последнее видео с камеры (см. `video.file`). |
| `<CamID>_snapshot.jpg` | Последний снимок, если сохранен через `commands.snapshot_file`. |
| `<CamID>_snapshot.jpg` | Последний снимок, если сохранен с помощью `commands.snapshot_file`. |

Имена файлов **постоянны для каждого слота**, содержимое меняется при ротации. Для встраивания в веб-среду используйте механизм защиты от кэширования в строке запроса (`?t={timestamp}`), чтобы браузер действительно перезагружал новый файл.

### Дополнительный видеоархив
Адаптер может копировать загруженные MP4-файлы в отдельную директорию архива, например, в путь к смонтированному сетевому хранилищу (NAS). Создание архива является необязательным и отключено по умолчанию.

Настройки архива задаются в административном интерфейсе адаптера:

* `Включить видеоархив`: позволяет копировать загруженные MP4-клипы в каталог архива.
* `Каталог архива`: абсолютный путь к архивированным файлам MP4, например, `/opt/iobroker/iobroker-data/blink-archive`.
* `Создать подпапки для камер`: создает одну архивную подпапку для каждой камеры.
* `Максимальное количество архивных клипов на камеру в сетке`: ограничивает количество архивных клипов, отображаемых на каждой камере в веб-сетке.

При включении архива адаптер также заполняет существующие локальные файлы MP4 из текущего состояния видео и истории видео в архив. В сетке камер под кнопкой навигации `Archive` отображаются заархивированные клипы, отсортированные по временной метке клипа и дедуплицированные по идентификатору клипа.

В разделе `blink.0.archive` создаются следующие состояния архива:

| Штат | Тип | Описание |
| --- | --- | --- |
| `archive.enabled` | логическое значение | Указывает, включен ли архив в конфигурации адаптера. |
| `archive.directory` | строка | Отображает настроенный каталог архива. |
| `archive.lastFile` | строка | Исходный MP4-файл, последний раз обработанный для архивирования. |
| `archive.lastTarget` | строка | Целевой путь архива последнего успешно скопированного MP4-файла. |
| `archive.lastSuccess` | строка | Метка времени последнего успешного копирования архива. |
| `archive.lastError` | строка | Последнее сообщение об ошибке архивации, если таковое имелось. |
| `archive.lastError` | строка | Последнее сообщение об ошибке архивации, если таковое имеется. |

Состояния архива являются индикаторами состояния только для чтения. Изменяйте параметры архива в конфигурации адаптера, а не записывайте данные в эти состояния.

## Советы по интеграции VIS
Для **предварительного просмотра в реальном времени** в VIS:

```
{cameras.1754227.video.file}      → absolute path
{cameras.1754227.video.timestamp} → use for cache-busting
{cameras.1754227.video.ready}     → if false, show a "no video" hint
{cameras.1754227.video.lastError} → if non-empty, show as error status
```

Для поиска информации в **исторической галерее** используйте поля запроса 0–9 по отдельности:

```
{cameras.1754227.video.history.0.file}
{cameras.1754227.video.history.0.timestamp}
{cameras.1754227.video.history.0.source}
... through slot 9
```

`source = "cloud"` означает, что клип был получен непосредственно из облака Blink (быстро, без загрузки с USB-накопителя).

`source = "local_storage"` означает, что клип был загружен с USB-накопителя модуля синхронизации 2 через облако.

## Примечания
— Предупреждения, связанные с питанием от батареи, обрабатываются через состояния `battery.*`.
- Устройства без встроенного аккумулятора, такие как Mini/Owl/PanTilt, не подпадают под действие предупреждений о заряде батареи.
— В этом случае `battery.lastMessage` устанавливается в значение `нет встроенной батареи`.
— Состояние изображения в реальном времени обновляется при получении снимка или при включении функции создания снимков в реальном времени.
- Состояния потока MJPEG имеют значение только в том случае, если потоковая передача включена в конфигурации адаптера.
- Собственные состояния сессии LiveView (`live.mode`, `live.active`, `live.url`, …) не зависят от вспомогательной функции веб-сетки MJPEG; перед вызовом `commands.start_live` на более старых моделях камер проверьте `live.unsupported`.
— Состояния функции Smart Detection обновляются при наличии классифицированных метаданных о движении из облака Blink Cloud.

## Дополнительная веб-сетка LiveView
Адаптер может дополнительно устанавливать и обновлять вспомогательный скрипт для веб-сетки LiveView.

Этот вспомогательный скрипт создаётся в пространстве имён JavaScript-адаптера ioBroker следующим образом:

```text
script.js.common.blink-video-url-server
```

Это сделано намеренно и используется только для дополнительной функциональности веб-сетки / вспомогательного средства LiveView. Существующие пользовательские скрипты с тем же идентификатором объекта могут быть перезаписаны. Если вы используете пользовательскую версию этого скрипта, пожалуйста, создайте резервную копию перед включением или обновлением этой функции.

> **Примечание:** Этот вспомогательный инструмент для веб-сетки является отдельной функцией от описанной выше встроенной сессии LiveView (`commands.start_live` / `live.url`). Встроенная сессия не требует адаптера JavaScript или `ffmpeg` и является рекомендуемой отправной точкой, если вам нужен только URL-адрес прямой трансляции с одной камеры в VIS или другой интеграции.

### Требования
Для работы веб-сетки LiveView требуется:

* JavaScript-адаптер ioBroker
* Программа `ffmpeg` установлена в хост-системе и доступна в `PATH`.
* Поддерживаются камеры Blink, использующие текущий протокол IMMI/MCLV LiveView.
* Сетевой доступ с хоста ioBroker к облачным сервисам Blink

В системах Debian/Ubuntu пакет `ffmpeg` обычно можно установить с помощью команды:

```bash
sudo apt update
sudo apt install ffmpeg
```

### Совместимость с камерами
Не все поколения камер Blink предоставляют одинаковый поток LiveView.

Камеры, использующие текущий поток IMMI/MCLV LiveView, могут быть преобразованы в поток HLS для веб-сети. Более старые камеры на базе XT/XT2/LFR могут не предоставлять пригодный для использования поток этим методом. В этом случае адаптер обнаруживает неподдерживаемое состояние LiveView и отключает кнопку LiveView для этой камеры вместо запуска прерванного потока. Тот же флаг `live.unsupported` также применяется к собственной сессии LiveView (`commands.start_live`).

### Примечания
Веб-сетка LiveView — это удобная функция. Основные функции адаптера, такие как вход в систему, обнаружение устройств, состояния движения, состояния батареи, миниатюры и загрузка видео, не требуют вспомогательного скрипта JavaScript или `ffmpeg`.
Вспомогательный скрипт веб-сетки LiveView поддерживается только в установках ioBroker на базе Linux. Он использует пути Linux и обрабатывает команды, такие как `/opt/iobroker`, `/tmp`, `/usr/bin/node`, `nohup` и `pkill`. Основная функциональность адаптера остается платформенно-независимой, но для функций веб-сетки LiveView требуется хост Linux.
