## Общие варианты прогноза

Для прогнозирования мы различаем два основных варианта:

- качественный прогноз или
- количественный прогноз

### Качественный прогноз

Качественные прогнозы — это субъективные оценки, которые создаются интуитивно экспертами, обладающими глубокими специализированными знаниями.

Возможный вариант — линейная экстраполяция → прошлые значения приблизительно проецируются в будущее.

Ещё одним вариантом являются опросы общественного мнения.

### Количественный прогноз

Количественные прогнозы в основном заключаются в обработке данных. Они дают конкретные числовые результаты.

Наиболее распространенными и известными количественными прогнозами являются прогнозы погоды.

## Прогнозирование в ioBroker.smartgarden

_**Всё есть данные — данные есть всё**_

Интеллектуальное устройство идеально подходит для сбора данных. Одни и те же процессы происходят регулярно. Поэтому в Smartgarden реализована функция прогнозирования, которая собирает некоторые исторические данные и использует их для прогнозирования оставшегося времени зарядки и кошения.

Насколько я понимаю, время кошения значительно меняется в течение года. Время кошения зависит от роста газона. Поэтому это учитывается в данной реализации. Точно так же, как и тот факт, что встроенный аккумулятор подвержен старению и со временем неизбежно теряет емкость.

### Что реализовано?

Данная система хранит исторические данные о циклах кошения и зарядки.

Приведенное ниже описание не зависит от времени кошения или зарядки — оно подходит для обоих случаев.

Для хранения исторических данных существует набор реальных циклов. Один реальный цикл содержит 101 элемент (например, емкость вашей батареи изменяется от 0 до 100 → 101 элемент). В каждом элементе сохраняется метка времени и текущая емкость батареи (в процентах).

Когда цикл завершается,

- Проверяется достоверность, и
- Разница во времени с конечным временем рассчитывается для каждого уровня заряда батареи.

#### Пример — зарядка аккумулятора.

| Емкость \[%}                        | 0     | 1     | 2     | 3     | ... | 98    | 99    | 100   |
| ----------------------------------- | ----- | ----- | ----- | ----- | --- | ----- | ----- | ----- |
| Время \[мин:сек]                    | 10:00 | 10:02 | 10:05 | 10:06 | ... | 13:16 | 13:18 | 13:20 |
| Δ время \[сек] для завершения цикла | 200   | 198   | 195   | 194   | ... | 4     | 2     | 0     |

Как видите, процесс начался с 0% (первая строка) в 10:00 (вторая строка) и закончился на 100% в 13:20. Разница во времени для каждого элемента указана в третьей строке. Как видите, разница во времени была почти линейной, но для перехода от 1% емкости к 2% батарее потребовалось немного больше времени.

Если бы вам нужно было спрогнозировать время, необходимое для следующей зарядки аккумулятора, вы бы наверняка сказали:

- При нулевой емкости: для полной зарядки аккумулятора требуется 200 секунд.
- При уровне заряда 1: для полной зарядки аккумулятора требуется 198 секунд.
- При уровне заряда 2: для полной зарядки аккумулятора требуется 195 секунд.
- При уровне заряда 3: для полной зарядки аккумулятора требуется 194 секунды.
- ...
- При емкости 99: для полной зарядки аккумулятора требуется 2 секунды.
- При емкости 100: для полной зарядки аккумулятора требуется 0 секунд.

Все эти прогнозные значения доступны в ваших исторических данных.

Как уже писалось, существует набор таких циклов. При наличии нескольких циклов для прогнозирования одного значения формируется среднее значение отдельных величин. Это снижает влияние возможных ошибок данных.

Разумеется, ваша газонокосилка не начнет заряжаться при 0% заряда батареи, или, другими словами, она не будет косить, пока батарея полностью не разрядится.

### Выявление недопустимых данных

Одна из самых больших проблем в статистике — выявление некорректных данных. Для этого ведется мониторинг ошибок. Кроме того, проводится базовая и расширенная проверка.

#### Проверка ошибок

Ошибки во время кошения постоянно отслеживаются. В данном контексте ошибка возникает, когда значение точки данных`state_value` не равен`OK` .

#### Базовая проверка

Для того чтобы запись в истории считалась действительной, необходимо зафиксировать завершение действия (кошение или зарядку). Это фиксируется изменением статуса.

- для завершения стрижки:
  - точка данных:`activity_value`
    | старый статус                                 | новый статус                    |
    | --------------------------------------------- | ------------------------------- |
    | `OK_CUTTING` или`OK_CUTTING_TIMER_OVERRIDDEN` | `OK_SEARCHING` или`OK_CHARGING` |

- По окончании зарядки:
  - точка данных:`batteryState_value`
    | старый статус | новый статус |
    | ------------- | ------------ |
    | `CHARGING`    | `OK`         |

#### Улучшенная проверка с помощью диаграммы размаха.

Дополнительную проверку корректности проводят с помощью метода ящичных диаграмм. Описание ящичных диаграмм можно найти в Википедии (на [английском](https://en.wikipedia.org/wiki/Box_plot) и [немецком языках](https://de.wikipedia.org/wiki/Box-Plot) ).

Для отображения уровня заряда батареи в конце действия строится диаграмма размаха.

Это значение, безусловно, будет меняться со временем, но быстрых и значительных изменений не следует ожидать. Ошибки в данных, например, из-за остановки кошения вручную, можно надежно выявить.

_Для уточнения:_ адаптер не создает реальные графики, а подготавливает данные так, как если бы графики были созданы, чтобы можно было определить, распознаются ли данные как действительные или нет.

### Обработка недопустимых данных

Некорректные данные не сохраняются в истории изменений.

Если адаптер обнаружит более 10 недействительных наборов истории подряд, вся история будет удалена.
