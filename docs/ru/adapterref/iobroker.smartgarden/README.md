# ioBroker.smartgarden

## Адаптер ioBroker smartgarden для интеллектуальной системы GARDENA

Адаптер для интеллектуальной системы GARDENA, использующий официальный [API и сервисы интеллектуальной системы GARDENA](https://developer.husqvarnagroup.cloud/apis/GARDENA+smart+system+API#/general) .

Адаптер позволяет разрабатывать приложения (например, с использованием VIS), которые можно использовать параллельно с официальным приложением GARDENA. Адаптер и его дополнительные функции не влияют на основные функции приложения GARDENA и наоборот.

Адаптер не является полной заменой приложения GARDENA, а лишь дополнением, позволяющим интегрировать устройства GARDENA в систему умного дома с помощью ioBroker. С помощью адаптера можно выполнять самые важные действия. Он также предоставляет возможность реализовать собственные идеи, которые невозможны с приложением GARDENA.

## Поддерживаемые устройства

- Умные роботизированные газонокосилки GARDENA SILENO
- Система интеллектуального управления орошением GARDENA
- Насос высокого давления GARDENA Smart
- Система интеллектуального управления водоснабжением GARDENA
- Умный адаптер питания GARDENA
- Умный датчик GARDENA

Более подробную информацию об устройствах можно найти на [немецком сайте GARDENA](https://www.gardena.com/de/produkte/smart/smartsystem/) , а также [здесь (на английском языке)](https://www.gardena.com/uk/products/smart/smart-system/) .

## Требования

Для использования этого адаптера вам понадобятся следующие вещи:

1. учетная запись интеллектуальной системы GARDENA
2. ключ приложения GARDENA
3. секрет приложения GARDENA

Чтобы получить эти возможности, пожалуйста, перейдите на портал разработчиков Husqvarna по адресу <https://developer.husqvarnagroup.cloud/> .

Пожалуйста, зарегистрируйтесь или войдите в систему, если у вас уже есть учетная запись, и создайте новую заявку, чтобы получить _ключ_ и _секретный_ ключ приложения.

## Точки данных адаптера

Адаптер предназначен для мониторинга и управления устройствами интеллектуальной системы GARDENA. Для этого потребуется один адаптер.`LOCATION` и один или несколько`DEVICE` 's. Для каждого`DEVICE` будет

- один`SERVICE_COMMON_<id>` и
- один или несколько`SERVICE_<servicelink_type>_<id>` .

Где`<servicelink_type>` Это описание типа устройства, например, газонокосилка или клапан.`<id>` Это (закодированный) идентификатор устройства GARDENA, используемый API. См. описание ServiceLink по адресу <https://developer.husqvarnagroup.cloud/apis/GARDENA+smart+system+API#/swagger> .

Управление/мониторинг каждого устройства возможен через`SERVICE_<servicelink_type>` перечислены в следующей таблице.`SERVICE_COMMON` Предоставляет общую информацию об устройстве.

| устройство                                  | SERVICE\_\<servicelink\_type>                         |
| ------------------------------------------- | ----------------------------------------------------- |
| умная роботизированная газонокосилка SILENO | SERVICE\_MOWER и SERVICE\_COMMON                      |
| интеллектуальное управление орошением       | SERVICE\_VALVE\_SET, SERVICE\_VALVE и SERVICE\_COMMON |
| интеллектуальный насос высокого давления    | SERVICE\_VALVE и SERVICE\_COMMON                      |
| интеллектуальное управление водой           | SERVICE\_VALVE и SERVICE\_COMMON                      |
| интеллектуальный адаптер питания            | SERVICE\_POWER\_SOCKET и SERVICE\_COMMON              |
| интеллектуальный датчик                     | SERVICE\_SENSOR и SERVICE\_COMMON                     |

Если вам нужна дополнительная информация о точках данных, пожалуйста, ознакомьтесь с информацией по ссылке <https://developer.husqvarnagroup.cloud/apis/GARDENA+smart+system+API#/swagger> . Там вы найдете описание каждой точки данных, за исключением тех, которые помечены как точки данных адаптера, а не API интеллектуальной системы GARDENA.

При выборе функции адаптер создает собственные точки данных для различных функций/опций. Эти точки данных не удаляются автоматически при снятии выбора с функции. Если они вам больше не нужны, их можно удалить вручную.

### Общие сведения о точках данных

Адаптер не изменяет значения, передаваемые API интеллектуальной системы GARDENA. Единственное, что делается (начиная с версии 1.0.0), — это проверка типа _временных меток_ и _чисел_ .

| проверить       | описание                                                                                                                                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| временные метки | Все метки времени указаны в формате UTC; если полученная метка времени не является действительной,`01 Jan 1970 00:00:00Z` Вместо этого используется (нулевое время Unix). Поэтому, если вы видите эту дату/время, пожалуйста, сообщите об этом. |
| числа           | если число не является допустимым,`-1` Вместо этого используется другое число. Поэтому, если вы увидите этот номер, пожалуйста, сообщите об этом.                                                                                               |

Запросы на управление устройством будут успешно выполнены, как только команда будет принята интеллектуальным шлюзом. Успешное выполнение команды на самом устройстве можно наблюдать по соответствующему изменению состояния. _Пример:_ отправка команды на запуск службы VALVE интеллектуального управления водоснабжением приведет к следующему результату:`activity_value` Данные сервиса, которые необходимо изменить после обработки командой устройством.

**Примечания:**

- Запросы на управление устройством не могут быть отправлены, пока адаптер smartgarden не подключен к API интеллектуальной системы GARDENA.
- Пожалуйста, убедитесь, что вы задали значение для команды с помощью`ack=false` См. [главу «Команды и состояния» в руководстве для разработчиков адаптеров.](https://github.com/ioBroker/ioBroker.docs/blob/master/docs/en/dev/adapterdev.md#commands-and-statuses)

### Для SERVICE\_MOWER

#### Контроль

Для управления устройством используйте точку данных.

- `activity_control_i` : тип`string`

  _Эта точка данных генерируется адаптером и не требуется благодаря API интеллектуальной системы GARDENA._

  Измените этот параметр, чтобы запустить газонокосилку.

  - Чтобы начать выполнение задания на заданное время, установите значение, равное запланированной продолжительности в секундах (пожалуйста, используйте числа, кратные 60; минимальное значение — 60); учитывайте тип данных.`string`
  - для автоматической работы установите строку`START_DONT_OVERRIDE`
  - Чтобы отменить текущую операцию и вернуться на зарядную станцию, используйте строку.`PARK_UNTIL_NEXT_TASK`
  - Чтобы отменить текущую операцию, вернитесь на зарядную станцию и проигнорируйте строку использования расписания.`PARK_UNTIL_FURTHER_NOTICE`

  **Примечание:** газонокосилка запускается только при полностью заряженном аккумуляторе.

#### Мониторинг

Все остальные данные используются исключительно для мониторинга и в информационных целях.

Особые данные:

- `activity_mowing_i`

  _Эта точка данных генерируется адаптером и не требуется благодаря API интеллектуальной системы GARDENA._

  Эта точка данных показывает два разных состояния газонокосилки:

  - `true` : кошение или
  - `false` Не косит.

  Эти данные можно использовать для дальнейших действий, когда важно знать, находится ли газонокосилка на газоне в безопасном положении.

  В зависимости от значения точки данных`activity_value` Данная точка данных задана. Подробности см. в следующей таблице.

  | `activity_value`                                                                                                   | `activity_mowing_i` |
  | ------------------------------------------------------------------------------------------------------------------ | ------------------- |
  | `OK_CHARGING` Газонокосилка должна косить, но из-за недостаточного уровня заряда она остается на зарядной станции. | ЛОЖЬ                |
  | `PARKED_TIMER` Газонокосилка припаркована в соответствии с таймером и снова запустится в заданное время.           | ЛОЖЬ                |

      },

        "14": {                      <<< hour

        },

## Полив во время кошения травы запрещен.

### В чём проблема?

Если у вас есть и газонокосилка, и система орошения с выдвижными дождевателями, существует риск того, что ваша газонокосилка во время работы системы орошения может задеть один из дождевателей и повредить его или причинить себе ущерб.

Чтобы этого избежать, систему орошения или, еще лучше, отдельные клапаны следует отключать во время работы газонокосилки.

### Что делается?

Благодаря этой функции можно остановить полив, когда газонокосилка находится на газоне. Это можно настроить отдельно для каждого клапана.

Для каждого клапана можно назначить одну или несколько косилок, при этом клапан не должен быть открыт во время работы косилки. В основном, косилка имеет приоритет над орошением, то есть, если возникает конфликт, когда косилка работает, а клапан открыт, клапан закрывается и устанавливается соответствующее предупреждение.

Кроме того, можно установить правило, согласно которому клапан никогда не должен открываться, независимо от того, работает газонокосилка или нет. Например, это можно использовать, если клапан или труба за ним повреждены.

В конфигурации экземпляра проверку можно включить или выключить целиком с помощью параметра _«Проверка орошения»_ .

Для каждого из них доступно три параметра.`SERVICE_VALVE` Они используются для настройки и для сообщения о предупреждениях.

| точка данных                              | записываемый | Описание точек данных                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `irrigationWhileMowing_allowed_i`         | да           | установить на`false` Необходимо проверить, разрешено ли полив во время работы газонокосилки на газоне.`true` в противном случае                                                                                                                                                                                                                              |
| `irrigationWhileMowing_mowerDefinition_i` | да           | один или несколько идентификаторов`SERVICE_MOWER` которые проверяются. Формат идентификатора газонокосилки см. ниже. Существует специальный код.`IRRIGATION_FORBIDDEN` Это означает, что клапан всегда закрыт независимо от того, работает газонокосилка или нет. Если необходимо установить несколько идентификаторов, разделите их точкой с запятой.`;` ). |
| `irrigationWhileMowing_warningCode_i`     | нет          | Предупреждающий код устанавливается, если клапан открывается. Возможные предупреждающие коды см. в следующей таблице. Если установлено более одного предупреждения, коды объединяются.`+` (например`STOPPED+UNKNOWN_MOWER` ).                                                                                                                                |

- _**формат идентификатора газонокосилки**_

  `smartgarden.0.LOCATION_xxxxxxxx-xxxxxx-xxxxxx-xxxxxx-xxxxxxxxxxxxxx.DEVICE_xxxxxxxx-xxxxxx-xxxxxx-xxxxxx-xxxxxxxxxxxxxx.SERVICE_MOWER_xxxxxxxx-xxxxxx-xxxxxx-xxxxxxxxxxxxxxxxxxxxx`

  Вы можете скопировать этот идентификатор газонокосилки со вкладки «Объекты» в ioBroker, см. красную стрелку на следующем рисунке.

  ![идентификатор газонокосилки](../../../en/adapterref/iobroker.smartgarden/img/mowerid_admin5.jpg)

- _**коды предупреждений**_
  | код предупреждения | описание                                                                                                                    |
  | ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
  | `NO_WARNING`       | Без предупреждения, клапан открыт.                                                                                          |

- клапан открывается или
- газонокосилка начинает косить

Программа не запускается при изменении значений в указанных выше параметрах данных. Это означает: если возникает конфликтная ситуация и вы вносите изменения...`irrigationWhileMowing_allowed_i` от`true` к`false` Конфликт не распознается, и конфликт будет продолжаться. Аналогичное поведение наблюдается и при изменении...`irrigationWhileMowing_mowerDefinition_i` .

### Базовое поведение — ПРЕДУПРЕЖДЕНИЕ

Эта функция не может предотвратить открытие клапана во время работы газонокосилки. Например, это можно сделать вручную через приложение GARDENA или автоматически по расписанию.

Эта функция может закрыть клапан как можно быстрее только в случае конфликта. При этом конфликт может и не быть распознан. Поэтому может случиться так, что вода всё же протечёт. **Например, нельзя предотвратить выдвижение дождевателей и столкновение газонокосилки с ними** , но вероятность этого сведена к минимуму. **Таким образом, задача вашего приложения — обеспечить, чтобы этот конфликт никогда не возникал.**

### 0.4.0 
* (jpgorganizer) 2020-Mar-31
  - **NOTE:** with this version an additional dependency is necessary at runtime. 
  If it does not get installed together with the installation of this adapter, 
  please install seperately with 
  `npm install https://github.com/jpgorganizer/ioBroker.utils` or 
  `npm i @jpgorganizer/utils`
  - **NOTE:** you **must delete all states** of the adapter instance to 
  install this release and please check your application carefully for 
  necessary adjustments regarding type/role changes (see below) 
  - data types of (nearly) all data points adjusted for compliance with 
  ioBroker guidance: 
    * states now have special ioBroker type and role instead of former 
	`string`/`text` where applicable, e.g. `number`/`value.battery` for 
	`batteryLevel_value`, see 
	[Issue 3](https://github.com/jpgorganizer/ioBroker.smartgarden/issues/3)
  - data point `activity_value_i` replaced by `activity_mowing_i` with 
    type/role `boolean`/`indicator.working`: `true` means *mowing*, `false` 
  means *not mowing*
  - possibility to pre-define states integrated, see new switch 
  `PreDefine States` in adapter/instance configuration, see 
  [Issue 2](https://github.com/jpgorganizer/ioBroker.smartgarden/issues/2)
  - states are readonly now; except states for commands, see 
  [Issue 4](https://github.com/jpgorganizer/ioBroker.smartgarden/issues/4)
  - input field for `useTestVariable` in adapter/instance configuration 
  switched to a *checkbox* (former: *text*); please check your settings
  - error in command  `stop_all_valves_i` in VALVE_SET fixed
