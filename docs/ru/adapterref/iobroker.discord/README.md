# IoBroker.discord
![логотип](../../../de/admin/discord.png)

Этот адаптер [ioBroker] интегрирует бота [Discord] в ioBroker.

Адаптер создает дерево объектов с объектами и состояниями для серверов и каналов, где присутствует бот.

Он также создает дерево объектов для всех пользователей, которых видит бот.

Эти состояния затем позволяют боту получать и отправлять сообщения и файлы через Discord.

Кроме того, адаптер может регистрировать команды Discord с косой чертой.

Затем их можно использовать для запроса или установки состояний ioBroker.

## Функции
* ioBroker указывает для всех серверов бота информацию о приеме и отправке сообщений.
* ioBroker указывает для всех пользователей, которых видит бот, информацию о получении и отправке прямых сообщений.
* Упрощено подключение и отключение от серверов Discord для бота.
* Настройка статуса бота, включая действия
* При желании можно отслеживать статус посещаемости пользователя.
* При желании можно отслеживать состояние голосовой связи пользователей.
* Голосовые команды для участников сервера (заглушить звук, оглохнуть, отключиться)
* Обработка всех сообщений или только сообщений, упоминающих бота в каналах сервера.
* Обработка личных сообщений
* При желании, можно автоматически отвечать на упоминания бота смайликом.
* Файл `.json` содержит информацию о канале, пользователе и сообщении.
* Отправляйте сообщения, файлы, реакции (эмодзи), ответы или пользовательское содержимое сообщений в формате JSON.
* Список участников сервера и канала, включая назначенные им роли.
* Поддержка команд Discord с косой чертой для запроса и установки значений статуса.
* Поддержка пользовательских команд Discord с косой чертой, которые могут быть использованы в пользовательских скриптах (включая Blockly).
* Поддержка [text2command] (необходимо включать отдельно для каждого состояния `.message`)
* Отправка, редактирование и удаление сообщений, отправка и ожидание ответов на сообщения в пользовательских скриптах.
* Дополнительные параметры исходных состояний для большей гибкости в пользовательских скриптах
* Поддержка Blockly с пользовательскими блоками для отправки и редактирования сообщений, а также обработки пользовательских команд с косой чертой.

Что *не* поддерживается и *не* предполагается:

* Сообщения в ветках обсуждений
* Отправка и получение голосовых сообщений

Отсутствует какая-либо функция? Просто создайте запрос на добавление функции на [GitHub][Новая задача на GitHub].

## Создание Discord-бота
Для использования этого адаптера необходимо создать приложение-бота Discord.

1. Перейдите на [Портал разработчиков Discord] и войдите в свою учетную запись Discord, если вы еще не авторизованы.
2. В разделе «Приложения» нажмите кнопку «Новое приложение» в правом верхнем углу.

[![[Новое приложение](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/en/media/bot-creation-1.png)](../../../de/adapterref/en/media/bot-creation-1.png)

3. Выберите название для приложения (это будет название бота) и нажмите «Создать».

[![[Название приложения](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/en/media/bot-creation-2.png)](../../../de/adapterref/en/media/bot-creation-2.png)

4. (Необязательно) Загрузите иконку приложения, измените название (Название), измените описание (Описание), добавьте несколько тегов и сохраните изменения (Сохранить изменения).

[![[Настройки приложения](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/en/media/bot-creation-3.png)](../../../de/adapterref/en/media/bot-creation-3.png)

5. В левом меню перейдите в раздел _Бот_ и нажмите кнопку _Добавить бота_.

[![Добавить бота](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/en/media/bot-creation-4.png)](../../../de/adapterref/en/media/bot-creation-4.png) В следующем диалоговом окне нажмите «Да, сделайте это!», чтобы подтвердить создание бота.

6. После создания бота необходимо один раз нажать кнопку «Сбросить токен», чтобы получить токен бота.

Поскольку это аннулирует все предыдущие токены, необходимо подтвердить это, нажав кнопку «Да, сделать!» во всплывающем диалоговом окне.

После этого токен бота отобразится **один раз**, и его следует скопировать в безопасное место (например, в конфигурацию экземпляра адаптера).

7. На странице _Бот_ прокрутите вниз до раздела _Привилегированные намерения шлюза_ и активируйте _Намерение присутствия_, _Намерение участников сервера_ и _Намерение содержимого сообщения_. Не забудьте сохранить изменения (_Сохранить изменения_).

[![[Привилегированные намерения шлюза](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/en/media/bot-creation-6.png)](../../../de/adapterref/en/media/bot-creation-6.png) Примечание: Как только бот появится более чем на 100 серверах, эти намерения потребуют проверки и одобрения со стороны Discord.

8. Теперь всё готово для запуска экземпляра адаптера и добавления бота на сервер Discord.

## Добавить бота на сервер
Чтобы добавить бота на сервер, используйте вкладку «Добавить бота на сервер» в конфигурации экземпляра адаптера.

Там отобразится ссылка, позволяющая добавить бота на сервер с автоматической настройкой всех необходимых разрешений и областей действия.

[![Добавить бота на сервер](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/de/media/bot-zu-server-hinzufuegen.png)](../../../de/adapterref/iobroker.discord/media/bot-zu-server-hinzufuegen.png)

Для работы адаптера требуются следующие разрешения бота:

* Изменить никнейм
* Читать сообщения/просматривать каналы
* Участники модерируют
* Отправить сообщения
* Встраивание ссылок
* Прикрепить файлы
* Прочитать историю сообщений
* Упомяните всех
* Добавить реакции
* Отключить уведомления
* Отключить участников
* Переместить участников

Кроме того, необходимы следующие области применения:

* бот
* applications.commands

Если отсутствуют разрешения или области действия приложения, то некоторые функции адаптера работать не будут.

### Удалить бота с сервера
Чтобы удалить бота с сервера, ниже на той же странице конфигурации экземпляра адаптера выберите сервер и нажмите кнопку «Покинуть сервер!», чтобы сообщить боту о необходимости покинуть сервер.

## Штаты
Каждый сервер, канал и пользователь идентифицируются своим уникальным числовым идентификатором.

Поскольку имена могут меняться, дерево объектов, создаваемое адаптером, использует эти идентификаторы для установления надежной структуры.

Всё дерево объектов генерируется на основе того, что видит бот.

Поэтому возможно, например, что на сервере может быть больше каналов, чем отображается.

### Discord.0.bot.*
| Имя | Описание |
|---|---|
| `activityType` | Тип активности бота. Возможные значения: `Playing`, `Streaming`, `Listening`, `Watching`, `Competing`, `Custom` или пустая строка. |
| `status` | Статус присутствия бота. Возможные значения: `online`, `idle`, `dnd` и `invisible`. |
| `status` | Статус присутствия бота. Возможные значения: `online`, `idle`, `dnd` и `invisible`. |

Эти состояния используются для определения статуса присутствия и активности бота, а также того, как эта информация будет отображаться пользователям.

### Discord.0.servers.\<server-id\>.*
| Имя | Описание |
|---|---|
| `channels.*` | Каналы сервера. |
| `members.*` | Участники сервера. |

### Discord.0.servers.\<server-id\>.channels.\<channel-id\>.*
| Имя | Описание |
|---|---|
| `channels.*` | Присутствует только в том случае, если канал является категорией. Структура такая же, как и для серверных каналов. |
| `members` | Список участников канала (отображаемые имена), разделенный запятыми. |
| `message` | Последнее сообщение, полученное в этом канале. |
| `messageId` | Идентификатор последнего полученного сообщения. |
| `messageAuthor` | Автор (уникальное имя пользователя или пользовательский тег) последнего полученного сообщения. |
| `messageTimestamp` | Временная метка последнего полученного сообщения. |
| `messageJson` | JSON-данные последнего полученного сообщения. |
| `send` | Отправка текстовых сообщений или сообщений в формате JSON. |
| `sendFile` | Отправка файла. |
| `sendReply` | Отправка ответа на сообщение. |
| `sendReaction` | Отправка реакции (эмодзи) на сообщение. |
| `json` | JSON-данные информации о канале. |
| `json` | JSON-данные с информацией о канале. |

Для всех состояний `message*` и `send*` см. раздел _Сообщения_ ниже.

### Discord.0.servers.\<server-id\>.members.\<user-id\>.*
| Имя | Описание |
|---|---|
| `tag` | Уникальный тег пользователя в Discord. |
| `displayName` | Отображаемое имя пользователя на сервере. |
| `roles` | Разделенный запятыми список ролей пользователя на сервере. |
| `joinedAt` | Отметка времени подключения пользователя к серверу. |
| `voiceChannel` | Голосовой канал, к которому пользователь в данный момент подключен, или пустая строка, если он не подключен. |
| `voiceDisconnect` | Кнопка для отключения пользователя от голосового канала. |
| `voiceSelfDeaf` | Индикатор того, отключил ли пользователь свой слух. |
| `voiceSelfMute` | Индикатор того, отключил ли пользователь звук. |
| `voiceServerDeaf` | Индикатор того, был ли пользователь оглушен сервером. Также может использоваться для изменения этого статуса. |
| `voiceServerMute` | Индикатор того, отключен ли пользователь сервером. Также может использоваться для изменения этого статуса. |
| `json` | JSON-данные с информацией о пользователе. |
| `json` | Данные в формате JSON, содержащие информацию о пользователе. |

Для актуальности состояний `voice*` необходимо включить в конфигурации экземпляра опцию _Мониторинг состояния голосового чата пользователей_.

Для использования действий `voiceDisconnect`, `voiceServerDeaf` и `voiceServerMute` бот должен иметь соответствующие разрешения на сервере.

### Discord.0.slashCommands.\<command-name\>.*
Если в конфигурации экземпляра адаптера включены пользовательские команды, существуют следующие дополнительные состояния.

Все эти состояния обновляются при каждом вызове заданной пользователем команды.

| Имя | Описание |
|---|---|
| `json` | Данные JSON из последнего использования команды. Содержит дополнительную информацию, не включенную в отдельные состояния. |
| `userId` | Идентификатор пользователя, выполнившего команду. |
| `userTag` | Уникальный тег пользователя, выполнившего команду. |
| `userName` | Имя пользователя, выполнившего команду. (Один раз, если `userTag` заканчивается на `#0`) |
| `channelId` | Идентификатор канала, в котором была вызвана команда. |
| `serverId` | Идентификатор сервера, на котором была вызвана команда, или `null`, если команда была вызвана в личном сообщении. |
| `timestamp` | Временная метка последнего использования команды. |
| `option-*` | Параметры, указанные для команды. Для каждого настроенного параметра создается отдельное состояние. Если параметр не указан при вызове команды, то соответствующее состояние устанавливается в `null`. |
| `option-*.value` | Последнее значение, указанное для параметра при вызове команды. Если параметр не указан, соответствующее состояние устанавливается в `null`. |
| `option-*.choices` | Массив JSON с предопределенными вариантами выбора для этой опции. Присутствует только для вариантов текстового типа. Пример: `["Wert 1", "Wert 2", { "name": "Wert 3", "value": "w3" }]` |
| `sendReply` | Отправить ответ на вызванную команду. Как и в случае с состояниями каналов или пользователей `.send`, это может быть строка или объект JSON. См. раздел _Сообщения_ ниже. |
| `sendReply` | Отправляет ответ на вызванную команду. Как и в случае с состояниями `.send` каналов или пользователей, это может быть строка или объект JSON. См. раздел _Сообщения_ ниже. |

**Примечание:** Рекомендуется использовать состояние `json` в собственных скриптах во избежание конфликтов.

Пример: Пользовательский скрипт считывает отдельные состояния `option-*`, и когда пользователь запускает команду снова, параметры из первого и второго запусков команды смешиваются.

### Discord.0.raw.*
Если в конфигурации экземпляра адаптера включена поддержка необработанных состояний, становятся доступны следующие дополнительные состояния.

**Примечание:** Эти состояния содержат необработанные данные без какой-либо проверки, фильтрации или модификации со стороны адаптера. Серверы называются гильдиями.

| Имя | Описание |
|---|---|
| `messageJson` | Необработанные JSON-данные последнего полученного сообщения. (Сообщения канала и личные сообщения) |
| `interactionJson` | Необработанные JSON-данные последнего полученного взаимодействия (например, команды со слэшем) |

## Авторизация
По умолчанию авторизация включена, и только авторизованные пользователи смогут взаимодействовать с адаптером.

Авторизованных пользователей и роли сервера можно определить в конфигурации экземпляра адаптера, включая разрешения для каждого пользователя/роли.

Для ролей сервера разрешения применяются только к соответствующему серверу, а не к другим серверам или в прямых сообщениях.

Если разрешения назначены для каждого пользователя и роли сервера, они объединяются для соответствующего сервера.

Пользователи и роли идентифицируются по их внутреннему идентификатору, поэтому даже изменения в теге пользователя, имени пользователя или имени роли не влияют на авторизацию.

Также можно отключить авторизацию. Однако это следует делать только в том случае, если всем пользователям на всех серверах бота можно доверять!

## Новости
Адаптер способен принимать и отправлять сообщения из текстовых каналов Discord и от пользователей.

По умолчанию в каналах обрабатываются только сообщения, содержащие упоминание бота.

Для обработки сообщений без упоминаний необходимо включить параметр «Обрабатывать все сообщения в каналах сервера» в конфигурации экземпляра.

При получении сообщения с упоминанием бота адаптер отвечает смайликом.

Это можно настроить в конфигурации экземпляра адаптера.

Если включена авторизация, бот будет отвечать только на упоминания от авторизованных пользователей.

### Получать сообщения
Полученные сообщения сохраняются в состояниях `.message*` соответствующего объекта канала для сообщений канала или объекта пользователя для прямых сообщений.

При включенной авторизации по умолчанию сохраняются только сообщения от авторизованных пользователей.

Это можно изменить с помощью параметра _Обрабатывать сообщения от неавторизованных пользователей_ в конфигурации экземпляра адаптера, чтобы сообщения от неавторизованных пользователей также сохранялись.

Последнее полученное сообщение для каждого канала/пользователя всегда хранится в состоянии `.message`.

В соответствующих состояниях хранятся метка времени, отправитель и идентификатор последнего полученного сообщения.

Кроме того, вся эта информация также хранится в формате JSON в состоянии `.messageJson`.

#### Использование text2command
Для использования text2command необходимо выбрать экземпляр text2command в конфигурации экземпляра адаптера.

Для каждого состояния `.message` можно включить определяемую пользователем настройку _enable text2command for this state_.

Если она включена, полученные сообщения будут отправляться выбранному экземпляру text2command.

Ответ от text2command отправляется адаптером либо как ответ, либо как обычное сообщение, либо не отправляется вовсе, в зависимости от конфигурации экземпляра адаптера.

### Отправка сообщений
Для отправки сообщения его содержимое можно записать в состояния `.send*` канала или пользователя.

#### Отправка простых текстовых сообщений
Чтобы отправить простой текст, просто введите текст в состояние `.send` желаемого получателя.

Для форматирования текста можно использовать Discord Markdown, как и в клиенте Discord.

Для упоминания пользователя можно использовать его идентификатор в формате `<@Benutzer-ID>`.

Для упоминания групп можно использовать `<@&Gruppen-ID>`, а для каналов - `<#Kanal-ID>`.

Примеры: `Dies ist meine Nachricht.`, `Dies ist _meine_ **formatierte** Nachricht.`, `Hey <@490222742801481728>!`

Пример: `https://www.iobroker.dev/images/iobroker.png`

#### Отправка реакций
Состояние `.sendReaction` позволяет реагировать на предыдущие сообщения с помощью эмодзи. Просто введите эмодзи в это состояние.

По умолчанию ответ отправляется сообщению, идентификатор которого в данный момент содержится в соответствующем состоянии `.messageId`.

Для ответа на конкретное сообщение идентификатор сообщения, за которым следует символ вертикальной черты `|` и эмодзи, можно записать в состояние `.sendReaction`.

Примеры: `👍`, `971032590515568660|👍`

#### Отправка ответов
Вы можете отвечать на предыдущие сообщения, используя состояние `.sendReply`.

Просто напишите свой ответ в этом состоянии.

По умолчанию ответ отправляется на сообщение, идентификатор которого в данный момент содержится в соответствующем состоянии `.messageId`.

Если ответ должен быть отправлен на конкретное сообщение, идентификатор сообщения, за которым следует символ вертикальной черты `|`, и ответ могут быть записаны в состояние `.sendReply`.

Примеры: `Dies ist eine Antwort.`, `971032590515568660|Dies ist eine Antwort.`

## Команды с косой чертой
Если эта функция включена в конфигурации экземпляра адаптера, адаптер может использовать команды Discord с косой чертой. Эти команды можно использовать для запроса или установки состояний ioBroker.

**Примечание:** Доступные состояния для команд Discord с косой чертой необходимо настраивать индивидуально. Подробности см. ниже.

Команды Discord с косой чертой могут быть зарегистрированы адаптером как серверные команды (по умолчанию) или как глобальные команды. Это можно настроить в конфигурации экземпляра адаптера.

Использование серверных команд имеет то преимущество, что изменения в командах (например, добавление состояний) применяются немедленно, без задержки.

Однако серверные команды нельзя использовать в личных сообщениях между пользователем и ботом.

Глобальные команды также можно использовать в личных сообщениях, но любые изменения в командах могут применяться Discord в течение часа. Это ограничение Discord, а не адаптера.

Команды, обозначаемые косой чертой по умолчанию, - это `/iob-get` и `/iob-set`.

Названия и описания команд можно настроить в конфигурации экземпляра адаптера.

### Настройка состояний для команд со слэшем
Для каждого состояния, доступного через команды Discord, необходимо включить эту функцию в пользовательских настройках состояния.

Для этого просто щелкните значок шестеренки «Пользовательские настройки» в разделе «Объекты» в административной панели, включите настройки для экземпляра адаптера и активируйте параметр «Включить команды Discord для этого состояния».

[![[Активировать команды Discord](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/de/media/slash-befehl-konfiguration-1.png)](../../../de/adapterref/iobroker.discord/media/slash-befehl-konfiguration-1.png)

[![[Активировать команды Discord](https://github.com/crycode-de/ioBroker.discord/blob/main/docs/de/media/slash-befehl-konfiguration-2.png)](../../../de/adapterref/iobroker.discord/media/slash-befehl-konfiguration-2.png)

Для каждого состояния в Discord можно задать имя (_Name) и псевдоним (_Alias_).

Имя (_Name) используется для автозаполнения команд, а псевдоним (_Alias_) служит внутренним идентификатором. Оба параметра не должны превышать 100 символов.

Для каждого состояния можно индивидуально указать, должно ли оно быть доступно для запроса и/или установки.

Кроме того, можно включить отображение сообщения при запросе, если соответствующее состояние не подтверждено, или потребовать подтверждения перед установкой.

Для состояний типа данных `string` можно выбрать обработку значения как файла (местоположение файла).

Если эта опция включена, текущее значение состояния отправляется так же, как и для состояний `.sendFile`.

Это позволяет, например, запрашивать изображения с помощью команды запроса.

Для состояний типа данных `number` можно указать количество десятичных знаков для округления значения в командах запроса.

Для состояний типа данных `boolean` можно задать значения, определяемые пользователем, для `true` и `false`, которые затем используются для отображения в командах запросов и для обнаружения в командах наборов.

### Состояния запроса
Чтобы проверить статус, просто введите `/iob-get Zustandsalias` в клиенте Discord.

Для `Zustandsalias` по мере ввода команды будет появляться автозаполнение.

Каждое значение форматируется для вывода в соответствии с объектом состояния и связанными с ним пользовательскими настройками.

При желании добавляется информация, если состояние не подтверждено.

### Установить состояния
Чтобы запросить состояние, просто вызовите команду `/iob-set Zustandsalias Neuer-Wert` в клиенте Discord.

Для команды `Zustandsalias` по мере ввода появится автозаполнение.

Команда `Neuer-Wert` будет обработана адаптером, если тип данных состояния равен `boolean` или `number`.

Для каждого состояния можно индивидуально настроить, следует ли устанавливать значение с подтверждением или без него.

Для состояний типа данных `boolean` значения `true`, `on`, `yes`, `1` и их соответствующие преобразования (`wahr`, `an`, `ja`), а также заданное для состояния значение _True_, интерпретируются как `true`.

Любое другое значение интерпретируется как `false`.

Для состояний типа данных `number` указанное значение интерпретируется как десятичное число.

Если в настройках ioBroker в качестве десятичного разделителя используется запятая, то число может быть указано либо с запятой, либо с точкой в качестве десятичного разделителя. В противном случае допускается только точка в качестве десятичного разделителя.

Если в объекте состояния определены значения для `min` и `max`, они также проверяются.

### Получите обзор состояний с настройками для команд, содержащих косую черту.
Чтобы получить обзор всех состояний с активной конфигурацией для команд с косой чертой, вы можете нажать кнопку «Записывать в журнал объекты состояния, настроенные для команд» в конфигурации экземпляра адаптера. После этого вывод появится в журнале установки ioBroker.

### Пользовательские команды со слэшем
Пользовательские команды со слэшем можно включить и настроить в конфигурации экземпляра адаптера.

Настроенные пользовательские команды затем регистрируются в Discord вместе со стандартными командами get и set.

К любой пользовательской команде можно добавить параметры.

Эти параметры будут отображаться в клиенте Discord для данной команды.

Если параметр не указан при вызове команды, он будет иметь значение `null`.

Для параметров типа _Текст_ можно динамически задавать предопределенные варианты в соответствующем состоянии `option-*.choices` в виде массива JSON.

При вызове заданной пользователем команды соответствующие данные записываются в связанные с ней состояния. См. описание состояний в разделе «Состояния» выше.

Вся информация, включая параметры, записывается в состояние `.json` команды.

Это состояние следует использовать в первую очередь для сохранения данных команды в скриптах, поскольку вся необходимая информация хранится в одном месте, предотвращая путаницу даже при быстром выполнении нескольких вызовов команд.

Для параметров типа _User_, _Role_, _Channel_ или _Mentionable_ в объектах параметров заполняются дополнительные поля.

**Примечание:** Команду необходимо выполнить вручную, а затем отправить ответ. Это можно сделать, например, с помощью пользовательского скрипта.

Ответ должен быть отправлен в течение 15 минут через состояние `.sendReply` или связанное с ним действие `sendTo(...)`.

Если ответ не будет отправлен в течение этого времени, клиент Discord отобразит сообщение об ошибке «Приложение не отвечает».

**Примечание:** Ответ на команду может быть отправлен несколько раз.

Ответ будет отредактирован и перезаписан новым содержимым.

## Использовать в скриптах
В скриптах функция `sendTo(...)` может использоваться для взаимодействия с экземпляром адаптера.

Примечание: все используемые идентификаторы являются строками.

### Отправка сообщения в скрипте
Для отправки сообщения можно использовать команду `send` или `sendMessage`. Обе они идентичны.

Часть `message` в `sendTo(...)` должна представлять собой объект, содержащий `content` для отправки и один из следующих параметров для идентификации цели:

* `userId`
* `userTag`
* `userName`
* `serverId` и `channelId`

Параметр `content` может представлять собой простую строку или объект [MessageOptions].

Возвращаемое значение в функции обратного вызова `sendTo(...)` представляет собой объект, содержащий параметры сообщения и строку `result`, а также `messageId` отправленного сообщения Discord в случае успеха или сообщение `error` в случае ошибки.

Примеры:

```js
// Senden einer Nachricht zu einem Benutzer bei Verwendung des einmaligen Benutzernamens
sendTo('discord.0', 'sendMessage', {
  userName: 'crycode',
  content: 'Hi!',
}, (ret) => {
  log(ret);
  // {'result':'Message sent to user crycode','userName':'crycode','content':'Hi!','messageId':'971779972052155891'}

  if (ret.error) {
    log(ret.error, 'error');
    return;
  }
  log(`Nachricht gesendet mit ID ${ret.messageId}`);
});

// Senden einer Nachricht zu einem Benutzer bei Verwendung des Benutzer-Tags
// (für Bots und Benutzer, die noch nicht zu einem einmaligen Benutzernamen migriert sind)
sendTo('discord.0', 'sendMessage', {
  userTag: 'cryCode#9911',
  content: 'Hi!',
}, (ret) => {
  log(ret);
  // {'result':'Message sent to user cryCode#9911','userTag':'cryCode#9911','content':'Hi!','messageId':'971779972052160552'}

  if (ret.error) {
    log(ret.error, 'error');
    return;
  }
  log(`Nachricht gesendet mit ID ${ret.messageId}`);
});

// Senden einer Antwort zu einem Benutzer
sendTo('discord.0', 'sendMessage', {
  userId: '490222742801481728',
  content: {
    content: 'Ok!',
    reply: {
      messageReference: '971779972052160552', // ID der Nachricht, auf die geantwortet werden soll
    },
  },
}, (ret) => {
  log(ret);
  // {'result':'Message sent to user crycode','userId':'490222742801481728','content':{'content':'Ok!','reply':{'messageReference':'971779972052160552'}},'messageId':'971786369401761832'}
});

// Senden einer Datei an einen Serverkanal
sendTo('discord.0', 'sendMessage', {
  serverId: '813364154118963251',
  channelId: '813364154559102998',
  content: {
    content: 'Schau dir das an:',
    files: [
      {
        attachment: "/tmp/image.jpg",
        name: "image.jpg",
        description: "Mein tolles Bild"
      },
    ],
  },
}, (ret) => {
  log(ret);
  // {'result':'Message sent to channel Allgemein','serverId':'813364154118963251','channelId':'813364154559102998','content':{'content':'Schau dir das an:','files':[{'attachment':'/tmp/image.jpg','name':'image.jpg','description':'Mein tolles Bild'}]},'messageId':'971780152759558234'}
});
```

### Редактирование сообщения в скрипте
Предыдущие сообщения можно редактировать с помощью команды `editMessage`.

Конечно, редактировать можно только сообщения, отправленные ботом.

Часть `message` в `sendTo(...)` идентична части `sendMessage` (см. выше) с добавлением `messageId` сообщения, подлежащего обработке.

Возвращаемое значение такое же, как и для `sendMessage`.

Примеры:

```js
// Eine Nachricht bearbeiten
sendTo('discord.0', 'editMessage', {
  userName: 'crycode',
  content: 'Hallo!',
  messageId: '971495175367049276',
}, (ret) => {
  log(ret);
  // {'result':'Message edited','userName':'crycode','content':'Hallo!','messageId':'971495175367049276'}
});

// Nachricht senden und nach fünf Sekunden bearbeiten
sendTo('discord.0', 'sendMessage', {
    userName: 'crycode',
    content: 'Es ist jetzt: ' + new Date().toLocaleString(),
}, (ret) => {
  if (ret.error) {
    log(ret.error, 'error');
    return;
  }
  setTimeout(() => {
    sendTo('discord.0', 'editMessage', {
      userName: 'crycode',
      content:  'Es ist jetzt: ' + new Date().toLocaleString(),
      messageId: ret.messageId,
    }, (ret2) => {
      log(ret2);
      // {'result':'Message edited','userName':'crycode','content':'Es ist jetzt: 5.5.2022, 16:25:38','messageId':'971779692166266920'}
    });
  }, 5000);
});
```

### Удаление сообщения в скрипте

Конечно, удалять можно только сообщения, отправленные ботом.

Часть `message` в `sendTo(...)` идентична части `sendMessage` (см. выше), но без `content`, зато с добавлением `messageId` сообщения, подлежащего удалению.

Возвращаемое значение такое же, как и для `sendMessage`.

Пример:

```js
// Löschen einer Nachricht

  log(ret);
```

### Ожидание ответа на сообщение в скрипте
Можно дождаться реакции (эмодзи) на предыдущее сообщение, используя команду `awaitMessageReaction`.

Часть `message` в `sendTo(...)` идентична части `editMessage` (см. выше), но без `content`, зато с дополнительным `timeout` и номером `max`.

Параметр `timeout` обозначает максимальное время ожидания для сбора результатов реакций в диапазоне от 100 до 60000 мс.

Параметр `max` определяет максимальное количество реакций, которые необходимо собрать.

По умолчанию значение равно 1, если не указано иное.

Функция обратного вызова для ``sendTo(...)`` вызывается при достижении максимального времени ожидания или указанного количества ответов.

Возвращаемое значение представляет собой объект, содержащий параметры сообщения и массив ``reactions``. Каждый ответ представляет собой объект, состоящий из ``emoji``, ``emojiId`` и ``users``, где ``users`` - это массив объектов, содержащих ``id`` и ``tag``.

Если ответ представляет собой обычный эмодзи, то используются ``emojiId`` и ``null``.

Для пользовательских эмодзи ``emoji`` содержит имя, а ``emojiId`` - идентификатор эмодзи.

```js
sendTo('discord.0', 'awaitMessageReaction', {
  serverId: '813364154118963251',
  channelId: '813364154559102998',
  messageId: '970754574879162458',
  timeout: 10000,
  max: 3,
}, (ret) => {
  log(ret);
  // {'reactions':[{'emoji':'👍','emojiId':null,'users':[{'id':'490222742801481728', 'name': 'crycode','tag':'crycode#0'}]}],'serverId':'813364154118963251','channelId':'813364154559102998','messageId':'970754574879162458','timeout':10000,'max':3}
```

### Реагирование на пользовательские команды со слэшем в скрипте
Команда `sendCustomCommandReply` может использоваться для отправки ответа на вызов пользовательской команды.

Часть `message` из `sendTo(...)` должна представлять собой объект, содержащий `content` для отправки и `interactionId` вызова команды.

Параметр `content` может представлять собой простую строку или объект [MessageOptions] (как и в случае с `sendMessage`).

```js
on({ id: 'discord.0.slashCommands.iob-test.json', change: 'any', ack: true }, (obj) => {
  log(`Benutzerdefinierter Slash-Befehl ${obj.state.val}`);
  // Benutzerdefinierter Slash-Befehl {"interactionId":"977265764136517725","commandName":"iob-test","channelId":"813364154559102998","serverId":"813364154118963251","user":{"id":"490222742801481728", "name":"crycode","tag":"crycode#0","displayName":"Peter"},"timestamp":1653068714890,"options":{"myopt":{"value":"test","type":"String"}}}

  const data = JSON.parse(obj.state.val);

  let reply;
  if (data.options.myopt.value) {
    reply = {
      content: `Du hast mir "${data.options.myopt.value}" gegeben.`,
      embeds: [
        {
          title: 'Das ist großartig!',
          color: '#00AA00',
        },
      ],
    };
  } else {
    reply = `Du hast mir nichts gegeben. 🤨`;
  }

  sendTo('discord.0', 'sendCustomCommandReply', {
    interactionId: data.interactionId,
    content: reply,
  }, (ret) => {
    log(ret);
    // {'result':'Reply sent','interactionId':'977265764136517725','content':{'content':'Du hast mir \'test\' gegeben.','embeds':[{'title':'Das ist großartig!','color':'#00AA00'}]},'messageId':'977265765122183248'}
  });
});
```
