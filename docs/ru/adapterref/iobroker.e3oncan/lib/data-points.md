### Что такое точка данных?

На устройствах серии E3 вся информация организована в виде точек данных. Каждая точка данных имеет:

- числовой идентификатор (например)`256` )
- имя (например)`BusIdentification` )
- длина в байтах
- внутренняя структура, описываемая кодеком

При чтении и записи по шине CAN всегда передаются необработанные байты. Кодек преобразует эти байты в удобочитаемые значения. Если структура точки данных еще неизвестна,`RawCodec` Используется поток неизмененных байтов.

База данных известных точек данных поддерживается в проекте [open3e](https://github.com/open3e) . Этот адаптер и проект [E3onCAN](https://github.com/MyHomeMyData/E3onCAN) используют одну и ту же базу данных, созданную на основе open3e. Обновления вносятся периодически. Пользователи могут вносить свой вклад через форум обсуждения open3e, раздел "Проблемы" или запросы на слияние.

### Общие и вариантные точки данных

Некоторые точки данных имеют разную длину и структуру на разных устройствах. Для решения этой проблемы точки данных организованы в две категории:

- **Общие параметры данных** — единое определение, подходящее для большинства устройств.
- **Варианты данных** — альтернативные определения для устройств, к которым не применяется общее определение.

В процессе сканирования точек данных адаптер автоматически выбирает правильный вариант для каждого устройства.

Обзор всех известных точек данных, включая их варианты, доступен в [проекте open3e](https://github.com/open3e/open3e/blob/develop/src/open3e/Open3Edatapoints.md) .

### Метаданные

Начиная с версии open3e 0.6.1 и версии адаптера 0.11.0, многие точки данных содержат дополнительные метаданные:

| Поле метаданных     | Описание                                                                      |
| ------------------- | ----------------------------------------------------------------------------- |
| Описание            | Краткое, понятное для человека объяснение данных.                             |
| Физическая единица  | например, °C, кВт·ч, Вт (где применимо)                                       |
| Примечания / ссылка | Дополнительная информация или справочные материалы                            |
| Доступ              | Является ли точка данных доступной только для чтения или для чтения и записи. |

Метаданные добавляются к объектам точек данных во время сканирования точек данных. Для точек данных, созданных при запуске адаптера (например, после структурного изменения в определении), метаданные применяются автоматически. Для всех остальных существующих точек данных метаданные обновляются только при выполнении нового сканирования точек данных.

### Форматы данных для температуры, даты и времени.

Точка данных`382` Содержит конфигурацию формата данных устройства, включая:

- **Физический формат:** метрическая (°C) или имперская (°F) шкала
- **Формат даты:** ДеньМесяцГод, МесяцДеньГод, ГодМесяцДень
- **Формат времени:** двадцать четыре часа или двенадцать часов

Конфигурация по умолчанию:`Metric / DayMonthYear / TwentyFourHours` .

Начиная с версии адаптера 0.11.0, эта информация считывается во время сканирования устройств и сохраняется для каждого устройства. Затем сохраненная конфигурация применяется следующим образом:

- **В процессе сканирования точек данных:** единицы измерения температуры устанавливаются в °C (метрическая система) или °F (имперская система). Преобразование числовых значений не выполняется.
- **При чтении и записи** значения даты и времени интерпретируются в соответствии с сохраненным форматом. Например, в формате MonthDayYear ожидается дата, которая сохраняется как месяц-день-год, а не день-месяц-год.

> **Примечание:** Обработка нестандартных форматов даты/времени является экспериментальной функцией. Пожалуйста, внимательно проверьте результаты, если ваше устройство настроено не в стандартном формате.

Если точка данных`382` Если для устройства отсутствует конфигурация главного устройства (CAN-адрес), это означает, что она отсутствует.`0x680` ) используется в качестве резервного варианта. Если конфигурация вообще отсутствует, адаптер ведет себя так же, как и в версиях до 0.11.0.

### Возможность записи точек данных

Точка данных считается доступной для записи, если выполняется хотя бы одно из следующих условий:

- Его идентификатор включен в белый список.`e3oncan.0.<DEVICE>.info.udsDidsWritable` .
- В метаданных (доступно начиная с версии адаптера 0.11.0) указано, что доступ к нему возможен как для чтения, так и для записи.

Оба условия оцениваются; белый список продолжает работать как и прежде.

### Что происходит при запуске адаптера и после обновлений?

При каждом запуске адаптера версии существующих определений точек данных сравниваются с версиями, входящими в состав текущего адаптера. Если доступны более новые определения (например, после обновления адаптера), соответствующие точки данных обновляются автоматически. Этот процесс подробно регистрируется в журнале.

**Что ожидать во время обновления:**

- Если структура точки данных изменяется, то изменяется вся информация.`tree` Вложенный объект для этой точки данных удаляется и создается заново с новой структурой. Это необходимо для корректной работы адаптера, но имеет побочные эффекты:
  - **Архивные данные** по элементам пострадавших`tree` Вспомогательный объект может быть потерян.
  - Возможно, потребуется обновить **ссылки** на эти элементы в скриптах, визуализациях или других адаптерах.
- Если пользователь изменил какой-либо параметр данных, относящийся к конкретному устройству, перед применением обновления создается резервная копия исходной структуры.

> **Рекомендация для работы с бета-версией ioBroker:** перед первым запуском адаптера после обновления создайте резервную копию всех объектов экземпляра адаптера (например,`e3oncan.0` ) или, по крайней мере, объекты отдельных устройств.

### Выполнение сканирования точек данных

Сканирование точек данных обнаруживает все доступные точки данных на каждом устройстве и создает или обновляет соответствующие объекты в ioBroker.

**Что делает сканирование:**

- Обнаруживает все доступные точки данных на каждом настроенном устройстве.
- Добавляет или обновляет метаданные (описание, единица измерения, информация о доступе) для каждой существующей точки данных — подробности см. в параметре сохранения ниже.
- Устанавливает метки единиц измерения температуры на основе конфигурации формата устройства (точки данных).`382` ).
- При необходимости записывает значения, считанные во время сканирования, в дерево объектов (см. ниже).

**Опция: Сохранять все значения точек данных во время сканирования.**

В диалоговом окне сканирования есть флажок **«Сохранить все значения точек данных в дерево объектов во время сканирования»** :

- **Отмечено (по умолчанию):** Все значения, считанные во время сканирования, записываются в дерево объектов. Объекты, содержащие отсутствующие точки данных, создаются.
- **Снята галочка:** значения и метаданные записываются для _существующих_ объектов точек данных. Объекты точек данных, которые еще не существуют, _не_ создаются. Используйте этот параметр для обновления метаданных без расширения дерева объектов — например, после миграции с более старой версии адаптера.

**Когда следует запускать сканирование:**

- На этапе первоначальной настройки (настоятельно рекомендуется, необходимо для написания текста).
- После обновления адаптера, в котором добавлены новые определения точек данных.
- После обновления программного обеспечения устройств Viessmann.

> **Рекомендация:** Сначала выполните сканирование устройств (перейдите на вкладку **«Список устройств UDS»** , нажмите « **Начать сканирование…** »).

**Как начать сканирование:**

Откройте диалоговое окно настройки адаптера, перейдите на вкладку **«Список точек данных»** , нажмите « **Начать сканирование…»** и подтвердите нажатием кнопки **«ОК»** . Сканирование может занять до 5 минут. Ход выполнения отображается в журнале адаптера (откройте вторую вкладку браузера).

### Определяемые пользователем структуры точек данных в udsDidsSpecific

государство`e3oncan.0.<DEVICE>.info.udsDidsSpecific` хранит определения точек данных, специфичные для устройства, которые отличаются от общих определений в`didsE3.json` Это включает в себя:

- **Варианты точек данных** — определения, автоматически выбранные во время сканирования точек данных, поскольку устройство вернуло длину, соответствующую записи в`didsE3var.json` .
- **Определяемые пользователем структуры** — это определения, созданные или измененные пользователем вручную.

Каждая запись в`udsDidsSpecific` Это JSON-объект, ключом которого является числовой идентификатор. Адаптер отслеживает происхождение каждой записи с помощью...`source` поле:

| `source` ценить        | Значение                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| отсутствующий          | Определение, созданное пользователем, или автоматически размещенное до введения отслеживания версий (адаптер < 0.11.0) |
| `"didsE3var_YYYYMMDD"` | Автоматически устанавливается адаптером; версия`didsE3var.json` на момент последнего обновления                        |

**Поведение во время запуска адаптера и сканирования точек данных:**

- Записи с`source: "didsE3var_..."` обновлены до последней версии из`didsE3var.json` если структура изменилась.
- Записи без`source` поле, которое использует`RawCodec` (Автоматически добавленные на основе старых сканов) также обновлены.
- Резервная копия перезаписанных записей хранится в`Backup` подраздел`udsDidsSpecific` .

**Защита определяемой пользователем структуры от переопределения (адаптер ≥ 1.0.3):**

Если вы вручную определили или проверили структуру варианта данных и хотите предотвратить его переопределение адаптером, добавьте следующее:`"protected": true` поле для записи в`udsDidsSpecific` Вы можете добавить по желанию`"reason"` Поле со свободным текстовым описанием; этот текст включается в журнал адаптера всякий раз, когда применяется защита.

Пример записи для DID 2086:

```json
"2086": {
  "codec": "O3EComplexType",
  "len": 68,
  "id": "ZigBeeOneDeviceCurrentValues",
  "protected": true,
  "reason": "Custom ZigBee TRV structure verified for my device",
  "args": { ... },
  "source": "didsE3var_20260527"
}
```

Адаптер будет вести журнал`Variant datapoint ... is protected by user. Update skipped. Reason: "..."` и оставить определение без изменений как при запуске адаптера, так и во время сканирования точек данных.

> **Примечание:** Защита распространяется только на **варианты** данных (те, которые присутствуют в`didsE3var.json` Определения для общих точек данных (из`didsE3.json` ) хранятся в`udsDidsCommon` и не подвержены влиянию этого механизма.
