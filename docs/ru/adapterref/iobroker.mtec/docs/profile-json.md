# Входной профиль `json`

Простой, универсальный формат MQTT: одна тема на устройство, каждое сообщение — один JSON-объект со всеми текущими значениями и временем измерения. Его может создать любой источник данных, например, поток Node-RED, скрипт или ваш собственный считыватель Modbus.

Профиль доступен для обоих устройств: теплового насоса и Energy Butler.

## Темы

Одна тема на устройство. В настройках экземпляра выберите **JSON** в качестве источника данных для устройства и укажите его тему:

| Устройство               | Тема по умолчанию           |
| ------------------------ | --------------------------- |
| Тепловой насос           | `energy/heatpump/telemetry` |
| Энергетический дворецкий | `energy/butler/telemetry`   |

Если у вас нет устройства, установите для него в качестве источника данных значение « **Не присутствует»** . Для **формата JSON** тема обязательна.

## Сообщение

```json
{
  "name": "butler",
  "fields": {
    "battery_soc_percent": 81,
    "pv_total_power_w": 2300,
    "grid_import_power_w": 628,
    "grid_export_power_w": 0
  },
  "timestamp": 1791956345000
}
```

| Ключ        | Значение                                                            |
| ----------- | ------------------------------------------------------------------- |
| `fields`    | Объект со значениями, имя поля → число. Обязательно для заполнения. |
| `timestamp` | Время измерения в миллисекундах в формате Unix. Обязательно.        |
| `name`      | Необязательный параметр, игнорируемый адаптером.                    |

Значения представляют собой простые числа. Значения включения/выключения передаются следующим образом: `0` или `1`.

## Правила

- **Время измерения:** Каждое значение получает `timestamp` как его `ts` Таким образом, адаптеры истории (InfluxDB, SQL) хранят фактическое время измерения, а не время получения данных.
- **Дубликаты и более старые сообщения** обнаруживаются системой. `timestamp` и отбрасывается: сообщение обрабатывается только в том случае, если оно... `timestamp` является более новым, чем последний обработанный файл. Поэтому QoS 1 и буферизация на источнике не представляют проблемы.
- **Временные метки, отстающие более чем на 60 секунд,** отклоняются. В этом случае часы источника или хоста ioBroker показывают неверное время.
- **Одно сообщение представляет собой полный снимок состояния поля.** Отправляйте все имеющиеся у вас поля в каждом сообщении. Если какое-либо известное поле отсутствует или не является числом, его точка данных устанавливается в значение, равное... `null` с качеством `0x82` (датчик не выдал никакого значения), поэтому старое значение не сохраняется.
- **Отсутствующее значение не равно 0.** Если датчик неисправен, вместо отправки 0, оставьте его поле пустым. 0 — допустимое значение.
- **Новые поля,** не указанные ниже, создаются автоматически в виде чисел и регистрируются в журнале один раз. Их имя становится частью идентификатора точки данных, поэтому оно может содержать только строчные буквы, цифры и т. д. `_` должно начинаться с буквы и не должно быть `info` или `mtecmqtt` Другие имена игнорируются с предупреждением.
- **Устаревшие данные:** Если последнее измерение выполнено раньше установленного предела (по умолчанию 20 секунд), `<device>.info.stale` становится `true` Рекомендуется использовать интервал отправки в несколько секунд (например, 5 секунд).
- **QoS и сохранение:** работают как QoS 0, так и QoS 1. Сохранение не требуется; сохраненное сообщение обрабатывается как любое другое, `info.stale` свидетельствует о своем возрасте.

Анализ (`analysis.*`) использует `pv_total_power_w`, `grid_import_power_w`, `grid_export_power_w`, `battery_charge_power_w`, `battery_discharge_power_w` и `battery_soc_percent` Без этих полей потребление электроэнергии, стоимость и суточная стоимость дома не отображаются. Импорт/экспорт и зарядка/разрядка должны быть указаны в отдельных полях без подписи.

## Примеры

С `mosquitto_pub`:

```bash
mosquitto_pub -h <broker> -t energy/butler/telemetry \
  -m '{"fields":{"battery_soc_percent":81,"pv_total_power_w":2300,"grid_import_power_w":0,"grid_export_power_w":450,"battery_charge_power_w":1200,"battery_discharge_power_w":0},"timestamp":1791956345000}'
```

В функциональном узле Node-RED перед исходящим узлом MQTT (тема) `energy/butler/telemetry`):

```js
msg.payload = {
    fields: {
        battery_soc_percent: flow.get('soc'),
        pv_total_power_w: flow.get('pv'),
    },
    timestamp: Date.now(), // better: the time the values were read
};
return msg;
```

`tools/mqtt-check.mjs` В течение нескольких секунд прослушивает темы по умолчанию и сравнивает поля с приведенными выше определениями:

```bash
node tools/mqtt-check.mjs --host <broker> --user <user>
```
