Типичные вопросы и сообщения из логов альфа-тестирования.

### Журнал показывает`unauthorized`

Система MotionEye доступна, но вход в систему или подписание API-подписи не удается.

**Проверять:**

1. Откройте настройки экземпляра, повторно введите имя пользователя и **пароль** **MotionEye** , **сохраните изменения** и перезапустите экземпляр.
2. Начиная с обновления адаптера 0.2.1, пароль хранится в зашифрованном виде — старое значение в открытом виде может снова работать только после повторного сохранения.
3. Если у MotionEye **нет пароля** , оставьте поле пустым (без пробелов).
4. Имя пользователя точно такое же, как в MotionEye (часто)`admin` ).
5. **Порт API конфигурации MotionEye** — **8765** , а не порт веб-интерфейса, расположенного за обратным прокси-сервером без переадресации API.

**Успех:**`_info.connection` =`true` , нет`unauthorized` -Предупреждения в журнале.

#### Вход через веб-браузер работает, но адаптер по-прежнему отображается...`unauthorized`

Если вы можете войти через браузер, но адаптер...`GET /config/list → HTTP 403: unauthorized` Когда об этом сообщается, это почти никогда не происходит из-за «неправильного хоста», а скорее из-за **разных данных доступа** или **неправильного адреса API** :

1. **Порт тот же, что и у адаптера:** вход через веб-браузер должен осуществляться по следующему адресу:`http://<motionHost>:8765/` функция — не только при`:80` ,`:443` или другой URL.
2. **Тот же пользователь:** значение в поле **"Пользователь MotionEye"** должно точно совпадать со значением имени администратора в MotionEye (часто это может быть как прописная, так и строчная буква).`admin` ).
3. **Пароль в ioBroker:** Полностью очистите поле → **Сохранить** → Перезапустите экземпляр → Введите пароль **вручную** (не копируйте) → **Сохранить** → Перезапустите. Это помогает при повреждении шифрования или наличии невидимых пробелов.
4. **Наличие двух разных серверов:** ioBroker и MotionEye на отдельных виртуальных машинах/LXC (например, Proxmox) — это нормально. Тесты SSH и...`node` Они должны находиться на **хосте ioBroker** , а не в контейнере MotionEye.
5. **MotionEye 0.44 или более поздняя версия:** Начиная с MotionEye **0.44,** API использует **вход через сессию** вместо подписи URL-адреса. Для этого требуется адаптер версии **0.5.0** или более поздней — в версии **0.4.x** это остается...`unauthorized` Хотя вход через веб-браузер работает. См. раздел [MotionEye 0.44+](#motioneye-044-adapter-050) .

### MotionEye 0.44+ (Адаптер 0.5.0+)

Начиная с **версии MotionEye 0.44** , аутентификация по API изменилась: вместо`_username` /`_signature` Клиент идентифицирует себя по URL-адресу.**`POST /login`** и использует сессионный cookie ( [Примечания к выпуску](https://github.com/motioneye-project/motioneye/releases/tag/0.44.0) ).

| MotionEye  | адаптер              | Результат                                                                |
| ---------- | -------------------- | ------------------------------------------------------------------------ |
| **0.43.x** | 0.4.x или **0.5.0+** | работает (подпись URL)                                                   |
| **0.44+**  | 0.4.x                | `unauthorized` — даже если вход через веб-браузер работает на порту 8765 |
| **0.44+**  | **0.5.0+**           | Это работает (вход через сессию, автоматический резервный вариант).      |
| **0.43.x** | **0.5.0+**           | Оно по-прежнему работает (обратная совместимость).                       |

**Проверить версию:** веб-интерфейс MotionEye,`http://<host>:8765/version` или точка данных`motioneye.<Instanz>._info.motionEyeVersion` .

**Обновление:** Обновите адаптер до версии **0.5.0** или более поздней (npm или ioBroker Admin). Никаких изменений в настройках камер или MotionEye не требуется — хост, пользователь и пароль остаются прежними.

### Настройки устройства (`settings.*` )

Начиная с версии адаптера **0.6.0** , параметры камеры находятся в разделе`motioneye.<Instanz>.<kamera>.settings.*` (например.`framerate` ,`resolution` ,`rotation` ,`autoBrightness` ,`privacyMask` Значения считываются во время опроса состояния и могут быть записаны через точку данных.

**Маска конфиденциальности (`settings.privacyMask` ):**

1. **Области маски** рисуются один раз в веб-интерфейсе MotionEye (видеоустройство → маска конфиденциальности).
2. Лучше всего **включать/выключать эту функцию** только через точку данных ioBroker.`settings.privacyMask` — Адаптер запоминает области отрисовки (они навсегда сохраняются в объекте, остаются активными после обновлений/перезапусков адаптера, начиная с **версии 0.6.1** ) и отправляет их снова при включении.
3. Если отключить маску **непосредственно в MotionEye** , MotionEye немедленно отбросит эти области. После этого единственным решением будет перерисовать маску в MotionEye, подождать немного (пока не произойдёт опрос) или перезапустить экземпляр, чтобы адаптер повторно использовал линии.
4. **Настройки яркости/контраста/насыщенности/оттенка** доступны в MotionEye только для локальных USB/v4l2 камер, а не для сетевых камер (RTSP) — следовательно, данные в адаптере отсутствуют.

**Изменение нескольких настроек одновременно:** начиная с версии адаптера **0.7.0,** операции записи конфигурации для каждой камеры ставятся в очередь. Если у вас несколько камер,`settings.*` /`overlay.*` /`motiondetection.*` Если точки данных с одной и той же камеры задаются практически одновременно (например, с помощью скрипта или множественного выбора), никакие изменения не будут потеряны. В более старых версиях: задавайте точки данных по отдельности, одну за другой, и`lastAction` Подождите, пока не будет изменено следующее.

### Обнаружение движения (`motiondetection.*` )

Начиная с версии адаптера **1.0.0** , параметры для точной настройки обнаружения движения находятся в разделе`motioneye.<Instanz>.<kamera>.motiondetection.*` (`frameChangeThreshold` ,`autoThresholdTuning` ,`autoNoiseDetect` ,`noiseLevel` ,`eventGap` ,`minimumMotionFrames` ,`lightSwitchDetect` ,`despeckleFilter` ,`preCapture` ,`postCapture` ).

1. Вы по-прежнему можете управлять **включением/выключением обнаружения** через корневую точку данных.`mode` (`off` /`still` /`sharp` ) —`motiondetection.*` Она регулирует чувствительность и время только во время активного обнаружения.
2. **`frameChangeThreshold`** Это процент пикселей изображения, которые должны измениться, чтобы вызвать движение (0–20%, как ползунок в MotionEye).`0` Система обнаружения практически отключена.
3. **`autoThresholdTuning`** &#x438;**`autoNoiseDetect`** MotionEye автоматически регулирует пороговое значение и уровень шума. Если включено автоматическое обнаружение шума,`noiseLevel` Надпись остается читаемой, но начинает работать только после выключения двигателя.
4. **Сроки:**`eventGap` Это период без движения до окончания события (в секундах).`minimumMotionFrames` отфильтровывает кратковременные ложные срабатывания.`preCapture` /`postCapture` Это буферы кадров до/после движения (количество кадров зависит от частоты кадров камеры).
5. **Задержка синхронизации:** изменения в веб-интерфейсе MotionEye отображаются в ioBroker только после следующего опроса состояния.`statusPollIntervalSec` (Стандартные 300 с). Запись из ioBroker вступает в силу немедленно.

После обновления адаптера: **перезапустите** экземпляр, чтобы новые объекты оказались в нужном месте.`motiondetection.*` быть сотворённым.

### Текстовое наложение (`overlay.*` )

Начиная с версии адаптера **0.7.0** , текстовое наложение камеры располагается ниже.`motioneye.<Instanz>.<kamera>.overlay.*` (`enabled` ,`leftText` ,`rightText` ,`customLeftText` ,`customRightText` ,`textScale` ).

1. **`enabled`** Это главный переключатель для наложения. Если вы его выключите, MotionEye удалит отображаемый текст из видео.`leftText` /`rightText` Текст, введенный пользователем, сохраняется в адаптере и в конфигурации MotionEye и используется повторно при повторном включении устройства.
2. **`leftText`/`rightText`** принять одно из значений`camera-name` ,`timestamp` ,`custom-text` ,`disabled` (отображается в виде выпадающего списка в административной панели/представлении объекта ioBroker).
3. **Пользовательский текст:** Установить`leftText` (или`rightText` ) на`custom-text` и введите текст в`customLeftText` (или`customRightText` ) один — порядок не имеет значения. MotionEye сохраняет пользовательский текст навсегда только в том случае, если этот режим уже активен.`custom-text` Поэтому адаптер всегда отправляет оба значения вместе в одном запросе, чтобы текст не был потерян.
4. **`textScale`** управляет размером текста (`1` –`10` (соответствует ползунку в интерфейсе MotionEye).

**Предварительно заданное наложение текста через конфигурацию адаптера (вкладка «Наложение»):**

Начиная с версии адаптера **0.8.0** , на вкладке «Конфигурация **наложения»** отображается одна строка для каждой камеры (из вкладки «Камеры») с теми же полями, что и выше, плюс кнопка **«Применить настройки наложения сейчас»** . Это работает только в одном направлении — от конфигурации к точкам данных — таблица никогда не обновляется автоматически при изменении точек данных и, следовательно, не может непреднамеренно отменить изменения, внесенные вами в режиме реального времени.

- Если оставить поле пустым (или если в выпадающем списке установлено значение **"— без изменений —"** ), оно будет пропущено — существующее значение никогда не будет перезаписано.
- **Новая камера** (созданная на вкладке «Камеры», но еще не сохраненная/перезапущенная): заполненные поля становятся начальными значениями точек данных сразу после их первого создания при следующем перезапуске — никаких дальнейших действий не требуется.
- **камера, которая уже`overlay.*` -Точки данных** (обычный случай, если вы используете адаптер уже некоторое время): Простое заполнение таблицы само по себе **ничего** не меняет — вам нужно нажать кнопку **«Применить настройки наложения сейчас».** Эта кнопка немедленно применяет таблицу (точки данных + MotionEye) без необходимости сохранения или перезапуска экземпляра, и ее можно повторять столько раз, сколько необходимо — это полезно, например, для одновременной настройки нескольких камер.
- Поскольку таблица конфигурации никогда не считывает изменения точек данных, параметр, измененный в режиме реального времени (например, через VIS или скрипт), не будет перезаписан таблицей при следующем перезапуске адаптера — строка снова вступит в силу только тогда, когда вы сами нажмете кнопку «Применить параметры наложения сейчас».

### Где хранятся снимки экрана и видеозаписи?

**Вкратце:** **весь медиаархив** (все снимки, все видеоклипы) находится на **сервере MotionEye** , а не в ioBroker. Кроме того, адаптер может кэшировать **последний снимок** для каждой камеры в **файловом хранилище ioBroker** (вкладка **«Снимки»** , включена по умолчанию): файл JPEG в разделе **«Администрирование» → «Файлы»** , «Точки данных».`snapshots.*` В ioBroker **нет** полного архива — есть только`lastsnap.jpg` , который перезаписывается при каждом обновлении.

| Что                                | Где                                                                                                                                                                                             |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Архив снимков/видео**            | На **сервере MotionEye** , в папке с медиафайлами камеры (по умолчанию)`/var/lib/motioneye/Camera<N>/` или в отдельной папке в поле MotionEye / **"Папка с медиафайлами"** на вкладке "Камеры". |
| **Точка данных`snapshot`**         | Кнопка — запускает запись в MotionEye; MotionEye сохраняет файл на сервере MotionEye.                                                                                                           |
| **Точка данных`motion`**           | Логическое событие через веб-хук — без файла изображения.                                                                                                                                       |
| **`storage.*`-Точки данных**       | Отображается только **количество файлов и объем используемого места в хранилище** MotionEye, а не сами файлы.                                                                                   |
| **`snapshots.*`+ вкладка «Файлы»** | **Последний снимок в формате JPEG** в файловом хранилище ioBroker (кэш, при желании можно отключить) —`snapshots.filePath` для Telegram/скриптов,`snapshots.urlLocal` /`snapshots.html` для ВИС |

**Просмотреть или загрузить архив:** через веб-интерфейс MotionEye (изображения/видео с каждой камеры) или непосредственно на хост-компьютере MotionEye.

Подробная информация о кэше снимков (VIS, Telegram, Blockly): Ниже представлен [кэш снимков](#snapshot-cache-snapshots) .

### Кэш моментальных снимков (`snapshots.*` )

Если **в ioBroker включено кэширование последнего снимка** (`snapshotCacheEnabled` (по умолчанию) адаптер заряжает`lastsnap.jpg` из MotionEye (символическая ссылка на последний сохраненный снимок) и сохраняет их в разделе **Администрирование → Файлы →`motioneye.<Instanz>/snapshots/<kanal>/lastsnap.jpg`** .

| курок                        | Когда                                                                                                          |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Точка данных`snapshot`**   | После каждого успешного создания снимка (с настраиваемым временем ожидания, чтобы MotionEye мог записать файл) |
| **Веб-перехватчик движения** | Необязательный (`snapshotCacheOnMotion` (по умолчанию отключено) — ограничение скорости для каждой камеры      |
| **`snapshots.refresh`**      | Перезагрузка вручную без создания нового снимка.                                                               |

**Данные для автоматизации / визуализации:**

- `snapshots.urlLocal` — URL-адрес виджета VIS/HTML в локальной сети, например.`http://192.168.1.10:8082/motioneye.0/snapshots/garten/lastsnap.jpg`
- `snapshots.filePath` — абсолютный путь к файлу Telegram и скриптам, например.`/opt/iobroker/iobroker-data/files/motioneye.0/snapshots/garten/lastsnap.jpg` (будет определено автоматически для вашего хостинга)
- `snapshots.html` — Привязка HTML-виджета (как в`streamUrl` )
- `snapshots.lastUpdate` — Время последнего обновления кэша

**Телеграмма:**`snapshots.filePath` в качестве **единственного** отчета/`text` Используйте Blockly (только точки данных, не объединяйте их с текстом). Подпись текста под изображением должна быть создана только с помощью JavaScript.`caption: '…'` ) или два отдельных сообщения в Telegram. **Не** URL для скачивания из раздела Администрирование → Файлы (`:8081/files/...` — Он выдает HTML, а не JPEG.

Необходимое условие: **веб-адаптер** (`admin` / Порт 8082), чтобы JPEG-файл был отправлен по HTTP для`urlLocal` доставлено. Для URL-адреса локальной сети **используется хост ioBroker для веб-хуков** .`webhookHost` ) используется, когда задано.

Чтобы снять флажок для каждой камеры отдельно: вкладка **«Снимки»** → **«Исключить из кэша снимков»** .

### Уведомления Telegram (вкладка **«Уведомления»** )

Благодаря **веб-хукам движения** или после **обновления снимка состояния** адаптер может автоматически отправлять сообщения Telegram — без Blockly/скриптов.

1. Установите **адаптер Telegram** и авторизуйте пользователя.
2. Вкладка **«Уведомления»** → **Активировать уведомления Telegram** и ввести **получателей** (обычно это экземпляр).`0` (ID чата из Telegram-адаптера). Отключите столбец **«Активные»** , чтобы временно скрыть пользователя.
3. Для каждой камеры в таблице: **Текст перед изображением** , **Отправить изображение** / **Отметка времени** , **При движении** / **При создании снимка** (Выпадающее меню Да/Нет, по умолчанию Да), необязательный **получатель** (пусто = все активны; в противном случае имя или идентификатор чата).

Адаптер отправляет **до трех отдельных сообщений в Telegram** (как в вашем примере с Blockly): текст предисловия → изображение (`snapshots.filePath` ) → Посттекст. Заполнители в текстах:`{camera}` ,`{channel}` ,`{timestamp}` .

Если для параметра **«Веб-перехватчик движения** с **изображением» установлено значение «Да»,** адаптер сначала запускает создание снимка MotionEye, а затем загружает изображение JPEG (см. [уровень защиты](/#/docs/adapterref/iobroker.motioneye/alert-level.md#telegram-bild-bei-bewegung-notify--full) ). Столбец « **При создании снимка»** применяется только к настройкам, выполненным вручную.`snapshot` /`snapshots.refresh` .

**Тест:** Кнопка **отправки тестового сообщения** . **Минимальное расстояние между камерами** предотвращает засветку во время непрерывного движения.

Для реализации пользовательской логики продолжайте использовать Blockly/scripts с`snapshots.filePath` возможный.

### (Место для хранения)`storage.*` )

Начиная с версии адаптера **0.9.0,** отображается следующее:`motioneye.<Instanz>.<kamera>.storage.*` показывает, сколько снимков/видеоклипов в данный момент хранится и сколько места они занимают (`snapshotCount` ,`videoCount` ,`usedSpaceMb` ,`lastRefresh` а также спусковой крючок`refresh` ).

1. **Почему это не происходит автоматически:** Чтобы определить эти значения, MotionEye приходится рекурсивно искать в папке с медиафайлами камеры и проверять каждый сохраненный файл — для камер с большими медиаархивами (тысячи снимков/видеоклипов) это может занять некоторое время и заметно нагрузить сервер MotionEye. Поэтому это **не** является частью обычного опроса состояния.`statusPollIntervalSec` ).
2. **Обновление вручную (всегда доступно):** Установить`storage.refresh` на нужной камере`true` — Адаптер получает текущие значения и устанавливает их.`refresh` затем автоматически открывается снова`false` Это работает независимо от следующих настроек.
3. **Переключатель глобального автоматического обновления:** на вкладке «Конфигурация **хранилища»** , в **разделе «Статистика дискового пространства», включите автоматическое обновление** .`storagePollEnabled` Эта функция по умолчанию отключена. Активируйте её и установите **интервал в секундах** .`storagePollIntervalSec` например`3600` (ежечасно), чтобы камеры автоматически обновлялись с этим интервалом.
4. **Снимите флажок для каждой камеры:** на вкладке **«Хранилище»** для каждой камеры отображается одна строка с **флажком «Исключить из автоматического интервала»** (по умолчанию отключено). Включите эту опцию для менее важных камер с большими медиаархивами, чтобы они пропускались во время автоматического интервала — это их точка данных.`storage.refresh` Эта функция будет продолжать работать независимо в любое время. На вкладке также находится кнопка **«Обновить статистику хранилища сейчас»** , которая немедленно обновляет данные со всех камер в таблице (независимо от наличия галочки) — это полезно для однократного обновления всех камер без ожидания заданного интервала.
5. **`usedSpaceMb`Это приблизительная оценка:** MotionEye предоставляет только округленное значение размера для каждого файла (например,`"1.2 MB"` ), точные значения байтов отсутствуют. Поэтому сумма имеет небольшую погрешность округления — достаточно точную для выявления тенденций использования памяти, но не являющуюся точным показателем её объёма.
6. Если обновление не удается (например, из-за истечения времени ожидания MotionEye при работе с очень большой папкой), предыдущие значения сохраняются, а ошибка регистрируется в журнале.`status` написано — попробуйте позже, иначе **запрос к API будет отправлен по истечении времени ожидания** .`requestTimeoutMs` ) увеличение в настройках.

- Настройки сохранены (пароль должен быть сохранен в экземпляре).

**Процесс:**

3. Результат отображается в сообщении администратора; подробная информация (количество камер, версия MotionEye) находится в журнале адаптера.

| Результат      | Значение                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Успех          | Данные API и доступа корректны — после перезапуска экземпляра все должно заработать.`_info.connection` =`true` становиться |

### Тестирование API через SSH (хост ioBroker)

Выяснилось, принимает ли MotionEye данные доступа — независимо от хранилища паролей ioBroker.

**Важно:** выполняйте команду на **хосте ioBroker** (например, через SSH к виртуальной машине/LXC ioBroker), **а не** на хосте Proxmox или MotionEye LXC. Там она отсутствует.`node` часто (`node: command not found` ).

ioBroker включает узел — полный путь:

```bash
/opt/iobroker/node/bin/node -e "const {createMotionEyeApi}=require('/opt/iobroker/node_modules/iobroker.motioneye/lib/motionEyeApi');createMotionEyeApi({host:'192.168.1.10',motionEyePort:8765,username:'admin',password:'DEIN_PASSWORT',requestTimeoutMs:10000,listCacheMs:0}).getCameraList().then(c=>console.log('OK',c.length)).catch(e=>console.error('FAIL',e.message));"
```

`192.168.1.10` и`DEIN_PASSWORT` Настройте пароль (введите его вручную).

| выход                     | Значение                                                                                                                                                        |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OK 1` (или другое число) | Учетные данные API и для входа верны → Проблема заключается в **экземпляре ioBroker** (шифрование). Удалите экземпляр, создайте новый и введите пароль вручную. |
| `FAIL unauthorized`       | Вероятно, веб-вход **не** работает на порту **8765** с теми же учетными данными — проверьте адресную строку браузера при входе.                                 |

**Docker-ioBroker:** Выполнение команды **в контейнере ioBroker** (`docker exec -it <iobroker-container> bash` ), при необходимости скорректируйте пути.

### Журнал показывает`EHOSTUNREACH` или`ECONNREFUSED` (Docker / Unraid)

Контейнер ioBroker достигает цели`motionHost:8765` Проблема не на сетевом уровне — проблем с паролем **нет** .

**Проверять:**

1. Проведите тестирование из **контейнера ioBroker** , а не с компьютера:

   ```bash
   docker exec -it <iobroker-container> sh
   wget -O- http://<motionHost>:8765/ 2>&1 | head
   ```

2. **Объект motionHost** должен быть доступен из **контейнера ioBroker** :
   - То же самое пользовательское сетевое имя Docker → имя контейнера (например,`motioneye` )
   - В противном случае используйте IP-адрес Unraid/хоста, если маршрутизация осуществляется из контейнера.
   - `192.168.x.x`Доступность из контейнера в браузере на ПК не гарантируется.

3. Docker-шаблон MotionEye: Порт **8765** опубликован?

4. **webhookHost** отключен — MotionEye должен связаться с ioBroker через порт **8090** для работы с веб-хуками движения.

### Функция Motion работает в ioBroker, но не в MotionEye (или наоборот).

Оставьте **управление MotionEye через Config API** включенным. Адаптер записывает режим, веб-хуки и поток в MotionEye. Если отключено, ioBroker будет получать только веб-хуки без синхронизации Config.
