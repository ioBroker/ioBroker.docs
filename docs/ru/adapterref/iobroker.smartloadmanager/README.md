# ioBroker.smartloadmanager

## Примеры для версии 0.2.0

Необходимое условие: Node.js версии 22.19.0 или более поздней. Адаптер отправляет команды устройству с помощью `ack: false`; подтверждение (`ack: true` Принимает управление соответствующий адаптер устройства. Значение входного напряжения должно представлять собой мощность в точке подключения к сети в ваттах. Если значение входного напряжения отрицательное, `feedinNegativ` активировать. Базовая нагрузка дополнительно вычитается в качестве резерва; не следует повторно вводить потребление домохозяйства, уже включенное в значение подключения к сети, в качестве базовой нагрузки.

### Бинарное потребление и отопление

Пример: сокет с `performance: 1000`, `switchOnPoint: 1200`, `switchOffPoint: 0`, `switchOnDelay: 20`, `switchOffDelay: 10` Задержка включения начинается, когда после базовой нагрузки остается избыток в 1200 Вт. Задержка выключения начинается, когда мощность потребляется из сети или когда пороговое значение для выключения не достигнуто. `minimumOnMinutes: 10` и `minimumOffMinutes: 5` ограничение частых переключений; более высокое потребление электроэнергии от сети, чем у конкурентов. `forecastMaxGridImport` Минимальный срок действия контракта отменяется. `0` Минимальные временные ограничения можно явно отключить.

`datapoint` переключатели логические `numericDatapoint` Цифровое обозначение с 0/1. Для систем отопления. `ruletype: heating` Выберите и настройте параметры температуры, выпуска воздуха и частоты сердечных сокращений. `maxTemperature` Отсутствие сигнала отпускания или некорректный сигнал пульса препятствует включению нагревателя. Проверяется истинность значения заданной точки данных пульса; при этом не отслеживается её возраст. Если настроенный датчик температуры отсутствует или не предоставляет конечного числового значения, нагреватель не включится или автоматически выключится. Функция «Выключать только в момент выключения» намеренно подавляет обычное отключение при перегреве до конца временного интервала; защита нагревателя остаётся в силе.

### Контроль процента заряда батареи.

Устройство с максимальной потребляемой мощностью 2000 Вт, работающее в данный момент на 50% мощности, потребляет 1000 Вт. Если сетевой счетчик показывает дополнительно 400 Вт потребляемой мощности, выходная мощность регулируется до 70%. При потреблении 200 Вт из сети она снижается до 40%. Если потребление портативного источника питания ниже... `minPercentStart` Потребление установлено на 0%. Деактивированные потребители не учитываются в расчете. При расчете платы за электроэнергию предполагается, что потребитель включен в сетевой счетчик.

Для батареи `batterySetpoint`, `performance`, необязательный `batterySOC` и `batteryTargetSOC` Выберите. При наличии 800 Вт избыточной мощности и максимальной мощности зарядки 1500 Вт, предварительно устанавливается значение 800 Вт. После достижения целевого уровня заряда (SOC) мощность зарядки снижается до 0. В качестве параметра глобального режима работы батареи используются значения 0 (выкл.), 1 (целевой уровень достигнут) и 2 (зарядка); эти значения должны соответствовать адаптеру устройства.

`controlMode` В дереве объектов: 0 = выключено, 1 = включено вручную, 2 = автоматический режим. Включение вручную устанавливает процент потребления на 100% или емкость батареи на заданный уровень. Автоматический процент и контроллеры батареи не отменяют ручной режим. Батарея учитывает ранее запрошенную мощность зарядки и корректирует ее в соответствии с измеренным избытком электроэнергии в сети. `batteryDelaySeconds` и `delaySecondsProzent` Эти настройки также применяются к частым обновлениям показаний счетчика; 0 означает немедленную корректировку. Если заданное значение SOC/целевого SOC отсутствует, мощность зарядки устанавливается на 0. Временные интервалы дополнительно проверяются каждые 15 секунд. Деактивация устройства завершает выполнение ожидающих команд переключения; она не приводит к автоматическому выключению устройства. `controlMode: 0` использовать.

### Прогнозирование PV с помощью ioBroker.pvforecast

`enableForecast` активировать, `forecastJsonDatapoint` примерно `pvforecast.0.summary.JSONData` набор и с потребителем `useForecast` активировать. Также. `pvforecast.0.plants.<Anlagenname>.JSONData` Это возможно; только тогда будет рассматриваться данная система. Требуется глобальная активация и опция «Использовать прогноз» для соответствующего потребителя. Опция «Уведомления о решениях по прогнозу» не активирует управление прогнозом самостоятельно и генерирует сообщение только при фактическом принятии решения по прогнозу. В версии 0.2.0 импорт данных отображается только в журнале отладки. В версии 0.4.1 в журнале отладки отображаются только сообщения о конфигурации, импорте данных и активированных решениях. Идентичные сообщения о решениях группируются в пределах пяти минут. Для внешних сообщений дополнительно настройте менеджер уведомлений или службу обмена сообщениями. Пример ожидаемого формата (временные метки в миллисекундах Unix):

```js
const now = Date.now();
const forecast = [0, 15, 30, 45].map(minutes => ({
    t: now + minutes * 60000,
    y: 3.5,
}));
// JSON.stringify(forecast), mit forecastPowerUnit = "kW"
```

При базовой нагрузке в 500 Вт прогнозируемый избыток составляет 3000 Вт. `forecastSafetyPercent: 80` Доступен вариант мощностью 2400 Вт (с запасом). Прибор мощностью 2000 Вт можно включить, если временной интервал не превышает... `forecastMinMinutes: 30` длинный, максимум `forecastMaxStartMinutes: 30` в нескольких минутах езды и в `forecastMinCurrentPercent: 50` Уже существует как минимум 1000 Вт фактического избытка. Прогнозы не заменяют измеренный избыток.

`forecastBridgeMinutes: 5` ограничивает возможность преодоления коротких провалов; `forecastMaxGridImport: 100` Предотвращает образование моста при потреблении электроэнергии от сети более 100 Вт. Предыдущие данные отбрасываются. Для малых значений мощности в Вт устройство необходимо явно установить в режим... `W` Установите это значение, поскольку автоматическое определение интерпретирует значения до 100 как кВт. `forecast.*` а значения прогнозируемого статуса потребителя указывают на принятое решение.

Временные интервалы могут выходить за пределы полуночи, например, с 22:00 до 6:00. Время начала и окончания, совпадающее с сегодняшним днем, считается интервалом на весь день.

Область тестирования и внешние зависимости релиза: [Отчет о тестировании релиза](/#/docs/adapterref/iobroker.smartloadmanager/release-0.2.0-pruefung.md) .

## 🔧 Описание

Адаптер **Smartloadmanager** динамически управляет нагрузками на основе значений, поступающих от солнечных батарей. Цель состоит в том, чтобы потреблять избыточную электроэнергию локально, тем самым минимизируя или полностью исключая подачу электроэнергии в общественную сеть. Он поддерживает как включение/выключение нагрузок и устройств с процентным управлением, так и системы хранения энергии на основе аккумуляторов.

## 🚀 Особенности

- ✅ Мониторинг настраиваемой точки ввода данных
- ✅ Динамическая активация потребителей в случае избытка
- ✅ Динамическое отключение в случае дефицита или потребления электроэнергии из сети
- ✅ Поддерживает **двоичный код** , **проценты** , а также потребление энергии **для отопления** и **работы от батареи.**
- ✅ Регулировка в процентах с задержкой (плавное снижение), опционально настраиваемая для каждого потребителя.
- ✅ Динамическая зарядка для систем хранения энергии с целевым уровнем заряда батареи (SOC)
- ✅ Временной интервал для включения/выключения для каждого потребителя (включая «только во время выключения»)
- ✅ Автоматическое создание объектов с расширенной информацией о каждом потребителе
- ✅ Режим управления: Выкл. / Ручное включение / Автоматический для каждого потребителя отдельно
- ✅ Регулировка гистерезиса с помощью отдельных точек включения/выключения
- ✅ Задержка переключения, специфичная для конкретного потребителя (переопределение глобальной задержки)
- ✅ Логическая схема включения (в зависимости от мощности) и выключения (в обратном порядке)
- ✅ Глобальная задержка переключения батареи (`batteryDelaySeconds`)
- ✅ Выполнить проверку режима управления батареей (отладочный вывод в лог)
- ✅ **Отложенное включение и выключение с помощью таймера**
- ✅ **Отображение запущенных таймеров в журнале отладки** с указанием оставшегося времени.
- ✅ Дополнительные **уведомления** о включении/выключении, контроле процента заряда батареи и состоянии аккумулятора (Telegram / Gotify)
- ✅ Оптимизация для точек данных 0/1 для устройств с булевым или числовым управлением 0/1
- ✅ Подробная регистрация всех таймеров, избыточной мощности и операций переключения
- ✅ Уведомления по типам потребителей (двоичные данные, проценты заряда батареи, заряд батареи, нагрев), возможность активации по желанию.
- ✅ Регулировка нагревательного элемента с контролем температуры, включения и проверки частоты срабатывания.

## 🔋 Поддержка хранения энергии в аккумуляторе

- Потребители с `"ruletype": "battery"` Они регулируют заданный уровень зарядки в зависимости от текущего избытка заряда.
- Если `batterySOC` и `batteryTargetSOC` После установки значение системы будет отключено при достижении целевого значения.
- При желании, а `batteryControlModeDatapoint` будет установлено:
  - `0 = Aus`, `1 = Manuell`, `2 = Automatik`
- Управление **возможно только в пределах заданных временных окон** .
- Элемент управления обновляется с заданной задержкой при каждом обновлении FeedIn. `batteryDelaySeconds`) выполнено снова.
- Задержки для всех цепей (двоичные, процентные, заряд батареи) могут регулироваться для каждого потребителя отдельно или глобально.
- Подробная регистрация событий и дополнительные уведомления о переключении батарей.

## 🌡️ Поддержка отопления

- Потребители с "типом правила": "нагрев" предназначены для нагревательных элементов или аналогичных потребителей.
- Управление происходит только в том случае, если: - Текущая температура ниже maxTemperature - Необязательно: защищено minTemperature - Необязательно: enableDatapoint активен - Необязательно: heartbeatDatapoint действителен
- Если условия не будут соблюдены, работа схемы будет немедленно прервана, и таймер остановится.
- Поддерживает таймеры включения/выключения (onTimerRemaining / offTimerRemaining) с отображением оставшегося времени.
- Подробная регистрация данных и, при необходимости, уведомления для потребителей отопительного оборудования.

## 🧠 Налоговая логика

1. **Результаты измерений интерпретируются в зависимости от конфигурации** (положительное значение = потребление электроэнергии из сети или подача электроэнергии в сеть).
2. **Избыточная нагрузка > Базовая нагрузка + Порог включения** :\
   &#x20;→ Потребители включаются (в двоичном коде) по мере увеличения потребления электроэнергии.
3. **Недостаточная нагрузка < Базовая нагрузка - предел отключения** :\
   &#x20;→ Потребителей будут отключать в обратном порядке.
4. **Правила для потребителей, потребляющих определенный процент от выручки** :\
   &#x20;→ % = Избыток / Максимальная производительность\
   &#x20;→ Регулируется в зависимости от задержки (общей или для каждого потребителя)\
   &#x20;→ Возможна дополнительная настройка параметров для каждого потребителя.
5. **Правила для потребителей батарей** :\
   &#x20;→ Мощность зарядки = min(избыток, максимальная мощность), если целевой уровень заряда не достигнут.\
   &#x20;→ Задержка закончилась `batteryDelaySeconds` или на одного потребителя
6. **Проверка временного окна для всех потребителей**\
   &#x20;→ Активно только в том случае, если текущее время находится в пределах `switchOnTime` до `switchOffTime`
7. **Управление осуществляется только в режиме управления «Авто (2)»**\
   &#x20;→ Ручные вмешательства (режим 1 или 0) остаются без изменений.
8. **Отложенное переключение с помощью таймера**\
   &#x20;→ Таймер прерывается до активации следующего переключателя; оставшееся время может быть отображено в журнале.
9. **Дополнительные уведомления о включении/выключении, проценте заряда и состоянии батареи.**
10. **Оптимизация для 0/1 точек данных**\
    &#x20;→ Поддерживает автоматическое логическое или числовое управление 0/1.
11. **Подробная регистрация всех операций переключения, избыточной мощности и таймеров.**
12. **Управление для потребителей отопления:** → Переключение только в пределах минимального/максимального температурного диапазона и при наличии действительных состояний включения/пульса → Таймеры отменяются, как только условия перестают выполняться

## 💡 Пример: Wallbox

| параметр              | Ценить   |
| --------------------- | -------- |
| подача                | 1000 Вт  |
| базовая нагрузка      | 100 Вт   |
| Максимальная мощность | 11000 Вт |

**Расчет:**

- Избыток: 1000 - 100 = 900 Вт
- Процент: 900 / 11000 ≈ 8,2% → Настенный блок питания настроен на 8%

## 📋 Структура объекта

Для каждого потребителя создается отдельный канал со следующими состояниями:

- `.controlMode` → 0 = Выкл., 1 = Ручной режим, 2 = Автоматический режим
- `.switchOnTime` /`.switchOffTime`
- `.alwaysOffAtTime` → верно/неверно
- `.performance`, `.switchOnPoint`, `.switchOffPoint`
- `.batterySetpoint` (только для "батареи")
- `.temperatureDatapoint` (только для "обогрева")
- `.onTimerRemaining / .offTimerRemaining` → Оставшееся время таймера включения/выключения
- `.timer` → Внутренний таймер для цепей с задержкой
- `.timerEnd` → Отметка времени истечения таймера (для ведения журнала)

## управление прогнозированием фотоэлектрической энергии

SmartLoadManager может `pvforecast.<Instanz>.summary.JSONData` Для его использования необходимо активировать управление прогнозированием, выбрать точку данных в формате JSON и включить функцию для нужных потребителей.

Адаптер оценивает непрерывное окно прогноза, а не одно значение. Настраиваемый коэффициент безопасности снижает оптимистичные прогнозы. Для активации на основе прогноза часть необходимой мощности должна уже быть доступна в виде реального избытка. Кратковременные спады потребления электроэнергии могут быть компенсированы в течение ограниченного времени, но только до установленного максимального потребления из сети.

Минимальное время автономной работы и минимальное время простоя предотвращают частое переключение. Прогнозируемые решения никогда не отменяют временные окна, температурные ограничения, выпуски оборудования, мониторинг состояния или ограничения уровня заряда батареи.

Рекомендуемые начальные значения: коэффициент запаса прочности 80%, окно прогнозирования 30 минут, максимальное время опережения 30 минут, требуемый фактический избыток 50%, время переключения на резервный режим 5 минут, максимальное потребление электроэнергии из сети 100 Вт и минимальное время работы/ожидания 10/5 минут.
