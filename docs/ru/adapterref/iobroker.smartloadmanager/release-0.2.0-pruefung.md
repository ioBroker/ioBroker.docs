# План работ и тестирования для версии 0.2.0

Все обнаруженные локальные изменения будут приняты и проверены в соответствии со спецификациями. Существующая архитектура адаптера будет сохранена. Ошибки будут исправлены с помощью воспроизводимых регрессионных тестов; фактическое тестирование устройства невозможно из-за отсутствия испытательного оборудования.

1. Проверьте задачи GitHub #90, #93, #86 и связанные с ними запросы на обновление; определите текущие версии npm для контроллера, администрирования и инструментов тестирования.
2. Контроль ошибок в `main.js` Воспроизведите проблему, используя смоделированные состояния ioBroker: команды переключения, управление процентами, состояние батареи, режимы работы, защита от перегрева и таймер.
3. Исправьте ошибки и проведите регрессионные тесты; проверьте входные данные для прогнозирования и минимальное время выполнения.
4. Проверьте зависимости, матрицу тестирования Node.js, переводы и содержимое пакетов.
5. Добавить список изменений в файл README и пользовательскую документацию на немецком и английском языках с примерами.
6. Синхронно установите версии в файлах пакета на 0.2.0. Запустите модульные, пакетные, типовые, линт- и интеграционные тесты для текущего js-контроллера.
7. Проверяйте изменения, фиксируйте их и отправляйте после успешного прохождения проверки.

Проблема #84 касается отдельного стабильного репозитория ioBroker. Загрузка только адаптера не обновляет его версию. Это не ошибочно рассматривается как локально исправленная ошибка.

## Исходная ситуация

- Локальная версия Node.js: 22.19.0.
- Первоначальное тестирование: 6 модульных тестов (один из которых был временным), пройдено 40 тестов пакета.
- Сертификация типа и проверка ESLint пройдены.
- Во время тестирования использовались следующие версии npm: js-controller 7.2.5, Admin 8.3.3, adapter-core 3.4.3, testing 6.3.1.
- Нет реального тестового экземпляра ioBroker и нет доступных подключенных устройств.

## Исправлены ошибки и проведено тестирование.

- Предыдущий шаблон заменен на настоящие регрессионные тесты. Проверяются логические/числовые команды, режимы работы, управление в процентах, знак, состояние заряда батареи (SOC), обратная связь по мощности зарядки, защита от перегрева и прерывания таймера.
- Отложенная активация повторно проверяет текущий избыток и временной интервал. Деактивация завершает работу таймеров переключения и отображения.
- Одновременные события счетчика не приводят к необратимому изменению управляющих таймеров; задержки, связанные с батареей, не обходятся путем немедленного управления.
- Прогнозы не учитывают прошлые значения и имеют нулевое опережение.
- Периодическая проверка учитывает временные интервалы даже без новых значений счетчика.
- Все одиннадцать каталогов переводов содержат одни и те же ключи. Уведомления и метаданные о релизах доступны на всех поддерживаемых языках.
- Официальные текущие JSON-схемы: 61 проверка пакетов прошла успешно.
- 29 функциональных тестов успешно завершены на узлах 22.19.0, 24.22.1 и 26.12.1.
- Интеграционный тест для js-controller 7.2.5 успешно завершен: объекты-потребители созданы, команда переключения выглядит следующим образом: `ack: false` полученный.
- Этот интеграционный тест также проходит проверку в Node.js 26.12.1 (2 теста).
- Проверка типов, проверка содержимого пакетов ESLint и npm прошли успешно; модуль среды выполнения, переводы и документация включены, тестовые файлы исключены.
- Чистая установка с `npm ci` успешный.
- Проверка репозитория 5.23.2 в локальном режиме: ошибок нет. Оставшиеся проблемы касаются невыпущенной версии 0.2.0, отсутствующего тега релиза, старых журналов CI, которые больше недоступны, и открытых проблем на GitHub.

## Сознательные решения и внешняя зависимость

- TypeScript останется в версии 6.0.3: версия 7 противоречит требованиям официальной настройки ioBroker ESLint. Поэтому запрос на слияние #79 не будет реализован бездумно.
- `alwaysOffAtTime` Это сохраняет свое задокументированное значение: нормальное отключение происходит только по истечении заданного временного интервала. Проверка защиты от перегрева остается независимой от этого.
- `npm audit` После установки совместимых обновлений система выдает шесть транзитивных сообщений: три из них умеренного характера. `@iobroker/testing` →`@alcalzone/esbuild-register` →`esbuild` и три высоко над `@iobroker/adapter-core` →`@iobroker/js-controller-common-db` →`node-forge` В подсчет включены затронутые родительские пакеты. В текущем дереве зависимостей нет совместимого обновления. Адаптер не запускает сервер разработки esbuild и не обрабатывает подписи RSA самостоятельно. Никаких заявлений о безопасности не делается, и принудительное понижение версии инструментов, необходимых для проверки репозитория, не выполняется.
- Проблема #84 требует внесения отдельных изменений в стабильный репозиторий ioBroker после успешного релиза и не будет решена одной лишь операцией Git push.
- Автоматизированные испытания не заменяют ввод в эксплуатацию с использованием реального оборудования.
