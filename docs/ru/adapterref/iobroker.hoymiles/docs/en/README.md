# ioBroker.hoymiles — Микроинверторы HMS и гибридные инверторы HAT от Hoymiles

## Поддерживаемые инверторы

Этот адаптер предназначен для **микроинверторов Hoymiles HMS со встроенным модулем DTU (DTUBI) Wi-Fi (или Wi-Fi + Bluetooth)** .

**Локальное соединение (TCP)** = прямое TCP/Protobuf-соединение на порту 10081 (модели WiFi). **Локальное соединение (BLE)** = локальное соединение Bluetooth через [Bluetooth-прокси ESPHome](https://esphome.io/projects/?type=bluetooth) (серия WB). **Облачное соединение** = API S-Miles Cloud — автоматическое обнаружение, данные в реальном времени (быстрый пакетный канал \~1,5–3 с), агрегированные данные об энергопотреблении, профиль сети, включение/выключение инвертора + перезагрузка, перезагрузка DTU.

Для остальных команд (ограничение мощности, блокировка, очистка предупреждений и т. д.) требуется локальное TCP-соединение.

### Гибридные инверторы с батареей (серия HAT) — облачные, только для чтения, экспериментальные.

В вашем аккаунте S-Miles отображается информация **о гибридном инверторе** Hoymiles — эталонная система: **HAT-6.0HV-EUG1** с батареей **HB-(10-23)S-G2** , трехфазным сетевым счетчиком и DTS-WIFI-G1 — **через облако** : значения трехфазного переменного тока, выходная мощность резервного источника питания (EPS), входная мощность фотоэлектрических панелей, подробная информация о батарее (состояние заряда и работоспособность, экстремальные значения для ячеек и модулей), а также потоки энергии и энергетический баланс электростанции за сегодняшний день, этот месяц, этот год и весь срок службы — импорт и экспорт из сети, прямое использование фотоэлектрической энергии, потребление, заряд и разряд батареи и коэффициент самообеспечения, а также данные из вкладки «Производство и потребление» в приложении S-Miles — и собственные данные о доходах и расходах из облака. Под инвертором также отображаются сегодняшние кривые мощности переменного тока, мощности батареи и состояния заряда, список тревожных сигналов из облака и, по запросу, настройки батареи и сухих контактов (реле). См. раздел «Гибридный инвертор» для получения информации о штатах. **Измерительные точки** электростанции — сетевой счетчик, нагрузки, счетчик фотоэлектрической системы на инверторе стороннего производителя, генератор — также считываются и отображаются под станцией; см. раздел «Измерительные точки станции». Эти данные работают для любой электростанции, для которой облачные сервисы предоставляют информацию, а не только для гибридных инверторов.

- **Чтение, а не управление.** Отображаются рабочий режим и настройки батареи. `<dtuSerial>.battery.*`), но это нельзя изменить — адаптер не имеет состояния, которое могло бы повлиять на работу системы хранения. Команда чтения профиля сети, разработанная для микроинверторов, не отправляется гибридному инвертору.
- **Три существующие команды работают так, как их отправляет портал S-Miles.** В разделе обслуживания устройств портала предлагаются _команды включения_ , _выключения_ и _перезагрузки_ для инвертора HAT, а также _перезагрузка_ для его DTU — это команды для адаптера. `inverter.active`, `inverter.reboot` и `dtu.reboot` Для накопителей энергии они используют собственный тип устройства инвертора и вариант DTU для накопителя, как это делает портал. Они были проверены на соответствие коду портала, **а не выполнены на реальном оборудовании** — отключение инвертора накопителя также отключает его резервный выход, поэтому используйте их с осторожностью.
- **Требуется учетная запись установщика** (та, которая может войти на global.hoymiles.com). Конечная точка для доступа к API S-Miles Home неизвестна.
- **Частота обновления:** быстрый канал реального времени работает и для накопителей энергии, в том числе и в облачной среде: фотоэлектрические системы, сеть, нагрузка и аккумуляторные батареи. `station-<id>.grid.*`) и состояние заряда батареи (`<dtuSerial>.battery.soc` Данные поступают примерно каждые 10 секунд — измеренные по эталонной системе, то есть с какой частотой устройство действительно выдает данные; более частый опрос не приносит ничего нового. В отличие от микроинверторов, для накопителя энергии канал не имеет режима для каждого устройства, поэтому все остальное (фазы, EPS, входные данные от солнечных батарей, сведения о батарее, показания счетчиков) загружается в облако устройством примерно каждые 5 минут.
- **Какие значения быстро меняются, а какие нет.** В реальном времени (примерно каждые 10 секунд) отображаются ровно пять значений: `station-<id>.grid.power` (PV), `grid.gridPower`, `grid.loadPower`, `grid.batteryPower` и `<dtuSerial>.battery.soc`. `grid.gridPower` _Это_ показания сетевого счетчика в режиме реального времени. Все остальное — включая показания по каждой фазе. `gridMeter.*`, `load.*` и `pvMeter.*` Данные — актуальны только на момент последней загрузки устройства в облако (примерно каждые 5 минут); облако не обеспечивает более быстрой загрузки ни для них, ни для портала.
- **Знаки.** `grid.gridPower` импорт/экспорт + и `grid.batteryPower` +разрядка/−зарядка, в обоих случаях из графа потока энергии облака. Значения для каждого устройства и каждого счетчика передаются по мере их поступления из облака — обратите внимание, что сетевой _счетчик_ сообщает об импорте как об **отрицательной** активной мощности. `gridMeter.power` прочитано −284 Вт, в то время как `grid.gridPower` показало +278 Вт).
- Создано на основе единой системы, доступ к которой осуществляется через облачный аккаунт её владельца (благодаря BastiBerlin) — пожалуйста, сообщите, что вы видите на своей системе.

> Данный адаптер **НЕ** совместим со следующими устройствами: HMS-1600/1800/2000-4T без "DW", сериями HM, MI, внешними модулями DTU или трехфазными моделями HMT.

> **В прошивке DTU версий V01.01.01 и более поздних шифруется локальное соединение.** Адаптер замечает это в первом ответе DTU и самостоятельно переключается на AES-128-GCM — никаких настроек не требуется. Такой DTU также взаимодействует с облаком по протоколу TLS (порт 10083), и облачный ретранслятор следует его примеру: он всегда подключается к серверу и порту, для которых настроен сам DTU. `config.serverDomain` /`config.serverPort`), с TLS на порту 10083 и обычным TCP на порту 10081. Более старые версии прошивки (до V01.00.07) продолжают работать точно так же, как и раньше.

#### Типы учетных записей — S-Miles: установщик / конечный пользователь / домашний

Адаптер принимает учетные записи из всех трех официальных приложений Hoymiles:

- **Установщик S-Miles** (`com.hm.hemaiInstall1`)
- **Пользователь S-Miles** (`com.hm.hemaiClient1`)
- **S-Miles Home** (`com.hm.balcony`)

Вход в систему осуществляется в рамках единого потока v3, за которым следует проверка профиля. `region_c → pre-insp → login → probe`):

- **Предварительная проверка и вход в систему** определяют вариант аутентификации. Hoymiles объединил все учетные записи на платформе Argon2id. `v=3 + salt`) в 2026 году, так что `v` больше не является сигналом профиля — сегодня учетные записи установщика, конечного пользователя и домашней учетной записи используют один и тот же запрос Argon2id (параметры из приложения S-Miles Home для Android): `t=3, m=32 MiB, p=1, hashLen=32, V13` Наследие `md5hex(password).sha256base64(password)` Этот вызов сохраняется в качестве запасного варианта для любого региона, который все еще принимает решения. `v=2`.
- **зонд** (`/pvm/.../select_by_page` Затем определяется, к какой платформе API для работы с данными разрешен доступ для учетной записи:
  - Проверка пройдена → профиль **установщика** — учетная запись работает на `global.hoymiles.com` и достигает полной `/pvm/...` веб-API, включая `latitude` /`longitude` /`address` /`local_time` /`status` /`warn_data` и строки версий прошивки.
  - Запрос отклонен (сервер сообщает: _«может использоваться только для входа в приложение S-Miles Home»_ ) → **домашний** профиль — ограничен сервером `/pvmc/.../*_c` Эта поверхность не содержит указанных выше полей, но отображает несколько дополнительных (энергия рефлюкса/самопотребления, цена на электроэнергию). Адаптер **не** создает состояния для отсутствующих полей — они появляются только тогда, когда базовый ответ фактически содержит это значение. `latitude` /`longitude` /`address` средства, возвращаемые на домашние счета, возмещаются через дополнительный фонд. `pvm-ext/station-ak/find` Конечная точка, которую использует само приложение S-Miles Home, обеспечивает работу опроса погоды.

> **Примечание:** `dataeu.hoymiles.com:10081` (простая, более старая прошивка) и `dataeu.hoymiles.com:10083` (TLS, прошивка V01.01.01 и более поздние версии) — это европейские точки облачного ретрансляции, на которые DTU передают данные; они **не** являются серверами авторизации пользователей. Адаптер автоматически обрабатывает облачную ретрансляцию (см. _Облачная ретрансляция_ ).

#### Тестовый вход в облако

В случае сомнений нажмите кнопку **«Проверить вход в облако»** рядом с полем для пароля. Она запускает четыре этапа один раз с использованием ваших текущих учетных данных. `region_c`, `pre-insp`, `login`, `probe`) и отчеты `v` а также наличие соли по результатам предварительной проверки, был ли создан токен при входе в систему и какой профиль был назначен зондом (`installer` /`home` Результат записывается в лог, поэтому вы можете вставить его в сообщение об ошибке на форуме. Тест не сохраняет токен и не изменяет состояние адаптера.

### BLE-шлюз (ESPHome)

Некоторые инверторы — **серии WB** (например, HMS-800-2WB) — доступны только через **Bluetooth** , а не через обычную сеть. Чтобы использовать их без облачного хранилища, добавьте в свою сеть небольшой и недорогой Bluetooth-мост (например **, ESPHome Bluetooth Proxy** ). После этого адаптер будет взаимодействовать с вашим инвертором через него.

**1. Настройте Bluetooth-мост.** Прошейте поддерживаемый ESP32 готовой прошивкой — воспользуйтесь ссылкой **«Прошить Bluetooth-прокси»** в настройках или <https://esphome.io/projects/?type=bluetooth> . Подключите его на расстоянии нескольких метров от инвертора. Ничего настраивать не нужно.

**2. Добавьте свой инвертор.** В настройках адаптера откройте вкладку **BLE** и включите **параметр «Включить шлюз BLE»** , затем сохраните. Когда инвертор включен, нажмите **«Добавить обнаруженные инверторы»** — ваш инвертор появится в таблице с уже заполненными серийным номером и адресом. Введите его **PIN-код** (тот, который вы установили на инверторе), поставьте галочку **«Активный»** и сохраните. Готово — адаптер подключается.

**Полезно знать.**

- Вы не выбираете мост. Если у вас их несколько, адаптер автоматически использует тот, у которого наилучший сигнал.
- Если **функция Add discovered inverters** ничего не обнаруживает, значит, ни один инвертор не находится в зоне действия Bluetooth моста.
- Неверный PIN-код приводит к выключению устройства; причина отображается в состоянии. `info.bleLastError`. Исправьте PIN-код и сохраните, чтобы попробовать снова.
- Когда инвертор отключается на ночь, связь Bluetooth обрывается, и данные помечаются как устаревшие. `info.connected` =`false` Адаптер автоматически переподключается утром. Если Bluetooth не восстанавливается, до тех пор, пока это не произойдет, данные поступают из облака — при условии, что подключение к облаку включено.

### Подключение счетчика электроэнергии (Shelly / ecotracker)

Инвертор, подключенный по Bluetooth (серия WB), может использовать общий **счетчик электроэнергии** . Это позволяет видеть не только то, что вы производите, но и то, что поступает в сеть или выводится из нее, — и по запросу инвертор регулирует свою мощность таким образом, чтобы **в сеть ничего не поступало** (нулевой экспорт).

**Требование:** счетчик должен находиться в той же сети и заявлять о себе там. Инвертор ищет его самостоятельно; все, что он найдет, отобразится в списке выбранных устройств.

**Инструкция:** в _Диспетчере конфигурации_ щелкните значок счетчика на вашем инверторе. Инвертор сам начнет поиск счетчиков в сети — выберите один из списка и выберите режим работы:

| Режим               | Эффект                                                                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Выключенный**     | Ничего не отправляется; существующее соединение остается без изменений.                                                                                                     |
| **Только счетчик**  | Инвертор считывает показания счетчика. Значения отображаются в подсчетчике. `<serial>.meter.*` Ничего не регулируется.                                                       |
| **Нулевой экспорт** | Кроме того, инвертор рассматривает счетчик как свой собственный сетевой счетчик и ограничивает собственную выходную мощность, как только избыток может быть передан в сеть. |

Регулировка осуществляется **внутри инвертора** — адаптер только настраивает его и следит за процессом. Для его работы не обязательно, чтобы он работал.

> **Важно:** счётчик должен заявить о себе в сети **через mDNS** . Если инвертор не может его найти, он принимает настройку, но никогда не получает никаких данных. Оригинальный Shelly делает это по умолчанию; в случае с эмулятором (например, uni-meter) служба mDNS должна быть запущена.

**Полезно знать.**

- `meter.gridPower` Это обменная сеть: положительное значение = импорт, отрицательное = экспорт. Рядом с ней находятся `pvPower`, `loadPower`, `storagePower` и `plugPower` — Разделение вычисляется инвертором.
- За каждый этап вы получаете `meter.l1Voltage` /`l1Current` /`l1Power` (аналогично для L2 и L3) плюс `meter.frequency`. Мощность обозначается знаком: отрицательное значение означает, что в данный момент экспортируется энергия из этой фазы.
- `meter.connected` Показывает, поступает ли в данный момент сигнал от счетчика. Если показания... `false` Соединение со счетчиком перешло в спящий режим — просто подтвердите режим еще раз в диалоговом окне, что перезапустит его.
- Это под силу только моделям серии WB. У моделей WiFi (T) нет ни входного разъема для счетчика, ни регулятора для него, поэтому значок там не отображается.

## Диспетчер конфигурации

Адаптер интегрируется с ioBroker **Config Manager** , поэтому каждый инвертор и облачная станция отображаются в виде карточки на вкладке _Config Manager_ в административном интерфейсе — с текущим состоянием, элементами управления и диалогом настроек, без необходимости создания собственного представления VIS.

**Что показано**

- Каждый **DTU/инвертор** (`<dtuSerial>`) и каждая **облачная станция** (`station-<id>`) адаптер создал.
- **Индикатор активного соединения** (зеленый/красный), а для локально подключенных DTU — **качество сигнала Wi-Fi в процентах** (0-100 %). В названии карты используется название станции (предприятия), к которой принадлежит инвертор — имя, которое вы указали в приложении S-Miles — плюс серийный номер DTU (например, `Zuhause · 4143A01CEDE4`), что позволяет каждому инвертору быть уникальным; без станции используется название модели или серийный номер.
- **На карте отображаются текущие значения:** мощность (Вт), количество выработанной энергии за сегодня (кВт·ч), мощность каждой фотоэлектрической батареи, фактически подключенной к инвертору (одна строка на батарею), и температура инвертора — все данные обновляются автоматически. Станции показывают суммарную мощность, **использование фотоэлектрической энергии в процентах** , суточную, годовую и общую выработку энергии, а также суточный и общий доход в валюте предприятия (строки дохода отображаются только при настройке цены на электроэнергию в облаке).
- **Значок** устройства по типу — плоский микроинвертор, вертикальный трехфазный инвертор (линия HMT) или станция. Те же значки используются для объектов устройств в дереве объектов.
- **Индикатор обновления прошивки,** когда облако сообщает об этом (из `dtu.fwUpdateAvailable`).
- Кнопка **«Подробнее»** открывает панель с подробной информацией только для чтения, сгруппированную по следующим категориям: **Инвертор** (модель, серийный номер, версия аппаратного/программного обеспечения), **DTU/прошивка** (серийный номер, версии прошивки, версия Wi-Fi, индикатор обновления), **Сеть** (используемый адрес, качество сигнала, SSID, IP- и MAC-адреса, DNS, DHCP) и **Облачный сервер** (домен, порт). Разделы «Сеть» и «Сервер» отображаются только для локально подключенных устройств, поскольку эти значения передаются только по локальному каналу связи.

> **Почему не все поля, относящиеся к сети, отображаются там:** конфигурационное сообщение DTU охватывает **все семейство DTU Hoymiles** . Помимо полей Wi-Fi, оно содержит набор полей для **проводной сети** (IP, MAC, маска подсети, шлюз, DNS для кабельного соединения) и поля для **сотовой связи** (APN, GPRS) и радиосвязи в диапазоне Sub-1GHz. Инвертор HMS работает только с Wi-Fi, поэтому его поля для проводной связи остаются в исходном виде. `0.0.0.0` и `00:00:00:00:00:00` навсегда. Адаптер скрывает любое поле, для которого устройство не сообщает реального значения — в противном случае на панели отображался бы несуществующий адрес. Числовой `0` Остается видимым: для такого флага, как DHCP, это ответ, а не отсутствие. Станции отображают емкость, состояние и адрес.

**Элементы управления и настройки — разделены по принципу сохранения.**

Карта отображает состояние записи, поэтому щелчок мышью направляет команду по обычному пути (предпочтительно локальное TCP-соединение, резервный вариант — облако). Два диалоговых окна разделены строго по тому, **что сохраняет устройство** :

> ⚠️ Названия состояний здесь вводят в заблуждение; прошивка принимает другое решение: `inverter.powerLimit` Звучит как параметр, изменяемый во время выполнения, но записывается в сохраняемую структуру и требует двух секторов флэш-памяти по 4 КБ на каждое изменение, в то время как `config.limitPowerMyPower` Он называется "постоянным", но находится только в оперативной памяти и исчезает после перезагрузки. Оба параметра проверены прошивкой. `_fwanalysis/ADAPTER_FINDINGS.md` §1, §2, §15).

**Элементы управления** (значок ползунка) — ничто из этого не сохранится после перезапуска DTU:

- **Управление (переключатели):** включение/выключение инвертора, блокировка инвертора.
- **В режиме реального времени:** ограничение мощности (поле конфигурации DTU) в виде ползунка, интервал отправки данных в облако. Оба параметра содержат примечание о том, что DTU забывает их при перезапуске.

Перед каждым ползунком указывается его текущее значение и единица измерения, поскольку ползунок отображает эти данные только во время перетаскивания.

**Настройки** (значок шестеренки, только для локальных устройств) — все данные, сохраняемые DTU:

- Ограничение мощности, ограничение коэффициента мощности, ограничение реактивной мощности.
- В каждом поле указано, что частые изменения приводят к износу памяти устройства. Диалоговое окно записывает **только те поля, которые вы действительно изменили** — нетронутые поля не перезаписываются.

**Кнопки на плате** (с подтверждением): перезагрузка инвертора, перезагрузка DTU и — **только при наличии подтверждения** — подтверждение предупреждений и подтверждение неисправности заземления. Кнопка предупреждения появляется во время `alarms.hasActive` Кнопка заземления установлена; кнопка заземления активна только в том случае, если в списке аварийных сигналов есть запись с кодом аварийного сигнала заземления (182). Ни одна из кнопок не отображается до тех пор, пока не будет прочитан список аварийных сигналов.

> На устройствах **серии WB** кнопка заземления никогда не появляется: прошивка принимает команду, но, как доказано, не выполняет её (пустой ответ, "нет ошибки"). Кнопка, сообщающая об успехе, но ничего не делающая, вводит в заблуждение. На устройствах серии T команда выполняется.

> **Примечание к версии Admin:** карта намеренно использует только те функции отображения, которые поддерживаются более старыми версиями Admin. В версии Admin 7.8.x графический интерфейс диспетчера устройств входит в состав пакета. `dm-utils 3.0.x` форма, которая еще не знает пользовательских символов состояния (`indicators`) и удаляет их без следа — поэтому качество Wi-Fi и использование PV отображаются там, где это предусмотрено в каждой версии, а значки подтверждения поставляются в том размере, в котором они должны отображаться (административная панель их не масштабирует).

Для инверторов, **работающих только через облако** (без локального подключения, например, HMS-800-2WB), отображаются только действия, которые может выполнить облако — включение/выключение инвертора, перезагрузка инвертора, перезагрузка DTU — поскольку остальные команды выполняются только локально. Станции отображают только состояние и подробную информацию (без элементов управления).

**Действия с экземпляром** (над списком устройств): **«Сканировать сеть»** — выполняет поиск DTU в локальной сети и сообщает о найденных устройствах, а **«Проверить вход в облако»** — запускает диагностику входа в систему. (Для обновления списка используется встроенная кнопка обновления Config Manager.)

> **Примечание:** Устройства, обнаруженные позже в облаке (примерно через 60 секунд после начала), отображаются после нажатия кнопки **«Обновить»** или повторного открытия вкладки; текущий статус уже перечисленных устройств обновляется автоматически.

### Автоматическое переподключение

Инвертор (DTU) доступен только тогда, когда вырабатывает электроэнергию (светит солнце). Адаптер автоматически переподключается с экспоненциальным уменьшением времени задержки (1 с, 2 с, 4 с, ... до 60 с максимум). При успешном подключении время задержки сбрасывается до 1 с.

Устройства BLE (HMS-800-2WB) используют тот же принцип, но с более медленными шагами, поскольку каждая попытка представляет собой полный цикл GATT через Bluetooth-прокси: 5 с, 10 с, 20 с, ... максимум до 5 минут, сбрасывается после успешного сопряжения. Неудачные попытки в течение ночи регистрируются в журнале. `debug`; в качестве предупреждения отображается только первый сбой в серии.

### Облачные каналы связи (сервер → адаптер)

> **Ретрансляция касается только TCP-устройств** (HMS-\*-xT). В этом случае DTU обслуживает один сокет на порту 10081: пока адаптер подключен локально, устройство не может самостоятельно связаться с облаком, поэтому адаптер загружает данные от его имени. У BLE-устройства (HMS-800-2WB) нет локального TCP-порта; адаптер никогда не отключает облачное соединение и продолжает загружать данные самостоятельно. Поэтому адаптер **не** запускает ретрансляцию для BLE-устройств — он бы создал второй поток данных под тем же серийным номером.
>
> Ретранслятор подключается к серверу и порту из собственной конфигурации DTU. На порту 10083 (по умолчанию в прошивке V01.01.01 и более поздних версиях) он использует протокол TLS и проверяет сервер по собственному центру сертификации Hoymiles, точно так же, как это делает DTU; на порту 10081 он использует обычный протокол HM, как и в более старых версиях прошивки. Внутренние кадры в обоих случаях одинаковы — DTU идентифицирует себя для облака только по своему серийному номеру, а не по сертификату.

Пока работает ретранслятор, облачный сервер подтверждает загрузку данных и периодически отправляет команды. Адаптер сопоставляет **каждое** такое сообщение с именем своей прошивки:

| Добрый                                  | Примеры                                                                    | Поведение                                                                                                                                         |
| --------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Благодарность за загруженные материалы. | `InfoDataRes`, `HBRes`, `RealRes`, `HistoryRes`                            | Считываются время сервера и смещение часового пояса; если сервер отклоняет загрузку (`error_code ≠ 0`) в журнале регистрируется предупреждение   |
| Команды                                 | `CommandRes` (действие)                                                    | Передаётся на устройство по локальному соединению; сервер получает подтверждение и информацию о состоянии.                                        |
| Запросы данных                          | Профиль сетки (действие 41), версия (действие 4)                           | ответ получен на основе данных, считанных локально.                                                                                               |
| Не выполнено                            | Загрузка OTA (действие 2/15), запись конфигурации (действия 52–54 и 56/57) | **Преднамеренно отклонено** и зарегистрировано — обновление прошивки или перенаправление сервера никогда не выполняются без участия пользователя. |

Сообщения, поведение которых еще не установлено, регистрируются с указанием их имени и длины, а не удаляются. Таким образом, нереализованная нисходящая связь видна в журнале и больше неотличима от полного отсутствия нисходящей связи.

### Ночной режим

Когда локальное соединение обрывается (обычно на закате), адаптер переходит в **ночной режим** :

- Облачный ретранслятор приостанавливает работу (отправляет последнюю загрузку данных, затем отключается).
- Облачный API ограничивается только обновлениями погоды и проверками прошивки (данные в реальном времени отсутствуют, поскольку ничего не меняется).
- После восстановления локального соединения (восхода солнца) адаптер выходит из ночного режима и возобновляет нормальную работу.

### Государственное качество

Адаптер использует атрибут качества состояния ioBroker (`q`) для указания достоверности и источника данных:

| Качество                 | Ценить      | Значение                                         | Когда                                                                                                                                                                                                                                                                      |
| ------------------------ | ----------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Хороший                  | `0x00` (0)  | Свежие данные, полученные из местных источников. | Нормальный режим работы — данные принимаются напрямую от DTU по протоколу TCP.                                                                                                                                                                                             |
| Заменять                 | `0x40` (64) | резервные данные из облачных источников          | Данные инвертора получаются из облачного API Hoymiles, а не по локальному TCP-соединению (для устройств, работающих только в облаке).                                                                                                                                      |
| Устройство не подключено | `0x42` (66) | Устаревшие данные, устройство отключено.         | Соединение DTU потеряно — значения представляют собой последние известные показания перед разрывом соединения. Также установлено на облачной станции. `grid.*` когда последняя загрузка данных в облако станции произошла более \~20 минут назад (DTU не загружает данные). |

**Затронутые штаты:** `grid.*`, `pv*.*`, `inverter.temperature`, `inverter.active`, `inverter.warnCount`, `inverter.warnMessage`, `inverter.activePowerLimit`, `meter.*` — плюс измерения облачной станции `station-<id>.grid.*` (отмечено) `0x42` (пока станция не работает/не работает).

Информация гласит (`info.*`), состояния конфигурации (`config.*`), а статические облачные данные на уровне станции (название, адрес, координаты, предупреждающие флаги) **не** затрагиваются изменениями качества.

**Автоматический сброс:** При восстановлении локального соединения DTU следующий успешный ответ на запрос данных автоматически вернет все затронутые состояния к исходному уровню качества. `0x00` (хорошо). Аналогично, когда облачная станция возобновляет загрузку, её `grid.*` качество возвращается `0x00` и адаптер немедленно выполняет полное обновление (подробности, устройства, микропрограмма, предупреждения), после чего возобновляет обычный режим опроса.

Атрибут качества можно использовать в скриптах и визуализациях для различения свежих и устаревших данных, например, путем затемнения или затемнения значений. `q > 0`.

## Несколько инверторов

Этот адаптер поддерживает одновременное подключение нескольких инверторов:

- **Локальный режим:** Добавьте несколько IP-адресов DTU в таблицу устройств.
- **Облачное хранилище:** Все инверторы и станции в вашей учетной записи обнаруживаются автоматически.

Каждый DTU создает узел устройства, используя свой серийный номер в качестве идентификатора:

```
hoymiles.0.4143A01CEDE4.grid.power
hoymiles.0.4143A01CEDE4.inverter.*
hoymiles.0.4143A01CEDE4.dtu.*
hoymiles.0.4143A01CEDE4.pv0.*
```

Облачные станции создают агрегированные узлы устройств:

```
hoymiles.0.station-12345.grid.power      ← Sum of all inverters
hoymiles.0.station-12345.grid.totalEnergy
hoymiles.0.station-12345.info.stationName
```

1. **Локальная информация:** получена из собственных данных инвертора.

3. **Резервный вариант:** по названию модели (`…-2T`, `…-4WB`, …), или по количеству строк, которые фактически отображаются в данных в реальном времени.

### `<dtuSerial>.history.*` — Суточная кривая мощности (по данным DTU, местные данные)

Инвертор поддерживает собственную кривую мощности на день в режиме мгновенного отображения. Адаптер получает её в режиме медленного опроса. `0xa315`) — **без использования облака** , как по протоколу TCP, так и по протоколу BLE.

Устройство разбивает данные за день на страницы, содержащие не более 200 выборок, и сообщает их количество. Адаптер собирает данные со всех страниц и публикует кривую только после того, как все данные за день собраны целиком — данные только с нулевой страницы заканчиваются в середине утра.

Измерения проводились на приборе HMS-800W-2T: 903 выборки с интервалом в одну минуту в течение 15 часов, пиковое значение составило 602 Вт в 14:06. Прибор HMS-800-2WB выдает ту же кривую с шагом в 300 секунд, начиная с полуночи.

> **О самом устройстве:** в прошивке это не указано — поле копируется из флэш-памяти без каких-либо преобразований. Поэтому коэффициент 0,1 Вт **измеряется, а не считывается из кода** : интегрирование кривой за день дает **4495 Вт·ч** против **4500 Вт·ч,** которые сообщает само устройство, разница составляет 0,12 %. Коэффициент 1 или 0,01 будет означать отклонение в десять раз.

| Состояние             | Тип   | Единица | Записываемый | Описание                                                            |
| --------------------- | ----- | ------- | ------------ | ------------------------------------------------------------------- |
| `history.powerJson`   | нить  | В       | нет          | Суточная кривая мощности в виде массива JSON, одно значение на шаг. |
| `history.startTime`   | число | РС      | нет          | Временная метка **первого** отсчета кривой                          |
| `history.stepTime`    | число | с       | нет          | Секунды между двумя образцами (2T: 60, 2WB: 300)                    |
| `history.dailyEnergy` | число | Что     | нет          | Суточная энергия, по данным устройства.                             |
| `history.totalEnergy` | число | кВтч    | нет          | Общая энергия, по данным, полученным от устройства.                 |

Временная метка образца: `history.startTime + index * history.stepTime * 1000`.

### `<dtuSerial>.config.*` — Конфигурация DTU (для каждого DTU, локально)

> ⚠️ **ВНИМАНИЕ — при каждом ограничении мощности происходит запись программ во внутреннюю флэш-память устройства.**
>
> Это влияет ** `inverter.powerLimit`, `inverter.powerFactorLimit` и `inverter.reactivePowerLimit` ** — Все три действия проходят по одному и тому же пути к успеху (действия 8, 47 и 48). Это **не** влияет `config.limitPowerMyPower`: это поле конфигурации доступно только для оперативной памяти. В более ранних версиях этой документации эти два параметра были перепутаны местами. `inverter.powerLimit` была описана как команда выполнения, работающая только в оперативной памяти, и `config.limitPowerMyPower` как устройство записи во флэш-память. Оба варианта были неверны. В конце успешной команды микропрограмма вызывает сериализатор конфигурации, который **стирает и перезаписывает два сектора флэш-памяти размером 4 КБ** (HMS-800W-2T: `0x4080d642` → стереть + записать для области 3 и области 0xe; HMS-800-2WB: `sys_cfg_write` пробеги `nv_erase` +`nv_write` дважды). Ресурс флэш-памяти ограничен — десятки тысяч циклов, — поэтому цикл нулевого экспорта в секунду приводит к её износу и может **навсегда вывести устройство из строя** .
>
> **Адаптер предотвращает это:** в настройках (вкладка _«Локальные»_ ) предлагается **мертвая зона** (по умолчанию 1 %) и **минимальный интервал** (по умолчанию 60 с). Изменение ниже мертвой зоны или изменение, произошедшее слишком рано после последней записи, не отправляется; состояние все равно подтверждается, и в журнале указывается причина. Оба значения можно отрегулировать или отключить, установив значение 0 — любой, кто намеренно хочет ускорить процесс, может это сделать и при этом смирится с износом.
>
> Для нулевого экспорта, `inverter.powerLimit` Остается правильным состоянием: эффект проявляется немедленно. Однако это **не** путь без вспышек — именно поэтому существуют мертвая зона и минимальный интервал. `config.limitPowerMyPower` Прошивка не требуется, но устройство не сохраняется после перезагрузки на HMS-800W-2T и не отправляет команды инвертору.

> ⚠️ **При записи конфигурации адаптер всегда сначала считывает данные.**
>
> DTU принимает **все** поля конфигурационного сообщения, включая те, которые протокол даже не передает, поскольку они содержат свои значения по умолчанию. Поэтому отправка только того поля, которое вы хотите изменить, очищает все остальные. Проверено прошивкой для HMS-800W-2T: `server_domain_name`, `serverport`, `limit_power_mypower`, `server_send_time`, `lock_password` и `lock_time` Они перезаписываются без защиты. На устройстве 2WB именно это привело к потере адреса сервера, порта и ограничения мощности в ходе реального тестирования.
>
> Таким образом, адаптер **никогда не записывает частичный набор данных** : он берет последнюю считанную с устройства конфигурацию, изменяет в ней только запрошенное поле и отправляет все обратно. Если в текущей сессии конфигурация не была считана, запись **отклоняется** , и причина регистрируется в журнале — лучше не записывать, чем записывать неполной информацией.
>
> Учетные данные Wi-Fi остаются без изменений: устройство использует их только при наличии дополнительного поля, которое адаптер намеренно оставляет пустым.

## Протокол

### Локальный (TCP/Protobuf)

- **Транспорт:** TCP-порт 10081
- **Кодировка:** Протокол Buffers (protobuf)
- **Кадр:** 10-байтовый заголовок (`HM` magic + command ID + CRC16 + length) + protobuf payload, with sequence numbers (0-60000)
- **Аутентификация:** отсутствует (только в локальной сети)
- **Шифрование:** отсутствует до версии прошивки DTU V01.00.x. Начиная с версии V01.01.01, DTU устанавливает бит 25. `dfs` В своем ответе на InfoData он ожидает использования **AES-128-GCM** для каждого второго локального кадра — ключ и nonce вычисляются из 16-байтового массива. `enc_rand` При передаче данных в открытом виде 16-байтовый аутентификационный тег следует за зашифрованным текстом за пределами длины кадра. Адаптер обнаруживает это в первом ответе и автоматически переключается. В открытом виде остаются только запрос и ответ InfoData.
- **Пульс:** сигнал пульса protobuf, отправленный через 20 секунд без трафика, поддерживает постоянное соединение открытым.
- **Повторное подключение:** через 5 минут без передачи данных и при каждом разрыве соединения, с экспоненциальной задержкой от 1 секунды до 5 минут.

### Облачные технологии (API S-Miles)

- **Базовый URL:** `https://neapi.hoymiles.com` Станции в дата-центре ЕС обслуживаются из `https://euapi.hoymiles.com` и адаптер выбирает хост для каждой станции.
- **Аутентификация:** подтверждение входа; Argon2id, если сервер предоставляет соль (S-Miles Home), в противном случае — устаревший хеш MD5/SHA-256, отправляемый веб-порталом.
- **Данные:** данные о работе станции в режиме реального времени и подробная информация, дерево устройств, индикаторы работы каждого устройства в режиме реального времени (гибридный инвертор, батарея, счетчики), канал быстрого импульсного отклика в режиме реального времени, суточные кривые, статистика энергопотребления (день, месяц, год, весь срок службы), доходы и расходы, списки аварийных сигналов и задачи устройств (считывание настроек, включение/выключение питания, перезагрузка).
- **Облачная ретрансляция:** адаптер пересылает данные DTU на сервер и порт, настроенные в DTU — обычный TCP на порту 10081 для более старых версий прошивки, TLS на порту 10083 (проверено с помощью собственного корневого центра сертификации Hoymiles) для прошивки V01.01.01 и более поздних версий.
- **Пароль:** хранится в зашифрованном виде в конфигурации ioBroker.

## Поиск неисправностей

### Адаптер не может подключиться

- Убедитесь, что IP-адрес DTU указан правильно (проверьте таблицу DHCP вашего маршрутизатора).
- Убедитесь, что к порту 10081 не подключено ни одно другое приложение (одновременно допускается только одно подключение).
- Если у вас запущено устройство dtuGateway ESP32, сначала остановите его.

### После подключения данные отсутствуют.

- Проверьте журнал адаптера на наличие ошибок декодирования protobuf.
- `Decryption failed: ... wrong final block length` или `bad decrypt` На устройстве DTU с прошивкой версии V01.01.01 это означает, что используется версия адаптера без поддержки зашифрованного протокола. Установите текущую версию и перезапустите экземпляр; после этого в журнале появится следующее сообщение: `DTU requires encrypted communication (firmware V01.01.01+)`

### Не удалось войти в облако.

- Проверьте свою электронную почту и пароль S-Miles.
- Убедитесь, что у вас есть возможность войти в систему по адресу <https://global.hoymiles.com/website/login>
- При возникновении постоянной ошибки аутентификации (неверные учетные данные, заблокированная учетная запись) адаптер останавливает цикл повторных попыток, чтобы избежать дальнейшей блокировки учетной записи. Сообщение об ошибке записывается в файл. `info.cloudLastError` и уведомление об ошибке ioBroker (область действия) `hoymiles`, категория `cloudAuth` Возникает ошибка. Исправьте учетные данные и сохраните конфигурацию, чтобы очистить состояние и возобновить попытки.

### Сообщение об ошибке

Чтобы превратить проблему "не работает" в проблему, которую можно исправить, адаптер выдает сфокусированный, **анонимизированный** диагностический журнал:

1. В административной панели ioBroker откройте настройки экземпляра адаптера и установите **уровень логирования** на `debug`.
2. Перезапустите экземпляр и дайте ему поработать несколько минут (один или два цикла опроса облака).
3. Экспортируйте журнал и выберите строки, помеченные тегами. `[diag]`.

Он `[diag]` В строках передаются необработанные ответы облачного API (процесс входа в систему, список/подробности станций, дерево устройств, данные в реальном времени, прошивка), а также результаты принятия решений адаптером. Серийные номера DTU/инвертора и адрес электронной почты учетной записи заменяются стабильными хеш-токенами, а координаты GPS/адрес/название станции удаляются — таким образом, `[diag]` Эти строки можно безопасно вставлять в сообщения об ошибках на публичных форумах. (Другие, не относящиеся к...) `[diag]` В отладочных строках всё ещё может содержаться реальный последовательный адрес, поэтому отправьте... `[diag]` (конкретно, строк.)
