# ioBroker.mcp

Сервер MCP для ioBroker

## Описание

Этот адаптер предоставляет доступ к ioBroker в качестве сервера [MCP (Model Context Protocol)](https://modelcontextprotocol.io) , поэтому клиенты, поддерживающие MCP (например, Claude Desktop), могут считывать данные и управлять вашей установкой с помощью четко определенного набора инструментов.

## Функции

- Сервер MCP использует протокол **Streamable HTTP** (`/mcp` конечная точка)
- Настраиваемый веб-сервер HTTP/HTTPS
- Настраиваемый порт и адрес привязки
- Дополнительная аутентификация
- Дополнительная поддержка SSL/TLS
- Диагностика сети (ICMP ping / TCP probe) для устранения неполадок в работе сетевых адаптеров.
- Поиск **в репозитории** адаптеров для рекомендации устанавливаемых адаптеров.

## Режимы работы

Адаптер может работать в двух режимах:

1. **Автономный режим** (по умолчанию) — запускает собственный веб-сервер на настроенном порту. Конечная точка MCP — \[укажите адрес]. `http(s)://<host>:<port>/mcp`.
2. **Веб-расширение** — оно работает внутри существующего[`web`](https://github.com/ioBroker/ioBroker.web) Экземпляр адаптера используется совместно с веб-сервером (порт, аутентификация, SSL). Выберите целевой веб-экземпляр в конфигурации администратора («Расширить веб-адаптер»). Затем конечная точка MCP будет обслуживаться через веб-адаптер, например. `http(s)://<host>:8082/mcp`.

   При выборе веб-экземпляра настройки автономного сервера (порт, адрес привязки, аутентификация, SSL) скрываются, поскольку они наследуются от выбранного экземпляра. `web` пример.

## Конфигурация

Адаптер можно настроить через административный интерфейс ioBroker с помощью JSONConfig:

### Конфигурация сервера

- **Расширить веб-адаптер** : выберите `web` Экземпляр для запуска в качестве расширения. Оставьте поле пустым для автономного запуска.
- **Порт** : Порт, на котором веб-сервер будет прослушивать запросы (по умолчанию: 8093) – только для автономного режима.
- **Адрес привязки** : IP-адрес, к которому будет привязан сервер (0.0.0.0 для всех интерфейсов) – только для автономного режима.
- **URL-адрес сервера MCP** : адрес для ввода в клиент MCP, с кнопкой для его копирования. Автономная версия создается на основе SSL, адреса привязки и порта этого экземпляра; в качестве веб-расширения — на основе SSL, адреса привязки и порта выбранного экземпляра. `web` экземпляр (при этом для всех экземпляров используется один URL на экземпляр). При использовании OAuth и **публичного URL** используется публичный URL, в противном случае — хост из адреса страницы администратора.

### Аутентификация

- **Включить аутентификацию** : Включить аутентификацию пользователей ioBroker для веб-сервера.
- **Пользователь по умолчанию** : Пользователь ioBroker, с правами которого выполняются запросы MCP при отключенной аутентификации (по умолчанию: `admin` При включенной аутентификации каждая сессия выполняется с правами пользователя, который вошел в систему, поэтому это поле скрывается. Все операции чтения и записи объектов/состояния, выполняемые инструментами, осуществляются от имени этого пользователя, поэтому применяются списки контроля доступа пользователя. Простое имя, например, `operator` автоматически расширяется до `system.user.operator` В качестве веб-расширения обеспечивается аутентификация и указание пользователя по умолчанию. `web` экземпляр применить.

### OAuth

Клиенты MCP, такие как Claude Desktop, подключаются через браузер, а не с помощью токена, созданного вручную. Клиент самостоятельно обнаруживает сервер, пользователь входит в систему и подтверждает авторизацию, и клиент никогда не видит пароль от ioBroker.

- **Включить OAuth (вход через браузер)** : В автономном режиме это требует _включения аутентификации_ . В качестве **веб-расширения** выбранный вариант `web` Экземпляр предоставляет доступ для авторизации, поэтому OAuth **также должен быть включен там** («Разрешить сторонним клиентам») — в противном случае клиенты MCP будут получать только перенаправление на страницу входа, которую они не смогут использовать.
- **Публичный URL** : внешний адрес этого сервера без указания пути, например. `https://iobroker.example.com` Требуется при использовании обратного прокси-сервера: URL-адреса, публикуемые для обнаружения OAuth, должны быть теми, к которым клиент фактически имеет доступ. Как веб-расширение, оно должно соответствовать общедоступному URL-адресу, настроенному в `web` пример.
- **Разрешить самостоятельную регистрацию клиентов** : позволить клиентам MCP регистрироваться самостоятельно (по умолчанию: **включено** ). При отключении этой опции каждому клиенту сначала придется регистрироваться вручную. В режиме веб-расширения это и есть `web` Это настройка экземпляра, поэтому данная опция здесь скрыта.

**HTTPS необходим** для всего, кроме `localhost` — поток данных проходит через браузер пользователя, и клиенты MCP отказываются от обычного доступа. `http://` для удалённых хостов.

Токены доступа привязаны к этой конечной точке, поэтому токен, выданный для другой службы на том же сервере, будет отклонен. Клиенты могут повторно удалить свои токены через `POST /oauth/revoke`.

### Разрешения

Все параметры, изменяющие систему, по умолчанию **отключены** ; включайте только те, которые действительно необходимы клиенту MCP.

**Состояния и объекты**

- **Разрешить установку состояний** : Разрешить клиентам MCP записывать значения состояний и подтверждать системные уведомления (`set_state`, `set_states` и `clear_notifications` инструменты). По умолчанию: **включено** . Какие состояния могут быть записаны, определяется списками контроля доступа (ACL) пользователя, от имени которого выполняется запрос (вошедший в систему пользователь или пользователь по умолчанию). `set_states` Сначала проверяется наличие прав на запись у всех состояний, и если хотя бы одно из них недоступно для записи, ничего не записывается.
- **Пометить состояние установки как деструктивное** (`setStateDestructive`): Объявить `set_state` и `set_states` с `destructiveHint: true` Таким образом, клиенты MCP могут выдавать предупреждения перед записью состояния. По умолчанию: **включено** . Если выключено, оба инструмента объявляются как выполняющие неразрушающую запись. `readOnlyHint` пребывание `false`); Вопрос о том, будет ли клиент по-прежнему запрашивать подтверждение, зависит от самого клиента.
- **Разрешить изменение объектов/файлов** (`allowObjectChange` Разрешить клиентам MCP создавать/изменять/удалять объекты, псевдонимы и файлы (`set_object`, `delete_object`, `create_state`, `create_scene`, `create_alias`, `write_file`, `delete_file`, `rename_file` и `mkdir` инструменты). По умолчанию: **выключено** .

**Система**

- **Разрешить управление экземплярами** (`allowInstanceControl`): Запуск, остановка и перезапуск экземпляров адаптера, а также изменение уровня их логирования (`start_instance`, `stop_instance`, `restart_instance`, `set_log_level` По умолчанию: **выключено** .
- **Разрешить управление адаптерами** (`allowAdapterManagement`): Добавление и удаление экземпляров, а также обновление адаптеров из репозитория (`add_instance`, `delete_instance`, `upgrade_adapter` По умолчанию: **выключено** .
- **Разрешить изменение скриптов** (`allowScriptChange`): Создавать, изменять, запускать/останавливать и удалять скрипты JavaScript-адаптера и запускать код один раз (`set_script`, `enable_script`, `delete_script`, `run_script` Чтение сценариев (`list_scripts`, `get_script`) всегда возможно. Скрипты запускаются с полным доступом к ioBroker. По умолчанию: **выключено** .
- **Разрешить отправку сообщений адаптерам** (`sendToAllowlist`): Адаптеры (`telegram`) или экземпляров (`backitup.0`) `send_to` Инструмент может отправлять сообщения, разделяемые запятыми; `*` Разрешает всё. По умолчанию: пусто, тогда ничего не разрешается. `send_to` инструмент.

**Безопасность**

- **Перед совершением опасных действий запросите подтверждение** . `confirmDangerous` Клиенты MCP, поддерживающие [запрос подтверждения,](https://modelcontextprotocol.io/specification/2025-06-18/client/elicitation) запрашивают у пользователя информацию перед удалением объекта или экземпляра, остановкой экземпляра, обновлением или установкой адаптера, сохранением или запуском скрипта, а также отправкой сообщения. Клиенты без запроса подтверждения полагаются на... `destructiveHint` инструментов и их собственного подтверждения. По умолчанию: **включено** .
- **Разрешить ссылки для скачивания/выгрузки** (`transferLinks` Инструменты могут выдавать кратковременные ссылки для данных, слишком больших для сообщения MCP (см. [раздел «Большие результаты и файлы»](#large-results-and-files) ). По умолчанию: **включено** .

**Разработчики**

- **Разрешить установку пакетов (только для разработчиков)** `allowPackageInstall` Предложите `install_package` инструмент, который устанавливает пакет адаптера на хост ioBroker — из npm, GitHub, по URL-адресу или через `.tgz` файл - точно так же, как _установка с пользовательского URL-адреса/файла_ в ioBroker.admin (`iobroker url ...` По умолчанию: **выключено** . Эта опция актуальна только для разработчиков адаптеров, например, чтобы позволить агенту ИИ создать адаптер и упаковать его. `npm pack` и установить `.tgz` На тестовой системе. Установленный пакет запускается с полными правами на хосте, поэтому никогда не включайте его на рабочей системе или для клиентов, которым вы не полностью доверяете.

**Права пользователя ioBroker.** Приведенные выше параметры определяют, какие инструменты доступны; то, что может сделать вызов, определяется правами пользователя ioBroker, от имени которого выполняется сессия MCP (вошедший в систему пользователь или пользователь по умолчанию без аутентификации), как в ioBroker.admin:

- Списки контроля доступа (ACL) для объектов, состояний и файлов, предназначенные для их чтения и записи.
- «Другие» права групп пользователя: **выполнение** команд на хосте (`install_package`, `add_instance`, `delete_instance`, `upgrade_adapter`) и **sendto** для отправки сообщений адаптерам (`send_to`, `run_script` Без них вызов будет отклонен до начала выполнения каких-либо действий. Администраторы обладают всеми правами.

Сессии даже не предоставляются инструменты, необходимые для управления группами пользователей, которым не хватает прав: без права записи для состояний нет `set_state` /`set_states`, без права записи для объектов нет `set_object`, `create_state`, `start_instance`..., без права удаления для штатов нет `delete_orphan_states`, без права записи для файлов нет `write_file`, без **выполнения** нет `install_package`, без **отправки** в нет `send_to` Права доступа считываются при начале сессии; в любом случае, каждый вызов проверяется автоматически.

`check_permissions` отображает эти права и списки контроля доступа (ACL) для данных объектов.

Каждый вызов инструмента для изменения параметров **регистрируется** на информационном уровне с указанием пользователя, инструмента и его аргументов. `MCP system.user.admin: set_state(id="hue.0.light.state", value=true)`), и каждый неудачный вызов сопровождается предупреждением с теми же подробностями. Длинные значения сокращаются; содержимое файла, код скрипта и `send_to` Полезная нагрузка заменяется на величину её размера.

### Настройка SSL/TLS

- **Включить HTTPS** : Включите HTTPS/SSL для безопасных соединений.
- **Открытый сертификат** : путь к файлу открытого сертификата.
- **Закрытый ключ** : путь к файлу закрытого ключа.
- **Цепочка сертификатов** : путь к файлу цепочки сертификатов (необязательно)

## Соединение ChatGPT и Клода

В каталогах коннекторов Claude и ChatGPT пока нет официального приложения ioBroker. До тех пор добавляйте ioBroker как **пользовательский коннектор** . Доступ к вашей установке можно получить двумя способами:

|                | A: через ioBroker Remote (рекомендуется)                                                   | B: напрямую на ваш сервер                                        |
| -------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| URL сервера    | `https://mcp.iobroker.in/mcp`                                                              | `https://<your public address>/mcp`                              |
| Авторизоваться | адрес электронной почты и пароль вашей учетной записи [ioBroker.pro](https://iobroker.pro) | пользователь ioBroker вашей установки                            |
| Требования     | Учетная запись и поддержка ioBroker.pro или удаленная активация подписки.                  | публичный HTTPS-адрес (переадресация портов или обратный прокси) |
| Открыть порты  | никто                                                                                      | Ваш MCP или веб-порт должен быть доступен из интернета.          |

### A: через ioBroker Remote

1. Настройте этот адаптер (автономный или как веб-расширение). Оставьте **параметры «Включить аутентификацию»** и **«Включить OAuth»** **выключенными** : вход в систему происходит на iobroker.pro, а ioBroker.iot подключается к этому экземпляру локально без учетных данных. В качестве веб-расширения выбранный адаптер будет работать корректно. `web` Экземпляр также не должен использовать аутентификацию. Порт не обязательно должен быть доступен из интернета.
2. В настройках **ioBroker.iot** (войдя в систему с помощью своей учетной записи ioBroker.pro) включите параметр **«Разрешить удаленный доступ»** и выберите этот экземпляр в качестве **экземпляра MCP** . Сохраните изменения.
3. Добавьте коннектор в Claude или ChatGPT (см. ниже) с URL-адресом. `https://mcp.iobroker.in/mcp`.
4. Откроется страница входа «Подключиться к ioBroker»: введите адрес электронной почты и пароль вашей учетной записи ioBroker.pro и нажмите **«Войти и разрешить»** . Разрешайте подключение только в том случае, если вы только что настроили его самостоятельно.

Доступ предоставляется при наличии подтвержденного адреса электронной почты и действующей лицензии ioBroker.pro. Новые учетные записи могут использовать сервис в течение 7 дней после регистрации без лицензии.

Полезно знать:

- ioBroker.iot должен быть подключен к облаку, иначе клиент получит ошибку "ioBroker находится в автономном режиме".
- Обновления в режиме реального времени (подписка на ресурсы) недоступны через удаленный доступ. Все инструменты работают.
- После перезапуска экземпляра MCP клиент самостоятельно запускает новую сессию.
- Удаление коннектора в клиенте прекращает доступ. Уже выданный токен доступа остается действительным до одного часа. Чтобы немедленно остановить доступ, очистите **экземпляр MCP** в файле ioBroker.iot.

### B: напрямую на ваш сервер

1. **Включите аутентификацию** и **OAuth** . Если вы используете веб-расширение, включите OAuth («Разрешить сторонним клиентам») в настройках. `web` в том числе и в этом случае.
2. Обеспечьте доступность сервера через **HTTPS** из интернета и введите этот адрес в качестве **публичного URL** .
3. Используйте URL-адрес `https://<your public address>/mcp` в клиенте войдите в систему под учетной записью пользователя ioBroker.

### Клод (claude.ai, Claude Desktop)

На всех тарифных планах доступны пользовательские коннекторы, бесплатный план ограничен одним пользовательским коннектором.

1. Откройте **«Настройка» → «Коннекторы»** , нажмите **+** и выберите **«Добавить пользовательский коннектор»** .
2. Введите имя (например) `ioBroker`) и URL-адрес сервера. **Расширенные настройки** (идентификатор и секрет клиента OAuth) остаются пустыми, Клод регистрируется.
3. Нажмите **«Добавить»** . Если вход в систему не запускается автоматически, нажмите **«Подключить»** рядом с коннектором.
4. В чате нажмите **+** (в левом нижнем углу) → **Коннекторы** и включите **ioBroker** .

Для команд и предприятий: сначала владелец добавляет коннектор в разделе **«Настройки организации» → «Коннекторы»** → **«Добавить»** → **«Пользовательский»** → **«Веб»** . Затем участники открывают **раздел «Настройка» → «Коннекторы»** и нажимают **«Подключить»** .

**Кодекс Клода:**

```bash
claude mcp add --transport http iobroker https://mcp.iobroker.in/mcp
```

Затем запустите `/mcp` В коде Клода выберите `iobroker` и войдите в систему через браузер.

### ChatGPT

Для пользовательских подключений MCP требуется **режим разработчика** , который доступен для учетных записей Plus, Pro, Business, Enterprise и Education в веб-версии ChatGPT. В рабочих пространствах Business и Enterprise администратор должен сначала разрешить его использование.

1. Откройте **«Настройки» → «Безопасность», войдите в систему** и включите **режим разработчика** .
2. Откройте [плагины ChatGPT](https://chatgpt.com/plugins) и нажмите **+** .
3. Введите имя (например) `ioBroker`) и описание (например, "Считывает данные и управляет моим умным домом ioBroker"). В разделе **"Подключение"** выберите **"Публичная конечная точка"** и введите URL-адрес сервера. В качестве метода аутентификации выберите **OAuth** .
4. Создайте соединение и войдите в систему. Затем ChatGPT отобразит список инструментов ioBroker.
5. В чате откройте **+** → **Режим разработчика** и выберите **ioBroker** . Полезно явно указать имя ioBroker в запросе, например: "Используйте ioBroker для выключения света на кухне".

ChatGPT помечает подключения в режиме разработчика как сопряженные с повышенным риском и запрашивает подтверждение перед выполнением операций записи.

Названия пунктов меню взяты со страниц справки [Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) и [ChatGPT](https://developers.openai.com/api/docs/guides/developer-mode) (сентябрь 2026 г.) и могут измениться.

### Рекомендации

- Пусть ИИ войдет в систему под учетной записью пользователя ioBroker, обладающего только необходимыми правами, или, без аутентификации, установите такого пользователя в качестве **пользователя по умолчанию** . Каждый инструмент работает со своими правами доступа.
- Отключите параметр **«Разрешить изменение объектов/файлов»,** если он вам не нужен.
- Включайте **системные** параметры (экземпляры, адаптеры, скрипты, сообщения) только для тех клиентов, которым вы доверяете, и только для тех, которые вам необходимы. С **параметром «Разрешить сообщения адаптерам»** указывайте имена адаптеров явно, вместо того чтобы... `*`.
- Отключите параметр **«Разрешить установку пакетов»** . Он предназначен только для разработчиков адаптеров на тестовых системах.
- Оставьте **настройки Mark в режиме «деструктивные»** и **«Запрашивать подтверждение перед опасными действиями»** включенными, чтобы клиенты запрашивали подтверждение, прежде чем что-либо менять или переключать.

## Конечная точка MCP

Сервер MCP обслуживается по адресу: `POST/GET/DELETE /mcp` с использованием транспортного протокола HTTP Streamable с сохранением состояния для каждой сессии (отслеживаемого через `Mcp-Session-Id` (заголовок). Направьте свой MCP-клиент по следующему адресу:

- автономный: `http(s)://<host>:<port>/mcp`
- веб-расширение: `http(s)://<host>:<webPort>/mcp`

### Большие результаты и файлы

Клиенты MCP отклоняют результаты работы инструментов размером более 1 МиБ, а модель не может передавать мегабайты данных в формате base64 в качестве аргумента инструмента. Таким образом:

- **Все результаты остаются ниже лимита.** Списки (`get_states`, `search_objects`, `list_files`, `list_scripts`, `history_query`) вернуть столько записей, сколько поместится, и добавить `truncated`, `total`, `nextOffset` и а `hint`; позвоните еще раз с `offset` установить на `nextOffset` для следующей части. `get_logs` Сохраняет самые новые строки. Любой другой результат, слишком большой по размеру, заменяется ссылкой для скачивания или сообщением об ошибке с просьбой сузить запрос.
- **Крупные скрипты и объекты по частям** : `get_script` с `offset` (начать с `0`) возвращает исходный код по частям, максимум по частям. `length` байты (по умолчанию 512 КиБ, меньше, если экранирование превысит лимит) с `size`, `truncated` и `nextOffset`, нравиться `read_file`. `get_object` с `offset` Возвращает весь JSON-объект в формате base64 для клиентов, которые могут запускать код, но не получают ссылки для скачивания: продолжить с `offset` установить на `nextOffset` и `sha256` В первой части проверяется SHA-256 объединенных байтов перед их разбором. Каждая часть снова считывает объект с правами пользователя сессии; если объект изменился в процессе, вызов завершается неудачей, и чтение начинается заново.
- **Ссылки для скачивания** (`download_url` В списке удаленных элементов содержится ссылка на все его записи в формате JSON, и `read_file` с `download: true` Возвращает ссылку на весь файл. Клиенты, способные выполнять команды оболочки (например, Claude Code), получают его с помощью `curl -o <file> "<download_url>"`.
- **Загрузите ссылки** : `prepare_upload` возвращает ссылку и `upload_id` Клиент загружает файл с помощью `curl -T <file> "<url>"` (`PUT` или `POST` необработанный текст (до 100 МБ) и проходит проверку. `upload_id` к `write_file` или `install_package` Ссылка может быть использована только один раз. Таким образом, агент ИИ может установить `.tgz` оно построено с `npm pack`.

Ссылки `<mcp endpoint>/transfer/<token>` Случайный токен является учетными данными, поэтому они работают без авторизации на конечной точке MCP и истекают через 15 минут. Они недоступны в качестве веб-расширения при включенной аутентификации в веб-адаптере, поскольку веб-адаптер сначала запрашивает авторизацию; затем инструменты сообщают об этом.

### Подсказки

Клиенты MCP предлагают эти команды в готовом виде (например, в виде команд со слэшем):

- `diagnose_adapter` (`instance`) - выяснить, почему экземпляр не работает: статус, журнал, уведомления, подключение и доступные обновления.
- `room_overview` (`room`) - краткое описание устройств в комнате и любых необычных моментов.
- `create_automation` (`description`) - преобразует описание в скрипт для JavaScript-адаптера.

### Ресурсы и оперативные обновления (SSE)

Состояния и объекты также доступны в качестве **ресурсов** MCP с использованием канонической схемы URI ioBroker, поэтому клиенты могут читать их и **подписываться** на них. Сервер передает изменения через поток Streamable HTTP SSE. `notifications/resources/updated`).

- Штаты: `iobstate://<id>` (например `iobstate://javascript.0.temperature`) –`resources/read` возвраты `{ id, val, ack, ts, lc, q }`.
- Объекты: `iobobject://<id>` (например `iobobject://system.adapter.admin.0`) –`resources/read` возвращает объект.
- Журналы: `ioblog://all` (каждый источник) или `ioblog://<source>` (например `ioblog://admin.0`) –`resources/read` возвращает последние строки лога (`{ source, logs: [{ ts, level, source, message }] }` Подписка включает пересылку журналов для адаптера; каждая новая соответствующая строка запускает `notifications/resources/updated`.
- `resources/subscribe` Подписывается на состояние/объект/журнал базового ioBroker; при каждом изменении клиент получает уведомление. `notifications/resources/updated` для этого URI и перечитывает его. `resources/unsubscribe` останавливает это.

Подписки отслеживаются для каждой сессии и подсчитываются по количеству ссылок, поэтому адаптер подписывается на состояние/объект только один раз, независимо от того, сколько клиентов/сессий следят за ним, и отписывается, когда последний клиент покидает систему.

(Использование файлов) `iobfile://<adapter>/<path>` по той же схеме; они доступны через `read_file` /`write_file` (В качестве инструментов, а не в качестве ресурсов, на которые можно подписаться.)
