## Настраивать

Адаптер поддерживает два режима MQTT для связи с Frigate.

### Встроенный MQTT-брокер (по умолчанию)

Адаптер использует собственный MQTT-брокер. Frigate подключается к нему напрямую.

1. Введите URL-адрес Frigate в настройках адаптера (например)`192.168.178.2:5000` )
2. Укажите порт MQTT (по умолчанию:`1883` )
3. Настройка Frigate`config.yml` Для подключения к ioBroker:

```yaml
mqtt:
  host: <ioBroker IP address>
  port: 1883
```

4. Запустите и Frigate, и адаптер. В журнале адаптера должно появиться сообщение «Новый клиент».

### Внешний MQTT-брокер

Если у вас уже используется MQTT-брокер (например, Mosquitto), настройте адаптер для подключения в качестве клиента.

1. Установить **режим MQTT** на`External MQTT Broker`
2. Введите хост брокера (например)`192.168.1.100` или`mqtt://192.168.1.100:1883` )
3. При желании введите имя пользователя и пароль.
4. Установите **префикс темы MQTT,** если Frigate использует собственный (по умолчанию:`frigate` )
5. Введите URL-адрес фрегата как обычно.

### Аутентификация API Frigate

Если в вашем экземпляре Frigate включена аутентификация (обычно на порту 8971 с использованием HTTPS), вы можете настроить адаптер для автоматического входа в систему.

1. Введите URL-адрес фрегата, используя`https://` префикс (например)`https://192.168.178.26:8971` )
2. Введите ваше **имя пользователя** и **пароль для доступа к системе Frigate** .
3. Адаптер будет входить в систему через`POST /api/login` и использовать токен JWT для всех вызовов API.

Если поля оставить пустыми, авторизация не выполняется, и адаптер работает как прежде (неаутентифицированный доступ к порту 5000).

Адаптер автоматически обновляет токен, если срок его действия истекает (ответ 401 запускает повторный вход в систему и повторную попытку запроса).

**Примечание:** Допускаются самоподписанные сертификаты. Если вы не используете HTTPS, оставьте URL-адрес без префикса (например,`192.168.178.26:5000` ) — по умолчанию адаптер использует протокол HTTP.

## Справочная информация по штатам

### Статистика

`frigate.0.stats.*` — Общая информация о системе обновляется каждые несколько секунд.

| Состояние                                | Описание                                           | Единица |
| ---------------------------------------- | -------------------------------------------------- | ------- |
| `stats.cameras.<name>.camera_fps`        | Кадры в секунду из видеопотока с камеры            | fps     |
| `stats.cameras.<name>.process_fps`       | Обрабатывается количество кадров в секунду         | fps     |
| `stats.cameras.<name>.skipped_fps`       | Пропущены кадры (перегрузка обработки)             | fps     |
| `stats.cameras.<name>.detection_fps`     | Количество операций обнаружения объектов в секунду | fps     |
| `stats.cameras.<name>.detection_enabled` | Активно обнаружение объектов                       | —       |
| `stats.cameras.<name>.audio_dBFS`        | Уровень звука                                      | dBFS    |
| `stats.cameras.<name>.audio_rms`         | Среднеквадратичная амплитуда звука                 | —       |
| `stats.detectors.<name>.inference_speed` | Время на один вывод                                | РС      |
| `stats.service.uptime`                   | Время безотказной работы сервиса                   | с       |
| `stats.service.version`                  | фрегатная версия                                   | —       |
| `stats.service.storage.<mount>.total`    | Общий объем хранения                               | МБ      |
| `stats.service.storage.<mount>.used`     | Использованное хранилище                           | МБ      |
| `stats.service.storage.<mount>.free`     | Бесплатное хранилище                               | МБ      |

### События

`frigate.0.events.*` — Последнее мероприятие с информацией о том, что будет до и после.

| Состояние                   | Описание                                  |
| --------------------------- | ----------------------------------------- |
| `events.after.camera`       | Камера, зафиксировавшая событие           |
| `events.after.label`        | Тип объекта (человек, автомобиль и т. д.) |
| `events.after.top_score`    | Наивысший показатель уверенности          |
| `events.after.has_snapshot` | Доступен снимок состояния.                |
| `events.after.has_clip`     | Доступен видеоролик.                      |
| `events.history.json`       | JSON-массив последних X событий           |

Каждое событие в истории содержит URL-адреса для снимков и видеороликов:

- `websnap` — URL снимка
- `webclip` — URL клипа (MP4)
- `webm3u8` — URL HLS-потока
- `thumbnail` — Миниатюра, закодированная в Base64

| `<cam>.detect_state`        | логический | да           | Включить/отключить обнаружение объектов                             |
| `<cam>.recordings_state`    | логический | да           | Включить/отключить запись                                           |
| `<cam>.snapshots_state`     | логический | да           | Включение/отключение снимков                                        |
| `<cam>.audio_state`         | логический | да           | Включить/выключить обнаружение звука                                |
| `<cam>.birdseye_state`      | логический | да           | Включить/отключить вид сверху                                       |
| `<cam>.birdseye_mode_state` | нить       | да           | Режим «Взгляд сверху» (объекты/непрерывный/движение)                |
| `<cam>.review_status`       | нить       | нет          | Уровень активности (НЕТ/ОБНАРУЖЕНИЕ/ОПОВЕЩЕНИЕ)                     |

### Пульты дистанционного управления камерой

`frigate.0.<camera_name>.remote.*` — Записываемые состояния для управления камерами.

| Состояние                          | Тип        | Описание                                                                 |

| `remote.motionThreshold`           | число      | Порог обнаружения движения (1-255)                                       |
| `remote.motionContourArea`         | число      | Минимальный размер области контура движения                              |
| `remote.birdseyeMode`              | нить       | Режим «Взгляд сверху» (объекты, непрерывный обзор, движение)             |

### Зоны

Зонные устройства создаются автоматически на основе конфигурации Frigate.

Количество простых объектов (например)`<zone>.person` ,`<zone>.car` ) напрямую взято из тем MQTT, относящихся к занятости портов Frigate (`frigate/<zone>/<object>` и`frigate/<zone>/all` ), поэтому он всегда соответствует данным, сообщаемым Frigate. Адаптер дополнительно предоставляет разбивку по активному/стационарному состоянию и сводку, полученные из потока событий.

| Состояние                  | Тип        | Описание                                            | Источник          |
| -------------------------- | ---------- | --------------------------------------------------- | ----------------- |
| `<zone>.person`            | число      | Лица, находящиеся в данный момент в зоне            | Фрегат MQTT       |
| `<zone>.all`               | число      | Все объекты, находящиеся в данный момент в зоне     | Фрегат MQTT       |
| `<zone>.person_active`     | число      | Активно перемещающиеся люди                         | агрегатор событий |
| `<zone>.person_stationary` | число      | Стационарные люди                                   | агрегатор событий |
| `<zone>.total_objects`     | число      | Всего объектов всех типов (активных + стационарных) | агрегатор событий |
| `<zone>.active`            | логический | Любой объект, обнаруженный в зоне                   | агрегатор событий |

Активное/стационарное состояния определяются с помощью параметров объекта.`current_zones` и обнуляются, как только объект покидает зону или событие завершается.

| `notifications.suspended` | число      | нет          | UNIX-метка времени окончания приостановки |

| `<cam>.audio_transcription`    | Расшифрованный аудиотекст                               |
| `<cam>.audio_<type>`           | Распознавание типов звука (речь, лай и т. д.)           |
| `<cam>.status_detect`          | Состояние функции обнаружения (онлайн/офлайн/отключено) |

## Уведомления

Адаптер может отправлять снимки и фрагменты событий в службы обмена сообщениями.

### Поддерживаемые услуги

- Телеграмма
- Pushover (только скриншоты, без видео)
- Сигнал (signal-cmb)
- Электронная почта
- Любой другой адаптер обмена сообщениями ioBroker

### Настройка уведомлений

1. Включите уведомления в настройках адаптера.
2. Введите один или несколько экземпляров уведомления (например)`telegram.0` )
3. При желании укажите имена/идентификаторы пользователей для целевой доставки.
4. Установите минимальный пороговый балл (0 = отключено)

Видеоролики отправляются по истечении заданного времени ожидания (по умолчанию: 5 секунд) после завершения события.

**Важно:** экземпляр системы уведомлений и адаптер Frigate должны работать на одном хосте, поскольку файлы передаются через локальную файловую систему.

### Шаблон текста уведомления

Используйте заполнители в тексте уведомления:

| Заполнитель  | Описание                                     |
| ------------ | -------------------------------------------- |
| `{{source}}` | Название камеры                              |
| `{{type}}`   | Тип объекта (человек, автомобиль и т. д.)    |
| `{{state}}`  | Состояние события (Событие до/Событие после) |
| `{{status}}` | Статус события (новое/обновленное/завершено) |
| `{{score}}`  | Показатель уверенности                       |
| `{{zones}}`  | Входящие зоны (разделенные запятыми)         |

Пример:`{{source}}: {{type}} detected ({{score}}) in {{zones}}`

## Интеграция

### Просмотр в реальном времени через веб-адаптер

Адаптер регистрирует веб-расширение в`ioBroker.web` Таким образом, все камеры доступны через веб-сервер, не раскрывая при этом возможности самого Frigate:

| URL                                                          | Содержание                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| `http(s)://iobroker-IP:8082/frigate.0/<camera>/snapshot.jpg` | текущий кадр в формате JPEG                                                     |
| `http(s)://iobroker-IP:8082/frigate.0/<camera>/stream.mjpeg` | непрерывный MJPEG, пригодный для использования в обычной среде`<img src="...">` |

Оба варианта принимают параметры запроса соответствующей конечной точки Frigate, например:`?height=480` для изображения меньшего размера,`?fps=5` ограничить частоту кадров потока или`?bbox=1&timestamp=1` чтобы Frigate мог отобразить ограничивающие рамки и метку времени на изображении.

Почему следует использовать веб-адаптер вместо прямого доступа к URL-адресу Frigate:

- Фрегат обычно приписан к`127.0.0.1` Поэтому его URL-адрес не работает ни на одном другом компьютере.
- Для доступа к порту 8971 требуется авторизация — токен хранится в сетевом адаптере, а не в браузере.
- HTTP Frigate, находящийся внутри HTTPS ioBroker.web, блокируется браузером как содержащий смешанный контент.
- Эти маршруты проходят аутентификацию через ioBroker.web, а собственный порт Frigate — нет.

Обратите внимание, что Frigate кодирует поток MJPEG отдельно для каждого пользователя. Для постоянной панели мониторинга предпочтительнее использовать снимок, который перезагружается каждые несколько секунд, и сохранять MJPEG для тех моментов, когда кто-то действительно наблюдает за процессом.

### Виджеты диспетчера устройств

Адаптер поставляется с двумя виджетами для **ioBroker.devices** . Оба позволяют выбрать камеру в виде простого объекта под экраном.`frigate` пространство имен (например)`frigate.0.driveway` ) и может позволить Frigate добавить в изображение области обнаружения и метку времени.

- **Frigate Snapshot** — восстанавливает статичное изображение с настраиваемым интервалом. Запрос отправляется адаптеру через сокет ioBroker, поэтому работает везде, где запущен пользовательский интерфейс устройств, включая административную панель, и использует учетные данные Frigate для входа в систему адаптера.
- **Frigate Live** — отображает поток MJPEG, который браузер декодирует автоматически. Поток загружается из **веб-** адаптера, к которому пользовательский интерфейс устройств может получить доступ только при работе в веб-версии. При работе в административной панели — обычный случай — введите веб-версию в настройках виджета, например.`http://192.168.1.5:8082` .

Если сомневаетесь, используйте виджет снимков, у него нет подобных ограничений.

### vis Интеграция

**Снимок экрана:**

```
String img src → Object ID: frigate.0.camera_name.person_snapshot
String img src → Object ID: frigate.0.events.history.01.thumbnail
```

**Видеоролик:**

```html
<video width="100%" height="auto" src="{frigate.0.events.history.01.webclip}" autoplay muted></video>
```

**Количество человек:**

```
Value → Object ID: frigate.0.camera_name.person
```

**Активность в зоне:**

```
Indicator → Object ID: frigate.0.Vorgarten.active
Value → Object ID: frigate.0.Vorgarten.person
```

### Скрипты и автоматизация

Пример: Включать свет при обнаружении человека в зоне:

```javascript
on({ id: 'frigate.0.Vorgarten.active', val: true }, () => {
    setState('hm-rpc.0.ABC1234567.1.STATE', true);
    log('Person detected in Vorgarten');
});
```

Пример: Отправлять уведомление, когда количество людей в зоне превышает пороговое значение:

```javascript
on({ id: 'frigate.0.Vorgarten.person', change: 'ne' }, (obj) => {
    if (obj.state.val >= 3) {
        sendTo('telegram.0', { text: `Warning: ${obj.state.val} persons in Vorgarten!` });
    }
});
```

## Часто задаваемые вопросы

**В: При установке адаптера из GitHub появляется сообщение «не удается найти стартовый файл».** О: Эта версия включает каталог сборки. Если ошибка сохраняется, запустите`npm run build` в каталоге адаптера.

**В: Устройства в зонах пусты.** О: Состояния зон создаются только тогда, когда Frigate обнаруживает объекты в этих зонах. Дождитесь события в зоне.

**В: У меня возникают ошибки ENOENT при работе со снимками/клипами.** О: Эта проблема исправлена в версии 2.3.0. Обновите до последней версии.

**В: Как изменить порог обнаружения движения?** О: Установите`frigate.0.<camera>.remote.motionThreshold` до значения от 1 до 255.

**В: Уведомления не отправляются.** О: Убедитесь, что экземпляр уведомлений (например, telegram.0) работает на том же хосте, что и адаптер Frigate. Проверьте, включены ли уведомления в настройках адаптера.
