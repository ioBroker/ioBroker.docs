# Переход с адаптера go-e (ioBroker.go-e) на go-e-charger

[Немецкая версия](/#/docs/adapterref/iobroker.go-e-charger/docu/migration-from-go-e_de.md)

Это руководство поможет пользователям адаптера [ioBroker.go-e](https://github.com/MK-2001/ioBroker.go-e) (экземпляра). `go-e.0`) для переключения на **ioBroker.go-e-charger** (экземпляр) `go-e-charger.0` Оба адаптера взаимодействуют с зарядным устройством через его локальный HTTP API, но используют разные объектные структуры и концепции конфигурации, поэтому миграция означает перенаправление скриптов, визуализаций и настроек истории.

## Зачем переходить на другую платформу?

- **Несколько зарядных устройств в одном экземпляре** , с общим избытком солнечной энергии в порядке убывания мощности в настенном блоке и опциональным общим бюджетом тока (защита предохранителем).
- **ChargeManager** : Зарядка избыточного заряда от солнечных батарей с использованием режимов работы домашней батареи (отключено / минимальный уровень заряда / приоритет батареи), гистерезис уровня заряда и проверка возраста батареи.
- **Автоматическое переключение 1-/3-фазных систем** (поколение 3+) и `Settings.PhaseMode` (0 = авто, 1, 3) во время выполнения.
- **Режим только для чтения** для каждого зарядного устройства. `info.chargeState` Объяснение причин, по которым зарядное устройство (не) заряжает, обнаружение в автономном режиме.
- Зарядка, начатая через приложение go-e, не прерывается ни нажатием кнопки, ни использованием RFID-метки, даже если оба режима работы адаптера выключены.
- Использует HTTP API версий 1 и 2, протестировано с прошивкой от V033 до V60.6, активно поддерживается.

Адаптер go-e обладает некоторыми функциями, которых пока нет у go-e-charger — перед переходом ознакомьтесь с информацией в разделе [«Пока не поддерживается»](#not-yet-supported) .

## Часто задаваемые вопросы

**Какой HTTP API необходимо включить в приложении go-e?** Для оборудования 3-го и 4-го поколений включите "HTTP API v1" (обязательно). Для переключения фаз, частоты сети и минимального тока оборудования также включите "HTTP API v2". Более старые зарядные устройства (2-го поколения) предоставляют API v1 без этой настройки.

**Какой режим работы приложения go-e следует использовать (эко или базовый)?** go-e-charger управляет самим зарядным устройством (высвобождение заряда и нестабильный ток). Функции зарядного устройства, которые также запускают, останавливают или ограничивают зарядку — избыток солнечной энергии (эко-режим с собственной логикой зарядки от солнечных батарей), зарядка на основе цены на электроэнергию или таймеры зарядки — могут работать с ChargeManager. При использовании ChargeManager эти функции зарядного устройства следует отключить и использовать базовый/стандартный режим зарядки; ChargeNOW и ChargeManager затем будут принимать решение о зарядке.

**Какой знак должны иметь значения PV и потребления?** Оба значения должны быть положительными в Вт: выработка электроэнергии от солнечных батарей ≥ 0, потребление домохозяйством ≥ 0. Значение в кВт необходимо преобразовать в Вт. Единое значение импорта/экспорта из сети пока нельзя использовать напрямую ( [#919](https://github.com/hombach/ioBroker.go-e-charger/issues/919) ); до тех пор создайте псевдоним или состояние скрипта с необходимыми значениями. Если в вашей конфигурации адаптера go-e используется "Negate", то в исходном объекте, скорее всего, указан неправильный знак для go-e-charger.

**Можно ли использовать оба адаптера параллельно?** Да, для чтения. Включите **режим только для чтения** для зарядного устройства в go-e-charger, пока сравниваете значения: в этом случае оно будет считывать данные, но не отправлять команды управления. Не позволяйте обоим адаптерам одновременно управлять одним и тем же зарядным устройством (go-e PV control / запись в `allow_charging` или `amperePV` и go-e-charger ChargeManager / ChargeNOW) – они перезапишут друг друга. Когда вы будете удовлетворены результатом, остановите экземпляр go-e (или его контроллер фотоэлектрической системы), отключите режим только для чтения и включите `Settings.ChargeManager`.

**Потеряю ли я свою историю?** Данные истории хранятся для каждого идентификатора объекта. Включите историю для новых точек данных; существующие данные останутся сохраненными в рамках существующей истории. `go-e.0` Идентификаторы.

**А что насчёт флэш-памяти/EEPROM зарядного устройства?** go-e-charger записывает зарядный ток через энергозависимый ключ. `amx` (используется только прошивка 033) `amp`) и отбрасывает команды, значение которых зарядное устройство уже сообщает.

## Не поддерживается (пока)

Следующие функции адаптера go-e недоступны в go-e-charger. Предложения отслеживаются как проблемы — обратная связь и запросы на добавление изменений приветствуются:

- Входные данные сетевого счетчика с указанием значения импорта/экспорта со знаком, опциями «Отрицание» и «Только подтверждение» – [#919](https://github.com/hombach/ioBroker.go-e-charger/issues/919)
- Режим Min+PV (всегда не менее 6 А плюс избыток) – [#920](https://github.com/hombach/ioBroker.go-e-charger/issues/920)
- Энергия текущей сессии и лимит энергии в кВт·ч – [#921](https://github.com/hombach/ioBroker.go-e-charger/issues/921)
- дополнительные параметры данных (температура, код ошибки, ток/мощность на фазу, коэффициент мощности, Wi-Fi, серийный номер, `modelStatus`, …) – [#922](https://github.com/hombach/ioBroker.go-e-charger/issues/922)
- Таймер: зарядка в течение X минут / остановка в заданное время – [#923](https://github.com/hombach/ioBroker.go-e-charger/issues/923)
- Интерфейс скрипта в ваттах (`energy.max_watts`, `adjustAmpLevelInWatts`) – [#924](https://github.com/hombach/ioBroker.go-e-charger/issues/924)
- Настраиваемые пороговые значения переключения фазы, буфер и задержка – [#925](https://github.com/hombach/ioBroker.go-e-charger/issues/925)
- Настройки записывающего устройства (блокировка кабеля, контроль доступа, светодиод, уровни тока кнопок) – [#926](https://github.com/hombach/ioBroker.go-e-charger/issues/926)
- остановка на уровне заряда батареи автомобиля, собственные расчеты фотоэлектрической энергии зарядного устройства (`ids`), информация MQTT/облако/управление нагрузкой и значения обмена электроэнергией (aWATtar)
