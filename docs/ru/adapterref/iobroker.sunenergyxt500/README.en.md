# ioBroker.sunenergyxt500

## Адаптер sunenergyxt500 для ioBroker

Интеграция и управление собственным потреблением для гибридных систем хранения энергии **[SunEnergyXT 500 / 500 PRO](https://www.sunenergyxt.com/details-500-series)** с переменным током (производитель: [SunEnergyXT](https://www.sunenergyxt.com/) ) через **локальный HTTP API** устройства — облачная учетная запись не требуется. Один экземпляр управляет **до тремя головками** (хранилищами).

## Функции

- Управляет **от одной до трех голов** в одном экземпляре, каждая в своем поддереве.`heads.<n>.*` плюс объединенный`total.*` агрегаты.
- Опрашивает локальный API (`GET /read` ) и отображает все стабильные поля в состояниях: уровень заряда батареи, мощность батареи/сети/нагрузки/солнечной батареи, ток/напряжение для каждого MPPT, ежедневные счетчики энергии, уровень заряда батареи, информация об устройстве/прошивке и состояние счетчика.
- Поля управления, доступные для записи (`POST /write` (подтверждено повторным прочтением), соответствует панели управления официальной интеграции, за исключением полей, которые в документации API помечены как _зарезервированные_ : заданное значение сетки.`GS` максимальная подача`IS` , пределы SoC`SI` /`SA` /`SO` режим самопотребления`MM` конфигурация счетчика`MD` часовой пояс`TZ` , перезапуск`RT` , максимальная выходная мощность сетки`MG` , то`LFB` /`LPS` /`PM` переключатели и локальный режим`LM` (⚠️`LM=1` блокирует управление облаком/приложением до сброса). Зарезервированные поля (например)`PT` ,`SI1` ,`SA1` ) доступны только для чтения.
- Два переключаемых **режима управления** : **контроллер** самопотребления на стороне адаптера (запись).`GS` из _любого_ состояния счетчика ioBroker, с прямой связью + P, с сторожевым таймером/безопасным режимом, который **распределяет одну заданную точку сети между всеми датчиками** , или **саморегулирование устройства** (привязывает поддерживаемый счетчик к единому хранилищу и позволяет устройству управлять собой) — плюс режим **выключения** для чистого мониторинга.
- Кнопка **«Проверить все головки»** в административной панели проверяет доступность каждой настроенной головки (модель + SoC) перед сохранением.
- Индикатор подключения (`info.connection` ) плюс`info.lastUpdate` и на душу населения`online` /`lastError` .
- Полный, неизмененный вариант.`/read` Реакция каждой головы сохраняется в`heads.<n>.info.rawResponse` (JSON), поэтому любое поле, которое адаптер не сопоставляет с выделенным состоянием, все равно можно прочитать оттуда.

## Как работает этот адаптер

Этот адаптер управляет хранилищем **локально** , без использования облачных сервисов производителя. Один экземпляр управляет **от одной до трех головок** (хранилищных блоков). Самостоятельное использование может осуществляться **двумя взаимоисключающими способами** — выбор одного из них осуществляется через настройку **режима управления** :

**Режим B — Адаптер-контроллер (рекомендуется по умолчанию, работает с любым счетчиком, 1–3 головки).** ioBroker считывает текущую мощность сети из **любого состояния, на которое вы его направите** .`gridPowerStateId` ) и адаптер записывает заданное значение сетки`GS` (прямая связь + коррекция P, с сторожевым таймером). В качестве счетчика может использоваться _любой компонент,_ поддерживаемый ioBroker — Shelly, Tasmota, адаптер для интеллектуальных счетчиков/Modbus — **включая счетчики, которые хранилище не может считывать самостоятельно** . Вы предоставляете одно состояние, содержащее **чистую мощность сети в ваттах** .`>0` = рисовать,`<0` = подача электроэнергии; включить _инвертирование знака источника_ , если он инвертирован; для кВт / раздельного импорта-экспорта / пофазных счетчиков сначала вычислить чистое сетевое значение в небольшом состоянии ioBroker). При наличии более чем одного электроусилителя контроллер вычисляет **одну** общую заданную точку и **распределяет ее между подключенными электроусилителями** — поровну, с ограничением мощности каждого электроусилителя, пропуская электроусилитель, который заполнен (во время зарядки) или пуст (во время разрядки); его доля перераспределяется между остальными. Адаптер принудительно`MM=0` на каждой головке, чтобы устройства выполняли`GS` При этом счетчик остается полностью работоспособным в ioBroker.

**Режим A — Саморегулирование устройства (поддерживаемые счетчики, только с одной головкой).** Адаптер привязывает поддерживаемый счетчик **к памяти** (`MM=1` +`MD` ) и позволяет **устройству регулировать себя самостоятельно** — собственное потребление производителя, которое может реагировать быстрее, чем внешний контур. Этот режим доступен **только с одним счетчиком** ; при конфигурации с двумя или тремя счетчиками его нельзя выбрать — используйте вместо этого контроллер адаптера. Поддерживаются только четыре типа счетчиков (EcoTracker, Shelly 3EM, Shelly Pro 3EM, Tasmota), и счетчик должен быть доступен для хранилища в локальной сети. Адаптер **не** записывает данные.`GS` В этом режиме используется простое mDNS/HTTP-опрос, поэтому счетчик **остается работоспособным в ioBroker** — в отличие от настроек счетчика в приложении производителя, которое может перенастроить счетчик и удалить его из ioBroker; этот адаптер выполняет прямую привязку и избегает этого.

**Выключено (по умолчанию, только мониторинг).** Адаптер никогда не записывает данные.`MM` /`MD` /`GS` ; это только опрос. Вы по-прежнему можете отдавать команды.`control.*` штаты вручную.

В обоих режимах управления адаптер **обладает`MM`** При каждом опросе проверяется мнение каждого руководителя.`MM` В зависимости от выбранного режима, система повторно подтверждает его (с предупреждением), если что-то другое изменило его — таким образом, случайное подключение счетчика или внешний скрипт не смогут незаметно отключить управление. Примечание: головной модуль выполняет только записанный запрос.`GS` когда`MM=0` ; с ограниченным размером (`MM=1` оно саморегулируется и игнорирует`GS` .

**Несколько блоков должны быть подключены к разным фазам.** Это ответственность оператора за электроснабжение — адаптер не может (и не должен) это проверять. Контроллер регулирует **суммарную** мощность сети, отображаемую вашим счетчиком, — именно это учитывает стандартный немецкий двунаправленный счетчик; оптимизация по фазам выходит за рамки его компетенции.

**Локальный режим (`LM=1` ) требуется.** Каждое устройство предоставляет доступ только к своему локальному HTTP API (`/read` /`/write` ) когда **локальный режим включен** — при его выключении,`/read` Не возвращает никаких данных (подтверждено на протестированной прошивке). Включение локального режима также отключает удаленное управление через облако/приложение; следовательно, мобильное приложение производителя больше не может управлять устройством.

## Требования

- От одного до трех SunEnergyXT 500 (`PK=1` 800 Вт) или 500 PRO (`PK=2` Насадки мощностью 2400 Вт, доступные в локальной сети (совместимость с разными моделями также допустима).
- **Локальный режим (`LM=1` Эта функция включена** на каждом устройстве — она необходима для передачи значений через локальный HTTP API (см. раздел « _Как работает этот адаптер_ »). Это также отключает удаленное управление из облака/приложения.
- В зависимости от режима управления требуется счётчик: для **режима B** (контроллер адаптера) — любой счётчик, для которого доступна информация о мощности сети в качестве **состояния ioBroker** ; для **режима A** (саморегулирование устройства, одноканальный) — один из четырёх поддерживаемых счётчиков (EcoTracker, Shelly 3EM, Shelly Pro 3EM, Tasmota), доступных из хранилища в локальной сети. В _выключенном_ режиме не требуется.

## Установка

1. В административной панели ioBroker откройте **раздел «Адаптеры»** , найдите **sunenergyxt500** и установите его.
2. После установки экземпляра`sunenergyxt500.0` Создан. Откройте его настройки и введите **IP-адрес/имя хоста Головы 1** (добавьте **Голову 2/Голову 3,** если у вас больше голов). Оставьте **режим управления** в _положении «Выкл.»_ для чистого мониторинга.
3. Сохранить и закрыть — адаптер начнет опрос и заполнит дерево объектов в подкаталоге.`sunenergyxt500.0.heads.*` (и`total.*` ).

## Конфигурация

**Связь**

- **IP-адрес/имя хоста головки 1** (обязательно) и **головки 2/3** (необязательно) — локальные адреса ваших головок хранения, каждая с необязательной меткой. Одним экземпляром можно управлять до тремя головками. Размещайте несколько головок на **разных фазах** (за это отвечает оператор); адаптер регулирует **суммарную** мощность сети. Один и тот же адрес нельзя ввести дважды.
- **Проверка всех головок** — программа проверяет каждую настроенную головку и сообщает модель + SoC (или ошибку), чтобы вы могли проверить адреса перед сохранением.
- **Интервал опроса (с)** — как часто запрашивается каждая головная станция.`/read` (по умолчанию 5 с).
- **Время ожидания запроса (мс)** — время ожидания HTTP-запроса (по умолчанию 8000 мс).

**Управление** — выберите **режим управления** :

_Выкл._ (по умолчанию) — только мониторинг; адаптер никогда не записывает данные.`MM` /`MD` /`GS` .

_Контроллер адаптера_ (режим B) — поля:

- **Состояние источника электроэнергии из сети** — иностранное государство, владеющее электроэнергией из сети вашего дома, поступающей на счётчик. Условные обозначения:`>0` = рисование сетки,`<0` = подача электроэнергии. Включите функцию **«Инвертировать знак источника»,** если ваш счетчик использует противоположную систему обозначений.
- **Адаптивное управление** (по умолчанию включено): регулирует мощность в трех проверенных производителем режимах — небольшие отклонения плавно (каждые 7 с, шаг 20 Вт), средние — каждые 2,5 с (120 Вт), большие шаги нагрузки — немедленно (450 Вт), с фиксированной мертвой зоной 5 Вт. Отключите его, чтобы настроить контроллер вручную с помощью полей усиления / мертвой зоны / интервала записи / ограничения шага (они появятся только в этом случае).
- **Целевая мощность сети** (Вт, по умолчанию 0): 0 = нулевая подача электроэнергии в сеть; положительные значения обеспечивают небольшое преднамеренное потребление электроэнергии из сети (подача электроэнергии в сеть никогда не осуществляется), отрицательные значения — небольшую преднамеренную подачу электроэнергии в сеть — используется та же система знаков, что и для состояния источника.`>0` = ничья).
- **Максимальная регулировка за одну коррекцию** (Вт, по умолчанию 500, 0 = неограниченно): ограничивает диапазон изменения заданного значения за один шаг управления, поэтому высокое усиление не может привести к перерегулированию при скачках показаний прибора.
- **Усиление** (по умолчанию 0,3), **Мертвая зона** (Вт), **Минимальный интервал записи** (мс), **Мертвая зона записи для каждой головки** (Вт — минимальное изменение заданного значения головки перед ее перезаписью, чтобы избежать помех при разделении потока). Максимальная мощность каждой головки **определяется устройством автоматически** (800 Вт для 500, 2400 Вт для 500 PRO), поэтому смешанные конфигурации работают без дополнительной настройки.
- **Предупреждение сторожевого таймера / аварийный режим (s)** — если источник данных в сети устаревает, контроллер регистрирует предупреждение и в конечном итоге принудительно запускает`GS=0` на **всех головках** (безопасное нейтральное положение) до восстановления источника. Телеметрия сторожевого таймера доступна под`controller.*` .

Контроллер считывает фактическую мощность каждого устройства в сети.`GP` ) обратно перед коррекцией, что обеспечивает естественную защиту от перенасыщения, когда устройство ограничивает мощность внутри себя (например, с помощью SoC).

_Саморегулирование устройства_ (режим A, **только для одной головки** ) — области:

- **Тип счетчика** — EcoTracker / Shelly 3EM / Shelly Pro 3EM / Tasmota.
- **Серийный номер / IP-адрес счетчика** — серийный номер для Shelly/Tasmota (определяется через mDNS) или IP-адрес локальной сети для EcoTracker (напрямую). Для Tasmota используйте префикс серийного номера без последних 4 символов и установите **клавишу питания** в соответствии с подтипом вашего энергомонитора.

Адаптер соединяет счетчик (`MM=1` +`MD` ) и устройство саморегулируется; адаптер не записывает`GS` . Привязанный счетчик остается доступным для использования в ioBroker. Этот режим скрывается/блокируется после настройки второго или третьего блока.

> **Безопасность:** В _выключенном_ режиме адаптер доступен только для чтения — он только опрашивает устройство.`/read` и никогда не пишет, если вы не дадите команду.`control.*` состояние. В режиме управления адаптер **обеспечивает`MM`** на каждой головке для этого режима и повторно активирует его при внешнем изменении; **не** запускайте второй раз.`GS` одновременно с писателем (ваш собственный сценарий или сценарий устройства)`MM` (с другим измерительным прибором), иначе они будут драться из-за батареи.

## Контроль поведения, точности и ограничений

**Что ожидать:** Контроллер поддерживает мощность сети в диапазоне **±10–20 Вт вокруг нуля** и корректирует скачки нагрузки — в зависимости от настроек — в течение **\~1–3 секунд, но не более \~30 секунд** . Постоянное, точное значение 0,0 Вт **по замыслу разработчиков недостижимо** — ни с одним контроллером на этом оборудовании:

- **Точность и уровень шума измерителя:** сам внешний измерительный прибор измеряет с погрешностью и уровнем шума в несколько ватт — регулирование ниже этого значения бессмысленно.`GS` Уставка имеет разрешение 1 Вт, поэтому точность установки не является пределом.
- **Задержка в цепочке измерений:** измеритель → состояние ioBroker → контроллер →`/write` → устройство плавно нарастает. Между этапом нагружения и его коррекцией неизбежно проходит \~1–3 секунды.
- **Динамика нагрузки:** Компрессор или чайник переключаются за миллисекунды — после этого реагирует каждый контроллер. Кратковременные скачки мощности на ваших графиках — это нормально и энергетически бессмысленно (ватт-секунды).
- Контроллер регулирует мощность в соответствии с заданным **целевым значением мощности сети** (по умолчанию 0) и **симметрично** колеблется вокруг него — короткие, небольшие моменты подачи электроэнергии в сеть являются частью нулевой подачи электроэнергии. Если подача электроэнергии в сеть никогда не требуется, установите целевое значение на небольшое преднамеренное потребление (например, +10 Вт).

**Как работают настройки:**

| Параметр                                                  | Эффект                                                             | меньшее значение                                                  | большее значение                                                                                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Прирост**                                               | доля отклонения, скорректированная за шаг                          | вялый, плавный (0,3 ≈ 7 шагов до \~0)                             | Быстродействующий (1,0 = одна коррекция), но более чувствительный к шуму измерительного прибора; значение >1 может привести к перерегулированию. |
| **Целевая мощность сети (Вт)**                            | значение, до которого регулируется мощность сети                   | <0 = преднамеренная подача                                        | >0 = преднамеренная ничья ("никогда не давайте мяч в корзину")                                                                                   |
| **Максимальная поправка за одно внесение изменений (Вт)** | ограничивает изменение заданного значения за шаг                   | сглаживает скачки показаний индикатора на высоком уровне усиления | Большие значения (или 0 = неограниченное значение) быстрее реагируют на большие скачки нагрузки.                                                 |
| **Мертвая полоса (Вт)**                                   | Отклонения ниже этого значения игнорируются.                       | Более точные записи, больше операций записи (0 = все исправлено)  | более спокойный, оставляет небольшое постоянное отклонение                                                                                       |
| **Минимальный интервал записи**                           | ритм исправлений                                                   | Более быстрое стабилизирование (пол 1000 мс)                      | меньше записей в устройство, более медленное отслеживание                                                                                        |
| **Мертвая зона записи на одного пользователя**            | подавляет мини-перераспределение между головками (многоголовочное) | более точный                                                      | меньше болтовни                                                                                                                                  |

**Адаптивное управление** (по умолчанию) автоматически выбирает темп для каждого уровня. Для ручного режима доступны два проверенных профиля: _«Расслабленный_ » (по умолчанию — спокойная работа, минимальное количество операций записи на устройство, диапазон ±20–30 Вт) и _«Точный»_ (усиление 0,8–1,0 · мертвая зона 0 · интервал 1000 мс · мертвая зона записи 0 — диапазон ±10–20 Вт, стабилизация за 1–3 с). В течение суток оба профиля дают практически одинаковый энергетический баланс — разница заключается в визуальном оформлении графика, а не в стоимости.

## Правила оформления вывесок

- `GP` (энергия из сети):`>0` = подача,`<0` = рисовать — **в противоположность метру Шелли** (`api.GP ≈ −shelly.gridPower` ).
- `BP` (питание от батареи):`>0` = зарядка,`<0` = разрядка.
- `GS` (заданное значение сетки):`>0` = подача/выгрузка,`<0` = зарядка от сети (±2400 Вт на модели Pro, разрешение 1 Вт).

## Дерево объектов

Каждая голова получает собственное поддерево под собой.**`heads.<n>.*`** (`n` = 1…3), плюс объединенны&#x435;**`total.*`** агрегаты и уровень адаптера`controller.*` /`info.*` Внутри головного узла состояния группируются в тематические каналы; **лист каждого идентификатора объекта представляет собой код поля API устройства** (идентификатор сущности из официального справочника полей), а двуязычное имя объекта описывает его — таким образом, дерево соответствует документированным полям устройства в соотношении 1:1.

| Канал                 | Содержание                                                                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `heads.<n>.battery.*` | SoC (`SC` ), питание от батареи (`BP` ), SoC на упаковку (`SC0` –`SC5` ), онлайн-пакеты (`ON` ), гистерезис SoC (`SI1` /`SA1` )                                                       |
| `heads.<n>.grid.*`    | электроэнергия из сети (`GP` ), суточная энергия зарядки/подачи в сеть (`GD1` /`GD2` )                                                                                                |

## Поля ручного управления счетчиком/режимом (MM/MD)

`MM` /`MD` Это показатели собственного потребления, измеряемые самим устройством. При выборе **режима управления** адаптер управляет ими автоматически (режим A устанавливает`MM=1` +`MD` на одной головке; режим B принуждения`MM=0` на каждой голове), и его защита подтверждает соответствие режима.`MM` на следующем опросе — поэтому любые изменения, внесенные вручную в режиме управления, носят временный характер.

Исходные поля остаются доступными для записи при использовании экспертами/вручную (например, в _выключенном_ режиме). Они соответствуют официальной схеме подключения: поворот`MM` также очищает`MD` и писательство`MD` включает`MM` (непустое значение) или отключает его (пустое значение).`MD` JSON-форматы для четырех поддерживаемых счетчиков находятся в локальной справочной информации API устройства; в режиме _саморегулирования устройства_ адаптер формирует их автоматически на основе типа счетчика и серийного номера/IP-адреса.

## Ограничения

- **До трех головок на один экземпляр.** Работа с одной головкой проверена на реальном оборудовании; разделение на несколько головок проверено модульными тестами, но на момент написания статьи **не тестировалось на реальной установке с 2–3 головками** — отзывы от пользователей, использующих многоголовочные системы, приветствуются. _Саморегулирование устройства_ доступно только для одной головки.
- **Электростанции должны быть подключены к разным фазам** (ответственность оператора). Адаптер регулирует **суммарную** мощность сети, а не мощность каждой фазы отдельно.
- Балансировка каждого блока осуществляется собственной системой управления батареей (BMS) каждой головки — адаптер управляет только общей мощностью головки и считывает показания.`battery.SC` (Итого) для контроля; не управляет отдельными упаковками.
- Ежедневные счетчики энергии (`PD` /`GD1` /`GD2` /`LD` ) — это необработанные **Вт·ч** , а не кВт·ч.`PD` требуется прошивка модуля управления`ES 1.1.14` (продается под названием "1.1.4" — публичная нумерация отличается от внутренней)`ES` Более старые версии прошивки просто опускают это поле, и состояние остается пустым.
- Ежедневные счетчики обнуляются устройством при перезагрузке, поэтому обновление прошивки в середине дня возвращает их к нулю.
- `MD` и`TZ` Вступают в силу немедленно, но нет гарантии, что устройство отобразит их в точности — подтвердите по эффекту, а не по повторному отображению.
- **Входы фотоэлектрических модулей не тестировались с оборудованием** (эталонная установка работает без фотоэлектрических модулей, поэтому...).`PV1–4` всегда равны 0). Интеграция и контроллер не зависят от типа фотоэлектрической системы и являются полными, но могут возникать особые ситуации, связанные с прошивкой фотоэлектрической системы (например, полная зарядка батареи + избыток энергии от фотоэлектрической системы, поля ИБП/байпаса).`FP` /`UG` ) не проверены — отзывы приветствуются.

## Поиск неисправностей

- **`info.connection`пребывание`false` / Нет данных:** сначала убедитесь, что **используется локальный режим (`LM=1` Функция** включена на устройстве — без нее локальный API не возвращает никаких значений. Затем убедитесь, что она включена.`http://<device-ip>/read` доступен с хоста ioBroker (проверьте с помощью браузера или`curl` ). На человека,`heads.<n>.info.online` и`heads.<n>.info.lastError` Укажите, какой из них не сработал.
- **Ничего не контролируется:** проверьте **режим управления** — _«Выкл.»_ никогда не записывает данные. В _контроллере адаптера_ установите допустимое **состояние источника питания от сети** ; в разделе _«Саморегулирование устройства»_ установите поддерживаемый **тип счетчика** и **серийный номер/IP-адрес** .
- **Устройство игнорирует`GS` Батарея не реагирует:** головка только выполняет записанный код.`GS` когда`MM=0` В режиме _контроллера адаптера_ это обеспечивается автоматически; если вы напишете`GS` Вручную убедитесь, что ни один счетчик не привязан (`MM=0` ). С ограничением по метру (`MM=1` Устройство саморегулируется и игнорирует`GS` .
- **Контроллер работает слишком медленно / никогда не достигает точно 0:** см. _Поведение управления, точность и ограничения_ — измерительная цепочка добавляет задержку примерно в 1–3 секунды, а сам измеритель имеет конечную точность, поэтому физическим оптимумом является диапазон ±10–20 Вт вокруг целевого значения. Для максимально быстрой реакции используйте профиль _«Точность»_ (усиление 0,8–1,0, мертвая зона 0, минимальный интервал записи 1000 мс); чтобы никогда не подавать сигнал на вход, установите **мощность целевой сети** на небольшое положительное значение.
- **Временные метки состояний выглядят устаревшими / флаг качества 32:** адаптер записывает состояние только тогда, когда изменяется его значение (стандартная практика — это защищает базу данных состояний от миллионов одинаковых записей). Поэтому временная метка состояния показывает последнее _изменение_ значения, а не последний опрос. Проверьте актуальность данных с помощью`info.lastUpdate` (обновляется после каждого успешного опроса) и`heads.<n>.info.online` Качество 32 («замена исходного значения») сохраняется только в тех состояниях, в которых устройство никогда не выдает значения (например, SoC модулей расширения, которые не установлены); после каждого запуска адаптера все выданные значения записываются один раз, поэтому их метки времени как минимум такие же актуальные, как и при запуске.
- **Два контроллера борются за батарею:** используйте только один. Адаптер это контролирует.`MM` Для выбранного режима — отключите все внешние устройства.`GS` скрипт (или собственный скрипт устройства)`MM` (с другим измерительным прибором) перед использованием режима управления.
- **Некоторые штаты остаются пустыми (`0` /`""` ):** устройство возвращает только те поля, которые фактически предоставляет его прошивка/топология (например, дополнительные пакеты).`SC2` –`SC5` или только при возникновении ошибки (или при использовании битовых масок ошибок). Полный необработанный ответ всегда доступен в`heads.<n>.info.rawResponse` .
- **После обновления с одноголовочной версии дерево выглядит неправильно:** структура дерева объектов была изменена следующим образом:`heads.<n>.*` В версии 0.2.0 адаптер автоматически удаляет устаревшие объекты при запуске; если что-то осталось, удаляет старые объекты (или повторно добавляет экземпляр).
- **Устройства периодически отключаются / происходит таймаут пинга:** модуль Wi-Fi устройства работает слабо, а при установке нескольких устройств друг на друга металлический корпус оказывается прямо над антенной. Проверено.`heads.<n>.device.network.WR` (Уровень сигнала в дБ) — ниже −75 дБ связь становится ненадежной. Разделите установленные блоки и увеличьте **интервал опроса** до 10–15 с (качество управления практически не страдает: контроллер реагирует на источник питания сети, а не на этот опрос). Чтобы исключить адаптер, остановите экземпляр и пингуйте головной блок в течение нескольких минут — если обрывы связи продолжаются, причина не в опросе. Сам адаптер отправляет один пинг.`/read` для каждого источника и с заданным интервалом, задействует несколько источников поочередно, закрывает каждое соединение после использования и автоматически отключается после неудачных опросов.
