# Документация для разработчиков по ioBroker.tractive-gps

Этот документ предназначен для участников проекта. Информация об установке, настройке, состояниях и использовании виджетов описана в основном [файле README](/#/adapters/tractive-gps) и [немецком файле README](/#/docs/adapterref/iobroker.tractive-gps/README_DE.md) .

## Требования к разработке

- Node.js 22.13 или более поздняя версия
- npm 10 или новее
- Для локального интеграционного тестирования требуется js-controller версии 7.2.2 или новее.
- Администратор 7.8.23 или более поздняя версия
- Для тестирования виджетов требуется VIS 2 версии 2.12.8 или новее.

Установите все зависимости рабочей области из корневого каталога репозитория:

```bash
npm install
```

## жизненный цикл адаптера

При запуске адаптер создает объекты жизненного цикла, проходит аутентификацию в Tractive, выполняет полную синхронизацию, подписывается на состояния команд обновления и отслеживания и планирует следующую плановую синхронизацию.

Синхронизация выполняется последовательно. Новый запрос, отправленный во время выполнения синхронизации, ставится в очередь, вместо того чтобы запускать перекрывающийся цикл синхронизации.

График синхронизации разделен по типам данных:

- Для отображения списков трекеров и их позиций используется заданный интервал опроса.
- Отчеты об аппаратном обеспечении и состоянии батарей составляются с 15-минутным интервалом.
- Профили питомцев, изображения, данные отслеживания и информация о местонахождении животных синхронизируются ежедневно в полном объеме.

## Клиент Tractive API

`src/lib/tractive-api.ts` Обладает полным доступом по протоколу HTTP. Важные правила:

- Учетные данные для аутентификации отправляются только в теле запроса на вход в систему.
- Токены доступа хранятся в памяти.
- Использование единого общего обещания обновления предотвращает одновременное обновление аутентификации.
- После HTTP-запроса с ошибкой 401 он повторяется еще раз.
- Запросы обрабатываются последовательно и с интервалами перед отправкой.
- Код ошибки HTTP 429 приводит к общеучетной задержке и адаптивной задержке запроса.
- `Retry-After` принимается значение в секундах или в формате HTTP-даты.
- В журналах ни в коем случае нельзя указывать URL-адреса запросов, учетные данные, токены, полезную нагрузку, полные ответы или координаты.
- Внешние значения проверяются до того, как они выйдут за пределы допустимых значений API.

Интерфейс Tractive является неофициальным и может изменяться без предварительного уведомления. Изменения в конечных точках требуют тестирования с использованием проверенных тестовых наборов данных.

## Реквизиты для входа

Административное приложение использует`AdminConnection` от`@iobroker/socket-client` Обычная кнопка «Сохранить» в ioBroker обращается к серверной части.`encrypt()` Этот метод позволяет записывать пароли в формате конфигурации AES, используемом в ioBroker.

`io-package.json` указывает пароль в обоих случаях`encryptedNative` и`protectedNative` Адаптер получает расшифрованное значение от js-контроллера во время выполнения.

Не добавляйте отдельную кнопку сохранения учетных данных и не сохраняйте токены доступа.

## Объектная модель

Общедоступная стабильная объектная модель состоит из:

- `info.*` для получения информации о жизненном цикле и синхронизации,
- `pets.<pet-id>.info.*` для нормализованных данных о домашних животных,
- `trackers.<tracker-id>.*` для нормализованных данных о трекере, местоположении, состоянии здоровья и командах,
- `api.data.*` и`info.currentApi` для очищенного зеркала API.

Зеркало API должно удалить учетные данные, адреса электронной почты, токены доступа и обновления, поля авторизации, идентификаторы пользователей и идентификаторы пользователей поблизости. Массивы хранятся в виде строк JSON. Существующие объекты трекера сохраняются и помечаются как отсутствующие, а не удаляются.

## Команды трекера

Состояния команд создаются только для возможностей, сообщаемых трекером. Команды для одного и того же трекера выполняются последовательно. Подтверждение состояния происходит только после успешного выполнения запроса Tractive.

## Административный интерфейс

Приложение Admin 8 находится в`src-admin/` и использует React, TypeScript, Material UI.`@iobroker/gui-components` , и`AdminConnection` .

Конфигурация сохраняется исключительно с помощью стандартного процесса сохранения ioBroker. Переводы необходимо обновить для каждой локали.`src-admin/src/i18n/` и перестроен в`admin/i18n/` .

## Виджеты VIS

Исходный код виджета находится в`src-widgets/` .`PetTrackerCard` Использует API компонентов VIS 2 и Leaflet/OpenStreetMap.

Классическая реализация VIS 1 регистрируется через`widgets/tractive-gps.html` как того требует VIS 1. Его исходные ресурсы находятся в`src-widgets/public/vis1/` ; Vite копирует их в`widgets/tractive-gps/vis1/` Наряду со сборкой VIS 2. Она использует EJS из VIS 1 и`vis.binds` API. Файлы Leaflet, предоставленные поставщиком, должны оставаться синхронизированными с API.`leaflet` версия в`src-widgets/package.json` .

Изменения в виджете должны сохранять:

- автоматическое изменение цветовой гаммы светлой и темной тем.
- Резервный вариант: образ API и пользовательский образ ioBroker.
- безопасный`_PRJ_NAME` Обработка пути к изображению,
- Настраиваемое взаимодействие с картой и ограничения масштабирования.
- автоматическое определение заданного или указанного радиуса.
- Очистка экземпляров Leaflet и обработчиков событий.

## Процесс выпуска

В корневом пакете адаптера, а также в частных рабочих областях Admin и VIS используется фиксированное версионирование Lerna. Сохраняйте версии в`package.json` ,`src-admin/package.json` ,`src-widgets/package.json` ,`io-package.json` , и`lerna.json` синхронизировано.

Документы на выпуск должны быть подготовлены на основе чистых и актуальных данных.`main` Ветвь. Сначала выполните пробный запуск с соответствующим повышением семантической версии:

```bash
npm run release -- major --dryRun --noPush --yes
```

Использовать`major` для внесения существенных изменений,`minor` для функций обратной совместимости, и`patch` для исправления ошибок, обеспечивающих обратную совместимость. После просмотра результатов пробного запуска выполните ту же команду без`--dryRun` и`--noPush` Скрипт выпуска обновляет список изменений и новости ioBroker, собирает проект, создает коммит релиза и аннотированный тег, а затем отправляет их. После этого тег запускает рабочий процесс доверенной публикации.
