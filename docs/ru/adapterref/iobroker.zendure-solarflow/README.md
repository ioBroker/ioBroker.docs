# ioBroker.zendure-solarflow

## Sentry

**Этот адаптер использует библиотеки Sentry для автоматического сообщения разработчикам об исключениях и ошибках в коде.** Более подробную информацию, а также инструкции по отключению отправки сообщений об ошибках см. [в документации Sentry-Plugin](https://github.com/ioBroker/plugin-sentry#plugin-sentry) ! Система отчетности Sentry используется начиная с js-controller 3.0.

## Адаптер Zendure Solarflow для ioBroker

Адаптер ioBroker для чтения и управления устройствами Zendure Solarflow через API Zendure Cloud, а также локально через zenSDK (HTTP) или MQTT для устаревших устройств.

## Функции

- Полная телеметрия с ваших устройств Solarflow, включая значения, не отображаемые в официальном приложении (например, напряжение батареи).
- Управляйте устройствами так же, как и официальным приложением — большинство настроек доступны.
- Установите ограничения на вход/выход для сценариев с нулевым входным напряжением без Shelly Pro EM или создавайте более сложные автоматизации с помощью скриптов/Blockly.
- Защита батареи: отключение подачи питания при низком напряжении батареи (требуется установка ограничения выходного напряжения через адаптер).
- Управляйте несколькими устройствами Solarflow одновременно с более точными расчетами.
- Встроенная система автоматизации без потери электроэнергии (управляемая по ПИ-регулятору, распределение мощности между несколькими устройствами с учетом уровня заряда батареи), работающая от сетевого счетчика.
- Совместимо со всеми устройствами Zendure Solarflow.
- **zenSDK** : локальное управление HTTP для совместимых устройств, при этом данные по-прежнему передаются в облако Zendure, поэтому вы сохраняете полный контроль, даже если интернет/серверы Zendure недоступны.

## Режимы

- **Аутентификация с помощью Cloud Key** (рекомендуется): официальный метод Zendure. Получите Cloud Key из приложения. По умолчанию для совместимых устройств в той же сети, что и ioBroker, используется zenSDK, что обеспечивает полный локальный контроль при одновременной передаче данных в облако. Также возможна аутентификация только через облако. Устаревшие устройства, уже подключенные к локальному MQTT-серверу, также могут передавать данные в облако без каких-либо недостатков.
- **Локальный режим** : только локальный режим. Направьте адаптер на локальный MQTT-сервер для устаревших устройств (см. ниже); устройства zenSDK обнаруживаются через mDNS.
- **Только zenSDK (mDNS / IP)** : нет облачной платформы Zendure и вообще нет MQTT-сервера. Устройства обнаруживаются с помощью [обнаружения mDNS](#mdns-discovery) или [настраиваются по IP-адресу](#zensdk-devices-by-ip-address) и опрашиваются/управляются локально только через zenSDK, поэтому поддерживаются только устройства, совместимые с zenSDK.

### Обнаружение мДНС

При включении zenSDK адаптер просматривает сеть через mDNS/Bonjour в поисках устройств, объявляющих себя как `Zendure-<model>-<serialNumber>` Пока он работает. Сеть запрашивается повторно через 5, 15, 30 и 60 секунд, а затем каждые 5 минут, поэтому устройства, подключенные к сети позже (или пропущенные при предыдущем запросе), по-прежнему обнаруживаются без перезапуска адаптера. Это заполняет или исправляет IP-адреса для известных облачных устройств и автоматически создает аксессуары (серия Mix, интеллектуальные счетчики), у которых нет облачного ключа продукта и которые невозможно создать иным способом. Устройства сопоставляются по полному серийному номеру, а не по IP-адресу или сокращенному суффиксу. Отключить можно с помощью параметра «Добавить устройства, найденные с помощью обнаружения mDNS».

### устройства zenSDK по IP-адресу

mDNS использует многоадресную рассылку, которая обычно не маршрутизируется между сегментами сети. Если ваши устройства Zendure находятся в другой VLAN/подсети, отличной от ioBroker, введите их IP-адреса (или имена хостов) в разделе «Устройства zenSDK по IP-адресу» в настройках адаптера. Адаптер запрашивает каждый адрес через zenSDK. `http://<ip>/properties/report`) при запуске, а затем каждые 5 минут, идентифицирует устройство по сообщаемому серийному номеру: устройство, уже известное (например, из списка устройств облака Zendure), сохраняет свои существующие состояния и переключается на локальное управление zenSDK; создается неизвестное устройство с его серийным номером в качестве ключа, как и устройство, найденное через mDNS. Работает во всех режимах подключения, пока включен zenSDK. Присвойте устройствам фиксированный IP-адрес (резервирование DHCP) и убедитесь, что ioBroker может связаться с ними через TCP-порт 80.

## Поддерживаемые устройства

### Устройства, совместимые с zenSDK ✅ (полное локальное управление через HTTP)

> **Zendure рекомендует** использовать режим аутентификации Cloud Key, описанный выше — он обеспечивает полный локальный контроль, сохраняя при этом подключение к облаку для удобства. Нет необходимости отключать эти устройства от облака.

- Solarflow 1600 AC Plus, 2400 AC, 2400 AC Plus, 2400 Pro, 800, 800 Plus, 800 Pro, 3000 Mix AC+
- Solarflow 4000 Mix AC+, 4000 Mix Pro _(облачный ключ продукта пока недоступен — добавлен только через [обнаружение mDNS](#mdns-discovery) )_

### Аксессуары для умных счетчиков 📊 (только для чтения, только для zenSDK/mDNS)

- **Интеллектуальный счетчик 1CT** — однофазное электропитание через один трансформатор тока.
- **Интеллектуальный счетчик 3CT** — полная мощность на фазу (A/B/C) и общая мощность, передаваемая через трансформаторы тока.
- **«Умный» счетчик D0** — отображение показаний счетчика коммунальных услуг в режиме реального времени через оптический интерфейс IEC 62056-21.

### Устаревшие устройства 🔄 (локальный режим MQTT через Zendure Cloud Disconnector)

- HUB 1200, HUB 2000, Hyper 2000, AIO 2400, ACE 1500 — все они поддерживают локальный режим и могут передавать данные в облако.

**Преимущества локального режима:** данные не отправляются на серверы Zendure (рекомендуется отправлять их через ретранслятор), прямая/более быстрая связь по протоколу MQTT, полная автоматизация в автономном режиме, а также возможность повторного включения облачного ретранслятора в любое время. Обновления прошивки через официальное приложение/Bluetooth по-прежнему работают.

## Автономный режим (отключение от Zendure Cloud) для устаревших устройств

⚠️ **Предупреждение о гарантии:** Изменение MQTT-сервера непосредственно на устройстве (с помощью инструментов Bluetooth или перенаправления DNS) официально не поддерживается и **аннулирует гарантию на ваше устройство** . Действуйте на свой страх и риск.

Чтобы отключить устаревшее устройство от облака, используйте [Solarflow Bluetooth Manager](https://github.com/reinhard-brandstaedter/solarflow-bt-manager) от Райнхарда Брандштеттера или мой [Zendure Cloud Disconnector](https://github.com/nograx/zendure-cloud-disconnector) — оба инструмента устанавливают MQTT-адрес устройства через Bluetooth. В качестве альтернативы, перенаправьте DNS-запросы для "mq.zen-iot.com" на ваш собственный MQTT-сервер через маршрутизатор.

**Примечание:** эти инструменты Bluetooth работают только с **устаревшими устройствами** . Для устройств **zenSDK** используйте официальный автономный метод Zendure.

Оба инструмента принудительно используют порт MQTT по умолчанию (1883 или 8883 с SSL) и требуют отключения аутентификации на вашем сервере, поскольку устройство использует жестко закодированный пароль. Вы можете использовать это в сочетании с ключом облачной аутентификации или в полностью локальном режиме.

## Важный

Для управления зарядкой/подачей электроэнергии через скрипт или Blockly используйте...** `setDeviceAutomationInOutLimit` ** Параметр управления — управляет устройством без записи во флэш-память. Отрицательные значения запускают зарядку от сети.

## Автоматизация адаптера (управление с нулевым входным сигналом)

Адаптер включает в себя встроенный контроллер нулевого уровня подачи электроэнергии. Он считывает показания вашего сетевого счетчика и непрерывно регулирует подачу электроэнергии. `setDeviceAutomationInOutLimit` для всех участвующих устройств, чтобы мощность сети оставалась близкой к настраиваемой заданной точке — внешний скрипт не требуется. Работает как с одним устройством, так и с группой из нескольких устройств.

### Настраивать

1. Откройте настройки адаптера, раздел **«Автоматизация»** и установите флажок **«Включить автоматизацию адаптера»** .
2. Выберите **состояние триггера** : состояние вашей сети/умного счетчика с указанием текущей мощности сети в Вт ( **положительное значение = импорт из сети, отрицательное = экспорт в сеть** ). Каждое изменение значения этого состояния запускает один цикл управления, поэтому оно должно обновляться часто (идеально — каждые 1-5 секунд).
3. Сохраните — адаптер перезагрузится и создаст файл. `adapterAutomation` штатов.
4. Включите автоматизацию для каждого устройства, которое необходимо контролировать: `<productKey>.<deviceKey>.adapterAutomation.automationEnabled = true`.
5. Включите глобальный переключатель `adapterAutomation.automationEnabled = true`.

⚠️ Пока для устройства активна автоматизация, не пишите. `setDeviceAutomationInOutLimit` Если вы используете собственные скрипты для этого устройства, автоматизация перезапишет их. Устройства с `automationEnabled = false` остаются совершенно нетронутыми.

| `120` /`121` | В режиме ожидания выполняется калибровка уровня заряда батареи (SOC) `socStatus` это 1)                    |

### Как это работает

- **ПИ-регулятор:** требуемая выходная мощность рассчитывается исходя из текущего потребления электроэнергии в доме (мощность сети + текущая выходная мощность) плюс ПИ-коррекция в сторону заданного значения. В пределах небольшой мертвой зоны (от заданного значения до заданного значения + 10 Вт) ничего не изменяется, чтобы избежать постоянных корректировок.
- **Распределение мощности:** необходимая мощность распределяется между активными устройствами в зависимости от их уровня заряда батареи (SOC) — устройства с более высоким уровнем заряда батареи получают большую долю. Устройства с более низким уровнем заряда батареи получают большую долю мощности. `minSoc` Не получают никакой доли. Энергия, которую устройство не может обеспечить (превышая свой максимальный запас), передается устройствам, имеющим запас мощности.
- **Ведущее устройство:** Устройства ранжируются по уровню заряда батареи (SOC) и потреблению солнечной энергии (пересортировка производится каждый час). Ведущее устройство всегда активно; дополнительные устройства добавляются при увеличении спроса (при загрузке активных устройств более 70%) или когда они почти полностью загружены. После добавления устройства остаются активными не менее 5 минут, чтобы избежать нестабильности. Неактивные устройства несколько минут находятся в режиме ожидания с потреблением 10 Вт, чтобы быстрее реагировать.
- **Защита батареи:** `suggestedInverseMaxPower` Ограничение выходной мощности при низком уровне заряда/низком напряжении элементов (например, всего 60-500 Вт при слабых элементах, опционально для каждого аккумуляторного блока) через `suggestedInverseMaxPowerPerPack`) а ночью (0-5 ч) предел определяется уровнем заряда батареи (SOC). Он никогда не превышает значение, установленное устройством. `inverseMaxPower`.
- **Устройства, работающие только от сети переменного тока** (например, SF 2400 AC, SF 1600 AC+, SF 3000/4000 Mix AC+), менее предпочтительны в качестве ведущего устройства, когда уровень заряда других батарей превышает 35%. Когда сетевой счетчик показывает избыток (как минимум, экспорт), `surplusChargeTrigger` Вт сверх заданного значения, по умолчанию 100 Вт, непрерывно в течение 30 секунд), неактивные устройства, работающие только от сети переменного тока (и устройства с `acChargingAllowed`) зарядить этим излишком, в пределах своих `chargeMaxLimit` (Мощность в Вт).
- **Распределение заряда:** Избыток распределяется таким образом, что общая мощность зарядки каждого устройства (переменный ток плюс собственный солнечный ток) взвешивается с учетом недостающего уровня заряда батареи и ее емкости — устройство, которое уже получает собственный солнечный ток, получает меньше переменного тока, остальное идет на остальные. Емкость определяется подключенными аккумуляторными батареями (используется только в том случае, если она известна для всех заряжаемых устройств). Для Hyper 2000 мощность зарядки переменным током также ограничена общей мощностью зарядки батарей (переменный ток + солнечный ток) в его конфигурации: 950 Вт с одной батареей AB1000, 1200 Вт с одной батареей AB2000, 1600 Вт с двумя или более батареями.
- **Безопасность зарядки:** устройство переключается в режим зарядки только после того, как оно находилось в режиме ожидания с мощностью 0 Вт в течение как минимум... `minIdleBeforeCharge` секунд (по умолчанию 60), чтобы устройство не переключалось напрямую между разрядкой и зарядкой. Пока подтверждается наличие избытка, устройство, ожидающее в режиме ожидания подачи питания, освобождается через `minIdleBeforeCharge` вместо 3 минут, чтобы можно было начать зарядку.
- **Управление зарядом:** Мощность заряда рассчитывается непосредственно из значения в сети без учета собственной (сообщаемой) мощности заряда устройств, поэтому она достигает избытка за один или два шага. После каждого изменения она удерживается до тех пор, пока устройства не достигнут и не сообщат о своей новой мощности заряда (10-30 с); чистый импорт в сеть (более 300 Вт) немедленно снижает ее.

## Примечания

Этот адаптер выполняет аутентификацию на официальных серверах MQTT с помощью кода авторизации облака, который можно сгенерировать в приложении Zendure.

### Sentry (отчеты об ошибках и статистика устройств)

Этот адаптер использует библиотеки Sentry для автоматического сообщения разработчику об исключениях и ошибках в коде. Кроме того, адаптер отправляет анонимную статистику устройств через 5 минут после запуска, а затем один раз в 24 часа: одно событие для каждого используемого класса устройств, содержащее только класс устройства, ключ продукта, название продукта и режим подключения. Ключи устройств, серийные номера, IP-адреса или учетные данные не передаются. Эта статистика помогает определить, какие устройства используются и где отсутствует поддержка.

Более подробную информацию, а также сведения о том, как отключить отчеты об ошибках, см. [в документации Sentry-Plugin](https://github.com/ioBroker/plugin-sentry#plugin-sentry) . Система отчетности Sentry используется начиная с js-controller 3.0.
