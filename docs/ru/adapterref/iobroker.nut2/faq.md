# Часто задаваемые вопросы

## В журнале указано, что мои учетные данные были отклонены, но при этом состояние экземпляра отображается зеленым цветом, а значения актуальны. Что происходит?

Оба варианта не противоречат друг другу.

Для чтения значений ИБП в NUT не требуется авторизация. Авторизация — это отдельный шаг, который адаптер выполняет при кратковременном вторичном соединении каждый раз при запуске (или переподключении) — исключительно для проверки действительности учетных данных. Если сервер их отклоняет, мониторинг продолжается без изменений; блокируется только переключение ИБП и запись переменной.

Состояние экземпляра остается "зеленым", потому что `info.connection` **Соединение с сервером NUT** установлено и обеспечивает передачу результатов. Вывод данных об оранжевом экземпляре вместе с новыми значениями был бы запутанным, а не честным ответом.

Обычно причиной является отсутствующая строка в `upsd.users` Для доступа к серверу требуется авторизация. `upsmon secondary` (или `upsmon primary`) для этого пользователя. Добавление этого параметра решит проблему. `upsd` ответы содержат неверный пароль и отсутствует `upsmon` — Строка с одинаковым отклонением, поэтому адаптер перечисляет обе возможности.

## Почему адаптер просто не остаётся зарегистрированным?

Потому что `upsd` Учитываются регистрации и первичные выборы. `upsmon` Этот счётчик используется во время отключения электроэнергии: перед выключением компьютера он ждёт, пока не останется других подключенных пользователей. Клиент мониторинга, постоянно подключенный к этому счётчику, задержит выключение и переключится на питание от батареи. Инструменты NUT, доступные только для чтения (`upsc`, `upscmd`, `upsrw` Они никогда не регистрируются по той же причине.

## Я хочу получать уведомления об отключении электроэнергии немедленно, а не при следующей проверке.

Не уменьшайте интервал опроса — в NUT нет функции отправки данных на сервер; более короткий интервал опроса просто означает более частый опрос. Компонент, который отслеживает события по мере их возникновения, это... `upsmon`, собственный клиент для видеонаблюдения от NUT. Он работает через `NOTIFYCMD` Выберите программу по своему усмотрению и передайте ей тип события и имя ИБП.

Эта программа нацелена на точку данных, доступную для записи. `nut2.0.notify` Для отображения этой информации разместите небольшой вспомогательный скрипт на сервере NUT — например, в таком виде: `/etc/nut/iobroker-notify.sh` — и сделать это осуществимым (`chmod +x`); `curl` его необходимо установить там:

```sh
#!/bin/sh
# Called by upsmon: the event is in $NOTIFYTYPE, the UPS in $UPSNAME.
curl -fsS "http://IOBROKER:8093/v1/state/nut2.0.notify?value=${NOTIFYTYPE}%20${UPSNAME}" > /dev/null
```

И в `upsmon.conf`:

```
NOTIFYCMD /etc/nut/iobroker-notify.sh
NOTIFYFLAG ONLINE   SYSLOG+EXEC
NOTIFYFLAG ONBATT   SYSLOG+EXEC
NOTIFYFLAG LOWBATT  SYSLOG+EXEC
NOTIFYFLAG FSD      SYSLOG+EXEC
NOTIFYFLAG SHUTDOWN SYSLOG+EXEC
NOTIFYFLAG REPLBATT SYSLOG+EXEC
```

Адрес обслуживается адаптером [REST API](https://github.com/ioBroker/ioBroker.rest-api) (порт 8093). Скрипт работает с любой версией NUT: начиная с версии 2.8.5 и выше, он запускает... `upsmon` тот `NOTIFYCMD` Без использования командной оболочки переменные можно использовать напрямую. `upsmon.conf` В таком случае его уже не нужно будет заменять. Со старым адаптером `simple-api` Адрес: `http://IOBROKER:8087/set/nut2.0.notify?value=…` (8087 при автономной работе, 8082 в веб-адаптере).

Каждая операция записи на `nut2.0.notify` Это запускает немедленный запрос ко всем ИБП; пустое значение просто указывает на ручное обновление. Если имя ИБП совпадает с именем обнаруженного устройства, событие также регистрируется в его конфигурации. `info.notify` Это позволяет скрипту реагировать на каждый ИБП, например, на `SHUTDOWN`.

Событие намеренно регистрируется **до** выполнения запроса: в случае выключения компьютер NUT может выйти из строя в середине выполнения запроса.

## канал `commands` Оно не отображается, хотя я включил команды.

Для выполнения команд требуются учетные данные для входа. `upsd` проверяет права доступа к командам (`instcmds`) по отношению к указанному пользователю — без имени пользователя и пароля проверять нечего, и ключи не создаются. Начиная с версии 0.14.0, адаптер сообщает об этом в журнале, вместо того чтобы молчать.

Если данные доступа сохранены, а канал по-прежнему отсутствует, драйвер ИБП не будет передавать никаких команд. `upscmd -l ups0` (указано на сервере) — ИБП без каких-либо команд не получает канал `commands` Клавиши для команд, которые драйвер больше не отображает, будут удалены.

## Как отправить команду, требующую ввода значения?

Владение и ценность в `commands.execute` писать, как `upscmd` она берет: `load.off.delay 120` или `beeper.enable` Действуют те же правила, что и для кнопок: **мгновенные команды должны быть включены** , данные доступа должны быть сохранены, и ИБП должен предлагать команду. Значение представляет собой одно слово (без пробелов). `#`, `=` (без кавычек и обратных косых черт).

## В журнале для одной из команд указано: "драйвер еще не подтвердил это".

Если сервер NUT отслеживает команды (начиная с NUT 2.8.0), адаптер запрашивает у драйвера информацию о том, выполнил ли он команду или изменил какие-либо настройки. Эта строка указывает на то, что сервер принял команду, но драйвер не ответил в течение периода ожидания команды — в этом случае следует проверить сам ИБП. Если драйвер сообщает об ошибке, вместо этого будет отображена строка с ошибкой.

## Значение, содержащее символ "#", не будет записано.

NUT не может передать это обратно: драйвер сообщает новое значение, не выходя за пределы... `#` На сервер NUT это сообщение отправляется, но сервер его игнорирует — он продолжает отображать старое значение, как и любой другой клиент NUT. Это основано на NUT 2.8.5; текущая версия NUT для разработки отправляет данные таким же образом. Поэтому адаптер не отправляет такое значение, регистрирует его в журнале и снова отображает значение, полученное от сервера. Значения с `#` Чтение помогает.

## Я переименовал точку данных в дереве объектов, и имя было возвращено.

Это сделано намеренно. Название и описание точек данных принадлежат адаптеру, как и их тип и роль, и обновление драйвера или адаптера должно позволять их исправлять. Предусмотрена возможность присвоения пользовательских имен. `0_userdata` или псевдоним.

Исключением являются ваши настройки записи, а также назначения помещений и функций — они принадлежат вам, никогда не перезаписываются и даже переносятся, когда адаптер переименовывает свою собственную точку данных.

## Источник бесперебойного питания (ИБП) исчез из дерева объектов.

Адаптер повторно считывает список ИБП при каждом запросе. Если сервер NUT больше не сообщает об ИБП, его объекты удаляются после трех запросов без его присутствия (сразу после запуска адаптера); если же он возвращается, они создаются заново. Таким образом, добавленный или удаленный с сервера ИБП отображается без перезапуска адаптера.

## Проверка соединения выдает ошибку TLS, хотя у меня включен TLS.

В этом случае рукопожатие не состоялось — при включенном TLS адаптер никогда не переключается на незашифрованное соединение. Обычные причины: сервер NUT был собран без поддержки TLS или она отсутствует. `CERTFILE` /`CERTPATH` в `upsd.conf` В обоих случаях он отказывается. `upsd` тот `STARTTLS` И тест это подтверждает.

## Я создал файл CA, затем отключил строгую проверку — и адаптер загорелся желтым.

Это была ошибка, исправленная в версии 0.14.0. Теперь файл CA читается только в том случае, если включена опция **"Требовать действительный сертификат"** — если строгая проверка отключена, проверка сертификата не производится, поэтому файл не используется. Путь, оставшийся от предыдущей попытки, включается в журнал отладки при каждом подключении и игнорируется в противном случае.

## Какие значения я могу указать?

Все, что ваш водитель UPS сообщает как доступное для записи (`LIST RW`), как только **будет включена опция "Разрешить запись переменных"** . Типичные кандидаты: `ups.delay.shutdown`, `ups.delay.start` а также статус звукового сигнала. Если сервер дополнительно сообщает допустимые значения или диапазон, точка данных получает список выбора или минимальное/максимальное значение — в этом случае администратор не сможет предложить вам ничего, что ИБП отклонит.

Переменные типа «да/нет» хранятся как значения истинности, и при записи в них... `yes` /`no` переведено обратно в соответствии с требованиями протокола.

## Может ли один экземпляр обеспечивать работу нескольких систем бесперебойного питания?

Да — каждый ИБП, предоставляемый сервером NUT, становится отдельным устройством в рамках экземпляра и автоматически обнаруживается. Второй экземпляр необходим только для второго **сервера** NUT.

Имя источника бесперебойного питания (ИБП), которое ioBroker не может использовать в качестве идентификатора объекта (пробелы, точки), удаляется; фактическое имя продолжает использоваться в журнале. Если два имени имеют одинаковый идентификатор, ко второму добавляется число, и адаптер выдает предупреждение об этом.
