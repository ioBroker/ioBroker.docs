# ioBroker.agent-dvr

## адаптер agent-dvr для ioBroker

Подключает ioBroker к [AgentDVR](https://www.ispyconnect.com) : автоматически обнаруживает все камеры, отображает свойства каждого устройства в виде точек данных, предоставляет кнопки для всех распространенных команд (запись, постановка на охрану, PTZ и т. д.), обеспечивает обновление галереи при появлении новых записей, генерирует адаптивный HTML-виджет галереи для каждой камеры и включает встроенную панель мониторинга в реальном времени с выбором потока для каждой камеры (MJPEG, MP4/FLV со звуком или go2rtc WebRTC).

> Это интеграция, поддерживаемая сообществом, не связанная с iSpyConnect и не получающая от неё поддержки. Пожалуйста, сообщайте о проблемах через [трекер GitHub этого репозитория](https://github.com/ipod86/ioBroker.agent-dvr/issues) , а не через каналы поддержки iSpyConnect.

## Требования

- ioBroker с `iobroker.web` адаптер
- **AgentDVR ≥ 7.8.0.0** — в более ранних версиях наблюдается регрессия в `streamFile.cgi` Конечная точка (неправильно сформированная кодировка фрагментов, неверный MIME-тип), которая препятствует записи и воспроизведению во встроенной панели управления. Разработчик подтвердил, что исправление включено в версию 7.8.0.0.

## Основные моменты

### Виджеты (веб-компоненты) для AURA, vis-2, устройств и других средств визуализации.

Галерея записей, динамический блок и обзор в реальном времени также доступны в виде веб-компонентов. `@iobroker/web-components` AURA (0.106.0+, рекомендуется 0.112.0+), vis-2 (2.20.7+), адаптер устройств (4.3.0+) и любая другая визуализация, поддерживающая веб-компоненты, отображает их в своей палитре виджетов — привязка HTML не требуется. Они отображаются непосредственно в браузере, а не показывают точки данных HTML, поэтому обновление страницы никогда не закрывает открытый плеер.

- **Записи Agent DVR** — галерея записей с камеры с возможностью поиска и фильтрации по тегам, встроенным проигрывателем или URL-адресом внешнего проигрывателя.
- **Agent DVR** — прямая трансляция с одной камеры; снимок обновляется в браузере, щелчок открывает прямую трансляцию.
- **Обзор данных Agent DVR в режиме реального времени** — отображение всех камер экземпляра в реальном времени.
- **Источник** : либо _виджет из настроек адаптера_ (все настройки вкладки «Виджеты» экземпляра), либо _собственные настройки здесь_ — все настройки виджета экземпляра (режим, количество, размер миниатюры, теги, сортировка, поиск, тег по умолчанию, компактная компоновка, плеер, соотношение сторон, интервал обновления, цвета, радиус границы) для каждого виджета.
- При желании можно использовать цвета темы визуализации.
- Не требует учетных данных: изображения и видео используют те же ссылки AgentDVR, что и HTML-виджеты; данные поступают из `widget_config` и `<cam>.widget_data`

### Уведомления (камера отключена, обнаружен человек/животное/транспортное средство, новая запись)

- Отдельная вкладка **«Уведомления»** : каждый тип уведомлений можно включить отдельно — камера отключена, камера снова подключена, сервер Agent DVR отключен/подключен, обнаружение человека, животного, транспортного средства или чего-либо еще, новая запись — для каждой камеры можно выбрать нужный тип уведомления с помощью списка флажков.
- Уведомления поступают в систему уведомлений ioBroker (значок колокольчика в административной панели); адаптер **notification-manager** пересылает их, например, в Telegram или по электронной почте — в этом адаптере нет настроек мессенджера.
- Сообщение **об отключении камеры** появляется, когда камера, включенная в Agent DVR, не подключается в течение заданного времени (по умолчанию 10 минут). Без подключения нет изображения и обнаружения движения; кратковременные сбои, такие как перезагрузка камеры, не регистрируются.
- Новые точки данных для каждой камеры: `status.offlineSince` и `status.offlineAlarm` для ваших собственных скриптов и визуализаций

### Записи хранятся в файловом хранилище ioBroker и в виде видео в Telegram.

- **Отображать последние записи в файловом хранилище ioBroker** (по умолчанию отключено): каждая новая запись с камеры загружается из AgentDVR и сохраняется как `rec1` …`rec3` для каждой камеры — с указанием пути к файлу, `iobfile://` URI и http URL в `<cam>.recordings.*` точно так же, как и на тревожных фотографиях.
- При желании можно использовать формат **MP4** (ремукс без потерь качества с помощью ffmpeg, без перекодирования) — воспроизводится везде, а также в Telegram.
- ** `sendRecording` ** отправляет последнюю, сохраненную или любую другую запись напрямую в Telegram (или другой экземпляр) в виде видео;** `getRecording` ** делает его доступным в виде файла для ваших собственных скриптов.
- Подробности: [Записи в файловом хранилище.](#recordings-in-the-file-storage)

## Функции

- Автоматическое обнаружение всех камер AgentDVR при запуске (за исключением микрофонов).
- Все свойства устройства отображаются в виде точек данных (полученных из API в плоском виде).
- Кнопки управления для каждого устройства: запись, снимок, обнаружение, оповещения о постановке/снятии с охраны, включение/выключение, обнаружение объектов, включение/выключение по расписанию, включение/выключение детектора, чувствительность (мин/макс/усиление), сброс, …
- Кнопки системного уровня: постановка на охрану, снятие с охраны, включение/выключение всех устройств, перезагрузка, управление хранилищем, перезапуск, …
- **Селектор профиля** — выпадающий список, отображающий текущий профиль AgentDVR (Дома / Вне дома / Ночь / пользовательский).
- **Снимок в формате Base64** —`snapshot_b64` Состояние каждой камеры, заменяемое кнопкой или автоматически обновляемое при каждом цикле опроса.
- Управление поворотно-наклонной платформой с помощью кнопок, позволяющих удерживать кнопку для перемещения.
- URL-адреса потоковой передачи для каждой камеры (снимок, фото, MJPEG, MP4)
- Конечная точка веб-перехватчика для обновлений в реальном времени — вызовите ее из действия AgentDVR, чтобы немедленно запустить полный опрос.
- HTML-виджет галереи записей для каждой камеры (`widget_recordings`) и живой тайл с одной камеры (`widget_live` — чистый HTML/CSS или полнофункциональный JS-режим с поиском и фильтром по тегам.
- Виджет обзора, объединяющий все камеры в одном HTML-состоянии.
- **Встроенная панель мониторинга в режиме реального времени** по адресу `http://<iobroker>:<webport>/agent-dvr.0/` — Дополнительное приложение не требуется:
  - Выбор формата потока для каждой камеры: MJPEG, MP4/FLV со звуком или go2rtc WebRTC/MSE.
  - Кнопка фильтра камер в заголовке (значок воронки) — открывает всплывающее окно с флажками для каждой камеры; значок показывает, сколько камер скрыто; состояние сохраняется в localStorage.
  - Индикаторы движения и оповещения в реальном времени (желтая/оранжевая рамка плиток) через Socket.io
  - Полноэкранный режим с наложением PTZ-эффекта, записью, отключением звука и встроенной кнопкой полноэкранного режима браузера; заголовок автоматически скрывается.
  - Вкладка «Записи» с отображением в виде сетки, временной шкалы и журнала событий, поиском, сворачиваемым фильтром по тегам и видеоплеером с навигацией «Предыдущее/Следующее».
  - Удаление записи непосредственно из всплывающего окна видеоплеера (требуется AgentDVR версии 7.7.8.0 и выше).
  - Настройки отображения записей — значок шестеренки ⚙ на панели выбора/удаления регулирует ширину столбцов сетки, максимальное количество отображаемых записей и видимость значка (сохраняется в localStorage).
  - Цвета с камер считываются из AgentDVR и применяются к полосам временной шкалы и точкам записи.
  - Предустановки PTZ — перейдите к сохраненным предустановкам из окна PTZ (требуется AgentDVR версии 7.7.8.0 и выше)
  - В строке состояния отображается количество камер в режиме реального времени и количество записей/событий в режиме записи.
  - Автоматическое переподключение для всех типов потоков после прерывания сети или переключения вкладок.
  - Полностью настраиваемая цветовая гамма через конфигурацию адаптера.

**Распределение по потокам**

Здесь вы назначаете источник потока каждой камере по отдельности. В выпадающем списке отображаются все камеры, обнаруженные AgentDVR (микрофоны исключены).

| Вариант                          | Описание                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| MJPEG _(AgentDVR)_               | Классический MJPEG-поток, предоставляемый AgentDVR — минимальная задержка, без звука.                          |
| MP4 / FLV со звуком _(AgentDVR)_ | Поток FLV, передаваемый через ioBroker с использованием flv.js — включает звук, правильное соотношение сторон. |
| _Название потока_ _(go2rtc)_     | Потоковая передача WebRTC/MSE от go2rtc — плавная, с низкой задержкой, поддержка звука.                        |

Названия потоков go2rtc автоматически загружаются с сервера go2rtc при открытии административного интерфейса. Если браузер не может напрямую связаться с go2rtc (например, при передаче смешанного контента по HTTPS), адаптер загружает их на стороне сервера в качестве резервного варианта.

**URL-адрес go2rtc** _(виден только в том случае, если хотя бы одна камера использует поток go2rtc)_

| Параметр   | Описание                             | Пример                     |
| ---------- | ------------------------------------ | -------------------------- |
| URL go2rtc | Базовый URL вашего экземпляра go2rtc | `http://192.168.1.10:1984` |

> **Примечание:** go2rtc должен быть предварительно настроен для потоков. Адаптер только считывает список потоков и выступает в качестве прокси для WebSocket — он не настраивает go2rtc.

## Интерактивная панель мониторинга

В комплект адаптера входит встроенная панель мониторинга в режиме реального времени. `http://<iobroker>:<webport>/agent-dvr.0/` Второй экземпляр доступен по адресу: `/agent-dvr.1/` третий в `/agent-dvr.2/`, и так далее.

**Функции:**

- Выбор формата потока для каждой камеры: MJPEG, MP4/FLV со звуком (через flv.js) или go2rtc WebRTC/MSE.
- Кнопка фильтра камер (значок воронки, заголовок в правом верхнем углу) — открывает всплывающее окно с флажками для каждой камеры и переключателем «Все»; значок показывает количество скрытых камер; состояние сохраняется в localStorage.
- Полноэкранный режим с наложением PTZ-эффекта, кнопкой записи, кнопкой отключения звука и полноэкранным режимом браузера (заголовок автоматически скрывается через 3 секунды бездействия; появляется снова при нажатии мыши или касании).
- Индикаторы движения в реальном времени (желтая рамка) и оповещения (оранжевая рамка) через Socket.io
- Автоматическое переподключение: MJPEG и FLV переподключаются после ошибки; go2rtc переподключается после неожиданного закрытия WebSocket или задержки в 10 секунд.
- Вкладка «Записи» с отображением в виде сетки, временной шкалы и журнала событий, поиском, сворачиваемым фильтром по тегам и видеоплеером с навигацией «Предыдущее/Следующее».
- Фильтр тегов разделяет разделенные запятыми теги AgentDVR на отдельные чипы для фильтрации по каждому тегу.
- Удалить запись из всплывающего окна видеоплеера или выбрать несколько записей, удерживая кнопку мыши, и выполнить массовое удаление (требуется AgentDVR версии 7.7.8.0 и выше).
- Настройки отображения записи — кнопка с изображением шестеренки ⚙ на панели выбора/удаления; ползунок для ширины столбцов сетки, ограничения максимального количества записей и переключения значка — все сохраняется в localStorage.
- Значок «Новые записи» на вкладке «Записи» показывает, сколько записей появилось с момента вашего последнего посещения этой вкладки; базовое значение хранится в локальном хранилище браузера и является общим для каждого браузера/устройства (не используется разными браузерами или устройствами).
- Цвета с камер считываются из AgentDVR и применяются к полосам временной шкалы и точкам записи.
- Предустановки PTZ — переход к сохраненным предустановкам из окна PTZ; одна точка выбора данных для каждой камеры (требуется AgentDVR v7.7.8.0+)
- В строке состояния отображается количество камер, загрузка процессора/оперативной памяти и свободное место на диске.
- Цветовое оформление через конфигурацию адаптера

### go2rtc WebRTC Streams

[go2rtc](https://github.com/AlexxIT/go2rtc) обеспечивает плавную передачу аудиопотоков WebRTC/MSE с низкой задержкой.

**Настраивать:**

1. Установите и запустите go2rtc, настройте потоки с камер в конфигурационном файле go2rtc.
2. В разделе «Конфигурация адаптера» → вкладка _«Панель управления»_ выберите из выпадающего списка желаемое имя потока go2rtc для каждой камеры.
3. Введите **URL-адрес go2rtc** , который отображается под таблицей (например, `http://192.168.1.10:1984`).
4. Сохраните изменения и перезапустите. Адаптер перенаправляет трафик WebSocket через ioBroker, чтобы обойти ограничения на междоменные соединения браузеров.

## Медиа-прокси

Адаптер может направлять все медиафайлы через ioBroker, поэтому браузеру никогда не потребуется прямое подключение к AgentDVR. Включите **медиа-прокси** на вкладке «Функции».

| Что используется в качестве прокси? | Прокси отключен           | Прокси включен                 |
| ----------------------------------- | ------------------------- | ------------------------------ |
| Прямая трансляция в формате MJPEG   | прямой URL AgentDVR       | `/agent-dvr.0/api/mjpeg?oid=…` |
| Снимок                              | прямой URL AgentDVR       | `/agent-dvr.0/api/snap?oid=…`  |
| Миниатюры записей                   | прямой URL AgentDVR       | `/agent-dvr.0/api/thumb?oid=…` |
| Запись видео                        | прямой URL AgentDVR       | `/agent-dvr.0/api/media?oid=…` |
| Прямая трансляция FLV               | **всегда через ioBroker** | **всегда через ioBroker**      |
| go2rtc WebSocket                    | **всегда через ioBroker** | **всегда через ioBroker**      |

FLV и go2rtc всегда работают через ioBroker независимо от настроек — браузер не может напрямую отправлять запросы к этим конечным точкам из других источников.

### Когда включать

- Доступ к панели управления возможен извне вашей домашней сети, где AgentDVR недоступен напрямую из браузера.
- Извне доступен только ioBroker (например, через обратный прокси или VPN).

### Когда следует его выключить

- Browser и AgentDVR находятся в одной сети (локальный доступ).
- Прямое соединение быстрее — нет лишнего перехода, меньшая задержка.
- Меньшая нагрузка на сервер ioBroker — потоки не проходят через Node.js.

### Безопасность

Этот адаптер хранит ваши учетные данные администратора AgentDVR и предоставляет к ним доступ. `system.control.purge`, `system.control.restart` и `system.control.unblockExternal` В режиме записи одним щелчком мыши любой, кто может получить доступ к веб-порту ioBroker, может удалить записи, перезапустить AgentDVR или отключить блокировку внешнего доступа. **Убедитесь, что `iobroker.web` Перед тем как предоставлять доступ к ioBroker за пределы вашей локальной сети (напрямую или через обратный прокси), должна быть включена аутентификация** — во многих конфигурациях ioBroker это не является настройкой по умолчанию.

> Настройки вступают в силу немедленно после сохранения — перезапуск не требуется.

## Вебхук

Адаптер предоставляет конечную точку веб-перехватчика, которая запускает немедленный полный опрос AgentDVR:

```
GET http://<iobroker>:<webport>/agent-dvr.0/webhook
```

Заменять `agent-dvr.0` с фактическим номером экземпляра (`agent-dvr.1` (и т. д.), если вы запускаете несколько экземпляров.

Настройте этот URL-адрес в качестве **действия** в AgentDVR (Камера → Редактировать → Оповещения → Действия → URL), чтобы получать обновления в режиме реального времени всякий раз, когда запись заканчивается или срабатывает оповещение. Адаптер немедленно повторно получит все данные с камер, записи и системную статистику — не нужно ждать следующего цикла опроса.

Возвраты `{"ok":true}` об успехе.

### Быстрое оповещение с каждой камеры

Добавьте идентификатор камеры, чтобы адаптер знал, какая камера произвела снимок:

```
GET http://<iobroker>:<webport>/agent-dvr.0/webhook?oid={ID}&ot={OT}
```

`{ID}` и `{OT}` Это теги AgentDVR, которые заполняются программой AgentDVR. Затем адаптер подает импульсы. `<cam>.events.webhook` **Немедленно** — до получения каких-либо данных — и опрос после этого. Используйте действие при _обнаружении движения_ . При включенной функции фотооповещений фотография сохраняется сразу же — см. [раздел «Получение изображений для VIS и скриптов](#getting-images-for-vis-and-scripts) для соответствующего триггера». AgentDVR часто вызывает это действие несколько раз при каждом обнаружении движения; дальнейшие вызовы для той же камеры в течение 20 секунд только обновляют данные и не повторяют импульсы. `<cam>.events.webhookParams` содержит все параметры последнего вызова в формате JSON (плюс) `ts`), написанный до импульса, а также во время задержки — добавьте любые необходимые теги AgentDVR к URL (например) `&ai={AI}&zone={ZONE}&name={NAME}`) и оцените их в своем собственном скрипте.

Без `oid` Веб-хук запускает только полный опрос. Параметры запроса записываются в журнал веб-экземпляра на уровне отладки.

Используйте простой `http` В веб-версии при выполнении действия AgentDVR молча отклоняет самоподписанные сертификаты.

## Записи в файловом хранилище

При **включенной опции «Предоставлять последние записи в файловом хранилище ioBroker»** (вкладка _«Функции»_ , по умолчанию отключена) адаптер загружает каждую новую запись с камеры из AgentDVR, как только она появляется в списке записей (в момент записи). `<cam>.events.new` импульсы — поэтому _точки данных события_ должны быть включены) и сохраняет их в файловом хранилище ioBroker. Загрузка происходит в память, а не во временный файл. Как и в случае с фотографиями оповещений, сохраняются последние 1, 2 или 3 записи с каждой камеры (настройка _«Количество сохраненных записей на камеру»_ , по умолчанию 1):

| Точка данных                      | Содержание                                                                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `<cam>.recordings.file1` …`file3` | Абсолютный путь к файлу, например `/opt/iobroker/iobroker-data/files/agent-dvr.0/cam_8_Reolink/rec1.mp4` (`1` = самый новый)                  |
| `<cam>.recordings.uri1` …`uri3`   | URI файла ioBroker, например `iobfile://agent-dvr.0/cam_8_Reolink/rec1.mp4`                                                                   |
| `<cam>.recordings.url1` …`url3`   | URL-адрес http(s) через веб-экземпляр, например `http://192.168.1.10:8082/agent-dvr.0/recordings/cam_8_Reolink/rec1.mp4` (поддерживает поиск) |
| `<cam>.recordings.name1` …`name3` | Исходное имя файла AgentDVR, например `8_2026-11-12_15-55-29_931.mkv`                                                                         |
| `<cam>.recordings.ts1` …`ts3`     | Время записи                                                                                                                                 |

Файлы: `<namespace>/<cam>/rec1.mp4` (или `.mkv`) …`rec3` При каждой новой записи (rec1 → rec2 → rec3) самая старая удаляется. При уменьшении числа лишние файлы и точки данных удаляются при следующем запуске. Объем дискового пространства остается фиксированным: число × максимальный размер на камеру. Записи _размером больше максимального_ (по умолчанию 50 МБ) пропускаются с информационным логом. `ts1` Запись производится **в последнюю очередь** , после завершения работы над файлом — используйте её в качестве триггера.

**Ограничение по объему хранения:** `file1` –`file3` Путь к файлу отображается только в том случае, если файловое хранилище ioBroker находится на локальном диске (база данных объектов file/jsonl по умолчанию). В Redis или другой базе данных, не содержащей файловые объекты, путь остается пустым — используйте `uri*` (Телеграм 6+, скрипты) или `url*` Вместо этого, они работают с любым хранилищем.

### Что происходит, когда…

- **…опция включена:** при следующем запуске (сохранение настроек перезапускает экземпляр) каждая выбранная камера получает свою последнюю запись, если слот 1 пуст или содержит более старую запись — одна камера за другой, с ограничением по размеру. После этого каждая новая запись сохраняется по мере ее появления.
- **…выбирается новая камера:** как и в предыдущем случае, она сразу же получает свою последнюю текущую запись.
- **…в AgentDVR добавляется новая камера:** она отображается при следующем опросе (список камер в настройках считывается в режиме реального времени из запущенного экземпляра); при добавлении _всех камер_ она заполняется и сохраняется так же, как и остальные.
- **…камера отключается:** при следующем запуске ее `recordings` точки данных и их файлы `rec1` –`rec3` и `send.*` удалены.
- **…эта опция отключена:** при следующем запуске `recordings` точки данных и `rec*` /`send.*` Файлы всех камер удалены.
- **…камера удаляется из AgentDVR:** ее данные удаляются, как и прежде, а вся папка с данными остается в файловом хранилище (`agent-dvr.0/<cam>/` — записи, `send.*` Если AgentDVR внезапно сообщает об отсутствии камер, ничего не удаляется (предполагается, что это сбой).
- **…выбранная камера больше не существует:** в настройках она указана как _"<cam> (больше не используется в AgentDVR)»_ , поэтому вы можете снять галочку; адаптер просто проигнорирует это.

`send.mp4|mkv` (используется `sendRecording` /`getRecording` (для записей, которые не находятся в слоте) сохраняется до тех пор, пока записи с камеры не будут очищены — один файл на камеру, перезаписываемый каждый раз.

### MP4 и ffmpeg

AgentDVR записывает MKV-файлы. При **включенной опции «Предоставлять как MP4»** (по умолчанию включено) адаптер перекодирует MKV-файл в MP4 с помощью ffmpeg — изменяется только контейнер, копируются видео и аудио, поэтому это занимает менее секунды. Видео HEVC (H.265) получают `hvc1` Чтобы устройства Apple и Telegram могли воспроизводить видео, добавьте тег. Если аудиокодек не подходит для формата MP4, видео будет перекодировано без звука (запись в лог один раз). Без ffmpeg файл MKV будет предоставлен без изменений (одна информационная запись в лог).

ffmpeg **не** входит в комплект поставки. Адаптер ищет его при запуске и по запросу: _путь к ffmpeg_ →`ffmpeg` с помощью `PATH` →`/usr/bin/ffmpeg`, `/usr/local/bin/ffmpeg`, `/opt/homebrew/bin/ffmpeg`, `C:\ffmpeg\bin\ffmpeg.exe`, `%ProgramFiles%\ffmpeg\bin\ffmpeg.exe` Результат представлен в `info.ffmpeg` (например `6.1.1 (/usr/bin/ffmpeg)` или `not found`) и в настройках рядом с опцией MP4, с кнопкой **«Поиск снова»** . Установите ffmpeg с помощью менеджера пакетов вашей системы:

| Система                         | Командование            |
| ------------------------------- | ----------------------- |
| Debian, Ubuntu, Raspberry Pi OS | `apt install ffmpeg`    |
| Альпин (Докер)                  | `apk add ffmpeg`        |
| Федора                          | `dnf install ffmpeg`    |
| macOS (Homebrew)                | `brew install ffmpeg`   |
| Windows                         | `winget install ffmpeg` |

Выполните команду от имени администратора/root, как обычно, в вашей системе. После этого _снова нажмите «Поиск»_ в настройках (или перезапустите экземпляр).

### Отправка записей: `sendRecording` и `getRecording`

`sendRecording` Создает запись, доступную в файловом хранилище адаптера, и отправляет ее в экземпляр мессенджера в виде видео. Запись, которая уже сохранена (`recordings.*` Используется напрямую; любой другой файл загружается в память, при необходимости преобразуется в формат MP4 и записывается в фиксированный файл для каждой камеры. `agent-dvr.0/<cam>/send.mp4` (или `.mkv`), который перезаписывается каждый раз, поэтому пространство остается неизменным:

```js
sendTo('agent-dvr.0', 'sendRecording', {
    camera: 'cam_8_Reolink',      // folder id, AgentDVR oid (8) or camera name
    recording: 'last',            // 'last' (newest in AgentDVR), 1-3 (stored slot) or an AgentDVR file name
    target: 'telegram.0',         // instance that gets the video
    caption: 'Motion at the front door',
    // user: 'Max', chatId: 123, // optional, passed through to Telegram
    // mp4: true,                 // optional, overrides "Provide as MP4"
}, res => {
    if (!res.ok) log(res.error, 'warn'); // e.g. too large for Telegram
});
```

Сообщение для адресата следующее: `{ text: 'iobfile://agent-dvr.0/<cam>/<file>', type: 'video', fileName: '<name>.mp4', width, height, duration, caption, user, chatId }` — Telegram 6 и более поздние версии считывают сам файл из файлового хранилища. `width`, `height` и `duration` Они считываются из видеофайла: Telegram сам не обнаруживает их для больших загружаемых ботом файлов и в противном случае отображал бы видео в чате с неправильным соотношением сторон, пока оно не будет открыто. Другие цели получают вместо этого абсолютный путь к файлу (или URI, если хранилище файла находится не на локальном диске). Ответ: `{ ok, error?, fileName, format, mime, size, uri, url, file, width, height, duration }` Запись, которую AgentDVR еще записывает, отправляется после ее завершения. **Telegram-боты могут отправлять файлы размером до 50 МБ** ; записи большего размера отклоняются с явным сообщением об ошибке — до начала загрузки, если AgentDVR уже указывает размер файла.

> **Видеоданные не передаются по шине сообщений ioBroker.** Большие сообщения (десятки МБ) могут заблокировать базу данных состояний, а вместе с ней и весь ioBroker. Именно поэтому адаптер передает только ссылку на файл и отказывается отправлять или отвечать на сообщения, содержащие двоичные данные.

Отправляйте все новые записи в Telegram (Blockly не требуется):

```js
on({ id: 'agent-dvr.0.cam_8_Reolink.events.new', val: true }, () => {
    sendTo('agent-dvr.0', 'sendRecording', { camera: 'cam_8_Reolink', recording: 'last', target: 'telegram.0', caption: 'New recording' });
});
```

При включенной функции хранения файлов, запустите триггер. `recordings.ts1` и отправить вместо этого сохраненную копию (`recording: 1`):

```js
on({ id: 'agent-dvr.0.cam_8_Reolink.recordings.ts1', change: 'ne', ack: true }, () => {
    sendTo('agent-dvr.0', 'sendRecording', { camera: 'cam_8_Reolink', recording: 1, target: 'telegram.0', caption: 'New recording' });
});
```

> **Совет: правильное соотношение сторон в чате.** Если вы отправляете видеофайл в Telegram самостоятельно (блокировка Telegram Blockly, `recordings.file1` /`uri1`), Telegram часто отображает видео больших размеров в предварительном просмотре чата в неправильном формате (например, 3:4), пока вы их не откроете — Telegram сам не считывает размер изображения из загруженных ботом файлов больших размеров. `sendRecording` Функция считывает ширину, высоту и длительность из видеофайла и передает их дальше, поэтому видео сразу воспроизводится в чате в соотношении сторон, соответствующем камере. Ничего настраивать не нужно, всё просто работает при использовании. `sendRecording`.

`getRecording` принимает то же самое `camera`, `recording` и `mp4`, делает запись доступной тем же способом и возвращает только то место, где она находится: `{ ok, error?, fileName, mime, format, size, uri, url, file, width, height, duration }` Прочитайте файл в своем скрипте самостоятельно, например:

```js
sendTo('agent-dvr.0', 'getRecording', { camera: 'cam_8_Reolink', recording: 'last' }, res => {
    if (!res.ok) return log(res.error, 'warn');
    // res.uri = 'iobfile://agent-dvr.0/cam_8_Reolink/send.mp4', res.url = http link, res.file = local path
    readFile('agent-dvr.0', res.uri.replace('iobfile://agent-dvr.0/', ''), (err, data) => { /* … */ });
});
```

| Прямая трансляция                   | `<cam>.urls.mjpeg`, `<cam>.urls.mp4` | видео                                                   | жить                                                          |
| Последняя запись – миниатюра        | `<cam>.events.last.thumb`            | Максимальное разрешение: 320×180 (ограничение AgentDVR) | Лучший момент записи, на котором показан обнаруженный объект. |
| Последняя запись – видео            | `<cam>.events.last.video`            | видео                                                   | после записи                                                  |
| Предупреждающие фотографии          | `<cam>.alertPhotos.grab1`…`grab3`    | полное разрешение                                       | момент оповещения (вебхук с `oid`)                            |

Он `urls.*` и `events.last.*` URL-адреса указывают непосредственно на AgentDVR. Они работают только в локальной сети — серверы Telegram не могут их получить. Либо сначала загрузите их с помощью HTTP-запроса (тип ответа). `arraybuffer`) или используйте фотографии для оповещений, которые уже сохранены в ioBroker.

### Какой триггер для чего

| Курок                         | Пожары                                                                                     | Использовать для                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| `<cam>.alertPhotos.ts1`       | Фотография сохраняется примерно через 1–2 секунды после оповещения.                        | **Отправить фото с предупреждением** (рекомендуется) |
| `<cam>.events.webhook`        | немедленно при вызове веб-перехватчика                                                     | самостоятельно загрузить изображение                 |
| `<cam>.events.new`            | новая запись указана                                                                       | миниатюра записи                                     |
| `<cam>.events.detected_<tag>` | AI-тег новой записи, например `detected_people` — также когда AgentDVR добавляет тег позже. | уведомлять только отдельных лиц                      |

> **Не использовать `events.webhook` Для сохраненного изображения оповещения.** Импульс веб-перехватчика срабатывает _до того, как_ новое изображение будет получено и сохранено. В этот момент `alertPhotos.grab1` /`uri1` /`url1` По-прежнему указывается на фотографию из **предыдущего** оповещения — затем в сообщении на ТВ или в Telegram отображается старое изображение (возможно, многочасовой давности). Для всего, что использует `alertPhotos.*` всегда срабатывать `alertPhotos.ts1`. `events.webhook` предназначен только для скриптов, которые в данный момент самостоятельно загружают изображение (например, `urls.photo` или снимок, сделанный их собственной камерой).

Используйте **«больше предыдущего»** (Blockly) или `change: 'gt'` в качестве условия. Адаптер перезаписывает свои состояния при каждом опросе, поэтому событие "было обновлено" срабатывает при каждом опросе. `status.alerted` Обычно он слишком короткий, чтобы его можно было заметить при опросе, и не является надежным индикатором.

### Телеграмма

Blockly: триггер на `<cam>.alertPhotos.ts1` Блок Telegram со _значением_ "больше, чем раньше", `<cam>.alertPhotos.uri1` в виде текста.

- **Telegram 6 или более поздняя версия:** используйте `uri1` (`iobfile://…` Telegram считывает фотографию непосредственно из файлового хранилища ioBroker и отправляет её как фото — работает со всеми типами хранилищ.
- **Более старые версии Telegram:** используйте `grab1` (путь к локальному файлу). Текст, представляющий собой существующий локальный файл. `.jpg` Путь отправляется в виде фотографии.

Отправка содержимого файла напрямую (например, _чтение файла_ → Telegram) из Blockly **не** работает: необработанные данные отправляются только в виде фотографии с явным указанием источника. `type: 'photo'`.

JavaScript:

```js
on({ id: 'agent-dvr.0.cam_8_Reolink.alertPhotos.ts1', change: 'gt' }, () => {
    sendTo('telegram.0', { text: getState('agent-dvr.0.cam_8_Reolink.alertPhotos.uri1').val });
});
```

Чтение самого файла с помощью скрипта: `readFile('agent-dvr.0', 'cam_8_Reolink/grab1.jpg', (err, data) => { … })`.

### ВИС / панели мониторинга

Фотографии для оповещений предоставляются веб-сервером — готовая ссылка находится в... `<cam>.alertPhotos.url1` …`url3` Адаптер выбирает включенный веб-экземпляр (обычный). `http` предпочтительно, поскольку приложения для ТВ часто отклоняют самоподписанные сертификаты) и IPv4-адрес хоста. Веб-экземпляр также можно выбрать в настройках ( _Функции → Веб-экземпляр для ссылок на фотографии_ ). При изменении веб-экземпляра (порт, HTTPS, адрес привязки, включено) или адреса хоста ссылки автоматически перезаписываются. Ссылки остаются неизменными для каждой новой фотографии, поэтому вы можете ввести их один раз в приложении:

```
http://<iobroker>:<webport>/agent-dvr.0/photos/<cam>/grab1.jpg
```

например `http://192.168.1.10:8082/agent-dvr.0/photos/cam_8_Reolink/grab1.jpg` (также `grab2.jpg`, `grab3.jpg` Используйте его в виджете изображения и обновляйте его при изменении. `alertPhotos.ts1` То же самое относится и к отправке ссылки на телевизор или в другое приложение: отправьте её дальше. `alertPhotos.ts1` не на `events.webhook` — в противном случае приложение загрузит предыдущую фотографию. Для отображения изображения в реальном времени используйте `urls.snapshot` или `urls.photo` с интервалом обновления.
