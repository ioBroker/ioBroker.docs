# ioBroker.pi-agent

Агент языковой модели для ioBroker, который сохраняет работоспособность после перезапусков и сбоев. Он построен на [Raspberry Pi. Технология Durable](https://earendil.com/posts/pi-durable/) : каждый вызов модели и инструмента сохраняется в виде контрольной точки перед запуском, поэтому прерванный запрос продолжается после повторного запуска адаптера, а не начинается заново.

## Что это делает

- Считывает и ищет состояния с помощью инструментов. `search_objects`, `get_state` (один идентификатор или `*` узор) и `list_instances` Эти инструменты можно безопасно использовать повторно. Оба показывают тип, единицу измерения, доступность для записи, а также минимальное, максимальное и допустимые значения, установленные в штате. `common.states`), поэтому агент записывает значение, которое ожидает устройство.
- Определяет состояния комнаты и/или функции, настроенные в ioBroker. `enum.rooms`, `enum.functions`) с `find_states` например, комната "Küche" и функция "Licht" для "освещения на кухне"; `list_rooms` и `list_functions` Покажите, что существует. Названия совпадают на каждом языке перечисления и частично; элемент, являющийся устройством или каналом, отображает состояния, находящиеся ниже него.
- `list_instances` начинается с объектов экземпляра и считывает `alive` и `connected` каждого экземпляра по его точному идентификатору. А `*` pattern находит только те состояния, которые содержат объект, поэтому устаревший результат будет неверным. `alive` Значение экземпляра, у которого отсутствует объект состояния, отсутствует в запросе по шаблону, но не в `list_instances`.
- Каждый вызов инструмента регистрируется в виде одной строки: `Tool <name> <arguments> -> <outcome>` (Заблокированные операции записи отображаются как предупреждение).
- Записывает состояния через `set_state` Этот инструмент **никогда не повторяется** после прерывания: модели сообщается, что вызов был прерван, и она сначала проверяет фактическое значение. Светильник нельзя переключить дважды перезапуском.
- Запись осуществляется только в те состояния, которые разрешены **правами на запись** . Все остальное блокируется до завершения работы программы.
- Ответ на каждый запрос выполняется ровно один раз. Идентификатор запроса определяется состоянием срабатывания, поэтому при повторном срабатывании обнаруживается исходный запрос.

## Требования

- Node.js 22.19.0 или новее, js-controller 6.0.11 или новее, admin 8.0.0 или новее.
- Ключ API выбранного поставщика: Anthropic, OpenAI, DeepSeek, Google Gemini или OpenRouter, или сервер, совместимый с OpenAI (локальный сервер, например Ollama, не требует ключа). Или общесистемные настройки ИИ в административной панели (Системные настройки, вкладка «ИИ»), которые определяют поставщика, модель и ключ один раз для всей системы.
- Адаптер работает как отдельный процесс (не в компактном режиме). Он поддерживает открытыми длительные запросы к моделям и хранилище диалогов, а его зависимости велики; запуск его отдельно предотвращает сбои или пиковые нагрузки на память других адаптеров. Ключ API хранится только в памяти этого экземпляра и никогда не передается в среду процесса.

## Использование

### Чат в административной панели

Пункт меню **«Pi Agent»** в левой части административной панели открывает чат с агентом:

- У каждого пользователя ioBroker есть свой собственный диалог; **новый диалог** начинается заново. Старый диалог удаляется из хранилища при следующем запуске экземпляра после создания резервной копии. `pi-agent-prepurge-….sqlite.gz` (в папке резервного копирования). После отправки напоминания удаляется переписка с напоминанием, срок выполнения которой еще не истек. Удаление зависит от схемы хранения Pi Durable; при неизвестной версии схемы (после обновления Pi Durable) ничего не удаляется.
- Ответ отображается в отформатированном виде, а над ним указаны вызовы инструментов агента.
- В чате предлагается написать сообщение в списке "Требуется подтверждение", используя кнопки ✅/❌.
- Запрос продолжает выполняться даже после закрытия страницы; ответ появится в чате после повторного открытия страницы.
- Напоминания о разговоре отображаются в чате (сохраняются до перезагрузки адаптера).
- В **разделе «Подробности** » (сохраняющемся в браузере) под каждым ответом отображается информация о поставщике, модели, времени, токенах (входящих, исходящих, кэшированных) и количестве вызовов модели, а для каждого вызова инструмента — его аргументы, начало результата и время; заблокированный или неудачный вызов отображается красным цветом.
- Администраторы (группа «администратор») выбирают в списке вверху другую беседу: чаты мессенджера, других пользователей-администраторов и других пользователей. `sendTo` Абоненты, такие как ioBroker.assistant (по одному на комнату или спутник), отображаются только для чтения и обновляются каждые несколько секунд.

### Штаты и сценарии

Напишите текст, чтобы `pi-agent.0.chat.input` Ответ находится в `pi-agent.0.chat.answer` Из сценария:

```js
sendTo('pi-agent.0', 'ask', { text: 'Is the living room light on?' }, result => log(result.answer));
```

Ответ `sendTo` Запрос возвращается только через функцию обратного вызова (`result.answer`, или `result.error`); это не написано для `chat.answer`.

Без дополнительных полей, все `sendTo` Запросы обрабатываются в рамках одного диалога. Абонент, обслуживающий несколько человек или помещений (например, голосовой помощник), может создать для каждого из них отдельный диалог со своей историей и инструкциями:

```js
sendTo('pi-agent.0', 'ask', {
    text: 'Is the light on?',
    conversation: 'kitchen', // own conversation of this caller; up to 100 characters
    instructions: 'Answer in one or two short sentences without Markdown; the answer is spoken.', // optional
    requestId: 'kitchen-1730123456789', // optional: a repeated request with the same id is answered once
    language: 'ru', // optional: language of the user, for the questions to confirm (see below)
}, result => log(result.answer, result.language));
```

Абонент, который отправляет `language` Озвучивает ответы (ioBroker.assistant). В ходе диалога также применяется правило для маркировки языка каждого ответа; pi-agent извлекает маркировку и возвращает код. `result.language` (`'ru'`, `'de'` …), поэтому звонящий может ответить по-русски, даже если спутник принимает сигнал на немецком языке. Когда модель пропускает отметку, `language` отсутствует, и звонящий решает сам.

**Округление значений для голосовых ответов** (вкладка «Права на запись», включено по умолчанию): в разговоре такого абонента. `get_state` Модель считывает температуру (°C, °F, K), проценты и скорость ветра (км/ч, м/с, миль/ч, узлов, баллов по шкале Бофорта) как целые числа, поэтому спутник показывает «от 1 до 8 градусов» вместо «от 0,6 до 8 градусов». Одного правила в инструкции было недостаточно: модель считывала данные о погоде. Другие значения (мм, кВт·ч и т. д.) и все остальные параметры сохраняются в точном виде.

Переписка ведется для каждого отправителя (`pi-agent.0.telegram.chats` перечисляет их как `sendTo:<instance>/<conversation>`). Измененные инструкции вступают в силу со следующего запроса в ходе беседы.

Запрос может содержать изображения; ioBroker.assistant передает фотографии, отправленные пользователями Telegram-боту, следующим образом:

```js
sendTo('pi-agent.0', 'ask', {
    text: 'What is this?', // optional when there are pictures
    images: [{ data: '<base64>', mimeType: 'image/jpeg' }], // a data URL works too
    conversation: 'telegram:Max',
}, result => log(result.answer));
```

- JPEG, PNG, GIF и WebP, максимум 4 изображения размером до 3,9 МБ каждое. Тип определяется по содержимому изображения. Другие файлы и изображения большего размера отбрасываются с предупреждением в журнале.
- Модель, не использующая ввод изображения, получает примечание вместо картинки.
- Изображение отправляется модели только один раз, со своим собственным сообщением. Модель записывает то, что показывает, в заметки после своего ответа. `<picture-notes>` Пользователь их не видит); в последующих вопросах вместо изображения отображаются эти заметки. Таким образом, изображение стоит свои токены один раз, и изображение, которое поставщик отклоняет, не может заблокировать разговор.
- В магазине хранятся 20 самых новых фотографий; более старые удаляются при следующем запуске экземпляра (их примечания сохраняются). `chat.pending` сохраняет только текст.

В таком диалоге нет кнопок, поэтому по умолчанию запись с пометкой «Требуется подтверждение», перезапуск и обновление блокируются. При наличии **подтверждения по SMS в диалогах sendTo** (вкладка «Разрешения на запись», по умолчанию отключена) агент запрашивает подтверждение по SMS:

- В ответ на запрос возвращается вопрос, за которым следует... `[[LISTEN]]` (ioBroker.assistant снова открывает микрофон), например: "Перезапустить экземпляр telegram.0? Скажите да или нет." Это находится в `language` Вызывающий абонент отправляет свой последний запрос в разговоре (ioBroker.assistant отправляет язык, на котором слушают его спутники), в противном случае — на языке системы ioBroker. Спутник, слушающий на русском языке, не понимает немецкого «Я»: его система распознавания речи возвращает либо «Я», либо «Нет».
- Следующий запрос в том же разговоре — это ответ. pi-agent проверяет его самостоятельно, а не модель: ответ должен состоять из слов, подтверждающих согласие, без учета регистра и знаков препинания: «да» или соответствующее слово на одном из языков адаптера («ja», «да», «oui»), то, что люди говорят вместо этого («okay», «klar», «jawohl», «конечно», «ага»), и то, как распознавание речи интерпретирует короткое «Ja» («Ya», «Yup»). Рядом с ними могут стоять вежливые слова («ja bitte», «да, пожалуйста»); одно и то же слово дважды («да да», «Ja, ja.») тоже засчитывается. Любое другое слово делает ответ отрицательным («ja, aber erst …», новый вопрос), как и 2 минуты без ответа. Контекст, который звонящий добавляет перед ответом, отделенный пустой строкой (ioBroker.assistant сначала отправляет время, погоду и информацию о присутствии), не засчитывается. В логе отображается, что было услышано и как было принято решение.
- Результатом является ответ на следующий запрос: что скажет агент после выполнения действия или на следующий вопрос.
- Голосовым способом любой присутствующий в комнате может сказать «да». Включайте устройство только там, где это допустимо.

### Пределы

Два лимита останавливают запрос до того, как он будет отправлен модели, поэтому неконтролируемый запрос не требует токенов:

- **Количество запросов в минуту на один разговор** (по умолчанию 10): цикл, например, скрипт или другой адаптер, который запрашивает повторно сразу после каждого ответа, останавливается при превышении лимита запросов. Каждый разговор учитывается отдельно (чат в мессенджере, пользователь административного чата, сателлит или разговор с вызывающим абонентом, фоновая задача); человек не достигает 10 запросов в минуту. Отклоненный запрос получает ошибку.`Too many requests from this conversation (at most 10
  per minute) ` и в журнале появляется одно предупреждение за каждый запуск с названием беседы, например.` sendTo:assistant.0/chat` Запросы, повторенные после перезапуска, не учитываются.
- **Количество токенов в день** (по умолчанию 0 = выключено): когда количество токенов с полуночи (`usage.tokensToday`) Достигнув заданного числа, на каждый запрос будет дан ответ. `The daily token limit (…) is reached; the agent answers again after midnight` До полуночи в журнале появляется одно предупреждение, и `usage.limitReached` является `true` до первого запроса после полуночи. Запрос, начатый до достижения лимита, завершается, поэтому день может закончиться немного выше него. Ответы на вопросы с ✅/❌ продолжают работать, им не нужна модель. При достижении 80%, 90% и 99% лимита пользователь, задавший вопрос, получает предупреждение один раз в день под ответом (в административном чате в виде заметки, в мессенджере, в задании или `chat.answer` в конце ответа), и в журнале появляется предупреждение; `sendTo` Звонящий получает это на месте `warning` Ответ не содержится в тексте ответа (его бы произнес спутник). Чтения из кэша не учитываются: каждый запрос отправляет весь диалог заново (инструкции, описания инструментов, сообщения и результаты работы инструментов на данный момент), и провайдер считывает из своего кэша ту часть, которую он уже видел, примерно за десятую часть цены. В полном объеме они составили более 90% токенов за день. Новый диалог после смены темы позволяет поддерживать небольшой объем запросов.
- **Токены на запрос (контекст)** (по умолчанию 0 = до окна модели): каждый запрос содержит инструкции, описания инструментов (вместе около 5-10 тысяч токенов) и историю разговора. Без ограничения история растет до тех пор, пока окно модели не будет почти заполнено (от 128 тысяч токенов до примерно 100 тысяч на запрос), и только тогда происходит ее суммирование. С ограничением, например, 40000, более старая часть разговора суммируется в фоновом режиме, начиная с трех четвертей от лимита, начиная с запроса, достигшего лимита; последние 30% лимита остаются дословными. Это делает каждый запрос дешевле, особенно первый после паузы, когда кэш провайдера исчерпан, и каждый токен стоит полную цену. Сумма — это один дополнительный вызов модели. Минимальное значение 24000; 32000-48000 подходит для голосовой связи и чата. Наибольшую выгоду получает спутниковый разговор, который длится неделями. В журнале отладки отображается каждый вызов модели, например: `Model call deepseek/deepseek-flash: context 41234 tokens (39000 from the cache = 95 %, 2234 new), answer 85, cost $0.00091`, и `Summarising the older part of a conversation (threshold): 58 messages` когда начинается сводка.

## Безопасность

- Модель сама определяет, какие инструменты вызывать. Права на запись и режим моделирования обеспечивают вашу защиту, а не командная строка.
- Скрипты, созданные агентом, выполняются с правами адаптера JavaScript: после запуска права на запись и режим симуляции pi-agent не ограничивают его. Перед подтверждением ознакомьтесь с изменениями (см. раздел «Скрипты»).
- Текст ваших запросов и значения, считываемые агентом, отправляются поставщику. Не предоставляйте ему доступ к состояниям, содержащим секреты.
- Переписка хранится в незашифрованном виде в каталоге данных экземпляра. `session.sqlite` SQLite, встроенный в Node.js). Установка, в которой по-прежнему используется хранилище JSONL версии 0.0.1/0.0.2 (папка). `session` При первом запуске без ожидающих запросов система переключается на SQLite; старая папка переименовывается в `session.jsonl-<date>` и сохраняются. Предыдущая история не переносится, и в чатах мессенджера начинаются новые разговоры.

## Уведомления, запланированные операции записи, диагностика

- `notify_when` Сообщает пользователю в чате переписки, когда состояние соответствует условию: `==`, `!=`, `>`, `<`, `>=`, `<=` или `changes` Дополнительно, на несколько минут, например, «стиральная машина закончила» (мощность ниже 5 Вт в течение 3 минут) или «окно открыто более 10 минут». Учитываются только значения, сообщаемые устройством (ack=true), а не команды. Часы срабатывают один раз и заканчивают работу не позднее чем через 7 дней; одновременно может срабатывать не более 20 часов. Часы хранятся в `scheduled.watches` и продолжить работу после перезагрузки.
- `schedule_set_state` Запись состояния производится позже («выключить обогреватель в 23:00»), максимум за 7 дней вперед. Права на запись и подтверждение проверяются при планировании; проверка прав повторяется, когда наступает срок выполнения, поэтому удаление прав в это время останавливает процесс. Пользователь получает сообщение о завершении. Процесс сохраняется после перезагрузок.
- `list_scheduled` отображает напоминания, запланированные записи и отслеживание разговора. `cancel_scheduled` отменяет один из них.
- `get_logs` Считывает самые новые строки файла журнала ioBroker (отфильтрованные по экземпляру, уровню и одному слову, не более 50); `list_notifications` Отображает уведомления ioBroker (значок колокольчика в админке). Оба приложения только для чтения.
- Сообщение из разговора `sendTo` Вызывающий объект (например, ioBroker.assistant) переходит к `chat.answer`; Голосовая связь осуществляется через спутник ioBroker.assistant 1.4.9+.

## Фоновые работы

Фоновая задача — это работа, которая длится несколько дней и требует постоянного обдумывания, например: «Пока меня нет до 20-го числа, сообщай мне, когда окно остается открытым в течение 15 минут, пока работает отопление, или когда датчик Zigbee выходит из строя» или «Каждое утро в 7 сообщай мне погоду и уровень заряда батареи».

- Агент настраивает это с помощью `create_job`: краткое название, задача, сформулированная пользователем, триггеры, количество дней выполнения (максимум 30) и куда отправляются сообщения.
- **Триггеры:** состояние, удовлетворяющее условию (`==`, `!=`, `>`, `<`, `>=`, `<=` или `changes` (опционально в течение нескольких минут; учитываются только значения устройства), время суток (`daily` (местное время) или интервал (от 15 до 1440 минут). Триггер состояния срабатывает, когда выполняется его условие, и снова только после того, как условие было нарушено.
- **Модель вызывается только при срабатывании триггера.** Адаптер сам отслеживает триггеры; затем начинается собственный диалог задания с задачей, считывается необходимая информация и сообщается пользователю, либо происходит молчание (ложная тревога). Задание, которое никогда не срабатывает, ничего не стоит.
- **Где отображается информация:** в чате, где была создана задача (по умолчанию), в административном чате, в чате мессенджера или **по голосовой связи** : через сателлит ioBroker.assistant, из которого была создана задача. `assistant.0.satellites.<id>.tts` (названный помощником с 1.4.9), иначе все они (`assistant.0.tts.text` Для **записи в режиме "Разрешения на запись" требуется разрешение** на запись; в режиме симуляции ничего не произносится. Агент, настроенный на голосовое управление, спрашивает, куда следует направить сообщение.
- **Действия, отмеченные только ✅/❌:** каждое изменение файла, перезапуск, команда, обновление или скрипт задания запрашивается в мессенджере или административном чате, в который оно отправляет отчет, даже без «Требуется подтверждение». Задание, которое отправляет отчет только голосом, может сообщить только об этом.
- **Ограничения:** не более 5 заданий и 5 триггеров на задание. Задание, активированное более 20 раз за день, приостанавливается с соответствующим сообщением, поэтому датчик, вызывающий срабатывание триггера, не сможет израсходовать выделенный бюджет; `resume_job` Начинает всё заново.
- `list_jobs` показывает задачи (триггеры, запущены или приостановлены, до какого момента, как часто они активировались). `stop_job` Останавливает одну задачу; работа может остановиться сама, когда она будет выполнена («сообщите мне, когда стиральная машина закончит»). Задачи хранятся в `scheduled.jobs` и продолжить работу после перезагрузки.
- В административной панели чат отображает задачи над перепиской (сворачиваемые): статус, триггеры, до какого момента, пробуждения за сегодня, последнее пробуждение, место, куда нужно отчитаться, с **кнопками «Остановить»** и **«Возобновить»** .
- Для отправки одного сообщения при возникновении события, `notify_when` Этого достаточно.

## Кодовый режим

В **режиме «Код»** (вкладка «Общие», по умолчанию отключено) агент может ответить на вопрос о многих состояниях с помощью короткого скрипта вместо последовательного вызова инструментов, например: «В каких комнатах уровень заряда батарей ниже 20%?»

```js
const rooms = await tools.list_rooms({});
for (const room of rooms.rows) {
    const found = await tools.find_states({ room: room.name, function: 'battery' });
    const low = found.rows.filter(s => s.role === 'value.battery');
    // …
}
```

- Скрипт запускается в изолированной среде QuickJS (`@earendil-works/pi-codemode`): никаких файлов, никакой сети, никаких таймеров, только инструменты агента. `tools.<name>(args)` Инструменты чтения передают свои значения в виде объектов. В модель поступает только то, что выводит скрипт, поэтому для ответа на вопрос о состоянии всего дома достаточно одного вызова модели вместо десятков, с гораздо меньшим количеством токенов.
- **Каждый вызов скрипта — это отдельный вызов инструмента:** для каждого из них сохраняются права на запись, режим моделирования и подтверждения, в том числе и в фоновых задачах. Скрипт, который переключает десять ламп из списка «Требуется подтверждение», запрашивает подтверждение десять раз. Заблокированный вызов — это ошибка в скрипте, которую скрипт может обработать.
- Скрипт сохраняется после перезапуска адаптера: он продолжает работу с того места, где остановился, и предыдущие вызовы не выполняются (прерванная запись сообщается как прерванная, как и вне скрипта).
- Скрипты не могут вызывать модели (ни классификаторы, ни генерация изображений). Модель определяет, когда использование скрипта оправдано; один переключатель остается одним вызовом инструмента.
- Инструменты описываются для модели с помощью объявлений TypeScript (примерно на 3000 токенов больше на каждый запрос). Лучше всего работает с надежными моделями; с небольшой моделью сравнивайте ответы, отключив режим кода.

> **В режиме кодирования токены экономятся только для вопросов, состоящих из нескольких шагов.** Вопрос, на который нужно ответить, используя шаблон («какие батареи разряжены менее чем на 20%?»), требует немного больше токенов в режиме кодирования, чем без него: на тестовой системе с флэш-памятью DeepSeek требуется 3 вызова модели вместо 2. Вопрос, который объединяет данные, подсчитывает количество элементов или проходит через множество устройств («где открыто окно, когда горит свет, и какие батареи разряжены менее чем на 20%?»), потребовал 1646 новых входных токенов вместо 7972, что примерно на 80% меньше, при этом скрипт выполнял точное сопоставление, а не определял модель. Включайте этот режим, когда такие вопросы встречаются часто или дом большой.

## Планировщик полный календарь

Для действий, которые повторяются (каждый будний день в 7:00), опережают события более чем на 7 дней, включают что-либо на некоторое время или зависят от условия, агент использует адаптер [fullcalendar](https://github.com/ioBroker/ioBroker.fullcalendar) (версия 3.3 или новее). `send_to`: `addEvent`, `updateEvent`, `deleteEvent`, `listEvents`, `getCalendars`, `enableCalendar` События отображаются в календаре, и их можно изменить там. Запланированные события агент читает в календаре. `fullcalendar.0.events.today`, `.tomorrow` и `.next`.

- Для этого требуется **разрешение на запись.** `fullcalendar.0` в разделе «Права на запись».
- FullCalendar записывает состояние события самостоятельно, позже. Поэтому pi-agent проверяет это состояние. `oid`) сначала против собственных прав на запись: событие для состояния pi-agent, которое не может записывать данные, блокируется. Для `updateEvent` без `oid` Проверяется состояние события. Где находится состояние или строка `fullcalendar.0` **Требуется подтверждение** , пользователь подтверждает событие, указывая, что и когда, например: "addEvent: hm-rpc.0.heater.STATE = false, start 23:00, recurring daily".
- Если FullCalendar не установлен или его установка запрещена, агент сообщает пользователю о недостающих компонентах и предлагает решения, работающие и без него. `schedule_set_state` один раз в течение 7 дней, `notify_when`, `remind_me` Агент обнаруживает установку без перезапуска.

## Перезапуск экземпляров

Инструмент `restart_instance` Перезапускает экземпляр адаптера, например: "Telegram не отвечает, перезапустите его":

- В таблице «Права на запись» **разрешен только экземпляры с разрешением на перезапуск** . Флажок применяется только к строке, областью действия которой является весь экземпляр. `telegram.0`), не для идентификатора объекта или шаблона, и никогда для pi-agent или admin. Запись и перезапуск разрешены отдельно.
- Каждый перезапуск подтверждается символами ✅/❌ в чате переписки (мессенджере или чате администратора), даже без необходимости подтверждения. `sendTo` Вызывающая сторона (например, ioBroker.assistant) не может подтвердить запрос, поэтому перезапуск с этой стороны блокируется, если не включена опция "Подтверждение текстом в диалогах sendTo".
- Перезапуск работает аналогично кнопке перезапуска в административной панели. Затем агент ждет до 45 секунд, пока экземпляр снова не запустится, и сообщает об этом. Выключенный экземпляр не включается. В режиме симуляции ничего не перезапускается.

## Команды для других адаптеров

Инструмент `send_to` отправляет команду другому адаптеру и возвращает его ответ, например, экземпляр. `telegram.0`, команда `send`, сообщение `{"text": "Hello"}` или адаптер преобразования текста в речь. Агент использует команду и сообщение, описанные в документации адаптера.

- Только для экземпляров, у которых в строке "Разрешения на запись" указан весь экземпляр целиком (`telegram.0`) с **разрешенной записью** ; строка для некоторых состояний экземпляра (`telegram.0.communicate.*`) недостаточно. Никогда не обращайтесь к pi-агенту или администратору.
- Если в этой строке **указано «Требуется подтверждение»** , каждая команда сначала подтверждается символами ✅/❌ в чате.
- Агент ожидает ответа до 30 секунд; если многие адаптеры не отвечают, команда всё ещё может сработать. Команда никогда не отправляется повторно после прерывания. В режиме симуляции ничего не отправляется.

Перед отправкой первой команды адаптеру агент считывает информацию о себе, предоставленную адаптером, с помощью соответствующего инструмента. `adapter_help`: адаптер отвечает на сообщение `help` со своими командами, их параметрами и ответами, важными состояниями, а также с указанием того, какие команды только читают, а какие что-то изменяют. `list_instances` отмечает случаи, которые это подтверждают (`common.supportedMessages.help` в их `io-package.json`) с `"help": true` Без посторонней помощи агент использует только команды, указанные в документации адаптера, и не пытается угадывать.

- `adapter_help` Только чтение: в поле "Права на запись" не требуется строка, и подтверждение не требуется.
- Он запрашивает только запущенные экземпляры, принимающие сообщения; адаптер, который не объявляет `help` Получает 3 секунды на ответ, а тот, кто объявляет о 10 секундах, отвечает.
- Адаптер, который не принимает сообщений (веб-адаптер без обработки, например, home3d), не может отвечать. `help` Его помощь оказывают состояния, которые он описывает в своих документах. `io-package.json`: то `instanceObjects` типа `state` с `common.desc` (не более 30), каждый со своим типом, ролью, возможностью написания и описанием (на английском языке, в противном случае — на родном языке). `list_instances` помечает такой адаптер с помощью `"help": true` а также. Запись этих состояний с помощью `set_state` Для них, как обычно, требуется разрешение на запись.

Адаптеры изучают новые функции с обновлениями, в то время как разговор (например, голосовой спутник сохраняет свои настройки в течение нескольких недель) по-прежнему помнит, что могла делать более старая версия. Поэтому pi-agent постоянно обновляет справочную информацию:

- В начале работы программа считывает справку каждого запущенного экземпляра, описывающего саму себя. Она отслеживает происходящее. `system.adapter.*.alive` и объекты экземпляра: после перезапуска экземпляра (обновление также перезапускает его) или изменения его объекта, он снова запрашивает справку у экземпляра. Экземпляр, который больше не выдает справку, отвечает без нее, выключен или удален, покидает список. В журнале указывается, когда изменилась справка или экземпляр покинул список.
- В инструкциях модели даны имена экземпляров, которые описывают сами себя, и действуют два правила: читать `adapter_help` Прежде чем впервые записывать состояния такого экземпляра, перечитайте их еще раз в том же запросе, прежде чем сообщать пользователю, что адаптер или устройство не могут что-либо сделать; предыдущий ответ в разговоре не является доказательством.
- pi-agent для каждого разговора указывает, с какой помощью он справлялся в каждом подобном случае (`get_state`, `set_state`, `send_to`) или читать (`adapter_help` Когда справка изменилась, модель в своих инструкциях сообщает, что экземпляр был обновлен и что информация, полученная в ходе обсуждения, может быть неверной, пока не будет повторно прочитана справка. Примечания хранятся в `adapter-knowledge.json` в каталоге данных экземпляра, для последних 300 разговоров.

## Зарегистрированный дом (ioBroker.recorder)

[ioBroker.recorder](https://github.com/ioBroker/ioBroker.recorder) записывает все важные состояния дома, не настраивая каждое из них, указывая, кто их включил, и определяет, что является обычным для каждого часа недели. Когда его экземпляр активируется при запуске pi-agent, агент получает четыре инструмента, которые считывают только:

| Инструмент        | Управление регистратором | Для таких вопросов, как                                                                     |
| ----------------- | ------------------------ | ------------------------------------------------------------------------------------------- |
| `house_events`    | `getEvents`              | «Что было переключено вчера вечером?», «Кто открыл гараж?»                                  |
| `house_snapshot`  | `getSnapshot`            | «Было ли окно в спальне открыто в 22:00?», «Насколько тепло было в гостиной в 3 часа ночи?» |
| `house_anomalies` | `getAnomalies`           | «Что-нибудь необычное произошло прошлой ночью?», «Почему я получил это уведомление?»        |
| `usual_value`     | `getProfile`             | «23 °C — это сейчас нормальная температура в ванной?»                                       |

- Время указано по местному времени дома; "22:00" означает последние 22:00. Комната указана на любом языке (например, "kitchen" обозначается как "Küche"), категории соответствуют категории записывающего устройства. `light`, `shading`, `climate`, `windowsDoors`, `motion`, `security`, `sockets`, `media`, `weather`, `energy`).
- Им не требуются права на запись и подтверждение. Датчики движения и присутствия отображаются только тогда, когда они включены в диктофоне; профиль для `usual_value` Усвоение происходит через 14 дней.
- После перезапуска pi-agent используется экземпляр, установленный позже.

## Поиск документации (RAG)

Модели, прежде всего локальные, разрабатывают функции API скриптов или настройки адаптеров. С помощью сервера проекта [ioBrokerRAG](https://github.com/bloop-herbert-bot/ioBrokerRAG) (REST API v1) агент сначала ищет информацию в документации ioBroker: в официальной документации, исходном коде ядра и файлах README адаптеров.

- Вкладка «Общие», блок «Поиск документации (RAG)»: URL-адрес сервера (например) `http://192.168.1.10:8000`) и только когда сервер устанавливает `IOB_RAG_TOKEN`, его токен (хранится в зашифрованном виде). Функция "Поиск тестовой документации" проверяет оба параметра. Пустой URL: отключено, и модель не получает инструмент.
- Инструмент `search_docs` отправляет вопрос модели на этот сервер и возвращает до 10 фрагментов текста с указанием их источника. Только фрагменты текста из источников с разрешительной лицензией (`license_status: allow`) Перейдите к модели.
- Агент выполняет поиск перед написанием скрипта и при запросе информации о работе адаптера или ioBroker. Идентификаторы состояния дома по-прежнему берутся из объектов, а не из документации.

## Обновления адаптеров

При **включенной опции «Разрешить обновления адаптеров** » (вкладка «Права на запись», по умолчанию отключена) агент может обновлять адаптеры, например, задавая вопросы типа «Есть ли обновления?» или «Обновить Telegram»:

- `list_updates` Отображает установленные адаптеры с более новыми версиями в репозитории, выбранном в ioBroker (как это отображается в админке), и предлагает агенту обновить их. При запросе информации о npm или новейших версиях («проверить все обновления в npm»), он сравнивает каждый установленный адаптер с npm за один вызов, включая pi-agent. `check_npm` Отображает самую новую версию одного адаптера в npm; также находит адаптер по его названию (FingerprintDoorbell →`fingerprint`).
- Версии, состояния и журналы, прочитанные ранее в ходе разговора, не используются повторно: если агенту задана повторная проверка, он читает их снова.
- Только адаптеры с экземпляром, имеющим **разрешение на запись** в настройках прав доступа, и сам pi-agent. Никогда не используйте admin или js-controller, и только адаптеры на хосте pi-agent.
- Каждое обновление подтверждается символами ✅/❌ в чате переписки, даже без необходимости подтверждения. `sendTo` Абонент не может подтвердить запрос, поэтому обновление оттуда блокируется, если не включена опция "Подтверждение по SMS в диалогах sendTo". В режиме симуляции ничего не устанавливается.
- Обновление выполняется на хосте аналогично кнопке обновления в административной панели. `iobroker upgrade`, или `iobroker url` (для npm); агент ждет до 10 минут и сообщает результат. Когда pi-agent обновляется, он перезапускается и затем сообщает чату, работает ли новая версия (состояние). `update.pending` в это время).

## Сценарии

При **включенной функции «Агент может создавать и изменять скрипты»** (вкладка «Права на запись», по умолчанию отключена) агент записывает скрипты JavaScript-адаптера, например, «написать скрипт, который включает свет в зале на закате». Скрипт выполняется с правами JavaScript-адаптера, а не pi-agent: права на запись и режим симуляции не распространяются на него после запуска. Поэтому это предназначено для пользователей, которые изучают код перед подтверждением.

- `list_scripts` и `get_script` Прочитайте каждый сценарий. `save_script` создает или изменяет что-либо. `set_script_enabled` запускает или останавливает его. `revert_script` возвращает предыдущую версию (каждый вызов выполняется на одну версию дальше; после этого выполнение скрипта останавливается).
- Новые скрипты пишутся на JavaScript; TypeScript — по запросу ("пишите на TypeScript"). Существующий скрипт сохраняет свой язык.
- Агент записывает данные только в папку. `script.js.pi-agent` **Кроме того, изменение других скриптов** позволяет изменять и другие скрипты, включая глобальные. Скрипты Blockly и Rules остаются доступными только для чтения.
- Каждое сохранение, запуск, остановка и отмена подтверждаются отдельно. В чате администратора изменения отображаются построчно; в Telegram и MAX — в той мере, в какой это позволяет сообщение. В вопросе также указано, что обнаружил pi-agent в коде: `exec`, `require` доступ к файлам, изменения объектов, `sendTo` сетевые звонки и `setState` Поиск осуществляется в состояниях, выходящих за пределы прав на запись pi-agent, или по вычисленному идентификатору. Этот поиск является подсказкой, а не защитой.
- Новый скрипт остаётся остановленным до подтверждения его запуска. Запущенный скрипт немедленно перезапускается с новым кодом; так указано в задании. Синтаксис проверяется до того, как пользователю будет задан соответствующий вопрос; агент сначала исправляет ошибки. TypeScript теряет свои типы для этой проверки (Node.js). `stripTypeScriptTypes` Типы не проверяются, и `enum` или `namespace` Только компилятором JavaScript-адаптера при запуске скрипта.
- После запуска агент в течение нескольких секунд отслеживает лог экземпляра JavaScript и сообщает об ошибках скрипта.
- Голосом (а) `sendTo` Подтверждение скриптов (например, в диалогах ioBroker.assistant) осуществляется только с помощью **функции «Подтверждение скриптов голосом** », для которой требуется «Подтверждение текстом в диалогах sendTo». Код не зачитывается: вопрос называет скрипт, в одном предложении описывает его действие (написанное моделью) и перечисляет, что pi-agent обнаружил в коде.
- Предыдущие версии (по пять на каждый скрипт) хранятся в каталоге данных экземпляра и являются частью резервных копий диалогов.

## Долговременная память

Разговор запоминает всё сказанное, но сами собеседники не знают друг друга. Факты, которые должны иметь значение повсюду, попадают в долговременную память:

- Агент сохраняет факт с помощью инструмента. `remember` когда вы просите его об этом («помните: лампа в гостиной — hue.0.lamp3») или когда вы указываете ему постоянное предпочтение, он его удаляет. `forget`.
- Вся информация вносится в инструкции к каждому разговору: в мессенджерах, в чате администратора и т. д. `sendTo` Вызовы, например, ioBroker.assistant. Максимум 100 фактов, по 500 символов каждый, и 8000 символов в сумме.
- Факты находятся в штате. `pi-agent.0.memory.list` (JSON). Вы можете отредактировать его там; адаптер перенесет изменения. `memory.count` показывает, сколько их всего. Память является частью резервных копий разговоров.
- Память используется всеми, кто пишет агенту. Отключите её с помощью параметра «Долговременная память» в настройках. Никогда не оставляйте пароли или ключи в памяти; агенту дано указание этого не делать.

## Резервная копия переписки

Разговоры ведутся в `session.sqlite` в каталоге данных экземпляра, которого нет в резервной копии ioBroker. Вкладка « **Резервное копирование»** сохраняет их там, где они находятся:

- **Функция создания резервной копии** записывает согласованную, сжатую с помощью gzip копию хранилища вместе с данными о назначенных чатах мессенджера в папку хранилища. `pi-agent.0.storage/backups` (администратор → **Файлы** ). Резервные копии, созданные с помощью ioBroker и BackItUp, сохраняют эту папку. Агент продолжает работать, пока создаётся копия.
- **Автоматическое резервное копирование** : ежедневно (по умолчанию) или еженедельно, отсчет начинается с последнего резервного копирования, в том числе после перезагрузки; резервное копирование, которое должно быть выполнено, запускается через пять минут после начала. Параметр «Сохранять автоматические резервные копии» (по умолчанию 7) удаляет самые старые автоматические резервные копии; резервные копии, созданные вручную, и резервные копии никогда не удаляются.
- **Функция восстановления** заменяет диалоги выбранной резервной копией и перезапускает экземпляр. Текущие диалоги сохраняются в первую очередь как резервная копия. `pi-agent-prerestore-….sqlite.gz` Запросы, находившиеся в состоянии ожидания, отбрасываются.
- **Копирование на внешний сервер (SFTP)** : каждая резервная копия также копируется на другой компьютер, например, на NAS, с использованием самого протокола SFTP (без монтирования, без sudo). Загрузка записывается следующим образом: `.part` и переименовывается по завершении; можно закрепить отпечаток сервера. Используйте пользователя, который может записывать данные только в целевой каталог. Файл содержит полный текст переписки и не зашифрован на сервере.
- **Восстановление с внешнего сервера** , например, после новой установки: войдите в настройки SFTP, включите копирование, сохраните, затем выберите резервную копию на сервере.

штаты `backup.last`, `backup.size`, `backup.lastRemote` и `backup.remoteError` Показать последнюю резервную копию и последнюю копию.
