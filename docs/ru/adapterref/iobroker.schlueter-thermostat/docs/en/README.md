# ioBroker.schlueter-thermostat

Система подогрева пола **Schlüter DITRA-HEAT / OJ Microline WD5** (OWD5 / MWD5) в ioBroker — через облако поставщика и, при необходимости, **локально в вашей собственной сети** (в тестовом режиме).

---

## 🌍 Обзор

- 🌡 Температура в помещении и на полу, состояние отопления
- 🎯 Заданные значения и режимы регулирования (расписание, комфорт, ручной, ускорение, экономичный, отпуск, защита от замерзания)
- 📅 Еженедельное расписание, ⚡ потребление энергии
- 🖥️ Диспетчер устройств с отображением в реальном времени и компактными элементами управления
- 🔔 Уведомления (Telegram, Pushover, WhatsApp, электронная почта, Signal, Matrix, Synology Chat)
- 🏠 **Локальное управление (в стадии тестирования):** адаптер берет на себя роль шлюза поставщика — быстрее, и при желании без использования облачных сервисов.

---

## 🧠 Архитектура

```
                         ┌──────────────── Cloud (default) ─────────────────┐
ioBroker ── adapter ─────┤  OWD5 API (read) · OCD5 API (write)              ├── thermostat
            │            └──────────────────────────────────────────────────┘
            │
            └─ Local gateway (port 9513) ◄──── thermostat (redirected by a DNS record)
                  │
                  └─ Relay: forwards to the vendor cloud (the app keeps working)
```

Облачное и локальное подключение используют **одни и те же** состояния. Термостат, подключенный локально, получает свои значения оттуда — немедленно, а не путем опроса.

## 🚀 Быстрый старт

1. Установите адаптер и откройте экземпляр.
2. Введите учетные данные:

| Параметр                  | Примечание                             |
| ------------------------- | -------------------------------------- |
| Имя пользователя / Пароль | Вход в приложение Schlüter / OJ        |
| Ключ API                  | Обычно работает значение по умолчанию. |
| Идентификатор клиента     | По умолчанию: **3**                    |
| Интервал опроса           | По умолчанию: 60 с (минимум 10 с)      |

3. Сохранить – термостаты отображаются в `groups.<group>.thermostats.<thermostat>` и в Диспетчере устройств.

Для настройки локального управления см. [раздел «Локальное управление»](#-local-control) .

## 🧩 Веб-компонент

Адаптер обеспечивает работу веб-компонента **«Термостат»** (`<iob-schlueter-thermostat-card>` ( [ioBroker web-components](https://github.com/ioBroker/web-components) ). Такие хосты, как vis-2, devices или admin, предлагают его в своей палитре; он выглядит как карточка диспетчера устройств.

| Часть         | Содержание                                                                                                                                                                          |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Заголовок     | Название (номер термостата), группа (номер группы), серийный номер, онлайн/офлайн (красный цвет при офлайн-режиме)                                                                  |
| Показатели    | Те же значки, что и на карточке Диспетчера устройств: подключение, отопление, комната, этаж, заданная температура, режим, отпуск, энергия.                                          |
| − / +         | Изменяет заданное значение с шагом 0,5 °C; отправляется в **ручном** режиме через 1,5 с после последнего нажатия.                                                                   |
| Кнопки режима | **Функции «Расписание»** и **«Эконом»** запрашивают свои значения в диалоге; функции **«Комфорт»** , **«Ручной режим»** , **«Ускорение»** , **«Отпуск»** запрашивают свои значения. |

| Параметр  | Значение                                              |
| --------- | ----------------------------------------------------- |
| Пример    | экземпляр адаптера (пустой: `schlueter-thermostat.0`) |
| Термостат | термостат экземпляра (пусто: первый)                  |

Команды проходят через один и тот же процесс. `apply.<mode>.*` Состояние такое же, как и у всех остальных пользовательских интерфейсов. Пока термостат находится в облаке в автономном режиме (и не подключен локально), элементы управления отключены; в редакторе хоста в карту ничего не записывается.

| Хозяин     | Примечание                                                                                                                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Аура       | В настройках виджета установите **параметр «Кликнуть на компонент»** в значение « **Компонент»** ; по умолчанию Aura сохраняет клики по виджету, и элементы управления не реагируют.                                                            |

## 🔁 Опрос и резервный вариант

| Ситуация                                                        | Облачный опрос                                                        |
| --------------------------------------------------------------- | --------------------------------------------------------------------- |
| Нормальный                                                      | с заданным интервалом (по умолчанию 60 с)                             |
| Все термостаты подключены **локально.**                         | Реже, значения по умолчанию каждые 300 секунд – загружаются локально. |
| Облачное хранилище недоступно или **все** термостаты отключены. | Интервал увеличивается вдвое до 1 часа, но только в 12:00 и 00:00.    |
| Термостат снова доступен.                                       | немедленно вернуться к нормальному интервалу                          |

Термостат, подключенный локально, считается находящимся в сети, поэтому режим "только локально" не переключается обратно только потому, что облако не видит устройство.

## 🏠 Локальное управление

> **В процессе тестирования** – для пользователей, знакомых с DNS и именами хостов. Подтверждено на **OWD5** (прошивка 1013W220) во всех режимах. Серия WG4 (Северная Америка) поддерживается, но не тестировалась на реальном оборудовании. Будем рады отзывам.

Термостат поддерживает собственное соединение с **шлюзом устройства** производителя. DNS-запись перенаправляет его на хост ioBroker — на самом термостате ничего не меняется. Удаление DNS-записи возвращает всё как прежде.

### Режимы

| Режим                          | Приложение    | Управление через ioBroker | Без интернета                                                                                                         |
| ------------------------------ | ------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Выключенный**                | ✔             | через облако              | ✘                                                                                                                     |
| **Эстафета** ⭐                 | ✔ (синхронно) | местный, непосредственный | ✔ Адаптер автоматически переключается на реле не позднее чем через 1 минуту после восстановления интернет-соединения. |
| **Только для местных жителей** | ✘ (офлайн)    | местный, непосредственный | ✔                                                                                                                     |

### Настраивать

1. Присвойте хосту ioBroker **фиксированный IP-адрес** .
2. Перенаправление `owd5-sl003-thermostat.ojelectronics.com` к хосту ioBroker в вашем DNS (Pi-hole, AdGuard, маршрутизатор) (при необходимости проверьте имя хоста в DNS-журнале термостата):
   - **Рекомендуется использовать запись CNAME** с именем хоста ioBroker (например, `iobroker.lan` Хост сохраняет свое имя; простая запись (запись типа A) заставляет Pi-hole отображать хост ioBroker под именем термостата. Pi-hole: _Локальный DNS → Записи CNAME_ ; Pi-hole должен знать сам целевой объект (собственная запись DNS или DHCP).
   - В качестве альтернативы: запись `owd5-sl003-thermostat.ojelectronics.com` → **IP-адрес хоста ioBroker** .
3. Вкладка **«Локальные команды»** : режим **«Ретрансляция** », включить «Отправлять команды локально», сохранить.
4. **Перезагрузите** термостат.
5. Проверьте панель инструментов:<img src="../images/home.svg" width="20"> **1** = подключено.<img src="../images/home-warning.svg" width="20"> "Нет термостата" = DNS-запись не работает.

Кнопка **«Проверить DNS»** показывает, куда указывает имя с точки зрения ioBroker. Если ioBroker работает в Docker со своим собственным DNS, он может показывать «облако», хотя перенаправление работает для термостата.

### Полезно знать.

- **Запускаются локально:** расписание, ручной режим, комфорт, ускорение, экономичный режим, отпуск. Имя всегда передается через облако (в режиме только локального доступа не используется).
- **Если локальная команда завершается с ошибкой** , она автоматически отправляется через облако.
- **В режиме локального питания энергия** поступает не из облака; она рассчитывается как произведение времени нагрева на нагрузку.
- **Порт 9513** должен быть свободен и доступен для термостата (Docker: опубликовать порт, VLAN: брандмауэр).
- **Несколько термостатов:** одна DNS-запись для всех (пока не тестировалось на нескольких реальных устройствах).
- **Возвращение в облако:** режим «Выкл.», удалить DNS-запись, перезагрузить термостат. Если запись останется активной, адаптер выдаст предупреждение.
- **Безопасность:** любое устройство в сети может получить доступ к порту 9513 — используйте его только в доверенной сети.
