# ioBroker.millheater

## О

Он `millheater` Адаптер интегрирует нагреватели Mill в ioBroker, используя локальный API нагревателя.

Адаптер предназначен для интеллектуальной автоматизации отопления. Он предоставляет значения и элементы управления, необходимые для работы устройств Mill из ioBroker, например, для использования избыточной мощности фотоэлектрических (PV) систем отопления.

Для этой цели выберит&#x435;** `Control individually` ** В этом режиме обогреватель работает в соответствии с заданной ioBroker целевой температурой, а не недельной программой или таймерами. В зависимости от типа обогревателя, ioBroker также может регулировать доступную мощность обогрева. Это позволяет, например, использовать избыточную мощность солнечных батарей для отопления, автоматически регулируя уровень обогрева в соответствии с имеющимся избытком.

Адаптер взаимодействует с нагревателем напрямую по локальной сети. Для связи между ioBroker и нагревателем не требуется подключение к облаку.

В настоящее время адаптер поддерживает нагреватели Millheat третьего поколения.

## Функции

- Локальная связь с устройствами Mill; подключение к облаку не требуется.
- Управляйте несколькими фрезерными станками в одном экземпляре адаптера.
- Поддержка конвекционных, масляных и панельных обогревателей, а также Wi-Fi-розеток.
- Автоматическое определение типа подключенного устройства
- Идентификация устройства и обнаружение необходимости его замены с использованием MAC-адреса.
- Отдельный статус и управление для каждого устройства.
- Температура в читальном зале, мощность обогрева и состояние устройств.
- Установка целевой температуры и режима работы.
- Считывание и изменение калибровки температуры
- Управление мощностью для масляных и панельных нагревателей с учетом специфики устройства.
- Дополнительное управление режимами работы Wi-Fi-розеток
- Разделите интервалы быстрого и медленного опроса.
- Дополнительный опрос при выключенном обогревателе.
- Статус подключения для каждого устройства
- Подходит для внешней автоматизации, включая управление избыточным напряжением фотоэлектрических систем.

## Требования

- ioBroker
- Поддерживаемые устройства Mill Generation 3 с доступным локальным API.
- Устройства Mill и ioBroker должны быть доступны по локальной сети.
- Node.js 22 или более поздняя версия, в зависимости от требований установленной версии ioBroker.

## Конфигурация

Настройте устройства Mill в списке устройств адаптера. Введите IP-адрес или имя хоста для каждого устройства. Один экземпляр адаптера может управлять несколькими устройствами.

Используйте фиксированный IP-адрес, резервирование DHCP или имя хоста, которое разрешается в имя устройства. Если устройство получает новый IP-адрес, обновите его настроенный адрес. MAC-адрес используется для идентификации физического устройства независимо от его сетевого адреса.

### Параметры конфигурации

| Параметр                  | Описание                                                         | По умолчанию |
| ------------------------- | ---------------------------------------------------------------- | -----------: |
| Адрес устройства          | IP-адрес или имя хоста каждого устройства Mill                   |            — |
| Таймаут HTTP              | Максимальное время ожидания ответа от API, в секундах.           |            5 |
| Быстрый интервал опроса   | Интервал обновления для часто изменяющихся значений, в секундах. |           30 |
| Медленный интервал опроса | Интервал обновления для значений, изменяющихся реже, в секундах. |        86400 |
| `pollWhenOff`             | Продолжайте опрос, пока обогреватель выключен.                   |            — |

Интервалы ожидания и опроса должны быть целыми числами. Адаптер проверяет значения в административном интерфейсе, а также при запуске:

- Тайм-аут HTTP: от 1 до 60 секунд
- Быстрый интервал опроса: как минимум равен времени ожидания HTTP плюс 1 секунда; максимум 3600 секунд (1 час).
- Интервал медленного опроса: как минимум равен интервалу быстрого опроса плюс время ожидания HTTP; максимум 86 400 секунд (24 часа).

### Опрос при выключенном обогревателе.

Он `pollWhenOff` Эта опция определяет, будет ли адаптер продолжать запрашивать информацию у нагревателей, даже когда они выключены.

- **Включено:** Опрос продолжается, даже когда нагреватель выключен. Это уместно, когда нагреватель может также включаться или выключаться вне ioBroker.
- **Отключено:** Как только адаптер обнаружит, что нагреватель выключен, опрос этого нагревателя прекращается. В этом режиме снова включите нагреватель через адаптер. Внешнее включение не обнаруживается, пока опрос остановлен.

Это сделано намеренно. Отключение опроса в выключенном состоянии предназначено для установок, где адаптер отвечает за управление нагревателем. Если требуется внешнее управление, включите эту опцию.

## Поддерживаемые типы нагревателей

Адаптер поддерживает следующие типы устройств Mill Generation 3:

- Конвекционные обогреватели
- Масляные обогреватели
- Панельные обогреватели
- розетки Wi-Fi

Адаптер определяет тип устройства на основе информации, предоставляемой API Mill, и, при необходимости, предоставляет соответствующие настройки, специфичные для данного устройства.

### Масляные обогреватели

Масляные нагреватели обеспечивают состояние, пригодное для записи. `settings.heating_level_percentage`:

| Ценить | Уровень отопления |
| -----: | ----------------- |
|   `40` | 40 %              |
|   `60` | 60 %              |
|  `100` | 100 %             |

Этот параметр регулирует выбранный процент от номинальной мощности нагревателя и может быть скорректирован системой автоматизации ioBroker в зависимости от доступного избытка солнечной энергии.

### Панельные обогреватели

Панельные нагреватели обеспечивают готовность к записи. `settings.limited_heating_power` Он принимает целочисленные значения из `10` к `100` и устанавливает максимально доступную мощность отопления в процентах.

### розетки Wi-Fi

Разъемы Wi-Fi обеспечивают состояние, доступное для записи. `settings.additional_mode` Он принимает целочисленные значения из `0` к `4`.

## Режимы работы

Он `control-status.operation_mode` Состояние поддерживает следующие значения:

| Ценить                 | Описание                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| `Off`                  | Устройство выключено.                                                                              |
| `Weekly program`       | Обогреватель работает по недельному расписанию.                                                    |
| `Independent device`   | Автономная работа нагревателя                                                                      |
| `Control individually` | Обогреватель поддерживает заданную температуру без использования таймеров или недельной программы. |

Для управления через ioBroker, особенно для автоматизации избыточной солнечной энергии, используйт&#x435;** `Control individually` ** Это позволяет ioBroker регулировать целевую температуру и мощность нагрева, специфичную для данного устройства, без вмешательства недельной программы нагревателя или таймеров.

Например, система управления избыточной мощностью фотоэлектрических систем может использовать доступную избыточную мощность для выбора соответствующего уровня обогрева:

- Низкий избыток фотоэлектрической энергии → более низкий уровень отопления
- Больший избыток фотоэлектрической энергии → более высокий уровень нагрева
- Отсутствие существенного избытка фотоэлектрической энергии → уровень отопления можно снова снизить.

## Идентификация устройства

Адаптер использует MAC-адрес для идентификации каждого физического устройства Mill. IP-адрес или имя хоста используется для связи с устройством; это не является его идентификатором.

- Один и тот же MAC-адрес идентифицирует одно и то же физическое устройство, даже если его настроенный IP-адрес изменяется.
- Другой MAC-адрес в заданном адресном пространстве рассматривается как другое устройство.
- Ранее известные устройства можно будет распознать повторно по их MAC-адресу.
- Если MAC-адрес отсутствует или недействителен, сохраняется уже установленный идентификатор устройства.

Адаптер не выполняет автоматическое сканирование сети на наличие устройств с неизвестными адресами. Если IP-адрес устройства изменяется, обновите его адрес в списке устройств. После этого MAC-адрес позволит адаптеру корректно распознать физическое устройство.

## Локальный API

Адаптер взаимодействует напрямую с устройствами Mill через их локальный HTTP API. Для локальной связи учетная запись в облаке Mill не требуется.

Локальный API, используемый этим адаптером, описан компанией Mill International AS в их документации.

[Документация по REST API третьего поколения](https://github.com/Mill-International-AS/Generation_3_REST_API) .

Доступность отдельных функций зависит от типа устройства.

## Опрос

Адаптер использует два независимо настраиваемых интервала опроса:

- Функция **быстрого опроса** обновляет часто изменяющиеся значения, такие как температура в помещении, мощность обогрева, режим работы и целевая температура.
- **Медленный опрос** обновляет информацию, которая обычно изменяется реже, например, данные об устройстве и калибровку температуры.

Каждое устройство обрабатывается независимо. Заданные интервалы определяют частоту обновления его значений. Если обновление занимает больше времени, следующий цикл начинается позже; циклы опроса не накапливаются.

Он `pollWhenOff` Эта опция определяет, будет ли продолжаться опрос устройства, когда оно выключено. Подробнее см. [раздел «Опрос при выключенном нагревателе»](#polling-while-a-heater-is-switched-off) .

## Ценности в письменной форме

Записываемые точки данных можно контролировать с помощью состояний ioBroker. Адаптер проверяет значения перед отправкой их на устройство и подтверждает успешные команды.

Действуют следующие ограничения:

- **Мощность масляного обогревателя:** `40`, `60` или `100`
- **Режим работы:** Один из поддерживаемых режимов, перечисленных выше.
- **Ограничение мощности панельного нагревателя:** целое число из `10` к `100`
- **Целевая температура:** от 5 °C до 35 °C
- **Смещение калибровки температуры:** от -30 °C до +30 °C
- **Дополнительный режим Wi-Fi-розетки:** Целочисленный из `0` к `4`

Изменять специфические для устройства настройки можно только на устройствах, которые их поддерживают. Недопустимые значения и неудачные команды не учитываются как успешные изменения состояния.

### Целевая температура

Температуру можно изменить даже при выключенном нагревателе.

После успешного изменения температуры адаптер немедленно подтверждает новое значение в ioBroker.

Когда нагреватель выключен, измененная целевая температура может не возвращаться. API возвращает настроенную целевую температуру снова после включения нагревателя. Это означает, что значение, отображаемое в `control-status.set_temperature` Возможно, вновь установленное значение не сразу отобразится после выключения нагревателя.

Исходный код написан на TypeScript.

## Руководящие принципы разработки

Адаптер соответствует рекомендациям ioBroker по разработке и кодированию. Для объектов состояния адаптер использует официальные роли состояния ioBroker.

### Обновления по штатам

Адаптер использует `setStateChanged()` для получения актуальной информации о состоянии дел в штате, где это возможно.

Это позволяет избежать ненужных записей в базу данных и событий изменения состояния, когда значение не изменилось. Это особенно полезно для данных устройства, которые регулярно опрашиваются.

Адаптер работает по следующим принципам:

- Значения параметров устройства записываются только при их изменении.
- Команды записи, успешно обработанные системой, подтверждаются немедленно. `ack = true`.
- Обновления состояния соединения записываются только при изменении состояния соединения.
- Недопустимые или отсутствующие значения API никогда не перезаписывают существующие состояния.
