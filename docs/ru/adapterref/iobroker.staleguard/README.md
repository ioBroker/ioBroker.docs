# ioBroker.staleguard

## Адаптер Staleguard для ioBroker

### Что это делает

Staleguard сообщает вам, когда состояние ioBroker перестает получать данные. Вы отмечаете любое состояние в обозревателе объектов и устанавливаете для него крайний срок. Если состояние остается без ответа дольше этого срока, Staleguard отправляет уведомление ioBroker, может перезапустить экземпляр адаптера, которому принадлежит это состояние, и сообщает, когда данные снова начнут поступать.

Он отслеживает состояния, а не устройства или адаптеры, поэтому работает с любым адаптером и с вашими собственными скриптами. Типичные случаи:

- облачный адаптер продолжает `info.connection` Да, это правда, но его значения перестали меняться;
- Датчик Shelly, Zigbee или радиодатчик перестал передавать данные;
- Скрипт перестал записывать состояние своего пульса.

### Настраивать

1. Установите адаптер и создайте экземпляр. Настройки по умолчанию подходят для большинства систем.
2. Откройте **«Объекты»** , щелкните значок шестеренки (пользовательские настройки) состояния, за которым вы хотите следить, и включите параметр **«Включено»** в настройках. `staleguard.0` раздел.
3. Задайте поля:

| Поле                                  | Диапазон                              | По умолчанию                   | Значение                                                                                                   |
| ------------------------------------- | ------------------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| Срок выполнения (мин)                 | 1–10080                               | 60                             | Сигнал тревоги срабатывает при отсутствии признаков жизни в течение длительного времени (максимум 7 дней). |
| Признак жизни                         | Любое обновление / изменение значения | Есть ли какие-либо обновления? | Какая временная метка учитывается, см. ниже.                                                               |
| Перезапуск экземпляра при каждом сбое | 0–5                                   | 0                              | перезапустить экземпляр-владелец, 0 = выключено                                                            |

Настройки экземпляра:

| Параметр                       | Диапазон | По умолчанию | Значение                                                                |
| ------------------------------ | -------- | ------------ | ----------------------------------------------------------------------- |
| Интервал проверки (с)          | 10–600   | 60           | Как часто проверяются все отслеживаемые штаты?                          |
| Перезапустить блокировку (мин) | 10–1440  | 60           | минимальное время между двумя перезапусками одного и того же экземпляра |

Неверные настройки для каждого состояния не заменяются значениями по умолчанию: наблюдение отклоняется и отображается в виде уведомления, чтобы вы заметили ошибку.

### Любые обновления или изменения значений

- **При каждом обновлении** проверяется время последней записи. `ts` Используйте его для датчиков и скриптов, которые записывают данные только тогда, когда у них появляется что-то новое.
- **При изменении значения** проверяется время последнего изменения значения. `lc` Облачные адаптеры часто перезаписывают одно и то же значение новой меткой времени при каждом опросе, поэтому замороженные облачные данные отображаются только в этом режиме.

Два фактора определяют, какой режим подходит:

- Многие адаптеры записывают состояние только тогда, когда изменяется его значение. Для таких состояний **любое обновление** ведет себя как **изменение значения** : неизмененное значение остается. `ts` тоже остались нетронутыми.
- Каждая запись имеет значение, а также каждая команда (`ack: false`) из скрипта или визуализации. Команда, отправленная неработающему устройству, поддерживает его состояние в обоих режимах, поэтому следите за состоянием, которое сообщает само устройство.

Значения, которые действительно остаются постоянными в течение длительного времени (мощность солнечных батарей ночью, уровень заряда припаркованного автомобиля), вызывают ложные срабатывания при **изменении значения** . Для замороженных облачных данных следите за меткой времени, которую предоставляет само облако. `lastSeen` или аналогичное), но с **изменением значения** .

После запуска Staleguard для каждого отслеживаемого состояния устанавливается полный срок, после которого данные могут быть переданы в систему, поэтому перезагрузка хоста не вызовет всплеска оповещений для состояний, которые уже устарели.

### Уведомления

Staleguard генерирует уведомления ioBroker в рамках данной области видимости. `staleguard` Они отображаются в области уведомлений администратора; [менеджер уведомлений](https://github.com/foxriver76/ioBroker.notification-manager) пересылает их в Telegram, электронную почту и другие мессенджеры. Сам Staleguard не содержит кода доставки.

| Категория                 | Степень тяжести | Когда                                                                                        |
| ------------------------- | --------------- | -------------------------------------------------------------------------------------------- |
| Государство молчит        | тревога         | Один из штатов не уложился в установленный срок; последняя попытка перезапуска не помогла.   |
| Государственная поддержка | информация      | молчаливое государство снова посылает                                                        |
| Проблема с часами         | уведомить       | Состояние не существует или не имеет значения, параметр недействителен, перезапуск не удался |

Состояние сообщается один раз, когда оно затихает, и один раз, когда оно восстанавливается, а не при каждой проверке. Все состояния, изменяющиеся в одной проверке, отправляют одно уведомление на категорию, поэтому неисправный шлюз с 40 датчиками отправляет одно сообщение, а не 40; длинные списки обрезаются после 20 записей с подсчетом остальных. Состояние, получившее свое первое значение, не сообщается как восстановившееся, как и затихшее состояние, которое снова становится нормальным только потому, что вы повысили его крайний срок или изменили признаки активности. Затишье продолжительностью два часа и более указывается в часах, начиная с двух дней — в днях. Тексты пишутся на немецком языке в немецкой системе, в остальных случаях — на английском.

### Перезапуск экземпляра

Если **количество перезапусков экземпляра при каждом отключении** превышает 0, Staleguard перезапускает экземпляр адаптера, к которому относится данное состояние. `<adapter>.<n>`):

- Первый перезапуск происходит, как только состояние становится молчаливым;
- Каждый последующий перезапуск наступает через один полный срок после предыдущего, если государство по-прежнему хранит молчание;
- Несколько состояний молчания одного экземпляра приводят максимум к одному перезапуску на каждую **блокировку перезапуска** ;
- После последней попытки появляется еще одно уведомление о том, что дальнейших попыток не последовало;
- Отключенный экземпляр никогда не запускается, и Staleguard никогда не перезапускается;
- Сообщается о неудачной перезагрузке, которая, тем не менее, засчитывается как попытка.

Перезапуск возможен только для состояний другого экземпляра адаптера, а не для других. `0_userdata`, `alias` или `system` штатов.

Для адаптера в режиме расписания (он работает по расписанию, например) `ical`), перезапуск запускает его немедленно. Такой адаптер записывает свое состояние только во время работы, поэтому установите крайний срок значительно выше интервала его расписания; в противном случае обычная пауза между двумя запусками вызовет тревогу.

Перезапуск всегда затрагивает весь экземпляр. Для сигнала подтверждения работоспособности, записанного скриптом, `javascript.0` Перезапуск перезапускает все скрипты этого экземпляра; оставьте перезапуски отключенными, если только вам это не нужно.

### Штаты

| Состояние                            | Тип        | Значение                                    |
| ------------------------------------ | ---------- | ------------------------------------------- |
| `staleguard.0.summary.watched`       | число      | количество наблюдаемых штатов               |
| `staleguard.0.summary.stale`         | число      | количество молчащих состояний               |
| `staleguard.0.summary.list`          | JSON       | `[{id, name, status, since}]` из всех часов |
| `staleguard.0.watches.<id>.stale`    | логический | `true` = молчаливый                         |
| `staleguard.0.watches.<id>.status`   | нить       | `ok`, `stale` или `missing`                  |
| `staleguard.0.watches.<id>.since`    | число      | время последнего изменения статуса          |
| `staleguard.0.watches.<id>.restarts` | число      | попытки перезапуска во время текущего сбоя  |

`<id>` идентификатор отслеживаемого состояния с `.` заменено `__` и все символы, кроме букв и цифр ASCII. `_` и `-` заменено `_` Все состояния доступны только для чтения. При отключении наблюдения его канал удаляется.

### Пределы

- Не более 5000 отслеживаемых государств; дальнейшие записи отклоняются и сообщаются.
- Объект, за которым ведется наблюдение и который удаляется во время выполнения, показывает `missing` до перезагрузки списка отслеживаемых каналов (перезапуск Staleguard или изменение пользовательских настроек). После этого список отслеживаемых каналов и сам канал удаляются без дальнейшего уведомления.
- Отметка времени в будущем (перевод часов назад) служит для отслеживания. `ok` пока часы не догонят.
