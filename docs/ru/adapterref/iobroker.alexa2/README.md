# ioBroker.alexa2

**Этот адаптер использует библиотеки Sentry для автоматического сообщения разработчикам об исключениях и ошибках в коде.** Более подробную информацию, а также инструкции по отключению отправки сообщений об ошибках см. [в документации Sentry-Plugin](https://github.com/ioBroker/plugin-sentry#plugin-sentry) ! Система отчетности Sentry используется начиная с js-controller 3.0.

Этот адаптер позволяет дистанционно управлять устройствами Alexa (Amazon Echo).

Огромная благодарность soef за первую версию адаптера, а также Hauke и ruhr70 за идеи в их скриптах с форума ioBroker (особенно за обновления о ходе выполнения)! Также большое спасибо meicker за помощь в документировании всего этого и многочисленным пользователям форума ioBroker за поддержку в тестировании!

Подробная информация. Голосовое оповещение и объявление: Введите здесь то, что вы хотите, чтобы Alexa сказала. Вы также можете отрегулировать громкость Alexa, указав процент перед текстом. Пример: 10;Alexa говорит Alexa с громкостью 10%, а 100;Alexa — 100%. Обычно за одну команду произнесения можно отправить только 250 символов. Используя точку с запятой, вы можете написать столько символов, сколько хотите, при условии, что вы разделяете 250 символов точкой с запятой. Alexa будет произносить текст один за другим с небольшим перерывом. Вы также можете использовать громкость вместе с другими блоками по 255 символов, написав #Volume;#Block1;#Block2 и т. д. Громкость, установленная здесь, будет использоваться вместо заданной громкости произнесения.

Частично звуки также работают из <https://developer.amazon.com/en-US/docs/alexa/custom-skills/ask-soundlibrary.html> . Укажите это в speak или ssml.`<audio src="soundbank://soundlibrary/animals/amzn_sfx_bear_groan_roar_01"/>` Подробности и обсуждение по ссылке: <https://forum.iobroker.net/topic/27509/ssml-audio>

## Отправляйте последовательности команд для устройств Alexa через сообщения.

Все команды для устройств Alexa могут отправляться через адаптер как на отдельные устройства, так и на группы. Адаптер поддерживает отправку этих команд и, при необходимости, также объединяет их для установки определенного уровня громкости перед голосовым выводом и восстановления исходного уровня громкости после него.

Если вы хотите отправлять пользовательские последовательности на устройства Alexa, вы можете создать Routine и запускать его также через состояния.

Если этого недостаточно для обеспечения гибкости, начиная с версии 3.14.0, адаптер предлагает способ отправки команд посредством сообщений.

Вы предоставляете структуру массива, которая будет преобразована в команды. Для одного элемента массива доступны два типа параметров:

**Команда**

```json
{
    "command": "speak", // command like the state name in Commands states
    "value": "This is a test speak.", // value like value you set on state
    "device": "..." // optional: serialNumber of the device to send this command to
}
```

**Определение последовательности**

```json
{
    "sequenceType": "...", // "SerialNode" or "ParallelNode"
    "nodes": [...] // array of commands or sequences
}
```

Отправка сообщения, например, с помощью JavaScript-адаптера, выглядит следующим образом:

```javascript
adapter.sendTo(
    "alexa.0", // target
    "sendSequenceCommand", // command
    { // value
        "deviceSerialNumber": "...", // Serial number of one device to get Meta data which will be used if no device is pecified on the commands
        "sequenceNodes": [...], // list of sequences or commands
        "sequenceType": "SerialNode" // "SerialNode" or "ParallelNode" for the provided sequenceNodes on main level. Default is "SerialNode"
    }, (err, res) => {
        console.log(err);
        console.log(JSON.stringify(res));
    }
);
```

Когда команды выполняются параллельно в режиме "ParallelNode", что в основном имеет смысл для отправки команд на разные устройства, команды в режиме "SerialNode" выполняются одна за другой — **об этом заботится и обрабатывает это Amazon, а не адаптер!**

Возможна следующая структура:

```json
... // use ParallelNode on main level
"sequenceNodes": [
    {
        "sequenceType": "SerialNode",
        "nodes": [
            {
                "command": "speak",
                "value": "This is a test speak.",
                "device": "DeviceA"
            },
            {
                "command": "speak",
                "value": "This is a second test speak.",
                "device": "DeviceA"
            }
        ]
    },
    {
        "sequenceType": "SerialNode",
        "nodes": [
            {
                "command": "speak",
                "value": "This is a test speak.",
                "device": "DeviceB"
            },
            {
                "command": "speak",
                "value": "This is a second test speak.",
                "device": "DeviceB"
            },
            {
                "sequenceType": "ParallelNode",
                "nodes": [
                    {
                        "command": "flashbriefing",
                        "device": "DeviceC"
                    },
                    {
                        "command": "flashbriefing",
                        "device": "Device B"
                    }
                ]
            }
        ]
    }
]

```

## Поиск неисправностей

### Проблема с определением файлов cookie при использовании двухфакторной аутентификации на основе SMS.

Если вы все еще используете двухфакторную аутентификацию по SMS/электронной почте, то этот способ может не работать. Пожалуйста, обновите метод двухфакторной аутентификации/одноразового пароля в настройках Amazon до текущей версии! Неработающий способ также может означать появление ошибки 404/Страница не найдена. В этом случае проверьте и обновите настройки OTP!

### Приложение Alexa открывается, когда я пытаюсь войти в систему.

Если вы откроете URL-адрес прокси-сервера с мобильного устройства, на котором также установлено приложение Alexa, возможно, это не сработает, поскольку Amazon может открыть приложение Alexa. Поэтому, пожалуйста, используйте устройство или компьютер, на котором приложение Alexa не установлено!

### На экране появляется страница с QR-кодом, который нужно отсканировать.

Если при вводе URL-адреса прокси вы видите страницу с сообщением о том, что "alexa.amazon.xx устарела" и вам следует использовать приложение Alexa, а также QR-код, это означает, что вы обращаетесь к URL-адресу прокси с другим IP-адресом/доменным именем, отличным от указанного в настройках "собственный IP-адрес прокси", или вы изменили IP-адрес, отображаемый в конфигурации адаптера.

Параметр "собственный IP-адрес" **должен** совпадать с IP-адресом/доменным именем, которое вы используете для вызова прокси-сервера!

### Проблемы с определением файлов cookie через электронную почту/пароль.

Иногда Amazon использует странные проверки при обнаружении неожиданного трафика на странице входа. Это может привести к проблеме, когда для авторизации необходимо ответить на капчу. Чаще всего, капчу нужно ответить один раз, после чего авторизация работает без капчи.

Если вам нужно ответить на подобную капчу, попробуйте сделать следующее:

- Используйте распространённый браузер (например, Chrome).
- Отключить JavaScript!
- Удалите все файлы cookie, которые могут быть связаны с Amazon, или используйте режим приватного просмотра/инкогнито в браузере.
- позвоните по адресу <https://alexa.amazon.de>
- Вы должны увидеть форму авторизации (обычно она отображается в старых мобильных браузерах).
- Войдите в систему, используя свои учетные данные Amazon, в том месте, где зарегистрировано устройство Echo/Alexa.
- Возможно, вам потребуется войти в систему дважды или решить капчу.
- В итоге вы должны увидеть URL-адрес " <https://alexa.amazon.de/spa/index.html> ", но без какого-либо реального содержимого (поскольку JavaScript по-прежнему отключен), НО ЭТО СОВЕРШЕННО НОРМАЛЬНО!!!!
- Теперь попробуйте снова получить печенье.
- Если это по-прежнему не работает, повторите попытку, проверьте значения User-Agent и accept-Language в вашем браузере и используйте их в адаптере при следующей попытке.

Кроме того, заголовок Accept-Language-Header (по умолчанию "de-DE") должен соответствовать вашему языку/языку браузера/языку страницы Amazon, на которую вы входите.

Вы также можете поэкспериментировать с User-Agent и выбрать тот, который лучше соответствует типу используемой вами системы. Например, сообщается, что использование User-Agent "Mozilla/5.0 (X11; Linux x86\_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/51.0.2704.103 Safari/537.36" работает лучше, когда ioBroker запущен в системе Linux.

Все эти параметры можно переопределить в конфигурации адаптера.

### Подключение с помощью кнопки "Push" не работает.

Иногда из-за слишком большого количества попыток подключения Amazon может заблокировать конечную точку push-уведомлений для определенного IP-адреса и «устройства».

Если соединение Push так и не устанавливается, можно попробовать следующее:

- удалить экземпляр адаптера
- Проверьте наличие файлов типа /opt/iobroker/node\_modules/iobroker.alexa2/formerDataStore\*.json — если они существуют, удалите их.
- добавить новый экземпляр и получить новый cookie

Тогда всё должно снова заработать.

### В моем списке устройств Echo слишком много устройств типа «Приложение/Это устройство».

Адаптер считывает все данные, которые предоставляет Amazon. Иногда в этом списке остаются неиспользуемые и старые приложения или другие подключения. Чтобы очистить этот список, необходимо зайти на сайт Amazon и удалить устройства оттуда.

Ссылка: <https://www.amazon.de/hz/mycd/digital-console/devicedetails?deviceFamily=ALEXA_APP>

После удаления неиспользуемого устройства перезагрузите адаптер, чтобы удалить его и там.

### 🌍 Региональная конфигурация Amazon

У некоторых пользователей при первой настройке адаптера могут возникать сбои.\
&#x20;Часто это происходит из-за того, что адаптер **предварительно настроен для немецкого региона Amazon (amazon.de)** .\
&#x20;Если ваша учетная запись Alexa зарегистрирована на другой торговой площадке Amazon, вам необходимо обновить несколько настроек, чтобы адаптер взаимодействовал с правильными региональными конечными точками.

Если эти значения не скорректированы, аутентификация и cookie могут работать, но при получении данных о ваших устройствах возникнет ошибка, что приведет к ошибкам запуска адаптера и получению сигнала завершения TERMINATE\_YOURSELF.

Для исправления региональных настроек перейдите по ссылке:`Instances > alexa2.x > Settings > Cookie` и настройте значения, как показано ниже.

| Регион / Страна     | Базовый URL-адрес Alexa | Принять язык | Файл cookie URL Amazon |
| ------------------- | ----------------------- | ------------ | ---------------------- |
| **Франция** 🇫🇷    | `alexa.amazon.fr`       | `fr-FR`      | `amazon.fr`            |
| _(Добавить еще...)_ |                         |              |                        |

Если ваш регион отсутствует в списке, и вы обнаружите соответствующее значение, не стесняйтесь дополнить эту документацию своими выводами.
