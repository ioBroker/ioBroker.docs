# Начало работы и тест первого запуска

В этом руководстве подробно описан весь процесс установки до первого нажатия кнопки. Оно намеренно краткое и на каждом этапе объясняет, как определить, что шаг был выполнен успешно. Полный тест приемки находится в...[`test-plan.md`](/#/docs/adapterref/iobroker.time-tracker/docs/en/test-plan.md) .

## 1. Требования

- Экземпляр ioBroker с js-контроллером (CI проверяет соответствие реальному контроллеру), Node ≥ 22
- свободный TCP-порт (по умолчанию) `8092`)
- Для **устанавливаемого PWA** и сервис-воркера: HTTPS — либо сам адаптер (настройка **«Использовать HTTPS»** , шаг 3), либо обратный прокси (nginx/caddy), см. README, раздел «HTTPS и обратный прокси». Для простого функционального тестирования, `http://<host>:8092` этого достаточно
- Дополнительно: планшет или телефон для терминала киоска, NFC-метка для T14/T15.

## 2. Установите

Адаптер доступен в **npm** — обычный способ установки — через административную панель ioBroker или через npm. **Экземпляр `time-tracker.0` создается автоматически.**

- **Администратор:** вкладка _«Адаптеры»_ → найдите _time-tracker_ ; если адаптера нет в списке, используйте символ **«Установить с пользовательского URL»** , вкладка **npm** и введите имя пакета. `iobroker.time-tracker`.
- **Командная строка:** `iobroker install iobroker.time-tracker` (Также создает экземпляр — чтобы создать его отдельно:) `iobroker add time-tracker`).

**Проверка:** в журнале написано `web interface found at …/www`, `API listening on http://127.0.0.1:8092/api` и `API routes: …`; государство `time-tracker.0.info.connection` является `true`.

> **Только для разработчиков:** репозиторий **не** содержит `build/` и `www/` (Веб-приложение уже создано), поэтому ioBroker не может запустить клон в текущем виде. `cannot find start file!`). Соберите проект один раз и используйте **сервер разработки** :
>
> ```bash
> npm ci
> npm run install:pwa    # dependencies of the web app
> npm run build:pwa      # web app → www/
> npm run build          # adapter → build/
> npm run dev-server     # local ioBroker with the adapter
> ```

## 3. Настройте экземпляр.

В настройках экземпляра (вкладки _«Общие»_ , _«Безопасность»_ , _«Миграция и резервное копирование»_ ):

1. Установите **секретный ключ сессии** и **секретный ключ ссылки на значок (HMAC)** (оба хранятся в зашифрованном виде; без секретного ключа HMAC подписанные ссылки на значки отключаются). Если **секретный ключ сессии** остается пустым, адаптер генерирует его при первом запуске и сохраняет в файле. `session-secret` рядом с базой данных — таким образом, сессии и токены CSRF сохраняются после перезапуска. Запись в этом поле всегда имеет приоритет и позволяет осуществлять целенаправленную ротацию.
2. Проверьте порт и адрес привязки (`127.0.0.1` = только для локального доступа, `0.0.0.0` = LAN — преднамеренное согласие). Ссылка в строке экземпляра (шаг 4) соответствует именно этим двум значениям.
3. Проверьте часовой пояс (`Europe/Berlin`), язык по умолчанию и страна праздника.
4. Установите **пароль для запуска первого администратора** — или оставьте его пустым: в этом случае в журнал **один раз** будет записан случайный пароль. `info.lastError` (остается пустым, если все прошло без проблем). Это значение также учитывается при вводе **после** первого запуска: пока первый администратор еще не изменил пароль запуска (приложение запрашивает изменение при первом входе в систему), адаптер устанавливает настроенный пароль при **каждом** запуске и сообщает об этом в журнале. `… exists already and still has its start password - it was set from the instance settings now` Если пароль уже был изменен, настройка **не вступит в силу** , и адаптер **выдаст предупреждение** :`the configured start password is not
   used` — затем очистите поле (администратор меняет пароль в собственном профиле приложения) или восстановите резервную копию, в которой все еще хранится пароль запуска. При каждом запуске сообщается ровно об одном из этих случаев — «тихий» экземпляр больше не существует.
5. Дополнительно: **включить киоск-терминал** и сохранение резервных копий.
6. HTTPS без прокси: включите параметр **«Использовать HTTPS»** и выберите сертификат и ключ из коллекции сертификатов ioBroker ( **Администрирование → Настройки → Сертификаты** ). Если сертификат отсутствует, приложение останется выключенным — скрытого переключения на HTTP **не** происходит; причина указана в журнале.
7. При использовании прокси-сервера: включите параметр « **Доверять обратному прокси-серверу»** (в противном случае...). `X-Forwarded-*` игнорируется).

## 4. Первый вход в систему

Откройте веб-приложение (`http://<host>:8092/`) — удобнее: нажмите на символ в строке `time-tracker.0` Список **экземпляров** администратора («Открыть приложение для отслеживания времени»); он ведет на тот же адрес, сформированный из хоста и порта настроек экземпляра. Затем войдите в систему, используя логин администратора и пароль запуска. Сервер немедленно запросит **смену пароля** — PWA отобразит для этого отдельный экран. После этого:

1. **Администрирование → Пользователи** : создайте учетные записи сотрудников (логин, имя, пароль, роль) и присвойте каждому **PIN-код для пропуска** (4–8 цифр), чтобы он мог отмечаться с помощью PIN-кода на киоске. В **разделе «Фото»** вы сохраняете фотографию сотрудника (PNG/JPEG/WEBP/GIF размером до 256 КБ). Она отображается на плитках экрана присутствия и на киоске; без фотографии интерфейс отображает заглушку. В **рабочем профиле** сотрудника **поле «Рабочее время» на карточке присутствия** отображает рабочее время за сегодняшний день на его плитке. `1:23` без удара `0:00` Карта видна всем, даже **до** ввода PIN-кода, поэтому администрация решает, как ее использовать для каждого сотрудника — по умолчанию она **отключена** .
2. **Администрирование → Терминалы** : создайте терминал (требуется PIN-код), **скопируйте токен устройства** и откройте отображаемый адрес. `…/terminal/<token>/` На планшете — это был этап работы киоска Т4. Без **PIN-кода устройство требовало** ввода PIN-кода: достаточно было отсканировать бейдж или выбрать имя. Неправильный PIN-код по-прежнему отклонялся.
3. **Администрирование → Настройки** : установить `report_font_path` в Юникод `.ttf` /`.otf` если заявления должны быть напечатаны на **языке ru** , **uk** или **zh-cn** (в противном случае экспорт будет отклонен). `report_font_missing`).
4. **Администрирование → Исправления** : просмотрите отметки времени сотрудника и выровняйте их — выберите сотрудника и месяц, затем измените время (значок карандаша), удалите отметку (корзина) или **добавьте** недостающие («Добавить отметку или день»: дата, время прихода, время ухода; оставьте поле «уход» пустым, если отсутствует только одна отметка). **Причина** в верхней части вкладки заносится в журнал аудита, а добавленные отметки имеют источник «добавлено администрацией» — таким образом, каждая корректировка остается отслеживаемой.

## 5. Первые проверки и отметки времени.

- Введите данные в веб-приложении (вход/выход), откройте ежемесячный просмотр, загрузите отчет в формате XLS и PDF.

- Загрузите образец (T17) в запущенный экземпляр:

  ```bash
  npm run load-smoke -- --login <user> --password '<password>' --count 5
  ```

  Ожидал: `OK: kein Fehler, alle Stempel vorhanden, Antwortzeiten im Sekundenbereich.` (код 0; скрипт выводится на немецком языке).

- Автоматическая проверка пути первоначального запуска (вход в систему, принудительная смена пароля, ввод PIN-кода сотрудника с помощью пропуска, отметка времени, оценка дня и месяца, отчеты в форматах XLS и PDF, резервное копирование):

  ```bash
  npm run first-run -- --login admin --password '<start password>'
  ```

  Ожидал: `Ergebnis: <all>/<all> Schritte erfüllt` и `OK: Erststart-Strecke ohne Fehler.` (код 0). Скрипт создает сотрудника. `pruefung` С помощью перфорации и PIN-кода — удалите это в административной панели позже, чтобы данные оставались чистыми. То, что намеренно опущено (потому что это необходимо для настройки), указано в самом конце: терминал киоска и связь с бейджем проверяются вручную в плане тестирования.

- **Контроль присутствия через ioBroker:** каждый сотрудник имеет доступное для записи состояние. `time-tracker.0.users.<id>.present` (роль `switch`). `true` отметки о начале и окончании рабочего времени (пропуски рабочего времени), `false` Перфорация предназначена для сканера отпечатков пальцев, RFID-моста, приборной панели или скрипта. Запись идемпотентна (вторая `true` не создает второго удара) и отображается как обычный удар с примечанием `state.present`. `users.<id>.hasOpenEntry` остается чистым дисплеем.

- **Команды из ioBroker (скрипт, Blockly, панель управления):** ниже `time-tracker.0.commands.*` Существует шесть состояний, доступных для записи — они управляют адаптером без веб-интерфейса. То, что вы записываете, впоследствии попадает в журнал адаптера (а также в журнал аудита как _System_ ):

  ```js
  setState("time-tracker.0.commands.punchUserId", 3); // target employee (0 = the only one)
  setState("time-tracker.0.commands.punch", true); // punch in or out
  setState("time-tracker.0.commands.quickPunch", true); // with quick rounding
  setState("time-tracker.0.commands.recalc", "2026-08"); // month, or "2026" for the year
  setState("time-tracker.0.commands.closeMonth", "2026-08"); // the month closing needs YYYY-MM
  setState("time-tracker.0.commands.backup", true); // write a backup now
  ```

  **Две кнопки удара реагируют на `true` только** (любое другое значение игнорируется), и адаптер возвращает их обратно в исходное состояние. `false` сразу же — поэтому **никогда не** пишите `false` выбить: `punch` автоматически выбирает правильное направление.

  **Какой сотрудник?** Команды отметки времени учитывают сотрудника. `commands.punchUserId` (адаптер соответствует текущему выбору,) `0` = «единственный сотрудник»). Если сотрудников несколько и выбора нет, команда отклоняется, и об этом сообщается в журнале. Идентификатор сотрудника отображается в экземпляре под `users.<id>` (число позади) `users.`).

  Даже без указания конкретного сотрудника это работает **для каждого сотрудника** отдельно: `time-tracker.0.users.<id>.present` (см. выше) или сообщение через `sendTo("time-tracker.0", "punch", { user: "anna" }, answer => …)`.

  Ошибки (неправильный период, неизвестный или деактивированный сотрудник) отображаются **в журнале как предупреждение** — при этом работа системы продолжается.

- **Защита от дубликатов (важно для считывателей):** два нажатия в течение **30 секунд** считаются двойным сканированием — второе не засчитывается. Считыватель отпечатков пальцев или RFID-меток, срабатывающий несколько раз, в этом случае безвреден; для функции «повторное нажатие» интервал должен быть больше 30 секунд. Это относится ко всем способам (веб-приложение, киоск, бейдж, объект ioBroker).

- Пример работы в автономном режиме: отключите Wi-Fi, сделайте отметку, подключитесь снова — отметка будет доставлена позже (см. раздел _«Синхронизация_ »).

- Администрирование → **Резервное копирование** : нажмите «Создать сейчас»; состояние `time-tracker.0.info.lastBackup` прыжки.

- Необязательно, но рекомендуется: скопируйте резервные копии на другой компьютер. В настройках экземпляра, на вкладке _«Миграция и резервное копирование»_ , в разделе _«Внешнее резервное копирование»_ : включите параметр **«Копировать резервные копии на внешний сервер (SFTP)»** , введите сервер, пользователя, пароль и каталог, нажмите **«Проверить соединение»** (появится отпечаток для ввода) и сохраните. После следующего резервного копирования `time-tracker.0.info.lastRemoteBackup` имя копии на сервере и `info.remoteBackupError` пусто.

- Выполните резервное копирование и восстановление один раз: остановите экземпляр, скопируйте файл резервной копии **за пределы** каталога адаптера, затем запустите экземпляр.

## 6. Импорт данных невозможен.

Адаптер **не** считывает данные из другой системы учета рабочего времени. Информация о сотрудниках, отметках времени и отсутствиях создается в интерфейсе:

- **Сотрудники:** Администрирование → Пользователи (логин, имя, пароль, роль, фотография (по желанию), PIN-код для пропуска)
- **Прошедшее время:** Администрирование → **Исправления** — здесь можно изменять, удалять и добавлять отметки времени, а также целые прошедшие дни (дата, время прихода, время ухода). **Причина** (поле над списком или в диалоговом окне) заносится в журнал аудита адаптера; значок рядом с каждой отметкой времени показывает ее **историю** (кто, когда, почему) в любой момент времени.

## 7. Когда что-то застряло

| Симптом                                             | Первое место, куда следует обратиться                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Веб-приложение недоступно                           | бревно `API listening on …`, состояние `info.connection`                                                            |
| PWA установить невозможно                           | Требуется HTTPS (собственный сертификат или обратный прокси), проверьте область действия сервис-воркера в журнале. |
| Сообщить об отсутствии/пустоте в `ru` /`uk` /`zh-cn` | набор `report_font_path` (Администрирование → Настройки)                                                            |
| Киоск не принимает PIN-код.                         | состояние `info.lastError` Блокировка аккаунта после 5 неудачных попыток (15 минут)                                 |
| Всё неясно                                          | бегать `npm run test:ts`, `npm run test:package`, `npm run test:integration` локально                               |

Критерии приемлемости и протокол исследования находятся в[`test-plan.md`](/#/docs/adapterref/iobroker.time-tracker/docs/en/test-plan.md) (Т1–Т29); отклонения и решения в[`decisions.md`](/#/docs/adapterref/iobroker.time-tracker/docs/en/decisions.md) .
