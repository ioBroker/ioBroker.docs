# Переводы (i18n)

Адаптер выпущен с поддержкой стандартного набора из **11 языков** ioBroker:

`en` (базовый и резервный варианты), `de`, `ru`, `pt`, `nl`, `fr`, `it`, `es`, `pl`, `uk`, `zh-cn`

## Где хранятся тексты

| Компонент                                        | Файлы                                                                                                         | Примечания                                                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Административный интерфейс адаптера (jsonConfig) | `admin/i18n/<lang>.json`                                                                                      | управляется с помощью `translate-adapter`; `admin/words.js` Этот параметр устарел и не подлежит редактированию.            |
| метаданные ioBroker                              | `io-package.json` →`common.titleLang`, `common.desc`, `common.news.<version>`, `common.localLinks.<key>.name` | должен содержать все 11 языков; синхронизация осуществляется с помощью `translate-adapter`                                 |
| Веб-приложение (PWA)                             | `src-www/src/i18n/<lang>.json`                                                                                | `i18next` /`react-i18next`; собственный набор ключей (тексты пользовательского интерфейса), `en.json` является основанием |
| Отчеты (PDF/XLS)                                 | генерируется во время выполнения                                                                              | Язык из пользовательских настроек, язык экземпляра в качестве резервного варианта.                                        |

Намеренно **не** переведены: ответы об ошибках API (они содержат стабильные коды ошибок, клиент их переводит) и названия состояний ioBroker (`common.name` (Английский + немецкий, согласно соглашениям ioBroker).

## Рабочий процесс

1. Добавляйте новый текст **только** в базовый файл на английском языке (`admin/i18n/en.json` или `pwa/src/i18n/en.json`).

2. Запустите инструмент перевода из папки адаптера:

   ```bash
   npm run translate                 # all languages
   npm run translate -- -l de ru     # only selected languages
   npm run translate --rebuild       # rebuild every file from scratch (do not mix with manual fixes)
   ```

   Набор `DEEPL_API_KEY` Для более высокого качества (предпочтительно DeepL, в противном случае используется Google Translate).

3. Просмотрите сгенерированные изменения — машинный перевод является черновиком, а не окончательным результатом.

4. Выполните проверку полноты — те же ключи, что и раньше. `en` В английском оригинале текст отсутствует, в коде не используется текст без ключа, метаданные полны:

   ```bash
   npm run check:i18n
   ```

5. Зафиксируйте изменения в языковых файлах вместе с изменениями в коде, которые внесли этот текст.

## Правила

- Заполнители сохраняют имеющееся у них имя. `en.json`: `{{minutes}}` пребывание `{{minutes}}` на любом языке. i18next заполняет только те переменные, которые передаются кодом, поэтому переведенное имя (`{{minuten}}`) буквально появляется на экране; `npm run check:i18n` Сравнивает имена и их порядок с базовым файлом.
- Никогда не переименовывайте и не меняйте назначение существующих ключей; извлекайте ключи только с помощью... `translate-adapter` (`remove-key`, `remove-translations`).
- В коде и JSON-конфигурации не должно быть жестко закодированного видимого текста.
- Вместо конкатенации строк в предложениях используйте заполнители и форматирование ICU.
- Форматирование дат, чисел, валют и единиц измерения с помощью `Intl` – Никогда не собирайте их вручную.
- Тексты отчетов и часовые пояса соответствуют настройкам пользователя, а не настройкам сервера.
- Для экспорта в PDF-файлы необходимы встроенные шрифты Unicode, охватывающие кириллицу и китайский (японский, японский, кириллический, корейский, ирландский, китайский, кипрский, корейский). `ru`, `uk`, `zh-cn`) и буквы вне WinAnsiEncoding (`pl`). Рендерер отклоняет такой язык с `report_font_missing` Вместо того чтобы рисовать бессмыслицу, решают подписи, поэтому язык, буквы которого встроенные шрифты не могут отобразить, отклоняется, даже если его название — латинское.

## Контрольная работа (что носитель языка может усвоить).

Технический эксперт не может оценивать формулировки. Эти пункты должны быть определены носителями языка; список составлен на основе второго этапа проверки от 18.09.2026 и остается открытым до тех пор, пока кто-нибудь на него не ответит.

**Кто может на них ответить?** Владелец хранит **немецкий** и **русский языки** и решает эти два вручную. Для остальных девяти языков **нет носителей языка** : они остаются машинным переводом, прошедшим техническую проверку, о чем и говорится в таблице выше. Поэтому их нерешенные вопросы документируются, а не решаются — неправильная догадка неносителя языка была бы хуже, чем текущий текст.
