# План приемочных и контрольных испытаний (первые реальные испытания)
Этот документ представляет собой руководство по проведению **первоначальных тестов на реальной установке ioBroker**. В нем описаны требования, тестовые данные, тестовые примеры T1-T29 с ожидаемыми результатами и критерии приемки. Для установки до первого запуска существует документ [`getting-started.md`](/#/docs/adapterref/iobroker.time-tracker/docs/en/getting-started.md); его шаги соответствуют описанной ниже подготовке. Общедоступный документ `README.md` написан на английском языке (требование проверяющего адаптера); этот документ по эксплуатации также доступен на немецком языке в [`../de/testplan.md`](https://github.com/sadam6752-tech/ioBroker.time-tracker/blob/main/docs/de/testplan.md) (оригинальный текст с сохраненным протоколом).

## 1. Цель
Для подтверждения того, что адаптер в процессе работы выполняет требования спецификации (разделы 3, 4, 9): ввод данных (онлайн, офлайн, терминал), расчет (целевые значения, перерывы, баланс, отпуск, праздничные дни), составление отчетов (Excel, PDF), обеспечение прав доступа на сервере, резервное копирование и восстановление.

## 2. Тестовая среда
| Пункт | Требование |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ioBroker | js-controller ≥ 6.0.11, admin ≥ 7.6.20 |
| Node.js | ≥ 22 (проверено локально с версией 22.22) |
| Порты | Порт адаптера свободен (по умолчанию `8092`), для теста достаточно `127.0.0.1` |
| HTTPS | **требуется** для установки PWA (сервис-воркера); в тесте используется либо собственный сертификат адаптера (**Использовать HTTPS**), либо обратный прокси (nginx/caddy) с самовыпущенным сертификатом, либо устройство в той же сети с действительным сертификатом |
| Браузер | Chrome/Edge (Android) или Safari (iOS) для установки; настольный браузер для просмотра API |
| Терминальное устройство | планшет/телефон в режиме киоска (экран остается включенным) **или** вкладка браузера |
| Время | один час на забег; в терминале T3 (в автономном режиме) необходимо тихое место для наблюдения за синхронизацией |

Для доступа необходимы две учетные записи: **администратор** (для всего) и **сотрудник** (только для собственных данных) - только так становятся видны ошибки доступа.

## 3. Установка для тестирования
```bash
cd <repo>
npm ci
npm run install:pwa
npm run build:pwa      # creates www/ (web app)
npm run build          # creates build/ (adapter)
npm run dev-server     # starts the adapter in a throw-away js-controller
```

В качестве альтернативы, можно установить пакет, уже имеющийся в системе: установите опубликованный пакет `iobroker.time-tracker` из npm, как описано в [`getting-started.md`](/#/docs/adapterref/iobroker.time-tracker/docs/en/getting-started.md).

После запуска: откройте экземпляр, проверьте **порт** и **адрес привязки**, установите `report_font_path` только в том случае, если требуются PDF-отчеты в `ru`, `uk` или `zh-cn` (в противном случае отчет ответит `422 report_font_missing` - это ожидаемое поведение, а не ошибка).

| Язык | Проверен шрифт (17.09.2026, реальный отчет со встроенным шрифтом) |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| `ru`, `uk` | `arial.ttf` (Arial заменяет кириллицу) |
| `pl` | `arial.ttf` - польские буквы (ś, ć, ł, ż, ę) находятся за пределами встроенного шрифта |
| `de`, `en`, `fr`, `it`, `es`, `nl`, `pt` | не требуется; при наличии набора шрифтов он также встраивается |
| `de`, `en`, `fr`, `it`, `es`, `nl`, `pt` | не требуется; при наличии набора шрифтов он также встраивается |

Отсутствие файла или шрифта без необходимых символов приводит к тому же сообщению об ошибке, что и отсутствие каких-либо настроек - поэтому отчет никогда не будет отправлен с пустыми полями.

## 4. Тестовые данные
1. Войдите в административную форму: используйте учетную запись `admin` (или настроенный логин) с паролем запуска экземпляра.

Настройка - если поле пустое, случайный пароль для запуска сохраняется **один раз в журнале адаптера** - **немедленно смените пароль** (адаптер требует этого при первом входе в систему). Пароль для запуска, введенный **после** первого запуска, также учитывается, если первый администратор еще не изменил пароль для запуска: перезапустите экземпляр, тогда в журнале появится `… exists already and still has its start password - it was set from the instance settings now`, и вход в систему будет работать с введенным значением. После изменения в приложении адаптер выдаст предупреждение `the configured start password is not used` (D15 в [`decisions.md`](/#/docs/adapterref/iobroker.time-tracker/docs/en/decisions.md)).

2. В веб-приложении в разделе **Администрирование → Сотрудники** создайте:
- `anna` (роль _сотрудник_), пароль в соответствии с политикой (≥ 8 символов, верхний и нижний регистр, цифры)
- `шеф-повар` (роль _менеджер_, если необходимо проверить принятие чужих месяцев работы)
- установить **PIN-код для бейджа** (4-8 цифр) для `anna` → для T4
3. Проверьте профиль работы `anna` в веб-приложении (**Администрирование → Сотрудники → _Профиль работы_**): уровень занятости,

Количество рабочих часов в неделю, количество рабочих дней, модель оплаты сверхурочных, количество дней отпуска, переносимые дни и **оплачиваемые минуты перерыва в день** (например, `15` = оплачивается четверть часа перерыва, `0` = перерыв не оплачивается); кроме того, выберите **правило перерыва** в **Администрирование → Настройки** (по умолчанию: перерыв с отметкой времени, в противном случае - по шкале).

4. Создайте **терминал** - в веб-приложении в разделе **Администрирование → Терминалы** (или с помощью `POST /api/terminals`), оставьте

Включите опцию «Требуется PIN-код». Затем откройте киоск на устройстве: в административной панели отобразится готовый адрес `http://<adapter host>:<port>/terminal/<device token>/` (токен отображается **один раз**; устройство запомнит его для следующего запуска).

5. Создайте государственные праздники на тестовый год (укажите страну праздника), отметьте тип отсутствия _отпуск_.

## 6. Критерии приемки
- **T1-T13 отмечены зеленым цветом.** T14-T17 были успешно пройдены как минимум один раз.
- Восстановление из резервной копии (T10) подтверждено: скопируйте файл, перезагрузите адаптер, и данные будут на месте.
- Каждое отклонение регистрируется (номер, наблюдение, оценка) и либо исправляется, либо намеренно принимается как открытое.

## 10a. Проверьте фрагмент кода для T21 (только для поиска, не является частью адаптера)
`calendar.absences` - это JSON; этот скрипт на вкладке **скрипты** записывает информацию об отсутствии сотрудников за сегодняшний день в журнал и отправляет отчет при каждом обновлении адаптера:

```js
const id = "time-tracker.0.calendar.absences";

/** Writes the absences running today into the log. */
function checkCalendar() {
	const state = getState(id);
	if (!state || !state.val) {
		log("time-tracker: no absences yet", "warn");
		return;
	}
	const today = formatDate(new Date(), "YYYY-MM-DD");
	const running = JSON.parse(state.val).filter(a => a.approval === "approved" && a.from <= today && a.to >= today);
	log(
		running.length === 0
			? "time-tracker: nobody is absent today"
			: `time-tracker: ${running.map(a => `${a.name} - ${a.type} (${a.code}) until ${a.to}`).join(", ")}`,
	);
}

checkCalendar();
on(id, checkCalendar);
```

## 11. Примечания по разработке (веб-интерфейс)
**Тесты браузера** (`npm run e2e`, папка `test/e2e/`): они запускают `test/e2e/server.mjs` - это реальный API в базе данных в оперативной памяти с веб-файлами, созданными в `www/`. ioBroker не требуется, сетевое соединение не нужно. Перед запуском `npm run build:pwa` **обязательно** должен быть запущен; тесты блокируют сервис-воркер, иначе Workbox доставит старые файлы из предварительного кэша.

> **Важно:** сначала проверьте код завершения сборки, а затем ознакомьтесь с результатами тестов. Прерванная сборка (например, из-за неиспользуемого импорта) оставляет `www/` неизменным - в этом случае тесты молча запускаются против **старого** состояния.

> **Один запуск выполняется ровно для одного сервера.** `playwright.config.ts` захватывает работающий E2E-сервер > (`reuseExistingServer`), и этот сервер хранит свою базу данных **в памяти**: второй запуск соответствует состоянию первого.
> Затем защита от двойного сканирования отбрасывает данные в течение 30 секунд, и проверка пароля запуска завершается неудачей, поскольку > он уже был изменен. Перед следующим запуском завершите работу сервера на порту `8099` или запустите его заново; в противном случае, принудительно прерванный запуск оставляет «зомби-сервер», на котором следующий раунд завершается неудачей с `ERR_CONNECTION_REFUSED` (проверка «действия не лежат на тексте» в `test/e2e/layout.spec.ts` также обнаруживает другой набор данных, чем ожидалось).

**Разрабатывайте веб-приложение, используя работающий адаптер** (быстрая обратная связь, React в режиме разработки с понятными сообщениями об ошибках):

```bash
npm --prefix src-www run dev     # port 5173, fetches /api/… through the proxy of 127.0.0.1:8092
```

- Прокси в файле `src-www/vite.config.ts` необходимо записывать как **вычисляемый** ключ `[API_PREFIX]`. При использовании `API_PREFIX:`

### Локальный экземпляр ioBroker (dev-server)
`npm run dev-server setup` (один раз), а затем `npm run dev-server watch` создают полную установку ioBroker с адаптером в `.dev-server/default`. Затем веб-приложение запускается в `http://127.0.0.1:8092`, административный интерфейс - в `http://127.0.0.1:8081`. Если в настройках экземпляра нет пароля запуска, он генерируется и записывается в журнал **один раз**:

```text
warn: time-tracker.0 administrator "admin" created with the start password "Zf-…" - change it at the first login
info: time-tracker.0 administrator "admin" exists already and still has its start password - it was set from the instance settings now
warn: time-tracker.0 the configured start password is not used: administrator "admin" changed his password already (empty the field "Start password of the first administrator" to silence this)
```

> **Windows 11 без `wmic`:** `dev-server watch` прерывается с `spawn wmic.exe ENOENT` - инструмент считывает размер диска > до `wmic`, и эта ошибка не обрабатывается в версии 0.8.0 (`wmic` был удален Microsoft). Контроллер и > адаптер к этому моменту уже установлены; Достаточно запустить контроллер напрямую: > > ```powershell > cd .dev-server\default > node node_modules\iobroker.js-controller\controller.js # работает в фоновом режиме > node node_modules\iobroker.js-controller\iobroker.js start time-tracker.0 # вторая консоль > node node_modules\iobroker.js-controller\iobroker.js start admin.0 # необязательно: интерфейс администратора > ``` > > Завершите ввод с помощью `iobroker.js stop time-tracker.0` или Ctrl+C в окне контроллера. Таким образом, горячей перезагрузки не будет: > после изменений запустите `npm run build` (адаптер) или `npm run build:pwa` (веб-приложение) и перезапустите экземпляр.

Чтобы изменения в веб-приложении входили в систему без переустановки, предоставленная папка `www` может указывать на папку репозитория (адаптер считывает файлы с диска при каждом запросе):

```powershell
cd .dev-server\default\node_modules\iobroker.time-tracker
cmd /c rmdir www                     # removes only the link, not the target
New-Item -ItemType Junction -Path www -Target <repository>\www
```

> **Создавайте только ссылки с `www` и всегда удаляйте соединения с `cmd /c rmdir`.** Два примера из процесса настройки: > > - Соединение **не** подходит для кода адаптера (`build/`): контроллер js тогда больше не находит адаптер > и завершает его `CANNOT_FIND_ADAPTER_DIR`.
> - `Remove-Item -Recurse` в соединении в PowerShell также удаляет **содержимое целевого объекта**. С > `cmd /c rmdir <path>` исчезает только ссылка.
> > Поэтому после изменения адаптера пересоберите и скопируйте файлы: > > ```powershell > npm run build > Copy-Item build .dev-server\default\node_modules\iobroker.time-tracker\build -Recurse -Force > ```

Разделы `.dev-server/` и `iobroker.*.tgz` уже рассмотрены в разделе `.gitignore`.

> **Обратите внимание на порт при тестировании:** `npm run test:integration` запускает собственный экземпляр ioBroker и привязывает тот же порт, что и адаптер (по умолчанию `8092`). Если ваш собственный экземпляр запущен, тестовый экземпляр не сможет открыть свой API, и проверка завершится ошибкой «запускает HTTP API на настроенном порту» - поэтому сначала остановите свой собственный экземпляр (`iobroker.js stop time-tracker.0`).
