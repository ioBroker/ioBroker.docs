# Развитие и безопасность зависимостей

## Поддерживаемый набор инструментов

Используйте версии Node.js, поддерживаемые CI (22, 24 и 26). `npm ci`, затем:

```sh
npm run build
npm run check
npm test
npm run lint
npm run coverage
npm run audit:dependencies
npm run test:integration
```

Для интеграционного тестирования используется официальная версия. `@iobroker/testing` Тестовый модуль устанавливает изолированный контроллер, запускает адаптер без настроенных устройств и проверяет его жизненный цикл. Он не использует и не изменяет существующую домашнюю установку ioBroker. Для этих тестов требуется доступ к сети npm, и они также запускаются на Linux, macOS и Windows.

Для интерактивного тестирования администратора и оборудования используйте отдельную тестовую установку ioBroker, например, [официальный образ Docker](https://github.com/buanet/ioBroker.docker) . Соберите и упакуйте адаптер с помощью... `npm run build && npm pack` Установите этот пакет в тестовой установке и загрузите его файлы Admin, используя стандартные инструменты ioBroker. Не используйте производственную установку в качестве неограниченной песочницы для разработки. Для обнаружения широковещательных UDP-пакетов необходим доступ к сети устройства; NAT-интерфейс Docker Desktop не пересылает автоматически широковещательные пакеты из локальной сети.

## Почему была удалена старая зависимость от dev-сервера?

`@iobroker/dev-server@0.8.0` все еще устанавливается `bs-html-injector`, `request` старый `jsdom`, и `xmldom` Устаревший стек горячей перезагрузки HTML не имеет поддерживаемого обновления, которое устраняло бы все выявленные проблемы безопасности. Этот адаптер использует конфигурацию JSON и не требует внедрения HTML для сборки, тестирования или работы адаптера.

Зависимость и `npm run dev-server` Точки входа намеренно удалены, а не перенесены в глобальную установку, чтобы аудит выглядел чистым. Это означает, что функция интерактивной горячей перезагрузки старого сервера разработки больше не предоставляется этим репозиторием. Используйте интеграционные тесты для автоматических проверок и отдельную установку тестов для интерактивных проверок. Существующие `.dev-server` Данные не удаляются и не переносятся; необходимо остановить все старые процессы сервера разработки и не продолжать использовать устаревшую среду. Аудит репозитория не проверяет старые профили, глобальные инструменты, отдельно установленный контроллер интеграции или образы Docker.

`@iobroker/adapter-dev` Он сохраняется для команд сборки/отслеживания изменений и перевода. Его зависимости могут быть обновлены в пределах поддерживаемых диапазонов; замена всего этого инструмента не потребовалась.

## Проверенные на совместимость переопределения в рамках определенной области действия

- `@iobroker/testing -> @alcalzone/esbuild-register`: заменить старый форк на API-совместимый. `esbuild-register@3.6.0` через псевдоним npm. В отличие от жесткой зависимости старого форка от уязвимого esbuild 0.11, оригинальный форк поддерживает `esbuild >=0.12 <1`; файл блокировки разрешает исправленную версию esbuild 0.25.12. Тесты пакета загружают реальный TypeScript через точное имя модуля ioBroker в дочернем процессе. Сборка, тесты контроллера и `npm ls --all` Проверьте всю цепочку инструментов.

Нью-Йорк `istanbul-lib-processinfo` обновлено до исправления из исходного кода (3.0.1), которое использует `node:crypto` вместо старого `uuid` Зависимость. Переопределение UUID не требуется. Тесты пакета проверяют фактическое создание идентификатора процесса; команда покрытия кода проверяет полный путь к NYC.

Сохраните область действия переопределения только для затронутого потребителя. Перепроверьте и удалите его, когда зависимости из вышестоящего проекта предоставят поддерживаемые исправления. `npm audit fix --force` глобальные переопределения и `--legacy-peer-deps` не являются частью процесса обновления.

## Обновления ESLint и TypeScript

Файл блокировки содержит последние совместимые версии ESLint 9 и typescript-eslint 8. Версия TypeScript 6.0.3 остаётся неизменной: typescript-eslint в настоящее время поддерживает[`>=4.8.4 <6.1.0`](https://typescript-eslint.io/users/dependency-versions/) Не TypeScript 7. Один только ESLint 10 не меняет это ограничение, и плагин React, используемый в общей конфигурации ioBroker, по-прежнему требует ESLint 9 или более ранних версий. Пересмотрите всю систему, прежде чем объединять крупное обновление TypeScript или ESLint.

Процесс тестирования и выпуска выполняется `audit:dependencies` в качестве блокирующего фактора, включая зависимости разработки и незначительные нарушения. Аудит без обнаруженных нарушений представляет собой снимок известных рекомендаций npm, а не общую гарантию безопасности.
