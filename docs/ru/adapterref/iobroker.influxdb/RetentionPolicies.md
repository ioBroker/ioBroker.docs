# Понимание политики хранения данных

Важно понимать взаимосвязь между **политиками хранения** и **сроками хранения данных в группах шардов** , чтобы определить, как долго данные будут храниться в InfluxDB.

Influx сохраняет все измерения в заданном временном диапазоне в одном и том же **шарде** , который, в свою очередь, является частью **группы шардов** . Группа шардов устанавливает временной диапазон, определяемый`Shard Group Duration` Для всех шардов, но настройки различаются в зависимости от версии InfluxDB.

При превышении заданного значения`Shard Group Duration` ,

- Создается новый Shard, который хранит новые данные измерений, начиная с этого момента.
- Старый Shard со всеми данными измерений по-прежнему хранится в базе данных, но будет удален, как только истечет срок хранения данных измерений.

Данные измерений не удаляются Influx путем проверки их политик хранения по отдельности, а вместо этого проверяется политика хранения всего шарда в целом, и он будет удален, если политика хранения превышена. Однако проверка будет выполняться только для старых шардов, то есть шарды, которые все еще активны, не проверяются, поскольку они также могут получать новые данные измерений.

_Для получения более подробной информации и примеров, пожалуйста, обратитесь к <https://docs.influxdata.com/influxdb/v1.4/concepts/schema_and_data_layout/#shard-group-duration-management> ._

Следующие два примера иллюстрируют, как один и тот же период хранения будет применяться по-разному в зависимости от настроенной продолжительности группы сегментов.

|                                              | Пример 1                                                                                                                                            | Пример 2                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Срок хранения                                | 2 часа                                                                                                                                              | 2 часа                                                                                                                                                                                                                                                                                                           |
| Длительность группы шардов                   | 1 час                                                                                                                                               | 1 день                                                                                                                                                                                                                                                                                                           |
| Как долго будут храниться данные (максимум)? | 2 часа                                                                                                                                              | 1 день                                                                                                                                                                                                                                                                                                           |
| Почему?                                      | Шард переключается каждый час, поэтому Influx будет применять настроенный RP один раз **в час** и сохранять только данные за **последние 2 часа** . | Переключение Shard происходит один раз в день, после чего Influx применяет настроенный RP, то есть сохраняет данные только за последние **2 часа** . Из-за этого данные измерений, введенные в начале работы Shard, теоретически должны храниться только 2 часа, но фактически будут храниться **целые сутки** . |

## iobroker.influxdb Adapter

Адаптер InfluxDB позволяет выбрать только **период хранения** и автоматически определяет **продолжительность работы группы шардов** в соответствии с [официальными рекомендациями InfluxDB](https://docs.influxdata.com/influxdb/v2.0/reference/internals/shards/#shard-group-duration) .

| Период хранения ведра  | Длительность работы группы сегментов по умолчанию |
| ---------------------- | ------------------------------------------------- |
| менее 2 дней           | 1 ч                                               |
| от 2 дней до 6 месяцев | 1д                                                |
| более 6 месяцев        | 7d                                                |

Длительность работы группы шардов по-прежнему можно изменить вручную в самой базе данных, но для сохранения управляемости конфигурации адаптера ее нельзя изменить напрямую в ioBroker.

По своей конструкции адаптер применяет только одну глобальную политику хранения данных, которая распространяется на все измерения — независимо от используемой версии базы данных. Политику можно изменить в любое время, но по причинам, описанным ранее, для вступления изменений в силу может потребоваться некоторое время.

## Дополнительные соображения

- Длительность работы групп шардов часто устанавливается короче периода хранения, чтобы обеспечить эффективное соблюдение правил. Однако это сложно назвать общим советом, поскольку следует учитывать и другие факторы, такие как производительность. Если длительность работы групп шардов установлена на очень короткий срок, это может быть полезно для обслуживания, но может негативно повлиять на производительность, например, привести к увеличению времени выполнения запросов или замедлению скорости записи.
- Политика хранения данных не может быть меньше 1 часа. Это решение было принято разработчиками InfluxDB ( <https://github.com/influxdata/influxdb/issues/5198#issuecomment-166629531> ) и может быть обойдено только путем сборки InfluxDB из последней версии исходного кода с измененными значениями напрямую.
- По умолчанию политика хранения данных проверяется каждые 30 минут. Однако это можно изменить в [конфигурации сервера для Influx 1.x](https://docs.influxdata.com/influxdb/v1.8/administration/config/#retention-policy-settings) и [конфигурации сервера для Influx 2.x.](https://docs.influxdata.com/influxdb/v2.0/reference/config-options/#storage-retention-check-interval) Это **не** отменяет принципы, описанные ранее.
- **Influx 1.x** : Для существующих баз данных адаптер способен определить текущую политику хранения по умолчанию и обновить ее. Если вы вручную изменили политику хранения и все еще сталкиваетесь с отсутствием данных в адаптере, это может быть связано с измененной политикой по умолчанию. Дополнительную информацию см. здесь: <https://docs.influxdata.com/influxdb/v1.7/troubleshooting/frequently-asked-questions/#why-am-i-missing-data-after-creating-a-new-default-retention-policy> .
