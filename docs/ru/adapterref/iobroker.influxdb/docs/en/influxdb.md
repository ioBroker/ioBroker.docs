## <span id="Configuration">Configuration</span>
### <span id="Storage-Settings">Настройки базы данных</span>
Введите здесь настройки, которые были установлены при создании InfluxDB, чтобы сервер ioBroker получил доступ к этой базе данных. [![](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_ioBroker_Adapter_influxDB_Konfig.jpg)](../../../../../en/adapterref/iobroker.influxdb/docs/de/img/influxdb_ioBroker_Adapter_influxDB_Konfig.jpg)

#### Хозяин
Имя хоста или IP-адрес сервера базы данных.

#### Порт
Порт, через который база данных доступна на хосте.

Протокол
Определяет, осуществляется ли доступ к базе данных по обычному протоколу HTTP или по защищенному протоколу HTTPS.

#### Авторизоваться
Владелец базы данных (пользователь), под чьим идентификатором записаны данные. Используется только с InfluxDB 1.x; для InfluxDB 2.x и 3.x вход осуществляется с помощью токена.

#### Пароль
Пароль указанного пользователя в базе данных. В целях безопасности пароль необходимо ввести повторно в следующее поле. Используется только с InfluxDB 1.x.

#### InfluxDB 3.x
Выберите версию базы данных "3.x", введите хост, порт (по умолчанию `8181`), токен и имя базы данных. InfluxDB 3 не может удалять отдельные значения или временной диапазон, а также не сообщает количество серий. В экспертных настройках параметр "Ожидание сохранения каждого значения в базе данных" заставляет отдельные значения ожидать записи в журнал предварительной записи (примерно одну секунду на каждое) вместо мгновенного подтверждения. Подробности и все ограничения: [README, InfluxDB 3.x](/#/adapters/influxdb#influxdb-3x).

Округлить до
Количество десятичных знаков, с которыми хранятся числа.

#### Сбор действий записи
Введенное здесь значение определяет, сколько новых значений необходимо собрать, прежде чем они будут записаны в базу данных. Чем выше значение, тем реже происходит запись в базу данных, но тем больше данных будет потеряно в случае сбоя адаптера. `0` записывает каждое значение в базу данных немедленно. Это увеличивает нагрузку на базу данных и на адаптер.

#### Интервал записи
Если здесь ввести значение, собранные данные будут записаны в базу данных по истечении заданного времени в секундах, даже если количество значений, указанных в предыдущем поле, еще не достигнуто.

### <span id="Default_settings_for_states">Настройки по умолчанию для штатов</span>
Эти настройки определяют значения, которые используются по умолчанию при настройке регистрации одной точки данных. [![](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_ioBroker_Adapter_influxDB_objects.jpg)](../../../../../en/adapterref/iobroker.influxdb/docs/de/img/influxdb_ioBroker_Adapter_influxDB_objects.jpg)

#### Только изменения в журнале
Если этот флажок установлен, для записи последовательных значений необходимо, чтобы они отличались. Если датчик, например, несколько раз передает одно и то же значение температуры, оно не записывается - только изменение значения создает новую запись.

#### Записывать одинаковые значения
Если тем не менее, время от времени необходимо сохранять неизмененные значения, введите здесь временной интервал в секундах, определяющий частоту таких сохранений. Соответственно, `0` означает, что повторяющиеся значения не сохраняются.

#### Минимальная разница с последним значением
Если постоянно изменяющиеся значения не должны сохраняться целиком, определите здесь минимальное значение, на которое значение должно измениться, прежде чем будет сохранено новое значение. Это полезно, например, для вилок учета электроэнергии, где не каждое незначительное изменение должно регистрироваться. Соответственно, `0` означает, что сохраняются все значения.

#### Сохранить как
При необходимости здесь можно определить тип данных, в котором будут храниться значения. Это следует делать только до первой активации ведения журнала.

[![](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_ioBroker_Adapter_SQL_objects_type.jpg)](../../../../../en/adapterref/iobroker.influxdb/docs/de/img/influxdb_ioBroker_Adapter_SQL_objects_type.jpg) InfluxDB фиксирует тип данных в первой записи измерения, и он должен оставаться неизменным в дальнейшем.

#### Сохранение данных
Определяет, как долго сохраняются значения (бесконечность, 2 года, 1 год, …, 1 день). [![](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_ioBroker_Adapter_SQL_objects_timerange.jpg)](../../../../../en/adapterref/iobroker.influxdb/docs/de/img/influxdb_ioBroker_Adapter_SQL_objects_timerange.jpg)

#### Время подавления дребезга контактов (мс)
Защита от слишком частых изменений значений. Это минимальное время в миллисекундах, после которого значение будет записано снова.

## <span id="Settings_for_datapoints">Настройки для точек данных</span>
Настройка регистрации точки данных осуществляется на вкладке «Объекты» непосредственно в самой точке данных. [![[![](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_ioBroker_adapter_History_devices.jpg)](../de/img/influxdb_ioBroker_adapter_History_devices.jpg) Щелкните значок шестеренки в крайнем правом столбце нужной точки данных. Откроется диалоговое окно конфигурации: [![](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_ioBroker_Adapter_influxDB_objects.jpg)](../../../../../en/adapterref/iobroker.influxdb/docs/de/img/influxdb_ioBroker_Adapter_influxDB_objects.jpg)

### <span id="Enabled">Включено</span>
Включает логирование данных. При использовании параметра "логировать только изменения" значения сохраняются только при изменении значения точки данных, что экономит место. Полезно сначала отфильтровать точки данных с помощью полей фильтра в заголовке таблицы, например, чтобы отобразить только точки данных "STATE", а затем включить логирование для всех них одновременно: [![Filtern_loggen](https://github.com/ioBroker/ioBroker.influxdb/blob/master/docs/de/img/influxdb_Filtern_loggen.jpg)](../../../../../en/adapterref/iobroker.influxdb/docs/de/img/influxdb_Filtern_loggen.jpg)

1. Отобразить представление в виде списка без группировки.
2. Введите фильтрующий(ие) термин(ы).
3. Выберите все отфильтрованные точки данных для записи в журнал.
1. Открывается диалоговое окно настройки параметров логирования.
4. Включите ведение журнала для всех отфильтрованных точек данных одновременно.
1. Установите дополнительные параметры, такие как "только изменения в журнале" и "срок хранения", единообразно для всех отфильтрованных точек данных.
5. Сохраните изменения.

### <span id="Custom_tags">Пользовательские теги</span>
Каждая точка данных может содержать дополнительные статические теги InfluxDB. Они вводятся в настройках точки данных в разделе «Пользовательские теги» в виде списка пар «имя/значение» и записываются вместе с каждым значением этой точки данных - для всех версий InfluxDB и независимо от параметра «Хранить метаданные в виде тегов, а не полей».

Это позволяет выбирать и группировать значения различных точек данных по их смыслу, а не по идентификаторам, например, присвоить всем точкам данных кухни тег `room=kitchen`, а всем датчикам температуры - тег `type=temperature`. В Grafana значения затем можно фильтровать или группировать по этим тегам:

```
from(bucket: "iobroker")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r._field == "value" and r.type == "temperature")
  |> group(columns: ["room"])
```

Пожалуйста, обрати внимание:

- Имена `value`, `q`, `ack`, `from` и `time`, а также имена, начинающиеся с `_`, зарезервированы и не могут быть использованы. Строки без имени или значения игнорируются; игнорируемые теги отображаются в журнале как предупреждение.
- InfluxDB идентифицирует ряд по измерению и всем его тегам. Изменение тегов точки данных, следовательно, запускает новый ряд; значения, записанные ранее, сохраняют свои старые теги. В InfluxDB 2.x вызов `getHistory` за временной диапазон, в котором были изменены теги, агрегирует каждый ряд отдельно - такой диапазон может содержать два значения на интервал. Лучше всего устанавливать теги до начала логирования.
- Каждая точка данных по-прежнему записывается в собственное измерение (с собственным идентификатором или псевдонимом). Использование одного и того же псевдонима для нескольких активных точек данных не поддерживается.

Теги также можно установить с помощью JavaScript, используя сообщение `enableHistory`:

```javascript
sendTo('influxdb.0', 'enableHistory', {
    id: 'hm-rpc.0.ABC123.1.TEMPERATURE',
    options: {
        customTags: [
            { name: 'room', value: 'kitchen' },
            { name: 'type', value: 'temperature' },
        ],
    },
});
```

## <span id="Statistics">Статистика и очистка</span>
Вкладка **Статистика** в конфигурации экземпляра отображает все точки данных, содержащиеся в базе данных, с указанием количества значений, самого старого и самого нового значения, количества серий и статуса:

| Статус | Значение |
|----------------|-------------------------------------------------------------------------------------------------|
| Зарегистрировано | Объект существует, и этот экземпляр регистрирует его |
| Выход из системы | Объект по-прежнему существует, но ведение журнала отключено - его история по-прежнему доступна |
| Объект удален | Объект был удален в ioBroker, никто больше не может получить доступ к его истории |

В отношении этих цифр важны две вещи:

- **Размер каждой точки данных не указан.** InfluxDB его не предоставляет ни в версии 1.x (команды `SHOW STATS` и `SHOW SHARDS` знают только движок и шарды), ни в версии 2.x (использование диска отслеживается для каждого сегмента). Вместо этого отображается количество **серий**: оно определяет объем памяти, необходимый индексу, а использование пользовательских тегов обычно приводит к его непреднамеренному увеличению.
- **Подсчет представляет собой полное сканирование.** InfluxDB не может найти количество строк, поэтому фактически считываются значения за исследуемый временной диапазон. Для базы данных с данными за несколько лет это занимает некоторое время - выбор временного диапазона над таблицей ограничивает сканирование, если общее количество строк не требуется.

В процессе очистки удаляются сохраненные значения точек данных, которые больше никто не регистрирует. **Ничего не удаляется без подтверждения**: в диалоговом окне сначала отображается, что будет удалено при подтвержденном запуске. По умолчанию выбираются только объекты, которые больше не существуют в ioBroker. Точки данных, ведение журнала которых просто отключено, включаются только в том случае, если вы явно это отметите - их история по-прежнему доступна и часто востребована. Точка данных, которая в данный момент регистрируется, никогда не выбирается. В диалоговом окне все найденные точки данных предварительно выбраны; используйте флажки, чтобы снять выбор с тех, которые вы хотите сохранить. Удаляются только выбранные точки данных.

Адаптер знает только, есть ли у измерения объект. Если скрипт записывает данные непосредственно в базу данных без объекта, такое измерение также отображается как «объект удален». Чтобы отличить такие измерения от реальных остатков, диалоговое окно отображает самое старое и самое новое значение каждой точки данных. Если в поле **Последнее значение старше … дней** введено число, предварительно выбираются только точки данных, самое новое значение которых старше (или которые вообще не имеют значения). Точки данных, в которые еще ведется запись, исключаются, но их все еще можно отметить вручную.

Те же данные также доступны через JavaScript с сообщениями `getDpStatistics` и `cleanupOrphaned`, см. [README](/#/adapters/influxdb#statistics-and-cleanup).

## <span id="Docker">InfluxDB и Grafana в Docker</span>
Адаптер может запускать InfluxDB 2.x (не 3.x) и, при необходимости, саму Grafana в виде контейнеров Docker. Для этого на хосте ioBroker должен быть установлен Docker, и пользователю `iobroker` должны быть разрешены права на использование Docker (при необходимости запустите `iob fix`).

### InfluxDB в Docker
Включите параметр **Использовать самостоятельно размещенную InfluxDB в Docker** в настройках экземпляра. В этом случае хост, порт, организация, токен и т.д. будут скрыты - адаптер сам установит соединение.

Контейнер создается со следующими фиксированными значениями:

| Настройка | Значение |
|-----------------|--------------------------------------------|
| URL | `http://<ioBroker-host>:8086` |
| Организация | `iobroker` |
| Ведро | `iobroker` |
| API-токен | `aW9icm9rZXI4NjY0NTYzODU0NjU2NTY1MjY1Ng==` |
| API-токен | `aW9icm9rZXI4NjY0NTYzODU0NjU2NTY1MjY1Ng==` |

По умолчанию контейнер прослушивает только порт `127.0.0.1`, поэтому веб-интерфейс InfluxDB можно открыть только на самом хосте ioBroker. Чтобы открыть его с другого компьютера, установите параметр **Запустить контейнер по IP-адресу** в панели _InfluxDB Docker_ на `0.0.0.0` (все интерфейсы) или на IP-адрес хоста. **Делайте это только в доверенной сети** - имя пользователя, пароль и токен, указанные выше, одинаковы для всех установок. Пароль можно изменить в веб-интерфейсе InfluxDB (меню пользователя → _Изменить пароль_); адаптер входит в систему с помощью токена и не затрагивается. Не удаляйте токен.

Данные хранятся в томах Docker `flux_data` и `flux_config` и сохраняются после обновления или повторного создания контейнера.

### Grafana в Docker
[Графана](https://grafana.com/) отображает данные из InfluxDB в виде панелей мониторинга. Если InfluxDB работает в Docker, адаптер может запустить Grafana вместе с ним: включите **Использовать саморазмещенную Grafana в Docker** в настройках экземпляра (флажок отображается только тогда, когда включена опция **Использовать саморазмещенную InfluxDB в Docker**). Подключение к InfluxDB устанавливается автоматически - в Grafana ничего настраивать не нужно.

#### Первый вход
1. Откройте `http://<ioBroker-host>:3000` в браузере - или просто щелкните плитку _Grafana_ на вводной странице администрирования (также отображается как ссылка в списке экземпляров). Адаптер добавит эту ссылку сразу после включения Grafana и перезапустит свой экземпляр один раз для этого. Порт можно изменить в панели _Grafana Docker_. Grafana по умолчанию прослушивает все интерфейсы (`0.0.0.0`); установите **Запуск контейнера по IP-адресу** на `127.0.0.1`, если он должен быть доступен только с самого хоста.
2. Войдите в систему с помощью
- **пользователь: `admin` **
- **пароль: `iobroker` ** - или значение **пароля администратора** в панели _Grafana Docker_, если он был изменен до первого запуска.
3. Grafana запрашивает новый пароль. Установите его самостоятельно или нажмите _Пропустить_.

**Пароль администратора применяется только при первом запуске контейнера**, когда Grafana создает свою базу данных. Изменение **пароля безопасности администратора** в настройках адаптера позже не имеет эффекта, и пароль, измененный в Grafana, не отображается в настройках адаптера. Если вы его забыли, сбросьте его на хосте ioBroker:

```bash
docker ps --filter name=grafana --format '{{.Names}}'     # shows the container name, e.g. iob_influxdb_0_grafana
docker exec -it iob_influxdb_0_grafana grafana cli admin reset-admin-password <new-password>
```

При включении функции **Регистрация пользователей** на странице входа отображается ссылка _Регистрация_, где каждый, кто может открыть Grafana, может создать пользователя. Отключите эту опцию, если Grafana доступна из сети.

#### Источник данных
Источник данных `InfluxDB` уже присутствует и установлен по умолчанию (_Подключения → Источники данных_). Он использует язык запросов **Flux**, организацию `iobroker` и корзину `iobroker` и подключается к контейнеру InfluxDB внутри сети Docker - независимо от порта, настроенного для хоста. Адаптер записывает этот источник данных заново при каждом запуске, поэтому его нельзя редактировать в Grafana. Рядом с ним можно добавить собственные источники данных.

#### Первая панель управления
1. _Панели мониторинга → Создать → Новая панель мониторинга → Добавить визуализацию_ и выберите источник данных `InfluxDB`.
2. Переключите редактор запросов на _Code_, если он отображается, и введите запрос Flux. Каждая точка данных хранится в измерении, названном в соответствии с ее идентификатором (или псевдонимом), значение находится в поле `value`:

```
from(bucket: "iobroker")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r._measurement == "system.adapter.admin.0.memRss" and r._field == "value")
  |> aggregateWindow(every: v.windowPeriod, fn: mean, createEmpty: false)
```

Замените `system.adapter.admin.0.memRss` на идентификатор одной из ваших зарегистрированных точек данных. `aggregateWindow` уменьшает количество точек до того, что помещается на графике - используйте `fn: last` для значений, которые не являются числами или не должны усредняться.

3. Нажмите кнопку «Обновить» над диаграммой, затем нажмите кнопку «Сохранить панель мониторинга».

Самый простой способ найти правильные названия измерений и полей - это использовать _Обозреватель данных_ веб-интерфейса InfluxDB (см. выше): выберите сегмент, измерение и поле и нажмите _Редактор скриптов_ - это отобразит соответствующий запрос Flux. В Grafana запросы можно протестировать в _Обозревателе_ без панели мониторинга.

Дополнительные подсказки:

- Плагины можно установить через опцию **Плагины** в панели _Grafana Docker_ (например, `grafana-clock-panel`); они устанавливаются при следующем запуске контейнера.
- Если доступ к Grafana осуществляется через обратный прокси-сервер по подкаталогу, введите полный публичный URL-адрес в поле **Корневой URL-адрес сервера**.
- Панели мониторинга, пользователи и настройки хранятся в томе Docker `grafana_data` и сохраняются после обновления контейнера.

### Grafana без Docker
Без Docker Grafana необходимо устанавливать отдельно, см. [[Руководство по установке](https://grafana.com/docs/grafana/latest/setup-grafana/installation/). Затем откройте `http://<host>:3000` и войдите в систему с именем `admin` / `admin` (пароль по умолчанию Grafana; новый пароль запрашивается сразу). После этого создайте источник данных, как описано [здесь].](https://grafana.com/docs/grafana/latest/datasources/influxdb/):

- InfluxDB 1.x: язык запросов _InfluxQL_, URL InfluxDB, имя базы данных и имя пользователя/пароль из настроек адаптера.
- InfluxDB 2.x: язык запросов _Flux_, URL InfluxDB, организация, токен и корзина по умолчанию из настроек адаптера.
- InfluxDB 3.x: язык запросов _InfluxQL_ (или _SQL_), URL InfluxDB, имя базы данных и токен из настроек адаптера.

Запрос из [Первая панель управления](#the-first-dashboard) работает для InfluxDB 2.x. Для InfluxDB 1.x и 3.x с InfluxQL используйте, например:

```
SELECT mean("value") FROM "system.adapter.admin.0.memRss" WHERE $timeFilter GROUP BY time($__interval) fill(previous)
```
