## 1. Настройка InfluxDB
Откройте настройки адаптера и перейдите на вкладку **InfluxDB**.

URL-адрес и токен можно предоставить двумя способами:

### Вариант A (по умолчанию): запись в экземпляре
Оставьте поле **Учетные данные** в значении **Нет** и введите URL, порт и токен непосредственно в соответствующие поля.

### Вариант B (Admin 8 и новее): учетные данные ioBroker "Логин и пароль"
URL-адрес и токен хранятся централизованно в разделе *Системные настройки → Учетные данные* и выбираются в поле **Учетные данные** (➕ там же создается и токен):

- **Вход** = URL, например, `http://192.168.1.10`
- **Пароль** = API-токен

Поля URL и токена блокируются. Учетные данные в формате *Key* не поддерживаются. Если учетные данные изменяются в административной панели, адаптер перезапускается.

### Поля
| Поле | Описание |
|-------|-------------|
| Учетные данные | **Нет** (вариант A) или учетные данные "Логин и пароль" (вариант B) |
| URL | Адрес сервера InfluxDB 2.x без указания порта, например, `http://192.168.1.10` |
| Порт | По умолчанию `8086`. `0` = порт протокола по умолчанию (например, 443 для HTTPS за обратным прокси). Порт, указанный в URL, имеет приоритет. |
| Организация | Ваша организация InfluxDB |
| Корзина | Целевая корзина для данных временных рядов |
| Токен | API-токен с правами на **запись** |
| Интервал опроса (с) | Как часто собираются значения с датчиков (5-30 секунд) |

При запуске адаптер проверяет соединение, записывая контрольную точку. Состояние соединения отображается в `info.connection`.

> **Обновление по сравнению со старыми версиями:** порт в URL (например, `http://192.168.1.10:8086`) автоматически перемещается в поле **Порт** при первом запуске. URL без указания порта сохраняет порт по умолчанию для своего протокола (80 или 443). Ничего делать не нужно.

Внизу этой вкладки вы найдете:

- Флажок для включения механизма формул **Data-SOLECTRUS** (см. раздел 5)
- Флажок для включения **Экспертного режима** (см. раздел 2 - Датчики)

## 2. Датчики
Перейдите на вкладку **Датчики**. В редакторе основных/подробных данных отображаются все настроенные датчики с их текущим состоянием и возможностью группировки.

### Стандартный режим против экспертного режима
По умолчанию адаптер работает в **стандартном режиме**. В списке датчиков отображаются все предварительно настроенные датчики (INVERTER_POWER, BATTERY_SOC, HOUSE_POWER, датчики прогноза и т. д.). В стандартном режиме:

- Список датчиков можно свернуть по **папке/группе**. Предварительно настроенные датчики SOLECTRUS отсортированы по папкам, как в обзоре датчиков HELIOS: **Инвертор**, **Сеть**, **Аккумулятор**, **Настенный блок**, **Электромобиль 1-5**, **Тепловой насос**, **Прогноз** и **Пользовательский потребитель**. Датчики из бывшей папки **Датчики SOLECTRUS по умолчанию** автоматически перемещаются в эти папки. Существующие датчики из старых конфигураций, которые не соответствуют набору датчиков по умолчанию, автоматически назначаются в группу **Пользовательские датчики**.
- **Редактируемый**: Исходное состояние (состояние ioBroker), флажок «Включено».
- **Только для чтения**: Название датчика, Тип данных, Измерение, Поле, Предустановка JSON
- **Скрытые**: кнопки «Добавить», «Удалить», «Дублировать», внутренний флажок, папка/группа, единица измерения, максимальное значение, время ожидания активности.

Это гарантирует, что новички смогут легко включать датчики и назначать состояния источников, не изменяя случайно сопоставление InfluxDB. В стандартном режиме применяются следующие параметры по умолчанию: **мониторинг значений отключен** (максимальное значение = 0) и **тайм-аут активности 60 минут**. Точная настройка доступна в экспертном режиме.

Для разблокировки полного доступа включите **Экспертный режим** на странице настроек InfluxDB. В экспертном режиме:

- Все поля доступны для редактирования.
- Датчики можно добавлять, удалять, дублировать и изменять их порядок.
- Вновь созданные датчики попадают в группу **Пользовательские датчики**, и при необходимости их можно перегруппировать там или сохранить без группы.
- Предварительные настройки JSON можно перевести в пользовательский режим.

### Автомобильные датчики
SOLECTRUS поддерживает до **5 автомобилей**. Каждый автомобиль `n` (1-5) имеет папку **Электромобиль n** со следующими датчиками:

| Датчик | Значение | Тип |
|---|---|---|
| `CAR_BATTERY_SOC_n` | степень заряда (%) | плавающий заряд |
| `CAR_RANGE_n` | оставшийся запас хода (км) | float |
| `CAR_CONNECTED_n` | автомобиль подключен | логическое значение |
| `CAR_LATITUDE_n` / `CAR_LONGITUDE_n` | местоположение (градусы) | число с плавающей запятой |
| `CAR_LATITUDE_n` / `CAR_LONGITUDE_n` | местоположение (градусы) | float |

Автомобиль 1 записывает данные в измерение `car`, автомобили 2-5 - в `car_2` … `car_5`. Автомобиль передает свои значения только во время работы в сети, поэтому для этих датчиков включена опция **Запись только при изменении**, а тайм-аут активности отключен (`0`). Каждое показание поступает в InfluxDB один раз, с указанием времени изменения, а не каждые 5 секунд с указанием текущего времени.

Когда **адаптер запускается**, текущее значение каждого из этих датчиков записывается немедленно, вместе со временем последнего изменения. Адаптер не ждет следующего изменения, поэтому значение, изменившееся во время остановки адаптера, не теряется. Если InfluxDB уже имеет эту точку, она просто перезаписывается; дубликат не создается. Если исходный адаптер записывает свое значение снова после перезапуска, и это перемещает **время последнего изменения**, значение получает новое время.

SOLECTRUS по-прежнему считывает данные с прежнего датчика `CAR_BATTERY_SOC` (без номера) как `CAR_BATTERY_SOC_1`. Данные `CAR_MILEAGE_n` из версии для разработчиков переименовываются в `CAR_ODOMETER_n` при запуске.

### Значки состояния в списке датчиков
- `⚪` = датчик отключен
- `🟡` = датчик включен, но **внутренний** (мониторинг да, запись в InfluxDB нет)
- `🟢` = датчик включен и отправлен в InfluxDB

### JSON-датчики (прогнозные данные)
Для данных прогноза погоды установите тип данных на **массив JSON**. Доступны два предустановленных режима:

| Режим | Описание |
|------|-------------|
| **Автоматический режим** | Автоматически определяет известные поля в данных JSON (`y`, `clearsky`, `temp`) и записывает каждое из них в соответствующее измерение/поле InfluxDB. Один датчик обрабатывает все обнаруженные типы прогнозов. |
| **Пользовательский** | Задайте вручную поле метки времени JSON, поле значения и тип InfluxDB. Используйте это для нестандартных источников JSON. |

**Автоматическое определение местоположения:**

| Поле JSON | Измерение InfluxDB | Поле InfluxDB | Тип |
|------------|---------------------|----------------|------|
| `y` | `inverter_forecast` | `power` | int |
| `temp` | `outdoor_forecast` | `temperature` | float |
| `temp` | `outdoor_forecast` | `temperature` | float |

Поля, отсутствующие в JSON-файле, автоматически пропускаются.

### Как работают датчики
1. Адаптер подписывается на состояние источника каждого датчика.
2. Значения дублируются в каталоге `solctrus-influxdb.X.sensors.*`
3. При каждом интервале опроса текущие значения добавляются в буфер записи (**Collect**).
4. Сразу после сбора данных буфер сбрасывается в InfluxDB (**Flush**).

Датчики, помеченные как **Внутренние**, по-прежнему дублируются в `solectrus-influxdb.X.sensors.*` и остаются частью мониторинга alive/max, но они исключены из операций записи в InfluxDB.

### Архитектура сбора и промывки
Сбор и промывка происходят практически одновременно, не блокируя друг друга:

1. Функция **Collect** собирает все значения датчиков и записывает их в буфер.
2. **Немедленная очистка** - после сбора данных очистка запускается на следующем такте цикла событий (без дополнительного интервала ожидания).
3. **Снимок и подмена** - при начале операции сброса текущий буфер берется как пакет и заменяется новым пустым массивом. Пока операция сброса ожидает ответа от InfluxDB, параллельный процесс сбора данных уже записывает данные в новый (пустой) буфер. Пакет данных никогда не изменяется во время операции сброса.
4. **Восстановление после сбоя** - если операция сброса не удалась, пакет данных добавляется в начало текущего буфера в хронологическом порядке. Значения не теряются.
5. **Защита от перекрытия** - флаг `isFlushing` предотвращает одновременное выполнение нескольких операций очистки.

### Защита NaN
Недопустимые значения (`NaN` для целых чисел/числовых значений с плавающей запятой, `null`/`undefined` для строк) автоматически пропускаются с предупреждением в логе.

### Отрицательные значения
SOLECTRUS не принимает отрицательные значения. Если датчик выдает отрицательное значение после запуска адаптера, предупреждение регистрируется **один раз**. Значения по-прежнему отправляются в InfluxDB, но могут привести к некорректным вычислениям там. Чтобы исправить это, проверьте состояния источника или используйте механизм формул Data-SOLECTRUS с опцией **Ограничить отрицательные значения до 0**.

### Автоматическое определение устройства
Когда в административном интерфейсе выбирается состояние источника (через диалоговое окно **Выбор** или путем ввода идентификатора состояния и оставления поля пустым), административный интерфейс считывает свойство `common.unit` объекта ioBroker и заполняет поле **Единица измерения**. Если для состояния не определена единица измерения, поле остается пустым, и в качестве значения по умолчанию на вкладке обзора используется `W`. Единицу измерения всегда можно изменить вручную в **Экспертном режиме**.

### Проверка максимального значения
Каждый цифровой датчик (`int`, `float` или тип по умолчанию) поддерживает поле **Максимальное значение** (настраивается в экспертном режиме). Если полученное значение превышает этот предел:

1. В журнале регистрируется предупреждение: «Датчик "..." выдает неправдоподобное значение (X > max Y). Используется последнее допустимое значение (Z)».
2. Вместо этого в InfluxDB отправляется **последнее допустимое значение** (самое последнее значение, равное или меньшее предела).
3. Если для данного датчика еще не получено допустимое значение, точка данных полностью пропускается.

Это предотвращает искажение данных временного ряда из-за временных скачков показаний датчиков (например, кратковременного импульсного измерения мощности в 99999 Вт).

Значение по умолчанию - **0 (отключено)** - мониторинг значений для новых датчиков по умолчанию отключен. В экспертном режиме можно установить индивидуальное ограничение для каждого датчика (например, `15000` или `5000` для вторичного инвертора). Если максимальное значение установлено на `0`, мониторинг значений для этого датчика отключается.

### Конфликты типов полей
Если InfluxDB сообщает о конфликте типов полей (например, о записи числа с плавающей запятой в существующее целочисленное поле), соответствующий датчик автоматически отключается, а буфер очищается.

## 3. Вкладка «Обзор датчиков»
Вкладка **Обзор SOLECTRUS** (доступная через панель вкладок в разделе адаптера) предоставляет краткий обзор всех настроенных и активных датчиков и элементов данных в режиме реального времени.

![Пример обзора датчика](../../../../../en/adapterref/iobroker.solectrus-influxdb/docs/img/sensor-overview.svg)

### Функции
- **Легенда цветов** (панель инструментов, в правом верхнем углу рядом с заголовком): позволяет быстро понять значение цветов на карточках - **зеленый** = активный датчик, **желтый** = внутренний датчик, **оранжевый** = превышено время ожидания, **красный** = превышено максимальное значение.
- Кнопка на панели вкладок имеет общее название **Датчики**; содержимое под ней разделено на две секции, каждая со своим заголовком: **Датчики InfluxDB** (синяя иконка в виде ромба, датчики, фактически записанные в InfluxDB) и **Внутренние датчики** (🔒, отображаются только при наличии хотя бы одного датчика).
- **Сетка датчиков InfluxDB**: Отображает все включенные датчики, данные с которых фактически записываются в InfluxDB, в виде компактных карточек в адаптивной сетке. Каждая карточка отображает:
- **Название датчика** и **значок типа данных** (`int`, `float`, `bool`, `string`, `json`)
- **Строка значений** (только для числовых датчиков): **текущее значение с единицей измерения**, выровненное по левому краю (например, `2697 Вт`); **значок максимального значения**, выровненный по правому краю - отображается только тогда, когда максимальное значение > 0 (активен мониторинг значений). Отображает *н/д*, если значение еще не получено. Значения JSON отображаются компактно моноширинным шрифтом. После превышения заданного времени ожидания текущее значение становится **оранжевым**; если также превышено максимальное значение, **красный** цвет имеет приоритет над оранжевым.
- **Поле измерения** - целевое местоположение в InfluxDB (разделенное двоеточием)
- **Исходное состояние** - идентификатор считываемого состояния ioBroker (сокращенный, полный путь отображается при наведении курсора)
- **Строка с временной меткой** (отображается, если настроен тайм-аут активности): **временная метка** с выравниванием по левому краю (дата и время последнего получения датчиком нового значения); **следующее ожидаемое обновление** с выравниванием по правому краю в виде значка (только время, без метки, автоматически вычисляется как временная метка + интервал тайм-аута - ручной ввод не требуется). Когда текущее значение равно 0, для расчета следующего обновления используется 60-минутный резервный интервал. Строка отображается **оранжевым цветом**, когда тайм-аут активности превышен.
- **Сетка внутренних датчиков** (отображается только при наличии хотя бы одного датчика с включенной опцией **Внутренние**): отдельный раздел под сеткой датчиков InfluxDB, использующий ту же структуру карточек, но с **желтой левой рамкой** и **желтым текущим значением**. Поскольку данные с этих датчиков не записываются в InfluxDB, они четко отделены от обычных (зеленых) датчиков.
- **Сетка механизма формул** (отображается только при включенном Data-SOLECTRUS): отображает все активные вычисляемые элементы в одном макете карточки, с индикатором режима, текущим значением, идентификатором состояния и формулой/выражением. Размер шрифта остается постоянным при любой ориентации устройства. Числовые значения отображают **единицу измерения** (например, `2697 Вт`) - единицу измерения, настроенную для элемента, по умолчанию - `Вт`, если она не задана; логические и строковые результаты отображаются без единицы измерения. Поскольку элементы Data-SOLECTRUS никогда не записываются в InfluxDB напрямую (только датчики), эти карточки всегда оформлены как **внутренние датчики**, с **желтой рамкой** и **желтым значением**.
- Если у элемента есть собственный **тайм-аут активности** (или этот элемент используется включенным датчиком с тайм-аутом активности), в строке с меткой времени тайм-аут отображается в виде значка справа (*Входы: 15 мин*, с именем датчика, если он используется). Устаревшие входы отображаются ниже **оранжевым цветом** с их последней меткой времени (*Вход без обновления*), а значение и метка времени также становятся **оранжевыми** (см. [Мониторинг активности](#alive-monitoring)).
- **Предварительный просмотр JSON-массива**: Для датчиков с типом данных `json` значение отображает **первый элемент массива**, за которым следует количество дополнительных элементов (например, `{"t":1710000000000,"y":1250} (+543 дополнительных элемента)`).
- **Автоматическое обновление**: Вкладка обновляется автоматически каждые 5 секунд.
- **Переключатель макета**: Кнопка **Полная ширина** / **Гибкий** на панели инструментов переключает обе сетки между гибким многоколоночным макетом и одноколоночным макетом полной ширины. Выбор сохраняется в браузере и восстанавливается при следующем посещении.

### Навигация
Нажмите кнопку **Открыть конфигурацию** (в правом верхнем углу), чтобы перейти непосредственно на страницу конфигурации экземпляра этого адаптера.

## 4. Источники прогнозов
Данные прогноза погоды и прогноза погоды от pvforecast или аналогичных адаптеров можно записывать в InfluxDB с помощью **JSON-датчиков** на вкладке «Датчики». Просто установите тип данных на **JSON Array** и используйте предустановку **Automatic**.

### Как это работает
1. Адаптер подписывается на одно или несколько состояний в формате JSON (например, `pvforecast.0.summary.JSONData`).
2. При изменении состояния JSON адаптер анализирует массив JSON.
3. В **автоматическом** режиме адаптер сканирует каждую запись на наличие полей с известными значениями (`y`, `clearsky`, `temp`).
4. Для каждого обнаруженного поля в InfluxDB записывается точка данных с правильным измерением, полем и типом.
5. Поскольку InfluxDB перезаписывает точки с теми же измерениями, тегами и меткой времени, **существующие точки прогноза автоматически обновляются** при изменении исходных данных.

### Формат JSON
Исходное состояние должно содержать JSON-массив объектов. Каждый объект должен иметь поле метки времени (`t`) и одно или несколько полей значений:

```json
[
  { "t": 1709035200000, "y": 1500, "clearsky": 2000, "temp": 12.5 },
  { "t": 1709038800000, "y": 2200, "clearsky": 2800, "temp": 14.0 }
]
```

### Датчики прогноза по умолчанию
В комплект адаптера входят три предварительно настроенных датчика прогноза погоды:

| Датчик | Измерение | Поле | Тип | Поле JSON |
|--------|-------------|-------|------|------------|
| ПРОГНОЗ МОЩНОСТИ ИНВЕРТОРА | `inverter_forecast` | `power` | int | `y` |
| ПРОГНОЗ ТЕМПЕРАТУРЫ НА ОТКРЫТОМ ВОЗДУХЕ | `outdoor_forecast` | `temperature` | float | `temp` |
| ПРОГНОЗ ТЕМПЕРАТУРЫ НА ОТКРЫТОМ ВОЗДУХЕ | `прогноз_температуры_на_наружу` | `температура` | плавающая точка | `температура` |

В **автоматическом** режиме один JSON-датчик определяет все присутствующие поля и автоматически записывает их. Вам нужно лишь включить один датчик и указать ему путь к исходному состоянию в формате JSON.

### Обработка временных меток
- **Миллисекунды** (число >= 10^12): Используется напрямую
- **Секунды** (число < 10^12): Автоматически преобразуется в миллисекунды
- **Строка ISO**: Разобрана с помощью конструктора `Date`

## 5. Инструкция: pvForecast с pvnode
В этом разделе объясняется, как подключить адаптер **pvforecast** к базе данных SOLECTRUS InfluxDB для получения прогнозных данных.

### Предварительные условия
- ioBroker с установленным адаптером pvforecast
- Адаптер SOLECTRUS InfluxDB установлен и подключен к InfluxDB.

### Шаг 1: Выберите бэкэнд pvforecast
Адаптер pvforecast поддерживает два бэкэнда:

| Административная панель | Доступные поля | Описание |
|---------|-----------------|-------------|
| **Стандарт** | `y` (прогнозируемая мощность) | Только базовый прогноз мощности фотоэлектрических систем |
| **pvnode: версия 6.0.0** | `y`, `clearsky`, `temp` | Полный прогноз с данными об уровне солнечной радиации и температуре в безоблачное время |

> **Важно:** Поля `clearsky` (watt_clearsky) и `temp` **доступны только при использовании pvnode** в качестве бэкенда. Стандартный бэкенд pvforecast предоставляет только поле `y` (прогнозируемая мощность).

### Шаг 2: Настройка pvforecast
1. Установите адаптер pvforecast в ioBroker.
2. Настройте параметры вашей фотоэлектрической системы (местоположение, модули, ориентация и т. д.).
3. Если вам нужны данные о ясном небе и температуре, настройте **pvnode** в качестве бэкэнда.
4. Убедитесь, что `pvforecast.0.summary.JSONData` содержит массив JSON с данными прогноза.

### Шаг 3: Включите датчик JSON в SOLECTRUS InfluxDB
1. Откройте настройки адаптера SOLECTRUS InfluxDB.
2. Перейдите на вкладку **Датчики**.
3. Найдите датчик **INVERTER_POWER_FORECAST** (или любой другой датчик прогнозирования).
4. Установите **состояние источника ioBroker** на `pvforecast.0.summary.JSONData`.
5. Включите датчик (поставьте галочку)
6. Сохраните конфигурацию.

Адаптер автоматически определит все доступные поля в данных JSON и запишет их в InfluxDB:

- `y` -> `inverter_forecast.power` (всегда доступно)
- `clearsky` -> `inverter_forecast_clearsky.power` (только для pvnode)
- `temp` -> `outdoor_forecast.temperature` (только для pvnode)

### Шаг 4: Проверка в InfluxDB
После следующего обновления pvforecast проверьте свой бакет InfluxDB на наличие измерений `inverter_forecast`, `inverter_forecast_clearsky` (только pvnode) и `outdoor_forecast` (только pvnode). В первых двух вы должны увидеть поле `power`, а в третьем - `temperature`.

### Поиск неисправностей
- **Данные не записаны**: Убедитесь, что датчик включен и исходное состояние содержит допустимый массив JSON.
- **Только измерение `inverter_forecast` **: Ваш бэкенд pvforecast не pvnode. Переключитесь на pvnode, чтобы получить дополнительные поля `clearsky` и `temp`.
- **Неверные временные метки**: Убедитесь, что данные JSON используют метки времени Unix (секунды или миллисекунды) или строки ISO.

## 6. Формульный движок Data-SOLECTRUS
Механизм формул - это дополнительная функция, позволяющая вычислять производные значения из любых состояний ioBroker. Для её включения установите флажок **Включить Data-SOLECTRUS (механизм формул)** на вкладке InfluxDB.

При включении этой функции появляются две дополнительные вкладки:

- **Значения данных** -- Настройка вычисляемых элементов
- **Среда выполнения данных** -- Глобальные настройки опроса и создания моментальных снимков

### Концепции
- **Элементы** являются строительными блоками. Каждый элемент считывает одно или несколько состояний ioBroker и формирует выходное состояние в рамках `solectrus-influxdb.X.ds.*`.
- Элементы могут работать в трех режимах: **Источник**, **Формула** или **Конечный автомат**.
- Элементы можно организовать в **папки/группы** для лучшего обзора.
- Вычисленные значения могут использоваться в качестве источников данных с датчиков для хранения в InfluxDB.
- Каждый элемент имеет необязательное поле **Единица измерения** (заполнитель `W`). Если единица измерения не указана, в сетке Formula Engine на вкладке **Обзор SOLECTRUS** (см. раздел 3) числовые значения по умолчанию отображаются как `W` - так же, как и у датчиков InfluxDB. Логические и строковые значения никогда не отображаются с указанием единицы измерения.
- Для каждого элемента есть поле **Время ожидания активности в минутах (0 = отключено)** (по умолчанию: `0`). Оно отслеживает входные сигналы элемента, которые не используются ни одним включенным датчиком. Для каждого входа рядом с **neg→0** (в режиме *Источник*: **Мониторинг состояния источника (Alive)**) есть флажок **Alive**, позволяющий отключить мониторинг для этого входа; значение по-прежнему используется в расчете. См. [Мониторинг активности](#alive-monitoring).

## 7. Режимы элементов
### Режим источника
Отображает состояние одного объекта ioBroker. При необходимости извлекает значение из JSON-данных с помощью JSONPath.

| Настройки | Описание |
|---------|-------------|
| Исходное состояние ioBroker | Состояние для зеркалирования |
| JSONPath (необязательно) | Извлечь вложенное значение, например, `$.apower` |
| Тип данных | `number` (по умолчанию), `boolean`, `string` или `mixed` |
| Обнулить отрицательные значения | Заменить отрицательные выходные значения на 0 |

### Режим Формулы
Вычисляет значение на основе нескольких именованных входных данных, используя математическое выражение.

| Настройки | Описание |
|---------|-------------|
| Входные данные | Именованные переменные, каждая из которых связана с исходным состоянием ioBroker |
| Формульное выражение | Математическое выражение с использованием имен входных переменных |
| Тип данных | Тип выходных данных |
| Ограничение / Мин / Макс | Дополнительное ограничение выходного сигнала |

**Конфигурация ввода:**

| Поле | Описание |
|-------|-------------|
| Обозначения | Имя переменной, используемой в формуле (например, `pv1`) |
| Состояние источника ioBroker | Состояние, из которого нужно считать значение |
| JSONPath (необязательно) | Извлечение из полезной нагрузки JSON |
| Ограничьте входное отрицательное значение до 0 | Ограничьте это конкретное входное значение перед вычислением формулы |

**Пример формулы:** `pv1 + pv2 + pv3`

### Доступные функции
| Функция | Описание | Пример |
|----------|-------------|---------|
| `min(a, b)` | Меньшее из двух значений | `min(5, 10)` = 5 |
| `clamp(v, min, max)` | Ограничение границ | `clamp(v, 0, 100)` |
| `IF(cond, then, else)` | Условный | `IF(soc > 80, surplus, 0)` |
| `abs(v)` | Абсолютное значение | `abs(-5)` = 5 |
| `round(v)` | Округлить до целого числа | `round(3.7)` = 4 |
| `floor(v)` / `ceil(v)` | Округление вниз / вверх | `floor(3.7)` = 3 |
| `pow(base, exp)` | Мощность | `pow(2, 3)` = 8 |
| `pow(base, exp)` | Power | `pow(2, 3)` = 8 |

### Функции состояния (расширенные)
Эти функции считывают состояния ioBroker непосредственно в формуле, без определения именованных входных параметров:

| Функция | Описание | Пример |
|----------|-------------|---------|
| `s("id")` | Считывать состояние как безопасное число (0, если недоступно) | `s("hm-rpc.0.power") + 100` |
| `jp("id", "$.path")` | Извлечение значения из состояния JSON через JSONPath | `jp("shelly.0.json", "$.apower")` |
| `jp("id", "$.path")` | Извлечение значения из состояния JSON через JSONPath | `jp("shelly.0.json", "$.apower")` |

### Поддерживаемые операторы
`+`, `-`, `*`, `/`, `%`, `()`, `&&`, `||`, `!`, `==`, `!=`, `>=`, `<=`, `>`, `<`, `? :`

## 8. Конструктор формул
Нажмите кнопку **Конструктор...** рядом с полем ввода формулы, чтобы открыть визуальный конструктор формул.

Строительная компания предоставляет:

- **Переменные (входные данные)** -- Нажмите, чтобы вставить именованные входные переменные
- **Операторы** -- Нажмите, чтобы вставить операторы с всплывающими подсказками, поясняющими каждый из них.
- **Функции** -- Вставка шаблонов функций (`min`, `max`, `clamp`, `IF`)
- **Функции состояния** -- Вставьте `s()`, `v()` или `jp()` с помощью диалогового окна выбора состояния.
- **Примеры** -- Типичные формулы расчета (сумма PV, излишек, процент, ограничение, условия)
- **Предварительный просмотр в реальном времени** -- Отображение результата формулы в режиме реального времени (требуется работающий адаптер)

Формула всегда редактируема как обычный текст. Конструктор вставляет блоки только в позиции курсора.

## 9. Режим конечного автомата
В режиме конечного автомата генерируются строковые или логические состояния на основе правил. Правила оцениваются сверху вниз; **побеждает первое совпадающее правило**.

Это полезно для:

- Преобразование числовых кодов состояния в читаемые метки.
- Определение режимов работы на основе показаний нескольких датчиков.
- Создание логических флагов на основе сложных условий

### Конфигурация
| Настройки | Описание |
|---------|-------------|
| Входные данные | Именованные переменные (аналогично режиму формул) |
| Тип данных | `string` или `boolean` |
| Правила | Упорядоченный список пар условие/выход |

### Правила
Каждое правило имеет:

| Поле | Описание |
|-------|-------------|
| Условие | Формульное выражение, результатом которого является истинное/ложное значение. Используйте имена входных переменных и операторы. |
| Выходное значение | Строковое или логическое значение, которое будет выведено при выполнении условия. |

**Особые условия:**

- `true` или пустое значение = правило по умолчанию/резервное правило (всегда совпадает)
- Используйте входные переменные и операторы: `soc < 10`, `battery > 80 && surplus > 0`

### Пример
Для элемента с входными параметрами `soc` (уровень заряда батареи) и `surplus` (избыток солнечной энергии):

| Условие | Выходное значение |
|-----------|-------------|
| `soc < 10` | `Battery-Empty` |
| `surplus > 1000 && soc > 80` | `Full-Export` |
| `true` | `Normal` |
| `истина` | `Нормальный` |

Результат: В зависимости от текущих значений, выходное состояние будет содержать `Battery-Empty`, `Battery-Low`, `Full-Export` или `Normal`.

## 11. Мониторинг и буфер
### Мониторинг в режиме реального времени
Адаптер автоматически отслеживает, регулярно ли обновляются значения датчиков. Поле **Alive Timeout (мин, 0 = отключено)** можно настроить индивидуально для каждого датчика в **Экспертном режиме** (по умолчанию: 60 минут). Если установить значение таймаута равным `0`, мониторинг в режиме реального времени для этого датчика полностью отключается - строка с меткой времени скрывается в обзоре датчиков.

Если датчик не получает новых значений в течение времени, превышающего заданный тайм-аут, адаптер регистрирует предупреждение:

```
Sensor "INVERTER_POWER": no update since 4/5/2026, 6:30:00 PM (longer than 60 minute(s))
```

Кроме того, в **вкладке** отображается последняя метка времени затронутого датчика оранжевым цветом, что позволяет быстро определить устаревшие данные с датчиков, не открывая журнал.

Если источником сигнала датчика является состояние алгоритма обработки формул (`ds.*`), то все входные данные этого элемента также отслеживаются с тем же таймаутом, включая входные данные вложенных элементов формулы. Само состояние формулы пересчитывается при каждом такте и в противном случае всегда будет выглядеть актуальным, даже если обновление входного значения прекратилось. В предупреждении указаны название датчика и затронутый входной сигнал:

```
Sensor "HOUSE_POWER → modbus.0.inputRegisters.grid": no update since 4/5/2026, 6:30:00 PM (update expected by 4/5/2026, 7:30:00 PM)
```

В **вкладочном режиме** карточка датчика также помечается **оранжевым** цветом, и каждый затронутый вход отображается с его последней меткой времени (*Вход без обновления*). Список устаревших входов также доступен в формате JSON в состоянии `solectrus-influxdb.X.info.staleInputs`.

Устаревшие входные данные по-прежнему используются в расчетах - механизм формул использует последнее полученное значение. Входные данные, которые записываются только при изменении (например, показания счетчика или статус), в противном случае будут сообщаться постоянно. Именно поэтому мониторинг можно отключить **для каждого входного параметра** в механизме формул с помощью флажка **Alive** (для элементов в режиме *Source* с **Monitor source state (Alive)**). По умолчанию: включено. Если входной параметр с отключенным мониторингом сам является элементом формулы, его входные данные также не отслеживаются. Значения, на которые в формуле ссылаются только через `s()`/`v()`/`jp()` и которые не настроены как входные данные, всегда отслеживаются.

**Внутренние элементы формул:** Если ни один из включенных датчиков не использует элемент формулы, он может получить собственный тайм-аут в редакторе механизма формул через **Тайм-аут активности в мин (0 = отключено)** (по умолчанию: `0`). Затем его входные данные отслеживаются так же, как и для датчика; флажок **Активность** для каждого входа также применяется здесь. Предупреждение начинается с **Формула** и называет элемент с префиксом `ds.`, например, `Formula "ds.pv → inverter.0.power": no update since …`; уведомление аналогично. На вкладке **Механизм формул** карточка отображает тайм-аут в виде значка (*Входы: 15 мин*); при устаревших входных данных значение и метка времени становятся **оранжевыми**, а затронутые входные данные отображаются в списке. Список хранится в формате JSON в состоянии `solectrus-influxdb.X.info.staleFormulaInputs`. Приоритет отдается датчику: если включенный датчик использует элемент, применяется только таймаут датчика, а таймаут элемента игнорируется - таким образом, элемент никогда не будет отображаться дважды. Элемент, который не используется ни одним включенным датчиком (например, потому что его датчик отключен), проверяется со своим собственным таймаутом, даже если другой датчик проверяет тот же вход через другой элемент. В обзоре карточка формулы по-прежнему отображает устаревшие входные данные, обнаруженные датчиком, с указанием его таймаута и имени в значке (например, *Входы: 10 мин (малые устройства)*).

Предупреждение повторяется не более одного раза за период ожидания для каждого датчика, чтобы избежать переполнения логов. Установите время ожидания на `0`, чтобы отключить проверку для отдельного датчика (только в экспертном режиме). Для вновь созданных датчиков по умолчанию установлено время ожидания `60` минут. Время ожидания должно быть больше интервала обновления соответствующего адаптера источника.

### Мониторинг значений (максимальное значение)
Мониторинг значений **отключен по умолчанию** (максимальное значение = 0). В **Экспертном режиме** для каждого числового датчика можно установить индивидуальное максимальное значение. Единица измерения отображается рядом со значком максимального значения в обзоре датчиков (по умолчанию `W`, если единица измерения не указана). Когда максимальное значение > 0, оно отображается в виде значка рядом с текущим значением в обзоре датчиков. Когда мониторинг значений отключен (максимальное значение = 0), значок скрывается.

### Состояния адаптера
| Штат | Описание |
|-------|-------------|
| `info.connection` | `true` если InfluxDB доступен |
| `info.buffer.oldest` | Временная метка самой старой буферизованной точки |
| `info.buffer.clear` | Кнопка для ручной очистки буфера |
| `info.lastError` | Последнее сообщение о критической ошибке |
| `info.lastError` | Последнее сообщение о критической ошибке |

### Состояния Data-SOLECTRUS (при включении)
Вычисленные значения отображаются в разделе `solectrus-influxdb.X.ds.*` вместе с диагностическими состояниями для каждого элемента.

### Поведение буфера
- Значения постоянно сохраняются на диске в буфере (`buffer.json`).
- Максимальный размер буфера: 100 000 точек
- Очистка базы данных происходит только при подтверждении **активного соединения с InfluxDB** (функция `ensureInflux()` проверяет это перед каждой очисткой).
- При сбое InfluxDB интервалы повторных попыток увеличиваются в геометрической прогрессии (до 5 минут).
- После переподключения все буферизованные точки очищаются.
- Во время сброса буфера он никогда не изменяется (схема создания снимка и подкачки).
- В случае неудачной операции сброса данные автоматически восстанавливаются в буфер.

## 12. Использование вычисленных значений в качестве источников данных с датчиков
Вы можете использовать вычисленные значения Data-SOLECTRUS в качестве входных данных для датчиков, чтобы записывать их в InfluxDB:

1. Создайте вычисляемый элемент (источник, формулу или конечный автомат) на вкладке **Значения данных**.
2. На вкладке **Датчики** добавьте новый датчик.
3. В качестве **исходного состояния ioBroker** выберите состояние вычисляемого значения: `solectrus-influxdb.X.ds.<outputId>`
4. Настройте измерение, поле и тип данных как обычно.

Адаптер автоматически обрабатывает порядок инициализации - подписки на датчики для состояний `ds.*` работают, даже если механизм формул запускается после настройки датчиков.

## 14. Уведомления
Адаптер может отправлять сообщения через настраиваемые поставщики уведомлений при возникновении важных событий.

### Активация
Вкладка **Уведомления** скрыта до тех пор, пока не будут включены уведомления. Установите флажок **Включить уведомления** на вкладке **InfluxDB**, чтобы отобразить её и активировать эту функцию, затем:

1. Выберите необходимые события-триггеры.
2. Настройте как минимум одного поставщика уведомлений.

### Триггеры
| Событие | Описание |
|-------|-------------|
| **Сбой подключения/восстановления InfluxDB** | **❗** Отправлено при первом сбое подключения и **✅** снова при восстановлении подключения |
| **Тайм-аут активности датчика** | **⚠️** Отправляется, когда датчик не предоставляет обновление в течение заданного тайм-аута (только для ненулевых значений) |
| **Тайм-аут выполнения формулы** | **⚠️** Отправляется, когда ввод элемента формулы с собственным тайм-аутом выполнения (не используемым включенным датчиком) не обеспечивает обновление в течение тайм-аута (только для ненулевых значений); та же опция и ограничение скорости, что и для датчиков |
| **Превышено максимальное значение** (`notifyOnMaxValueExceeded`) | **⚠️** Отправляется, когда значение датчика превышает заданное максимальное значение; ограничение частоты отправки - не более одного раза в час для каждого датчика |
| **Отсутствует поле JSON** (`notifyOnJsonFieldMissing`) | **⚠️** Отправляется один раз за сессию, когда известное поле JSON (`y`, `clearsky`, `temp`) полностью отсутствует в исходных данных - указывает, что бэкенд не предоставляет это поле (например, `clearsky`/`temp` требуют pvnode). Уведомление сбрасывается, если поле появляется снова. |

### Поддерживаемые поставщики
| Поставщик | Требование |
|----------|-------------|
| **Телеграм** | Адаптер ioBroker для Telegram установлен и настроен |
| **Pushover** | Адаптер ioBroker Pushover установлен и настроен |
| **WhatsApp** | Адаптер ioBroker whatsapp-cmb установлен и настроен |
| **Электронная почта** | Адаптер электронной почты ioBroker установлен и настроен |
| **Сигнал** | Адаптер ioBroker signal-cmb установлен и настроен |
| **Матрица** | Адаптер ioBroker matrix-org установлен и настроен |
| **Synology Chat** | Адаптер ioBroker synochat установлен и настроен |

Можно одновременно настроить несколько поставщиков. Перед отправкой адаптер проверяет, активен ли соответствующий экземпляр адаптера, и регистрирует предупреждение, если экземпляр не запущен.

### Выбор экземпляра
У каждого провайдера есть выпадающий список **Экземпляр**. Доступные экземпляры адаптера считываются автоматически и предлагаются для выбора. Это позволяет легко выбрать конкретный экземпляр, когда запущено несколько экземпляров одного и того же адаптера.

### Примечания
- Локализация уведомлений осуществляется с помощью функции `getNotificationMessage()` с использованием настроенного `systemLanguage`.
- При сбоях подключения к InfluxDB уведомление отправляется при **первом** сбое и может повторяться через `notifyRepeatMinutes`, пока соединение остается неактивным.
- При использовании параметра **Задержка перед уведомлением о сбое соединения** уведомление отправляется только после того, как соединение будет разорвано в течение указанного времени. Если соединение восстановится раньше, уведомление о сбое или восстановлении не отправляется (например, при кратковременных сбоях во время резервного копирования NAS). 0 = немедленно.
- Уведомления о превышении времени ожидания датчика отправляются при выполнении заданного условия ожидания (экспертный режим) и регулируются параметром `notifyRepeatMinutes`. То же самое относится к уведомлениям о превышении времени ожидания формулы с учетом времени ожидания элемента формулы.

## 15. Резервное копирование
### Встроенная вкладка резервного копирования
Вкладка **Резервное копирование** в конфигурации адаптера позволяет создавать, загружать, восстанавливать, скачивать и удалять резервные копии этого экземпляра напрямую - установка других адаптеров не требуется. Резервная копия содержит:

- Общие настройки (параметры подключения)
- Конфигурация датчика: внутренний/внешний, активированный/деактивированный
- Элементы Data-SOLECTRUS (расчеты/формулы) и их папки.
- Все папки объектов/каналы/состояния, созданные этим экземпляром.

Резервные копии хранятся локально на этом хосте ioBroker. По умолчанию они размещаются в собственном каталоге данных этого экземпляра, но вы можете выбрать пользовательское место хранения (например, другой диск или смонтированную сетевую папку) с помощью поля «Каталог резервных копий». Используйте поле «Сохранять последние N резервных копий», чтобы управлять тем, сколько самых последних резервных копий будет автоматически сохраняться; более старые удаляются при создании каждой новой резервной копии. Восстановление резервной копии автоматически перезапускает экземпляр, поэтому восстановленная конфигурация вступает в силу.

> **Примечание:** Токен InfluxDB является защищенной/зашифрованной настройкой и никогда не включается в эти резервные копии. После восстановления его необходимо будет ввести вручную на вкладке **InfluxDB**.

### Хранилище WebDAV
Как и в случае с ioBroker.backitup, вкладка «Резервное копирование» также может хранить резервные копии на сервере WebDAV (например, Nextcloud, ownCloud, NAS). Включите параметр **Также хранить резервные копии на сервере WebDAV** и введите:

- **URL WebDAV** - например, `https://<example.com>/remote.php/dav/files/<username>/` для Nextcloud
- **Имя пользователя** и **Пароль** (пароль хранится в зашифрованном виде и никогда не включается в резервные копии)
- **Каталог WebDAV** - целевой каталог на сервере (по умолчанию `/solectrus-influxdb`, создается автоматически)
- **Разрешить только подписанные сертификаты** - отключите эту опцию для серверов с самоподписанным сертификатом.
- **Удалить старые резервные копии WebDAV** - сохраняет на сервере только последние N резервных копий (то же количество, что и "Сохранить последние N резервных копий")

Используйте **Проверить соединение**, чтобы проверить настройки. Каждая резервная копия, созданная с помощью **Создать резервную копию сейчас**, также загружается на WebDAV-сервер. Сохраненные там резервные копии отображаются ниже локальных резервных копий в разделе **Резервные копии WebDAV** и могут быть восстановлены или удалены там. При восстановлении резервная копия сначала копируется в локальный каталог резервных копий, а затем восстанавливается как локальная резервная копия.

> **Примечание:** Диалоговое окно конфигурации администратора не автоматически считывает восстановленные настройки, пока оно открыто (оно отображает только то, что было загружено при открытии). После восстановления закройте диалоговое окно конфигурации адаптера и откройте его снова, чтобы увидеть восстановленные значения.
