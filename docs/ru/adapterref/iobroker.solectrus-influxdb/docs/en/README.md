## 1. Настройка InfluxDB

Откройте настройки адаптера и перейдите на вкладку **InfluxDB** .

| Поле                | Описание                                                          |
| ------------------- | ----------------------------------------------------------------- |
| URL                 | Адрес сервера InfluxDB 2.x (например)`http://192.168.1.10:8086` ) |
| Организация         | Ваша организация InfluxDB                                         |
| Ведро               | Целевой сегмент для данных временных рядов                        |
| Токен               | API-токен с правами **на запись**                                 |
| Интервал опроса (с) | Как часто собираются показания датчиков (5-30 секунд)             |

При запуске адаптер проверяет соединение, записывая контрольную точку. Состояние соединения отображается в...`info.connection` .

Внизу этой вкладки вы найдете:

- Флажок для включения механизма формул **Data-SOLECTRUS** (см. раздел 5)
- Флажок для включения **экспертного режима** (см. раздел 2 — Датчики)

## 2. Датчики

Перейдите на вкладку **«Датчики»** . В редакторе основных/подробных данных отображаются все настроенные датчики с их текущим состоянием и возможностью группировки.

### Стандартный режим против экспертного режима

По умолчанию адаптер работает в **стандартном режиме** . В списке датчиков отображаются все предварительно настроенные датчики (INVERTER\_POWER, BATTERY\_SOC, HOUSE\_POWER, датчики прогноза и т. д.). В стандартном режиме:

- Список датчиков можно свернуть по **папкам/группам** . Все предварительно настроенные датчики SOLECTRUS изначально находятся в группе **датчиков SOLECTRUS по умолчанию** . Существующие датчики из более старых конфигураций, которые не соответствуют набору датчиков по умолчанию, автоматически назначаются в группу **пользовательских датчиков** .
- **Редактируемые параметры** : Исходное состояние (состояние ioBroker), флажок «Включено».
- **Только для чтения** : Название датчика, Тип данных, Измерение, Поле, Предустановка JSON.
- **Скрытые элементы** : кнопки «Добавить», «Удалить», «Дублировать», внутренний флажок, папка/группа, единица измерения, максимальное значение, время ожидания активности.

Это гарантирует, что новички смогут легко включать датчики и назначать состояния источников, не изменяя случайно сопоставление InfluxDB. В стандартном режиме действуют следующие настройки по умолчанию: **мониторинг значений отключен** (максимальное значение = 0) и таймаут активности **60 минут** . Точная настройка доступна в экспертном режиме.

Для разблокировки полного доступа включите **экспертный режим** на странице настроек InfluxDB. В экспертном режиме:

- Все поля доступны для редактирования.
- Датчики можно добавлять, удалять, дублировать и изменять их порядок.
- Вновь созданные датчики изначально находятся в группе **«Пользовательские датчики»** , и при необходимости их можно перегруппировать там или сохранить без группы.
- Предварительные настройки JSON можно перевести в пользовательский режим.

- `⚪` = датчик отключен

### Как работают датчики

1. Адаптер подписывается на состояние источника каждого датчика.
2. Значения отражены ниже`solectrus-influxdb.X.sensors.*`
3. При каждом интервале опроса текущие значения добавляются в буфер записи ( **Collect** ).
4. Сразу после сбора данных буфер сбрасывается в InfluxDB ( **Flush** ).

Датчики, помеченные как **«Внутренние»** , по-прежнему отображаются в зеркальном отображении.`solectrus-influxdb.X.sensors.*` и остаются частью мониторинга alive/max, но исключаются из операций записи в InfluxDB.

### Архитектура сбора и смыва

Сбор и промывка происходят практически одновременно, не блокируя друг друга:

1. **Функция Collect** собирает все значения датчиков и записывает их в буфер.
2. **Мгновенная очистка** — после сбора данных очистка запускается на следующем такте цикла событий (без дополнительного интервала ожидания).
3. **Функция создания снимка и замены** — при начале операции сброса текущий буфер берется как пакет и заменяется новым пустым массивом. Пока операция сброса ожидает ответа от InfluxDB, параллельный процесс сбора данных уже записывает данные в новый (пустой) буфер. Пакет данных никогда не изменяется во время операции сброса.
4. **Восстановление после сбоя** — если операция сброса не удалась, пакет данных добавляется в начало текущего буфера в хронологическом порядке. Значения не теряются.
5. **Защита от перекрытия** —`isFlushing` Этот флаг предотвращает одновременное выполнение нескольких операций сброса.

### защита NaN

Недопустимые значения (`NaN` для целых чисел/чисел с плавающей запятой,`null` /`undefined` (для строк) автоматически пропускаются с предупреждением в логе.

### Отрицательные значения

SOLECTRUS не принимает отрицательные значения. Если датчик выдает отрицательное значение после запуска адаптера, в **журнал** записывается предупреждение. Значения по-прежнему отправляются в InfluxDB, но могут привести к некорректным вычислениям. Чтобы исправить это, проверьте состояния источника или используйте механизм формул Data-SOLECTRUS с опцией **«Ограничить отрицательные значения до 0»** .

### автоматическое определение устройства

Когда в административном интерфейсе выбирается исходное состояние (через диалоговое окно **«Выбор»** или путем ввода идентификатора состояния и закрытия поля), административный интерфейс считывает следующее:`common.unit` свойство объекта ioBroker и заполняет поле **«Единица измерения»** . Если в состоянии не определена единица измерения, поле остается пустым.`W` В качестве значения по умолчанию на вкладке «Обзор» используется единица измерения. В **экспертном режиме** единицу измерения всегда можно изменить вручную.

### Проверка максимального значения

Каждый цифровой датчик (`int` ,`float` (или тип по умолчанию) поддерживает поле **«Максимальное значение»** (настраивается в экспертном режиме). Если собранное значение превышает этот лимит:

1. В журнале зарегистрировано предупреждение:`Sensor "..." delivers implausible value (X > max Y). Using last valid value (Z) instead.`
2. В InfluxDB отправляется **последнее допустимое значение** (самое последнее значение, равное или меньшее предела).
3. Если для данного датчика еще не получено допустимое значение, точка данных полностью пропускается.

Это предотвращает искажение данных временного ряда из-за временных скачков показаний датчика (например, кратковременного импульсного измерения в 99999 Вт).

Значение по умолчанию — **0 (отключено)** — мониторинг значений для новых датчиков по умолчанию отключен. В экспертном режиме можно установить индивидуальное ограничение для каждого датчика (например,`15000` или`5000` (для вторичного инвертора). Когда установлено максимальное значение`0` Для данного датчика мониторинг значений отключен.

### Конфликты типов полей

Если InfluxDB сообщает о конфликте типов полей (например, о записи числа с плавающей запятой в существующее целочисленное поле), соответствующий датчик автоматически отключается, а буфер очищается.

## 3. Вкладка «Обзор датчиков»

Вкладка **«Обзор SOLECTRUS»** (доступная через панель вкладок в разделе адаптера) предоставляет краткий обзор всех настроенных и активных датчиков и элементов данных в режиме реального времени.

![Пример обзора датчика](../../../../../en/adapterref/iobroker.solectrus-influxdb/docs/img/sensor-overview.svg)

### Функции

- **Легенда цветов** (панель инструментов, в правом верхнем углу рядом с заголовком): позволяет быстро понять значение цветов на карточке — **зеленый** = активный датчик, **желтый** = внутренний датчик, **оранжевый** = превышено время ожидания, **красный** = превышено максимальное значение.
- Кнопка на панели вкладок имеет общее название **«Датчики** »; содержимое под ней разделено на две секции, каждая со своим заголовком: **«Датчики InfluxDB»** (синяя иконка в виде ромба, датчики, фактически записанные в InfluxDB) и **«Внутренние датчики»** (🔒, отображаются только при наличии хотя бы одного датчика).
- **Сетка «Датчики InfluxDB»** : отображает все включенные датчики, данные с которых фактически записываются в InfluxDB, в виде компактных карточек в адаптивной сетке. Каждая карточка отображает:
  - Значок **с названием датчика** и **типом данных** (`int` ,`float` ,`bool` ,`string` ,`json` )
  - **Строка значений** (только для цифровых датчиков): **текущее значение, выровненное по левому краю, с указанием единицы измерения** (например,`2697 W` **Значок максимального значения,** выровненный по правому краю, отображается только тогда, когда максимальное значение > 0 (активен мониторинг значений). Отображает _«н/д»_ , если значение еще не получено. Значения JSON отображаются компактно моноширинным шрифтом. После превышения заданного времени ожидания текущего значения оно становится **оранжевым** ; если также превышено максимальное значение, **красный цвет** имеет приоритет над оранжевым.
  - **Измерение: поле** — целевое местоположение в InfluxDB (разделенное двоеточием)
  - **Исходное состояние** — идентификатор считываемого состояния ioBroker (сокращенный, полный путь отображается при наведении курсора).
  - **Строка с временной меткой** (отображается, если настроен тайм-аут активности): **временная метка,** выровненная по левому краю (дата и время последнего получения датчиком нового значения); **следующее ожидаемое обновление,** выровненное по правому краю (только время, без метки, автоматически вычисляется как временная метка + интервал тайм-аута — ручной ввод не требуется). Если текущее значение равно 0, для расчета следующего обновления используется 60-минутный резервный интервал. Строка отображается **оранжевым** цветом, когда тайм-аут активности превышен.
- **Сетка внутренних датчиков** (отображается только в том случае, если хотя бы у одного датчика включена опция **«Внутренний»** ): отдельный раздел под сеткой датчиков InfluxDB, использующий ту же структуру карточек, но с **желтой левой рамкой** и **желтым текущим значением** . Поскольку данные с этих датчиков не записываются в InfluxDB, они четко отделены от обычных (зеленых) датчиков.
- **Сетка механизма формул** (отображается только при включенной функции Data-SOLECTRUS): отображает все активные вычисляемые элементы в одном макете карточки, с указанием режима, текущего значения, идентификатора состояния и формулы/выражения. Размер шрифта остается неизменным при любой ориентации устройства. Числовые значения отображают **единицу измерения** (например,`2697 W` ) — единица измерения, указанная для данного элемента, по умолчанию —`W` Если значение не задано, отображаются логические и строковые результаты без единицы измерения. Поскольку элементы Data-SOLECTRUS никогда не записываются в InfluxDB напрямую (записываются только данные с датчиков), эти карточки всегда оформлены как **внутренние датчики** , с **желтой рамкой** и **желтым значением** .
- **Предварительный просмотр массива JSON** : для датчиков с определенным типом данных.`json` Значение отображает **первый элемент массива,** за которым следует количество дополнительных элементов (например,`{"t":1710000000000,"y":1250} (+543 more entries)` ).
- **Автоматическое обновление** : вкладка обновляется автоматически каждые 5 секунд.
- **Переключатель макета** : кнопка « **Полная ширина** / **Гибкий»** на панели инструментов переключает обе сетки между гибким многоколоночным макетом и одноколоночным макетом полной ширины. Выбор сохраняется в браузере и восстанавливается при следующем посещении.

### Навигация

Нажмите кнопку **«Открыть конфигурацию»** (в правом верхнем углу), чтобы перейти непосредственно на страницу конфигурации экземпляра этого адаптера.

## 4. Источники прогнозов

Данные прогноза погоды и прогноза погоды от pvforecast или аналогичных адаптеров можно записывать в InfluxDB с помощью **JSON-датчиков** на вкладке «Датчики». Просто установите тип данных на **«JSON-массив»** и используйте предустановку **«Автоматический»** .

### Как это работает

1. Адаптер подписывается на одно или несколько состояний JSON (например,`pvforecast.0.summary.JSONData` )
2. При изменении состояния JSON адаптер анализирует массив JSON.
3. В **автоматическом** режиме адаптер сканирует каждую запись на наличие полей с известными значениями (`y` ,`clearsky` ,`temp` )
4. Для каждого обнаруженного поля в InfluxDB записывается точка данных с правильным измерением, полем и типом.
5. Поскольку InfluxDB перезаписывает точки с теми же измерениями, тегами и меткой времени, **существующие точки прогноза автоматически обновляются** при изменении исходных данных.

### формат JSON

Исходное состояние должно содержать массив объектов в формате JSON. Каждый объект должен иметь поле с меткой времени (`t` ) и одно или несколько полей значений:

```json
[
  { "t": 1709035200000, "y": 1500, "clearsky": 2000, "temp": 12.5 },
  { "t": 1709038800000, "y": 2200, "clearsky": 2800, "temp": 14.0 }
]
```

### Датчики прогноза по умолчанию

В комплект адаптера входят три предварительно настроенных датчика прогноза погоды:

| Датчик                                  | Измерение                    | Поле          | Тип     | Поле JSON  |
| --------------------------------------- | ---------------------------- | ------------- | ------- | ---------- |
| ПРОГНОЗ МОЩНОСТИ ИНВЕРТОРА              | `inverter_forecast`          | `power`       | инт     | `y`        |
| INVERTER\_POWER\_FORECAST\_CLEARSKY     | `inverter_forecast_clearsky` | `power`       | инт     | `clearsky` |
| ПРОГНОЗ ТЕМПЕРАТУРЫ НА ОТКРЫТОМ ВОЗДУХЕ | `outdoor_forecast`           | `temperature` | плавать | `temp`     |

В **автоматическом** режиме один JSON-датчик определяет все присутствующие поля и автоматически записывает их. Вам нужно лишь включить один датчик и указать ему путь к исходному состоянию в формате JSON.

### Обработка временных меток

- **Миллисекунды** (число >= 10^12): используются напрямую
- **Секунды** (число < 10^12): Автоматически преобразуются в миллисекунды
- **ISO-строка** : Разобрана с помощью`Date` конструктор

## 5. Инструкция: pvForecast с pvnode

В этом разделе объясняется, как подключить адаптер **pvforecast** к базе данных SOLECTRUS InfluxDB для получения данных прогноза.

### Предварительные требования

- ioBroker с установленным адаптером pvforecast
- Адаптер Solectrus InfluxDB установлен и подключен к InfluxDB.

### Шаг 1: Выберите бэкэнд pvforecast.

Адаптер pvforecast поддерживает два бэкэнда:

| Бэкенд                     | Доступные поля                | Описание                                                                                 |
| -------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------- |
| **Стандарт**               | `y` (прогнозируемая мощность) | Только базовый прогноз выработки солнечной энергии.                                      |
| **pvnode: в версии 6.0.0** | `y` ,`clearsky` ,`temp`       | Полный прогноз с указанием количества солнечного излучения и температуры при ясном небе. |

> **Важно:** Поля`clearsky` (watt\_clearsky) и`temp` **Доступны только при использовании pvnode** в качестве бэкенда. Стандартный бэкенд pvforecast предоставляет только следующие возможности:`y` (прогнозируемая мощность) поле.

### Шаг 2: Настройка pvforecast

1. Установите адаптер pvforecast в ioBroker.
2. Настройте параметры вашей фотоэлектрической системы (расположение, модули, ориентация и т. д.).
3. Если вам нужны данные о ясном небе и температуре, настройте **pvnode** в качестве бэкэнда.
4. Проверьте это.`pvforecast.0.summary.JSONData` содержит JSON-массив с прогнозными данными.

### Шаг 3: Включите датчик JSON в SOLECTRUS InfluxDB

1. Откройте настройки адаптера SOLECTRUS InfluxDB.
2. Перейдите на вкладку **«Датчики»** .
3. Найдите датчик **INVERTER\_POWER\_FORECAST** (или любой другой датчик прогнозирования).
4. Установите **значение Source State для ioBroker** .`pvforecast.0.summary.JSONData`
5. Включить датчик (флажок)
6. Сохраните конфигурацию

Адаптер автоматически определит все доступные поля в данных JSON и запишет их в InfluxDB:

- `y` ->`inverter_forecast.power` (всегда в наличии)
- `clearsky` ->`inverter_forecast_clearsky.power` (Только для pvnode)
- `temp` ->`outdoor_forecast.temperature` (Только для pvnode)

### Шаг 4: Проверка в InfluxDB

После следующего обновления pvforecast проверьте свой InfluxDB на наличие данных измерений.`inverter_forecast` ,`inverter_forecast_clearsky` (только pvnode), и`outdoor_forecast` (Только для pvnode). Вы должны увидеть это поле.`power` в первых двух и`temperature` в третьем.

### Поиск неисправностей

- **Данные не записаны** : Убедитесь, что датчик включен и исходное состояние содержит допустимый массив JSON.
- **Только`inverter_forecast` Измерение** : Ваш бэкэнд pvforecast не использует pvnode. Переключитесь на pvnode для получения дополнительных данных.`clearsky` и`temp` поля
- **Неверные временные метки** : Убедитесь, что данные JSON используют метки времени Unix (секунды или миллисекунды) или строки ISO.

## 6. Формульный движок Data-SOLECTRUS

Механизм формул — это дополнительная функция, позволяющая вычислять производные значения из любых состояний ioBroker. Для её включения установите флажок **«Включить Data-SOLECTRUS (механизм формул)»** на вкладке InfluxDB.

При включении этой функции появляются две дополнительные вкладки:

- **Значения данных** — Настройка вычисляемых элементов
- Настройки **среды выполнения данных** — глобальные параметры опроса и создания моментальных снимков.

### Концепции

- **Элементы** являются строительными блоками. Каждый элемент считывает одно или несколько состояний ioBroker и выдает выходное состояние.`solectrus-influxdb.X.ds.*`
- Элементы могут работать в трех режимах: **Источник** , **Формула** или **Конечный автомат.**
- Для лучшего обзора элементы можно организовать в **папки/группы.**
- Вычисленные значения можно использовать в качестве источников данных с датчиков для хранения в InfluxDB.
- Для каждого элемента предусмотрено необязательное поле **«Единица измерения»** (заполнитель).`W` Если единица измерения не указана, в сетке «Формулировочный механизм» на вкладке **«Обзор SOLECTRUS»** (см. раздел 3) числовые значения по умолчанию отображаются в формате .`W` — То же самое, что и с датчиками InfluxDB. Логические и строковые значения никогда не отображаются вместе с единицами измерения.

## 7. Режимы элементов

### Исходный режим

Отображает состояние одного объекта ioBroker. При необходимости извлекает значение из JSON-данных с помощью JSONPath.

| Параметр                             | Описание                                                 |
| ------------------------------------ | -------------------------------------------------------- |
| ioBroker Source State                | Состояние, которое нужно отразить                        |
| JSONPath (необязательно)             | Извлечь вложенное значение, например`$.apower`           |
| Тип данных                           | `number` (по умолчанию),`boolean` ,`string` , или`mixed` |
| Установите отрицательный полюс на 0. | Замените отрицательные выходные значения на 0.           |

### Режим Формулы

Вычисляет значение на основе нескольких именованных входных данных, используя математическое выражение.

| Параметр             | Описание                                                                          |
| -------------------- | --------------------------------------------------------------------------------- |
| Входные данные       | Именованные переменные, каждая из которых связана с исходным состоянием ioBroker. |
| Формульное выражение | Математическое выражение с использованием имен входных переменных                 |
| Тип данных           | Тип вывода                                                                        |
| Зажим / Мин / Макс   | Дополнительное ограничение выходного сигнала                                      |

**Конфигурация ввода:**

| Поле                                                         | Описание                                                              |
| ------------------------------------------------------------ | --------------------------------------------------------------------- |
| Ключ                                                         | Имя переменной, используемое в формуле (например)`pv1` )              |
| ioBroker Source State                                        | Для считывания значения из состояния необходимо считать значение.     |
| JSONPath (необязательно)                                     | Фрагмент из JSON-данных                                               |
| Ограничьте входной сигнал, установив его отрицательным на 0. | Перед вычислением формулы ограничьте ввод этого конкретного значения. |

**Пример формулы:**`pv1 + pv2 + pv3`

### Доступные функции

| Функция                | Описание                  | Пример                     |
| ---------------------- | ------------------------- | -------------------------- |
| `min(a, b)`            | Меньшее из двух значений  | `min(5, 10)` = 5           |
| `max(a, b)`            | Большее из двух значений  | `max(0, value)`            |
| `clamp(v, min, max)`   | Зажмите между границами   | `clamp(v, 0, 100)`         |
| `IF(cond, then, else)` | Условный                  | `IF(soc > 80, surplus, 0)` |
| `abs(v)`               | Абсолютное значение       | `abs(-5)` = 5              |
| `round(v)`             | Округлите до целого числа | `round(3.7)` = 4           |
| `floor(v)` /`ceil(v)`  | Округление вниз / вверх   | `floor(3.7)` = 3           |
| `pow(base, exp)`       | Власть                    | `pow(2, 3)` = 8            |

### Функции состояния (расширенные)

Эти функции считывают состояния ioBroker непосредственно в формуле, без определения именованных входных параметров:

| Функция              | Описание                                                                        | Пример                            |
| -------------------- | ------------------------------------------------------------------------------- | --------------------------------- |
| `s("id")`            | Укажите штат как безопасное число (0, если недоступно).                         | `s("hm-rpc.0.power") + 100`       |
| `v("id")`            | Состояние считывается как исходное значение (строка/число/логическое значение). | `v("mqtt.0.status")`              |
| `jp("id", "$.path")` | Извлечение значения из состояния JSON с помощью JSONPath                        | `jp("shelly.0.json", "$.apower")` |

### Поддерживаемые операторы

`+`,`-` ,`*` ,`/` ,`%` ,`()` ,`&&` ,`||` ,`!` ,`==` ,`!=` ,`>=` ,`<=` ,`>` ,`<` ,`? :`

## 9. Режим конечного автомата

В режиме конечного автомата генерируются строковые или логические состояния на основе правил. Правила оцениваются сверху вниз; **побеждает первое совпадающее правило** .

Это полезно для:

- Преобразование числовых кодов состояния в читаемые метки.
- Определение режимов работы на основе показаний нескольких датчиков.
- Создание логических флагов на основе сложных условий

### Конфигурация

| Параметр       | Описание                                          |
| -------------- | ------------------------------------------------- |
| Входные данные | Именованные переменные (аналогично режиму формул) |
| Тип данных     | `string` или`boolean`                             |
| Правила        | Упорядоченный список пар условие/выходные данные  |

### Правила

Каждое правило имеет:

| Поле              | Описание                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Состояние         | Формульное выражение, результатом которого является истинное/ложное значение. Используйте имена входных переменных и операторы. |
| Выходное значение | Строковое или логическое значение, которое будет выведено при выполнении условия.                                               |

**Особые условия:**

- `true` или пусто = правило по умолчанию/резервное правило (всегда совпадает)
- Используйте входные переменные и операторы:`soc < 10` ,`battery > 80 && surplus > 0`

### Пример

Для элемента с входными данными`soc` (уровень заряда батареи) и`surplus` (Избыток солнечной энергии):

| Состояние                    | Выходное значение |
| ---------------------------- | ----------------- |
| `soc < 10`                   | `Battery-Empty`   |
| `soc < 30`                   | `Battery-Low`     |
| `surplus > 1000 && soc > 80` | `Full-Export`     |
| `true`                       | `Normal`          |

Результат: Выходное состояние будет содержать`Battery-Empty` ,`Battery-Low` ,`Full-Export` , или`Normal` в зависимости от текущих значений.

## 11. Мониторинг и буферизация

### Мониторинг в режиме реального времени

Адаптер автоматически отслеживает, регулярно ли обновляются значения датчиков. Поле « **Время ожидания (мин., 0 = отключено)»** можно настроить индивидуально для каждого датчика в **экспертном режиме** (по умолчанию: 60 минут). Когда время ожидания установлено на`0` Мониторинг в реальном времени для этого датчика полностью отключен — строка с меткой времени скрыта в обзоре датчиков.

Если датчик не получает новых значений дольше установленного времени ожидания, адаптер выводит предупреждение в лог:

```
Sensor "INVERTER_POWER": no update since 4/5/2026, 6:30:00 PM (longer than 60 minute(s))
```

Кроме того, на **вкладке** **оранжевым** цветом отображается последняя метка времени затронутого датчика, поэтому вы можете с первого взгляда определить устаревшие данные с датчиков, не открывая журнал.

Предупреждение повторяется не более одного раза за период ожидания для каждого датчика, чтобы избежать переполнения логов. Установите время ожидания на`0` Чтобы отключить проверку отдельного датчика (только в экспертном режиме). Для вновь созданных датчиков по умолчанию устанавливается тайм-аут.`60` минут. Время ожидания должно быть больше интервала обновления соответствующего адаптера источника.

### Мониторинг стоимости (максимальная стоимость)

Мониторинг значений **по умолчанию отключен** (максимальное значение = 0). В **экспертном режиме** для каждого числового датчика можно установить индивидуальное максимальное значение. Единица измерения отображается рядом со значком максимального значения в обзоре датчиков (по умолчанию —`W` (если не настроен ни один модуль). Когда максимальное значение > 0, оно отображается в виде значка рядом с текущим значением в обзоре датчика. Когда мониторинг значений отключен (максимальное значение = 0), значок скрывается.

### Состояния адаптера

| Состояние            | Описание                                          |
| -------------------- | ------------------------------------------------- |
| `info.connection`    | `true` если InfluxDB доступен                     |
| `info.buffer.size`   | Количество буферизованных точек данных            |
| `info.buffer.oldest` | Временная метка самой старой буферизованной точки |
| `info.buffer.clear`  | Кнопка для ручной очистки буфера                  |
| `info.lastError`     | Последнее критическое сообщение об ошибке         |

### Состояния Data-SOLECTRUS (при включении)

Вычисленные значения отображаются в разделе`solectrus-influxdb.X.ds.*` с диагностическими состояниями для каждого элемента.

### Поведение буфера

- Значения постоянно сохраняются на диске в буфере (`buffer.json` )
- Максимальный размер буфера: 100 000 точек.
- Очистка базы данных происходит только при подтверждении **активного соединения с InfluxDB** .`ensureInflux()` (проверка перед каждым смывом)
- При сбое InfluxDB интервалы повторных попыток увеличиваются в геометрической прогрессии (до 5 минут).
- После переподключения все буферизованные точки очищаются.
- Во время сброса буфера он никогда не изменяется (схема создания снимка и подкачки).
- В случае неудачной операции сброса данные автоматически восстанавливаются в буфер.

## 12. Использование вычисленных значений в качестве источников данных от датчиков.

Вы можете использовать вычисленные значения Data-SOLECTRUS в качестве входных данных для датчиков, чтобы записывать их в InfluxDB:

1. Создайте вычисляемый элемент (источник, формулу или конечный автомат) на вкладке **«Значения данных»** .
2. На вкладке **«Датчики»** добавьте новый датчик.
3. В поле **«Состояние источника ioBroker»** выберите состояние вычисляемого значения:`solectrus-influxdb.X.ds.<outputId>`
4. Настройте измерение, поле и тип данных как обычно.

Адаптер автоматически обрабатывает порядок инициализации — подписки на датчики для`ds.*` Состояния сохраняются, даже если двигатель Формулы запускается после настройки датчиков.

## 14. Уведомления

Адаптер может отправлять сообщения через настраиваемые поставщики уведомлений при возникновении важных событий.

### Активация

Вкладка **«Уведомления»** скрыта до тех пор, пока уведомления не будут включены. Установите флажок **«Включить уведомления»** на вкладке **InfluxDB** , чтобы отобразить её и активировать эту функцию, затем:

1. Выберите необходимые события-триггеры.
2. Настройте как минимум одного поставщика уведомлений.

### Триггеры

| Событие                                                           | Описание                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Сбой подключения к InfluxDB / восстановление**                  | **❗** Отправляется при первой ошибке соединения и **✅** снова при восстановлении соединения                                                                                                                                                                                                                 |
| **Таймаут активности датчика**                                    | **⚠️** Отправляется, если датчик не предоставляет обновление в течение заданного времени ожидания (только для ненулевых значений)                                                                                                                                                                           |
| **Превышено максимальное значение** (`notifyOnMaxValueExceeded` ) | **⚠️** Отправляется, когда значение датчика превышает заданное максимальное значение; частота отправки ограничена до одного раза в час для каждого датчика.                                                                                                                                                 |
| **Отсутствует поле JSON** (`notifyOnJsonFieldMissing` )           | **⚠️** Отправляется один раз за сессию при обнаружении известного поля JSON (`y` ,`clearsky` ,`temp` Полное отсутствие этого поля в исходных данных указывает на то, что бэкэнд его не предоставляет (например,`clearsky` /`temp` (требуется pvnode). Уведомление сбрасывается, если поле появляется снова. |

### Поддерживаемые поставщики

| Поставщик             | Требование                                                |
| --------------------- | --------------------------------------------------------- |
| **Телеграмма**        | Адаптер ioBroker для Telegram установлен и настроен.      |
| **Слабак**            | Адаптер ioBroker Pushover установлен и настроен.          |
| **WhatsApp**          | Адаптер ioBroker whatsapp-cmb установлен и настроен.      |
| **Электронная почта** | Адаптер электронной почты ioBroker установлен и настроен. |
| **Сигнал**            | Адаптер ioBroker signal-cmb установлен и настроен.        |
| **Матрица**           | Адаптер ioBroker matrix-org установлен и настроен.        |
| **Чат Synology**      | Адаптер ioBroker synochat установлен и настроен.          |

Можно одновременно настроить несколько поставщиков. Перед отправкой адаптер проверяет, активен ли соответствующий экземпляр адаптера, и регистрирует предупреждение, если экземпляр не запущен.

### Выбор экземпляра

У каждого поставщика есть выпадающий список **«Экземпляр»** . Доступные экземпляры адаптера считываются автоматически и предлагаются для выбора. Это позволяет легко выбрать конкретный экземпляр, когда запущено несколько экземпляров одного и того же адаптера.

### Примечания

- Уведомления локализуются посредством`getNotificationMessage()` используя настроенный`systemLanguage` .
- При сбоях подключения к InfluxDB уведомление отправляется при **первом** сбое и может повторяться после него.`notifyRepeatMinutes` при этом соединение остается прерванным.
- Уведомления о таймауте датчика отправляются при выполнении заданного условия "таймаут активности" (экспертный режим) и регулируются в зависимости от установленного лимита времени ожидания.`notifyRepeatMinutes` .

## 15. Резервное копирование

### Встроенная вкладка «Резервное копирование»

Вкладка **«Резервное копирование»** в конфигурации адаптера позволяет создавать, загружать, восстанавливать, скачивать и удалять резервные копии этого экземпляра напрямую — установка других адаптеров не требуется. Резервная копия содержит:

- Общие настройки (параметры подключения)
- Конфигурация датчиков: внутренние/внешние, активированные/деактивированные
- Элементы Data-SOLECTRUS (расчеты/формулы) и их папки.
- Все папки объектов/каналы/состояния, созданные этим экземпляром.

Резервные копии хранятся локально на этом хосте ioBroker. По умолчанию они размещаются в собственном каталоге данных этого экземпляра, но вы можете выбрать пользовательское место хранения (например, другой диск или смонтированную сетевую папку) с помощью поля «Каталог резервных копий». Используйте поле «Сохранять последние N резервных копий», чтобы управлять тем, сколько самых последних резервных копий будет автоматически сохраняться; более старые удаляются при создании каждой новой резервной копии. Восстановление резервной копии автоматически перезапускает экземпляр, поэтому восстановленная конфигурация вступает в силу.

> **Примечание:** Токен InfluxDB является защищенной/зашифрованной настройкой и никогда не включается в эти резервные копии. После восстановления его необходимо будет ввести вручную на вкладке **InfluxDB** .

> **Примечание:** Диалоговое окно конфигурации администратора не автоматически считывает восстановленные настройки, пока оно открыто (оно отображает только то, что было загружено при открытии). После восстановления закройте диалоговое окно конфигурации адаптера и откройте его снова, чтобы увидеть восстановленные значения.
