# IoBroker.cam-recorder
## Адаптер для видеорегистратора для ioBroker
Записывает короткие видеоролики (MP4 или GIF) и снимки (JPEG) с RTSP-камер, например, с дверной станции, при звонке в дверь или обнаружении движения, и может отправлять результат в Telegram, MAX, по электронной почте и в другие мессенджеры.

- **В комплект входит ffmpeg.** Адаптер поставляется со своим собственным исполняемым файлом ffmpeg (пакетом).

[ffmpeg-static](https://github.com/eugeneware/ffmpeg-static)), ничего устанавливать в систему не требуется.

- **В скриптах пароли не используются.** Данные для входа в камеру хранятся в настройках адаптера и зашифрованы. В скриптах используется только имя пользователя.

камера.

- **Работает без скриптов.** Таблица триггеров связывает любое состояние (дверной звонок, движение, кнопка) с камерой.
- **Бережно относится к небольшим системам.** ffmpeg запускается только во время записи клипа, количество параллельно работающих процессов ffmpeg ограничено.

имеет ограничения, и видеопоток с камеры можно скопировать, а не перекодировать.

## Настройки
### Камеры
На каждую камеру приходится одна строка: имя, RTSP-адрес, имя пользователя и пароль. Примеры RTSP-адресов:

| Камера | URL |
| ------------------ | ----------------------------------------------------- |
| DoorBird | `rtsp://192.168.1.20:554/mpeg/media.amp` |
| Reolink | `rtsp://192.168.1.41:554/h264Preview_01_main` |
| UniFi Protect | `rtsp://<console>:7447/<alias>` (см. ниже) |
| UniFi Protect | `rtsp://<console>:7447/<alias>` (см. ниже) |
| Для большинства камер с интерфейсом ONVIF | см. руководство пользователя камеры или инструмент для работы с устройствами ONVIF |

Введенный в URL-адрес логин (`rtsp://user:password@host/...`) перемещается в поля имени пользователя и пароля при следующем запуске. Специальные символы в паролях допустимы, адаптер кодирует их для ffmpeg.

По умолчанию используется протокол TCP; он надежно работает даже в контейнерах Docker. Использование только ключевых кадров помогает, когда снимки с камеры H.265 получаются серыми.

_↻_ поворачивает изображение с камеры, установленной вверх ногами или на боку и не способной поворачиваться самостоятельно: на 90°, 180° или 270° по часовой стрелке, или зеркально (↔ влево и вправо, ↕ вверх и вниз). Снимки, GIF-файлы, перекодированные клипы, таймлапс-видео и изображения для проверки ИИ поворачиваются по-настоящему; ширина учитывается для повернутого изображения. Скопированный mp4-файл (_Копировать поток с камеры_) не может быть повернут без перекодирования: ему присваивается метка (матрица отображения), которую Telegram, браузеры, VLC и большинство плееров применяют при отображении видео. В системе ffmpeg старше 6.0, которая не может записывать эту метку, клипы с повернутой камеры перекодируются вместо этого (встроенный ffmpeg достаточно новый).

Функция _Sound_ переносит звук с камеры в MP4-клипы, а также в предварительно записанные видео, поэтому они воспроизводятся со звуком в Telegram и других приложениях. Камера должна передавать звук в своем RTSP-потоке; у многих камер эта функция отключена по умолчанию или передается только в одном из потоков (найдите аудио в настройках видео или потока камеры). Камеры передают G.711 или AAC; адаптер всегда записывает AAC, который необходим для MP4 и мессенджеров, в том числе при копировании изображения. GIF-файлы, снимки и таймлапс-видео остаются без звука. Камера без звука продолжает записывать, но без звука.

При воспроизведении звука и изображения время инертно совпадают. Запись в режиме реального времени начинается с момента подключения: камера, использующая ключевые кадры только каждые несколько секунд, показывает первое изображение сразу после начала звука. В предварительно записанных клипах такой паузы нет.

Название камеры становится идентификатором объекта: `Front Door` → `cam-recorder.0.cameras.front_door`. Буквы с диакритическими знаками транслитерируются (`ü` → `ue`, `é` → `e`), другие специальные символы становятся `_`.

#### Онлайн или офлайн
Каждую минуту адаптер проверяет, подключена ли каждая камера к сети, и записывает это в `cameras.<camera>.reachable` (состояние карты в Диспетчере устройств). Без дополнительных настроек он устанавливает TCP-соединение с хостом и портом, указанными в URL-адресе. В случае с камерой, подключенной к сетевому видеорегистратору (UniFi Protect, Frigate, go2rtc, Synology Surveillance Station), отображается только сам видеорегистратор: соединение принимается, пока камера за ним выключена. Есть два выхода:

- **Состояние подключения к сети** (столбец камеры): любое состояние, указывающее, находится ли камера в сети, например, состояние адаптера.

NVR. `true`, число, отличное от 0, `connected`, `online`, `on`, `ok`, `yes`, `up` считаются как онлайн, все остальные значения - как офлайн. Адаптер мгновенно отслеживает изменения; состояние, которого не существует, сообщается в начале, и камера проверяется как прежде.

- **Вход в UniFi Protect** (ниже таблицы): камеры UniFi Protect передают потоковое видео через консоль (`rtsp://<console>:7447/<alias>`)

или `rtsps://<console>:7441/<alias>`, URL из _Protect → камера → Настройки → Дополнительно → RTSP_). При использовании локального пользователя консоли адаптер входит в консоль каждую минуту, считывает список камер один раз для всех камер и получает `isConnected` с камеры, поток которой имеет псевдоним URL. Дополнительный адаптер не требуется. Создайте локального пользователя (не учетную запись пользовательского интерфейса с двухфакторной аутентификацией) в _UniFi OS → Администраторы и пользователи_; достаточно роли _Только просмотр_ для Protect. Порт HTTPS - 443 на консолях UniFi OS (UDM, UNVR, Cloud Key Gen2+ с UniFi OS).
Если консоль не отвечает или отклоняет вход в систему, регистрируется предупреждение, и тем временем проверяются ее камеры по TCP; После отказа в подключении адаптер ждет 15 минут, прежде чем повторить попытку, поэтому неверный пароль не блокирует пользователя. Камера, псевдоним которой неизвестен консоли (протокол RTSP для нее отключен или URL-адрес изменен после перезагрузки), отображается как недоступная с предупреждением.

### Триггеры
| Колонка | Значение |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| Штат | Любой штат, например, `doorbird.0.Doorbell.1.trigger` или `doorbird.0.Motion.trigger` |
| Когда | _Значение истинно_ (по умолчанию) или _При каждой записи_ |
| Время восстановления | Количество секунд, в течение которых дальнейшая запись не запускает новый клип (три нажатия на дверной звонок = один клип) |
| Только если, Сравнение, Значение | Дополнительное условие, см. ниже |
| Камера | Название камеры на первой вкладке |
| Действие | Видеоклип, снимок или и то, и другое (оба воспроизводятся одновременно, фотография приходит первой) |
| Длительность | Секунды, 0 = значение вкладки _Запись_ |
| Формат | Видео MP4, GIF-анимация или _по умолчанию_ |
| Сообщение | Профили вкладки _Отправить_, получающие результат, разделенные несколькими запятыми; пусто = нет сообщения |

**Условия.** Триггер с параметром _Только если_ срабатывает только тогда, когда это состояние сравнивается с заданным значением: `=`, `≠`, `>` или `<`. Примеры: `0_userdata.0.away` `=` `true` (только когда никого нет дома), `javascript.0.isNight` `=` `true`, `hm-rpc.0.ABC.LUX` `<` `50`. Логическое состояние также соответствует `1`/`0`, `on`/`off`, `yes`/`no`; тексты сравниваются без учета регистра. Состояние считывается в момент события; пропущенное событие регистрируется и не запускает период ожидания.

Каждая запись состояния учитывается, даже если значение не меняется. При предварительной записи запись внутри периода ожидания **продлевает** клип, который еще обрезается, вместо того, чтобы игнорироваться: клип в этом случае завершает длительность триггера после последнего звонка, до _Максимальной длины клипа_ на вкладке _Запись_ (по умолчанию 30 с). В журнале это отображается как `extended 2x`.

### Запись
Длительность и формат видеоролика, а также способ создания файлов MP4:

- **Перекодирование** (по умолчанию): клип масштабируется (ширина по умолчанию 640 пикселей) и кодируется в формате H.264, небольшие файлы, которые Telegram

Воспроизводится везде. Для воспроизведения клипа требуется ресурсы процессора.

- **Копирование видеопотока с камеры**: практически без использования ресурсов процессора, исходное разрешение. Камера должна передавать H.264.

Копированный поток может начинаться только с ключевого кадра, в то время как длина клипа отсчитывается от момента соединения: если камера отправляет ключевой кадр каждые несколько секунд, скопированный клип будет короче на величину этого интервала. Перекодированные клипы начинаются с первого изображения и сохраняют свою полную длину.

GIF-анимации всегда перекодируются (ширина и частота кадров отображаются на одной вкладке).

### Предварительная запись
Запись звонка, начинающаяся с момента нажатия кнопки, не включает в себя момент, когда человек подходит к двери. При предварительной записи запись также содержит секунды **до** события.

- **По умолчанию отключено.** Включите его с помощью _Предварительная запись_ на вкладке _Запись_, затем установите _Предварительная запись (с)_ (от 1 до 30).

для каждой камеры, которая должна его использовать. Камеры с номером 0 не затрагиваются.

- **Сколько это стоит.** Для каждой такой камеры постоянно работает один процесс ffmpeg. Он копирует видеопоток с камеры в...

Видеоролики длительностью 2 секунды создаются без перекодирования (небольшая нагрузка на процессор, несколько МБ дискового пространства во временной папке), а старые фрагменты удаляются. Камера постоянно держит открытым один поток - убедитесь, что она разрешает второй поток для снимков и просмотра в реальном времени.

- **Как создаётся клип.** В момент события адаптер ждёт, пока данные за несколько секунд после события не будут записаны на диск, после чего присоединяется к...

Фрагменты и обрезки окна _предварительной записи + длина клипа_. Таким образом, клип готов примерно на 2-4 секунды позже, чем без предварительной записи. Длительность в таблице триггеров и в `sendTo` - это время **после** события.

- **Снимки** создаются из буфера во время работы программы: самый новый снимок на диске, старше максимум примерно на секунду, без каких-либо изменений.

Второе подключение к камере - мгновенное, и оно показывает момент события. `sendTo` с `live: true` вместо этого запрашивает данные у камеры.

- **Прямая трансляция.** Столбец _Прямая трансляция(и)_ вкладки _Камеры_ (затемнен, если нет предварительной записи) отображает новейшую версию.

Кадры из буфера записываются в `cam-recorder.0.storage/<camera>_live.jpg` каждые несколько секунд для виджета изображения размером vis с тем же интервалом обновления (через веб-экземпляр, например, `http://<host>:8082/cam-recorder.0.storage/door_live.jpg`).
Декодируются только ключевые кадры, поэтому это практически не требует ресурсов процессора и второго соединения; изображение имеет возраст не более одного ключевого кадра. Для реального видео в реальном времени используйте go2rtc; видеорегистратор может затем использовать его RTSP-поток в качестве URL-адреса камеры.

- **В случае сбоя** (камера отключена, трансляция прервана на 20 секунд), процесс перезапускается через 5, 10 или 30 секунд.

60 секунд, затем каждые 5 минут с предупреждением в журнале. Пока буфер не работает, клипы записываются с момента события без предварительной записи, с предупреждением в журнале. После запуска адаптера буферу требуется около 10 секунд (ffmpeg анализирует поток, затем ожидает ключевые кадры), пока `prebuffer` не отобразит `running`.

- **Чтение предупреждения.** В нем указано, как долго длился поток и последние предупреждения ffmpeg, например:

`received no data for 20 s after 37 s of stream: [rtsp] RTP: missed 12 packets (5×)`. _до поступления каких-либо данных_ означает, что камера никогда не отправляла данные (неверный URL, логин, порт); _после … секунд потока_ с одинаковым временем снова и снова означает, что камера прекращает отправку данных через некоторое время, например, потому что другой клиент (приложение камеры, видеорегистратор) принимает поток или сессия завершается. Попробуйте другой протокол передачи данных (TCP/UDP) или выключите и включите звук камеры.

- Файлы сохраняются во временную папку системы (`/tmp/iobroker-cam-recorder.0-prebuffer` в Linux), если вы не введете команду

папка. На системах с SD-картой хорошим выбором будет виртуальный диск в оперативной памяти (tmpfs).

### Отправлять
**Профиль** определяет, куда отправляется результат и что именно передается. Триггеры и таймлапсы выбирают профили по имени в столбце _Сообщение_ (выберите один из списка или введите несколько имен, разделенных запятыми; пустое поле или `—` = нет сообщения; начальные имена таких триггеров в журнале, если они не используются для проверки состояния ИИ), скрипты - с `profiles: 'Name'`. В списке столбца отображаются профили с сохраненными настройками, поэтому сохраняйте изменения после добавления профиля.

| Колонка | Значение |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Имя | Уникальное имя профиля |
| Экземпляр | Экземпляр обмена сообщениями, например, `telegram.0`, `max.0`, `email.0` (см. таблицу ниже) |
| Получатель | Необязательный параметр, в формате, ожидаемом адаптером; пустое значение = значение по умолчанию для данного адаптера |
| ИИ | Только для профиля с критериями на вкладке _Проверка ИИ_: как используется проверка (см. [Проверка ИИ](#ai-check)) |
| Текст | Подпись: `{camera}`, `{date}`, `{time}`, `{description}` и `{matches}` заменены, дата в формате системных настроек |
| Текст | Подпись: `{camera}`, `{date}`, `{time}`, `{description}` и `{matches}` заменены, дата в формате системных настроек |
| Шаблон | Дополнительное JSON-сообщение для адаптеров без встроенного формата или для замены встроенного (см. ниже) |

Режим «Только текст» отправляет текст сразу после срабатывания триггера, до завершения записи, без файла - например, короткое сообщение «Кто-то у двери», пока клип с файлом проходит второй этап обработки. Для таймлапса или сценария текст отправляется, когда файл готов.

| Адаптер | Что поставляется | Получатель |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| `telegram` | файл (MP4 как видео, GIF как анимация) | пользователь, пусто = все пользователи бота |
| `email` | файл как вложение, подпись как тема | адрес |
| `pushover` | изображения в качестве вложения, видеоролик в качестве текста | устройство |
| `discord` | файл | `serverId/channelId`, идентификатор пользователя или тег пользователя |
| `matrix-org` | картинки, фрагмент текста | - |
| `signal-cmb` | текст с указанием камеры, типа и имени файла | номер телефона |
| `whatsapp-cmb` | текст | номер телефона |
| `gotify` | текст | - |
| `ntfy` | текст | тема |
| `ntfy` | текст | тема |

Все адаптеры обмена сообщениями должны работать на том же хосте, что и этот адаптер, поскольку они считывают файл из указанного им пути.

Пример дверной панели с двумя кнопками для двух квартир:

| Имя | Экземпляр | Получатель | Вложение |
| ------------ | ---------- | --------- | ---------- |
| Я | telegram.0 | Алекс | Всё |
| Отец | telegram.0 | Отец | Только клип |
| Отец (МАКС.) | макс.0 | 123456 | Только текст |

Триггер `doorbird.0.Doorbell.1.trigger` → _Сообщение_ `Me`; триггер `doorbird.0.Doorbell.2.trigger` → _Сообщение_ `Father, Father (MAX)`. Имя, не соответствующее ни одному активному профилю, отображается в начале.

**Обновление с версии 0.4.x.** При первом запуске после обновления настройки бывшей вкладки «Уведомления» преобразуются в профили, один раз: экземпляр Telegram становится профилем `Telegram`, каждый последующий целевой объект - профилем с его именем (идентичные целевые объекты только один раз, целевой объект без имени называется в соответствии с экземпляром и получателем), все с прежним заголовком. Каждый триггер и таймлапс получают профили, которым они отправляли сообщения ранее; пустая вкладка «Отправить на» становится списком всех этих профилей. После этого экземпляр перезапускается один раз. Скрипты с `telegram: true` продолжают работать (см. «Скрипты»).

#### Шаблон
В столбце _Template_ отображается JSON-сообщение, которое адаптер отправляет экземпляру профиля, в формате `sendTo('<instance>', 'send', <template>)`. Оставьте его пустым, чтобы использовать встроенный формат таблицы выше. Введите шаблон для адаптера, которого нет в таблице, или для замены встроенного формата, например, для добавления параметров.

| Заполнитель | Заменено на |
| ------------- | ----------------------------------------------------------------------------- |
| `{file}` | полный путь к файлу |
| `{fileUrl}` | путь в виде `file:///…` URL |
| `{caption}` | Текст профиля с заполненными данными о камере, дате и времени |
| `{camera}` | название камеры |
| `{format}` | `mp4`, `gif` или `jpg` |
| `{duration}` | длительность клипа в секундах |
| `{recipient}` | Получатель профиля |
| `{text}` | готовый текст, например, `Door 09:00: mp4 clip 10 s (door_2026-11-11_09-00-00.mp4)` |
| `{text}` | готовый текст, например, `Дверь 09:00: mp4 клип 10 с (door_2026-11-11_09-00-00.mp4)` |

- Заполнители заменяются внутри строк JSON, поэтому их значения всегда являются строками, а также `{duration}`.

Вставляйте числа и символы `true`/`false` непосредственно в JSON.

- Кавычки в подписи не должны нарушать шаблон: сначала он анализируется как JSON, а значения заполняются позже.
- При использовании только текстового поля `{file}`, `{fileName}`, `{fileUrl}`, `{format}` и `{duration}` остаются пустыми.
- В начале записи в журнале сообщается о шаблоне, который не является допустимым JSON-файлом.

Telegram без звуковых уведомлений:

```json
{ "text": "{file}", "caption": "{caption}", "user": "{recipient}", "disable_notification": true }
```

Pushover имеет высокий приоритет; Pushover прикрепляет только изображения, поэтому установите для параметра _Вложения_ этого профиля значение _Только снимки_:

```json
{ "message": "{text}", "file": "{file}", "priority": 1 }
```

Любой другой адаптер:

```json
{ "to": "{recipient}", "title": "{camera}", "body": "{caption}", "attachment": "{file}" }
```

### Проверка ИИ
При использовании [ioBroker.pi-agent](https://github.com/sadam6752-tech/ioBroker.pi-agent) и модели, которая распознает изображения, профиль вкладки _Отправить_ получает дополнительное сообщение, когда изображение события показывает то, что важно для получателя.

| Активный | Критерий | Профили |

Профиль, критериям которого соответствует изображение, получает еще одно сообщение через свой собственный экземпляр и получателя:

| ИИ | Что получает профиль |

#### Отчет
Раз в день pi-agent подводит итоги проверок, проведенных с момента последнего отчета, например:

> 📋 Отчет от 15.11.2026 > Входная дверь: 10:12 почтальон, 14:40 курьер с посылкой, 18:05 звонят двое (посетители).

> Двор: машина на подъездной дорожке в 07:30 и 17:45, в остальное время только кошки.

| Обстановка | Смысл |
| ---------------------- | ------------------------------------------------------------------------ |
| Отправка ежедневного отчета | Главный переключатель: сбор чеков и отправка отчета |
| Время (ЧЧ:ММ) | При отправке по умолчанию `21:00` |
| Профили отчета | Профили вкладки _Отправить_ (разделенные запятыми); пусто = только `report.text` |
| Камеры | Камеры в отчете (разделенные запятыми), пустое поле = все |
| Пожелания для pi-агента | Необязательно, например, "только люди и транспортные средства, никаких животных" |

- Каждая проверка снимка с описанием, выполненная ИИ, добавляет строку (время, камера, описание, наблюдаемые критерии) в

`report.json` находится в папке данных экземпляра и сохраняется после перезапуска. Учитываются только изображения, которые проверяет pi-agent, поэтому для критерия необходим профиль или _состояние_. Для отчета изображение не сохраняется.

- В установленное время pi-agent получает строки в текстовом виде (без изображений, диалог `cam-recorder-report`) и записывает их.

Отчет отправляется на языке системы. Сообщение содержит только этот текст, а не текст, прикрепленный шаблон или файл профиля. Если pi-agent не отвечает, вместо него отправляется обычный список; без строк ничего не отправляется.

- Отправленный отчет запускает следующий: строки до этого момента удаляются.
- `report.send` отправляет отчет сразу, `report.text` сохраняет последний отправленный отчет, `report.lastTime` сообщает, когда он был отправлен. Скрипты

Агенты могут задавать вопросы с помощью `sendTo('cam-recorder.0', 'report', { send: false })`: ответ `{ text }` - это отчет на данный момент, ничего не отправлено и не удалено.

### Таймлапс
Одна строка на каждую камеру: снимок каждые _Интервал_ минут, и один раз в день в _Видео в_ (ЧЧ:ММ, по умолчанию 23:55) снимки преобразуются в видеофайл MP4 (_Кадров в секунду_, ширина вкладки _Запись_), названный `<camera>_timelapse_<YYYY-MM-DD>.mp4` в честь дня создания первого снимка. Снимки удаляются после создания видео. Во время предварительной записи снимки загружаются из буфера без повторного подключения к камере.

- Кнопка `cameras.<camera>.timelapse` (или `sendTo(…, 'timelapse', 'Front Door')`) запускает видео сразу.
- Если адаптер был остановлен во время записи видео, пропущенное видео будет записано при следующем запуске.
- _Сообщение_ отправляет видео через указанные профили на вкладке _Отправить_.
- Дисковое пространство: один кадр в минуту с разрешением 640 пикселей занимает около 50 МБ в день до завершения видеосъемки; максимум 10 000 кадров.

Ожидание для каждой камеры. Старые видеоролики в режиме замедленной съемки удаляются по истечении максимального срока, указанного во вкладке «Хранилище».

### Хранилище
Файлы записываются в `iobroker-data/cam-recorder.<instance>/media/` (или в папку, которую вы укажете), с именем `<camera>_<YYYY-MM-DD_HH-MM-SS>.<mp4|gif|jpg>`. Старые файлы удаляются для каждой камеры и типа: сохраняются _n_ самых новых файлов (по умолчанию 20), и не сохраняется ничего старше максимального срока (по умолчанию 7 дней). Другие файлы в папке остаются нетронутыми.

Функция «Сортировать по папкам по месяцам» помещает каждый файл в папку `<folder>/<camera>/<yyyy-mm>/` (местное время), включая видео с замедленной съемкой.
Тот, кто сортирует файлы по папкам по месяцам, сохраняет их: количество файлов и максимальный срок хранения затем отключаются (отображаются серым цветом), а старые папки удаляются вручную или с помощью вашей собственной программы. Файлы, созданные ранее, остаются на своих местах.

Самый новый файл для каждой камеры и типа также копируется в файловое хранилище ioBroker (`cam-recorder.0.storage/<camera>.mp4`, `.gif`, `.jpg`), где его можно открыть на вкладке администратора _Файлы_ или через экземпляр `web`.

## Диспетчер устройств
В версиях admin 7 и новее Диспетчер устройств отображает по одной карте на каждую настроенную камеру на вкладке «Устройства» в настройках экземпляра и в разделе «Устройства» в меню администратора:

- **Статус:** онлайн или офлайн. Адаптер устанавливает TCP-соединение с хостом и портом, указанными в URL-адресе камеры.

Запуск происходит каждую минуту (без входа в систему, без ffmpeg), либо отслеживается состояние сети или консоли UniFi Protect (см. _Онлайн или офлайн_), и результат записывается в `cameras.<camera>.reachable`. Последняя ошибка отображается на карте в виде предупреждения.

- **Идет запись:** красная точка, указывающая на _Запись_ или _Создание снимка_, пока ffmpeg работает с этой камерой.
- **Последний клип** и **последний снимок** с указанием даты и времени, а также секунд до начала записи, если эта функция включена.
- **Изображение:** последний снимок, сделанный, когда включена опция _Копировать новейший файл в файловое хранилище ioBroker_ (вкладка _Хранилище_).
- **Запись видео** и **Снимок:** аналогично кнопкам `cameras.<camera>.record` и `.snapshot` - клип с

Длина и формат вкладки «Запись» или изображения без уведомлений. В диалоговом окне отображается имя файла или ошибка, после чего карточка обновляется. Пока камера находится в автономном режиме, обе кнопки неактивны; администратор не обновляет кнопки автоматически, поэтому карточка, которая была открыта ранее, отображается до повторной загрузки страницы, и нажатие на нее лишь сообщает о том, что камера находится в автономном режиме.

Камеры, триггеры и все остальные настройки остаются в параметрах экземпляра; Диспетчер устройств только отображает их и запускает запись.

## Расписание
Помимо триггеров, камера может делать снимки или видеоролики самостоятельно: каждые несколько минут или в фиксированное время. Расписание хранится в состояниях `cam-recorder.0.cameras.<camera>.schedule.*`, а не в настройках экземпляра, поэтому оно изменяется без перезапуска, и скрипты, Blockly, сцены и агенты ИИ (ioBroker.pi-agent считывает его описание через `help`) могут устанавливать его так же, как и карта памяти. Состояния хранятся в резервных копиях.

На вкладке «Устройства» у каждой карты памяти камеры есть две кнопки:

- **Интервал**: каждые _N_ минут, отсчитывая от полуночи (30 = в :00 и :30), по желанию только между двумя временными интервалами.

(Работа с 22:00 до 06:00, после полуночи).

- **Расписание**: фиксированное время в виде шаблона cron, отображаемого в диалоговом окне cron администратора, например, `0 7,19 *** для 7:00 и

19:00 или `*/15 * * * 1-5` каждые 15 минут по будням.

Обе формы имеют общие параметры: _Активный_, действие (снимок, клип или и то, и другое), профили для отправки и два условия. Каждый запуск работает как триггер: файлы сохраняются и отправляются, а проверка ИИ выполняется для профилей, соответствующих заданным критериям. На карточке отображается следующий запуск.

- **Отправка только при совпадении с ИИ** (требуется pi-agent на вкладке _Проверка ИИ_): файлы всегда сохраняются, но отправляются только в

профили, критерии которых pi-agent видит на снимке, вместе с сообщением о совпадении. Снимок двора каждые 5 минут ночью поступает только тогда, когда там находится «человек», а не 96 раз пусто. В отличие от триггера, где неудачное распознавание никогда не должно приводить к отправке сообщения о дверном звонке, расписание без этого переключателя отправляет сообщение при каждом запуске.

- **Только если**: состояние и условие, как в таблице триггеров, например, `0_userdata.0.away` `=` `true`. Запуск, у которого

Если условие не выполняется, оно пропускается без предупреждения (журнал отладки).

| Штат | Пример | Значение |
| ------------- | ------------------- | ----------------------------------------------- |
| `enabled` | `true` | главный выключатель |
| `from` | `22:00` | интервал только с … (оба пусты = весь день) |
| `to` | `06:00` | … до |
| `cron` | `0 7,19 * * *` | фиксированное время, пустой = выключено |
| `action` | `snapshot` | `snapshot`, `record` или `both` |
| `profiles` | `Alex, Telegram` | отправлять профили, пустой = только сохраненные |
| `aiOnly` | `true` | отправлять только профилям, соответствующим ИИ |
| `onlyIfState` | `0_userdata.0.away` | Запускать только при выполнении этого состояния |
| `onlyIfOp` | `eq` | `eq`, `ne`, `gt`, `lt` |
| `onlyIfValue` | `true` | значение условия |
| `next` | (только для чтения) | время следующего запуска, 0 = нет |
| `следующий` | (только для чтения) | время следующего запуска, 0 = нет |

В журнале и на карточке отображается неверное значение (шаблон cron с опечаткой, например, время `25:00`), и эта часть программы не запускается.

## Скрипты
Ответ появится, когда файл будет готов, поэтому ждать определенного времени не нужно:

```js
on({ id: 'doorbird.0.Doorbell.1.trigger', change: 'any' }, () => {
    sendTo('cam-recorder.0', 'record', { camera: 'Front Door', duration: 5, format: 'mp4' }, result => {
        if (result.error) {
            log(result.error, 'warn');
            return;
        }
        sendTo('telegram.0', 'send', { text: result.file, user: 'User1', caption: 'Doorbell' });
    });
});
```

| Команда | Сообщение | Ответ |
| -------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `record` | `{ camera, duration?, pre?, format?: 'mp4' \| 'gif', width?, fps?, profiles? }` | `{ file, size, format, duration, pre, extended, fromBuffer, realDuration, camera, time }` или `{ error }` |
| `timelapse` | `{ camera }` или просто название камеры | видео, как указано выше, или `{ error }`, если ожидается менее двух изображений |
| `report` | `{ send?: boolean }`, `send: false` формируют текст только | `{ text }` (пустой без отмеченных событий) или `{ error }`, когда отчет отключен |
| `listCameras` | - | `[{ value, label }]` |
| `listProfiles` | - | `[{ value, label }]` |
| `help` | - | `{ help }`: команды, состояния и правила в текстовом виде для агента ИИ |
| `help` | - | `{ help }`: команды, состояния и правила в текстовом виде для агента ИИ |

`profiles: 'Me, Father'` (или список) отправляет результат через профили вкладки _Отправить_. Способ из версии 0.4.x по-прежнему работает: `telegram: true` отправляет через каждый активный профиль, а `recipients: 'Father'` - только через них.
Если профиль сообщения имеет критерий вкладки _Проверка ИИ_, проверяется также снимок (см. _Проверка ИИ_), и ответ имеет `description`.

`pre` ограничивает время до события (максимум значение, установленное для камеры, `0` = предварительная запись для этого клипа невозможна); `duration` всегда обозначает время после события, а `duration` ответа - весь клип.

## Примечания по безопасности
- Пароли от камер хранятся в зашифрованном виде в объекте экземпляра, и список камер недоступен для чтения другими пользователями.

адаптеры (`protectedNative`).

- ffmpeg запускается без командной оболочки. Данные об авторизации удаляются из каждой строки лога, состояния и ответа.
- Во время работы ffmpeg его командная строка (с входом через камеру) может быть видна другим пользователям **той же машины**.

Список процессов (`ps`). ffmpeg не может принимать RTSP-запросы из других источников. На выделенном хосте ioBroker или в контейнере это обычно допустимо; предоставьте камере пользователя, который может только просматривать поток.

- Записанные файлы не зашифрованы. Файлы, скопированные в файловое хранилище ioBroker, могут быть открыты любым администратором, и

в зависимости от настроек, через экземпляр `web`.

- Пароль консоли UniFi Protect хранится в зашифрованном виде (`encryptedNative`). Консоль имеет сертификат.

собственный сертификат, который никто не подписал, поэтому его проверка не выполняется; используйте пользователя с ролью _Только просмотр_.

- Пароль SFTP хранится в зашифрованном виде (`encryptedNative`). Проверка соединения с пустым полем пароля использует...

Сохраненный пароль предназначен только для сохраненного сервера, поэтому ни один скрипт не сможет отправить его на другой хост.
