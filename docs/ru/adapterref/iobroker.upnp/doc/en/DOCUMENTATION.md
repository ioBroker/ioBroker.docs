### Назначение

Предназначен для связи и взаимодействия со всеми устройствами, поддерживающими протокол UPnP.

#### Что такое UPnP?

UPnP = Universal Plug and Play (Универсальное подключение и воспроизведение). Это попытка стандартизировать связь между устройствами в сети. Для этого существуют так называемые «схемы», которые отображаются в виде XML-файла. Они содержат всю информацию об устройстве или программном обеспечении и предоставляемых ими услугах. Для обеспечения возможности использования этих услуг предоставляется описание каждой из них. Это описание соответствует схеме, определенной для данной услуги, что позволяет быстро обмениваться информацией и командами, не зная модели или производителя устройства или программного обеспечения. В прошлом эта стандартизация в основном использовалась для медиаустройств и программного обеспечения. В последнее время предпринимаются усилия по стандартизации связи в рамках «Интернета вещей» (IoT). Для этой цели в 2016 году был основан «Фонд открытого подключения» (Open connectivity Foundation), который перенимает задачи форума UPnP, проводившего сертификацию устройств, поддерживающих UPnP, и создававшего стандарты.

#### Функциональное описание

Адаптер передает и обрабатывает ответы при первом запуске. Ответы содержат ссылку на XML-файлы сервисов. XML-файлы используются для создания объектов в ioBroker и заполнения их всей доступной информацией.

С задержкой запускается служба, которая ожидает сообщений от устройств/служб, входящих или выходящих из системы. Вновь обнаруженные устройства/службы автоматически добавляются к существующим. Вторая служба входит в систему на каждом доступном устройстве и подписывается на сообщения о состоянии, так что ioBroker автоматически получает уведомления о любых изменениях (отправленных) устройству/службе.

#### Структура объекта

Каждое устройство или программное обеспечение, реагирующее на трансляцию, создаётся как отдельный объект. Под этим объектом вы найдёте все доступные сервисы с их возможностями. Возможности разделены на 3 категории (роль/роль): индикатор, состояние, действие и аргумент.

**state —** это переменная, представляющая текущее состояние объекта/точки данных в устройстве/сервисе. Каждый indicator.state имеет определенный тип, например, число, строка, логическое значение и т. д. Кроме того, указывается, какое именно значение или диапазон значений может принимать indicator.state; эти сведения хранятся в "native" объекта. Ранее реализованные native:

- sendEvents = Значение на данный момент неизвестно.
- allowedValues = допустимые строки.
- minimum = Указывает наименьшее значение, при котором значение принимается.
- Максимум = Указывает наивысшее значение, при котором принимается решение.
- шаг = Указывает, на каких шагах можно изменить значение.

**button -** "reuqest" — это команда, которая может быть отправлена устройству/сервису и принята им. Этот объект обычно имеет подобъект, аргумент.

**Аргумент —** это подобъект действия. Тип — «смешанный», поскольку он не указан. Собственные объекты объекта содержат различную информацию, она может отличаться от аргумента к аргументу. Ранее известные собственные объекты:

- direction = Указывает направление потока информации. In означает, что значение не возвращается. Out означает, что значение возвращается.
- relatedStateVariable = Возвращает индикатор состояния, за которое отвечает обмен данными.
- argumentNumber = Возвращает количество аргументов действия.

### Общие объекты

Для каждого устройства/сервиса имеются следующие объекты, необходимые для администрирования. Они не являются частью стандарта UPnP или руководства пользователя/инструкции к соответствующему устройству.

**Alive —** устанавливается устройством/службой в значение «true», а адаптер устанавливает его в значение «null» через x секунд, если устройство/служба не установит его в «true» снова. Время истечения срока действия зависит от максимального времени жизни сигнала Alive, предоставляемого устройством. При выходе устройства из системы статус устанавливается в «false». Можно установить этот объект в значение «true» вручную или с помощью скрипта, но это следует делать только в том случае, если вы уверены в доступности устройства/службы. Если Alive был установлен вручную в значение «true», его также следует вручную установить в значение «false», если это больше не требуется, иначе могут возникнуть ошибки.

**SID —** служит идентификатором подписки. Эта страница создается хостом каждый раз, когда клиент запрашивает подписку. SID действует по истечении времени, определенного хостом, поэтому он постоянно обновляется. Он действителен только для конкретной услуги.

### Объекты UPnP

Перечисленные здесь объекты можно найти в стандарте UPnP и/или в файлах device/dinest-descriptions. Это не полный список всех объектов, представленный перечень включает только часто встречающиеся объекты.

**(A\_ARG\_TYPE\_)InstanceID —** Идентификатор экземпляра является наиболее распространенным и обязательным, поскольку он указывает экземпляр службы, к которой необходимо обратиться. В большинстве случаев идентификатор экземпляра равен 0. Этот идентификатор передается вместе с каждым сообщением события от службы и каждой командой, отправляемой службе.

**(A\_ARG\_TYPE\_)Channel (\*) -** Объект канала связан с аудио/видеосервисами. Например, канал необходимо указать, если вы хотите изменить громкость. Возможные значения: "Master", "LF" или "RF". В этом примере "Master" обозначает общую громкость, "LF" — громкость левой передней панели, а "RF" — громкость правой передней панели. Если вы хотите изменить громкость только на правой передней панели, необходимо указать "RF" в поле Channel.

**(Установка/Получение)Громкость (\*) -** Объект Volume связан с аудио/видеосервисами. В зависимости от места его использования, он применяется для отображения громкости или для её регулировки. Этот объект всегда имеет минимальное и максимальное значения, которые можно задать; в большинстве случаев диапазон значений находится в пределах от 0 до 100. Шаг обычно равен 1, что означает, что можно вводить только четные числа.

### Контроль

**Кнопка —** действие «запрос» — это команда, которая может быть отправлена устройству/сервису. Каждое действие также включает аргументы, которые должны быть указаны как обязательные. Действие можно распознать по его роли/role, которая обозначается как «действие». Если вы опишете действие как «отправить», команда будет отправлена устройству/сервису.

**state.argument.x —** обязательное значение для действия, если роль — "state.argument.in". Возможные значения, которые можно/нужно указать, можно найти в "Related State Variable". Имя этой "Related State Variable" хранится в объекте в разделе "native" -> "relatedStateVariable". Аргументы должны быть указаны в определенном порядке, для этого есть "native" -> Argument\_No. Аргумент можно распознать по его роли/role, где указано "argument". Некоторые строки должны быть записаны с """" в точке данных. На этот вопрос невозможно ответить однозначно, но в случае сложных строк, таких как URL-адреса, это может быть так. Полезно только попробовать. Если вы хотите передать "" в аргументе, необходимо использовать "".

**(Связанная переменная состояния) —** это переменные, используемые для обмена данными. В исходных данных переменной содержится некоторая информация:

- Параметр allowedValues = предоставляет информацию о возможном содержимом переменной или о том, что может быть передано в качестве аргумента при выполнении действия.
- minimum = наименьшее значение, которое может содержать переменная или которое может быть передано в качестве аргумента при выполнении действия.
- maximum = максимальное значение, которое может содержать переменная или которое может быть передано в качестве аргумента при выполнении действия.
- шаг = указывает, на каком этапе задается значение.
- sendEvents = ? Возможные значения: "yes" или "no". Но совершенно непонятно, что это означает. Предположение о том, что значения этой переменной автоматически отправляются устройством/сервисом только в том случае, если для sendEvents установлено значение "yes", не подтвердилось.

Пример того, как опрашивать значения:

```
// get every 10 seconds the values from device
schedule("*/10 * * * * *",  function () {
   setState( "upnp.0.FRITZ!Box_6590_Cable.WANDevice.WANCommonInterfaceConfig.GetCommonLinkProperties.request"/*GetCommonLinkProperties*/, true);
   setState( "upnp.0.FRITZ!Box_6590_Cable.WANDevice.WANCommonInterfaceConfig.GetAddonInfos.request"/*GetAddonInfos*/, true);
});
```

Включить опрос можно в административной панели через конфигурацию объектов.

### Функции, специфичные для устройств/услуг

**Sonos:** Создать подписку на QPlay невозможно. Для этого может потребоваться аутентификация.

**Phillips Hue Bridge 2:** В Hue Bridge 2 реализован стандарт UPnP, из-за чего устройство обнаруживается, но недоступно через UPnP.

**Yamaha:** Использует API, основанный на стандарте UPnP, но с собственным форматом данных. В настоящее время это не поддерживается адаптером UPnP.

**Sony:** Использует интерфейс ScalarWebApi, называемый UPnP-адресуемым, но использующий собственный формат данных. В настоящее время это не поддерживается адаптером UPnP.

**Amazon Kindle:** Предоставляет услугу UPnP, но описание этой услуги отсутствует, поэтому её нельзя использовать.
