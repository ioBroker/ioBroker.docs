# ioBroker.sungrow-local

_Прочтите это на другом языке: [Deutsche Kurzbeschreibung](/#/docs/adapterref/iobroker.sungrow-local/README_de.md) ._

Подключает **гибридный инвертор Sungrow** (разработанный на базе SH20T) и его **аккумулятор** (серия SBH, например, SBH400) к ioBroker через коммуникационный модуль **WiNet-S2** по **протоколу Modbus TCP** – локально, без использования iSolarCloud.

Производитель: [Sungrow Power Supply Co., Ltd.](https://www.sungrowpower.com/en) – гибридные инверторы серии SH (например, SH-RT), аккумуляторы и коммуникационный модуль WiNet-S2: [обзор продукции](https://en.sungrowpower.com/products) . Данный адаптер является независимым проектом (см. [товарный знак](#trademark) ).

Этот адаптер был разработан как замена стандартному адаптеру. `ioBroker.modbus` экземпляр, считывающий те же регистры. Он сохраняет идентификаторы состояний такого экземпляра, поэтому существующие скрипты, визуализации и настройки истории можно перенести простой заменой текста (см. [Миграция](#migration-from-iobrokermodbus) ).

## Зачем еще один адаптер Modbus?

WiNet-S2 — это шлюз Modbus TCP ↔ RTU: каждый запрос проходит по одной шине RS485, используемой инвертором (блок 1) и батареей (блок 2). Батарея работает медленно — WiNet предоставляет ей _интервал выполнения инструкций_ в 5000 мс, в течение которого шина блокируется. При использовании стандартного экземпляра Modbus это приводит к следующему:

- Один интервал опроса для всего — либо значения энергопотребления низкие, либо истекает время ожидания запроса от батареи.
- При каждом истечении времени ожидания разрывается всё TCP-соединение; после переподключения все значения PV отсутствуют примерно на минуту.
- Записи, попадающие на заблокированную шину, отбрасываются и выглядят так, как будто инвертор их проигнорировал.

## Функции

- К WiNet-S2 **подключается ровно одно TCP-соединение** . Все запросы ставятся в очередь и отправляются строго один за другим, с настраиваемой минимальной паузой между ними.
- **Опрашивать группы пользователей** с собственным интервалом, таймаутом запроса и, при необходимости, паузой после каждого запроса. Значения по умолчанию (измерены на эталонной установке): `live` 5 с, `energy` 60 с, `control` 60 с, `battery` 120 с с таймаутом 15000 мс и паузой 5000 мс. Более короткие значения отмечены красным в административном интерфейсе (только предупреждение). Блоки формируются так же, как в ioBroker.modbus (максимальный размер блока / максимальный интервал), но для каждой группы.
- **Тайм-аут приводит к сбою только в собственном блоке.** Соединение восстанавливается только после N сбоев подряд (по умолчанию 3) или когда шлюз закрывает сокет; только тогда `info.connection` становится `false` Исключения Modbus считаются ответом.
- **Приоритетная запись:** данные в регистры хранения записываются до следующего запроса на чтение (FC6; при этом _не следует использовать запись в несколько регистров,_ в том числе и для 32-битных значений), и данные считываются немедленно. `ack=true` Устанавливается только с подтвержденным значением – даже если то же значение было записано повторно.
- **Режим только для чтения** (отклонение запросов на запись и сброс состояния), например, в первые дни после миграции.
- **Пропуск неизмененных записей** (по умолчанию включено, 0.6.0): команда, значение которой устройство уже сообщает (то же самое исходное значение после множителя/смещения, опрашиваемый регистр, значение не старше двух интервалов опроса + 10 с), не отправляется по WiNet; состояние подтверждается с помощью `ack=true` Тем не менее. Компания Sungrow не рекомендует часто записывать данные в регистры RW через WiNet.
- **Запись счетчиков на регистр** (0.6.0) в пределах `info.write.registers.<register>.*` (команды и подтвержденные записи, за сегодня и в общей сложности) и одно предупреждение на каждый регистр в день сверх N команд (по умолчанию 50) – скрипты, которые постоянно записывают данные, становятся видимыми.
- **Управление батареей и регистры настенного блока** (0.6.0, экспериментальная версия, **по умолчанию отключены** ) – см. [раздел «Управление батареей](#battery-control-experimental) и [настенный блок»](#wallbox-experimental) .
- **Простой текст и ограничения** на каждый регистр (`states` как `value:text;value:text`, `min`, `max` Запись за пределы этих ограничений регистрируется как предупреждение и всё равно отправляется.
- **Диагностика по группам** в рамках `info.groups.<group>.*`: время ответа, последний успешный ответ, последняя ошибка, количество запросов/тайм-аутов/ошибок/пропущенных раундов за сегодня и общее количество тайм-аутов/ошибок; запись в под `info.write.*`.
- **Частота сердечных сокращений** в каждой группе: `lastRound` (отметка времени каждого полного раунда, в том числе без изменения значений), `roundDuration` и `lastRoundText` плюс `info.lastValueUpdate` Значения регистров записываются только при изменении, поэтому старая метка времени в регистре не является ошибкой — зависание шины отображается в... `lastRound`.
- **Вкладка «Статус»** в настройках экземпляра содержит информацию о состоянии соединения, пульсе, времени ответа и счетчиках для каждой группы.
- **Шаблон регистрации:** помимо регистров, считываемых по умолчанию, таблицы содержат еще 100 известных регистров Sungrow (не отмечены). Отметьте строку, чтобы прочитать ее — она присоединится к блокам запросов своей группы, без дополнительных соединений. Собственные регистры по-прежнему можно добавлять.
- Вкладка **«Помощник по преобразованию»** : адреса во всех форматах, объяснение типа данных, знака, порядка слов и множителя, декодирование исходных значений всеми распространенными способами, предупреждения о достоверности и дополнительная функция однократного тестового считывания регистра.
- **Карты управления устройствами** (администратор → _Устройства_ ): инвертор, батарея и сетевой счетчик с основными значениями, направлением тока (зарядка/разрядка, импорт/подача) и индикатором неисправности – только для чтения, запись на карты не производится.

## Требования

- Гибридный инвертор Sungrow с модулем **WiNet-S2** и поддержкой Modbus TCP (порт 502).
- Устройство WiNet-S2 имеет **список разрешенных IP-адресов для протокола Modbus TCP** . Клиент, не включенный в этот список, получает подтверждение соединения, а затем разрывает соединение при первом же запросе. `ECONNRESET`) – похоже, проблема в сети. Добавьте IP-адрес хоста ioBroker (как его видит WiNet, то есть после NAT) в веб-интерфейс WiNet.
- Одновременно с WiNet должен взаимодействовать только один клиент Modbus. Перед включением этого адаптера отключите другие экземпляры Modbus, опрашивающие тот же шлюз.
- js-controller >= 6.0.11, **admin >= 8.2.0** (страница конфигурации использует компоненты React из административной панели), Node.js >= 22.

## Конфигурация

На странице настроек шесть вкладок. Все работает с помощью мыши, клавиатуры и сенсорного экрана; перетаскивание всегда необязательно (для каждого действия есть отдельная кнопка).

1. **Обзор** – например, светофоры, информация о подключении, последние значения и каждая группа опросов (последний раунд, длительность раунда, тайм-ауты/ошибки/пропущенные раунды сегодня), а также динамические плитки: мощность фотоэлектрических панелей, мощность батареи с указанием направления (знак тока батареи). `43021`), уровень заряда батареи, сетка (`35601` + импорт / − подача электроэнергии в сеть), потребление электроэнергии в доме (расчетное: выработка переменного тока) `43034` + сеть; не заблокировано – неизмеренный генератор в домашней сети отображается как «небалансируемый») и любой другой регистр. Плитки можно добавлять, удалять и заказывать. При создании нового экземпляра (без адреса) здесь открывается **мастер настройки** : адрес шлюза, проверка подключения (код типа устройства → модель, серийный номер, батарея инвертора, батарея SBH блока 2) и профиль _«Базовый / Батарея / Расширенный»_ с предварительным просмотром нагрузки шины.
2. **Регистры** – каталог регистров по темам (PV, батарея, сеть, инвертор, управление, информация, собственные) с возможностью поиска. Активируйте регистр щелчком мыши (в его группу по умолчанию, стрелка = другая группа) или перетащите его в группу опроса. Каждая группа представляет собой столбец с интервалом и отправляемыми запросами; **индикатор нагрузки шины** (для каждой группы и в целом) рассчитывается на основе реального количества блоков в адаптере и показывает, _почему_ регистр требует еще один запрос («+1 запрос, потому что 13050 не находится рядом с остальными»). **Собственные регистры** : адрес в любой нотации (документ Sungrow от 1, протокол от 0, столбец 30001/40001, Modicon) с предупреждением о смещении на единицу и тестовым чтением перед сохранением.
3. **Управление** – регистрами хранения, доступными для записи. Запись осуществляется **для каждого регистра отдельно** (новинка в версии 0.4.0; в существующих установках регистры с установленными метками остаются доступными для записи), диапазона значений (минимум/максимум или таблица значений), поведения вне диапазона (предупреждение или отклонение), главного переключателя только для чтения и журнала последних команд записи. `info.write.log`).
4. **Подключение** – адрес и порт WiNet-S2; _Расширенные_ (свернутые): паузы, поведение при переподключении, тайм-аут/повторные попытки записи, построение блоков, десятичные знаки и используемая пропускная способность шины для индикаторов нагрузки.
5. **Инструменты** – помощник преобразования (см. ниже) и диагностика всех групп в одной таблице.
6. **Expert** – это простые таблицы (группы, регистры ввода и хранения) для массовых изменений.

### модель нагрузки автобуса

Шлюз обрабатывает примерно **1,25 запроса в секунду** в течение длительного времени (измерено на эталонной установке SH20T + SBH400 за модулем WiNet-S2): `live` 5 с +`energy` 60 с +`control` 60 с +`battery` Стабильная работа в течение 120 секунд (1,14 запросов/с). `live` 3 с (1,81/с) пропущенных раундов и `battery` 60 секунд приводят к таймаутам. Запрос к медленному шинному устройству блокирует шину на время паузы (батарея SBH: 5 секунд). Нагрузка = количество запросов в секунду / пропускная способность + доля пауз; зеленый цвет ниже 80%, желтый до 100% (полностью используется), красный выше. Группа, интервал которой короче, чем пауза другой группы, будет пропускать раунды. Пропускную способность можно изменить в разделе _«Подключение» → «Дополнительно»_ .

## Шаблон регистрации

В таблицах регистров содержатся все регистры, известные этому адаптеру; **отмеченные** регистры считываются:

- **По умолчанию отмечены** именно те регистры, что и в предыдущих версиях — обновление ничего не меняет из того, что считывается, и не изменяет идентификатор состояния.
- **Сняты галочки** с остальных известных регистров (начиная с версии 0.6.0: 120 входных и 86 удерживающих, включая строки для настенного блока): тип устройства (с названиями моделей), серийный номер и версии прошивки, MPPT 4, номинальная мощность и ток батареи (более новая прошивка), точная частота сети, напряжения/токи/суммы счетчика энергии, ежемесячная выработка солнечной энергии, коды аварий и неисправностей, ток и температура батареи настенного блока (блок 2), системные часы, ограничение экспорта, регулировка нагрузки, ограничения мощности заряда/разряда батареи, принудительная зарядка и многое другое. Записываемые строки содержат простой текст (`states`) или пределы.
- Отметьте строку и сохраните: регистр будет добавлен в блоки запросов своей группы (например, ток батареи и температура блока 2 находятся в существующем запросе на батарею – дополнительный запрос не требуется). Редко изменяющиеся значения находятся в группе. `info` (один раз в час).
- **Снятие флажка с** ранее прочитанного регистра удаляет его точку данных — **за исключением случаев, когда у него есть пользовательские настройки** (история, InfluxDB, SQL и т. д., начиная с версии 0.6.0): в этом случае объект остается. `native.orphaned = true` Этот объект больше не получает значений, и при каждом запуске появляется предупреждение с его именем. Удалите настройки (или объект) вручную, когда записанные данные больше не нужны. Повторная установка флажка в регистре снимает метку.
- В существующих установках шаблон добавляется один раз при первом запуске версии 0.3.0 (экземпляр перезапускается один раз); строки, которые вы настроили самостоятельно, всегда имеют приоритет – строка шаблона, перекрывающая один из ваших регистров, не добавляется.
- В столбце « _Источник / примечание»_ указано, откуда взята строка:
  - **HA mkaiser (MIT)** – [Sungrow-SHx-Inverter-Modbus-Home-Assistant](https://github.com/mkaiser/Sungrow-SHx-Inverter-Modbus-Home-Assistant) от Мартина Кайзера, лицензия MIT, © 2025 Мартин Кайзер. Адреса регистров, типы данных, масштабирование и таблицы значений (коды типов устройств, коды включения/выключения, режимы EMS и регулировки нагрузки) были взяты из `modbus_sungrow.yaml`.
  - **Референтный список** – регистрационный список эталонной установки (SH20T + SBH400 через WiNet-S2), проверенный на устройстве; частично с примечаниями (например, ежемесячная производительность: измеренный коэффициент 0,1, в документе указан 1).
- Параметры сетевого кода (LVRT/HVRT, защита от перенапряжения/повышенной мощности, кривые реактивной мощности) намеренно не включены в шаблон — это настройки установщика без документированного масштабирования.

## Вспомогательная программа для преобразования

Документы Sungrow, конфигурации Home Assistant и инструменты Modbus подсчитывают адреса по-разному и описывают типы данных по-разному. Вкладка **«Помощник преобразования»** помещает один регистр во все обозначения:

| ------------------------------------------------------------------- | ---------------------- | --------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Документ Sungrow, столбец _«Регистр»_ (счет от 1)                   | ввод 13023             | владение 13058                                | –                            | Sungrow PDF, SunGather, привязка openHAB (обе программы вычитают 1 перед отправкой)                                                                                                                                          |
| Протокольный адрес (отсчитывается от 0, передается по шине)         | 13022                  | 13057                                         | документ − 1                 | В реестре указаны "адрес, включая смещение", Home Assistant / mkaiser `address: 13022  # reg 13023` evcc, Loxone, ioBroker.modbus **без** псевдонимов (обычное руководство форума, идентификаторы типа `13022_Battery_level`) |
| _Адрес_ столбца этого адаптера = ioBroker.modbus **с** псевдонимами | 43023                  | 53058                                         | протокол + 30001 / + 40001   | этот адаптер                                                                                                                                                                                                                 |
| Модикон, 6 цифр                                                     | 313023                 | 413058                                        | протокол + 300001 / + 400001 | инструменты Modbus                                                                                                                                                                                                           |

- **Число…:** выберите источник вашего числа или _определите его автоматически_ : столбец (вход ≥ 30001, хранение ≥ 40001) и 6-значные номера Modicon являются однозначными; меньшее число может считаться от 0 или от 1 – в этом случае помощник отображает оба показания с регистром, который этот адаптер знает, и ничего не считывает.
- **Известный регистр и отклонение на единицу:** вспомогательная функция присваивает имя регистру ваших таблиц по адресу и соседним таблицам, которые вы получаете, считая от 0 вместо 1 (столбец 43022 — уровень _заряда батареи_ , 43023 — _уровень заряда батареи_ ).
- **Типы данных:** 16 бит `U16` (никогда не отрицательное) или `S16` (мощность, ток, температура – исходные значения выше 32767 являются отрицательными). 32-битные значения используют два регистра, и Sungrow отправляет **младшую часть первым** : `uint32sw` /`int32sw` В таблицах приведен список типов, содержащий эти пояснения.
- **Коэффициент:** Sungrow предоставляет разрешение, например, "0,1 кВтч" = коэффициент 0,1. Значение = исходное значение × коэффициент + смещение.
- **Исходные значения:** введите их (`950`, `0x03B6`, `4464 1` (для 32-битных систем) или установите флажок _«Чтение с устройства»_ : адаптер считывает регистр один раз через свое соединение (поставляется в очередь, как и каждый второй запрос, не чаще, чем каждые 5 секунд, только для FC4/FC3 – запись никогда не производится).
- **Вывод:** все адреса и результирующий идентификатор состояния, значение выбранного типа, те же самые исходные слова, что и в U16/S16/U32/S32 в обоих порядках слов, предупреждения (`0xFFFF` = отсутствие значения, знак, порядок слов, неправдоподобное значение с лучшим коэффициентом) и строка для внесения в регистровую таблицу.
- При первом считывании регистра после запуска его значение проверяется на соответствие допустимому диапазону в единицах измерения (В, А, Вт, кВт·ч, %, °C, Гц); неправдоподобное первое значение записывается в качестве подсказки (информации).

## Управление батареей (экспериментальная функция)

**По умолчанию отключено.** Включите его на вкладке _«Управление»_ . Затем `control.battery.mode` Принимает три режима работы; адаптер самостоятельно записывает необходимые регистры (их не нужно отмечать галочками) по обычному пути записи (запись перед следующим чтением, чтение с подтверждением):

| Режим    | Записанные реестры (номера документов Sungrow)                                                                                                                    | Эффект                                                     |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `normal` | Окно принудительной зарядки отключено (33208 = 0x55), команда остановки (13051 = 0xCC), самопотребление в режиме EMS (13050 = 0)                                  | нормальная работа                                          |
| `hold`   | Окно выключено, команда остановки, принудительный режим EMS (13050 = 2)                                                                                           | Батарея не заряжается и не разряжается.                    |
| `charge` | Команда остановки, самопотребление, окно принудительной зарядки 1 с настоящего момента для `minutes` до `targetSoc` (33209–33214), окно на (33208 = 0xAA) последнее | Инвертор заряжается в свой собственный временной интервал. |

Безопасность:

- `hold` и `charge` конец после `minutes` (1 … _максимальная продолжительность_ , по умолчанию 240 мин); затем адаптер возвращается к `normal` Конец хранится в `control.battery.until` После перезагрузки адаптера истекший режим возвращается к исходному состоянию. `normal` Сразу после подключения. Период зарядки заканчивается не позднее 23:59 и завершается самим инвертором — повторные команды не требуются.
- Минимальная пауза между двумя изменениями (по умолчанию 60 с) и максимальное количество команд удержания/зарядки в день (по умолчанию 12); `normal` Это всегда разрешено. Пока экземпляр находится в режиме только для чтения, ничего не записывается.
- Если регистр `hold` /`charge` Если запись или подтверждение невозможны, адаптер возвращается к исходному состоянию. `normal`.
- **Пока адаптер остановлен, ничего не возвращается в нормальное состояние** . `hold` (Принудительный режим) остается активным в инверторе до тех пор, пока адаптер не будет снова запущен.
- Окно принудительной зарядки соответствует времени суток по **часам инвертора** (см. документ Sungrow 5000 и далее). Некоторые версии прошивки игнорируют это, а максимальный уровень SoC (13058/33031) ниже целевого уровня ограничивает зарядку. Регистры взяты из протокола Sungrow V1.1.11 и списка ссылок; **запись тестировалась только на смоделированном WiNet** , а не на реальном инверторе.

## Миграция с ioBroker.modbus

Идентификаторы, имена, единицы измерения, факторы, типы данных и роли формируются точно так же, как в ioBroker.modbus (с включенной поддержкой _нескольких идентификаторов устройств_ ), поэтому регистровые таблицы существующего экземпляра можно скопировать в этот адаптер, и все идентификаторы состояний останутся неизменными, за исключением префикса экземпляра. `modbus.N.` →`sungrow-local.0.` Это справедливо для случаев, когда _псевдонимы_ включены. В большинстве руководств Sungrow по ioBroker.modbus псевдонимы **отключены,** и вместо них вводятся протокольные адреса (идентификаторы, например, такие). `13022_Battery_level`): добавьте 30001 (вход) / 40001 (удержание) к этим адресам – идентификаторы изменятся (`13022_…` →`43023_…`), сценарии и история должны быть адаптированы.

Одно исключение, начиная с версии 0.4.3: символы вне `[A-Za-z0-9_-]` (начиная с версии 0.5.0, также запятая) в столбце имени заменяются на `_` (умлауты транслитерируются), как рекомендует ioBroker для идентификаторов объектов. ioBroker.modbus сохраняет, например, `/` из `53051_Charge/discharge_command` Здесь указан идентификатор. `53051_Charge_discharge_command` Замените также эти идентификаторы.

Рекомендуемый порядок действий: создать резервную копию; переключить скрипты/сторожевые таймеры на новый экземпляр; отключить старый экземпляр Modbus (WiNet должен видеть только одного клиента); войти в систему хоста и включить этот адаптер (сначала в режиме только для чтения); сравнить значения; затем разрешить запись. Исторические данные старых состояний можно продолжить с помощью `aliasId` Настройка адаптера истории.

## Отличие от других адаптеров

- **ioBroker.modbus** — это универсальный адаптер Modbus, и именно с ним совместим данный адаптер. Он идеально подходит для любых других устройств Modbus. `sungrow-local` Добавляет только то, что необходимо WiNet-S2: интервалы для каждой группы, тайм-ауты, которые не приводят к разрыву соединения, приоритетную и подтвержденную запись, а также диагностику.
- На момент написания статьи в репозитории ioBroker **отсутствует специализированный адаптер Sungrow** ; другие решения используют iSolarCloud (интернет) или API веб-сокетов WiNet. Этот адаптер использует только документированный локальный интерфейс Modbus TCP.

## Используя значения из evcc (или другого программного обеспечения)

evcc использует собственный шаблон Sungrow, но он открывает **второй Modbus-клиент** на WiNet-S2. WiNet надежно обрабатывает только одного клиента (одна общая шина RS485, медленный батарейный блок) — два клиента конфликтуют и вызывают тайм-ауты в обоих. Пусть evcc считывает значения, которые этот адаптер уже считал, через ioBroker:

- **Простой API-адаптер** (HTTP, порт по умолчанию 8087): `http://<iobroker>:8087/getPlainValue/<state ID>` возвращает обычное значение.
- **MQTT-адаптер** : публикует состояния в виде тем (например, `sungrow-local/0/inputRegisters/1/35601_power_total-EnergyMeter`); evcc считывает их с помощью `source: mqtt`.

Пример использования simple-api (пользовательские счетчики evcc; точный синтаксис см. в документации evcc для вашей версии):

```yaml
meters:
  - name: grid
    type: custom
    power: # + = import, - = feed-in
      source: http
      uri: http://192.168.1.10:8087/getPlainValue/sungrow-local.0.inputRegisters.1.35601_power_total-EnergyMeter
  - name: pv
    type: custom
    power:
      source: http
      uri: http://192.168.1.10:8087/getPlainValue/sungrow-local.0.inputRegisters.1.35017_Total_DC_Power
  - name: battery
    type: custom
    power: # + = discharging, - = charging (tick the template row 35214 "Battery power signed")
      source: http
      uri: http://192.168.1.10:8087/getPlainValue/sungrow-local.0.inputRegisters.1.35214_Battery_power_signed
    soc:
      source: http
      uri: http://192.168.1.10:8087/getPlainValue/sungrow-local.0.inputRegisters.1.43023_Battery_level
```

Цены на электроэнергию не включены в данный адаптер: их предоставляют EVCC, Tibberlink, адаптер спотовых цен или скрипт.

## Примечания

- `35016` Это текущий параметр MPPT 3. До версии 0.3.0 строка по умолчанию называлась "MPPT 2 Current" (унаследована от старой конфигурации Modbus). В новых установках используется `35016_MPPT_3_Current`; существующие установки сохраняют `35016_MPPT_2_Current` до тех пор, пока строка в таблице регистров не будет переименована (после чего старый объект можно будет удалить).
- `43001` (Состояние выполнения) — это битовое поле, и `43030` (Состояние сетки) не задокументировано должным образом – оба параметра отображаются в виде чисел без текстового представления. `43030` без масштабирования, коэффициент 1).
- Верхний предел мощности составляет 20000 Вт. `53052` (Мощность заряда/разряда) — это предположение для модели SH20T; скорректируйте его для других моделей.
- `43008` (Мощность нагрузки) считывается как `int32sw` и фазные токи `43031` –`43033` как `int16be` (подписанные, как в протоколе Sungrow); до версии 0.3.0 они были неподписанными, и `43030` имел коэффициент 0,1. Существующие экземпляры исправляются один раз при первом запуске, если строка не была изменена вручную. Идентификаторы остаются неизменными.
- `43022` (Мощность батареи) — это величина без знака — знак `43021` (ток батареи) или строка шаблона `35214` _Сигнал питания от батареи_ (регистр 5214, более новая версия прошивки) определяет направление.
- `43023` Уровень заряда батареи (SoC) — это полезный уровень между минимальным и максимальным значениями SoC; собственный уровень заряда батареи — это... `40744` (раздел 2). Оба варианта совпадают, поскольку `40744 ≈ min SoC + 43023 × (max SoC − min SoC) / 100` до тех пор, пока уровень находится в пределах окна.

  indicator (43052) on the inverter with the tooltip "No fault" / "Fault: …". A value whose register is not ticked is left out. The control dialog of a
  card shows more (AC output, house consumption, temperatures, health, backup reserve, min./max. SoC, EMS mode if
  polled). No actions, no configuration and no writing from the cards.
- README: link to the manufacturer and its product overview.

### 0.4.3 (2026-10-25)

- State IDs only contain the characters recommended by ioBroker (`[A-Za-z0-9_,-]`): other characters of the
  name column (e.g. `/`) become `_`, umlauts are transliterated. Affected defaults:
  `holdingRegisters.1.53051_Charge_discharge_command`, `53052_Charge_discharge_power`,
  `70230_Manual_Scanning_-_ON_OFF`, `72535_Zustand_Netzanschluss_-_ON_OFF`. Existing objects are migrated on the
  first start: custom settings (history/sql/influxdb with `aliasId` = old ID, so the recorded data goes on), the
  last value and the rooms/functions move to the new ID, the old object is deleted. **Switch scripts and
  visualisations to the new IDs** (the log lists them).
- The role `level.mode` of older configurations (not in the ioBroker role list) becomes `level` (template v6).
- vis template *Akku*: register 53051 is labelled "Zwangsbefehl (nur im Zwangsmodus)" - it only acts in the EMS
  forced mode.
- Poller: no variable named `wait` (repository checker W5051); the pause between requests stays on the adapter
  timers, because stopping must end it immediately.

### 0.4.2 (2026-10-25)

- Admin: sizes for large screens in the tab *Tools*; Dutch text completed.
- README: formula of the house consumption tile (AC output 43034 + grid).

### 0.4.1 (2026-10-25)

  (previously 0 with ack=true, so scripts could react on e.g. SoC 0 % at adapter start). The default value
  is removed from existing objects; IDs, custom settings and values stay.
- Debug log line for every incoming command.
- Tests: the EMS command test waits until the adapter is ready (was flaky on slow Windows CI runners).

### 0.4.0 (2026-10-25)

- New configuration page with React components (admin >= 8.2): overview with traffic lights and live tiles,
  register catalog by topic with search, drag & drop into poll groups and a live bus load per group and in
  total (from the real block building, with the reason for every extra request), own registers in any address
  notation with test read, setup wizard (connection test, model detection, profile), tab *Control*, tab
  *Tools* with conversion helper and diagnostics, tab *Expert* with the plain tables.
- Register catalog: 187 further known registers (109 input, 78 holding: Sungrow protocol V1.1.11, register list
  of the reference installation, Home Assistant integration by mkaiser), every register with a name and a
  description in 11 languages; object names are translated as long as the description column is unchanged.
- Writing is released per holding register (`allowWrite`); a write to a register that is not released is
  rejected and the device value restored. Existing installations keep their ticked registers writable
  (template version 3). New option: reject values outside the range instead of only warning.
- Write log `info.write.log` (last 25 write commands with result).
- A too short answer (fewer registers than requested) discards the whole block and counts as an answer, not as a
  connection error.
- Messages for the admin: `probe` (test read, FC3/FC4 only), `wizardTest`, `analyse`.
- Value tables of writable registers (EMS mode, charge/discharge command, backup, load control, forced charging,
  on/off switches – 24 registers) in 11 languages: the states appear as a selection in admin/vis/apps, the tab
  *Control* offers them as a menu with a short explanation per mode and writes only after a confirmation. With
  "reject" a value outside the table is not written (template version 4 adds missing tables; own texts stay).
- Uniform register names (one term per quantity; "(from inverter)" / "(from BMS)" / "(from meter)" where the same
  quantity comes from two sources; pairs are shown next to each other). IDs do not change; object names follow the
  catalog as long as the description column still holds a former default text.
- Nearly constant values (nominal power, battery health, battery capacity, installed PV power, battery net capacity,
  rated load power) are read in the group `info` (hourly); existing instances move them once if the row still has the
  default group (template version 5).
- Read test of every template register on an SH20T behind a WiNet-S2: 67 addresses are rejected there ("illegal data
  address") and are marked in the catalog; the log explains a request that fails for this reason.
- Fix: battery direction. A positive battery current (43021) means **discharging** (verified with 4 days of history
  and raw reads); the overview and the vis templates showed it inverted. House consumption = AC output (43034) +
  meter (35601); a result clearly below zero (a generator the inverter does not measure) is shown as
  "not balanceable" instead of 0 W.

### 0.3.0 (2026-10-24)

- Register template: 100 further known registers (74 input, 26 holding) from the Home Assistant integration by
  mkaiser (MIT) and the register list of the reference installation, unticked in the register tables; existing
  installations get them once on the first start (one restart). Nothing that was read before changes.
- New column *Read* (tick) and *Source / note*; readable data type names, factor choice with examples.
- New tab *Conversion helper*: addresses in all notations (Sungrow document from 1, protocol address from 0 as in
  register lists / Home Assistant / evcc / ioBroker.modbus without aliases, column of this adapter, 6-digit
  Modicon) with automatic detection where unambiguous, the known register at the address and its off-by-one
  neighbours, interpretations of raw words, warnings, single test read (read only).
- New poll group `info` (3600 s) for device information; diagnostics only for groups that read registers.
- Hint in the log when the first value of a register is implausible for its unit.
- Fix: the round duration after a reconnect no longer contains the time without connection (was 26 640 904 ms
  after a night without gateway).
- Fix: no more warning "setTimeout called, but adapter is shutting down" when the instance stops.
- Fix: `43008` load power is signed (`int32sw`), phase currents `43031`–`43033` are signed (`int16be`), `43030`
  grid state is unscaled (factor 1). Existing instances get the correction once (template version 2) unless
  the row was edited.
