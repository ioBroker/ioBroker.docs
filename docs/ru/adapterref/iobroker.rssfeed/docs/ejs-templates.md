# Обозначение шаблона EJS

[Вернуться к основному файлу README](/#/adapters/rssfeed#ejs-template-notation)

EJS — это шаблонный язык, который объединяет обычный HTML с выражениями JavaScript и управляющими операторами. На этой странице объясняется сама нотация. Переменные и особенности поведения каждого виджета RSSFeed описаны в руководствах [VIS 1](/#/docs/adapterref/iobroker.rssfeed/docs/vis1-widgets.md) и [VIS 2](/#/docs/adapterref/iobroker.rssfeed/docs/vis2-widgets.md) .

## Как оценивается шаблон

Текст, находящийся вне тега EJS, копируется непосредственно в результат. Код внутри тега EJS выполняется при рендеринге виджета. Затем результат вставляется в виджет в виде HTML-кода.

```ejs
<p>This is ordinary HTML.</p>
<p>The value is <%= value %>.</p>
```

## EJS-теги

| Ярлык               | Цель                                                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `<%= expression %>` | Выполняет оценку выражения и экранирует результат с помощью HTML-кода. Предпочтительнее использовать этот метод для текста.               |
| `<%- expression %>` | Выполняет оценку выражения без экранирования HTML. Используйте только в том случае, если значение намеренно содержит доверенный HTML-код. |
| `<% code %>`        | Выполняет JavaScript-код без непосредственного добавления вывода. Используйте его для условий, циклов и переменных.                       |
| `<%# comment %>`    | Добавляет комментарий к шаблону, который не отображается в сгенерированном HTML-коде.                                                     |
| `<%%`               | Выводит буквальные символы.`<%` вместо того, чтобы начинать с тега EJS.                                                                   |
| `<%_ code %>`       | Выполняет JavaScript-код и удаляет пробелы перед открывающим тегом.                                                                       |
| `<% code -%>`       | Выполняет JavaScript и удаляет следующий перенос строки.                                                                                  |
| `<% code _%>`       | Выполняет JavaScript и удаляет следующие пробелы.                                                                                         |

При экранировании символы, такие как`<` ,`>` ,`&` и кавычки для текстобезопасных HTML-сущностей. Это предотвращает неожиданное превращение значения в разметку или скрипт. Описания лент иногда содержат преднамеренный HTML-код; используйте только`<%- ... %>` для подобного контента, если источник заслуживает доверия.

## Значения и резервный текст

Выражение может содержать обычный JavaScript. Используйте`||` для обеспечения простого резервного варианта на случай отсутствующих, пустых или ложных значений:

```ejs
<h2><%= title || "Untitled" %></h2>
```

Используйте необязательную цепочку вызовов, если промежуточный объект может отсутствовать:

```ejs
<%= image?.title || "No image title" %>
```

Используйте оператор объединения с нулевым значением, когда`0` или`false` Это допустимые значения, которые не следует заменять:

```ejs
<%= count ?? "Unknown" %>
```

## Условия

Ан`if` Блок может включать или опускать целые HTML-разделы:

```ejs
<% if (link) { %>
    <a href="<%= link %>" target="_blank" rel="noopener">Open article</a>
<% } else { %>
    <span>No link available</span>
<% } %>
```

Ан`else if` или`else` Ветвление соответствует стандартному синтаксису JavaScript. Тернарное выражение полезно для коротких вариантов выбора:

```ejs
<span class="<%= active ? "active" : "inactive" %>"><%= label %></span>
```

## Циклы

Использовать`forEach` Чтобы повторить разметку для каждого элемента массива:

```ejs
<ul>
<% items.forEach(function (item) { %>
    <li><%= item.title || "Untitled" %></li>
<% }); %>
</ul>
```

Перед итерацией по необязательным массивам проверьте их целостность:

```ejs
<% if (Array.isArray(items) && items.length) { %>
    <% items.forEach(function (item) { %>
        <p><%= item.title || "" %></p>
    <% }); %>
<% } else { %>
    <p>No entries available.</p>
<% } %>
```

Переменная цикла (`item` (здесь) существует только внутри цикла. В руководствах по виджетам показано, какие массивы и свойства предоставляют их шаблоны.

## Локальные переменные и форматирование

Временные переменные могут упростить чтение шаблона:

```ejs
<%
    const heading = title || "Untitled";
    const cssClass = important ? "important" : "normal";
%>
<h2 class="<%= cssClass %>"><%= heading %></h2>
```

Методы, такие как`join` ,`map` , и`toLocaleString` Их можно использовать, если значение это позволяет. При наличии переменных данных сначала проверьте тип:

```ejs
<%= Array.isArray(categories) ? categories.join(", ") : "" %>
```

## HTML-атрибуты и ссылки

Экранирующие значения, помещенные в атрибуты:

```ejs
<a href="<%= link || "#" %>" title="<%= title || "" %>"><%= title || "Open" %></a>
```

Когда ссылка открывает новую вкладку, добавьте`rel="noopener"` Избегайте создания JavaScript-кода обработчика событий на основе значений из ленты новостей.

## CSS внутри шаблона

Шаблон может содержать`<style>` Блок. Привязывайте селекторы к текущему виджету, если виджет предоставляет идентификатор; в противном случае CSS может повлиять на каждый виджет в представлении.

VIS может интерпретировать пару фигурных скобок как привязку. Многострочный CSS — это наиболее безопасный способ обозначения:

```css
.article {
    display: flex;
    gap: 0.5rem;
}
```

Избегайте сжатия правила в`.article { display: flex; }` внутри шаблона VIS. Применяйте те же меры предосторожности к литералам объектов JSON или JavaScript, встроенным в шаблон.

Для адаптивных изображений размер следует определять по контейнеру, а не вычитать предполагаемую ширину полосы прокрутки:

```css
img {
    width: 100%;
    max-width: 100%;
    height: auto;
    box-sizing: border-box;
}
```

## Вопросы, касающиеся сценария, событий и таймера.

Шаблоны могут содержать скрипты, но виджет может перерисовываться многократно при изменении состояния или параметра. При каждой перерисовке можно зарегистрировать другой обработчик событий или таймер. Предпочтительнее использовать разметку и CSS. Если требуется использование скриптов:

- DOM-запросы ограничиваются текущим виджетом;
- Избегайте использования глобальных имен переменных и функций;
- не запускайте неуправляемый процесс`setInterval` ;
- обеспечить возможность отмены или замены таймеров и обработчиков событий из более раннего рендеринга;
- Обеспечьте безопасность скрипта, если существует более одного экземпляра виджета.

## Устранение неполадок с шаблоном

- Начните с небольшого фрагмента HTML-кода и добавляйте поля по одному.
- Для просмотра фактических данных воспользуйтесь инструментами Meta Helper или Article Helper, описанными в руководствах по виджетам.
- Рассматривайте все поля как необязательные, поскольку форматы RSS и издатели различаются.
- Использовать`<%=` текст и резервирование`<%-` для преднамеренно отображаемого, заслуживающего доверия HTML.
- Проверять`Array.isArray(...)` перед тем, как пройтись по данным, которые могут отсутствовать.
- Обеспечьте правильную вложенность HTML-элементов и закройте все блоки управления EJS.
- Ограничьте область действия CSS-селекторов и идентификаторов элементов, чтобы несколько экземпляров виджетов не мешали друг другу.
