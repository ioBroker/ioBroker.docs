# Компактный режим

## Договор на проектирование и остановку производства.

Существующая фабрика CommonJS создает новый адаптер при встраивании; прямое выполнение по-прежнему создает один обычный процесс адаптера. Планировщики/таймеры очередей уже используют экземпляр адаптера, а данные о транспортных средствах, записи команд, квоты, статус соединения и история уведомлений об истечении срока действия уже являются полями экземпляра. В производственной среде нет `process.exit()` или переопределения среды процесса, зависящие от конфигурации.

Остальные изменения касаются только жизненного цикла и обработки сообщений на стороне бэкэнда:

- Логи бэкэнда, уведомления и результаты проверки соединения всегда отображаются на английском языке, поэтому они остаются полезными при обращении в службу поддержки. Полные многоязычные имена объектов и логика их миграции остаются без изменений.
- Каждый HTTP-клиент владеет собственными контроллерами прерывания (AbortControllers) и обработчиками таймаутов (timeout). `abort()` Закрывает доступ навсегда и отменяет запросы посредством обработки тела ответа. Тайм-ауты остаются ошибками API; завершение работы — это отдельный внутренний сигнал отмены. Ресурсы запроса удаляются в `finally` В том числе и в случае сбоя. Для проверки подключения администратора к адаптеру регистрируются отдельные клиенты.
- Планировщик/очередь останавливаются навсегда, сбрасывают свои таймеры, прерывают работу клиента, игнорируют запоздавшие ответы и обнуляют активные промисы. Завершение работы очереди также обнуляет немедленные отчеты и отправленные в очередь данные. Перезапуск создает новые компоненты через фабрику.
- Адаптер устанавливает флаг остановки жизненного цикла синхронно в `onUnload()` Защищенный адаптерный порт проверяет каждый вызов методов StateWriter, quota-store и expiry-watcher, включая вызовы, достигнутые после истечения срока действия. `await` Отслеживаются и обрабатываются принятые коллбэки готовности/сообщений/изменения состояния и ответов. Сбои очистки регистрируются, а коллбэк выгрузки имеет единственный путь завершения.
- После установки этого флага новые операции с состоянием/объектом не запускаются. Операция, уже отправленная в базу данных ioBroker, может завершиться; операции с базой данных не могут быть отменены этим адаптером. Квота сохраняется во время обычной обработки запросов и ответов. Функция выгрузки удаляет существующие сохраненные данные без начала дальнейших записей. Таким образом, сохранение последней квоты осуществляется по принципу «наилучших усилий», если функция выгрузки прерывает сохранение нескольких состояний или база данных недоступна; исключение из барьера записи не создается.

В метаданных адаптера не задана фиксированная компактная группа. Данные общего модуля состоят только из таблиц определений; запросы, таймеры и другие данные времени выполнения относятся к отдельным экземплярам. Для отмены HTTP-запросов не требуется расширенный stopTimeout; операции с базой данных остаются в рамках обычного лимита ioBroker.

## Автоматизированная проверка

```sh
npm run build
npm run test:unit
npm run test:package
npm run test:integration
npm run test:compact
npm run check
npm run lint
npm run check:spec
git diff --check
```

`test:compact` выбирает `Compact group 1` Этот пакет интегрирован в существующую систему интеграции. Он позволяет `system.compact` во временной конфигурации хоста и запускает реальный контроллер компактной группы js-контроллеров с аргументом group. `1` Два объекта-экземпляра имеют `compact`, `runAsCompactMode` Группа 1 и группа 1 заданы явно. Они используют разные VIN-коды, ключи API и квоты. Перенаправление HTTP только для тестирования направляет два ключа на отдельные фиктивные серверы. Трассировка межпроцессного взаимодействия доказывает, что запросы обоих экземпляров, в том числе после перезапуска первого, исходят от одной и той же группы PID. `system.adapter.<instance>.compactMode` Проверяются также и штаты.

Тестовый набор проверяет создание объекта, результаты проверки соединения на английском языке, команды, фактическое 60-секундное время проверки, остановку, отсутствие последующих изменений состояния адаптера/запросов, продолжение выполнения команд во втором экземпляре и перезапуск первого. Перезапуск учитывает сохраненную квоту, поэтому явная проверка соединения подтверждает работу HTTP-системы перезапущенного экземпляра без обхода обычной задержки опроса. Модульные тесты дополнительно останавливают ожидающие/выполняемые задачи, тела ответов и продолжения записи; проверяют тайм-аут/отмену, ошибки очистки, состояния гонки готовности/выгрузки и новые компоненты после завершения работы. Необработанные отклонения промисов приводят к сбою модульных тестов.

Данный тестовый модуль предоставляет фактические базы данных объектов/состояний ioBroker, но не адаптер Admin. Удаляется только зависимость Admin от тестовых экземпляров, и их версия синхронизируется с установленным пакетом перед запуском группы. Зависимости от производственной среды остаются без изменений. Контроллер группы запускается напрямую; автоматическое создание группы полноценным контроллером хоста в данном тестовом модуле не выполняется.

Оба компактных экземпляра отправляли запросы в одной и той же группе PID, включая перезапущенный экземпляр. Полный снимок состояния адаптера остановленного экземпляра остался неизменным, в то время как второй выполнял другую команду. Определения объектов, схемы/значения API, роли/типы и полные определения преобразования имен объектов остались неизменными; последние также сравнивались побайтно с определениями до изменений.

В ходе одновременного завершения работы окончательной группы клиент базы данных выдал следующее сообщение `get state error: Connection is closed.` Тем не менее, оба экземпляра и группа завершились с кодом 0, без необработанных отклонений или сбоев очистки адаптера. Реализация адаптера установленного контроллера вызывает `finishUnload()` как от функции обратного вызова \`unload\`, так и от её резервного варианта с задержкой в 500 мс, в то время как `terminate()` Также уничтожает клиентов базы данных через 500 мс. Повторная запись в активное состояние может, следовательно, вызвать гонку с закрытием базы данных. Предупреждение выводится внутри `@iobroker/db-states-redis` 's `setState()` Считывание предыдущего значения. Эта проблема с разрывом соединения контроллера задокументирована, она не исправлена и не скрыта увеличением параметра stopTimeout адаптера. Проверки остановки/изоляции отдельных экземпляров пройдены успешно.

## Процедура приемки установки

На временной установке ioBroker с установленной поддерживаемой зависимостью Admin:

1. Включите компактный режим для хоста, используя его конфигурацию/интерфейс командной строки ioBroker.
2. Назначьте два экземпляра адаптера группе сжатия 1 и включите выполнение в режиме сжатия. Настройте отдельные авторизованные пары VIN/ключ. Не настраивайте перенаправление API для производственной среды.
3. Убедитесь, что в логах обоих экземпляров отображается следующее: `COMPACT`, оба `compactMode` Состояния истинны, и оба выполняются в рамках одного и того же процесса компактной группы (а не в рамках отдельных резервных процессов).
4. Проверьте объекты транспортного средства, состояния квот и сроков действия, обычные опросы, сообщения проверки соединения и соответствующую команду, а также опрос для ее проверки.
5. Остановите первый экземпляр, пока у него есть запрос или ожидающая команда. Подтвердите корректное завершение работы, отсутствие новых записей в адаптер после остановки, отсутствие повторных запросов, отсутствие вводящих в заблуждение ошибок API/необработанных отклонений и продолжение работы второго экземпляра.
6. Запустите первый экземпляр снова. Убедитесь, что PID группы и второго экземпляра остаются стабильными, сохраненная квота соблюдается и обычная работа возобновляется.

Для группы 0, выполнения теста с использованием реального транспортного средства, пути создания группы на полном хосте, других версий Node/контроллера и других операционных систем требуется отдельный приемочный запуск. Они не подразумеваются успешным локальным тестированием группы 1/имитационным тестом.

Реальный набор контроллеров для компактных групп работает под управлением Linux. Контроллер js-controller для разработки устанавливается с помощью... `@iobroker/testing` На macOS и Windows контроллер компактной группы может завершить свою работу до того, как сработают таймеры запуска экземпляра с нулевой задержкой. На обеих платформах продолжается работа полного набора тестов, включая тесты жизненного цикла и изоляции компактной группы, а также обычные тесты интеграции адаптера.
