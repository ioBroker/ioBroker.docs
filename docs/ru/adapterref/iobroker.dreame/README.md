# ioBroker.dreame

**Этот адаптер использует библиотеки Sentry для автоматического сообщения разработчикам об исключениях и ошибках в коде.** Более подробную информацию, а также инструкции по отключению отправки сообщений об ошибках см. [в документации Sentry-Plugin](https://github.com/ioBroker/plugin-sentry#plugin-sentry) ! Система отчетности Sentry используется начиная с js-controller 3.0.

![Виджет «Карта в реальном времени»](../../../en/adapterref/iobroker.dreame/docs/Pics/Map-Screen.jpg)

## Адаптер Dreame для ioBroker

Адаптер для роботов-пылесосов и роботов-газонокосилок Dreame и MOVA.

**Поддерживаемые бренды:** Dreame, MOVA (выберите в настройках адаптера)

**Протестировано с:** L10, L20, X40, A2 1200 (газонокосилка), MOVA 600, MOVA 1000

---

## Установка

### Через административную панель ioBroker (рекомендуется)

1. Убедитесь, что репозиторий «Последние» активен в разделе «Администрирование» → «Настройки» → «Репозитории».
2. Перейдите на вкладку «Адаптеры» и найдите «dreame».
3. Нажмите «Установить»

В настоящее время адаптер доступен в репозитории **Latest** . Запрос на включение в стабильный репозиторий был отправлен (см. статус по адресу <https://github.com/ioBroker/ioBroker.repositories/pull/6200> ).

### Через командную строку

```
iobroker install dreame@latest
```

### Для разработки адаптеров

Если вы хотите внести свой вклад в разработку самого кода адаптера (а не просто использовать его):

```
git clone https://github.com/TA2k/ioBroker.dreame.git
cd ioBroker.dreame
npm install
npm link
```

#### Уборка номера

`dreame.0.XXXX.remote.start-custom-clean`

```json
[
  { "piid": 1, "value": 18 },
  { "piid": 10, "value": "{\"selects\":[[X,1,3,2,1]]}" }
]
```

X = ID комнаты. Несколько комнат:`{\"selects\":[[X,1,3,2,1],[Y,1,3,2,1]]}`

#### Карта переключения

`dreame.0.XXXXXXX.remote.customCommand` :

```json
{ "siid": 6, "aiid": 2, "in": [{ "piid": 4, "value": "{\"sm\":{},\"mapid\":X}" }] }
```

X = mapId (см.`dreame.0.XXXX.status.map-list` )

### Уборка номеров на заказ

Функция **«Индивидуальная уборка комнат»** позволяет выбрать отдельные комнаты и отправить робота только в эти комнаты, вместо того чтобы убирать весь этаж. Уровень всасывания и объем воды применяются ко всем выбранным комнатам.

#### Пошаговое руководство

**а) Дайте название вашей карте (необязательно, рекомендуется для многоэтажных домов).**

Когда карта впервые обнаруживается,`map.maps.<id>.mapName` создается с использованием значения-заполнителя.`"Map <id>"` (например`"Map 1"` Это состояние можно напрямую записывать — изменить значение в дереве объектов ioBroker на что-то осмысленное, например, с`"Map 1"` к`"Ground Floor"` Название канала`map.maps.<id>` Обновление происходит автоматически сразу после сохранения нового значения. Перезагрузка адаптера не требуется.

**б) Установите активную карту**

Укажите идентификатор карты (например)`1` ) к`remote.custom-room-cleaning.active-map` При нажатии кнопки «Старт» роботу будут отправлены только комнаты, относящиеся к указанной карте. Указанная карта из шага (а) поможет вам определить, какой идентификатор соответствует какому этажу.

**c) Выберите номера**

Под`remote.custom-room-cleaning.map-<id>/` Каждая распознанная комната отображается как логическое состояние. Названия каналов и состояний показывают переведенное название комнаты с карты (например,`kitchen` ,`living-room` ,`bathroom` Установите желаемые комнаты на`true` .

**d) Отрегулируйте уровень всасывания и объем воды (опционально)**

`remote.suction-level` и`remote.water-volume` Применить ко всем выбранным комнатам. Установите их перед запуском, если хотите использовать значения, отличные от значений по умолчанию. Это те же состояния, которые используются для обычной уборки.

**e) Начать цикл очистки**

Набор`remote.custom-room-cleaning.start` к`true` Адаптер формирует выбор комнаты на основе флажков на активной карте, отправляет его роботу и сбрасывает настройки.`start` государство к`false` автоматически.

#### Расширенные настройки: прямой`customCommand` редактирование

`remote.custom-room-cleaning.customCommand` Содержит исходные данные выбора в виде строки JSON. При желании вы можете записать их напрямую:

```json
{"selects":[[roomId, repeats, suctionLevel, waterVolume, index], ...]}
```

Пример — кухня (ID 4), один раз при сильном всасывании, средний расход воды:

```json
{"selects":[[4, 1, 2, 2, 1]]}
```

Он`customCommand` Флажки для выбора комнаты **синхронизированы в обоих направлениях** : редактирование одного из них автоматически обновляет другой.`customCommand` Обновляет флажки на активной карте напрямую; установка флажка приводит к перестроению карты.`customCommand` Оба пути эквивалентны.

#### Известные ограничения

- **Глобальные настройки всасывания/подачи воды** — уровень всасывания и объем воды устанавливаются одинаково для всех выбранных комнат. Настройки для каждой комнаты (как показано на рисунке)`map.cleanset.*` ) не поддерживаются данной функцией.
- **Многоэтажная система протестирована с одной картой** — структура с несколькими картами (одна группа каналов на карту) полностью реализована, но на реальном оборудовании было проведено всестороннее тестирование только работы с одной картой. Многоэтажные дома с двумя и более картами должны работать, но их работа еще не проверена от начала до конца.

### Быстрые команды для пылесоса

Ярлыки (быстрые команды, созданные в приложении Dreame) анализируются на основе свойства 4-48 (имена, закодированные в base64). Каждому ярлыку присваивается свой собственный канал.`deviceId.shortcuts.{id}` :

| Состояние | Описание                         |
| --------- | -------------------------------- |
| имя       | Расшифрованное название ярлыка   |
| бег       | Запущен ли в данный момент ярлык |
| начинать  | Кнопка для запуска ярлыка        |

Каналы автоматически перестраиваются при запуске адаптера (а не только при следующем изменении на стороне приложения) и автоматически удаляются при удалении ярлыка в приложении.

### Виджет интерактивной карты

Адаптер включает в себя виджет карты в реальном времени, работающий в браузере: положение робота, маршрут уборки и количество убранных комнат, обновляющийся в режиме реального времени во время уборки. Он предоставляется непосредственно этим адаптером — виджет vis или дополнительный адаптер не требуются, и его можно встроить в качестве iframe в vis, Grafana или пользовательскую панель мониторинга.

#### Настраивать

- Для отображения страницы требуется **веб-** адаптер ioBroker (любой экземпляр).
- Откройте его по адресу`%web_protocol%://%ip%:%web_port%/dreame/` — например`http://<your-iobroker>:8082/dreame/` Готовая ссылка ("Dreame-Map") находится на стартовой странице ioBroker и рядом с этим экземпляром в списке адаптеров.
- Необходимо включить функцию **«Получить карту»** (см. [раздел «Конфигурация»](#configuration) ) — без неё виджет не будет содержать данных.
- Если карта еще не отображается, запустите адаптер один раз, пока робот находится в док-станции, чтобы загрузить первую полную карту.
- При одновременной работе нескольких роботов: если обнаружено более одного устройства, в заголовке виджета отображается переключатель устройств, или вы можете выбрать одно из них напрямую.`?did=<did>` в адресе.

> **Роботы с камерами/VSLAM-системами не поддерживаются.** Устройства, использующие камеру для навигации вместо лидара (например, Mijia 1C/1T, Dreame F9), не охватываются виджетом карты — он разработан и протестирован только для лидарных роботов. Адаптер выдает предупреждение, и карта остается пустой для таких устройств.

#### Появление

Все настройки внешнего вида находятся в самом виджете — откройте значок шестеренки в правом верхнем углу. Доступны четыре цветовых режима:

| Обычай        | Пять индивидуально выбираемых цветов (фон, боковая панель, кнопки, границы, текст) для полного контроля.                                                                     |

#### Функции

- В заголовке меню есть переключатель устройств для конфигураций с несколькими роботами.
- Настраиваемая компоновка: боковая панель слева/справа, масштабирование интерфейса, ширина боковой панели, поворот карты.
- Панели можно отображать или скрывать по отдельности (Уборка, Ярлыки, Станция, Обслуживание, Вода и влажная уборка, Статистика) — некоторые панели дополнительно позволяют скрывать отдельные строки/плитки внутри себя (например, уровень всасывания или влажность на панели «Уборка»).
- Панель ярлыков: один значок для каждого ярлыка приложения, нажмите, чтобы запустить его непосредственно из виджета.
- Кнопка «Расписания» открывает таблицу всех расписаний, созданных в приложении Dreame (время, дни недели, тип, настройки для номера или всего этажа), с переключателем включения/выключения для каждого — расписание, указывающее на удаленный ярлык, отображает заблокированный переключатель вместо того, чтобы молча ничего не делать.
- Интерфейс виджета доступен на немецком и английском языках, в соответствии с системным языком ioBroker.
- Режим киоска (`?gear=0` ) скрывает значок настроек — для дисплеев только для чтения (настенные планшеты, приборные панели)
- Текущие настройки внешнего вида и панели можно экспортировать в виде компактной ссылки (`?cfg=<blob>` ), для быстрого обмена или повторного использования настроек в нескольких встроенных приложениях без изменения сохраненной конфигурации.
- Счетчики расхода воды и воды для мытья полов (панель «Вода и вода для мытья полов»)
- Сброс настроек внешнего вида и панели до значений по умолчанию одним нажатием кнопки, независимо от сохраненной конфигурации адаптера.

#### Пример киоска/iframe

Комбайн`?gear=0` (скрыть настройки) с помощью`?cfg=` Ссылка, сгенерированная в панели настроек, позволяет встроить предварительно настроенное представление только для чтения:

```
http://<your-iobroker>:8082/dreame/?gear=0&cfg=<blob>
```

Он`<blob>` Этот параметр генерируется разделом «Ссылка» в панели настроек виджета и влияет только на эту вкладку/встроенный элемент браузера — он никогда не перезаписывает настройки, сохраненные для самого виджета.

#### Покос в определенных зонах

Каждая зона скашивания, определенная на карте, отображается как отдельный канал в рамках`dreame.0.<did>.mower.map.slot<X>.zone<zoneId>` Откройте обозреватель объектов ioBroker, перейдите к своей газонокосилке, а затем к`mower.map` и вы увидите один`slot0` ,`slot1` ... для каждой сохраненной карты. Каждый слот содержит одну`zone<N>` канал на каждую зону скашивания — например`slot0.zone1` ,`slot0.zone3` Внутри каждой зоны вы найдете`name` (как показано в приложении),`area` (м²),`time` , и`path` .

**Числовая часть после`zone`** это идентификатор зоны, в которую вы записываете данные.`remote.mow-zone` Итак, если дерево выглядит так:

```text
dreame.0.<did>.mower.map.slot0.zone1     name = "Front lawn"
dreame.0.<did>.mower.map.slot0.zone3     name = "Back lawn"
dreame.0.<did>.mower.map.slot0.zone5     name = "Side strip"
```

затем:

Однозонная стрижка: "Передний газон":

```text
dreame.0.<did>.remote.mow-zone = "1"
```

Несколько зон — стрижка газона: "Передний газон" + "Задний газон" + "Боковая полоса":

```text
dreame.0.<did>.remote.mow-zone = "1,3,5"
```

Формат JSON тоже работает — это удобно при использовании Blockly или JavaScript-скриптов:

```text
dreame.0.<did>.remote.mow-zone = "[1,3,5]"
```

Пример использования Blockly / JavaScript-адаптера:

```js
setState('dreame.0.' + did + '.remote.mow-zone', '1,3', false);
```

Газонокосилка обрабатывает список, начинает косить выбранные зоны и возвращается на станцию по завершении работы. Чтобы остановить работу во время движения, нажмите кнопку.`stop-mow` (o=2) или`pause-mow` (o=4). Сначала переключение карт (`mow-change-map` ) требуется, если целевые зоны находятся на другой карте — в противном случае идентификаторы зон не будут разрешены.

#### Переключение активной карты

Если у газонокосилки несколько карт, выберите активную карту перед записью идентификаторов зон:

```text
dreame.0.<did>.remote.mow-change-map = 0   // first map
dreame.0.<did>.remote.mow-change-map = 1   // second map
```

### Схема газонокосилки

Данные карты получаются через API Dreame iotuserdata (а не через MQTT, как у пылесосов).

| Состояние      | Описание                                                        |
| -------------- | --------------------------------------------------------------- |
| mapImage       | Карта отображается в формате PNG (URL-адрес данных base64).     |
| slot0.zone\_X  | Данные по зонам (название, площадь, время кошения)              |
| mowingPath     | Исходные координаты траектории скашивания                       |
| настройки      | Настройки кошения для каждой зоны                               |
| расписание     | график покоса                                                   |
| 3dmap-url      | Ссылка для скачивания 3D-карты LIDAR (предварительно подписана) |
| 3dmap-progress | Ход генерации 3D-карты (0-100%)                                 |

**Опрос карты:** Карта загружается при запуске адаптера и через`fetchMap` Кнопка. Во время активной стрижки (статус 1, 3, 5, 11) карта автоматически опрашивается каждые 30 секунд для отслеживания траектории стрижки.

**Отображение карты:** Требуется дополнительный модуль.`canvas` Пакет npm. На карте показаны зоны (зеленый цвет), контуры (белые линии), траектория скашивания (желтый цвет), запрещенные зоны (красный цвет) и препятствия (красные круги).

**3D-карта LIDAR:** Нажмите`generate-3dmap` Для запуска сканирования и загрузки трехмерной карты облака точек газонокосилкой. Загруженный файл представляет собой файл PCD (Point Cloud Data), который можно просмотреть с помощью таких инструментов, как CloudCompare или MeshLab. Прогресс отслеживается в`3dmap-progress` После завершения процесса предварительно подписанная ссылка для скачивания записывается в файл.`3dmap-url` Этот URL-адрес является временным и истекает через несколько часов.

## Известные ограничения

**Дерево объектов заполняется постепенно (ленивое создание состояний).** Состояния появляются только после того, как устройство хотя бы раз сообщит о соответствующем свойстве. После чистой установки или перезагрузки адаптера дерево может выглядеть неполным в течение нескольких минут — это ожидаемое поведение.

**L40s Pro Ultra и аналогичные устройства: некоторые состояния появляются только после активного использования.** Свойства в группе SIID 4 (`cleaning-mode` 4-23,`suction-level` 4-4,`water-volume` 4-5) и SIID 28 (`wetness-level` Состояния 28-1) могут передаваться устройством только после активного сеанса очистки, а не во время простоя при опросе. Эти состояния не появятся до тех пор, пока не завершится хотя бы один цикл очистки после установки или перезапуска адаптера.

**`cleaning-mode`На некоторых** устройствах, включая L40s Pro Ultra, в версиях до 0.3.18 могли отображаться необработанные составные значения (например, 5120, 5121, 5122) вместо задокументированного диапазона 0–3. Это было вызвано тем, что адаптер не декодировал составное значение, объединяющее режим, площадь и влажность в одно целое число. Начиная с версии 0.3.18, декодирование выполняется корректно. Если после обновления вы по-прежнему видите необработанные значения выше 1000, пожалуйста, создайте заявку с указанием вашей модели и наблюдаемого необработанного значения.

Fixed multi-room cleaning only cleaning the first selected room on 5th gen devices. Fixed swapped cleaning modes (vacuum/vacuum+mop) on devices with liftable mop pads. Fixed stream-status type warning (#82). German translation: renamed dining hall segment from Speisesaal to Esszimmer. Thanks to RicardoHipp for reporting and analyzing several of these issues.

### 0.3.24 (2026-07-01)
- Fixed custom room cleaning bug where switching active-map without touching a checkbox left customCommand holding room IDs from the previously selected map, causing the robot to clean the wrong room (room segment IDs are not unique across maps). customCommand is now rebuilt automatically whenever active-map changes, and is recomputed fresh from the active map's checkboxes immediately before every start as a final safeguard. Start is now aborted with a warning if no room is selected for the active map.
