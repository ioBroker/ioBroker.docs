## Для работы SourceAnalytix требуются следующие компоненты (Node.js, js-controller, административная панель)?

<!-- abschnitt: prio=B; gewicht=12; readme=partial; cluster=logs-install-26,upgrade-migration-other-14; features=req-versions,req-admin-ui-i18n -->

<!-- muss beantworten: Mindestversionen von Node.js, js-controller und Admin; Admin-Versionen, mit denen die Oberfläche läuft. -->

**Вкратце:** начиная с версии 0.7.0, для работы SourceAnalytix необходимы Node.js 22, js-controller 6.0.11 и Admin 8.0.0 или более поздней версии. Admin 8 необходим, поскольку страница настроек экземпляра с вкладками «Обзор» и «Проблемы» построена на основе компонентов Admin 8.

<!-- quelle: code=io-package.json:161-170; code=package.json:11-13; issue=#1269 -->

|               | начиная с версии 0.7.0          | от v0.6.0 до v0.6.x             |
| ------------- | ------------------------------- | ------------------------------- |
| Node.js       | 22 или новее                    | 22 или новее                    |
| js-контроллер | 6.0.11 или более поздняя версия | 6.0.11 или более поздняя версия |
| Администратор | 8.0.0 или более поздняя версия  | 7.8.23 или более поздняя версия |

<!-- quelle: code=io-package.json:161-170; code=package.json:11-13; code=io-package.json:161-170@v0.6.1; code=package.json:11-13@v0.6.1 -->

Проверьте версии в консоли с помощью `iobroker -v` (js-контроллер) и `node -v` (Node.js). Если ваша система не соответствует требованиям, сначала обновите этот компонент, а затем SourceAnalytix. Версии 0.6.0–0.6.x работают с Admin 7.8 и Admin 8. Более старые утверждения с форума, такие как «работает с Admin 6», больше не актуальны.

<!-- quelle: code=.github/ISSUE_TEMPLATE/BugReport.md:31-32; code=io-package.json:161-170@v0.6.1; issue=#1202; forum=938927 -->

### Если SourceAnalytix не запускается после обновления Node.js

Если в журнале отображается `TypeError: Class extends value … is not a constructor or null` После обновления Node.js обычно оказывается, что js-controller устарел. Обновите js-controller, запустите... `iob fix` В консоли перезапустите экземпляр. Если ioBroker работает в Docker, обновите образ контейнера и при необходимости восстановите резервную копию.

<!-- quelle: forum=1195593; forum=218835 -->

## Как установить SourceAnalytix и создать экземпляр?

<!-- abschnitt: prio=B; gewicht=12; readme=missing; cluster=logs-install-24,setup-ui-03; features=req-versions,req-admin-ui-i18n -->

<!-- muss beantworten: Installation über den Admin-Store oder GitHub; danach Instanz anlegen (nur eine Instanz nötig). -->

**Вкратце:** в системных настройках ioBroker переключите репозиторий на "latest" (бета-версия) и установите SourceAnalytix на вкладке "Адаптеры". Администратор создаст экземпляр. `sourceanalytix.0` для вас. Затем откройте настройки экземпляра и настройте свой первый источник на вкладке «Обзор».

<!-- quelle: interview=21; forum=1133140; forum=215063 -->

В настоящий момент SourceAnalytix доступен только в репозитории "latest", а не в "stable". Он будет перенесен в "stable" после этапа тестирования. При выборе "stable" вы не найдете его в списке адаптеров.

<!-- quelle: interview=21; forum=1133140 -->

### Как это сделать (начиная с версии 0.7.0)

1. Проверьте [требования](#requirements-sourceanalytix-have-node-js) , особенно Admin 8.
2. В разделе «Репозитории» в панели администратора откройте системные настройки и выберите репозиторий «последняя версия» (бета-версия) в качестве активного репозитория.
3. Откройте вкладку «Адаптеры», обновите список адаптеров и найдите «SourceAnalytix».
4. Установите адаптер. Администратор создаст экземпляр. `sourceanalytix.0` и запускает его.
5. На вкладке «Экземпляры» откройте настройки `sourceanalytix.0` На вкладке «Обзор» отображается карточка «Настройка SourceAnalytix» с шагами «Создать цену», «Добавить источник» и «Просмотреть значения».
6. На вкладке «Определения цен» создайте хотя бы одно определение цены, например, для электроэнергии в кВтч, и сохраните его. Сохранение перезапустит адаптер.
7. На вкладке «Обзор» нажмите «Добавить первый источник». Дальнейшие действия описаны [в разделе «Где настроить SourceAnalytix для точки данных?»](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#configure-sourceanalytix-datapoint) .

<!-- quelle: interview=21; forum=1133140; forum=953340; code=admin/jsonConfig.json:1-45; code=src-admin/src/SourcesApp.tsx:245-279; code=src-admin/src/Wizard.tsx:553-595; code=src-admin/src/i18n/de.json -->

![Вкладка «Обзор» сразу после установки, с вкладкой «Настройка SourceAnalytix».](../../../../../../en/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/img/einrichten.png)

Для работы вкладок «Обзор» и «Проблемы» требуется запущенный экземпляр. Если он остановлен, вверху появится сообщение «Экземпляр не запущен» с кнопкой «Запустить». Все действия, отмеченные символом ⚡, будут заблокированы до этого момента.

<!-- quelle: code=src-admin/src/SourcesApp.tsx:111-140; code=src-admin/src/SourcesApp.tsx:474-476; code=src-admin/src/Wizard.tsx:955-961 -->

### Примера не было.

Если вы установили SourceAnalytix из консоли с помощью npm или с URL-адреса GitHub, ioBroker не создаст экземпляр. Создайте его самостоятельно с помощью значка плюса, который добавляет экземпляр в админке. Одного экземпляра достаточно для всех источников.

<!-- quelle: forum=1133140; forum=953340; forum=1143623; forum=215074; forum=378273 -->

> \[!NOTE] Установка с URL-адреса GitHub предназначена только для тестирования, по запросу разработчика. Административная панель не отображает обновления для такой установки. Чтобы вернуться к "последней" версии репозитория, см. [раздел "Как обновить SourceAnalytix (и что такое понижение версии)?"](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/05.betrieb-und-wartung.md#update-sourceanalytix-downgrade) .

<!-- quelle: forum=213055; forum=938927; interview=21 -->

**В версиях до 0.6.x:** Настройки экземпляра содержат только «Основные настройки» и «Определения цен». Там же, на вкладке «Объекты», вы включаете источники, используя значок гаечного ключа для точки данных.

<!-- quelle: code=admin/jsonConfig.json:1-8@v0.6.1; code=admin/jsonConfig.json:142-143@v0.6.1; code=main.js:106-137@v0.6.1 -->

**См. также:** [Нужно ли мне несколько экземпляров или версий, расположенных рядом?](#need-several-instances-versions-side) · [Мой первый измеритель](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#configure-sourceanalytix-datapoint)

<a id="need-several-instances-versions-side"></a>

## Мне нужно несколько экземпляров или версий, работающих одновременно?

<!-- abschnitt: prio=B; gewicht=5; readme=missing; cluster=setup-ui-16,upgrade-migration-other-23; features=source-enable -->

<!-- muss beantworten: Eine Instanz reicht für alle Datenpunkte; zwei Versionen parallel sind nicht möglich; Instanz löschen. -->

**Короче говоря:** нет. Один экземпляр обрабатывает любое количество источников, каждый со своими настройками. Вы не можете запустить две версии SourceAnalytix одновременно, потому что ioBroker устанавливает ровно одну версию каждого адаптера.

<!-- quelle: code=main.js:126-145; forum=969466; issue=#158 -->

### Один экземпляр для всего

Настройки источника применяются ко всем экземплярам. Они хранятся в точке данных в соответствующем разделе. `common.custom.sourceanalytix.<instance>` При этом каждый экземпляр вычисляет только те источники, которые для него включены. Вкладки «Обзор» и «Проблемы» также отображают только источники этого экземпляра. Второй экземпляр ничего вам не даст, если только вы намеренно не хотите использовать отдельные папки. `sourceanalytix.0` и `sourceanalytix.1`.

<!-- quelle: code=main.js:126-145; code=main.js:4426-4433; code=main.js:4624-4632; forum=969466 -->

В нескольких экземплярах всегда установлена одна и та же версия. Поэтому вы не можете протестировать новую версию рядом со старой. Установите её как обновление после создания резервной копии. Чтобы вернуться к предыдущей версии, если что-то пойдёт не так, см. [раздел «Понижение версии»](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/05.betrieb-und-wartung.md#update-sourceanalytix-downgrade) .

<!-- quelle: issue=#158 -->

### Удаление лишнего экземпляра

Второй случай часто остается незамеченным, например, при повторной установке SourceAnalytix из репозитория после установки через GitHub. Для устранения проблемы:

1. На вкладке «Объекты» проверьте, в каком экземпляре хранятся ваши значения, то есть находятся ли ваши папки в каком-либо из них. `sourceanalytix.0` или в рамках `sourceanalytix.1`.
2. На вкладке "Экземпляры" удалите лишний экземпляр, отмеченный значком корзины.

<!-- quelle: forum=938949; forum=567818 -->

> \[!ВНИМАНИЕ] Удаление экземпляра также удаляет его папки со всеми значениями. Никогда не удаляйте экземпляр, содержащий ваши данные. Если вы хотите отключить только один источник, используйте действие «Деактивировать» для этого источника.

<!-- quelle: forum=938949; code=src-admin/src/i18n/de.json -->
