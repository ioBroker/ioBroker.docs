# Источники, единицы измерения и знаки
<!-- сайт: gewicht=76; ru=en/02.anleitungen/01.quellen-und-einheiten.md -->

<a id="separate-import-feed-one-datapoint"></a>

Как разделить потребление из сети и подачу электроэнергии в сеть (одна точка данных со знаком)?
<!-- abschnitt: prio=B; гевичт=20; readme = отсутствует; кластер = цены-затраты-19, совокупная мощность-22, результаты-а именно-34, совокупная мощность-21, цены-затраты-20; Features=source-ignore-negative,source-power-integration,consumption-vs-delivery,source-multi-edit,calc-negative-values-cumulative --> <!-- muss beantworten: Ein Datenpunkt für Bezug und Einspeisung: Einstellung "negative Werte ignore", zwei Quellen, Verhalten bei negaten Лейстунген. -->

**Вкратце:** SourceAnalytix не различает потребление данных из сетки и из источника данных по знаку. Вы создаете два источника: саму точку данных для потребления и псевдоним с измененным знаком для источника данных. Оба получают параметр «Игнорировать отрицательные значения», а источник данных также получает определение цены с типом затрат «Прибыль».

<!-- quelle: interview=10; code=lib/calculation.js:752-755; code=main.js:2145-2165 -->

Направление источника определяется только типом затрат в его ценовом определении. При использовании параметра "Затраты" SourceAnalytix записывает потребление и затраты (`consumed`, `costs`). При использовании параметра "Доходы" он записывает доставку и доход (`delivered`, `earnings`). Без галочки отрицательное значение мощности считается отрицательным значением энергии и уменьшает общий баланс, поскольку источники питания не имеют функции обнаружения сброса. При установке флажка "Игнорировать отрицательные значения" значение считается равным 0 Вт.
<!-- quelle: code=main.js:2145-2165; code=main.js:3871-3880; code=lib/calculation.js:743-755; code=lib/calculation.js:766-783 -->

### Как это сделать (начиная с версии 0.7.0)
1. Откройте настройки экземпляра SourceAnalytix и добавьте две строки на вкладке «Определения цен», например, `Strom Bezug` с типом затрат «Затраты» и `Einspeisung` с типом затрат «Доходы», обе с единицей измерения `кВтч`. Для электроэнергии, вырабатываемой из сети, в поле «Цена за единицу» укажите ваш тариф за кВтч. Сохранение перезапустит адаптер.
2. В разделе «Объекты» создайте псевдоним для вашей точки данных мощности, который меняет знак при чтении (`-val`), и укажите единицу измерения `W`.
3. В настройках экземпляра перейдите на вкладку «Обзор» и нажмите «Добавить источник». Выберите исходную точку данных, тип «Мощность» и цену «Strom Bezug». На шаге «Расчет» в разделе «Для экспертов» установите флажок «Игнорировать отрицательные значения» и активируйте источник.
4. Создайте второй источник для псевдонима аналогичным образом, указав цену `Einspeisung` и параметр «Игнорировать отрицательные значения».
5. Потребление затем отображается в `sourceanalytix.0.<import>.currentYear.consumed`, входящие данные - в `sourceanalytix.0.<feedin>.currentYear.delivered`, а доходы - в `…currentYear.earnings`.

<!-- quelle: interview=10; code=src-admin/src/Wizard.tsx:68; code=src-admin/src/Wizard.tsx:636-670; code=main.js:2145-2165; code=admin/jsonConfig.json:39-83 -->

Для уже запущенного источника установите флажок в разделе «Настройки» в его подробных сведениях и нажмите «Применить». Изменения вступят в силу немедленно, без перезапуска.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:84-91; code=src-admin/src/SourceDetail.tsx:423-439; code=src-admin/src/SourceDetail.tsx:586-596 -->

> [!ПРЕДУПРЕЖДЕНИЕ] > Без параметра "Игнорировать отрицательные значения" ввод данных приводит к уменьшению общего объема потребления. В этом случае ежедневное потребление будет отображать только чистый баланс и может стать отрицательным.

<!-- quelle: code=lib/calculation.js:752-755; code=main.js:3871-3880; forum=434762 -->

Если ваш электросчетчик выдает два отдельных показания для потребления и подачи электроэнергии, используйте их в качестве двух источников показаний типа «показания счетчика». Это точнее, чем «показания счетчика с знаком», и показания счетчика не отображаются: если показания счетчика падают, SourceAnalytix рассматривает это как сброс, а не как подачу электроэнергии. Почему показания счетчика точнее, объясняется в разделе [Какой показатель мне следует активировать: счетчик (кВтч) или мощность (Вт)?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#datapoint-enable-meter-kwh-power).

<!-- quelle: code=lib/calculation.js:445-455; code=lib/calculation.js:766-783; forum=636815 -->

Планируется создание специальной настройки, которая разделяет потребление и передачу данных на основе одной точки данных ([#1272](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1272)).

<!-- quelle: issue=#1272; interview=10 -->

**До версии 0.6.x:** Флажок «Игнорировать отрицательные значения степени» находится в настройках SourceAnalytix для точки данных (Объекты, ключ) в разделе «Настройки вычислений».

<!-- quelle: code=admin/jsonCustom.json:107-128@v0.6.1 -->

## Какую единицу измерения установить для точки данных (кВт·ч вместо Вт·ч, м³ вместо литров)?
<!-- abschnitt: prio=B; гевичт=19; readme = отсутствует; кластер = накопительная мощность-24, выходные данные-09, показания счетчиков-21; функции=исходная-единица,обнаружение-конверсия-единиц,поддерживаемые-единицы,таблица-определений-цен --> <!-- нужно написать: Quelleinheit korrekt wählen; был bei nachträglicher Änderung passiert; warum кВтч стат м³ erscheint. -->

**Вкратце:** В источнике вы задаёте единицу измерения, которую фактически отображает точка данных. Обычно достаточно параметра "Определить автоматически". Единица измерения, в которой отображаются значения, берётся из определения цены. SourceAnalytix самостоятельно преобразует данные из Вт·ч в кВт·ч или из л в м³.

<!-- quelle: code=main.js:2069-2092; code=main.js:2170-2171; code=lib/calculation.js:9-20 -->

Единицы измерения и все преобразования указаны в таблице в разделе [Какие единицы измерения поддерживаются (энергия, объем, вес, длина)?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#units-supported-energy-volume-weight).

### Как это сделать (начиная с версии 0.7.0)
1. При создании источника данных мастер на шаге «Единица измерения» отображает строку «Обнаружено из точки данных: …». Выберите единицу измерения, в которой подсчитывается точка данных. Если обнаруженная единица измерения верна, оставьте ее без изменений.
2. На этапе «Цена» можно выбрать только те определения цены, для которых совпадает единица измерения. Остальные выделены серым цветом и имеют пометку «другая единица измерения».
3. Для существующего источника измените единицу измерения в его подробных сведениях в разделе «Настройки» в поле «Единица измерения» и нажмите «⚡ Применить».
4. Если SourceAnalytix не обнаруживает модуль, на вкладке «Проблемы» отображается сообщение «Модуль отсутствует или не распознан». Используйте кнопку «Исправить», чтобы выбрать его прямо там.

<!-- quelle: code=src-admin/src/Wizard.tsx:513-535; code=src-admin/src/Wizard.tsx:545-590; code=src-admin/src/SourceDetail.tsx:388-404; code=src-admin/src/Dialogs.tsx:527-529; code=lib/source-overview.js:50-53 -->

![В мастере, на шаге «Единица измерения» выберите «Обнаружено по точке данных».](../../../../../../en/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/img/assistent-einheit.png)

Типичные ошибки:

- **Показания счетчика, но с пометкой «Вт»:** SourceAnalytix берет значение мощности и суммирует его за определенный период времени. Это приводит к абсурдно высоким значениям. Выберите «Вт·ч» или «кВт·ч».
- **Мощность, но с указанием «Вт·ч» или «кВт·ч»:** SourceAnalytix считывает все значения показаний счетчика. Выберите «Вт» или «кВт».
- **Перепутаны значения `Втч` и `кВтч`:** Все значения завышены или занижены в 1000 раз.

<!-- quelle: code=main.js:2069-2092; код = main.js: 3439-3470; код=lib/calculation.js:9-20; форум=575673; форум=951120 -->

### Почему вместо м³ отображается кВт·ч
SourceAnalytix отображает все значения в единицах измерения, указанных в определении цены. Если вы видите кВт·ч, даже если ваш газовый счетчик показывает м³, значит, выбранное вами определение цены имеет единицу измерения `kWh`. Для газа создайте отдельное определение цены с единицей измерения `m³` и ценой за м³ и выберите его в качестве источника. SourceAnalytix преобразует литры и кубические метры друг в друга, но не м³ газа в кВт·ч. Начиная с версии 0.6.2, источник с `m³` и определением цены в `kWh` вообще не запускается, и в журнале отображается `Unit m³ of <datapoint> cannot be converted to unit kWh of price definition <name>`.

<!-- quelle: code=main.js:2108-2117; code=lib/calculation.js:139-158; issue=#1278; forum=953404 -->

Планируется перевод объемов газа из м³ в кВт·ч ([#6](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/6)).

<!-- quelle: issue=#6; interview=19b -->

### Если вы позже измените устройство
Новая единица измерения в источнике или в определении цены применяется со следующего значения. SourceAnalytix не преобразует уже сохраненные данные: общую сумму, начальные значения, а также значения текущего и прошлых периодов. Если единица измерения была неправильной ранее, то общая сумма и потребление останутся неправильными и после изменения. Исправьте их позже с помощью функции «Выровнять показания счетчика» и исправьте затраты, как описано в [Исправьте неверные значения.](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative).

<!-- quelle: code=main.js:2065-2066; code=main.js:4550-4605; code=lib/calculation.js:445-455 -->

**До версии 0.6.x:** Единицу измерения вы задаете в настройках SourceAnalytix для точки данных в разделе «Выбор единицы измерения». По умолчанию установлено значение «Обнаруживать автоматически». Как это сделать, описано в разделе [Где мне настроить SourceAnalytix для точки данных?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#configure-sourceanalytix-datapoint).

<!-- quelle: code=admin/jsonCustom.json:52-66@v0.6.1 -->

<a id="sourceanalytix-compute-consumption-meter-reading"></a>

## Может ли SourceAnalytix рассчитать потребление и показания счетчика на основе мощности (Вт)?
<!-- abschnitt: prio=B; гевичт=12; readme = покрыто; кластер = накопительная мощность-02; функции = интеграция-источник-мощности, преобразование-обнаружение-единиц, источник-кумулятивный-метр --> <!-- muss beantworten: Leistung als Quelle: было entsteht, welche Einheit, wie genau; Verweis auf Hintergrund. -->

**Вкратце:** Да. SourceAnalytix умножает каждое значение мощности на время до следующего значения и добавляет результат к своей сумме. На основе этого он рассчитывает потребление и затраты за день, неделю, месяц, квартал и год в единицах измерения энергии, указанных в определении цены, например, кВт·ч.

<!-- quelle: code=main.js:3862-3935; code=lib/calculation.js:766-783; code=main.js:3488-3497 -->

Сумма (`sourceanalytix.0.<device>.cumulativeReading`) начинается с 0 при активации. Таким образом, она показывает энергию с момента активации, а не показания вашего электросчетчика. Точность зависит от того, как часто устройство отправляет данные. Первое значение после активации и после каждого перезапуска SourceAnalytix служит только отправной точкой. Для источников питания нет функции обнаружения сброса, и вам не нужны никакие начальные значения.

<!-- quelle: code=main.js:2148-2150; code=main.js:3920-3930; code=main.js:2194-2197 -->

### Как это сделать (начиная с версии 0.7.0)
1. В настройках экземпляра на вкладке «Обзор» нажмите «Добавить источник» и выберите точку данных с соответствующим энергопотреблением.
2. На шаге «Тип» выберите «Мощность». Мастер уже предлагает варианты для единиц измерения «Вт» и «кВт».
3. На этапе «Цена» выберите определение цены с помощью `Вт·ч`, `кВт·ч` или `МВт·ч`. Другие единицы измерения будут недоступны (отображаться серым цветом).
4. В разделе «Для экспертов» на шаге «Расчет» вы найдете «Средние значения мощности» и «Игнорировать отрицательные значения». 5. На шаге «Начальные значения» доступен только параметр «Отсчет с текущего момента». Введите имя и активируйте источник.

Поскольку мощность является лишь приблизительной оценкой, впоследствии они снова расходятся. Действие «Поменять местами счетчик» для источников питания отсутствует.

Как отслеживать выработку солнечной энергии, подачу электроэнергии в сеть и прибыль?
<!-- abschnitt: prio=B; гевичт=9; readme = частичный; кластер = цены-затраты-22, цены-затраты-24; функции=источник-кумулятивный-метр,потребление-поставка,выходная стоимость-заработок,включение источника,начальные-значения источника --> <!-- должны быть написаны: Richtigen PV-Datenpunkt wählen, Startwert, Verbrauch против Lieferung, Erlöse. -->

**Вкратце:** Каждый счетчик становится собственным источником: общая выработка инвертора и показания счетчика подачи электроэнергии. В каждом случае используйте показания счетчика в кВт·ч, которые только увеличиваются, и определение цены с типом затрат «Прибыль». Затем SourceAnalytix записывает данные о доставке и прибыли вместо потребления и затрат.

<!-- quelle: code=main.js:2145-2165; forum=1157391; forum=1265526; forum=794768 -->

| Что вы хотите отслеживать | Точка данных | Определение цены |
|---|---|---|
| Выработка фотоэлектрической энергии | Общая выработка инвертора в кВт·ч | Тип затрат «Прибыль». Если вы не хотите видеть деньги, оставьте поле «Затраты» пустым в источнике. |
| Подача электроэнергии в сеть и доход | Счетчик подачи электроэнергии в сеть | Тип затрат «Доход», «Цена за единицу» = тариф на подачу электроэнергии в сеть за кВт·ч |
| Потребление электроэнергии из сети | Импортный счетчик вашей электроэнергии | Тип затрат "Затраты" |

<!-- quelle: code=main.js:2145-2165; код = main.js: 3755-3775; код=admin/jsonConfig.json:67-83 -->

Значения находятся в разделе `sourceanalytix.0.<device>.currentYear.delivered`, а доходы - в разделе `…currentYear.earnings`. В подробной информации об источнике столбцы называются «Поставка» и «Доходы».

<!-- quelle: code=main.js:2164-2165; code=src-admin/src/SourceDetail.tsx:333-341 -->

### Как это сделать (начиная с версии 0.7.0)
1. На вкладке «Определения цен» добавьте строку с типом затрат «Прибыль» и единицей измерения «кВтч». Сохранение перезапустит адаптер.
2. На вкладке «Обзор» нажмите «Добавить источник» и выберите общий счетчик. Мастер помечает точки данных, которые выглядят как ежедневные значения («heute», «today», «daily»), с помощью «ежедневный счетчик».
3. Выберите тип «Показания счетчика» и на шаге «Цена» укажите новое определение цены.
4. На шаге «Начальные значения» выберите «Отсчет с настоящего момента», если отсчет периодов должен начинаться с сегодняшнего дня. Если же необходимо учитывать и урожайность с начала дня или месяца, выберите «Включить потребление с начала периода» и введите показания счетчика на начало периода. Как это сделать, описано в разделе [Что нужно ввести в качестве начальных значений (и в каких единицах)?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#start-values-unit).
5. Введите имя и активируйте источник. Для счетчика подаваемой электроэнергии повторите эти шаги.

<!-- quelle: code=src-admin/src/Wizard.tsx:68; code=main.js:4648-4649; code=src-admin/src/Wizard.tsx:716-760; code=lib/calculation.js:365-390 -->

> [!ВАЖНО] > Не используйте «Урожай сегодня» или аналогичный ежедневный счетчик. Он обнуляется каждую ночь. Это работает только при обнаружении сброса, и при каждом падении теряется небольшая часть урожая. Подробнее об этом в [Счетчик, который ежедневно обнуляется.](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/05.hintergrund/02.zaehler-reset.md#counter-reset-0-daily-happens).

<!-- quelle: interview=4; code=lib/calculation.js:445-455; code=src-admin/src/i18n/de.json:63-64 -->

Если ваш инвертор обеспечивает только мгновенную мощность, используйте его в качестве источника питания; см. [Может ли SourceAnalytix рассчитывать потребление и показания счетчика на основе мощности (Вт)?](#sourceanalytix-compute-consumption-meter-reading). Если у вас есть только точка данных сетки со знаком, см. [Разделение потребления и подачи электроэнергии].](#separate-import-feed-one-datapoint), как преобразовать его в два источника.

<!-- quelle: interview=10; code=main.js:3862-3935 -->

SourceAnalytix не рассчитывает самопотребление и самообеспечение. Это запланировано ([#643](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/643)).

<!-- quelle: issue=#643 -->

**До версии 0.6.x:** Вы активируете точки данных по одной в настройках SourceAnalytix для каждой точки данных и выбираете там определение цены, см. [Где мне настроить SourceAnalytix для точки данных?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#configure-sourceanalytix-datapoint).

Как получить значение счетчика на основе скорости потока, времени выполнения или данных с нескольких устройств?
<!-- abschnitt: prio=B; гевичт=8; readme = отсутствует; кластер = выходные данные-а именно-14, совокупная мощность-29, показания счетчиков-16; функции=счетчик-источника-кумулятивной мощности,интеграция-мощности-источника,поддерживаемые единицы,обнаружение-сброса-источника,подтверждение-сброса --> <!-- необходимо написать: Summen und abgeleitete Zähler (Phasen, Brenner, Füllstand), Reset-Erkennung dafür. -->

**Вкратце:** С помощью скрипта. SourceAnalytix обрабатывает каждую точку данных самостоятельно, и со временем суммирует только мощность (Вт) и импульсы в минуту. Для суммирования расхода, времени работы или уровня заполнения вы, следовательно, записываете собственные показания счетчика с помощью скрипта, который только увеличивает их в поддерживаемых единицах измерения и активирует эту точку данных.

<!-- quelle: code=lib/calculation.js:9-20; code=lib/calculation.js:160-168; code=main.js:3441-3445; forum=1241171 -->

| Дело | Чем вы занимаетесь |
|---|---|
| Несколько фаз одного счетчика | Используйте общий счетчик устройства. Если его нет, с помощью скрипта сложите показания фазного счетчика в кВт·ч. |
| Несколько устройств одновременно | Каждое устройство является собственным источником. Если вам нужна сумма в качестве счетчика, создайте ее с помощью скрипта. |
| Скорость потока (`m³/h`, `l/min`) | Скорость потока не поддерживается. Скрипт добавляет скорость × время к объему в `m³` или `l`. |
| Запуск горелки | Начиная с версии 0.7.0, непосредственно в виде показаний счетчика с помощью устройства `piece`, см. [Кусочки и бобы](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#units-supported-energy-volume-weight). |
| Запуск горелки | Начиная с версии 0.7.0, непосредственно в виде показаний счетчика с единицей измерения «штука», см. [Штуки и импульсы](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#units-supported-energy-volume-weight). |
| Уровень заполнения (например, масляного бака) | Не используйте сам уровень заполнения, он снижается по мере потребления. Скрипт суммирует только уменьшения и не учитывает пополнения. |

Планируется «Сумма всех источников» ([#60](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/60)).

<!-- quelle: code=src-admin/src/SourcesApp.tsx:676-679; issue=#60 -->

Как создать точку данных скрипта таким образом, чтобы SourceAnalytix ее обнаружил, описано в следующем разделе в [Точки данных скрипта](#use-script-datapoints-unreliable-sources).

### Сброс обнаружения сумм
Для SourceAnalytix сумма - это обычное показание счётчика. Если показания субсчётчика сбрасываются, сумма уменьшается. При включенном обнаружении сброса SourceAnalytix обрабатывает это как любой другой сброс: он ждёт следующего значения, а затем продолжает подсчёт поверх старой суммы. Принцип работы описан в [Что означает сообщение "Обнаружена перезагрузка устройства" и как работает обнаружение перезагрузки?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/05.hintergrund/02.zaehler-reset.md#device-reset-detected-mean-reset).

<!-- quelle: code=lib/calculation.js:445-455; code=lib/calculation.js:508-600; forum=919324 -->

> [!TIP] > Самый чистый вариант - это сумма, которая никогда не уменьшается: скрипт добавляет только увеличение каждого субсчетчика с момента его последнего значения и игнорирует уменьшения. В этом случае SourceAnalytix вообще не замечает сброса субсчетчика.

<a id="use-script-datapoints-unreliable-sources"></a>

## Можно ли использовать данные из скриптов или ненадежные источники?
<!-- abschnitt: prio=B; гевичт=8; readme = отсутствует; кластер = установка-ui-24, накопительная мощность-18; Features=source-cumulative-meter,source-enable,output-timestamps-ack,other-object-subscription,reset-jitter-ignore --> <!-- необходимо написать: Skript-/Fremd-Datenpunkte (Simple-API, другой адаптер); Ausreißer und Nachkomastellen filtern. -->

**Вкратце:** Да. Любая точка данных может быть источником, будь то адаптер, скрипт, псевдоним или Simple API. Главное, чтобы она передавала число в поддерживаемой единице измерения. Неважно, было ли значение записано с подтверждением или без него (`ack`).

<!-- quelle: code=main.js:2540-2565; code=main.js:3446-3453; forum=474030 -->

Значения из другой установки ioBroker сначала должны поступить в систему, на которой запущен SourceAnalytix, в виде точки данных, например, через Simple API или скрипт.

<!-- quelle: code=main.js:4624-4653 -->

### Точки данных скрипта
- Создайте точку данных, указав в объекте номер типа и единицу измерения, например, `кВтч`. Мастер отображает в разделе «Соответствующие точки данных» только точки данных с обнаруженной единицей измерения. Если единица измерения не указана, выберите точку данных с помощью кнопки «Выбрать объект» и укажите единицу измерения на следующем шаге.
- Запишите показания счетчика, которые будут только увеличиваться, и не обнуляйте их ежедневно.
- Начиная с версии 0.6.2, SourceAnalytix также считывает показания счетчиков, поступающие в текстовом формате, например, «12,5», а начиная с версии 0.7.0 - значения мощности, например, «1,5» ([#1288](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1288)). Если текст не является числом, в журнале появляется сообщение «Значение «…» <точки данных> не является числом, показания игнорируются». Затем на вкладке «Проблемы» появляется сообщение «Точка данных передает текст вместо числа».

<!-- quelle: code=main.js:4624-4642; code=src-admin/src/Wizard.tsx:513-535; code=main.js:3446-3453; code=main.js:3870-3876; code=lib/source-overview.js:161; issue=#1255; issue=#1288 -->

### Выбросы и десятичные знаки
SourceAnalytix фильтрует значения только на основе обнаружения сброса:

- Падение значения, не превышающего «Порог», считается шумом измерения и игнорируется.
- Одно низкое значение, например, кратковременный ноль, отбрасывается как выброс, если следующее значение возвращается к прежнему уровню.
- Резкий скачок вверх мгновенно воспринимается как потребление. Фильтра против этого нет.

<!-- quelle: code=lib/calculation.js:445-455; code=lib/calculation.js:508-600; issue=#1258 -->

Если ваш источник иногда выдает абсурдно высокие значения, предварительно отфильтруйте их с помощью скрипта, который записывает только правдоподобные, неубывающие значения в свою собственную точку данных, и активируйте именно ее. Если уже было получено неверное значение, исправьте его, как описано в [Исправьте неверные значения.](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative).

<!-- quelle: code=lib/calculation.js:445-455; forum=938999 -->

Большое количество десятичных знаков в исходном коде не является проблемой. Количество выходных данных SourceAnalytix для исходного кода задается в разделе «Для экспертов» с помощью параметров «Десятичные знаки для потребления» и «Десятичные знаки для затрат».

<!-- quelle: code=src-admin/src/SourceDetail.tsx:534-543; code=lib/calculation.js:257-295 -->

**До версии 0.6.1:** SourceAnalytix не вычисляет значения точек данных, которые представляют собой числа в текстовом формате. Начиная с версии 0.6.2, он считывает их ([#1255](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1255)).
