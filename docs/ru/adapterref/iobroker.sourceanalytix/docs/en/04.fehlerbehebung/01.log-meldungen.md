# Запись сообщений и ошибок во время настройки
<!-- сайт: gewicht=129; ru=en/04.fehlerbehebung/01.log-meldungen.md -->

## Ошибка "Единица измерения не поддерживается" / "Единица измерения не определена" - как мне задать единицу измерения?
<!-- abschnitt: prio=A; гевичт=32; readme = частичный; кластер = выходные данные-viz-07, журналы-установка-10, настройка-ui-13; Features=source-unit,unit-detection-conversion,supported-units,log-source-config-errors --> <!-- необходимо написать: Ursachen (Einheit am Datenpunkt fehlt orer unbekannt), Lösung, Verweis auf Referenz Einheiten. -->

**Вкратце:** SourceAnalytix не может найти единицу измерения для точки данных, поэтому он не выполняет вычисления. Начиная с версии 0.7.0, источник отображается в настройках экземпляра на вкладке «Проблемы» с пометкой «Единица измерения отсутствует или не распознана». Нажмите «Исправить» и выберите единицу измерения, в которой устройство выдает значение.

<!-- quelle: code=main.js:2072-2090; code=lib/source-overview.js:48-53; code=lib/source-overview.js:159; code=src-admin/src/SourcesApp.tsx:447-449; code=src-admin/src/i18n/de.json:114; code=src-admin/src/i18n/de.json:214; issue=#1269 -->

Вот как выглядит сообщение в журнале:

```text
No unit defined for <datapoint>, cannot execute calculations !
Please choose unit manually in state configuration
Cannot handle calculations for <datapoint>, check log messages and adjust settings!
```

<!-- quelle: code=main.js:2087-2088; код = main.js: 2136; код=main.js:1927-1928@v0.6.1; код=main.js:1954@v0.6.1 -->

Точка данных не вычисляется, и SourceAnalytix не создает для нее состояний. Сообщение `Sorry unite type … not supported` появляется в старых версиях до v0.4.2. Начиная с v0.4.7, оно отображается как `No unit defined`.

<!-- quelle: code=main.js:1954-1958@v0.6.1; code=main.js:327@0.4.2; code=main.js:251@v0.4.7 -->

Откуда поступает сообщение?
SourceAnalytix использует единицу измерения, выбранную вами для источника (начиная с версии 0.7.0 в сведениях об источнике в разделе «Единица измерения», и до версии 0.6.x в диалоговом окне точки данных в разделе «Выбрать единицу измерения»). Если для этого установлено значение «Определять автоматически», используется единица измерения, указанная в объекте точки данных. Сообщение появляется, когда ни один из вариантов не работает:

- Объект не имеет единиц измерения. Это характерно для данных, полученных из скриптов, а также для данных, созданных вами самостоятельно.
- Единица измерения объекта **отсутствует в списке**, например, `Ватт` вместо `Вт`, `м³` вместо `м³` или `м³/ч`.
- Количество **не поддерживается**, например, шт., импульсов, часов работы или `%`. **Начиная с версии 0.7.0**, единицы измерения `шт.` и `шт./мин` охватывают шт. и импульсы (см. [Штаммы и импульсы](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#units-supported-energy-volume-weight)).

<!-- quelle: code=main.js:1914-1930@v0.6.1; code=lib/calculation.js:8-33@v0.6.1; code=main.js:2072-2090; code=src-admin/src/SourceDetail.tsx:388-403; issue=#1264; issue=#304; issue=#74 -->

Список доступных единиц измерения приведен в разделе [единицы измерения](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#units-supported-energy-volume-weight).

### Как это сделать (начиная с версии 0.7.0)
1. В разделе «Экземпляры» откройте настройки экземпляра SourceAnalytix и перейдите на вкладку «Проблемы». Экземпляр должен быть запущен.
2. Найдите строку с вашим источником, содержащую сообщение «Единица измерения отсутствует или не распознана», и нажмите «Исправить».
3. В диалоговом окне «Установить единицу измерения» отображается единица измерения для данной точки данных. В поле «Единица измерения» выберите единицу измерения, в которой работает устройство. Если ваш газовый счетчик выдает «м³», выберите «м³». Если ваша розетка выдает ватты, выберите «Вт».
4. Нажмите «Применить». Настройка вступает в силу немедленно, без перезапуска. После этого в журнале отображается сообщение «Включить SourceAnalytix для: <точка данных>» без сообщения об ошибке, а после повторной проверки строка исчезает со вкладки «Проблемы».

<!-- quelle: code=src-admin/src/SourcesApp.tsx:338-410; code=src-admin/src/SourcesApp.tsx:447-449; code=src-admin/src/Dialogs.tsx:515-572; code=src-admin/src/i18n/de.json:49; code=src-admin/src/i18n/de.json:114; code=src-admin/src/i18n/de.json:301-302; code=main.js:2432; issue=#1269 -->

![Вкладка «Проблемы» с открытым диалоговым окном «Исправить устройство»](../../../../../../en/adapterref/iobroker.sourceanalytix/docs/en/04.fehlerbehebung/img/einheit-beheben.png)

Аналогичный выбор вы найдете в разделе "Настройки" в поле "Единица измерения" в подробных сведениях об источнике. Чтобы добавить новый источник, лучше всего использовать кнопку "Добавить источник": мастер не продолжит работу, пока не будет выбрана единица измерения.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:388-403; code=src-admin/src/Wizard.tsx:158-166; code=src-admin/src/i18n/de.json:30 -->

**До версии 0.6.x:** Откройте настройки SourceAnalytix для точки данных ([Вот как их найти.](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#configure-sourceanalytix-datapoint)), выберите единицу измерения в разделе «Выберите единицу измерения» и сохраните. Если диалоговое окно не может найти подходящую единицу измерения, отобразится сообщение «Поддерживаемая единица измерения не обнаружена. Пожалуйста, выберите единицу измерения», и сохранение не произойдет.

<!-- quelle: code=admin/jsonCustom.json:52-66@v0.6.1; code=admin/jsonCustom.json:58-60@v0.6.1; code=admin/i18n/de.json:47@v0.6.1; code=main.js:2172-2173@v0.6.1 -->

> [!ВАЖНО] > Выберите единицу измерения, которую устройство **поставляет**, а не ту, которую вы хотите видеть. Определение цены определяет единицу измерения, в которой SourceAnalytix производит расчеты и отображает данные. Если вы выберете `kWh`, хотя устройство поставляет `Wh`, все значения будут завышены в 1000 раз.

<!-- quelle: code=main.js:1982-1983@v0.6.1; code=lib/calculation.js:42-65@v0.6.1 -->

Если в журнале отображается `reading incorrect after conversion contact DEV`, то единица измерения точки данных не соответствует единице измерения определения цены, например, `kg` и `kWh`. Начиная с версии 0.6.2, SourceAnalytix сообщает об этом при запуске: `Unit <unit> of <datapoint> cannot be converted to unit <unit> of price definition <name>` ([#1278](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1278)). Затем выберите определение цены с соответствующей единицей измерения. Начиная с версии 0.7.0, источник отображается на вкладке «Проблемы» с сообщением «Единица измерения не соответствует цене». Вплоть до версии 0.6.1 то же сообщение появляется и тогда, когда источник выдает текст вместо числа (см. [Источник выдает текст вместо числа]).](#source-delivers-text-instead-number)).

<!-- quelle: code=main.js:2997-3008@v0.6.1; code=lib/calculation.js:52-60@v0.6.1; code=main.js:2107-2119; code=lib/source-overview.js:59-60; code=src-admin/src/i18n/de.json:213; issue=#1255; issue=#1278 -->

**Начиная с версии 0.6.2:** SourceAnalytix также распознает написание `m3`, `kwh` и аналогичные в объекте, и выполняет вычисления с `m³` или `kWh` ([#1264](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1264)). Затем в логе отображается `Единица измерения "m3" <datapoint> используется как m³`. Диалоговое окно настроек также принимает эти варианты написания в разделе "Обнаруживать автоматически" ([#1278]](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1278)). Написанные полностью имена, такие как `Watt` или `Liter`, по-прежнему необходимо выбирать вручную.
<!-- quelle: issue=#1264; pr=#1274; issue=#1278; code=main.js:2072-2085; code=lib/calculation.js:25; code=lib/calculation.js:114 -->

**См. также:** [Какие единицы измерения поддерживаются (энергия, объем, вес, длина)?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#units-supported-energy-volume-weight) · [Какую единицу измерения мне следует установить для точки данных (кВт·ч вместо Вт·ч, м³ вместо литров)?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/01.quellen-und-einheiten.md#unit-datapoint-kwh-wh-m3)

## Ошибка "Known valueAtDeviceReset > known cumulative value"
<!-- abschnitt: prio=B; гевичт=19; readme = отсутствует; кластер = журналы-установка-06, периоды-09, показания счетчиков-20; Features=log-source-config-errors,source-hidden-reset-keys,reset-manual-correction,calc-first-activation-start-values,source-start-values --> <!-- нужно написать: Offset und cumulativeReading в Einklang Bringen. -->

**Вкратце:** Сохраненное смещение (`valueAtDeviceReset`) больше, чем сумма (`cumulativeReading`). Начиная с версии 0.6.2, это всего лишь предупреждение: источник продолжает работу, и SourceAnalytix сам выравнивает смещение по следующему значению. После этого проверьте сумму и, при необходимости, сопоставьте ее с показаниями вашего счетчика с помощью действия «Выровнять показания счетчика». До версии 0.6.1 источник не запускается при возникновении этой ошибки.

<!-- quelle: code=main.js:2121-2131; code=main.js:3520-3530; code=main.js:1943-1952@v0.6.1; issue=#1257; issue=#640 -->

Понятия «сумма», «стоимость устройства» и «смещение» поясняются в разделе [Условия](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/05.hintergrund/02.zaehler-reset.md#device-reset-detected-mean-reset). Правило всегда следующее: сумма = стоимость устройства + смещение.

### Как выглядит сообщение?
Начиная с версии 0.6.2, при запуске в журнале появляется предупреждение, а вторая строка содержит следующее значение из источника:

```text
Known valueAtDeviceReset (<offset>) of <datapoint> is larger than the known cumulative value (<total>); the offset will be realigned with the next reading so the total continues from <total>
Realigned valueAtDeviceReset of <datapoint> from <old offset> to <new offset>: device value <device value>, total continues from <total>
```

<!-- quelle: code=main.js:2128; код = main.js: 3524; проблема = # 1257; пр=#1274 -->

В версиях до 0.6.1 это ошибка, и исходный код не запускается:

```text
Check settings for <datapoint> ! Known valueAtDeviceReset : (<offset>) > known cumulative value (<total>) cannot proceed
Troubleshoot Data <datapoint> custom Data : {…}
Cannot handle calculations for <datapoint>, check log messages and adjust settings!
```

<!-- quelle: code=main.js:1946-1947@v0.6.1; код=main.js:1954@v0.6.1 -->

Откуда поступает сообщение?
Смещение хранится в настройках SourceAnalytix для точки данных, а сумма - в состоянии `sourceanalytix.0.<device>.cumulativeReading`. Когда эти два параметра перестают совпадать, появляется это сообщение. Типичные причины:

- Вы вручную уменьшили только `cumulativeReading` или установили его равным 0, например, следуя старому руководству.
- Состояние `cumulativeReading` или вся папка источника были удалены. Отсутствующая сумма засчитывается как 0, в то время как смещение в настройках сохраняется.
- После замены или восстановления счетчика общая сумма и настройки считываются из разных временных точек.

<!-- quelle: code=main.js:2062-2066; код=lib/calculation.js:319@v0.6.1; форум=558368; форум = 602307; форум=959873; форум=1097776 -->

Источники мощности (Вт) и другие источники, суммарная мощность которых, рассчитанная с помощью SourceAnalytix, не имеют смещения. Они никогда не выдают это сообщение.

<!-- quelle: code=main.js:2125-2127; code=main.js:1944@v0.6.1 -->

### Как это сделать (начиная с версии 0.7.0)
1. В разделе «Экземпляры» откройте настройки экземпляра SourceAnalytix и на вкладке «Обзор» выберите свой источник.
2. Сравните значение «Итого» с показаниями вашего измерителя. Если они совпадают, ничего делать не нужно. SourceAnalytix автоматически выравнивает смещение по следующему значению.
3. Если показания не совпадают, выберите «Выровнять показания счетчика» в разделе «Действия», введите показания вашего счетчика в поле «Что показывает ваш счетчик сейчас?» и нажмите «Выровнять». SourceAnalytix мгновенно и без перезапуска установит общее значение и смещение таким образом, чтобы они совпадали.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:275-278; code=src-admin/src/SourceDetail.tsx:602-611; code=src-admin/src/Dialogs.tsx:112-200; code=main.js:4124-4175; issue=#640; issue=#1269 -->

До получения следующего значения источник также отображается на вкладке «Проблемы» с пометкой «Итого не соответствует счетчику». Кнопка «Выровнять» в этой строке открывает то же действие. В подробной информации об источнике текущее смещение отображается в разделе «Для экспертов» как `valueAtDeviceReset`.

<!-- quelle: code=lib/source-overview.js:162; code=main.js:4464; code=src-admin/src/SourcesApp.tsx:450-452; code=src-admin/src/SourceDetail.tsx:289-306; code=src-admin/src/i18n/de.json:117; code=src-admin/src/i18n/de.json:205 -->

> [!ПРЕДУПРЕЖДЕНИЕ] > Автоматическая корректировка продолжает отсчет от сохраненной суммы, даже если эта сумма неверна. ## Ошибка "Тип затрат не определен" - отсутствует определение цены
<!-- abschnitt: prio=B; гевичт=17; readme = покрыто; кластер = журналы-установка-27, настройка-UI-12; Features=source-price-definition,log-source-config-errors,price-definitions-table --> <!-- необходимо написать: Preisdefinition anlegen und zuordnen. -->

**Вкратце:** Каждому источнику требуется определение цены, даже если вам нужно только потребление. Его единица измерения - это целевая единица, в которой SourceAnalytix производит расчеты. Начиная с версии 0.7.0, источник без действительного определения цены отображается на вкладке «Проблемы». С помощью кнопки «Выбрать цену» вы открываете источник и выбираете его в разделе «Определение цены».

<!-- quelle: code=main.js:2099-2111; code=lib/source-overview.js:54-58; code=lib/source-overview.js:159; code=src-admin/src/SourcesApp.tsx:456-458; code=src-admin/src/i18n/de.json:112; forum=214572; forum=769206 -->

### Как выглядит сообщение?
Если для источника не выбрано определение цены:

```text
No cost type defined for <datapoint>, please Select Type of calculation at state setting
Cannot handle calculations for <datapoint>, check log messages and adjust settings!
```

<!-- quelle: code=main.js:2100; код=main.js:2136 -->

Если выбранное определение цены больше не существует, например, потому что его "Категория" была переименована или удалена:

```text
Selected Type <name> does not exist in Price Definitions
Please choose proper type for state <datapoint>
Or add price definition <name> in adapter settings
```

<!-- quelle: code=main.js:2102-2105; код=main.js:1459 -->

В обоих случаях источник не рассчитывается, и состояния не создаются. На вкладке «Проблемы» случаи называются «Определение цены не выбрано» и «Определение цены больше не существует». Старое сообщение `Error in case handling of cost type identification: undefined` больше не существует в текущих версиях.

<!-- quelle: code=main.js:2134-2140; code=src-admin/src/i18n/de.json:204; code=src-admin/src/i18n/de.json:207; code=CHANGELOG_OLD.md:120; forum=214572; issue=#116 -->

### Как это сделать (начиная с версии 0.7.0)
1. Если у вас еще нет подходящего определения цены, создайте его в настройках экземпляра на вкладке «Определения цен». Важна «Единица измерения»: она должна соответствовать источнику, например, «кВтч» для электросчетчика или для значения мощности в Вт. Сохранение перезапустит адаптер.
2. Откройте вкладку «Проблемы» и нажмите «Выбрать цену» в строке источника. Откроется подробная информация об источнике.
3. В разделе «Настройки» выберите категорию в поле «Определение цены». В списке единица измерения указана в скобках, например, «Энергия (кВтч)».
4. Нажмите «Применить». Источник запустится немедленно, без перезапуска.

<!-- quelle: code=admin/jsonConfig.json:38-43; code=admin/i18n/de.json:53; code=src-admin/src/i18n/de.json:165; code=src-admin/src/SourcesApp.tsx:456-458; code=src-admin/src/SourceDetail.tsx:405-421; code=src-admin/src/SourceDetail.tsx:582-596; code=main.js:2394-2440 -->

Если единица измерения цены не соответствует источнику, на вкладке «Проблемы» появляется сообщение «Единица измерения не соответствует цене» (см. [Ошибка "единица измерения не поддерживается" / "Единица измерения не определена"](#error-unit-not-supported-no)). Мастер «Добавить источник» предлагает только определения цен с соответствующей единицей измерения и не продолжит работу без выбора.

<!-- quelle: code=lib/source-overview.js:59-60; code=src-admin/src/Wizard.tsx:158-166; code=src-admin/src/Wizard.tsx:553-570 -->

**До версии 0.6.x:** В диалоговом окне в точке данных выберите категорию в разделе «Выберите определение цены» и сохраните ([Вот как найти диалог.](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#configure-sourceanalytix-datapoint)). Начиная с версии 0.6.0, сохранение диалогового окна без определения цены невозможно.

<!-- quelle: code=admin/jsonCustom.json:37-51@v0.6.1; issue=#1202 -->

## Сообщения "Не удалось инициализировать" / "Невозможно выполнить вычисления" / "Неверное чтение"
<!-- abschnitt: prio=B; гевичт=13; readme = отсутствует; кластер = журналы-установка-07, журналы-установка-08; функции = log-startup-summary, log-source-config-errors, log-lifecycle-info, source-enable, source-hidden-reset-keys --> <!-- нужно написать: Bedeutung beim Start und bei Konvertierung; Урсачен прюфен. -->

**Вкратце:** Это универсальные сообщения. Они лишь указывают на то, что SourceAnalytix не запустил источник или не смог вычислить значение. Причина кроется в строках лога непосредственно перед этим. Начиная с версии 0.7.0, вкладка «Проблемы» в настройках экземпляра показывает причину вместе с предлагаемым решением.

<!-- quelle: code=main.js:160-213; code=main.js:2134-2140; code=lib/source-overview.js:135-196; forum=565033; forum=649964 -->

### Сообщения при запуске и активации
| Сообщение | Смысл |
|---|---|
| `Initialization of <datapoint> successfully` | Источник запущен. |
| `Cannot handle calculations for <datapoint>, check log messages and adjust settings!` | То же самое для одного источника, сразу после причины. |
| `Cannot handle calculations for <n> of <m> enabled states, check error messages` | Сводка по завершении запуска: n из m источников не запущены. |

| `[Cannot enable SourceAnalytix for <datapoint>, check settings and error messages` | Источник, который вы активировали или изменили во время работы, не смог запуститься. |

| `Невозможно обработать инициализацию для <точки данных>` | Дополнительное сообщение: отсутствуют проверенные настройки для источника. Здесь причина также указана в предыдущих строках. |

<!-- quelle: code=main.js:165-181; code=main.js:206-212; code=main.js:2136; code=main.js:2432-2439; code=main.js:2273-2275 --> |

Распространенные причины указаны в предыдущих строках:

- `Для … не определена единица измерения`: см. [Ошибка "единица измерения не поддерживается" / "Единица измерения не определена"](#error-unit-not-supported-no).
- `Не определен тип затрат для …` или `Выбранный тип … не существует в определениях цен`: см. [Ошибка "Не определен тип затрат"](#error-no-cost-type-defined).

- `Невозможно использовать идентификатор выходных данных… нет существующего дерева выходных данных для сохранения`: запрошенный вами технический идентификатор недействителен или уже занят, см. [Имя, псевдоним и идентификатор выходных данных](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/03.referenz/01.einstellungen.md#name-datapoint-alias-output-id).
- В версиях до 0.6.1 также выполняется проверка настроек для … известного значения при сбросе устройства …: см. [Ошибка "Известное значение при сбросе устройства > известное совокупное значение"](#error-known-valueatdevicereset-known-cumulative).

После устранения причины в настройках и их применения SourceAnalytix запускает источник без перезапуска. В журнале отображается `Enable SourceAnalytix for : <datapoint>` без каких-либо ошибок после этого.

<!-- quelle: code=main.js:2394-2440; code=src-admin/src/i18n/de.json:40 -->

### Сообщение "Неверное чтение после преобразования"
```text
[calculationHandler] reading incorrect after conversion contact DEV and provide these info | Reading : null | start reading {…} | stateDetails {…}
```

<!-- quelle: code=main.js:3476; код=main.js:3007@v0.6.1 -->

Вплоть до версии 0.6.1 это сообщение появляется с каждым значением, если источник не выдает число (например, `null` или текст, например, `"12,5"`), или если единица измерения источника не соответствует определению цены, например, `kg` и `kWh`. Источник продолжает работать, но ничего не вычисляет. Проверьте историю данных источника, чтобы увидеть, что поступило на момент сообщения, и проверьте единицу измерения.
<!-- quelle: code=main.js:2995-3008@v0.6.1; code=lib/calculation.js:43-65@v0.6.1; forum=558176; forum=1315010; forum=1333372 -->

**Начиная с версии 0.6.2**, SourceAnalytix заранее обнаруживает обе причины: он считывает числа внутри самого текста и пропускает значение без числа с предупреждением `Value <value> of <datapoint> is not a number, reading ignored` (см. [Источник выдает текст вместо числа.](#source-delivers-text-instead-number)). Он отклоняет несоответствующие единицы измерения при запуске. Если сообщение по-прежнему появляется, сообщите об этом как о проблеме в репозитории адаптера, указав всю строку лога.

## Источник выдает текст вместо числа (строку вместо числа, с десятичной точкой)
<!-- abschnitt: prio=B; гевичт=12; readme = отсутствует; кластер = журналы-установка-09, выходы-а именно-32; Features=log-calculation-errors,unit-detection-conversion,source-cumulative-meter,reset-invalid-reading,source-alias --> <!-- muss beantworten: Quelle/Skript/Alias so umstellen, dass eine Zahl ankommt. -->

**Вкратце:** Начиная с версии 0.6.2, SourceAnalytix считывает числа непосредственно из текста, с запятой или точкой, например, `"12,5"` или `".14"`. Он не может считывать текст с разделителем единиц или тысяч, например, `"12,5 kWh"` или `"1.234,5"`, и пропускает значение с предупреждением. Самый безопасный вариант - это исходная точка данных типа число.

<!-- quelle: code=main.js:3446-3453; code=lib/dynamic-pricing.js:7-17; issue=#1255; pr=#1274 -->

### Как это распознать
- **Начиная с версии 0.7.0**, источник отображается на вкладке «Проблемы» с подсказкой «Точка данных выдает текст вместо числа», если последнее значение является текстом. Кнопка «Руководство» ведет сюда.
- **Начиная с версии 0.6.2**, если текст не содержит читаемого числа, в журнале отображается сообщение `Значение "<значение>" <точки данных> не является числом, чтение игнорируется`. Это значение не учитывается, но следующее читаемое значение учитывается.
- **Вплоть до версии 0.6.1** SourceAnalytix выполняет вычисления без каких-либо текстовых значений. Для показаний счетчиков в журнале отображается сообщение «неверные показания после преобразования, свяжитесь с DEV… Показания: null» со всеми значениями, а источник остается без значений.

<!-- quelle: code=lib/source-overview.js:161; code=src-admin/src/i18n/de.json:131; code=src-admin/src/i18n/de.json:212; code=src-admin/src/SourcesApp.tsx:414-418; code=src-admin/src/SourcesApp.tsx:437-440; code=main.js:3452; code=lib/calculation.js:43@v0.6.1; code=main.js:3007@v0.6.1; issue=#1255 -->

**Начиная с версии 0.7.0**, SourceAnalytix также считывает текст с запятой или точкой для обозначения источников мощности (Вт), например, `"1,5"`, так же, как и для показаний счетчиков. Если текст не является числом, в журнале отображается `Value "<value>" of <datapoint> is not a number, reading ignored`, и значение не учитывается ([#1288](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1288)).

<!-- quelle: issue=#1288; code=main.js:3870-3876; code=lib/dynamic-pricing.js:7-17 -->

**Вплоть до версии 0.6.x** SourceAnalytix преобразует текст для источников питания только в том случае, если используется десятичная точка (`"12.5"`). При наличии запятой в журнале отображается `[wattToWattHour] Invalid power reading interval for <datapoint>, using current reading as new baseline` для каждого значения, и данные о потреблении не отображаются.

<!-- quelle: code=main.js:3335@v0.6.1; code=main.js:3366@v0.6.1; code=lib/calculation.js:766-781; issue=#1288 -->

### Как переключиться на число
1. Сначала проверьте, есть ли у адаптера источника данных настройка для отображения числовых значений или предлагается ли другой способ представления показаний счетчика в числовом формате. Используйте этот вариант.
2. В противном случае создайте собственную точку данных типа "число". Например, создайте псевдоним типа "число", функция чтения которого преобразует текст, или скрипт, который преобразует текст с помощью `parseFloat` и записывает его в новую точку данных. Сначала замените запятую точкой.
3. Укажите для новой точки данных единицу измерения, в которой работает устройство, например, `кВт·ч`.
4. Настройте новую точку данных как источник, используя кнопку "Добавить источник".

<!-- quelle: forum=559520; форум=590394; форум = 1284986; форум=943059; форум = 870108; проблема = # 468; code=src-admin/src/i18n/de.json:30 -->

> [!NOTE] > Для SourceAnalytix новая точка данных представляет собой новый источник со своей собственной папкой. Значения старого источника остаются в своей папке. Вы переносите показания счетчика с помощью [начальные значения](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#start-values-unit) или с помощью "Выровнять показания счетчика".

## Точки данных включены, но папки и состояния не отображаются
<!-- abschnitt: prio=B; гевичт=10; readme = отсутствует; кластер = настройка-ui-15, настройка-ui-27, накопительная мощность-25; Features=source-enable,log-source-config-errors,output-tree-layout,source-calc-consumption,source-price-definition --> <!-- необходимо написать: Контрольный список: Kostenart, Einheit, Meldungen, Aktivierung, Objektliste. -->

**Вкратце:** Практически всегда SourceAnalytix отклоняет источник, обычно из-за отсутствия определения цены или единицы измерения. Начиная с версии 0.7.0, это можно увидеть в настройках экземпляра: на вкладке «Обзор» источник имеет статус «Проблема», а на вкладке «Проблемы» отображается причина и кнопка для ее исправления.

<!-- quelle: code=main.js:2134-2140; code=lib/source-overview.js:135-196; code=lib/source-overview.js:206-214; code=src-admin/src/i18n/de.json:257-260; forum=866427; forum=694176; issue=#1008 -->

### Контрольный список (начиная с версии 0.7.0)
1. **Запущен ли экземпляр?** Без запущенного экземпляра SourceAnalytix не выполняет вычисления, и в обзоре отображается сообщение «Для обзора требуется запущенный экземпляр».
2. **Находится ли источник на вкладке «Обзор»?** Если нет, то точка данных не настроена для данного экземпляра, например, она настроена для `sourceanalytix.1` вместо `sourceanalytix.0`. Настройте ее с помощью кнопки «Добавить источник». Мастер проверит единицу измерения и цену перед сохранением.
3. **Какой у него статус?** «Деактивирован»: откройте источник и выберите «Активировать» в разделе «Действия». «Проблема» или «Подсказка»: перейдите к шагу 4.
4. **Что отображается на вкладке "Проблемы"?** «Определение цены не выбрано», «Определение цены больше не существует», «Единица измерения отсутствует или не распознана», «Единица измерения не соответствует цене» или «Точка данных больше не существует». Кнопка в этой строке устраняет проблему или открывает нужное место.
5. **Что написано в журнале?** После команды `Enable SourceAnalytix for : <datapoint>` появляется сообщение об ошибке с указанием причины, см. сообщения ["Initialization failed" / "Cannot handle calculations"](#messages-initialization-failed-cannot-handle).
6. **Отмечен ли флажок «Потребление»?** Без флажка «Потребление» в настройках источника значения потребления не создаются для дня, недели, месяца, квартала и года.

<!-- quelle: code=src-admin/src/SourcesApp.tsx:474-476; code=src-admin/src/i18n/de.json:163; code=main.js:4426-4433; code=src-admin/src/Wizard.tsx:158-166; code=src-admin/src/SourceDetail.tsx:639-646; code=lib/source-overview.js:150-160; code=main.js:2432-2439; code=src-admin/src/SourceDetail.tsx:84-91; code=main.js:2789-2870@v0.6.1 -->

После запуска источника SourceAnalytix немедленно создает папку `sourceanalytix.0.<device>`. Первые значения отображаются вместе со следующим значением точки данных. Если вы по-прежнему не видите папку на вкладке "Объекты", перезагрузите представление и проверьте, активен ли фильтр в списке объектов.

<!-- quelle: code=main.js:2267-2330; forum=694176; forum=1217092 -->

**Начиная с версии 0.7.0:** Если вы включили источник данных на вкладке «Объекты» со значением «включено», определение цены еще не выбрано. В этом случае источник отображается на вкладке «Проблемы» со значением «Определение цены не выбрано». Выберите определение цены в подробных сведениях об источнике и нажмите «⚡ Применить» ([#1286](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1286)).

**До версии 0.6.x:** Проверьте те же точки в диалоговом окне в поле данных и в журнале. Начиная с версии 0.6.0, диалоговое окно не сохраняет данные без указания цены и единицы измерения. Старый совет о необходимости ввода начального значения больше не актуален: SourceAnalytix автоматически заполняет пустые начальные значения при первом запуске.

## Высокая загрузка ЦП и памяти, а также слишком большой объем вывода логов
<!-- abschnitt: prio=B; гевичт=8; readme = отсутствует; кластер = журналы-установка-14, журналы-установка-13; Features=интеграция-мощности-источника,средняя-мощность-источника,подписка-другой-объект,блок-расчет-расчета,сводка-запуска журнала --> <!-- необходимо написать: Anzahl Datenpunkte, Log-Level. -->

**Вкратце:** SourceAnalytix выполняет вычисления для каждого нового значения каждого источника. Источники, которые отправляют данные очень часто, создают наибольшую нагрузку. До версии 0.6.1 постоянная переинициализация добавляла постоянную нагрузку, которая исправлена в версии 0.6.2. Для уменьшения количества логов установите уровень логирования "warn".

<!-- quelle: code=main.js:2527-2566; issue=#1233; pr=#1238; interview=5 -->

### Снижение нагрузки
- **Обновление:** До версии 0.6.1 SourceAnalytix перестраивал источник данных всякий раз, когда изменялся объект активного источника, даже если на самом деле ничего не изменилось. **Начиная с версии 0.6.2**, он игнорирует такие изменения и записывает объекты только тогда, когда изменяется их определение ([#1233](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1233)).
- **Отправляйте данные реже:** Каждое обновление исходной точки данных запускает вычисления. Если устройство отправляет данные каждую секунду, по возможности установите более длительный интервал в адаптере источника.
- **Показания счетчика вместо мощности:** Если ваше устройство отображает показания счетчика (кВт·ч), используйте их вместо мощности (Вт). См. [Какой показатель мне активировать: счетчик (кВт·ч) или мощность (Вт)?](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/02.erster-zaehler.md#datapoint-enable-meter-kwh-power).
- **Только необходимые источники:** Начиная с версии 0.7.0, вы можете отключить ненужные источники с помощью кнопки "Деактивировать" для соответствующего источника. Данные сохраняются.

<!-- quelle: code=main.js:2144-2190@v0.6.1; код = main.js: 2394-2415; код = main.js: 2527-2566; код=src-admin/src/i18n/de.json:8-10; проблема = # 1233; пр=#1238; форум=411981; форум = 294377; проблема=#109 -->

### Меньше вывода логов
Новый экземпляр запускается с уровнем логирования "info". Затем SourceAnalytix записывает несколько строк для каждого источника при запуске. Для длительной работы рекомендуется уровень "warn": вы по-прежнему будете видеть предупреждения и ошибки. Уровень логирования устанавливается на вкладке "Экземпляры" для экземпляра SourceAnalytix (в экспертном режиме).

<!-- quelle: code=io-package.json:145; code=main.js:165-181; interview=5; forum=406676 -->

**Вплоть до версии 0.6.1** источник с отключенным обнаружением сброса записывает `Cumulative reading for … decreased while reset detection is disabled` на информационном уровне для каждого падающего значения. **Начиная с версии 0.6.2**, это сообщение появляется только в журнале отладки ([#1262](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1262)).

<!-- quelle: code=main.js:3073@v0.6.1; code=main.js:3601; issue=#1262 -->

Если другой адаптер заполняет лог, например, адаптер истории, то помогает именно его уровень логирования, а не уровень SourceAnalytix.

<!-- quelle: forum=382814 -->

**См. также:** [[Предупреждение об ограничении количества объектов](#object-limit-warning-5000) · [Известные ошибки в более старых версиях]](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/04.fehlerbehebung/02.falsche-werte-und-bekannte-fehler.md#known-bugs-older-versions-please)

## Проблемы с установкой и отображением административной панели
<!-- abschnitt: prio=B; гевичт=8; readme = отсутствует; кластер = обновление-миграция-другое-24, журналы-установка-25, настройка-ui-10, настройка-ui-28; Features=req-admin-ui-i18n,req-versions --> <!-- необходимо написать: GitHub-Installation 404/422, адаптер для новой установки не отображается, "nicht gepflegt", Multihost. -->

**Вкратце:** Установите SourceAnalytix из репозитория "latest" (бета-версия), а не напрямую с GitHub. Начиная с версии 0.7.0, требуется Admin 8.0.0 или новее, js-controller 6.0.11 и Node.js 22. Если после установки в Admin чего-то не хватает, загрузите файлы адаптера еще раз в консоли с помощью `iobroker upload sourceanalytix`.

<!-- quelle: interview=21; code=io-package.json:161-170; code=package.json:12; forum=311540; issue=#870 -->

Инструкции по установке см. в разделе [Установка и создание экземпляра](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/01.installation.md#install-sourceanalytix-create-instance).

### Установка из GitHub завершается ошибкой 404 или 422
Это проблема с установкой ioBroker, а не с SourceAnalytix. В описанных случаях помогло обновление js-controller. Установка из "последней" версии проще.

<!-- quelle: forum=635126; forum=656505; interview=21 -->

### В административной панели отсутствуют настройки SourceAnalytix или его параметры.
- **В разделе "Экземпляры" нет записи:** После установки необходимо создать экземпляр.
- ** `Не удается загрузить jsonConfig из sourceanalytix: он не существует` или `index_m.html не найден`:** Администрация не может найти файлы страницы настроек. Запустите `iobroker upload sourceanalytix` и перезагрузите страницу администратора. В версиях до v0.4.9 эта страница полностью отсутствовала, и помогает только обновление.
- **Вкладки «Обзор» и «Проблемы» пусты (начиная с версии 0.7.0):** Если отображается сообщение «Для обзора требуется запущенный экземпляр» или «Не удалось загрузить источники», запустите экземпляр и нажмите «Повторить попытку». Пока экземпляр остановлен, действия заблокированы. Вы по-прежнему можете изменять и сохранять настройки.

### "Не поддерживается" и значки разных размеров
Метка «не поддерживается» зависит от репозитория, из которого вы устанавливали программу. При установке из GitHub эта информация отсутствует. Значки папок разных размеров - это эффект отображения административной панели в браузере на телефоне. Ни то, ни другое не влияет на работу SourceAnalytix.

Для работы SourceAnalytix требуется Admin, начиная с версии 0.7.0 и выше (версии 8.0.0 и новее). Если хост сообщает «admin не найден» при запуске или во время установки, установите или обновите Admin. В описанном случае Admin отсутствовал на хосте, где должен был работать экземпляр.

## Полночь: сбой или переход на следующий день в неподходящее время
<!-- abschnitt: prio=B; гевичт=5; readme = отсутствует; кластер = журналы-установка-17, периоды-28; Features=rollover-midnight-cron,rollover-hour-safety-check,rollover-missed-recovery-start,rollover-recovery- periods-button --> <!-- muss beantworten: ENOENT-Fehler, Zeitumstellung. -->

**Вкратце:** Перенос периода происходит в 0:00 по системному времени машины или контейнера, на котором работает ioBroker. Сбой с ошибкой `ENOENT` в полночь происходит из-за js-controller, а не из SourceAnalytix. SourceAnalytix восстанавливает пропущенный перенос самостоятельно. Начиная с версии 0.7.0, вы также можете восстановить его с помощью кнопки "Восстановить" на вкладке "Проблемы".

<!-- quelle: code=main.js:3014; code=main.js:3025-3033; code=lib/source-overview.js:172-174; interview=13b; forum=892050; forum=965788 -->

### Сбой с ENOENT в полночь
В полночь js-контроллер выполняет ротацию лог-файла. Если в этот момент файл отсутствует, адаптер может завершиться с ошибкой `ENOENT`. SourceAnalytix не может это предотвратить. Важно, чтобы пропущенная ротация была восстановлена.

<!-- quelle: forum=892050; forum=965788 -->

### Как SourceAnalytix восстанавливает состояние после переполнения буфера
- При запуске SourceAnalytix проверяет каждый источник и немедленно восстанавливает пропущенный цикл обновления.
- Во время работы адаптер также каждый час проверяет, не пропущено ли переключение на следующую передачу.
- **Начиная с версии 0.7.0**, пропущенная смена периода отображается на вкладке «Проблемы» как «Пропущена смена периода». Кнопка «Восстановить» восстанавливает ее для этого источника. Действие «Восстановить периоды» для источника делает то же самое.
- Во всех версиях, начиная с v0.5.5, это также можно сделать с помощью состояния кнопки `sourceanalytix.0.info.recoverPeriods`.

<!-- quelle: code=main.js:2324-2325; code=main.js:3025-3033; code=lib/source-overview.js:172-174; code=src-admin/src/SourcesApp.tsx:463-466; code=src-admin/src/i18n/de.json:17-19; code=src-admin/src/i18n/de.json:115; code=src-admin/src/i18n/de.json:209; code=main.js:3154-3171; code=README.md:98 -->

В логе отображается `Processing calendar rollover for <datapoint>: {…}`. Подробнее см. [ioBroker был отключен после полуночи.](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/05.betrieb-und-wartung.md#iobroker-was-down-midnight-recover).

<!-- quelle: code=main.js:2771 -->

**Начиная с версии 0.6.2:** Если ioBroker отключался после полуночи, SourceAnalytix распределял потребление данных за период между двумя днями по времени. До версии 0.6.1 все данные переносились на новый день ([#1260](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1260)).

<!-- quelle: issue=#1260; pr=#1274; code=main.js:2867-2895 -->

### Перенос дня происходит в неподходящее время
У SourceAnalytix нет собственного часового пояса. Смена часового пояса происходит в соответствии с часовым поясом процесса, в котором работает ioBroker. Например, если контейнер Docker настроен на UTC, то смена часового пояса происходит в 1:00 или 2:00 по немецкому времени. Установите правильный часовой пояс машины или контейнера, например, для Docker с помощью переменной среды `TZ=Europe/Berlin`, и перезапустите контейнер.

<!-- quelle: code=main.js:3014; interview=13b; forum=516634; issue=#490 -->

## Предупреждение об ограничении количества объектов (5000)
<!-- abschnitt: prio=B; гевичт=3; readme = отсутствует; кластер = журналы-установка-18, обновление-миграция-другое-15; Features=output-tree-layout,other-object-subscription,year-statisticsarchive --> <!-- необходимо написать: js-controller-Warnung und Anheben. -->

**Вкратце:** Предупреждение исходит от js-controller, а не от SourceAnalytix. Сам адаптер не имеет ограничений по количеству объектов. Каждый активный источник создает свою собственную папку со множеством состояний. Сначала проверьте, какие параметры и источники вам нужны, и увеличивайте лимит только в том случае, если это количество вас устраивает.

<!-- quelle: forum=1343567; forum=1313361; code=main.js:2216-2245 -->

### Меньше объектов
- В настройках экземпляра в разделе «Основные настройки» разделы «Статистика за год» («Недели», «Месяцы», «Кварталы») и «Текущий год» («День недели», «Недели», «Месяцы», «Кварталы», «Предыдущий период») определяют, какие состояния получает каждый источник. Если отключить какой-либо параметр, SourceAnalytix удалит соответствующие состояния.
- Начиная с версии 0.7.0, вы можете удалить ненужные источники с помощью действия «Удалить данные», включая папку и все годы.
- Вы можете спокойно удалить старые папки с годом и неделей.

<!-- quelle: code=admin/jsonConfig.json:195-295; code=admin/i18n/de.json:17; code=admin/i18n/de.json:33; code=admin/i18n/de.json:40; code=admin/i18n/de.json:52; code=admin/i18n/de.json:62; code=admin/i18n/de.json:81-84; code=main.js:2216-2245; code=CHANGELOG_OLD.md:12; code=src-admin/src/i18n/de.json:11-13; issue=#1265; interview=8 -->

> [!ВНИМАНИЕ] > Функция "Удалить данные" навсегда удаляет папку источника со всеми значениями и годами. Если вы хотите только приостановить работу, используйте функцию "Деактивировать".

<!-- quelle: code=src-admin/src/i18n/de.json:11-13; code=src-admin/src/i18n/de.json:73; issue=#1265 -->

### Повышение лимита
Ограничение относится к js-контроллеру. В описанном случае его можно было бы повысить в экспертном режиме для объекта экземпляра (`system.adapter.sourceanalytix.0`).

## В истории адаптера источника отображаются 0 или старые значения
<!-- abschnitt: prio=B; гевичт=2; readme = отсутствует; кластер = журналы-установка-22, журналы-установка-23; Features=source-enable,source-cumulative-meter,output-tree-layout --> <!-- необходимо написать: Wechselwirkung mit Quell-Adapter und History. -->

**Вкратце:** SourceAnalytix только считывает заданную вами точку данных в качестве источника и никогда не записывает в неё значение. Если SourceAnalytix показывает 0 или старые значения, это обычно означает, что точка данных источника больше ничего не получает. Нули в истории точки данных источника поступают от адаптера источника или от скрипта.

<!-- quelle: code=main.js:2339; code=main.js:2527-2566; forum=1337092; forum=511730 -->

### Адаптер источника переименовал свои точки данных
Если адаптер переименовывает свои точки данных после обновления, значения поступают в новых точках данных. SourceAnalytix продолжает отслеживать старые точки данных, и его значения остаются на прежнем уровне.

1. В настройках экземпляра откройте источник и установите флажок «Последнее обновление».
2. Если старая точка данных удалена, то начиная с версии 0.7.0 источник отображается на вкладке «Проблемы» с пометкой «Точка данных больше не существует». Кнопка «Деактивировать» останавливает источник, и данные сохраняются.
3. Настройте новую точку данных как новый источник с помощью кнопки "Добавить источник" и перенесите показания счетчика с помощью кнопки "Выровнять показания счетчика".
4. Обновите ссылки в VIS или скриптах на новую папку. Старая папка останется в виде архива.

Планируется действие "Переключить точку данных", которое переносит данные в новую точку данных ([#1271](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1271)).

<!-- quelle: issue=#1271; code=src-admin/src/i18n/de.json:23-25; code=src-admin/src/i18n/de.json:199 -->

### Нули в истории исходной точки данных
SourceAnalytix записывает значения только в свою собственную папку `sourceanalytix.0.<device>`. В объекте исходной точки данных он изменяет только свои собственные настройки, например, смещение, но никогда не значение. Таким образом, 0 в истории исходной точки данных записывается другим адаптером или скриптом.
