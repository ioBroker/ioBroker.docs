## Описание

Адаптер ioBroker.poolcontrol используется для управления, мониторинга и анализа систем пулов.

Она обеспечивает автоматизацию работы насосов, систем отопления, управления солнечными и фотоэлектрическими системами, а также мониторинг, диагностику, химический анализ и оценку энергоэффективности.

## Функции

### Управление и автоматизация

- **Управление насосом**
  - Режимы работы: Автоматический, Автоматический (PV), Ручной, Таймер, Выкл.
  - Обнаружение ошибок (отсутствие потребления энергии, питание при выключенном состоянии, перегрузка)
  - Функции безопасности (защита от замерзания, защита от перегрева)
  - Приоритетное владение и координация действий помощников
  - Рекомендации по мощности насосов с регулируемой скоростью вращения
  - Функции обучения для анализа поведения мощности и потока (`pump.learning.*` )

- **Контроль времени**
  - До 3 свободно настраиваемых недельных временных интервалов
  - Постоянные значения конфигурации
  - Защита от перезаписи во время обновлений

- **Солнечный контроль**
  - Пороги включения/выключения коллектора с гистерезисом
  - Изменение параметров поверхности сбора данных в реальном времени для панелей мониторинга и скриптов.
  - Порог срабатывания предупреждения коллектора
  - Дополнительный голосовой вывод для предупреждений.
  - Логика автоматического сброса

- **Солнечная расширенная**
  - Раздельное управление внешними солнечными актуаторами
  - Пороги включения/выключения Delta
  - Актуальные значения пула сборщиков данных для панелей мониторинга и скриптов.
  - Максимально допустимые температуры воды в бассейне
  - Диагностические и причинные состояния
  - Логика приоритетов и блоков
  - Раздел «Статус»`solar.extended.*`
  - Изменения во время выполнения`solar.extended.pool_temperature_source` применяются автоматически, поскольку Solar Extended использует циклический интервал проверки, расчеты, логику управления и`solar.extended.collector_pool_reference_delta` Обновление может занять до 60 секунд.

- **Управление фотоэлектрическими системами**
  - Управление насосом на основе избытка солнечной энергии и потребления домохозяйства.
  - Начните логику с использованием настраиваемых дополнительных полей.
  - Возможен дополнительный выезд самолета в облачную погоду.
  - Игнорировать режим при достижении целевого уровня циркуляции.
  - Поддерживает внешние идентификаторы энергетических объектов.
  - Режим работы насоса:`Automatic (PV)`

- **Управление отоплением/тепловым насосом**
  - Автоматическое управление нагревательным элементом или тепловым насосом
  - Настраиваемые целевые и безопасные температуры
  - Дополнительный предпусковой и перепускной режимы насоса (опционально)
  - Защита прав собственности
  - Логика блокировки технического обслуживания
  - Поддерживает переключаемые выходы и логические состояния.
  - Внутреннее состояние и диагностика в рамках`heat.*`
  - Никакой химии или солнечной логики.

- **Дополнительные исполнительные механизмы**
  - Управление освещением
  - Дополнительные насосы
  - Устройства с последующим насосом
  - Автоматическое включение/выключение в зависимости от режима работы насоса.
  - Проверка внешних целевых состояний
  - Подходит для УФ-систем, водных объектов и вспомогательных систем.

### Мониторинг и диагностика

- **Управление температурой**
  - До 6 датчиков:
    - поверхность
    - земля / дно
    - поток
    - возвращаться
    - коллекционер
    - внешняя температура
  - Минимальные/максимальные значения за сутки
  - Почасовые изменения
  - Разница температур
  - Отслеживание последнего действительного значения
  - Мониторинг и диагностика источников загрязнения
  - Логика восстановления для отсутствующих обновлений
  - оценка состояния источника

- **Время работы и распространение**
  - Счетчики времени выполнения (за сегодня / всего)
  - Расчет кровообращения и оставшегося объема
  - Самовосстановление во время выполнения
  - система напоминания о обратной промывке
  - Отслеживание последнего обратного потока
  - Автоматический сброс после завершения обратной промывки
  - Интеграция фотоэлектрических систем для достижения целевых показателей циркуляции.

- **Интеграция датчика давления**
  - Измерение давления в реальном времени
  - Анализ тенденций
  - Средние значения обучения
  - Самообучающиеся диапазоны минимального/максимального значений
  - Диагностические состояния
  - История и оценка давления
  - Поддержка внешних датчиков и блока управления давлением PoolControl PressureBox.
  - Информация предоставлена исключительно в ознакомительных целях (автоматическое управление отсутствует).

- **SystemCheck**
  - Область диагностики и отладки
  - Мониторинг отдельных подсистем
  - Внутренний журнал отладки
  - Ручная очистка журнала
  - Предназначен для анализа и устранения неполадок.

### Аналитика и выводы

- **Система статистики**
  - Ежедневная / еженедельная / ежемесячная статистика
  - Расчеты минимума/максимума/среднего значения
  - Оценка во время выполнения
  - Постоянные состояния
  - HTML и JSON сводки

- **Аналитические материалы о солнечной энергии**
  - Анализ времени работы солнечных батарей
  - Расчеты эффективности
  - Результаты диагностики
  - Ежедневный журнал
  - HTML / JSON / текстовый вывод
  - Информация предоставлена исключительно в ознакомительных целях (без контрольной группы).

- **Анализ фотоэлектрической отрасли**
  - Анализ времени выполнения
  - Оценка энергоэффективности
  - Расчеты экономии
  - Статистика запусков и эксплуатации
  - HTML/JSON сводки

- **Информация о бассейнах**
  - Анализ пула на основе правил в разделе analytics.insights.pool.\*
  - Считывает только существующие данные PoolControl.
  - Отсутствует автоматическое управление, дозирование, переключение насосов или исполнительных механизмов.
  - Отключено по умолчанию
  - Дополнительная функция передачи сводной информации в speech.queue.
  - HTML / JSON / текстовый вывод

- **Выходные данные, готовые к визуализации**
  - Вывод структурированного текста
  - HTML-вывод
  - JSON-сводки
  - Подходит для панелей мониторинга VIS / VIS2 / дашбордов

### Химия и искусственный интеллект

- **Анализ химического состава воды**

  **pH**

  - Ручные или внешние источники
  - Логика определения местоположения измерения
  - Логика стабилизации
  - Поддержка ручного смешивания
  - Автоматическая дозировка отсутствует.

  **ТДС**

  - Ручные или внешние источники
  - Оценка трендов (24 ч / 7 дн / 30 дн.)
  - Референтные значения
  - Логика определения местоположения измерения
  - HTML / JSON / текстовый вывод

  **ОВП / Редокс**

  - Оценка ОРП
  - Поддержка эталонного значения pH
  - Только для ознакомления.
  - Контроль за содержанием хлора отсутствует.
  - Автоматическая дозировка отсутствует.

  **Двухуровневая ограниченная история химии**

  - Существующие данные в файле samples\_json сохраняют краткосрочную историю за 7 дней и 15 минут: максимум 672 образца, каждый размером 64 КБ.
  - Новые внутренние состояния daily\_json сохраняют компактные агрегированные данные по дням локального календаря с указанием min/max/avg/last/count: максимум 32 записи и 8 КБ каждая.
  - Для трендов за 24 часа и 7 дней используется samples\_json; для трендов за 30 дней используется последнее значение соответствующего дневного агрегата.
  - Существующие данные о трендах за 24, 7 и 30 дней, а также текстовые/HTML/JSON отчеты сохраняют свой API и смысл.
  - Ежедневные сводки дополняют, но не заменяют исходные исторические данные; достоверные устаревшие данные нормализуются во время миграции, а JSON-файлы большого размера отклоняются перед анализом.
  - Исходные данные о долгосрочных сделках хранятся в специальной базе данных ioBroker, содержащей историю и временные ряды.
  - Если слишком большой файл states.jsonl уже препятствует запуску js-controller, его необходимо исправить извне, прежде чем PoolControl сможет запуститься.

  **Химические инструменты**

  - Калькулятор pH+
  - Калькулятор pH минус
  - Калькулятор соли
  - Вспомогательные средства для ручных вычислений
  - Поддержка предварительного заполнения объема бассейна
  - Дополнительное ручное изменение значения
  - Результаты анализа отображаются с проверкой достоверности и обработкой ошибок. Автоматическое дозирование химических реагентов не предусмотрено.
  - Только для ознакомления.

- **Система искусственного интеллекта**
  - Прогноз погоды (Open-Meteo)
  - Рекомендации по бассейнам
  - Ежедневный обзор
  - Отчет за выходные
  - Прогноз погоды на завтра
  - Дополнительные функции вывода речи
  - Отслеживание дублирующегося контекста

- **Помощь по химии**
  - Интерактивная помощь в химии
  - Типичный выбор проблемы бассейна
  - Объяснения причин и решений
  - Автоматическая дозировка отсутствует.
  - Управление устройством отсутствует

- **Речевые выходы**
  - поддержка Alexa
  - Поддержка в Telegram
  - Уведомления о работе насоса, предупреждения и показания температуры.

## Конфигурация

Настройка осуществляется через вкладки в административном интерфейсе:

- **Общие сведения** → Название бассейна, размер бассейна, минимальный объем циркуляции воды
- **Насос** → Мощность насоса, ограничения мощности, функции безопасности
- **Температуры** → Выбор и идентификаторы объектов датчиков
- **Управление солнечной энергией** → Пороги включения/выключения, гистерезис, порог предупреждения
- **Контроль времени** → Временные окна для работы насоса
- **Голосовой вывод** → Активация, интеграция с Alexa/Telegram
- **Потребление и затраты** → внешний счетчик кВт·ч, цена на электроэнергию

## Планируемые расширения

- Расширенный анализ эффективности фотоэлектрических и солнечных систем (расчет коэффициента полезного действия, ежедневная выгода, учет погодных условий)

- Расширение на основе ИИ и голосового помощника (ежедневный отчет по бассейну, советы, голосовые команды)

## Changelog
### 1.4.5 (2026-08-11)

- Fixed a conflict between Auto-PV and Extended Solar control.
- Extended Solar could incorrectly switch off the main pump while the pump was being controlled by Auto-PV and sufficient PV surplus was still available.
- Extended Solar now only writes to the main pump switch when `pump.mode = auto`.
- Auto-PV operation is no longer interrupted by the Extended Solar control cycle.
- Existing Extended Solar pump control in normal `auto` mode remains unchanged.

### 1.4.4 (2026-07-31)

- Fixed a race condition in the Auto-PV helper that could occur during rapid updates of PV generation and household power values.
- Added a short debounce for PV and household power events to ensure calculations always use the latest matching values.
- Replaced the previous throttle mechanism with a serialized recalculation workflow to prevent overlapping asynchronous recalculations.
- Added an internal "latest run wins" protection so outdated recalculations can no longer overwrite newer results or trigger outdated pump decisions.
- The existing Auto-PV holding logic introduced in v1.4.1 remains unchanged.
- `photovoltaic.power_surplus_w` continues to represent the real remaining PV surplus (`PV generation - household consumption`).
- Existing Auto-PV features such as afterrun, circulation handling, solar overheating protection and controlHelper priority remain fully compatible.

### 1.4.3 (2026-07-25)

- Fixed restoration of the previous pump mode after maintenance mode and automatic circulation catch-up runs.
- Maintenance mode now restores the previous valid user mode even after an adapter restart.
- Maintenance mode and automatic catch-up runs now use separate restore values and can no longer overwrite each other.
- Invalid values such as `null`, empty values, or internal helper modes are no longer written back to `pump.mode`.
- Automatic circulation catch-up runs no longer start while maintenance mode is active.
- Starting maintenance mode during an active catch-up run now stops the catch-up process cleanly before maintenance takes control.
- Added validation to the pump-mode restoration after backwashing.
- The existing overload protection remains unchanged and continues to switch `pump.mode` to `off` when an overload is detected.

### 1.4.2 (2026-07-01)

- Fixed monthly temperature statistics reset scheduling
  - Monthly reset no longer uses long timeouts above the Node.js/ioBroker limit
  - Added persistent monthly period tracking
  - Missed month changes after adapter downtime are detected safely
  - Monthly reset is now checked daily and executed only once per period

- Improved solar logbook logging
  - Oversized solar logbook entries are now logged as debug instead of warning
  - This avoids unnecessary warning noise for non-critical diagnostic information

### 1.4.1 (2026-06-30)

- Fixed Auto-PV holding logic for already running pumps.
- When Auto-PV already controls the pump, the current pump power is now considered for the holding decision.
- This prevents a running pump from triggering its own Auto-PV afterrun/stop cycle after startup.
- The displayed PV surplus (`photovoltaic.power_surplus_w`) remains the real remaining surplus and is not artificially adjusted.
