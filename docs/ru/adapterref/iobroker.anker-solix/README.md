# ioBroker.anker-solix

![Версия NPM](https://img.shields.io/npm/v/iobroker.anker-solix.svg)

адаптер ioBroker для **Анкер Соликс** Системы электропитания (солнечная батарея, интеллектуальный счетчик, источник бесперебойного питания, зарядное устройство для электромобилей и многое другое). Основана на интеграции с Home Assistant. [thomluther/ha-anker-solix](https://github.com/thomluther/ha-anker-solix) и использует тот же неофициальный **соликсапи** Библиотека Python.

>
> | ОС          | Статус                                                                                |
> | ----------- | ------------------------------------------------------------------------------------- |
> | **Linux**   | Основная производственная цель — **CI-протестировано** (Docker, NAS, Raspberry Pi, …) |

небольшой **мост Python** (Постоянный демон, как в Home Assistant) опрашивает облако Anker и, при необходимости, MQTT, а затем предоставляет значения в виде состояний ioBroker. Дополнительные группы сущностей (начиная с версии 0.9.0) повторяют область действия Home Assistant: только **Основной** Эта функция включена по умолчанию для ограничения нагрузки на API.

## Отказ от ответственности и условия использования

Этот адаптер **нет** аффилировано с Anker. Торговые марки и названия продуктов принадлежат их соответствующим владельцам.

Адаптер использует **неофициальный** Библиотека Python для взаимодействия с Anker Power **облачный API** (аналогично мобильному приложению). Этот API может измениться или перестать работать в любой момент. Неправильные настройки могут повлиять на устройства; пользователь принимает на себя эти риски, активируя экземпляр.**Счет** (вкладка). В будущих обновлениях адаптера могут быть расширены возможности мониторинга или управления.

## Как работает этот адаптер в ioBroker

| Слой                                 | Роль                                                                                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| **Адаптер Node.js**                  | Конфигурация экземпляра, планирование, состояния ioBroker, очередь управления                         |
| **мост Python** (`python/bridge.py`) | Длительная сессия: API + опционально MQTT (в стиле Home Assistant)                                    |
| **соликсапи**                        | Вход в облако, сайты/устройства, статистика энергопотребления, карта MQTT.                            |
| **authcache**                        | `iobroker-data/<instance>/authcache/<email>.json` — используется повторно после успешного входа в API |

Интервал опроса должен быть **60–180 с** (Та же рекомендация, что и для HA). Список объектов обновляется каждый цикл; данные об устройствах/объектах и данные об энергопотреблении обновляются с меньшей периодичностью.`deviceDetailMultiplier`(по умолчанию — каждый 10-й опрос).

> **Важный:** Для облачных устройств используется API Anker. **обязательный** (Одного протокола MQTT недостаточно для получения полных системных данных). Исключение: **Только Modbus** В этом режиме используется локальный TCP-протокол, и учетные данные облака не требуются. Данный адаптер не требует... **нет** заменить локальные интеграции BLE — см. [Дополнительные ресурсы](#credits--further-reading).

## Требования и установка

- ioBroker **js-controller >= 6**, **admin >= 7.6**
- **Node.js >= 22**
- **Python 3.12+** на хосте ioBroker (рекомендуется / требуется вышестоящим сервером):
  - **Linux:** `python3-venv` + `python3-pip` (Debian/Ubuntu) — основная целевая платформа для производства
  - **Окна:** Python 3.12+ с сайта python.org или `py -3.12`; установщик адаптера обрабатывает виртуальные среды и **`tzdata`**
  - **macOS:** **не поддерживается** (Автоматическая установка Python не проверена)
  - **Исключение (максимальные усилия):** Linux **контейнеры Docker** на основе **Debian 12 Bookworm** (например `buanet/iobroker:latest-v11`) может использовать систему **Python 3.11** Когда версия 3.12 недоступна через pt. Для работы Bookworm без операционной системы, других дистрибутивов и контейнеров, не являющихся Bookworm, по-прежнему требуется... **3.12+**&#x420;екомендуется устанавливать Python 3.12+ в постоянный путь и настраивать параметры. **pythonPath** по возможности.

Зависимости Python устанавливаются в папку адаптера (`python/.venv` или `python/site-packages`Начиная с версии 0.2.0: автоматически при запуске (**Параметры** → `autoInstallPython`) или кнопка **Установите зависимости Python.**.

Установка через ioBroker (рекомендуется):

```bash
iobroker install anker-solix
```

После внесения изменений в файлы адаптера локально, загрузите экземпляр:

```bash
iobroker upload anker-solix
```

**Многохостовый режим:** использовать `--host "PC(SmartHome)"` Если имя содержит специальные символы, оно должно быть заключено в кавычки.

Удалите устаревшую символическую ссылку, если она присутствует: `rm -f /opt/iobroker/node_modules/iobroker.AnkerSolix`

Ручная настройка Python (при необходимости):

```bash
cd node_modules/iobroker.anker-solix
python3 -m venv python/.venv && python/.venv/bin/pip install -r python/requirements.txt
```

### Локальный Modbus (опционально)

Более новые устройства Anker (Solarbank 4 / Max AC / Max, Smart Meter Gen 2, Smart Plug Gen 2, **Соликс X1 ХЕС**, **Интеллектуальное зарядное устройство для электромобилей V1**) можно опросить **локально через Modbus TCP** (порт 502). Карты регистрации прилагаются. [Официальные протоколы Modbus от Anker](https://support.ankersolix.com/) и проверенные сообществом сопоставления X1 ([анкер-х1-ха](https://github.com/afewyards/anker-x1-ha)).

1. Давать возможность **Модбус TCP** в приложении Anker (Solarbank: система / сторонний контроль; **X1**: Профессиональное приложение → Настройки связи; **Зарядное устройство V1 для электромобилей**: Настройки → Интеграции).
2. Администрирование адаптера → **Modbus (локальный)** → Активируйте канал, добавьте IP-адреса каждого устройства.
3. Необязательно: включить **Только Modbus (без облачного сервиса)** Если вы не хотите использовать вход в облако Anker, то Python, учетные данные и условия использования не требуются; экземпляр доступен. **зеленый** Когда подключено хотя бы одно устройство Modbus (в противном случае отображается желтый цвет).
4. Датчики: `anker-solix.0.modbus.<name>.sensors.*` (SOC, PV, сеть, батарея, SN, …).
5. Элементы управления: `anker-solix.0.modbus.<name>.control.*`
   - Солнечная батарея: `operating_mode`Пределы SOC, `backup_soc_enable`, `battery_power_direction` + `battery_power_setpoint` (установленное значение только в **третий\_сторонний\_контроль**(Сначала задайте направление; заряд обозначается как отрицательные ватты).
   - Умная розетка второго поколения: `power_switch`.
   - Умный счетчик второго поколения: только для чтения.

Без **Только Modbus**Для старых устройств и MQTT по-прежнему используется облачный вход в систему. Solarbank 3 — это... **нет** в официальных картах Modbus от Anker. Если другой клиент Modbus только что запросил устройство, первый запрос может получить **В соединении отказано** до истечения периода ожидания этого клиента; следующий интервал опроса повторяется.

## Конфигурация

1. Создать экземпляр: `iobroker add anker-solix`
2. **Счет:** Электронная почта Anker, пароль, код страны (например) `DE`) — **сохранить после ввода пароля**
3. **Счет:** Разрешить использование неофициального API (поставьте галочку внизу вкладки)
4. **Параметры:** Интервал опроса 60–180 с, **MQTT** при необходимости, `deviceDetailMultiplier` (По умолчанию в Home Assistant: 10)
5. **Устройства:** **Нагрузочные устройства**необязательный фильтр по идентификатору сайта/серийному номеру устройства
6. **Объекты** (v0.9.0+): включить необязательные группы; только **Основной** включено по умолчанию → **перезагрузить адаптер** после изменений

Делать **нет** использовать **Очистить кэш входа в Anker** Если только вам не потребуется преднамеренный повторный вход в систему (неверная учетная запись, поврежденный файл). Очистка принудительно выполняет новый вход в облако и часто запускает капчу на серверах — см. [Поиск неисправностей](#troubleshooting-login--poll).

## Кэш учетных записей и входа в Anker

После **первый успешный вход через API**Адаптер хранит токены в:

`iobroker-data/anker-solix.0/authcache/<your-email>.json`

(Имя файла должно совпадать с адресом электронной почты в файле) **Счет** точно.)

С момента появления приложения Anker **3.10** (середина 2025 года), один аккаунт часто можно использовать на **несколько клиентов параллельно** (приложение + ioBroker + высокая доступность). Более старые документы о «только одном токене» сегодня менее критичны, но... **не удалось повторно войти в систему** ioBroker по-прежнему не может обновить файл, если Anker возвращает капчу.

**Общие/пользовательские аккаунты:** В семейном аккаунте может отображаться меньше информации об использовании API, чем в аккаунте владельца (аналогично Home Assistant).

Дополнительные примечания к учетной записи: [HA INFO.md – счета](https://github.com/thomluther/ha-anker-solix/blob/main/INFO.md).

## Ограничения

- **Неофициальный API** — Документация отсутствует; конечные точки могут измениться в любое время.
- **Облачные технологии ЕС и COM** - неправильный **страна** В настройках → вход в систему работает, но **нет систем/устройств**Не переключайте страну после сопряжения устройств.
- **Устаревшие облачные данные** Если Wi-Fi устройства отключен, используйте индикаторы подключения к облаку/MQTT, если они включены.
- **MQTT** Обновления зависят от цикла публикации устройства; некоторые значения доступны только при наличии обновления. **триггер в реальном времени** (при высокой загруженности сети, если круглосуточно).
- **Автономные устройства** (Блок питания, зарядное устройство, кулер не входят в состав системы электропитания) **Практически отсутствуют данные об энергопотреблении API.** — Может потребоваться протокол MQTT ([ограничения HA](https://github.com/thomluther/ha-anker-solix#limitations)).
- **Динамический тариф** Помимо Nordpool: данные о прогнозах/ценах могут быть неверными или доступны только для чтения.
- **Капча (100032)** при прямом входе через API с VPS/VPN/дата-центра — см. [Поиск неисправностей](#troubleshooting-login--poll). Копия `authcache` Если ioBroker не может войти в систему, используйте Home Assistant или другую работающую конфигурацию.

Для добавления устройств: экспортируйте анонимизированные данные через HA. [экспортные системы](https://github.com/thomluther/ha-anker-solix/blob/main/INFO.md#export-systems-action) или [anker-solix-api Export\_system.py](https://github.com/thomluther/anker-solix-api#export_systempy).

## Государственная структура и группы субъектов

Типичные пути (экземпляр) `anker-solix.0`):

- `anker-solix.0.solarbank.<deviceId>.sensors.*` — мощность, уровень заряда батареи и т. д.
- `anker-solix.0.solarbank.<deviceId>.control.*` — возможность записи элементов управления там, где это поддерживается
- `anker-solix.0.<device>.<id>.statistics.*` — суточная суточная потребляемая электроэнергия (включить) **Объекты** → статистика энергии)
- `…statistics.week.*` / `statistics.month.*` / `statistics.year.*` — Итоговые данные за календарную неделю, месяц и год в кВт·ч (отдельные группы объектов; опрос проводится при обновлении подробных данных, а не в каждом цикле)
- **Объединенный объект:** статистика только в `combiner_box.<id>.statistics.*` (не дублируется на `system.*` или каждый `solarbank.*`). **Без сумматора:** за `solarbank.*` (и `smartmeter.*` (для метрик сетки). Запросы API остаются **один раз на сайт**.
- `anker-solix.0.smartmeter.<deviceId>.sensors.*`
- `anker-solix.0.services.*` — экспорт, расписание, обновление (состояния кнопок)
- `anker-solix.0.info.connection`, `anker-solix.0.info.pythonReady`

**Группы сущностей** (Администратор →) **Объекты**): сопоставление с наборами функций высокой доступности — потоки энергии, диагностика, PPS, зарядное устройство для электромобилей, HES, цена объекта, информация об учетной записи и т. д. Отключенные группы исключаются из опросов API для снижения нагрузки.

## Устройства, управляемые по протоколу MQTT

Давать возможность **MQTT** в **Параметры** Когда вам нужны данные в реальном времени или элементы управления, которые не предоставляются облачным API (многие функции PPS/EV/зарядных устройств).

- Дополнительные датчики/элементы управления получаются из MQTT-карт в solixapi (декодируются сообществом для каждой модели).
- **Триггер в реальном времени** и **запрос статуса** Они ведут себя как кнопки Home Assistant — автоматизация их работы в режиме 24/7 увеличивает нагрузку и поддерживает устройства в активном состоянии.[Раздел HA MQTT](https://github.com/thomluther/ha-anker-solix#mqtt-managed-devices)).
- **Гибридное управление** (Резерв SOC станции, ограничения переменного тока, экспорт в сеть в многосистемном режиме) требуется MQTT + API, как в Home Assistant.
- Устройства в **Локальный режим MQTT** (например, E10 за Power Dock) передаются через центральное устройство — см. [Информация о Home Assistant – локальный режим MQTT](https://github.com/thomluther/ha-anker-solix/blob/main/INFO.md#devices-in-mqtt-local-mode).

Расшифровка новых моделей: [Рекомендации MQTT](https://github.com/thomluther/anker-solix-api/discussions/222), инструмент `mqtt_monitor.py` в [anker-solix-api](https://github.com/thomluther/anker-solix-api).

## Специальные примечания к устройству

Сокращено из [README интеграции HA](https://github.com/thomluther/ha-anker-solix)Поведение облачной платформы/MQTT одинаково при использовании solixapi. Локальные примечания Modbus зависят от адаптера.

### Solarbank 4 E5000 Pro / Solarbank Max / Max AC

Облачное решение: тот же путь опроса, что и у других солнечных батарей (API + опционально MQTT). **Ежедневный объем кВтч** (`statistics.daily_*`) извлекается на **подробные опросы** (каждый `deviceDetailMultiplier` циклов (по умолчанию \~10), а не каждую минуту — проверьте журнал. `Daily kWh statistics updated`. **С блоком питания/комбинатором:** значения находятся только ниже `combiner_box.<SN>.statistics.*`не под каждым `solarbank.*`После включения перезагрузите адаптер. **Объекты → Tagesstatistiken**Итоговые данные за неделю/месяц/год публикуются по вечернему расписанию (23:00 / 23:15 / 23:30 Европа/Берлин).

**Локальный Modbus TCP** (Официальные карты): включите Modbus в приложении Anker (Система / Управление сторонними сервисами), затем Администрирование → **Modbus (локальный)**&#x422;ипичные коды моделей включают AE103 (SB4). Штаты: `anker-solix.0.modbus.<name>.sensors.*` и `.control.*` (режим работы, ограничения уровня заряда батареи, заданное значение заряда батареи) **третий\_сторонний\_контроль**). **Только Modbus** Пропускает облачные сервисы/Python; светодиод экземпляра горит зеленым, когда подключено хотя бы одно устройство Modbus.

Если другой Modbus-клиент только что запросил устройство, первый запрос может дать результат... **В соединении отказано** до истечения периода ожидания для этого клиента — при следующем интервале опроса попытка повторится.

### Умный счетчик второго поколения / Умная розетка второго поколения

Облачные объекты аналогичны тем, что используются для других счетчиков/розеток. **Локальный Modbus:** Измерительный прибор второго поколения — это **только для чтения** (мощность/напряжение/ток на фазу). Smart Plug Gen 2 предоставляет следующие возможности `power_switch`Каждому устройству необходим собственный IP-адрес (порт 502).

### Автономные инверторы (МИ80)

Это не полноценная «энергетическая система» для приложений, но облако отслеживает показатели эффективности. API создает **виртуальный сайт**Состояние Wi-Fi инвертора в API часто бывает неверным; состояние подключения к облаку является более надежным показателем. **Не** Изменение ограничений инвертора на постоянной основе (количество циклов аппаратной записи).

### Солнечная батарея 1 (E1600)

Облачные обновления \~каждый **60 с** во время производства/разгрузки; примерно ежечасно в режиме ожидания. **Ошибка в расписании:** Один сеанс API на весь день позволяет установить экспорт на **0 Вт** — Используйте ≥2 слота в приложении, если используете предустановленные параметры вывода. Ежедневная статистика разрядов с середины 2024 года включает пропущенные PV (также неверно в приложении). Мониторинг/управление MQTT из HA v3.4+/3.5+.

### Солнечная батарея 2 + интеллектуальные счетчики

Часто наблюдается облачность в течение определенного интервала. **\~5 минут**Изменения в управлении могут занять до **\~6 минут** должны появиться в датчиках. В общих учетных записях исторически были недоступные объекты (исправление на стороне Anker). Некоторые **ограничение выхода** Пути к API по-прежнему неизвестны.

### Солнечная батарея 2 AC

Тарифные планы, действующие по времени, управляются через соответствующие элементы управления; обновления облачных сервисов могут зависать после интенсивного использования приложений.[HA #211](https://github.com/thomluther/ha-anker-solix/issues/211)).

### Комбинированный SB2 + каскадный SB1

Итоговые данные/статистика в облаке Anker отражают **SB2 только**SB1 частично представляет собой «черный ящик». При ручном управлении SB2 на SB1 устанавливается минимальное расписание — это показывают некоторые элементы управления ioBroker/HA. **недоступно** намеренно. Для корректного расчета энергии заряда/разряда суммируйте **на устройство** Питание от батареи, а не только питание от сети системы ([подробности HA](https://github.com/thomluther/ha-anker-solix#combined-solarbank-2-systems-containing-cascaded-solarbank-1-devices)).

### Солнечная батарея 3

Интеллектуальный режим, динамическое ценообразование, режимы с временными интервалами — часто **только переключатель** через API (предварительно настройте в приложении). Динамическое ценообразование. НДС/комиссии могут быть. **только кэш** Индивидуальные настройки. Прогноз Nordpool наиболее надежен.

### Мультисистема с док-станцией питания

До 4 блоков SB3; общие настройки станции (режим использования, резерв SOC, экспорт в сеть). Управление объединено на **комбинированный / Power Dock** в логике интеграции. Облачные данные могут отставать на начальных этапах развертывания. Многосистемный подход. **ограничение выходной мощности переменного тока** Возможно, эти параметры нельзя изменить через API.

### Управление станцией

Резерв SOC, ограничения PV/AC, экспорт в сеть часто требуют **API + MQTT** (гибрид). Сторонние переключатели, поддерживающие солнечные батареи/электромобили, обычно требуют однократной настройки через приложение — они не доступны для автоматизации.

### PPS / Solarbank PPS (F3000 + американский счетчик)

В США используется автоматизированная система резервного копирования данных на дому; управление осуществляется преимущественно через MQTT.

### Зарядное устройство для электромобилей (V1)

Большинство метрик/элементов управления передаются через MQTT; поддерживаются учетные записи участников. Режимы работы соответствуют конечному автомату в стиле Home Assistant — в ioBroker проверьте доступные параметры управления перед запуском скриптов. Статистика истории сессий не реализована (используйте историю состояний).

### Транспортные средства

Виртуальные устройства на учетную запись EV; создание через адаптер не требуется — обнаружено при обновлении.

### Панель питания и HES (X1)

Ограниченные возможности API; обходное решение использует **В среднем примерно за 5 минут** на основе статистики энергии (**\~80 МБ/день** (при включении) дополнительный трафик на систему). Отключите категории с высокой нагрузкой в **Объекты** при необходимости.

**Локальный Modbus (X1):** включить Modbus TCP в **Anker Solix Professional** приложение, затем Администратор → **Modbus (локальный)** → профиль **Соликс X1 ХЕС** (или автоматическое определение). Штаты в соответствии с `modbus.<name>.sensors.*` и элементы управления режимом работы / заданным уровнем заряда батареи (VPP / режим сторонних производителей). X1 поддерживает **только один клиент Modbus TCP** за раз.

### Интеллектуальное зарядное устройство для электромобилей V1 (локальный Modbus)

При использовании учетной записи Anker сущности Cloud/MQTT остаются доступными. **только для местных жителей** управление, включить Modbus TCP в **Интеграции** в приложении Anker и добавьте профиль **Интеллектуальное зарядное устройство для электромобилей V1**Управление: запуск/остановка зарядки, максимальный ток (6–32 А). До **два** Зарядное устройство поддерживает одновременное подключение нескольких клиентов Modbus.

### Резервное копирование на домашний компьютер (E10, AX170)

Почти **нет** Облачный API для управления энергопотреблением системы; E10 часто **Локальный режим MQTT** через док.

### Другие / автономные устройства

Только в **энергосистема** Для использования полного API требуется MQTT + декодирование сообщества.

## Устранение неполадок при входе в систему / опросе

### Нет `authcache/<email>.json`

Файл создается только после **успешный** Вход через API. Если при каждом входе возвращается капча, скопируйте рабочий файл из... [ха-анкер-соликс](https://github.com/thomluther/ha-anker-solix) (`custom_components/anker_solix/solixapi/authcache/`) в `iobroker-data/anker-solix.0/authcache/`, то же имя файла, что и в **Счет**.

### `(100032) Captcha id empty`

Анкер блокирует некоторые **сервер/VPN** Вход через API. Библиотека не может обработать капчу.

1. Подтвердите вход в приложение в пределах одной локальной сети; правильно. **страна**; VPN на хосте ioBroker отключен.
2. **Не** Очистите кэш при входе в систему, чтобы «исправить» капчу.
3. Копия `authcache` из системы высокой доступности или повторно войдите в систему, когда это позволит облако.
4. После многочисленных неудачных попыток подождите 15–30 минут.
5. Используйте адаптер **≥ 0.9.3** Таким образом, при перезапуске действительный кэш не удаляется.

В журнале указан точный путь к кэшу. **0.9.4+**.

### Ограничения скорости (26161 / 429)

Увеличьте интервал опроса; уменьшите количество включенных **Объекты** группы; адаптер повторяет попытки и может на короткое время переключиться на одноразовый мост.

## Предотвращение ограничений (необязательно)

Вкладка **Abregelungsvermeidung** / **Избегание ограничений**: требует [ioBroker.pvforecast](https://www.iobroker.net/#en/adapters/adapterref/iobroker.pvforecast/README.md) адаптер. (Ранее основано на [ioBroker.solarprognose](https://www.iobroker.net/#en/adapters/adapterref/iobroker.solarprognose/README.md) / solarprognose.de — переключился, потому что **Сайт solarprognose.de закрывается.** (и этот источник данных больше не является жизнеспособным.) Установите **растительная дорожка** (например `pvforecast.0.plants.pv`Значения мощности считываются из `{path}.power.hoursToday.*`. **Разрешение прогноза** (60 / 30 / 15 минут, по умолчанию) **60**) должен соответствовать интервалу, настроенному в pvforecast. **Только элементы управления:** **руководство** режим + **`ac_output_limit`** (Выход/выход переменного тока). **Не** изменить базовые настройки станции (ограничение экспорта сетки, `allow_grid_export`(предварительная настройка домашней нагрузки, ограничение зарядки от сети переменного тока). **До:** `ac_output_limit` = активный PV. **Активно:** `missing_charge_wh`, `max_charge_w` = `missing_charge_wh` ÷ `remaining_hours`, `export_w` = `live_pv_w` − `max_charge_w`, `ac_output_limit` = `export_w`. **После:** Восстановить выбранный режим. Состояния: `curtailment.live_pv_w`, `missing_charge_wh`, `max_charge_w`, `export_w`, `remaining_hours`.

**Администратор:** флажок _В наличии распределительная коробка._ — без сумматора: идентификатор устройства + тип солнечной батареи + мощность батареи в Вт·ч; с сумматором: идентификатор сумматора + до **4** слоты для солнечных батарей (каждый слот может быть _никто_). **Комбинатор:** общий лимит переменного тока = **сумма** предельных значений на единицу (SB2) **1000** W, SB3 Pro **1200** W, SB4 Pro **2500** В). **Автономный:** всегда **800** В.

## HTML-панели мониторинга (в стиле Solix4)

Вдохновлено **[ioBroker.solix4](https://github.com/michihorn64/ioBroker.solix4)** к **Майкл Хорн ([@michihorn64](https://github.com/michihorn64))** — Спасибо за оригинальную концепцию панели управления! Подробности: [CREDITS.md](CREDITS.md).

После каждого успешного опроса адаптер пишет **самодостаточный HTML** (темная тема, поток энергии в реальном времени, настройки, суточная потребленная электроэнергия в кВтч, диагностика, список устройств) для преобразования состояний в строки с указанием роли `html`:

| Состояние                                           | Содержание                                                                            |
| --------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `anker-solix.0.dashboard.sites.<siteKey>.live.html` | Поток электроэнергии в реальном времени (Солнечная энергия → Дом ↔ Сеть, аккумулятор) |
| `…dashboard.html`                                   | Сочетание функций Live и настроек (раскладка для планшетов)                           |
| `…energy.html`                                      | Ежедневное потребление кВтч + автаркия / собственное потребление                      |
| `…settings.html`                                    | Ограничения и режимы (только для чтения)                                              |
| `…diagnosis.html`                                   | Предупреждения, MQTT, состояние устройства                                            |
| `…devices.html`                                     | Инвентаризация устройств                                                              |
| `anker-solix.0.dashboard.overview.html`             | Многоцентровое сравнение                                                              |

`<siteKey>` это первые 8 символов идентификатора сайта Anker (аналогично solix4).

**ВИС / ВИС-2:** добавить виджет **HTML-панель управления** (набор **анкер-соликс**) и привяжите его, например, к `anker-solix.0.dashboard.sites.<siteKey>.dashboard.html`или используйте стандартный VIS **HTML** Виджет. Изменяет размер до размера планшета (\~900×700 пикселей). HTML-код обновляется при каждом опросе адаптера.

Давать возможность **Объекты → Tagesstatistiken** для блоков данных кВтч; включить **Leistungsflüsse** для получения актуальных значений мощности.

Издательская деятельность использует **npm доверенное издательство** (OIDC из GitHub Actions — нет долгосрочного токена npm). Классические токены автоматизации устарели в npm. **Январь 2027 г.**&#x42D;тот адаптер уже находится в списке доверенных издателей. Зарегистрируйтесь в [ioBroker.repositories](https://github.com/ioBroker/ioBroker.repositories) как только пакет будет доступен в npm.

**Перед каждым релизом** (принудительно обеспечивается) `npm run test:package` → `test/io-package-policy.js`; запустить локально через `npm run verify:ci` перед каждым нажатием):

1. Ударяться `version` в `package.json` и `io-package.json` (должно совпадать).
2. Добавить `### x.y.z` раздел к этому списку изменений в файле README (E6006).
3. Добавлять **один** новый `common.news` запись для этой версии; сохранить **максимум 7** Ключевые слова для новостей — только версии, уже размещенные в npm (кроме той, которую вы собираетесь опубликовать). Переместить удаленный текст в [CHANGELOG\_OLD.md](CHANGELOG_OLD.md).
4. Администратор `jsonConfig.json`: заголовок `size` должно быть **≤ 5** (использовать `5` (для самого маленького заголовка).
5. Не добавляйте корневые файлы в npm. `files` если не потребуется (`CHANGELOG_OLD.md` (не находится вне упаковки).
6. `package.json` `os` должна соответствовать матрице ОС в `test-and-release.yml` (E3027). Сохранить права администратора `i18n/*.json` синхронно с `en.json` (W5604/W5605).
