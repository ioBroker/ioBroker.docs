Неофициальный адаптер ioBroker для [роботизированных газонокосилок Anthbot Genie](https://de.anthbot.com/products/genie-mahroboter) , ориентированный на подробную телеметрию, диагностику и управление газонокосилками Genie 600/1000/3000/5000 и более новыми моделями M5/M9.

Адаптер подключается к облачной учетной записи Anthbot, обнаруживает подключенные газонокосилки, считывает теневые данные из облака и IoT, а также предоставляет в ioBroker обширное дерево состояний, содержащее информацию о статусе, настройках, командах для газонокосилок, данных о зонах, расходных материалах, местоположении, диагностике и необработанных данных для устранения неполадок.

Он предназначен для пользователей, которым требуется больше, чем просто просмотр информации о состоянии устройства в режиме онлайн/заряда батареи/статуса: состояние RTK и базовой станции, сведения о прошивке и OTA-обновлениях, информация о сети и SIM-карте, данные GPS и координаты местоположения, временные метки жизненного цикла карты, сведения об ошибках газонокосилки, сроки службы расходных материалов, настройки дождя, метаданные зон и записываемые элементы управления скашиванием доступны в виде состояний ioBroker.

Этот адаптер доступен в ioBroker.`latest` Репозиторий. Пожалуйста, оставляйте отзывы и результаты тестирования в [теме на форуме ioBroker](https://forum.iobroker.net/topic/84983) .

Пример использования ioBroker Blockly с условиями для автоматизации газонокосилки можно найти в [примере автоматизации Blockly](https://forum.iobroker.net/topic/84392/2) .

## Функции

- Вход в облако Anthbot с зашифрованным хранением паролей в собственной конфигурации ioBroker.
- Автоматическое обнаружение газонокосилок, привязанных к настроенной учетной записи Anthbot.
- Поиск региона и конечной точки IoT для каждой газонокосилки
- Автоматическое обновление временных учетных данных IoT после AWS IoT`403` ответы
- Опрос представителей теневой экономики в сфере собственности и услуг
- Подробная информация о состоянии подключения, состоянии сети, состоянии батареи, состоянии газонокосилки, состоянии зарядки, времени кошения, площади кошения, общем времени кошения/площади, состоянии карты, состоянии задачи картирования, ошибках, активном режиме кошения, точечном кошении и количестве зон.
- Диагностические состояния для RTK-установки, базовой станции RTK, предупреждений о перемещении антенны, версий прошивки, хода OTA-обновления, Wi-Fi, сотовой связи, SIM-карты, Bluetooth, флагов камеры/карты, системы предотвращения столкновений, флагов безопасности, системных временных меток и данных об ошибках газонокосилки, хранящихся в облаке.
- Информация о местоположении для GPS-координат, предотвращающих потерю, и локального положения газонокосилки.
- Срок службы расходных материалов и кнопки сброса для зарядного порта, камер и лезвий.
- Настраиваемые параметры управления для кошения по всей карте, зонального кошения, высоты среза, громкости голоса, пользовательского направления кошения, обхода препятствий, настроек на случай дождя и кошения вблизи зарядной станции.
- Команды управления для полного скашивания, остановки, возврата на зарядную станцию, паузы при возврате на зарядную станцию, сброса травы, режима обслуживания дисков, скашивания краев, скашивания возле зарядной станции, точечного скашивания, обновления, ручного зонирования и автоматического зонирования.
- Метаданные зон, созданных вручную и автоматически, представлены в формате JSON, включая активные идентификаторы зон, созданных вручную.
- Состояния изображения карты в формате PNG (только для чтения) для исходной карты, маски скошенной области RTK и исторической траектории скашивания.
- Исходные теневые свойства, теневые сервисы, преобразования кодов событий Anthbot и полезные нагрузки определений областей для устранения неполадок и автоматизированной отладки.

## Требования

- ioBroker с js-контроллером`>= 6.0.11`
- администратор ioBroker`>= 7.6.20`
- Node.js`>= 22`
- Учетная запись Anthbot, содержащая как минимум одну привязанную газонокосилку Genie.
- Доступ в Интернет с хоста ioBroker к облаку Anthbot и конечной точке AWS IoT.

## Установка

Адаптер доступен в ioBroker.`latest` репозиторий, который можно установить из интерфейса адаптера ioBroker или из командной строки.

### Администратор ioBroker

Если`latest` Если репозиторий еще не активен, откройте административную панель ioBroker, перейдите в **«Настройки» -> «Репозитории»** , выберите или включите его.`latest` и обновите список адаптеров.

Затем откройте окно адаптера и найдите...`anthbot-genie` и установите адаптер из`latest` репозиторий.

### CLI

Установка с помощью:

```bash
iobroker repo set latest
iobroker update
iobroker add anthbot-genie
```

или явно с указанием версии:

```bash
iobroker add anthbot-genie@0.1.13
```

Откройте конфигурацию экземпляра адаптера в административной панели ioBroker и установите следующие параметры:

| Параметр                                                | Описание                                                                                          | По умолчанию      |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------- |
| Имя пользователя аккаунта Anthbot                       | Имя пользователя или адрес электронной почты учетной записи Anthbot                               | пустой            |
| пароль от аккаунта Anthbot                              | Пароль от учетной записи Anthbot хранится в зашифрованном виде на сервере ioBroker.               | пустой            |
| код города                                              | Например, телефонный или банковский код города.`49` для Германии                                  | `49`              |
| хост API                                                | Хост API облака Anthbot                                                                           | `api.anthbot.com` |
| Интервал опроса в секундах                              | Интервал опроса данных о работе газонокосилки. Адаптер устанавливает интервал не менее 10 секунд. | `60`              |
| Загрузка карты (высокая загрузка ЦП)                    | Загрузите и визуализируйте исходную карту, RTK-маску и историческую траекторию скашивания.        | `false`           |

После сохранения конфигурации запустите или перезапустите экземпляр адаптера.

## Штаты

Адаптер создает отдельное дерево устройств для каждого серийного номера газонокосилки. Если Anthbot когда-либо вернет серийный номер с символами, небезопасными для идентификаторов объектов ioBroker, адаптер нормализует только эти символы, сохраняя при этом исходный серийный номер в собственных метаданных объекта устройства:

```text
anthbot-genie.<instance>.<serial>.*
```

### Изображения карт

| Состояние                         | Тип  | Описание                                                                                                 |
| --------------------------------- | ---- | -------------------------------------------------------------------------------------------------------- |
| `<serial>.map.image`              | нить | Карта навигации в исходном виде в формате PNG (URI данных)                                               |
| `<serial>.map.imageWithRtkMask`   | нить | Встроенная навигационная карта с использованием Anthbot`rtk_mask_map` в виде URI данных PNG              |
| `<serial>.map.imageWithMowedPath` | нить | Карта навигации с загруженными историческими данными о траектории скашивания в формате PNG (URI данных). |
| `<serial>.map.mowedPath`          | нить | JSON-массив с точными историческими точками пути, использованными для`map.imageWithMowedPath`            |

Три состояния изображения доступны только для чтения и используют`media.image` роль.`map.mowedPath` Состояние доступно только для чтения и использует`json` роль. Адаптер загружает Anthbot.`multi_maps` файл карты, выдержки`maps/remote_map_navi.map` и отображает исходный растр с использованием совместимой с приложением палитры освещения.`map.image` содержит только карту;`map.imageWithRtkMask` добавляет полный`maps/rtk_mask_map` Растровое изображение скошенной площади;`map.imageWithMowedPath` запросы`req_history_mapping_path` , загрузки`path_<SN>.txt` , отображает исторический маршрут синим цветом и добавляет текущую позу газонокосилки в виде желтой иконки робота, а также встроенный маркер зарядного устройства под ней.`map.mowedPath` Содержит те же точки пути JSON, что и этот PNG-файл.`x` и`y` Значения используют исходные сантиметровые координаты исторического маршрута; разделите их на`100` для преобразования их в локальные метры карты, используемые для состояний положения. Встроенные ресурсы приложения ориентированы таким образом, что передняя часть газонокосилки направлена вниз, и поворачиваются с помощью`location.pose.yaw - 90°` (например, реальное отклонение примерно на 100 градусов)`-16°` указывает на переднюю правую сторону); сгенерированный резервный вариант использует ту же ориентацию. Маркер зарядного устройства и только для чтения.`location.charger.x` /`location.charger.y` Штаты считываются из`charger_point` в`maps/remote_map.json` Координаты штата указаны в метрах. Оба наложенных изображения отображают настроенные запрещенные зоны красным цветом. Историческое изображение никогда не возвращается к короткоживущему режиму.`curpath` Состояния изображений и пути обновляются при изменении идентификатора карты, метки времени, истории пути, положения газонокосилки или точки зарядки. Отсутствие или некорректность данных карты приводит к тому, что состояния остаются пустыми, пока адаптер продолжает опрос.

Эти два параметра карты намеренно управляют разными видами работ:

- `fetchMap = false` : не запрашивается путь к архиву карты, растровому изображению, PNG-файлу или истории изменений. Существующие значения координат карты и зарядного устройства остаются неизменными, поэтому ранее сгенерированные координаты карты и зарядного устройства могут отображаться, но не обновляются.
- `fetchMap = true` и`generateMapWithPaths = false` Обновлены исходная карта и состояние RTK-маски. Исторический путь не запрашивается, и`map.imageWithMowedPath` и`map.mowedPath` остаются без изменений. Использовать`map.image` или`map.imageWithRtkMask` для отображения карты с меньшим потреблением ресурсов процессора.
- Обе настройки`true` : все три состояния изображения и`map.mowedPath` генерируются состояния;`map.imageWithMowedPath` Содержит исторический маршрут и текущую иконку робота.

#### VIS: карта со встроенным значком робота

Используйте этот прямой путь, если включены обе настройки карты. Привяжите виджет изображения VIS к`<serial>.map.imageWithMowedPath` Адаптер уже отображает исторический путь и иконку робота в текущей позе. Второй виджет иконки VIS не требуется. Сохраняйте контейнер изображения с исходным соотношением сторон PNG.`404:488` ).

#### ВИС: карта с отдельным значком наложения

Используйте этот путь с меньшей загрузкой ЦП, когда`fetchMap = true` и`generateMapWithPaths = false` Привяжите виджет изображения к`<serial>.map.image` или`<serial>.map.imageWithRtkMask` Затем разместите прозрачный виджет значка абсолютно над ним. Привяжите или вычислите его положение на основе этого значения.`<serial>.location.pose.x` и`<serial>.location.pose.y` Эти значения указаны в метрах; метаданные карты содержат начало координат и разрешение. Разместите оба виджета в одном и том же относительно расположенном контейнере и используйте одинаковое соотношение сторон.`404:488` ), в противном случае`object-fit: contain` может добавить черные полосы по бокам и сместить наложенную иконку. Если`fetchMap = false` Изображение карты может по-прежнему отображать старое состояние, но ни сама карта, ни ее отдельное положение в наложении не обновляются адаптером.

После развертывания системы преобразования измерителя положения в измерение состояния,`location.pose.x` и`location.pose.y` Это метры. Преобразуйте их в пиксели карты, используя значения заголовка карты из...`maps/remote_map.json` :

```js
const map = {
    width: 404,
    height: 488,
    resolution: 0.05,
    xMin: -15.353175,
    yMin: -9.549684,
};

const pixelX = (poseX - map.xMin) / map.resolution;
const pixelY = map.height - 1 - (poseY - map.yMin) / map.resolution;
const poseYaw = Number(poseYawState); // <serial>.location.pose.yaw

icon.style.left = `${(pixelX / map.width) * 100}%`;
icon.style.top = `${(pixelY / map.height) * 100}%`;
icon.style.transform = `translate(-50%, -50%) rotate(${poseYaw - 90}deg)`;
```

Для текущего снимка,`pose.x = 0.094` и`pose.y = 0.356` Разместите значок примерно в пикселях.`(309, 289)` , или`left: 76.5%` и`top: 59.2%` . Определять`poseYaw` от`<serial>.location.pose.yaw` ; с иконкой, расположенной спереди вниз, применить`poseYaw - 90` так что происходит вращательное движение в реальном времени.`-16` Направляет переднюю часть вправо. В настоящее время адаптер не публикует ширину карты, высоту, разрешение или начало координат в качестве состояний, поэтому эти значения необходимо обновлять при создании новой карты газонокосилкой; не смешивайте пиксели массива карты с координатами газонокосилки в метрах.

#### Рыскание: происхождение и расчет

`<serial>.location.pose.yaw` Это обозначение головки косилки, указанное Anthbot как...`pose.yaw` Значение выражено в градусах и не переводится из миллиметров. Адаптер осуществляет только преобразование.`pose.x` и`pose.y` От миллиметров до метров; угол рыскания передается без изменений. X/Y описывают положение косилки, поэтому угол рыскания нельзя рассчитывать только на основе текущего положения.

Для отдельного значка VIS, на исходном изображении которого передняя часть газонокосилки направлена вниз, рассчитайте поворот изображения с фиксированным значением.`90°` компенсировать:

```js
const yawDeg = Number(yawState); // <serial>.location.pose.yaw
const iconRotationDeg = yawDeg - 90;

icon.style.transform = `translate(-50%, -50%) rotate(${iconRotationDeg}deg)`;
```

Он`-90°` Параметр offset выравнивает соглашение об отображении заголовков Anthbot с основным элементом. Та же формула используется для встроенной иконки карты и ее резервного варианта. Примеры:`yaw = 90°` результаты в`0°` Поворот изображения (спереди вниз), при этом значение в реальном времени`yaw = -16°` результаты в`-106°` (эквивалентно`254°` ) и направляет переднюю часть вправо. Если рыскание недоступно, оставьте объект в его стандартной ориентации — передней частью вниз.

#### Источник иконки робота

Проверенный пакет приложений Anthbot содержит локальные ресурсы для отображения маркеров на карте, включая Genie.`pic_device_map` актив, варианты S2/S3/M9Pro, специфичные для конкретной модели, и`view_map_battery_position` Маркер зарядного устройства. Это упакованные файлы пользовательского интерфейса, выбранные приложением; полезная нагрузка облака/API и загруженный архив карты не предоставляют многоразовый URL-адрес значка или состояние значка. Адаптер упаковывает соответствующие ресурсы маркеров, полученные из приложения, для известных моделей и использует собственный автономный маркер робота, если какой-либо ресурс отсутствует, нечитаем или модель неизвестна. Адаптер не зависит от установленного приложения.

## Зональная стрижка газонов

Адаптер обеспечивает доступ к ручным/настраиваемым зонам косилки в следующих местах:

```text
<instance>.<serial>.zones.manual.list
```

В этом штате содержится JSON-массив с известными зонами. Используйте его.`id` или точно`name` Из этого списка начнём косить.

Запишите выделенный фрагмент в:

```text
<instance>.<serial>.commands.mowing.startZone
```

Допустимые значения:

- одна зона по идентификатору:`3`
- одна зона по названию:`Front yard`
- несколько зон в виде идентификаторов или названий, разделенных запятыми:`3,5,Back yard`
- несколько зон в виде JSON-массива:`[3,5,"Back yard"]`

После успешной записи адаптер отправляет`custom_area_mow_start` с соответствующими идентификаторами зон, заданными вручную, и очищенными зонами.`commands.mowing.startZone` снова.

Автоматические зоны работают аналогичным образом:

```text
<instance>.<serial>.zones.autoList
<instance>.<serial>.commands.mowing.startAutoZone
```

Для автоматических зон адаптер преобразует выбранные идентификаторы или имена зон в координаты зоны и отправляет их.`region_mow_start` .

## Поиск неисправностей

### Адаптер не подключается

- Проверьте имя пользователя, пароль и код города.
- Убедитесь, что газонокосилка отображается в приложении Anthbot с той же учетной записью.
- Повысьте уровень логирования адаптера до`debug` и перезапустить экземпляр.
- Проверять`anthbot-genie.<instance>.info.connection` .

### Объекты газонокосилки не создаются.

- В учетной записи Anthbot должна быть как минимум одна подключенная газонокосилка.
- Проверьте журнал адаптера на наличие`No Anthbot devices found for this account` .
- Убедитесь, что хост ioBroker имеет доступ к интернету.

### Команды не работают

- Сначала проверьте, работает ли опрос состояния.
- Убедитесь, что целевой штат соответствует правильному серийному номеру газонокосилки.
- Для команд зон сравните записанное значение с идентификаторами и именами в`zones.manual.list` или`zones.autoList` .
- Адаптер автоматически обновляет временные учетные данные IoT один раз после завершения операции AWS IoT.`403` Если после этой повторной попытки команды по-прежнему не выполняются, проверьте журнал адаптера на наличие ошибок, связанных с полезной нагрузкой или состоянием газонокосилки, характерных для данной модели.
- Проверять`raw.shadow.service` а также журнал адаптера для проверки ошибок команд.
