Неофициальный адаптер ioBroker для [Роботизированные газонокосилки Anthbot Genie](https://de.anthbot.com/products/genie-mahroboter), ориентированный на подробную телеметрию, диагностику и управление газонокосилками Genie 600/1000/3000/5000 и более новыми моделями M5/M9.

Адаптер подключается к облачной учетной записи Anthbot, обнаруживает подключенные газонокосилки, считывает теневые данные из облака и IoT, а также предоставляет в ioBroker обширное дерево состояний, содержащее информацию о статусе, настройках, командах для газонокосилок, данных о зонах, расходных материалах, местоположении, диагностике и необработанных данных для устранения неполадок.

Он предназначен для пользователей, которым требуется больше, чем просто просмотр информации о состоянии устройства в режиме онлайн/заряда батареи/статуса: состояние RTK и базовой станции, сведения о прошивке и OTA-обновлениях, информация о сети и SIM-карте, данные GPS и координаты местоположения, временные метки жизненного цикла карты, сведения об ошибках газонокосилки, сроки службы расходных материалов, настройки дождя, метаданные зон и записываемые элементы управления скашиванием доступны в виде состояний ioBroker.

Этот адаптер доступен в репозитории ioBroker `latest`. Пожалуйста, оставляйте отзывы и результаты тестирования в репозитории [ветка форума ioBroker](https://forum.iobroker.net/topic/84983).

Пример ioBroker Blockly с условиями для автоматизации газонокосилки доступен в [Пример автоматизации с помощью Blockly](https://forum.iobroker.net/topic/84392/2).

## Функции
- Вход в облако Anthbot с зашифрованным хранением паролей в собственной конфигурации ioBroker.
- Автоматическое обнаружение газонокосилок, привязанных к настроенной учетной записи Anthbot.
- Поиск региона и конечной точки IoT для каждой газонокосилки.
- Автоматическое обновление временных учетных данных IoT после ответов AWS IoT `403`
- Опрос представителей теневой экономики в сфере собственности и услуг
- Подробная информация о состоянии подключения, состоянии сети, состоянии батареи, состоянии газонокосилки, состоянии зарядки, времени кошения, площади кошения, общем времени кошения/площади, состоянии карты, состоянии задачи картирования, ошибках, активном режиме кошения, точечном кошении и количестве зон.
- Диагностические состояния для RTK-установки, базовой станции RTK, предупреждений о перемещении антенны, версий прошивки, хода OTA-обновления, Wi-Fi, сотовой связи, SIM-карты, Bluetooth, флагов камеры/карты, системы предотвращения столкновений, флагов безопасности, системных временных меток и данных об ошибках газонокосилки, хранящихся в облаке.
- Данные о местоположении для защиты от потери: GPS-координаты и локальное положение газонокосилки.
- Режимы работы расходных материалов и кнопки сброса для зарядного порта, камер и лезвий.
- Возможность изменения параметров управления для кошения по всей карте, зонального кошения, высоты среза, громкости голоса, пользовательского направления кошения, обхода препятствий, настроек на случай дождя и кошения вблизи зарядной станции.
- Команды управления для полного скашивания, остановки, возврата на зарядную станцию, паузы при возврате на зарядную станцию, сброса травы, режима обслуживания дисков, скашивания краев, скашивания возле зарядной кучи, точечного скашивания, обновления, ручного зонирования и автоматического зонирования.
- Метаданные зон, созданные вручную и автоматически, в формате JSON, включая активные идентификаторы зон, созданных вручную.
- Состояния изображения карты в формате PNG только для чтения: исходная карта, маска скошенной области RTK и историческая траектория скашивания.
— Теневые свойства, теневые сервисы, преобразования кодов событий Anthbot и полезные нагрузки определений областей для устранения неполадок и автоматизированной отладки.

## Требования
- ioBroker с js-контроллером `>= 6.0.11`
- ioBroker admin `>= 7.6.20`
- Node.js `>= 22`
- Аккаунт Anthbot, содержащий как минимум одну привязанную газонокосилку Genie.
— Доступ в Интернет с хоста ioBroker к облаку Anthbot и конечной точке AWS IoT.

## Установка
Адаптер доступен в репозитории ioBroker `latest` и может быть установлен из представления адаптера ioBroker или из командной строки.

### Администратор ioBroker
Если репозиторий `latest` еще не активен, откройте административную панель ioBroker, перейдите в **Настройки -> Репозитории**, выберите или включите `latest` и обновите список адаптеров.

Затем откройте окно адаптера, найдите `anthbot-genie` и установите адаптер из репозитория `latest`.

### CLI
Установка с помощью:

```bash
iobroker repo set latest
iobroker update
iobroker add anthbot-genie
```

или явно с указанием версии:

```bash
iobroker add anthbot-genie@0.1.13
```

## Поддерживаемые устройства
- Genie 600
- Джинн 1000
- Genie 3000
- Genie 5000
- М5
- М9

## Конфигурация
Откройте конфигурацию экземпляра адаптера в административной панели ioBroker и установите следующие параметры:

| Настройки | Описание | По умолчанию |
| --- | --- | --- |
| Имя пользователя аккаунта Anthbot | Имя пользователя или адрес электронной почты аккаунта Anthbot | пусто |
| Пароль от аккаунта Anthbot | Пароль от аккаунта Anthbot, хранящийся в зашифрованном виде через ioBroker | пусто |
| Код города | Код города телефона или учетной записи, например, `49` для Германии | `49` |
| Интервал опроса в секундах | Интервал опроса данных газонокосилки. Адаптер обеспечивает интервал не менее 10 секунд. | `60` |
| Загрузка карты (высокая загрузка ЦП) | Загрузка и отрисовка исходной карты, RTK-маски и исторической траектории скашивания | `false` |
| Создание карты с маршрутами (еще более высокая загрузка ЦП) | Загрузка и отображение исторического маршрута скашивания на изображении карты. Требуется загрузка карты. | `false` |
| Язык описания ошибок | Язык, используемый для описания ошибок в облаке Anthbot | `English` |
| Язык описания ошибок | Язык, используемый для описания ошибок в облаке Anthbot | `Английский` |

Если какой-либо из параметров карты отключен, адаптер прекращает запрашивать или отображать данные карты, оставляя существующие значения состояния карты без изменений.

После сохранения конфигурации запустите или перезапустите экземпляр адаптера.

## Штаты
Адаптер создает отдельное дерево устройств для каждого серийного номера газонокосилки. Если Anthbot когда-либо вернет серийный номер с символами, небезопасными для идентификаторов объектов ioBroker, адаптер нормализует только эти символы, сохраняя при этом исходный серийный номер в собственных метаданных объекта устройства:

```text
anthbot-genie.<instance>.<serial>.*
```

### Изображения карт
| Штат | Тип | Описание |
| --- | --- | --- |
| `<serial>.map.image` | строка | Карта навигации в формате PNG в виде URI данных |
| `<serial>.map.imageWithMowedPath` | строка | Карта навигации с загруженным историческим маршрутом скашивания в формате PNG |
| `<serial>.map.mowedPath` | строка | JSON-массив с точными историческими точками пути, использованными для `map.imageWithMowedPath` |
| `<serial>.map.mowedPath` | string | JSON-массив с точными историческими точками пути, использованными для `map.imageWithMowedPath` |

Три состояния изображения доступны только для чтения и используют роль `media.image`. Состояние `map.mowedPath` доступно только для чтения и использует роль `json`. Адаптер загружает файл карты Anthbot `multi_maps`, извлекает `maps/remote_map_navi.map` и отображает исходный растр с использованием совместимой с приложением палитры освещения. `map.image` содержит только карту; `map.imageWithRtkMask` добавляет полный растр `maps/rtk_mask_map` скошенной местности; `map.imageWithMowedPath` запрашивает `req_history_mapping_path`, загружает `path_<SN>.txt`, отображает исторический путь синим цветом и добавляет текущее положение газонокосилки в виде желтого значка робота, а также собственный маркер зарядного устройства под ним. `map.mowedPath` содержит те же точки пути в формате JSON, что и этот PNG. Его значения `x` и `y` используют собственные сантиметровые координаты исторического пути; разделите их на `100`, чтобы преобразовать их в локальные метры карты, используемые состояниями положения. Встроенные ресурсы приложения ориентированы таким образом, что передняя часть газонокосилки направлена вниз, а вращение осуществляется с помощью `location.pose.yaw - 90°` (например, в реальном времени угол поворота около `-16°` направлен вправо); сгенерированный резервный вариант использует ту же ориентацию. Маркер зарядного устройства и состояния `location.charger.x`/`location.charger.y` считываются из `charger_point` в `maps/remote_map.json`; координаты состояния отображаются в метрах. Оба наложенных изображения отображают настроенные запрещенные зоны красным цветом. Историческое изображение никогда не возвращается к кратковременному состоянию `curpath`. Изображения и состояние пути обновляются при изменении идентификатора карты, метки времени, исторического пути, положения газонокосилки или точки зарядки. Отсутствие или некорректность данных карты приводит к тому, что состояния остаются пустыми, пока адаптер продолжает опрос.

Эти два параметра карты намеренно управляют разными видами работ:

- `fetchMap = false`: не запрашивается путь к архиву карты, растровому изображению, PNG-файлу или истории изменений. Существующие значения координат карты и зарядного устройства остаются неизменными, поэтому ранее сгенерированные координаты карты и зарядного устройства могут отображаться, но не обновляются.
- `fetchMap = true` и `generateMapWithPaths = false`: обновляются исходное состояние карты и RTK-маски. Исторический путь не запрашивается, а `map.imageWithMowedPath` и `map.mowedPath` остаются без изменений. Используйте `map.image` или `map.imageWithRtkMask` для просмотра карты с меньшим потреблением ресурсов процессора.
- Оба параметра установлены в значение `true`: генерируются все три состояния изображения и состояние `map.mowedPath`; `map.imageWithMowedPath` содержит историю перемещений и текущую иконку робота.

#### VIS: карта с интегрированным значком робота
Используйте этот прямой путь, если включены обе настройки карты. Привяжите виджет изображения VIS к `<serial>.map.imageWithMowedPath`; адаптер уже отображает исторический путь и значок робота в текущей позе. Второй виджет значка VIS не требуется. Сохраняйте контейнер изображения с исходным соотношением сторон PNG (`404:488`).

#### VIS: карта с отдельным значком наложения
Используйте этот путь с меньшим потреблением ресурсов ЦП, когда `fetchMap = true` и `generateMapWithPaths = false`. Привяжите виджет изображения к `<serial>.map.image` или `<serial>.map.imageWithRtkMask`, затем разместите прозрачный виджет значка абсолютно над ним. Привяжите или рассчитайте его положение из `<serial>.location.pose.x` и `<serial>.location.pose.y`. Эти состояния указаны в метрах; метаданные карты предоставляют начало координат и разрешение. Держите оба виджета в одном и том же относительно расположенном контейнере и используйте одинаковое соотношение сторон (`404:488`), иначе `object-fit: contain` может привести к появлению черных полос по краям и смещению значка наложения. Если `fetchMap = false`, изображение карты может по-прежнему отображать старое состояние, но ни карта, ни ее отдельное положение наложения не обновляются адаптером.

После выполнения преобразования в метры положения и состояния, значения `location.pose.x` и `location.pose.y` будут соответствовать метрам. Преобразуйте их в пиксели карты, используя значения заголовка карты из `maps/remote_map.json`:

```js
const map = {
    width: 404,
    height: 488,
    resolution: 0.05,
    xMin: -15.353175,
    yMin: -9.549684,
};

const pixelX = (poseX - map.xMin) / map.resolution;
const pixelY = map.height - 1 - (poseY - map.yMin) / map.resolution;
const poseYaw = Number(poseYawState); // <serial>.location.pose.yaw

icon.style.left = `${(pixelX / map.width) * 100}%`;
icon.style.top = `${(pixelY / map.height) * 100}%`;
icon.style.transform = `translate(-50%, -50%) rotate(${poseYaw - 90}deg)`;
```

Для текущего снимка `pose.x = 0.094` и `pose.y = 0.356` размещают значок приблизительно на пикселе `(309, 289)` или `left: 76.5%` и `top: 59.2%`. Определите `poseYaw` на основе `<serial>.location.pose.yaw`; для значка, расположенного лицевой стороной вниз, примените `poseYaw - 90` так, чтобы в реальном времени поворот вокруг `-16` указывал лицевой стороной вправо. В настоящее время адаптер не публикует ширину карты, высоту, разрешение или начало координат в качестве состояний, поэтому эти значения необходимо обновлять при создании новой карты газонокосилкой; не смешивайте пиксели массива карты с метровыми координатами газонокосилки.

#### Рыскание: начало координат и расчет
`<serial>.location.pose.yaw` — это направление движения косилки, сообщаемое Anthbot как `pose.yaw`. Оно выражено в градусах и не переводится из миллиметров. Адаптер преобразует только `pose.x` и `pose.y` из миллиметров в метры; угол рыскания передается без изменений. X/Y описывают положение косилки, поэтому угол рыскания не должен рассчитываться только на основе текущего положения.

Для отдельного значка VIS, на исходном изображении которого передняя часть газонокосилки направлена вниз, рассчитайте поворот изображения с фиксированным смещением `90°`:

```js
const yawDeg = Number(yawState); // <serial>.location.pose.yaw
const iconRotationDeg = yawDeg - 90;

icon.style.transform = `translate(-50%, -50%) rotate(${iconRotationDeg}deg)`;
```

Параметр `-90°` смещает указатель направления Anthbot относительно изображения, расположенного лицевой стороной вниз. Та же формула используется для встроенной иконки карты и ее резервного варианта. Примеры: `yaw = 90°` приводит к повороту изображения `0°` (лицевой стороной вниз), а значение `yaw = -16°` приводит к `-106°` (эквивалентно `254°`) и направляет изображение лицевой стороной вправо. Если поворот по оси Y недоступен, изображение остается в ориентации по умолчанию (лицевой стороной вниз).

#### Источник иконки робота
Проверенный пакет приложения Anthbot содержит локальные ресурсы маркеров карты, включая ресурс Genie `pic_device_map`, варианты для конкретных моделей S2/S3/M9Pro и маркер зарядного устройства `view_map_battery_position`. Это упакованные файлы пользовательского интерфейса, выбранные приложением; полезная нагрузка облака/API и загруженный архив карты не предоставляют многоразовый URL-адрес значка или состояние значка. Адаптер упаковывает соответствующие ресурсы маркеров, полученные из приложения, для известных моделей и использует собственный автономный маркер робота, если ресурс отсутствует, нечитаем или модель неизвестна. Адаптер не зависит от установленного приложения.

## Зонная стрижка
Адаптер обеспечивает доступ к ручным/настраиваемым зонам косилки в следующих местах:

```text
<instance>.<serial>.zones.manual.list
```

В этом штате содержится JSON-массив с известными зонами. Используйте `id` или точно `name` из этого списка, чтобы начать косить.

Запишите выделенный фрагмент в:

```text
<instance>.<serial>.commands.mowing.startZone
```

Допустимые значения:

- одна зона по ID: `3`
- одна зона по названию: «Передний двор»
- Несколько зон в виде идентификаторов или названий, разделенных запятыми: `3,5,Задний двор`
- Несколько зон в виде массива JSON: `[3,5,"Задний двор"]`

После успешной записи адаптер отправляет `custom_area_mow_start` с соответствующими идентификаторами зон, указанными вручную, и снова очищает `commands.mowing.startZone`.

Автоматические зоны работают аналогичным образом:

```text
<instance>.<serial>.zones.autoList
<instance>.<serial>.commands.mowing.startAutoZone
```

Для автоматических зон адаптер преобразует выбранные идентификаторы или имена зон в координаты зоны и отправляет `region_mow_start`.

## Поиск неисправностей
### Адаптер не подключается
— Проверьте имя пользователя, пароль и код города.
— Убедитесь, что газонокосилка отображается в приложении Anthbot с той же учетной записью.
— Повысьте уровень логирования адаптера до `debug` и перезапустите экземпляр.
- Проверьте `anthbot-genie.<instance>.info.connection`.

### Объекты газонокосилки не создаются
- В учетной записи Anthbot должна быть как минимум одна подключенная газонокосилка.
— Проверьте журнал адаптера на наличие сообщения «Для этой учетной записи не найдено устройств Anthbot».
— Убедитесь, что хост ioBroker имеет доступ к интернету.

### Команды не работают
— Сначала проверьте, работает ли опрос состояния.
— Убедитесь, что целевой штат соответствует правильному серийному номеру газонокосилки.
- Для команд зон сравните записанное значение с идентификаторами и именами в `zones.manual.list` или `zones.autoList`.
— Адаптер автоматически обновляет временные учетные данные IoT один раз после ошибки AWS IoT `403`; если команды по-прежнему не выполняются после этой повторной попытки, проверьте журнал адаптера на наличие ошибок, специфичных для модели устройства или состояния газонокосилки.
— Проверьте `raw.shadow.service` и журнал адаптера на наличие ошибок команд.
