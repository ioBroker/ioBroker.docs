# Веб-компоненты ioBroker в vis-2 (предварительная версия)

Веб-компонент — это пользовательский элемент, который может отображаться в любом интерфейсе ioBroker: vis-2, devices, aura, admin. Компонент предоставляет собственное описание своих настроек, хост отображает это описание в виде собственного интерфейса настроек и передает компоненту соединение с ioBroker и значения настроек.

Контракт — модуль, манифест, свойства элемента, события, диалоги — и базовый класс для компонентов находятся в[`@iobroker/web-components`](https://github.com/ioBroker/web-components) Эта страница описывает только то, что vis-2 делает в качестве хоста. Работа хоста описана в...[`src-vis/src/Vis/WebComponents/`](https://github.com/iobroker/iobroker.vis-2/blob/master/packages/iobroker.vis-2/src-vis/src/Vis/WebComponents/) Демонстрационный компонент, который предоставляет Vis-2, это:[`src-vis/public/demo-components/iob-state-tile.js`](https://github.com/iobroker/iobroker.vis-2/blob/master/packages/iobroker.vis-2/src-vis/public/demo-components/iob-state-tile.js) — Доступно в палитре только на сервере разработки.

## Как vis-2 находит компоненты

В адаптере перечислены его компоненты в `common.webComponents` его `io-package.json`: файлы манифеста, относительно папки admin. И admin, и web предоставляют доступ к этой папке. `/adapter/<adapter>/` В манифесте модуль ES элемента называется следующим образом: `module` относительно самого себя:

```json
"common": {
    "webComponents": ["webcomponents/my-tile.json"]
}
```

vis-2 считывает это из объектов экземпляра (во время выполнения из `config.js`, который адаптер записывает с помощью `webComponents`) и разрешает URL-адреса с помощью `getWebComponentSources()` из упаковки, поэтому vis-2 под `/vis-2/` А за обратным прокси-сервером находятся те же файлы. Недействительный манифест пропускается, и в консоли появляется ошибка; тег, который приносят два компонента, берется из первого.

Палитра и атрибуты берутся исключительно из манифеста. vis-2 импортирует модуль компонента при первом отображении его виджета. `importWebComponent()` (из пакета), один раз для всех его виджетов, и после этого создает элемент. Если модуль не может быть загружен или не определяет тег своего манифеста, виджет остается пустым; редактор показывает причину.

Модуль, экспортирующий свой манифест (`@iobroker/web-components` 0.2) по-прежнему работает: vis-2 импортирует его сразу для чтения манифеста. Демонстрационный компонент представляет собой именно такой модуль.

Компонент React не включает React в состав пакета: веб-интерфейс и административная панель предоставляют по одной копии для каждого основного компонента. `/lib/esm/react-19.js` и `/lib/esm/react-18.js`, видеть `REACT_19_URL` упаковки.

## Виджет

Каждый компонент становится виджетом определенного типа. `tplWc_<tag>` в наборе палитр своего адаптера, размером `manifest.size` для нового виджета; `size.noResize` Это делает виджет неизменяемым по размеру. Если адаптер содержит собственные виджеты vis-2, компоненты располагаются рядом с ними в этом наборе; в противном случае набор помечается соответствующим образом. `common.titleLang` и `common.icon` адаптера. Среда выполнения загружает компоненты только тогда, когда проект отображает их, и не загружает виджеты адаптера в этом случае.

Если адаптер добавляет виджет vis-2 с тем же именем — тот же набор, то же имя в палитре, например, "Блок-схема" потока — палитра будет предлагать только виджет vis-2. Виджеты уже размещенного компонента останутся без изменений.

Ан `objectId` настройка с `root` предлагает только этот объект и объекты, расположенные под ним, например.`"types": "config",
"root": "flow.0.diagrams"`.

Этот элемент получает следующие свойства:

| Свойство   | В vis-2                                                                                                            |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| `socket`   | связь вис-2                                                                                                        |
| `settings` | Значения атрибутов, заданные в соответствии с указаниями в манифесте; новый объект создается только при изменении. |
| `theme`    | цвета, шрифт и углы темы vis-2 (`getWebComponentTheme`)                                                           |
| `editMode` | Если в редакторе установлено значение true, элемент ничего не записывает и не открывает диалоговые окна.           |
| `dialogs`  | Диалоги MUI в vis-2 см. ниже.                                                                                      |

Привязки работают во всех полях: виджет передает значения после того, как vis-2 их обработал.

## Настройки

vis-2 не отображает JSON-Config. Он сопоставляет настройки манифеста с полями своей панели атрибутов:

| JSON-Config          | поле vis-2     | Примечания                                                              |
| -------------------- | -------------- | ----------------------------------------------------------------------- |
| `text`               | `text`         | `minRows > 1` предоставляет многострочный редактор                      |
| `password`           | `password`     |                                                                         |
| `number`             | `number`       | `min`, `max`, `step`                                                   |
| `slider`             | `slider`       | `min`, `max`, `step`                                                   |
| `checkbox`           | `checkbox`     |                                                                         |
| `color`              | `color`        |                                                                         |
| `select`             | `select`       | `options: [{ value, label }]`                                           |
| `selectSendTo`       | `custom`       | Варианты, запрашиваемые у адаптера, см. ниже.                           |
| `autocompleteSendTo` | `custom`       | текст с предложениями от адаптера; `freeSolo`, `maxLength`, `options`   |
| `objectId`           | `id`           | `types` ограничивает браузер объектов (например) `config`), `root` ветвь |
| `instance`           | `instance`     | `adapter`                                                               |
| `header`             | `help`(смелый) | `text`, нет значения                                                   |
| `staticText`         | `help`         | `text`, нет значения                                                   |
| `divider`            | `delimiter`    | нет ценности                                                            |

Вкладки становятся группами на панели атрибутов. `hidden` и `disabled` являются ли выражения JavaScript над `data` как в JSON-Config. Любой другой тип отображается как текстовое поле. vis-2 не включает параметр, имя которого используется для каждого виджета отдельно. `name`, `class`, `comment`, `filterkey`, `locked`, `multi-views`, `visibility*`, `signals-*`, `lc-*`, `g_*`).

### Варианты настроек адаптера: `selectSendTo` и `autocompleteSendTo`

Параметры этих настроек известны только адаптеру во время выполнения — его местоположение, устройства, схемы. vis-2 запрашивает у экземпляра информацию о... `sendTo(instance, command, message)` через собственное соединение и показывает ответ `[{ value, label }]` в качестве вариантов (`label` строка или `{ en, de, ... }` (простое значение само по себе является меткой). `getSendToRequest(setting, data, adapter)` и `toSendToOptions(answer)` пакет (0.8) выполняет работу:

- В данном случае речь идёт о `instance` обстановки, узор, подобный `${data.instance}`; без этого vis-2 спрашивает `<adapter>.0` адаптера, который обеспечивает подачу компонента. Сообщение следующее: `data` как есть, или `jsonData` Это шаблон, который обрабатывает значения всех настроек, типизированные по мере их получения компонентом, и возвращает значение в формате JSON. `command` является `send` если отсутствует.
- vis-2 повторно запрашивает информацию, когда экземпляр, команда, сообщение или настройка в `alsoDependsOn` Изменения происходят через 300 мс после последнего изменения, поэтому при вводе настроек система запрашивает подтверждение один раз. Ответ ожидается через 10 секунд.
- `selectSendTo` Это выборка. Значение, отсутствующее в ответе, остается и помечается как «Не в списке».
- `autocompleteSendTo` — это текстовое поле с ответом, затем... `options` из манифеста, в виде предложений; `maxLength` Ограничивает текст. Ввод метки параметра сохраняет его значение. Без этого `freeSolo` Текст, который не является вариантом, помечается как «Нет в списке» — при этом он сохраняется, поэтому ничего набранного не теряется.
- Пока нет случая, чтобы задать этот вопрос. `${data.instance}` Если не выбран ни один экземпляр, нет ответа, ошибка, истечение времени ожидания или пустой список: поле представляет собой текстовое поле с указанием причины под ним, поэтому значение остается редактируемым.

Значение хранится как текст, как и любое другое значение в Vis-2, и передается компоненту в виде строки. В панели атрибутов эти настройки отображаются следующим образом: `custom` поля; поле загружается только тогда, когда редактор его отображает. Форма `dialogs.open()` показывает их таким же образом, со значениями в следующем виде: `data`.

## События и диалоги

- `iob-navigate` с `detail: { view }`: vis-2 отображает это представление и отменяет событие. Не в редакторе.
- `dialogs.open()` с помощью элемента: vis-2 помещает его в диалоговое окно MUI; элемент закрывает его с помощью `iob-dialog-close`, чей `detail` В результате получается следующее. Закрытие диалогового окна в противном случае приводит к следующему результату. `null`.
- `dialogs.open()` с формой: vis-2 отображает панель JSON-Config с типами полей из приведенной выше таблицы и возвращает значения, или `null` при отмене.

Диалоговые окна загружаются по запросу: страница, компоненты которой никогда не открывают диалоговое окно, не получает их. Диалоговое окно, остающееся открытым после закрытия виджета, отвечает на запрос. `null`.
