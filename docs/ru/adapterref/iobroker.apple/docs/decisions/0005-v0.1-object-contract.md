# ADR 0005: Версия 0.1 Объектный и командный контракт

- Статус: принято; права доступа к корневому каталогу устройства изменены в соответствии с ADR 0010, права доступа изменены в соответствии с ADR 0011, роли и громкость Apple TV изменены в соответствии с ADR 0019
- Дата: 31.08.2026

## Контекст

Принятый в эксплуатацию прототип Apple TV теперь позволяет использовать первый вертикальный срез адаптера. Дерево объектов ioBroker представляет собой публичный API, используемый автоматизацией и визуализацией, поэтому его идентификаторы, типы, роли, поведение при записи и семантика подтверждения должны быть определены до того, как бэкэнд протокола начнет записывать состояния.

В версии 0.1 обнаружены только устройства Apple TV. HomePod и универсальные AirPlay-приемники классифицированы и учтены, но пока не получают отдельные объекты устройств или элементы управления. Apple Music, потоковая передача, группы, сцены, учетные записи, выходы и универсальная конечная точка команд JSON остаются вне этого релиза.

## Решение

Использовать `devices.appletv.<deviceId>` для одного физического Apple TV, где `deviceId` — это стандартизированный 12-символьный идентификатор устройства AirPlay в нижнем регистре. Отображаемые имена и сетевые адреса никогда не участвуют в определении идентификатора объекта.

Объект устройства `common.name` является читаемым `AppleTV <display name>` этикетка, например `AppleTV Living Room` Технический идентификатор объекта остается стабильным, поэтому переименование, дублирование отображаемого имени или изменение локализации не нарушат работу скриптов.

Общественность `devices.*` Дерево содержит только активные, постоянно сопряженные устройства Apple TV. Несопряженные устройства остаются доступными в качестве временных кандидатов на сопряжение администратора, но не создают постоянные деревья объектов. Пассивные устройства сохраняют свое сопряжение и запись в инвентаризации администратора, но отключаются и не имеют отдельного публичного дерева. При запуске адаптер удаляет текущие деревья Apple TV, для которых не включено соответствующее сопряжение. Явное удаление сопряжения удаляет весь корневой каталог устройства, и последующее обнаружение само по себе его не воссоздает. ADR 0011 определяет формат постоянного включения и поведение обновления по умолчанию.

Все прогнозы и результаты команд, полученные с помощью бэкэнда, основаны на использовании... `ack=true` Адаптер обрабатывает только созданные возможности. `remote.*`, `playback.*`, и `power.*` пишет с `ack=false` и логическое значение `true` Программа сериализует команды для каждого целевого объекта, проверяет текущее соединение и возможности, выполняет введенную команду бэкэнда, записывает стабильный результат, а затем сбрасывает кнопку. `false` с `ack=true` Неудачная команда никогда не отображается как успешная обратная связь о состоянии.

Ошибки подключения и команд, отображаемые в состояниях, представляют собой стабильный код проекта, а не необработанные сообщения от исходного источника. Версия 0.1 использует `not_paired`, `not_discovered`, `not_connected`, `unsupported`, `busy`, `timeout`, `protocol_error`, и `unavailable`.

## Последствия

Автоматизация и визуализация получают стабильные скалярные состояния без типов протоколов Apple. Несопряжённые сетевые кандидаты больше не оставляют устаревших общедоступных объектов устройств; они появляются в дереве только после завершения сопряжения. Классы устройств становятся видимыми до того, как появятся их управляющие бэкэнды, без создания спекулятивных объектов устройств. Для более поздних API для управления громкостью, учётной записью, выводом, общими командами и сценами требуется подтверждение новых возможностей, а также обновление ADR и анализ миграции.

## Проверка

Контрактные тесты должны проверять каждое определение объекта, тип, роль, флаг чтения/записи, единицу измерения/диапазон, идемпотентное согласование, читаемые метки устройства. `ack=false` обработка команд `ack=true` Проекция, независимое управление возможностями удаленного доступа/воспроизведения/питания, диспетчеризация команд питания, сериализация команд, подсчет классов обнаружения и стабильные ошибки. Интеграционные тесты должны проверять поведение перезапуска и выгрузки. Приемочные испытания на реальных устройствах должны проверять как пробуждение, так и приостановку, прежде чем управление питанием будет считаться аппаратно подтвержденным.
