# ioBroker Zeekr Adapter

<p align="center">
  <img src="admin/zeekr.svg" alt="Zeekr logo" width="160" height="160" />
</p>

Этот репозиторий содержит адаптер ioBroker для [электромобилей Zeekr](https://www.zeekr.com) . Он соответствует стандартной структуре адаптера ioBroker и предоставляет данные о состоянии транспортного средства в виде точек данных.

## Функции

- Стандартная компоновка адаптера ioBroker с пользовательским интерфейсом настройки.
- Имя пользователя/пароль Zeekr, а также специфические для Zeekr секреты, необходимые для работы клиента zeekr\_ev\_api, настраиваются в административном интерфейсе ioBroker.
- Дополнительное автоматическое извлечение секретных данных из `zeekr_secrets.json` файл или напрямую из APK-файлов Zeekr на хосте ioBroker.
- Обнаружение транспортных средств и опрос их состояния осуществляется через мост на языке Python, использующий клиент API Zeekr.
- Данные о транспортном средстве, уровне заряда батареи, запасе хода, показаниях одометра, состоянии зарядки, состоянии блокировки, климатическом режиме и общей полезной нагрузке.
- Журнал учета движения со стороны адаптера (`trips.own*` работает с общими учетными записями), оценка сеанса оплаты с учетом роуминговых тарифов (`energy.*`), агрегированные данные за день/неделю/месяц и экспорт в CSV для визуализаций и электронных таблиц.
- Именованные геозоны, адаптивный опрос (быстрый во время движения) и оповещения через веб-перехватчик (зарядка завершена/прервана, требуется обслуживание, предупреждение о состоянии шин, низкое напряжение 12 В).
- Состояния здоровья и тревоги, такие как `info.health`, `info.alertCount`, и `info.lastSuccessfulUpdate`
- Автоматическая загрузка локальной среды выполнения Python и зависимости Zeekr при первом использовании.

## Требования

- Node.js 22+ (совпадения) `engines` в `package.json`)
- Python 3

Ручная установка пакетов Python не требуется. Адаптер создает локальную виртуальную среду при первом запуске и автоматически устанавливает зависимость Zeekr.

На хостах и в контейнерах Debian/Ubuntu загрузка виртуального окружения происходит автоматически: виртуальное окружение создается без системного pip, а pip загружается из встроенного pip. `lib/get-pip.py` — никаких загрузок, никаких пакетов ОС. Только если `venv` Сам модуль Python отсутствует; вам потребуется пакет операционной системы и перезапуск экземпляра (адаптера). `.venv` (каталог перестраивается автоматически):

```bash
apt-get update && apt-get install -y python3-venv
```

## Установка

Установите адаптер из репозиториев ioBroker: откройте административный интерфейс, перейдите в раздел «Адаптеры», найдите... `Zeekr` и установите его. Затем создайте новый экземпляр и настройте его (см. ниже).

Если после обновления адаптер работает некорректно, выполните следующие действия: `iobroker fix` на хосте.

## Настройте экземпляр

Откройте административный интерфейс ioBroker и создайте новый экземпляр. `Zeekr` адаптер и настройте:

- Имя пользователя: адрес электронной почты вашей учетной записи Zeekr или имя для входа.
- пароль: пароль от вашей учетной записи Zeekr
- countryCode: код страны по стандарту ISO, используемый клиентом API Zeekr (по умолчанию -`AU`)
- hmacAccessKey: Ключ доступа HMAC, необходимый для работы вышестоящего клиента.
- hmacSecretKey: Секретный ключ HMAC, необходимый клиенту, работающему с исходным кодом.
- passwordPublicKey: открытый ключ шифрования пароля, необходимый клиенту.
- prodSecret: производственный секрет, необходимый клиенту из вышестоящего источника.
- vinKey: ключ шифрования VIN, необходимый для работы вышестоящего клиента.
- vinIv: IV шифрования VIN, необходимый клиенту вышестоящего уровня.
- Интервал опроса: интервал обновления в секундах
- Фильтр транспортных средств: необязательный фильтр подстрок для одного или нескольких транспортных средств; он определяет только, какие транспортные средства будут отображаться в качестве точек данных.
- pythonBinary: необязательный параметр для указания исполняемого файла Python, используемого адаптерным мостом и экстрактором секретов.
- autoExtractSecrets: если включено, адаптер попытается извлечь недостающие секреты из APK-файлов или из `zeekr_secrets.json` файл при запуске адаптера
- apkBasePath/apkArm64Path: необязательные пути к APK-файлам Zeekr для автоматического извлечения
- secretsJsonPath: необязательный путь к `zeekr_secrets.json` создано экстрактором
- extractRegion: регион, используемый вышестоящим экстрактором (`EM`, `SEA`, `EU`, `CN`)
- debug: включить подробное логирование моста

## Автоматическое извлечение секретов

Адаптер позволяет автоматизировать процесс извлечения из вышестоящего источника. `zeekr_key_extractor` инструмент. Для его работы вам потребуется либо:

- полная базовая APK-версия Zeekr и соответствующая разделенная APK-версия для ARM64 на хосте ioBroker, или
- предварительно сгенерированный `zeekr_secrets.json` файл.

Скрипт извлечения данных входит в состав адаптера и находится в закрепленном и проверенном коммите в исходном коде (`lib/extractor/` (MIT) — во время выполнения ничего не клонируется и не загружается.

### Как получить APK-файлы с телефона или эмулятора

Обязательная подготовка на вашем собственном устройстве — адаптер не сможет сделать это за вас:

1. На Android-смартфоне или эмуляторе установите приложение Zeekr из Play Store.
2. На вашем ПК установите `adb` (Инструменты платформы Android) и включите отладку по USB на устройстве, затем проверьте соединение:
   - `adb devices` (Ваше устройство должно быть в списке)
3. Найдите точные пути к пакетам (используйте `com.zeekr.overseas` для счетов ЕС, `com.zeekr.global` в противном случае):
   - `adb shell pm path com.zeekr.overseas`
4. Загрузите именно эти два файла (`arm64_v8a` Разделение обязательно —`xxhdpi` (или разделение по языкам **не** работает):
   - `adb pull /data/app/<...>/base.apk base.apk`
   - `adb pull /data/app/<...>/split_config.arm64_v8a.apk arm64.apk`
5. Загрузите два файла со своего компьютера: в настройках адаптера (вкладка «Доступ») нажмите «Загружать APK-файлы с этого компьютера» и выберите... `base.apk` плюс APK-файл, разделенный на части для ARM64. Распаковка начнется автоматически; после этого перезапустите экземпляр, чтобы начался опрос с новыми секретами. (В качестве альтернативы, поместите файлы в любое другое место). `iobroker` пользователь может читать и вводить пути в `apkBasePath` /`apkArm64Path`.)
6. Набор `extractRegion` в регион, соответствующий вашей учетной записи Zeekr (`EU` для `com.zeekr.overseas`, в противном случае `EM`, `SEA`, или `CN`).
7. Уточните у `testConnection` сообщение (или проверка) `info.connection`): В случае успеха работа завершена. Информация о недостающих ключах приведена ниже.

### Резервное копирование и восстановление секретов

Защищенные значения конфигурации (`password` Ключи HMAC, секретный ключ продукта, ключи VIN никогда не отображаются в административной панели — ioBroker намеренно их скрывает. Информация о наличии видна без значений:

- штаты `zeekr.0.info.secretsPresent.*` (`true` /`false` (за секретную группу),
- тот `Credentials:` строка в журнале адаптера при запуске.

Для защиты секретов за пределами ioBroker (миграция, переустановка, безопасное хранение):

1. Откройте страницу APK (`Upload APKs from this PC`), раздел 4: **Экспорт резервной копии секретов** .
2. Резервная копия загружается непосредственно на ваш компьютер. `zeekr-secrets-backup.json` и дополнительно хранится на хосте (по умолчанию: `secrets-backup.json` в папке данных экземпляра, например `/opt/iobroker/iobroker-data/zeekr.0/` настраивается через `secretsBackupPath` **Файл представляет собой обычный текст** — сохраните его в безопасном месте и удалите с хоста, когда он больше не понадобится.
3. **Функция «Импорт секретов»** считывает резервную копию: выберите файл на вашем ПК (доступ к хосту не требуется) или оставьте поле выбора пустым, чтобы использовать файл с хоста (например, после перемещения экземпляра). После этого перезапустите экземпляр.

Загруженные APK-файлы находятся в той же папке с данными экземпляра (`apks/` подкаталог) и сохраняются после обновлений и перезапусков адаптера (ранее они хранились во временном каталоге контейнера — если после этого изменения ваши файлы пропали, загрузите их снова).

Файл резервной копии никогда не сохраняется (см. `.gitignore`) и никогда никуда не загружается адаптером.

Кроме того, адаптер автоматически сохраняет файл резервной копии при каждом запуске (при наличии секретов) и заполняет в нем пробелы: переустановка адаптера перезаписывает объект экземпляра и удаляет секреты, хранящиеся в адаптере (отображаются как `from: system.host.iobroker.cli` (с пустыми значениями) — при следующем запуске они будут восстановлены автоматически. Заполняются только пустые поля; чтобы навсегда удалить секреты, удалите также файл резервной копии.

## Конфигурация

Адаптер предоставляет следующие поля конфигурации:

- `username`
- `password`
- `countryCode`
- `hmacAccessKey`
- `hmacSecretKey`
- `passwordPublicKey`
- `prodSecret`
- `vinKey`
- `vinIv`
- `pollingInterval`
- `drivePollingInterval` (секунды, мин 30 — быстрый опрос во время движения автомобиля)
- `storeTripPositions` (логическое значение, необязательно: начальные/конечные координаты в собственном журнале, округленные; по умолчанию отключено)
- `zonesJson` (необязательный список, например) `[{"name":"Office","lat":52.5,"lon":13.4,"radiusM":200}]` — показано как `zones.currentZone`)
- `tariffsJson` (Дополнительные тарифы на зарядку/время сеанса, см. раздел «Энергия» ниже)
- `homeLat` /`homeLon` /`homeRadiusM` (домашняя зона для `isHome` и соответствие тарифам)
- `batteryCapacityKwh` (по умолчанию 100 — установите свою реальную сетевую пропускную способность), `chargingEfficiencyPct` (по умолчанию 88), `defaultPricePerKwh` (по умолчанию 0,3)
- `smartChargeEnabled`, `smartChargeDeparture` (оплата производится в самый дешевый период перед вылетом)
- `vehicleFilter`
- `vehicleModel` (необязательно, отображается как `details.model` — API не предоставляет название модели)
- `abrpEnabled`, `abrpApiKey`, `abrpUserTokens` (см. раздел «Загрузка ABRP» ниже)
- `mockMode` (логическое значение, проверка соединения без реального аккаунта)
- `alertWebhook` (необязательно, оповещения об ошибках)
- `pythonBinary` (необязательный)
- `autoExtractSecrets` (логическое значение)
- `apkBasePath` /`apkArm64Path` (необязательный)
- `secretsJsonPath` (необязательный)
- `secretsBackupPath` (необязательно, пусто =`secrets-backup.json` (в папке данных экземпляра)
- `extractRegion`
- `debug` (логическое значение)

### Компромисс при совместном использовании счета

Использование второй (общей) учетной записи для адаптера позволяет избежать конфликтов сессий 079021 с приложением — рекомендуется. Однако сервер ограничивает доступ к некоторым конечным точкам только для учетной записи владельца. Конкретно:

| Функция                                                                 | Учетная запись владельца | Общий (второй) аккаунт                                                                           |
| ----------------------------------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------ |
| Текущий статус, уровень заряда батареи, GPS, одометр, состояние зарядки | да                       | да                                                                                               |
| Зарядка/тарифы/дистанционные команды                                    | да                       | да                                                                                               |
| Журнал пути API (`trips.*` контрольные точки, `ms-vehicle-trail`)       | да                       | **нет** — остается пустым/`total: 0` (`trips.fetchJson`) даже когда приложение отображает диски |
| Собственный бортовой журнал (`trips.own*` (со стороны адаптера)         | да                       | да                                                                                               |
| Сеансы зарядки (`energy.*` (со стороны адаптера)                        | да                       | да                                                                                               |

Если `trips.count` Значение остается равным 0, в то время как приложение отображает данные о поездках, что является вероятной причиной (конечная точка, доступная только владельцу), а не ошибкой сопоставления.

## Точки данных

Адаптер создает отдельный канал для каждого обнаруженного транспортного средства со следующими подканалами:

- `status`: батарея, запас хода, одометр, мощность зарядки, скорость, состояние разъема, состояние зарядки, состояние блокировки, климат-контроль, предел заряда, давление в шинах, GPS, 12-вольтовая батарея, центральный замок, состояние открытых дверей/багажника, расход топлива, состояние двигателя/технического обслуживания и временные метки
- `control`: полезная нагрузка команды, идентификатор службы, кнопка отправки, введенные кнопки (блокировка, климат-контроль, зарядка, окна, солнцезащитный козырек, освещение), лимит перезаписываемой зарядки, температура/продолжительность климат-контроля, входные данные для зарядки/плана поездки, последняя команда и последний результат
- `trips`: Количество поездок по API, расстояние/начало/конец/продолжительность/средняя скорость/расход топлива в последней поездке, список последних поездок (журнал, последние 5 без координат), статус получения данных (`trips.fetchJson`: ключи ok/total/payload — пустые, если сервер ничего не отправляет, например, в случае общих учетных записей (см. выше), а также журнал событий на стороне адаптера ниже.
- `energy`: последняя сессия, итоги за текущий месяц, расход в режиме ожидания, агрегированные данные за день/неделю, история сессий зарядки (`sessionsList`), входные параметры для переопределения цены за сессию (`nextSessionPrice` /`nextSessionName` (автоматический сброс после стабилизации), входной сигнал измеренной энергии (`nextSessionKwh`), входные данные для ретроактивной коррекции (`editSessionKwh` /`editSessionPrice` /`editSessionCost` /`editSessionTariff`), ежемесячная стоимость, распределенная по тарифам (`monthByTariff`)
- `smartCharge`: состояние принятия решения по самому дешевому окну
- `zones`: текущая именованная географическая зона (`currentZone`) и время последней смены; `isHome` отражает настроенную домашнюю зону
- `batteryLog`: ежемесячные снимки показаний одометра/запаса хода/уровня заряда батареи
- `raw`: необработанные данные полезной нагрузки с мостика
- `details`: дополнительные метаданные; `details.model` Отображается настроенная модель автомобиля (вкладка «Дополнительно»), поскольку API не предоставляет название модели.

Опрос является адаптивным: движущиеся транспортные средства используют `drivePollingInterval` (по умолчанию 30 с, минимум 30 с, с гистерезисом, чтобы короткие остановки не приводили к срабатыванию таймера), зарядные устройства опрашиваются каждые 60 с, неактивные — с заданным интервалом. Веб-перехватчик оповещений (с ограничением скорости, 15-минутным периодом охлаждения, срабатыванием по фронту сигнала) срабатывает при неожиданных остановках зарядки, завершении зарядки, открытии новых дверей/крышек, необходимости технического обслуживания (≤ 30 дней или ≤ 2000 км), предупреждениях о состоянии шин и низком напряжении батареи 12 В (< 12,0 В).

### Собственный журнал учета (работает с любой учетной записью)

Журнал взаимодействия с API хранится только у владельца, поэтому адаптер ведет собственный журнал на основе данных опроса. `trips.own*`) — независимо от `trips.*`:

- Начало поездки в движении (`currentSpeed > 0` При работающем двигателе или скачке показаний одометра на ≥ 0,1 км); поездка заканчивается после 3 припаркованных столбов. Работа двигателя на холостом ходу без пройденного расстояния (< 0,2 км) отбрасывается и не регистрируется.
- `trips.ownList` (последние 20), `trips.ownCount` Расстояние/начало/конец/продолжительность/средняя скорость/потребление энергии/стоимость последней поездки. `trips.ownMonthKm` /`trips.ownMonthCount` /`trips.ownMonthUsedKwh` /`trips.ownMonthCost` Ежемесячное потребление и стоимость на 100 км. Сохраняет работоспособность после перезапусков (каталог данных экземпляра).
- По умолчанию координаты отсутствуют; включить `storeTripPositions` также для хранения округленных начальных/конечных позиций.
- Потребление/энергия рассчитывается как разница между уровнем заряда батареи (SoC delta × ). `batteryCapacityKwh` — Укажите вашу реальную полезную емкость (например, 100 кВт·ч для батареи на 100 кВт·ч, меньше для батарей меньшего размера), иначе данные об энергопотреблении будут неверными.

### Отображение в VIS (и других средствах визуализации)

Все отображаемые значения представляют собой простые состояния — виджеты VIS не поставляются (адаптер остается независимым от представления):

- **Обзор событий на сегодня/неделю:** `energy.todayKwh` /`todayCost` /`todayLossKwh`, `energy.weekKwh` /`weekCost`, `trips.ownTodayKm` /`ownTodayCount`, `trips.ownWeekKm` Отдельные числа, идеально подходят для информационных виджетов или панелей электронных диаграмм.
- **Месяц:** `energy.monthKwh` /`monthCost` /`monthLossKwh`, `trips.ownMonthKm` /`ownMonthCount` /`ownMonthUsedKwh` /`ownMonthCost`, `trips.ownMonthConsumptionKwh100km`, `trips.ownMonthCostPer100km`.
- **Таблицы:** `trips.ownList` и `energy.sessionsList` Это JSON-массивы (последние 20) для виджетов таблиц (например, таблица vis-inventwo, Jarvis или набор данных ECharts). Записи о поездках содержат информацию о начале/конце, расстоянии, продолжительности, потреблении энергии и стоимости; записи о сессиях содержат информацию о потреблении кВт·ч, стоимости, тарифе и цене. `energy.monthByTariff` Предоставляет информацию о текущем месяце для каждого поставщика в виде объекта JSON.
- **История:** журнал `status.batteryLevel`, `all.chargePower`, `status.isCharging`, `status.pluggedIn` (В стандартных установках функция сохранения истории уже включена) для кривых заряда; `status.batterySoh` Отображается, как только API выдает правдоподобное значение (0 = не поддерживается, отображается как пустое значение).
- **Экспорт в CSV:** страница APK («6. Загрузка журнала в формате CSV») загрузки `zeekr-trips.csv` +`zeekr-sessions.csv` Для электронных таблиц — то же содержимое, что и в списках JSON, разделенное точкой с запятой.

## Энергетика, затраты и интеллектуальная зарядка

Каждое транспортное средство имеет `energy` канал:

- `sessionKwh` /`sessionCost` /`sessionTariff` /`sessionLossKwh`: последняя завершенная сессия зарядки. Энергия, вырабатываемая зарядным устройством, включает в себя как прирост **, так и потери** заряда батареи (`charger = max(integrated power, gain / efficiency)`).
- `monthKwh` /`monthCost` /`monthLossKwh` Итоговые данные за текущий месяц (сохраняются после перезапусков, обнуляются каждый месяц).
- `standbyMonthKwh`/`standbyMonthCost`: слив воды во время стоянки, по стандартному тарифу.
- `lastSession` Подробная информация представлена в формате JSON.

Тарифы в `tariffsJson` В настройках определяется цена за сеанс в зависимости от **местоположения и времени** , например, ночной тариф для дома против тарифа для общественных зарядных станций:

```json
[{"name":"home-night","lat":52.52,"lon":13.405,"radiusM":200,"pricePerKwh":0.25,"from":"22:00","to":"06:00"}]
```

Записи без указания местоположения совпадают везде; записи без указания местоположения. `from` /`to` Сопоставление цены возможно в любое время. Без сопоставления цены применяется цена по умолчанию. Установить `batteryCapacityKwh` (по умолчанию 100) и `chargingEfficiencyPct` (по умолчанию 88) для корректного расчета потерь.

Для уточнения стоимости разового роуминга напишите... `energy.nextSessionPrice` (€/кВтч) и опционально `energy.nextSessionName` до/во время выставления счета (VIS, скрипт или администратор): при следующем расчете используется переопределение вместо географического тарифа/тарифа по умолчанию, и все три состояния переопределения сбрасываются. `nextSessionPrice`, `nextSessionName`, `nextSessionKwh`) впоследствии. Использованная цена сохраняется для каждой сессии в `lastSession` /`sessionsList`.

Измеренные значения являются приблизительными: если вы считываете показания счетчика кВт·ч с дисплея общественной зарядной станции (или из счета-фактуры позже), запишите их в... `energy.nextSessionKwh` — При подключении адаптер использует его в качестве энергии зарядного устройства вместо восстановленного значения (потери пересчитываются на основе накопленного прироста заряда батареи, если таковой имеется). Без него адаптер интегрирует мощность зарядки по опросам или переключается на коэффициент усиления SoC, деленный на КПД.

Исправления постфактум (обычная ситуация в дороге — ioBroker недоступен на зарядной станции, а общественные зарядные станции часто выставляют счета позже через приложение): запишите значения счета в `energy.editSessionKwh` /`energy.editSessionPrice` /`energy.editSessionCost` (Итоговая сумма счета определяет цену за единицу товара) /`energy.editSessionTariff` — Адаптер применяет их к последней сессии и пересчитывает историю, итоговые значения за день и (текущий) месяц, а затем сбрасывает состояния редактирования. Сессии из закрытых месяцев обновляют только историю.

`energy.monthByTariff` показывает разбивку по тарифам/провайдерам за текущий месяц (`{"EnBW": {"kWh": …, "cost": …}}`) — обзор перемещений без использования электронных таблиц.

Правила надежности: сессия стабилизируется только после двух последовательных опросов в режиме ожидания (допускается исключение для отдельных неактуальных опросов, разделяющих один заряд на фрагменты) и только при подключении — скачки уровня заряда SoC без кабеля никогда не становятся сессиями. Фрагменты, разделенные интервалом менее 15 минут, объединяются обратно в одну запись сессии (итоговые значения остаются точными). Итого за месяц автоматически сбрасывается при смене календарного месяца.

`isHome` Отражает настроенную домашнюю зону. С `smartChargeEnabled` и время отправления, адаптер запускает/приостанавливает зарядку через `RCS` Таким образом, автомобиль заряжается в наиболее дешевый подходящий временной промежуток перед отправлением. `smartCharge.state` шоу `charge` /`wait` /`idle`).

## Загрузка ABRP

Адаптер может передавать данные о заряде батареи (а также информацию о местоположении, скорости и дальности хода, если они известны) в программу [A Better Routeplanner](https://abetterrouteplanner.com) после каждого опроса, используя телеметрическую точку доступа Iternio. `https://api.iternio.com/1/tlm/send`.

### Пошаговая настройка

1. Приложение ABRP: создайте один пользовательский токен для каждого автомобиля (Настройки → Данные в реальном времени → Общие). Скопируйте токен.
2. Браузер: открыть `abetterrouteplanner.com/resources/api` → «Управление ключами API телеметрии» → создайте бесплатный ключ телеметрии. Скопируйте ключ.
3. Администрирование ioBroker → Экземпляры →`zeekr.0` → Вкладка ABRP:
   - Включите параметр «Включить загрузку ABRP».
   - «Ключ API ABRP»: вставьте ключ телеметрии из шага 2.
   - «Токен пользователя из приложения ABRP»: вставьте точно токен из шага 1 — ничего больше, без VIN (адаптер знает свои автомобили). Только при наличии нескольких автомобилей используйте карту для каждого VIN-номера отдельно: `{"VIN": "token", ...}`.
   - Сохранить. Оба ключа находятся в `protectedNative` (никогда не в состояниях или логах).
4. Дождитесь следующего опроса (максимум один интервал опроса) или запустите немедленную загрузку с помощью `sendAbrpTelemetry` сообщение для `zeekr.0`.
5. Проверять: `info.abrpLastSend` отображает метку времени, VIN и уровень заряда батареи; `info.abrpLastResult` показывает ответ сервера (`{"status":"ok",...}` — а `missing: ...` Подсказка содержит только список необязательных полей и является обычной. `info.abrpLastError` должно оставаться пустым.

### Поиск неисправностей

- Нет `abrpLast*` При отображении любого состояния: загрузка отключена, ключ API пуст или поле токенов не является допустимым JSON / не содержит записи для этого VIN — адаптер в этом случае молча пропускает запрос (только в журнале отладки).
- Ошибка сервера или HTTP 401: Неверный ключ API или токен пользователя — создайте оба и вставьте их заново.
- ABRP показывает устаревшие данные: телеметрия старше нескольких минут считается устаревшей; во время движения адаптер опрашивается каждый раз. `drivePollingInterval` (по умолчанию 30 секунд) автоматически.
- Конфиденциальность: при включении этой функции данные о состоянии системы (SoC), местоположении и скорости передаются в облако ABRP при каждом опросе.

Отправлены данные полезной нагрузки: `utc`, `soc`, `power` (отрицательный полюс во время зарядки), `speed`, `lat` /`lon`, `is_charging`, `is_parked`, `odometer`, `est_battery_range`, `capacity` Диагностика посредством `info.abrpLastSend`, `info.abrpLastResult`, `info.abrpLastError`; а `sendAbrpTelemetry` Сообщение запускает немедленную загрузку.

## Рекомендация по истории

Записывайте эти состояния в InfluxDB/SQL для построения графиков и получения долгосрочной статистики: `status.batteryLevel`, `status.rangeKm`, `status.odometerKm`, `status.chargePower`, `status.isCharging`, `status.pluggedIn`, `energy.monthKwh`, `energy.monthCost`, `trips.ownTodayKm`, `trips.count`, `status.batterySoh` (после того, как API предоставит его).

Адаптер также предоставляет доступ к корневым состояниям в рамках `info` для получения информации о состоянии соединения, работоспособности, ошибках, журналах и последнем успешном обновлении.

## Команды

Адаптер предназначен для установки лёгкого адаптера. `sendCommand` сообщение с:

- `vin`: VIN целевого транспортного средства
- `command`: команда дистанционного управления (например) `start` или `stop` (в зависимости от целевого действия)
- `serviceId`: Идентификатор сервиса Zeekr (например) `RCS` (для управления зарядом или других услуг дистанционного управления)
- `setting` Объект полезной нагрузки перенаправлен в API Zeekr.

Команда передается через мост Python и перенаправляется на нижестоящий сервер. `zeekr_ev_api` клиент.

Записываемые состояния элементов управления реагируют на прямую запись: установите состояние кнопки (например) `vehicles.<id>.control.lock`) к `true` с `ack: false` из административного интерфейса, Vis, Blockly (`setState`) или скриптов, и адаптер выполняет команду и сбрасывает кнопку. Прямая запись состояния и `sendTo(instance, 'stateChange', { id, value })` Сообщения обрабатываются одним и тем же обработчиком.

### Экспериментальные команды (исследование borconi/openzeekr)

Дополнительные кнопки с маркировкой `(experimental)` Эти функции взяты из исследований Smali в [borconi/openzeekr](https://github.com/borconi/openzeekr) и **не проверены** : багажник/передний багажник, крышка зарядного устройства, размораживание, люк, режим охраны, дистанционный запуск/остановка двигателя, пробуждение, предварительный подогрев батареи, обогрев сидений/рулевого колеса, холодильник, вентиляция салона. Они добавляют только новые действия; проверенные настройки по умолчанию остаются без изменений.

Подтверждено после последнего обновления (openzeekr перешел на те же значения, конфликты разрешены):

- окна/солнцезащитный козырек: `RWS` + цели в нижнем регистре (`window`, `ventilate`, `sunshade`, `sunroof`) — наши ценности были верны
- Разблокировка багажника: `start` /`RDU` /`target=trunk` (upstream #162, протестировано в реальных условиях на 7X — наш `stop` (исправлено)
- климат/комфорт: единый `ZAF` услуга (`AC`, `DF`, `SH.11`, `SW`) — наши ценности были верны
- вспышка/гудок: строчные буквы `rhl` Главное — наши ценности были верны.

Известные оговорки:

- электропривод открывания/закрывания задней двери (`RDU_2` /`RDL_2`) требуется телематическая транспортная система ecarx (`PUT /remote-control/vehicle/telematics/{vin}`), который `zeekr_ev_api` Клиент не говорит — не ожидайте никакого эффекта от этого адаптера. Обычная разблокировка транка (`RDU`) использует стандартный транспорт.
- В режиме охраны требуется использовать строчные буквы. `rsm` ключ (регистр букв игнорируется автомобилем). Для включения системы Sentry-on автомобиль также должен быть **заблокирован** (openzeekr #41: разблокировка = молчаливое бездействие, несмотря на Cloud 200) — адаптер отказывается. `sentryOn` при условии полной разблокировки и отправки соответствующего сообщения `control.lastResult`.
- Для команд, запускаемых через бардачок/прием посетителей/шкафчик, требуется физический PIN-код. `0000` (заполнитель) и намеренно **не** отображаются как кнопки, активируемые одним щелчком мыши.
- зарядный ток (`control.chargeCurrent`, 6–32 А через `RCS` /`rcs.ac.current`) является экспериментальным.

### Контрольный список для A/B-тестирования в реальных условиях (для реального автомобиля)

Для каждой открытой пары попробуйте указанный вариант и сообщите, выполняет ли его автомобиль (проверьте). `control.lastResult` плюс сам автомобиль):

## Выпуск и техническое обслуживание

- В репозиторий включены GitHub Actions для непрерывной интеграции и создания релизов.
- Выпуск релизов автоматизирован с помощью `release-please` Публикация релиза запускает процесс сборки ресурсов.
- В процессе выпуска создается tar-архив и автоматически прикрепляется к релизу на GitHub.
- Для публикации через npm не требуется локальный токен: добавление тега версии (`vX.Y.Z`) запускает задачу развертывания Test-and-Release, которая публикует изменения в npm через доверенный источник публикации. Никогда `npm publish` Никогда не подтверждайте токены вручную.
- `common.news` Сохраняет не более 7 записей (бот репозитория обрезает, E1032): при выпуске удаляет самые старые записи — полная история сохраняется в списке изменений ниже.
- Запланированный рабочий процесс синхронизации с исходным репозиторием проверяет эталонный репозиторий на наличие новых коммитов и открывает задачу отслеживания изменений при их обнаружении.

## Отказ от ответственности

Неофициальный общественный проект. Не связан с Zeekr или Geely.

- Использование только в личных и образовательных целях, на ваш собственный риск.
- Адаптер взаимодействует с недокументированными API Zeekr и получает ключи из официального приложения Android (см. `wysie/zeekr_key_extractor` Обратное проектирование и использование API могут нарушать условия Zeekr и местное законодательство; перед использованием ознакомьтесь с информацией.
- Никогда не добавляйте APK-файлы в репозиторий. `zeekr_secrets.json` Учетные данные или токены. Секреты хранятся в ioBroker. `protectedNative` Никогда не отображается в Git, логах или состояниях (это обеспечивается сканированием секретов CI).
- В этом репозитории нет APK-файлов и ключей активации.
