# Устранение проблем с правами доступа

ioBroker работает под собственным именем пользователя. `iobroker`не как `root`Этому пользователю необходимы определенные права доступа к каталогу.
`/opt/iobroker`в npm и в некоторых системных службах. Если они некорректны, это проявляется в ошибках, которые на первый взгляд выглядят совершенно иначе: адаптеры не могут быть установлены, файлы не могут быть записаны, экземпляры не могут быть запущены.

Он **Ремонтник** восстанавливает эти права.

```bash
curl -sLf https://iobroker.net/fix.sh | bash -
```

Скрипт загружается с GitHub, как и установочный скрипт, и поэтому всегда актуален.

## Когда он помогает

- После установки, которая включала в себя `sudo` или как `root` было выполнено.
- Если установка адаптеров не удалась, и в журнале указаны проблемы с правами доступа (`EACCES`, `permission denied`).
- После **Редис** Впоследствии он был установлен. Программа-исправитель устанавливает необходимые для доступа ioBroker права доступа.
- После перемещения каталога или восстановления, в результате которого возникла путаница с правами собственности.
- В качестве меры предосторожности, прежде чем обращаться за помощью на форум: систему, на которой уже запущена программа для исправления ошибок, проще поддерживать.

Он может **так часто, как пожелаете** для выполнения. Именно для этого он и предназначен: если скрипт установки будет доработан, программа исправления обновит существующую установку до того же уровня.

## Что он делает и чего он не делает

**Он так и делает.**: пользователь `iobroker` Создайте его, если он отсутствует, и установите права доступа к файлу и каталогу в соответствующем разделе. `/opt/iobroker` Настройте необходимые права sudo и обработайте особые случаи для Redis и BackItUp.

**Он этого не делает**Это обновление не затрагивает Node.js, npm, js-controller или какой-либо адаптер. Оно влияет только на права доступа и владение файлами. Для получения обновления см. \[ссылка/reference].
[Установите обновления](/docs/tutorial/updates.md) правильный.

## Выполнять

Как **обычный пользователь**не как `root` и без `sudo` до этого. Каталог, из которого вызывается программа, не имеет значения; программа-исправитель ожидает, что установка будет произведена в... `/opt/iobroker`.

Это относится ко всем системам Linux. Это не распространяется на Windows.

!> **Не использовать с Docker.** Внутри контейнера всё и так работает без сбоев. `root`Там права доступа понимаются по-другому, и исправление ошибок может принести больше вреда, чем пользы. Для решения проблем с образом Docker, решение кроется в его...
[собственная документация](https://docs.buanet.de/de/iobroker-docker-image/).

Для тех, кто не уверен: программа для исправления ошибок не меняет содержимое, только права доступа. Однако предварительное создание копии каталога никогда не повредит, и...
[Безопасность](/docs/config/backup.md) Оно должно быть там в любом случае.

## Что он изменил

Оба скрипта ведут журнал изменений:

- [Скрипт установки](https://github.com/ioBroker/ioBroker/blob/master/CHANGELOG_INSTALLER_LINUX.md)
- [Ремонтник](https://github.com/ioBroker/ioBroker/blob/master/CHANGELOG_FIXER_LINUX.md)

Любой, кто умеет читать скрипты командной оболочки, проверит сам скрипт перед его выполнением. Это относится к каждой команде, начинающейся с определенного символа. `curl ... | bash` В итоге, это хорошая привычка.
