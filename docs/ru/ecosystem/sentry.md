# Отчеты о дорожно-транспортных происшествиях

Когда адаптер выходит из строя, в журнал записывается сообщение об ошибке. Разработчик видит его только в том случае, если кто-то сообщает о проблеме. Именно этот пробел и заполняют отчеты о сбоях: вышедший из строя адаптер автоматически отправляет сообщение об ошибке разработчику, и никому не нужно создавать заявку в службу поддержки.

За этим скрывается **Часовой**ioBroker — широко используемый сервис для сбора информации об ошибках в программах. Для этого ioBroker использует собственный плагин, который может интегрировать адаптер. Не каждый адаптер это делает.

## Что передается?

Отчет о сбое содержит само сообщение об ошибке: текст ошибки, местоположение в программном коде, цепочку вызовов, ведущую к ней, версию адаптера и среду, в которой выполнялась программа. Он также включает анонимный идентификатор установки, что позволяет разработчику определить, поступают ли сто отчетов из ста разных систем или из одной и той же системы.

Ваше имя, адрес электронной почты или IP-адрес передаваться не будут. Сообщения будут удалены максимум через 90 дней.

Какая авария! _нет_ Передаваемые данные не содержат: значений объектов, данных доступа, конфигурации адаптера. Передаётся ошибка программы, а не состояние вашей системы.

## Какие адаптеры это умеют?

В списке адаптеров адаптеры, сообщающие о сбоях, имеют специальный значок: **зеленые горы**Это позволяет с первого взгляда увидеть на экране адаптера, знает ли разработчик вообще о сбое.

Та же информация доступна в списке экземпляров в обзоре столбцов: там символ для каждого экземпляра указывает, сообщает ли этот экземпляр о сбоях.

## Выключить

Существует три уровня, и они функционируют независимо друг от друга.

**Для всей установки** через системные настройки, вкладка _статистик&#x430;_&#x422;ам так написано. **никто**Согласно информационному тексту в диалоговом окне, ни статистика использования, ни отчеты о сбоях передаваться не будут. Эта настройка предназначена для тех, кто не хочет ничего отправлять. Подробности о том, как выглядит вкладка, приведены ниже. [Статистика использования](/docs/ecosystem/statistics.md).

**Для одного хоста** или отдельный экземпляр через командную строку:

```bash
iobroker plugin disable sentry
iobroker plugin disable sentry --instance adaptername.0
```

Первая команда применяется к хосту, на котором она выполняется, вторая — только к указанному экземпляру. `enable` вместо `disable` Его снова включат.

**В дереве объектов**Если вы уже находитесь в этом районе, стойка регистрации расположена в...
`system.host.NAME.plugins.sentry.enabled` для хоста и в
`system.adapter.NAME.INSTANCE.plugins.sentry.enabled` Например, это тот же параметр, что и в командной строке, только устанавливается вручную.

## Для разработчиков

Адаптер получает сообщения о сбоях.
[plugin-sentry](https://github.com/ioBroker/plugin-sentry)Это будет внесено в `io-package.json` под `common.plugins.sentry`с `dsn` Обязательно укажите название вашего проекта Sentry. При желании можно добавить или исключить пути и типы ошибок, чтобы предотвратить попадание в вашу почту всех ненужных исключений.

Любой, кто хочет полностью предотвратить отправку отчетов по какому-либо случаю, устанавливает
`common.disableDataReporting` в объекте экземпляра. Поля расположены в
[Схема объекта](/docs/dev/objectsschema.md) описано.
