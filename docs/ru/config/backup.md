# резервное копирование данных

Установка ioBroker разрастается в течение нескольких месяцев: экземпляры, объекты, скрипты, визуализации, записанные значения. Неисправная SD-карта или неудачное обновление могут всё это уничтожить. Поэтому вопрос не в том, чтобы... **ли**
защищено, но **когда создается первая резервная копия**И ответ таков: до того, как что-либо произойдет.

## Что должно находиться в предохранителе?

Резервная копия ioBroker содержит обе базы данных, то есть все. **объекты** и
**Условия**Он содержит список установленных адаптеров с их конфигурациями, а также файловое хранилище, включающее скрипты и визуализации. **нет** Сами адаптеры; они загружаются заново при восстановлении.

Все данные, хранящиеся адаптером вне этих баз данных, не включаются в резервную копию и требуют создания собственной резервной копии: базы данных `influxdb` или `sql`файлы `history`— адаптер, сетевая карта Zigbee-стика, конфигурация центрального блока Homematic, поток Node-RED. В адаптере предохранителей есть специальные переключатели именно для этих целей, и они не настроены по умолчанию.

Это особенно касается **зарегистрированные значения**Восстановление возвращает все настройки системы в исходное состояние, при котором все диаграммы оказываются пустыми, если соответствующий переключатель отсутствовал. Расположение каждой настройки описано ниже.

## Без адаптера, через командную строку.

ioBroker также может создавать резервные копии без дополнительного адаптера:

```bash
iobroker stop
iobroker backup
```

Файл хранится как `<Datum>_backupIoBroker.tar.gz` в каталоге
`/opt/iobroker/backups`Игра воспроизводится с использованием следующих средств:

```bash
iobroker stop
iobroker restore <Name oder Pfad der Sicherung>
iobroker start
```

При вызове без параметров он выводит список. `iobroker restore` имеющиеся предохранители.

Для выполнения обеих команд необходимо остановить ioBroker. Резервное копирование, выполненное во время работы системы, может быть неполным.
