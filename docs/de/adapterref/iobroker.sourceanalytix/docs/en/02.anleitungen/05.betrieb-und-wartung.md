## Wie aktualisiere ich SourceAnalytix (und was ist ein Downgrade)?

<!-- abschnitt: prio=A; gewicht=23; readme=missing; cluster=upgrade-migration-other-18,upgrade-migration-other-22,upgrade-migration-other-19,upgrade-migration-other-13; features=req-versions,migration-output-id-default,migration-rounding-per-source,price-history-states -->

<!-- muss beantworten: Update nicht sichtbar, GitHub-Version, Versionssuffixe, Downgrade, Update-Risiken. -->

**Kurz gesagt:** SourceAnalytix wird derzeit nur über das Beta-Repository („latest“) und nicht über die stabile Version (stable) bereitgestellt. Administratoren sehen daher nur dann ein Update, wenn das Beta-Repository in den ioBroker-Systemeinstellungen aktiviert ist. Das Update erfolgt dann wie bei jedem anderen Adapter auf der Registerkarte „Adapter“. Ihre Einstellungen und Status bleiben erhalten.

<!-- quelle: interview=21; forum=587033; forum=784125; forum=1361101; issue=#458 -->

SourceAnalytix fehlt vollständig im stabilen Repository (Stand: 13. November 2026). Dies ist kein Problem Ihrer Installation. SourceAnalytix wird erst nach einer Testphase in das stabile Repository aufgenommen. Anschließend erhalten Sie auch Updates mit dem Zusatz „stable“.

<!-- quelle: interview=21; pr=#1276 -->

### So aktualisieren Sie Ihr System

1. Sichern Sie Ihr ioBroker-System.
2. Öffnen Sie im Adminbereich die Systemeinstellungen und wählen Sie im Abschnitt „Repositories“ das „neueste“ (Beta-)Repository als aktives Repository aus.
3. Öffnen Sie den Tab „Adapter“ und aktualisieren Sie die Adapterliste.
4. Klicken Sie auf die Schaltfläche „Aktualisieren“ für SourceAnalytix.
5. Prüfen Sie anschließend auf der Registerkarte „Instanzen“, ob die Instanz ausgeführt wird, und überprüfen Sie das Protokoll, um sicherzustellen, dass sie fehlerfrei gestartet wurde.

<!-- quelle: interview=21; forum=587033; forum=866682 -->

<!-- bild: Systemeinstellungen, Repository „latest" aktiv, und Update-Knopf bei SourceAnalytix im Reiter „Adapter" (entsteht in Phase 5) -->

Verwenden Sie in der Konsole `iobroker upgrade sourceanalytix` Dies funktioniert auch nur mit einem Repository, das SourceAnalytix enthält, also aktuell nur mit der „neuesten“ Version. Sie installieren eine bestimmte Version mit `iobroker upgrade sourceanalytix@0.6.1` Geben Sie die Versionsnummer ohne vorangestelltes „v“ an.

<!-- quelle: forum=784125; forum=1105289; pr=#1276 -->

> \[!WICHTIG] Ab Version 0.6.0 benötigt SourceAnalytix Node.js 22, js-controller 6.0.11 und Admin 7.8.23 oder neuer. Ab Version 0.7.0 ist Admin 8.0.0 oder neuer erforderlich, da die Instanzeinstellungen darauf basieren. Ist eine dieser Voraussetzungen nicht erfüllt, bietet ioBroker kein Update an oder die Installation schlägt fehl. Siehe [Voraussetzungen](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/01.installation.md#requirements-sourceanalytix-have-node-js) .

<!-- quelle: code=io-package.json:161-170@v0.6.1; code=package.json:11-13@v0.6.1; code=io-package.json:161-170; issue=#1269 -->

### Was geschieht mit Ihren Daten während eines Updates?

Alle Werte werden in ioBroker als Zustände und Objekte gespeichert. Ein Update ändert daran nichts. Dies gilt auch für Updates auf Version 0.6.0 oder neuer:

- Die "Technische ID", die der Ordnername unter `sourceanalytix.0` Die ID bleibt unverändert. SourceAnalytix trägt die vorherige ID als Ausgabe-ID in die Einstellungen des Datenpunkts ein.
- Die bisher angewendete Rundung wird einmal pro Datenpunkt gespeichert. Sollten sich die Standardeinstellungen der Instanz später ändern, behalten die vorhandenen Datenpunkte ihre Rundung bei.
- Neue Bundesstaaten für Preise und Preishistorie werden angezeigt unter `sourceanalytix.0.priceDefinitions`, `priceHistory` Und `basicPriceHistory` Die

<!-- quelle: code=lib/output-id.js:14-26@v0.6.1; code=main.js:1775-1804@v0.6.1; code=main.js:1843-1851@v0.6.1; code=main.js:340-445@v0.6.1; forum=1355632 -->

**Ab Version 0.7.0:** Nach dem Update werden alle Ihre bestehenden Quellen mit ihren aktuellen Einstellungen auf der Registerkarte „Übersicht“ der Instanzeinstellungen aufgelistet. Sie müssen nichts neu einrichten. Überprüfen Sie anschließend einmalig die Registerkarte „Probleme“. Dort werden beispielsweise ungeeignete Startwerte oder ein verpasster Periodenüberlauf angezeigt, zusammen mit einem Lösungsvorschlag ( [#1269](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1269) ).

<!-- quelle: code=main.js:4426-4437; code=lib/source-overview.js:135-194; issue=#1269 -->

### Ich sehe kein Update.

- **Falsches Repository:** Wenn „stable“ aktiv ist, wird SourceAnalytix dort nicht mit einer neuen Version angezeigt. Wechseln Sie wie oben beschrieben zu „latest“.
- **Installation von GitHub:** Wenn Sie SourceAnalytix direkt über das Katzensymbol von GitHub installiert haben, zeigt die Administrationsoberfläche keine Updates für diese Installation an. Installieren Sie stattdessen die gewünschte Version aus dem Repository „latest“, um wieder Updates zu erhalten.
- **Anforderungen zu alt:** Siehe den obigen Hinweis.

<!-- quelle: interview=21; forum=587033; forum=487733; forum=552764; issue=#458 -->

### Was bedeuten Versionsnummern wie 0.4.8-alpha.3?

Der Teil nach dem Bindestrich kennzeichnet eine Vorabversion zum Testen (`alpha`, `beta` Die Version ohne Suffix ist neuer als alle ihre Vorabversionen: `0.4.8` ist neuer als `0.4.8-beta.0` Installieren Sie eine Vorabversion nur dann, wenn der Entwickler Tester sucht, und erstellen Sie vorher unbedingt ein Backup.

<!-- quelle: forum=704956; forum=1267538 -->

### Downgrade: Rückkehr zu einer älteren Version

Ein Downgrade installiert eine ältere Version über die bestehende. Dies ist nur erforderlich, wenn eine neue Version einen Fehler auf Ihrem System aufweist.

1. Erstelle ein Backup.
2. Aktivieren Sie den Expertenmodus auf der Registerkarte „Adapter“.
3. Wählen Sie für SourceAnalytix die Option „Eine bestimmte Version installieren“ und anschließend die gewünschte Version aus.
4. Alternativ können Sie die Konsole verwenden, wiederum mit dem aktivierten „latest“-Repository: `iobroker upgrade sourceanalytix@<version>`, Zum Beispiel `iobroker upgrade sourceanalytix@0.6.1` Die

<!-- quelle: forum=1105289; forum=412213; forum=224155 -->

> \[!WARNUNG] Ältere Versionen kennen Einstellungen nicht, die erst in neueren Versionen eingeführt wurden. Wenn Sie beispielsweise auf eine Version unter 0.6.0 zurückgehen, erkennt SourceAnalytix keine benutzerdefinierten Ausgabe-IDs. Falls Sie eine solche ID geändert haben, speichert die ältere Version die Werte wieder unter der alten ID. Im Zweifelsfall sollten Sie die Sicherung wiederherstellen, anstatt einfach die Version zu wechseln.

<!-- quelle: forum=1105289; code=lib/output-id.js:14-26@v0.6.1 -->

**Ab Version 0.6.2:** Wenn Sie auf Version 0.6.2 aktualisieren, werden alte Versionen nicht mehr unterstützt. `valueAtDeviceInit` Die Einträge bleiben in den Datenpunkteinstellungen erhalten. SourceAnalytix liest sie nicht mehr, und Sie müssen nichts weiter tun ( [#1263](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1263) ).

<!-- quelle: issue=#1263; pr=#1274 -->

## Wie kann ich einen Datenpunkt deaktivieren oder Quellen und Zustände entfernen?

<!-- abschnitt: prio=B; gewicht=15; readme=missing; cluster=setup-ui-02,logs-install-19,logs-install-21,outputs-viz-06; features=source-enable,output-state-deletion,year-statistics-archive,source-multi-edit,output-tree-layout -->

<!-- muss beantworten: Abschalten vs. Löschen; Massen-Aktivierung rückgängig; Fehler nach gelöschtem Gerät. -->

**Kurz gesagt:** Ab Version 0.7.0 öffnen Sie die Quelle in den Instanzeinstellungen und wählen unter „Aktionen“ eine der beiden folgenden Optionen: „Deaktivieren“ beendet SourceAnalytix für diese Quelle. Alle Werte bleiben erhalten, und Sie können die Quelle jederzeit wieder aktivieren. „Daten löschen“ entfernt den Quellordner mit allen Werten und Jahren sowie die SourceAnalytix-Einstellungen für den Datenpunkt endgültig.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:639-657; code=src-admin/src/i18n/de.json:8-13; code=main.js:4609-4618; code=main.js:4373-4420; issue=#1265; issue=#1269 -->

### Daten deaktivieren oder löschen?

|                                                              | "Deaktivieren"   | "Daten löschen" |
| ------------------------------------------------------------ | ---------------- | --------------- |
| SourceAnalytix berechnet fortlaufend                         | NEIN             | NEIN            |
| Ordner `sourceanalytix.0.<device>` mit allen Jahren           | Aufenthalte      | wird gelöscht   |
| Einstellungen für den Datenpunkt (Preis, Startwerte, Offset) | bleiben          | werden gelöscht |
| Rückgängig machen                                            | mit "Aktivieren" | nicht möglich   |

<!-- quelle: code=main.js:4609-4618; code=main.js:2453-2458; code=main.js:4402-4418; code=src-admin/src/i18n/de.json:2-13 -->

### So deaktivieren Sie eine Quelle (ab Version 0.7.0)

1. Unter „Instanzen“ öffnen Sie die Einstellungen der SourceAnalytix-Instanz und anschließend die Quelle auf der Registerkarte „Übersicht“.
2. Klicken Sie unter „Aktionen“ in der Zeile „Deaktivieren“ auf die Schaltfläche „Deaktivieren“. Die Änderung wird sofort und ohne Neustart wirksam.
3. In der Übersicht hat die Quelle nun den Status „Deaktiviert“. Ihre Zustände bleiben bestehen, werden aber nicht mehr aktualisiert.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:215-220; code=src-admin/src/SourceDetail.tsx:639-647; code=src-admin/src/i18n/de.json:257; code=main.js:2453-2458 -->

Sie können die Quelle an derselben Stelle mit „Aktivieren“ wieder einschalten. SourceAnalytix setzt die Berechnung dann mit den gespeicherten Einstellungen fort.

<!-- quelle: code=src-admin/src/i18n/de.json:2-4; code=main.js:2423-2450 -->

### Wie man die Daten einer Quelle löscht (ab Version 0.7.0)

1. Öffnen Sie die Quelle wie oben beschrieben und klicken Sie in der Zeile „Daten löschen“ auf „Löschen“.
2. Im Dialogfeld wird angezeigt, was entfernt wird: die Anzahl der Datenpunkte im Ordner, das Archiv der Jahre, die Gesamtsumme und die SourceAnalytix-Einstellungen für den Datenpunkt.
3. Zur Bestätigung geben Sie den Namen der Quelle ein und klicken Sie auf „Endgültig löschen“.

<!-- quelle: code=src-admin/src/Dialogs.tsx:428-505; code=src-admin/src/i18n/de.json:70-79; code=main.js:4373-4420 -->

![Der Dialog „Daten löschen“ mit der Liste der zu löschenden Elemente und dem Bestätigungsfeld](../../../../../../en/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/img/daten-loeschen.png)

> \[!VORSICHT] Das Löschen von Daten kann nicht rückgängig gemacht werden. Die Gesamt- und Ausgangswerte sowie alle Jahre sind danach unwiederbringlich verloren. Erstellen Sie daher vorher eine Sicherungskopie, falls Sie die Werte noch benötigen, und verwenden Sie „Deaktivieren“, wenn Sie die Anwendung lediglich pausieren möchten.

<!-- quelle: code=main.js:4402-4418; code=src-admin/src/i18n/de.json:73-74 -->

Beide Aktionen benötigen eine laufende Instanz. Wenn diese gestoppt ist, sind die Sofortaktionen deaktiviert.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:639-657; code=src-admin/src/i18n/de.json:173 -->

### Viele Quellen gleichzeitig abschalten

Falls Sie versehentlich viele Datenpunkte aktiviert haben, können Sie diese auf der Registerkarte „Objekte“ schneller deaktivieren. Wählen Sie die Datenpunkte aus, öffnen Sie deren gemeinsame Einstellungen mit dem Schraubenschlüssel-Symbol und entfernen Sie das Häkchen bei „Aktiviert“ unter `sourceanalytix.0` Die Quellordner bleiben erhalten. Sie können sie dann einzeln über „Daten löschen“ oder auf der Registerkarte „Objekte“ löschen.

<!-- quelle: code=admin/jsonCustom.json:1-55; code=main.js:2453-2458; issue=#1286; forum=567100 -->

**Ab Version 0.7.0:** Der Dialog für benutzerdefinierte Einstellungen enthält jetzt nur noch das Kontrollkästchen „Aktiviert“. Andere Einstellungen, wie z. B. die Preisdefinition oder der Schwellenwert, können dort nicht mehr für mehrere Datenpunkte gleichzeitig geändert werden. Diese werden für jede Quelle in ihrer Detailansicht festgelegt ( [#1286](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1286) ).

<!-- quelle: issue=#1286; code=admin/jsonCustom.json:1-55; code=src-admin/src/SourceDetail.tsx:374-598 -->

### Datenpunkt gelöscht

Wenn Sie den Quelldatenpunkt selbst löschen, beispielsweise weil Sie ein Gerät entfernt haben, deaktiviert SourceAnalytix die Quelle automatisch. Im Protokoll heißt es: „Quellstatus … wurde gelöscht; SourceAnalytix hat ihn deaktiviert, wobei der berechnete Verlauf beibehalten wurde.“ Die berechneten Werte bleiben erhalten.

<!-- quelle: code=main.js:2460-2466; forum=690622; forum=1212532; issue=#1009 -->

**Ab Version 0.7.0:** Der Tab „Probleme“ meldet eine solche Quelle als „Datenpunkt existiert nicht mehr“ und schlägt vor, die Daten zu deaktivieren oder zu löschen. Ein Ordner ohne Datenpunkt wird in der Übersicht als „Ordner ohne Datenpunkt“ angezeigt und kann dort mit „Daten löschen“ entfernt werden. Die Übertragung der Daten auf einen neuen Datenpunkt ist geplant ( [#1271](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1271) ).

<!-- quelle: code=lib/source-overview.js:150-157; code=src-admin/src/i18n/de.json:178; code=src-admin/src/i18n/de.json:210; code=src-admin/src/i18n/de.json:276; code=src-admin/src/Dialogs.tsx:432-434; issue=#1271 -->

### Entfernen einzelner Perioden

Wenn Sie bestimmte Zustände, wie beispielsweise Quartale, nicht mehr benötigen, deaktivieren Sie die entsprechende Option auf der Registerkarte „Haupteinstellungen“ der Instanzeinstellungen. SourceAnalytix löscht die zugehörigen Zustände beim nächsten Start. Manuell gelöschte Zustände werden jedoch wiederhergestellt, solange die Option und die Quelle aktiv sind.

<!-- quelle: code=main.js:29; code=main.js:2216-2237; code=main.js:2252-2265; code=main.js:2267-2318; issue=#128; issue=#217 -->

**Bis Version 0.6.x:** Die einzige Möglichkeit, eine Datenquelle zu deaktivieren, bestand darin, das Kontrollkästchen „Aktiviert“ in den SourceAnalytix-Einstellungen des Datenpunkts (Registerkarte „Objekte“, Schraubenschlüssel-Symbol) zu aktivieren. Es gab keine Option zum Löschen. Sie haben den Ordner unter `sourceanalytix.0` manuell auf der Registerkarte „Objekte“, nachdem die Quelle deaktiviert wurde.

<!-- quelle: code=main.js:2144-2217@v0.6.1; issue=#1265 -->

## Wo befinden sich die Daten, wie sichere ich sie und wie verschiebe ich sie?

<!-- abschnitt: prio=B; gewicht=12; readme=missing; cluster=upgrade-migration-other-01,upgrade-migration-other-04; features=output-tree-layout,output-cumulative-reading,source-start-values,rollover-missed-recovery-start -->

<!-- muss beantworten: Speicherort der States, Backup-Inhalt, Umzug auf neue Hardware. -->

**Kurz gesagt:** SourceAnalytix verfügt über keine eigene Datenbank. Alle Werte werden als normale Objekte und Zustände in ioBroker gespeichert, und die Einstellungen jeder Quelle befinden sich im Objekt ihres Datenpunkts. Eine vollständige ioBroker-Sicherung, beispielsweise mit BackItUp, enthält daher alles. Um auf neue Hardware umzuziehen, stellen Sie diese Sicherung auf dem neuen System wieder her, jedoch nicht kurz vor Mitternacht.

<!-- quelle: code=main.js:2280-2318; code=main.js:2801-2808; code=main.js:4066-4070; interview=11c; forum=1157744; forum=457006 -->

### Wo alles ist

| Was                                                         | Wo                                                                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Gesamt, laufende Perioden, vorherige Perioden, Jahresarchiv | Ordner `sourceanalytix.0.<device>`                                                                            |
| Zuletzt verarbeitete Perioden und Kostenspeicher            | `periodMemory` Und `dynamicCostMemory` im selben Ordner                                                       |
| Quelleneinstellungen mit Startwerten und Offset             | Im Objekt des Quelldatenpunkts unter `common.custom.sourceanalytix.0`                                         |
| Preisdefinitionen und Instanzoptionen                       | In den Instanzeinstellungen (Objekt `system.adapter.sourceanalytix.0`)                                       |
| Preise und Preishistorie                                    | `sourceanalytix.0.priceDefinitions`, `sourceanalytix.0.priceHistory` Und `sourceanalytix.0.basicPriceHistory` |
| Aufgezeichnete Geschichte                                   | In Ihrem Verlaufsadapter, nicht in SourceAnalytix.                                                           |

<!-- quelle: code=main.js:2280-2318; code=main.js:2681-2700; code=main.js:824-845; code=main.js:2801-2808; code=main.js:4066-4070; code=main.js:1402-1408; code=main.js:343-397 -->

Ab Version 0.7.0 finden Sie die technische ID in den Quelldetails unter „Für Experten“.

<!-- quelle: code=src-admin/src/SourceDetail.tsx:288-304 -->

### Was gehört ins Backup?

Sichern Sie immer das gesamte ioBroker-System mit Objekten und Zuständen. Eine Sicherung nur des Systems ist ebenfalls erforderlich. `sourceanalytix.0` Ein Ordner allein reicht nicht aus, da die Startwerte und der Offset im Quelldatenpunkt gespeichert sind. Ohne diese stimmt die Summe nach einer Wiederherstellung nicht mehr mit dem Zählerstand überein. Wenn ioBroker mit Redis verwendet wird, muss auch das Redis-Backup eingebunden werden.

<!-- quelle: code=main.js:2801-2808; code=main.js:4066-4070; forum=430979; forum=533877; issue=#162; issue=#308 -->

### So wechseln Sie zu neuer Hardware

1. Planen Sie den Umzug nicht kurz vor Mitternacht, damit kein Periodenüberlauf in einen Zeitraum fällt, in dem kein System läuft.
2. Erstellen Sie eine vollständige Datensicherung des alten Systems.
3. Installieren Sie ioBroker und SourceAnalytix auf dem neuen System (siehe [Installation](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/01.erste-schritte/01.installation.md#install-sourceanalytix-create-instance) ) und stellen Sie die Sicherung wieder her.
4. Starten Sie die Instanz. Falls ein Tages-, Wochen- oder Monatsüberlauf verpasst wurde, wird dieser einmal pro Datenquelle beim Start nachgeholt.
5. Prüfen Sie auf der Registerkarte „Probleme“ der Instanzeinstellungen, ob keine Fehler gefunden wurden, und vergleichen Sie die Summe mit Ihrem Zähler (ab Version 0.7.0).

<!-- quelle: interview=11c; code=main.js:2324-2325; code=main.js:2746-2808; code=lib/source-overview.js:194; forum=905118; forum=1274816; forum=894627 -->

![Der Reiter „Probleme“ ohne Ergebnisse](../../../../../../en/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/img/probleme-ohne-befund.png)

Wenn die Summe vom Zählerstand abweicht, gleichen Sie sie mit der Aktion „Zählerstand abgleichen“ ab (siehe [„Korrektur falscher Werte](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative) “).

<!-- quelle: issue=#640; issue=#1269 -->

> \[!WARNUNG] Der Export des Objektbaums allein liefert zwar die Struktur, aber keine Werte. Auch das Erstellen derselben Quellen auf dem neuen System ersetzt nicht die Wiederherstellung: SourceAnalytix startet dann mit neuen Startwerten.

<!-- quelle: forum=1253495; forum=229721; code=lib/calculation.js:365-384 -->

Erhält der Quelldatenpunkt im neuen System eine andere ID, beispielsweise durch den Anschluss der Geräte mit einem anderen Adapter, behandelt SourceAnalytix ihn als neue Quelle mit einem neuen Ordner. Der alte Ordner bleibt als Archiv erhalten. Die Übertragung der Daten auf einen neuen Datenpunkt ist geplant ( [#1271](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1271) ).

<!-- quelle: interview=7; issue=#1271; code=lib/output-id.js:14-26 -->

**Ab Version 0.6.2** teilt SourceAnalytix den Verbrauch zwischen dem letzten Wert vor Mitternacht und dem ersten Wert danach auf den alten und den neuen Tag anteilig auf ( [#1260](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1260) ). Selbst wenn die Verschiebung also Mitternacht umfasst, landet nicht der gesamte Verbrauch am neuen Tag.

## Wie kann ich mit einem neuen Datenpunkt beginnen und die Daten alter Jahre bereinigen?

<!-- abschnitt: prio=B; gewicht=10; readme=missing; cluster=meter-readings-24,logs-install-20; features=output-state-deletion,source-enable,calc-first-activation-start-values,source-hidden-reset-keys,log-first-activation -->

<!-- muss beantworten: States löschen, neu aktivieren, alte Jahres-/Wochenordner entfernen. -->

**Kurz gesagt:** Ab Version 0.7.0 löschen Sie die Daten der Quelle mit der Aktion „Daten löschen“ und richten sie anschließend mit „Quelle hinzufügen“ neu ein. SourceAnalytix behandelt dies dann wie eine Erstaktivierung und beginnt alle Perioden bei 0. Unabhängig davon können Sie die Ordner abgeschlossener Jahre auf der Registerkarte „Objekte“ bedenkenlos löschen.

<!-- quelle: code=main.js:4373-4420; code=main.js:2150; code=lib/calculation.js:365-384; interview=8; issue=#1265 -->

Das Löschen des Quellordners allein reicht für einen Neustart nicht aus. Die Startwerte und der Offset werden in den Einstellungen des Datenpunkts gespeichert. Solange die Quelle aktiv ist, erstellt SourceAnalytix den Ordner beim nächsten Start mit diesen Werten neu. „Daten löschen“ entfernt daher beides.

<!-- quelle: code=main.js:2150; code=main.js:2267-2318; code=main.js:4405-4418 -->

### Wie man von vorne beginnt (ab Version 0.7.0)

1. Unter „Instanzen“ öffnen Sie die Einstellungen der SourceAnalytix-Instanz und anschließend die Quelle auf der Registerkarte „Übersicht“.
2. Wählen Sie unter „Aktionen“ die Option „Daten löschen“, geben Sie den Namen der Quelle ein und klicken Sie auf „Endgültig löschen“. Der Ordner und die Einstellungen des Datenpunkts werden dann gelöscht.
3. Klicken Sie auf der Registerkarte „Übersicht“ auf „Quelle hinzufügen“ und wählen Sie denselben Datenpunkt aus.
4. Im Schritt „Startwerte“ wählen Sie „Ab jetzt zählen“. Alle Perioden beginnen dann bei 0.
5. Beim ersten Wert heißt es im Protokoll: „Initialisierung … zum ersten Mal in SourceAnalytix“ und „Startwerte für leere Perioden für … aus dem aktuellen Messwert initialisiert …“.

<!-- quelle: code=src-admin/src/Dialogs.tsx:428-505; code=src-admin/src/Wizard.tsx:719-750; code=src-admin/src/i18n/de.json:30; code=src-admin/src/i18n/de.json:253-254; code=main.js:3531-3533; code=main.js:3608-3619 -->

> \[!VORSICHT] Die Option „Daten löschen“ entfernt auch die vorherige Summe. Wenn Sie nur fehlerhafte Zahlen korrigieren möchten, verwenden Sie stattdessen „Zählerstand ausrichten“ (siehe [„Fehlerhafte Werte korrigieren](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative) “). Weitere Informationen zu den beiden Aktionen „Deaktivieren“ und „Daten löschen“ finden Sie unter [„Datenpunkt deaktivieren oder Datenquellen entfernen](#disable-datapoint-remove-sources-states) “.

<!-- quelle: code=src-admin/src/i18n/de.json:74-79; issue=#640 -->

### Aufräumen alter Jahre

Jedes Jahr, in dem die Option „Jahresstatistik“ aktiviert ist, erhält einen eigenen Ordner. `sourceanalytix.0.<device>.<year>` Die Ordner mit den abgeschlossenen Jahren sind reine Geschichte und können gelöscht werden.

<!-- quelle: code=main.js:2216-2237; code=main.js:2775; interview=8; forum=919699; forum=931836 -->

1. Öffnen Sie in Admin den Tab „Objekte“ und dann `sourceanalytix.0.<device>` Die
2. Löschen Sie den Ordner des Jahres, den Sie nicht mehr benötigen, zum Beispiel `2023` Die
3. Nicht löschen `currentYear`, `cumulativeReading` oder `periodMemory` Löschen Sie außerdem nicht den Ordner des aktuellen Jahres. SourceAnalytix benötigt diese Zustände weiterhin. Solange die Quelle aktiv ist, werden sie beim nächsten Start ohnehin neu erstellt.

<!-- quelle: code=main.js:2267-2318; code=main.js:2681-2745; code=main.js:2216-2237 -->

Die Aktion „Kosten ab Datum neu berechnen“ berechnet nur Zeiträume neu, deren Status noch vorhanden sind. Gelöschte Jahre werden übersprungen.

<!-- quelle: code=main.js:4281-4289 -->

Wenn Sie zukünftig keine wöchentlichen oder jährlichen Ordner mehr benötigen, deaktivieren Sie die Optionen „Wochen“, „Monate“ und „Quartale“ unter „Jahresstatistik“ auf der Registerkarte „Haupteinstellungen“ der Instanzeinstellungen. SourceAnalytix löscht dann die Datensätze im Ordner des aktuellen Jahres und behält die Daten älterer Jahre bei.

<!-- quelle: code=admin/jsonConfig.json:201-237; code=admin/i18n/de.json:84; code=main.js:2216-2237 -->

**Bis Version 0.6.x** gab es keine Löschfunktion. Um von vorn zu beginnen, musste die Datenquelle deaktiviert, der zugehörige Ordner im Tab „Objekte“ gelöscht und die gespeicherten Startwerte sowie der Offset des Datenpunkts entfernt werden. Andernfalls wurde die neue Aktivierung nicht als erste gezählt. Ab Version 0.7.0 erledigt die Funktion „Daten löschen“ all dies in einem Schritt.

<!-- quelle: code=main.js:3031-3037@v0.6.1; code=main.js:1943-1957@v0.6.1; issue=#1265 -->

<a id="iobroker-was-down-midnight-recover"></a>

## ioBroker war um Mitternacht offline: Wie kann ich den Tagesrollover nachholen?

<!-- abschnitt: prio=B; gewicht=7; readme=covered; cluster=periods-01; features=rollover-missed-recovery-start,rollover-hourly-safety-check,rollover-recover-periods-button,rollover-sendto-recoverperiods,rollover-midnight-cron -->

<!-- muss beantworten: recoverPeriods per Button/sendTo; stündliche Sicherheitsprüfung. -->

**Kurz gesagt:** Normalerweise müssen Sie nichts tun. SourceAnalytix merkt sich für jede Quelle, an welchem Tag, in welcher Woche und in welchem Monat sie zuletzt geschlossen wurde, und holt verpasste Rollover beim nächsten Start automatisch nach. Läuft die Instanz weiter, prüft sie außerdem stündlich, ob ein Rollover fehlt. Ab Version 0.7.0 können Sie den Rollover auch in den Instanzeinstellungen mit der Aktion „Zeiträume wiederherstellen“ auslösen.

<!-- quelle: code=main.js:2681-2745; code=main.js:2324-2325; code=main.js:3011-3036; code=src-admin/src/SourceDetail.tsx:222-225; code=src-admin/src/i18n/de.json:17-19; forum=560905; forum=859930; issue=#904; issue=#905 -->

### Was SourceAnalytix von selbst aufholt

- **Beim Start:** Beim Start vergleicht jede Quelle den gespeicherten Status im Zustand `sourceanalytix.0.<device>.periodMemory` mit dem heutigen Datum. Falls ein Kalenderüberlauf (Tag, Woche, Monat, Quartal oder Jahr) fehlt, wird dieser einmalig verarbeitet. Im Protokoll erscheint dann die Meldung „Kalenderüberlauf wird verarbeitet für …“.
- **Jede Stunde:** Eine Sicherheitsprüfung holt einen Rollover nach, den der Mitternachtsplan verpasst hat, obwohl die Instanz lief, zum Beispiel nachdem der Computer aus dem Ruhezustand aufgewacht war oder die Systemzeit korrigiert wurde.

<!-- quelle: code=main.js:2324-2325; code=main.js:2746-2771; code=main.js:3011-3036 -->

Beim Aufholen der vorherigen Zeiträume wie zum Beispiel `01_previousDay` Außerdem wird der Zeitstempel 23:59:59 des Vortages abgerufen. Selbst wenn der Ausfall mehrere Tage dauerte, verarbeitet SourceAnalytix nur einen Rollover. `01_previousDay` enthält dann den Verbrauch des letzten Tages vor dem Ausfall, die Tage dazwischen erhalten keinen eigenen Wert.

<!-- quelle: code=main.js:2746-2808; code=lib/calculation.js:238-250; code=lib/calculation.js:297-309 -->

### Wie man den Rollover manuell abfängt (ab Version 0.7.0)

1. Öffnen Sie unter „Instanzen“ die Einstellungen der SourceAnalytix-Instanz. Falls ein Rollover fehlt, wird auf der Registerkarte „Probleme“ für die betroffene Quelle „Periodenrollover verpasst“ mit der Schaltfläche „Wiederherstellen“ angezeigt.
2. Alternativ können Sie eine Quelle auf der Registerkarte „Übersicht“ öffnen und unter „Aktionen“ in der Zeile „Zeiträume wiederherstellen“ auf „Wiederherstellen“ klicken.
3. "Periodenüberlauf wiederhergestellt für<source> Dann erscheint die Meldung. Beide Methoden gelten nur für diese eine Quelle, die anderen Quellen bleiben unberührt. Wenn kein Rollover fehlt, ändert sich nichts.

<!-- quelle: code=lib/source-overview.js:172-174; code=src-admin/src/SourceDetail.tsx:222-225; code=src-admin/src/SourceDetail.tsx:629-637; code=src-admin/src/i18n/de.json:209; code=src-admin/src/i18n/de.json:115; code=src-admin/src/i18n/de.json:229; code=main.js:4758-4763; code=main.js:3049-3083; issue=#1292 -->

![Die Registerkarte „Probleme“ mit der Meldung „Periodenüberlauf verpasst“ und der Schaltfläche „Wiederherstellen“.](../../../../../../en/adapterref/iobroker.sourceanalytix/docs/en/02.anleitungen/img/probleme-periodenwechsel.png)

### Aus einem Skript oder einer Schaltfläche in VIS

Ohne die Instanzeinstellungen wird der Status verwendet. `sourceanalytix.0.info.recoverPeriods`: schreiben `true` dazu (unbestätigt, also `ack=false` SourceAnalytix holt dann die verpassten Rollover **aller** Quellen nach und setzt den Zustand zurück auf `false` Aus einem Skript verwenden `sendTo` entweder für alle Quellen oder mit `source` nur für eine. Die Antwort gibt die Anzahl der Quellen an:

<!-- quelle: code=main.js:3154-3173; code=main.js:2527-2538; code=main.js:4758-4774; issue=#1292 -->

```javascript
// all sources
sendTo('sourceanalytix.0', 'recoverPeriods', {}, result => {
    log(`Rollover recovered for ${result.recovered} sources`);
});
// one source only (from v0.7.0), ID of the source datapoint
sendTo('sourceanalytix.0', 'recoverPeriods', {source: 'shelly.0.SHEM-3#1#.Total.ConsumedPower'}, result => {
    if (result.error) log(result.message, 'warn');
});
```

Wenn die Quelle nicht aktiv ist, lautet die Antwort: `{error: 'sourceNotActive'}` Die

Falls bereits ein Rollover läuft, wird der Aufruf übersprungen und die Antwort ist 0.

<!-- quelle: code=main.js:3049-3053 -->

### Wo der Verbrauch während des Ausfalls gebucht wird

**Ab Version 0.6.2:** SourceAnalytix teilt den Verbrauch bei Zählerständen zeitlich anteilig zwischen dem letzten Wert vor Mitternacht und dem ersten Wert danach auf. Der Anteil, der auf den alten Tag fällt, wird dem Vortag zugeordnet, der Rest dem neuen Tag. Bis einschließlich Version 0.6.1 wurde der gesamte Verbrauch dem neuen Tag zugeordnet ( [#1260](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1260) ).

<!-- quelle: issue=#1260; pr=#1274; code=main.js:2827-2915; code=lib/calculation.js:78-101 -->

Beispiel: Der letzte Messwert wird um 22:00 Uhr erfasst, der nächste nach dem Neustart um 2:00 Uhr, und der Zähler hat dazwischen 4 kWh gezählt. SourceAnalytix bucht daraufhin 2 kWh für gestern und 2 kWh für heute.

<!-- quelle: code=lib/calculation.js:78-101 -->

Dies gilt nicht für Stromquellen (W). Ab Version 0.6.2 bucht SourceAnalytix deren Energieverbrauch bis Mitternacht auf den vorherigen Tag beim Jahreswechsel, jedoch nur, wenn die Instanz um Mitternacht lief ( [#1254](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1254) ).

<!-- quelle: issue=#1254; code=main.js:3056-3058; code=main.js:3093-3133; code=main.js:2827-2829 -->

> \[!HINWEIS] Der Rollover richtet sich nach der Uhrzeit des Computers oder Containers, auf dem ioBroker ausgeführt wird. Stimmt die Zeitzone dort nicht, führt SourceAnalytix den Rollover zur falschen Stunde durch. Siehe [Absturz oder Rollover zur falschen Zeit](/#/docs/adapterref/iobroker.sourceanalytix/docs/en/04.fehlerbehebung/01.log-meldungen.md#midnight-crash-rollover-wrong-time) .
