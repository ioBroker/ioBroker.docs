# Übersetzungen (i18n)

Der Adapter wird mit dem ioBroker-Standardset von **11 Sprachen** veröffentlicht:

`en` (Basis- und Ausweichlösung), `de`, `ru`, `pt`, `nl`, `fr`, `it`, `es`, `pl`, `uk`, `zh-cn`

## Wo die Texte leben

| Komponente                    | Dateien                                                                                                       | Anmerkungen                                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Adapter-Admin-UI (jsonConfig) | `admin/i18n/<lang>.json`                                                                                      | verwaltet mit `translate-adapter`; `admin/words.js` ist veraltet und darf nicht bearbeitet werden |
| ioBroker-Metadaten            | `io-package.json` →`common.titleLang`, `common.desc`, `common.news.<version>`, `common.localLinks.<key>.name` | muss alle 11 Sprachen enthalten; wird synchronisiert durch `translate-adapter`                    |
| Web-App (PWA)                 | `src-www/src/i18n/<lang>.json`                                                                                | `i18next` /`react-i18next`; eigener Schlüsselsatz (UI-Texte), `en.json` ist die Basis            |
| Berichte (PDF/XLS)            | zur Laufzeit generiert                                                                                        | Sprache aus den Benutzereinstellungen, Instanzsprache als Fallback                               |

Absichtlich **nicht** übersetzt: API-Fehlerantworten (sie enthalten stabile Fehlercodes, die vom Client übersetzt werden) und ioBroker-Statusnamen (`common.name` (Englisch + Deutsch, gemäß ioBroker-Konvention).

## Workflow

1. Füge neuen Text **nur** zur englischen Basisdatei hinzu (`admin/i18n/en.json` oder `pwa/src/i18n/en.json`).

2. Führen Sie das Übersetzungstool aus dem Adapterordner aus:

   ```bash
   npm run translate                 # all languages
   npm run translate -- -l de ru     # only selected languages
   npm run translate --rebuild       # rebuild every file from scratch (do not mix with manual fixes)
   ```

   Satz `DEEPL_API_KEY` für höhere Qualität (DeepL wird bevorzugt, ansonsten wird Google Translate verwendet).

3. Überprüfen Sie die generierte Differenz – maschinelle Übersetzung ist ein Entwurf, kein Endergebnis.

4. Führen Sie die Vollständigkeitsprüfung durch – dieselben Schlüssel wie `en`, kein Text mehr im englischen Original, kein im Code verwendeter Text ohne Schlüssel, Metadaten vollständig:

   ```bash
   npm run check:i18n
   ```

5. Übertragen Sie die Sprachdateien zusammen mit der Codeänderung, die den Text eingeführt hat.

## Regeln

- Platzhalter behalten den Namen, den sie haben. `en.json`: `{{minutes}}` Aufenthalte `{{minutes}}` in jeder Sprache. i18next füllt nur die Variablen, die der Code übergibt, sodass ein übersetzter Name (`{{minuten}}`) erscheint buchstäblich auf dem Bildschirm; `npm run check:i18n` Vergleicht die Namen und ihre Reihenfolge mit der Basisdatei.
- Bestehende Schlüssel dürfen niemals umbenannt oder anderweitig verwendet werden; Schlüssel dürfen nur mit Hilfe von \[Name der Software/des Tools] entfernt werden. `translate-adapter` (`remove-key`, `remove-translations`).
- Kein fest codierter, sichtbarer Text im Code oder in der JSON-Konfiguration.
- Verwenden Sie Platzhalter und ICU-Formatierung anstelle von Zeichenkettenverkettung für Sätze.
- Datumsangaben, Zahlen, Währungen und Einheiten formatieren mit `Intl` – niemals manuell zusammenbauen.
- Die Berichtstexte und Zeitzonen richten sich nach den Einstellungen des Benutzers, niemals nach der Serverumgebung.
- Für PDF-Exporte werden eingebettete Unicode-Schriftarten benötigt, die Kyrillisch und CJK abdecken (`ru`, `uk`, `zh-cn`) und die Buchstaben außerhalb der WinAnsiEncoding (`pl` Der Renderer lehnt eine solche Sprache ab. `report_font_missing` Statt Unsinn zu zeichnen, entscheiden die Bezeichnungen, sodass eine Sprache, deren Buchstaben die eingebauten Schriftarten nicht darstellen können, selbst dann abgelehnt wird, wenn ihr Name Latein ist.

## Arbeitsblatt zur Überprüfung (was ein Muttersprachler festlegt)

Die technische Prüfung kann die Formulierung nicht beurteilen. Diese Punkte sollten von einem Muttersprachler der jeweiligen Sprache entschieden werden; die Liste stammt aus der zweiten Prüfungsrunde vom 18.09.2026 und bleibt so lange offen, bis jemand sie beantwortet.

**Wer kann diese Fragen beantworten?** Der Inhaber verwaltet **Deutsch** und **Russisch** und bearbeitet diese beiden Sprachen manuell.
